# team-discussion

## Purpose

规定 `/team` 只读讨论与独立于聊天的 `/team configure` profile 配置；配置或方案选择均不授权实施。

## Requirements

### Requirement: 2.1 功能入口与运行模式

`/team` MUST 由用户主动调用；规划、诊断和比较共用，不按规模降单代理。

#### Scenario: 自然语言入口

- **WHEN** 用户从 TUI、CLI 或宿主调用 `/team <问题或需求>`（可指定任意需求文档）
- **THEN** 共用只读流程，无表单／子模式；裸命令提示补问题／目标。

Enter／Ctrl+Enter 等异步 input hook 前分离图片；压缩排队／循环重放保草稿所有权。图片不进讨论；成功派发消费不串下条，失败恢复文本、图片及标记，不覆合并中新草稿。

源码及发行共用 [Team 指南](../../../docs/team.md) `omp://team.md`，区分 `config.yml` 与 provider `models.yml`。

### Requirement: 2.2 参与者与模型配置

`team.members` MUST 按完整 ID／精确别名解析，保序、重复及同实例别名。

#### Scenario: 成员解析与扩编

- **WHEN** `/team` 解析名单
- **THEN** 仅未设／`[]` 回退会话模型；显式名单不追加主模型，`OMP_OFFLINE=1` 不另选 company／同家族模型。

基础名单 `M` 项，独立槽 `N = max(3, M)`，零基槽 `i` 取名单 `i % M`。唯一索引及标签 `A`…`Z`、`AA`…`AZ`、`BA`…（不限 26），标签绑定阻断 ID、路由、归属。同模型不共享上下文／提案。会话模型由用户按综合能力选，可在名单外，仅对齐／综合。首个子调用前独立校验主模型及全槽：身份、范围、Team 只读工具、结构化 `yield`；缺失／不可用／禁用／能力不足具名拒绝，不跳过。

### Requirement: 2.3 只读边界（机械保证）

子代理工具 MUST 仅限已启用 `read`、`grep`、`glob`、`ast_grep`（read 审批）、`yield`；工具或子代理失败不提权。

#### Scenario: 越权拒绝

- **WHEN** 讨论、澄清、追问或选择中请求副作用
- **THEN** 宿主 MUST 先拒绝；可调查、建议修改／验证，修订仅改讨论内容。

禁项目、配置、需求／公司文档变更及 bash/eval、task、`ast_edit`、安装、构建、测试、提交、推送；仅会话记录例外，原稿、证据、修订可回查。

可读本代理材料及普通源码；路径、内部 URL、选择器、目录检索、符号链接均隔离他人原稿／转录，含其材料的祖先目录禁枚举／递归搜索。禁 MCP 的子会话不得借全局 manager、未注册 scheme 或未知 `skill://` 回退访问 MCP；普通会话资源不变。

### Requirement: 2.4 编排形态：全程序化编排器

原生注册 `/team`；编排器 MUST 持状态和身份，强制 2.3／2.5。

#### Scenario: 程序放行

- **WHEN** `/team` 推进、结束或失败
- **THEN** 不凭模型文本放行；经 `runSubprocess` 的 `modelOverride` 按 2.2／2.5 建子会话，不加角色／人格。会话模型读拼装上下文对齐、综合，不经主代理 Task、不投票。用户无需组队、分发或在报告落地前答疑。

### Requirement: 2.5 固定工作流程

MUST 有序推进五阶段，不跳必要审查／复核。

#### Scenario: 五阶段有序执行

- **WHEN** 运行完整讨论
- **THEN** 按下表传递材料：

| 阶段 | 输入 → 产出 |
| --- | --- |
| 1 调查 | 各槽新代理，共同原问题／约束／资料入口，按 5.4 调度；独立查指定资料、规范、术语、历史方案、接口、实现及影响。结构化原稿：方案／诊断、证据、关键假设及失败影响、风险、未知、验收、解读及采用项。无据可不提案，有据可提用户未列方向。 |
| 2 对齐 | 会话模型一次，原问题／全部原稿 → 可证统一理解／验收（提案仅补漏）、共同未知、事实冲突／待查处、解读分歧／影响。同义／补充、可查清或不影响选择均非实质。3 回查事实、5 核证，未证标未知；取舍留 5。 |
| 3 审查 | 每拟选项一新代理，从提案槽下一槽起循环取首个异模型；无则用提案槽模型。隔离提案上下文；给原问题／约束、对齐解释／验收、方案、事实差异、资料入口；可查全提案、wiki、代码。 |
| 4 修订／复核 | 每方案至多两轮；提案／原审查模型各开新代理修订／按门禁复核 → 新版、处理结果、结论、已解／未解关键问题。 |
| 5 综合 | 会话模型读原问题／验收、全部最新版／修订审查史、事实回查、解读分歧、未决阻断；不读会话现场，问题须自包含。先核证／硬约束再比较，仅汇总已审设计，不拼未审选项；按 2.7 交付。 |

- 对齐、审查／复核及综合原样接收关键假设及失败影响、风险、未知、证据。综合保各轮逐 ID 回应／理由／证据、裁决／依据及失败；成功不覆历史，历史失败不等于当前受阻。
- 分原始要求、适用强制约束、对齐解释；解释不得改写前两者。冲突查原文及适用范围，不盲从摘要、不预设用户绝对优先；歧义保留，综合选前再核要求／约束。
- 对齐摘要只含需求、事实、观点，标签只标归属；代码匿名审查 prompt。两者不泄作者／模型、支持人数、共识或预推荐。归类保原稿／依据／差异，不凭标题、选型、表格删候选。
- 一致仍核共同前提。审需求、规范、不变行为、接口／代码／调用、关键假设、正确性／兼容／可实施、共同验收。每条带方案、问题、影响、依据、严重度（阻断／重要／次要）；事实给出处，新设计可推导／举反例，不冒称实测。允许无实质问题，不等于证实正确。

**修订与复核门禁**

| 条件 | MUST 行为 |
| --- | --- |
| 作者回应 | `responses[].findingId` 精确覆盖最新成功 findings ∪ 未决阻断，各一次、非空解释：接受修订、举证拒绝、保留取舍或无法解决。未知／重／缺 ID、空解释无效，不匹配自由文本；不因错误质疑强改、空称已解决、降验收或自行关闭。 |
| 复核触发 | 结构化正文、改动理由、四标志：核心设计／接口／数据／兼容策略变化；声称解决已确认阻断／严重问题；新证据改变关键假设／解读／适用约束；举证反驳阻断。任真复核受影响部分；全假不复核。 |
| 裁决 | `blockingResolutions` 精确覆盖未决 ID（初审空）：`findingId`、`status`（`resolved`／`unresolved`）、非空 `basis`。仅有效 `resolved` 关闭；部分修复保残余，新增另报。`noSubstantiveIssues` 仅指无新增实质问题，空 findings 亦不关旧项。 |
| 必需复核失败／超时／无效 | 未知／重／缺 ID、空依据、坏格式、旧整体状态整份无效。标当前版“尚不可采用”及原因；保原阻断／证据，不配新 ID、不更新成功基线、占一轮。下次给最后成功基线及其后全部修订／审查；有效复核可恢复。 |
| 两轮耗尽 | 代码计数；未决或必需复核未完成即停、标“尚不可采用”；不放行、不重命名／重开。 |

仅 prompt 投影去重：同已展当前正文，复核／综合可引 `current`；同最后成功审查版，复核可引 `previous`；两处正文相同只展一次。其余不全局去重；保待审中间版、回应、依据、失败及原工件／schema／追踪。

**综合门禁**

- 硬约束＝用户明确要求、适用强制规范、必保兼容及据此形成的共同验收。违例／未决阻断由代码优先判“尚不可采用”。新违例 `hardConstraintViolations` 含已有标签、问题、依据，未知标签／任一空白使综合无效。沿用 ID 分配器追加阻断、补影响及针对部分；不增候选、不解旧阻断。
- 自写 `【推荐】`（正文／理由／前提）或肯定被否决项可用 → 综合无效、报未完成，不并呈矛盾。沿用 TUI Markdown 一次 HTML 实体解码；否定仅及对应谓词、解除阻断才可用的条件仅及对应分句，不豁免其后无条件推荐。
- 先答题、共同结论／证据／验收只写一次；按风险、复杂度、范围、兼容、维护、可验证性说明取舍，不以工作量抵正确性。同向归类保标签／差异／条件；实质不同且有价值才分列，无可用给原因。正文目标 ≤2000 字，不省必要阻断、歧义、证据、条件。
- 明显优选：`recommendedProposal` 标签、非空白 `recommendationReason`、`recommendationPreconditions`；资格通过仅渲染器加 **【推荐】**。有推荐无理由则失败；无明显优选留空并解释取舍。

### Requirement: 2.6 证据与关键假设

MUST 分事实、推断、假设、未知，只读核证。

#### Scenario: 核验证据

- **WHEN** 任一阶段调查或验证
- **THEN** 需求是目标，当前源码是现状，适用公司规范强制；冲突按 2.5。可规划新增，不冒称已有；共识／信心／偏好非证据；严重度据成立的问题及影响。

- 文档列可查出处；历史不当然有效，未命中不证无规范。`glob`／`grep`／`ast_grep` 后读当前源码验定义／调用／影响；零命中非不存在，局部非全覆盖。
- 未知术语／规范／接口／行为先查，无据列缺口及影响。分禁用／不可用／失败／零命中，可换只读工具；确认不可用不重探，纠偏仍无关则读源码；无新线索不重查，不推全库无关／无规范。
- 关键假设列主张、依据、状态、失败影响（显著改方案或不可用）；可只读即本次核，仅运行时可验则列执行前检查；证伪项不作条件。
- 运行时检查须验证前提或区分解释，列主张、区分输入／观察、支持／反驳／不足及采用影响。不要求双向证明、不把未复现当不存在；不可区分保未决及条件。无必要不加、不执行。

### Requirement: 2.7 用户可见结果与方案选择

影响选择的解读差异 MUST 置顶。

#### Scenario: 交付与前提分歧

- **WHEN** 形成结论
- **THEN** 一条自足 Markdown：共同目标／约束／验收；候选方向、步骤、范围（无实现细节）、依据位置、取舍、适用条件、风险／假设／分歧、执行前检查；未决 ID 及具体／残余问题。仅【推荐】给推荐理由／前提；必要时简述淘汰／尚不可采用原因，不倾倒记录。截断见 5.8。

固定收尾：

> 选择方案请直接回复（如"选择方案 A"）。选择仅确认该方案、其验收标准与执行前检查，不触发实施；如需修改代码，请另行明确要求。若存在影响选择的"需求理解差异"，请先回答该差异并带答案重跑 `/team`，不要在不同前提的方案间盲选。

普通聊天据结果选择／追问，不重跑无关调查、不执行；不等同过程记忆。诊断先答根因是否确认，未确认时给可能原因、证据缺口和补查，不将未验根因供任选。优化比较预期影响、不变行为、验证，不冒报实测增益。核心方案变更带原问题、新约束重跑，旧结论／推荐失效。

### Requirement: 2.8 异常与结束规则

必要步骤缺失 MUST 报未完成，不作无解。

#### Scenario: 失败分流

- **WHEN** 讨论中断或结论失效
- **THEN** 依下表分流，完成不强求推荐。

| 条件 | 处理 |
| --- | --- |
| 指定文件缺失／位置不明 | 说明并结束，纠正后重跑。 |
| wiki／关键资料不可得 | 报未核约束及影响；影响成立不得通过。 |
| 提案／审查／修订失败、超时或未完 | 标失败及参与不完整，处理其余；无重试／替补，不当同意或无问题。 |
| 对齐／综合失败或必要审查不能完成 | 报未完成，不发半成品、不降单代理；必需复核见 2.5。 |
| 仅一项可用／全不可用 | 给唯一项及依据／给原因和所需信息；不凑项、不自动重开。 |
| 取消／需求或资料事后变化 | 见 5.4；变化使受影响结论失效，实质变化重跑。 |

### Requirement: Team 保存接口的范围

授权代配 MUST 仅经共享服务写 `team.members`。

#### Scenario: Agent 配置 provider

- **WHEN** 用户授权 Agent 新增 provider 定义
- **THEN** Team 成员接口不得写 provider；任意文本编辑无共享服务锁、版本、事务保证。

#### Scenario: Agent 按自然语言代配成员

- **WHEN** 用户在普通聊天中授权代配（不交给只读 `/team`）
- **THEN** 查目标环境／profile 真实目录，按完整 selector 或名称／家族／简称／版本／规模／provider 限制匹配。唯一有效即用；多项或“最好／最新”无标准时列差异统一确认，不猜。无匹配先以中英文片段查全目录、禁用／认证状态；仍缺则报，不造 ID、换版本／provider。
- **AND** 保序、保明确重复；不切主模型、启用 provider、改凭据、擅加成员或启动讨论／推理。读回有效值、核回执，报名称→selector、路径与覆盖。

### Requirement: Team 模型配置界面

`/team configure` MUST 经 slash 注册表精确进专用界面，不转模型。

#### Scenario: 配置入口与候选

- **WHEN** TUI 调用 `/team configure`
- **THEN** 普通 `/team` 无需预配置。

候选取环境／profile／项目实际 registry 全 provider，按认证、有效启禁、`enabledModels`、2.2 筛聊天模型，排除 embedding／reranker。不合格可示原因不可新选；不用固定／company 名单，不启用 provider、改认证或实测。offline 仅获准内网来源，打开／搜索／刷新不访公网。全局冷目录复用 SDK 本地凭据作用域缓存（含仅本地缓存的已认证 Copilot／Cursor 等），不刷新 provider、联网／推理或建会话。

| 区域 | 契约 |
| --- | --- |
| 上下文 | 用户层原值／读取状态、生效来源、覆盖。 |
| 有序草稿 | 增、替、移、复制、删；显示原 selector、解析名称／`provider/model-id`、状态；重复标独立槽。失效／禁用／消失保位置、selector、错误，可替／删。 |
| 选择 | 搜名称、ID、provider、已核中文别称／简称；跨 provider 同名示来源、待确认。`selectOnly` 注入完整候选，不用 `scopedModels`／最近列表或普通多选；不切主模型、不压缩、不存 role。 |
| 预览 | 只读当前有效值、拟存值、覆盖后槽位／顺序／重复／回退。按 workspace／profile／草稿版本丢迟答；未解析只诊断，修复／移除后才存具体身份。 |
| 操作 | 恢复默认只改草稿 `[]`；保存全列表；取消不写、脏退出确认留／弃。键盘／滚动／窄屏可用，长 ID 不遮来源、状态、关键操作。 |
| 变化 | 冲突保草稿，可重读／比对／重提，不覆盖；外部变化提示。切 workspace／profile 不跨上下文保存；用服务四类回执。 |

TUI 仅布局／草稿；查询、校验、预览、保存经共享服务。不直读写 YAML／数据库，不复制凭据、筛选或槽位算法；role、临时模型走原生接口。

### Requirement: Team 配置保存服务

共享服务 MUST 复用 Settings／registry／参与者规则。`team.members` 属当前 profile 共享用户层，保高层覆盖及有效顺序。

#### Scenario: 版本化保存

- **WHEN** 共享服务查询、预览、保存
- **THEN** 统一用户／有效值、资格、槽位、版本及读回。

| 环节 | 契约 |
| --- | --- |
| 目标 | 沿实际 YAML、默认／命名 profile、原始根解析，仅写用户层 `config.yml`（兼容 `config.yaml`）的 `team.members`；不硬编码 home、借他进程路径、写 `agent.db`／provider 或另建文件。`[]` 显式回退，移除字段删用户值；保项目／overlay／运行时覆盖。 |
| 校验 | 现有 YAML 解析严格验相关原文结构及重复映射键（含 `team:`／`members:`），拒写、报文件或逻辑位置；不末值覆盖、清键、另造格式。成员重复及跨层覆盖合法。 |
| 提交 | Settings 本机锁内重读、比目标版本、最小合并、原子替换；保无关项、可保注释。冲突不写；同值无变更但仍验版本。 |
| 回执 | 保存且生效／保存但被覆盖／失败／`unknown`；未知先读回、不重放。 |
| 刷新 | 重载相关 Settings、复用 `settings_changed`；下次 Team 重读有效值；跨进程靠既有文件变化／版本检查。打开／保存不讨论、不实测、不切主模型。 |

#### Scenario: 全局配置不消费聊天会话模型

- **WHEN** 无会话，或会话主模型／可选范围变化
- **THEN** 无会话仍可查询、预览、保存；workspace 仅作可信路由／目录解析，不建会话、不影响在跑讨论。查询、编辑、保存不展示主模型或缩候选；同 profile／目录／有序名单，TUI 与 Agent 保存资格一致。默认回退仅显示配置选择；讨论启动才确定并校验会话模型。

### Requirement: 5.2 审查分配与轮次

问题 ID MUST 仅在整份审查有效后由程序分配。

#### Scenario: 程序分配与关闭 ID

- **WHEN** 编排器接收审查结果
- **THEN** `TeamReviewOutput` 的 `TeamFinding` 无 ID；自造 ID／`priorBlockingStatus` 整拒，无兼容回退。有效转 `TeamReviewRecord`／`TeamTrackedFinding`，各严重度共享提案内 `nextFindingNumber`（从 1 递增，如 `A-F1`）；同文异 ID 独立、不回收。

`parseTeamReview`／`parseTeamRevision` 验 2.5 的裁决／回应集合；无效必需复核走 `pendingRecheck`／`recheckFailed`。历史、复核、`unresolvedBlocking` 用带 ID 追踪；未决集按 2.5 关闭后加入新阻断。

### Requirement: 5.4 取消、进度与并发

任务、依赖、报告及界面回调 MUST 归发起会话。

#### Scenario: 会话归属与取消

- **WHEN** 讨论运行、取消、恢复或切换
- **THEN** 取消传播至全部运行子代理并停后续阶段；成功恢复／切到别会话取消原任务、丢迟答，不跨会话写入。

`task.maxConcurrency` 超限排队不截名单。沿用阶段／成员完成／失败显示；生命周期／进度／事件走根观测总线、现有 TUI／RPC、转录及 ownership；Agent Hub 查明细，不另建面板。

子代理不得设单次 wall-clock 上限或因超时结束；用取消／并发限额管理长阶段占额。

### Requirement: 5.5 结果落地

报告 MUST 持久追加，不启回合、不入内存 `nextTurn`。

#### Scenario: 报告提交与工件发布

- **WHEN** 生成成功／失败报告
- **THEN** 等回合空闲，可取消地写 durable custom message。默认无十分钟期限；显式交付超时报未完成，排队非交付。取消不追加／确认；持久提交后才 acknowledge、刷新。

任务结果保原稿，不落计划文件、不建 Todo、不改外部状态。完整工件验 UTF-8 字节、落盘大小及可读性后原子替换；Windows 深路径（含超 MAX_PATH 暂存）不得丢／截，持久 `agent://<id>` 可查完整中文及尾证。写／校验／发布失败须报保存失败，摘要非成功；保旧有效工件、清本次暂存，路径／文件名／隔离不变。

### Requirement: 5.6 后台任务承载、并发上限与派发通知

`/team` MUST 使用发起会话后台异步能力。

#### Scenario: 派发与通知

- **WHEN** `/team` 注册任务
- **THEN** 无此能力则明示并拒启，不假报启动、不降同步。

| 分支 | 契约 |
| --- | --- |
| 注册失败（含限额） | 报原因，提示等现有任务结束或经 Agent Hub／hub cancel 取消后重试。不判命令失败、不抛未处理异常、不丢问题。 |
| 成功 | 命令返回前直接向发起会话追加 `team-dispatch` custom message，即使忙碌；`details.jobId`，正文含任务 ID、独立代理数、不同模型数、问题前 80 字、`[team-dispatch <jobId>]`；可附进度／Agent Hub。持久会话须落日志，非持久只记本会话；不排队、不启回合。 |
| 通知／刷新／提示失败 | 不撤任务、不使命令失败；区分未写入、已记录但刷新失败。 |
| 投递 | 禁自动把成功／失败 async-result 送后续模型回合；保 5.7 报告、`proc://<jobId>` 及其保留期／文本。 |

### Requirement: 5.7 失败结果的回查入口

非用户取消的失败 MUST 可经 `proc://<jobId>` 回查。

#### Scenario: 未交付与取消

- **WHEN** 讨论失败，或任务抛异常且失败报告未交付，且非用户取消
- **THEN** 既有输出／错误通道报原因、任务 ID、回查地址。完整可读的 `TeamRunResult` 文本（至少 `runId`、`inputVersion`、`candidates`、`subagentResults`）不依赖渲染／将清文件；可附结构化数据。取消不提示，终态区别于失败。

### Requirement: 5.8 结构化输出的预算与截断

字段截断 MUST NOT 改候选身份、逐 ID 阻断、硬约束或资格。

| 输出 | 契约 |
| --- | --- |
| 初稿 | 全文字含证据来源及调查阻断原因（不计布尔／状态枚举）≤4000 字；超限整拒不截、不重试／替补，可见实际字数及上限。 |
| `investigationBlockedReason` | 必填；查完为 `""`（确认无解仍 `noViableProposal=true`，正常结束）。指定资料、约束或访问缺失致调查未完成：具体原因及 `noViableProposal=true`，报未完成，不对齐／综合。 |
| 审查 | `reviewSummary`、findings 问题／影响／依据／针对部分、`blockingResolutions[].basis` 合计 ≤1500 字。摘要过长先带标记截；合计仍超整拒，不裁 findings／裁决。每次至多 10 个新问题，两轮累计裁决／回应容量 30，不截前 10。 |

#### Scenario: 按字段截断

- **WHEN** 修订后方案／修订摘要／统一需求理解／最终 markdown 分别超 4000／1500／3000／12000 字
- **THEN** schema 前截字段并追加 `…（超出输出预算，已截断）`（计入上限），校验后继续；不整拒、不静默剪。

受阻仍标“尚不可采用”，不把裁剪正文称完整；所需证据、歧义、条件经完整结构化结果及 2.7／5.5／5.7／5.9 核对。

### Requirement: 5.9 无持久会话时的临时工件租期

无持久会话的工件 MUST 随任务清理，不承诺 `agent://<id>`。

#### Scenario: 临时工件清理

- **WHEN** 子代理创建工件
- **THEN** 有 `*.jsonl` 转录用同名相邻目录（5.5）；否则 `os.tmpdir()/omp-team-<id>`、`persistArtifacts=false`；完成／失败／取消后删，可待代理退出，无可发现残留。

### Requirement: 6. 验证要求

验证 MUST 依[验证门禁](../fork-maintenance/spec.md#requirement-按风险选择验证和报告证据)断言行为，不靠源码／prompt 匹配或复制 mock。

#### Scenario: Fork 行为与真实入口门禁

- **WHEN** 验证 Team 变更
- **THEN** 真实入口覆盖 2.1–2.8，含排队、逐 ID 闭环、未完成；按下表区分证据：
