# team-run-view

## Purpose

规定 ZCode 中 Team 运行卡片与详情的动态状态、调用关系和冷历史呈现。页面读取原生运行事实，不凭时间邻近推造关系或启动隐藏 Agent。

## Requirements

### Requirement: Team 动态运行视图与交互关系

OMP MUST 聊天运行卡片与详情显示真实阶段、调用、关系与终态；历史读取不启动 Agent。

#### Scenario: Team 动态运行视图与交互关系的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：


当前可执行观测合同为 `runtime/capabilities.ompTeam` 与 `omp/team` 的 `list`／`read`／`stop`，参数、归属、冷恢复及错误边界见 [OMP 附加能力与方法契约](../zcode-app-server/spec.md)，类型源为 `packages/coding-agent/src/modes/zcode/team.ts`。运行观测不取代 `/team` 派发或成员配置；查看历史不启动 Agent，关闭详情不取消运行。

适配层只发布有原生调用标签依据的关系边；未公开的对齐输入、反馈及综合消费因果关系显示 `unavailable`。真实状态、工具、消息及 job 变化可以形成时间线，但不得靠相邻时间、模型相同或阶段顺序补边。

Team 在 ZCode 中是当前会话的内置聊天命令。用户通过聊天输入框 `/team …` 发起原生讨论，运行显示为复用工作流卡片组件的流程图运行卡片；点击卡片在右侧使用既有工作流详情组件展示阶段、Agent 调用、审查／修订关系与过程。完成后卡片和最终方案持久保留在所属聊天记录，用户直接在原输入框继续对话；关闭右侧详情不取消运行。专用设置只负责成员、模型与顺序，不设置独立任务输入／运行页面。视图仅投影原生 Team 编排事实，不把 Team 改写成普通工作流、不增加另一套编排器，不改变第 2.3 节只读讨论及方案选择不授权实施的边界；不得只显示汇总消息或通用加载动画。

* **总览与阶段：** 展示本次 run、任务、当前五阶段、整体状态和每个独立 Agent 的模型、角色、槽位、排队／运行／完成／失败／取消状态。相同模型的不同槽位、审查／修订／复核的每次独立调用均有稳定身份，不合并成一个模型节点。
* **逐 Agent 过程：** 可从节点下钻查看该次调用的实际阶段、轮次、开始／结束时间、公开输出、工具调用及结果、引用证据和错误；流式过程与终态、历史相衔接。仅展示运行时已公开的过程，不编造内部思考、百分比、工具进度或消息。
* **交互关系图：** 以真实的提案归属、对齐输入、作者—审查者分配、问题反馈、修订—复核和综合消费关系生成有向边。可选择节点／连线查看对应消息、材料、问题 ID 及交互时间；没有发生的交互不得绘制为已发生。关系图与过程时间线必须指向同一 run／Agent／调用身份。
* **动画效果：** 正在运行的节点和正在传递的真实交互使用与工作流一致的状态过渡、进度高亮或流向动画；成功、失败、取消有清晰终态。等待模型、排队和执行工具须可区分；完成后不继续播放“仍在运行”的动画。遵循主题、低动态偏好和页面可见性，减少动态时仍能通过静态状态、文本和方向理解全部信息。
* **恢复与隔离：** 刷新、切换会话、重连和冷历史查看可恢复同一 run 的阶段、节点、关系与已完成过程，不为看图重新启动 Agent、发送模型请求或重复执行。桌面 continuous 与手机 replayable 各自保持既有恢复语义；迟到事件不能写入另一 run 或会话。停止及失败由原生 owner 结算，界面不伪造完成。
* **展示约束：** 复用工作流已有的布局、节点／边、过程下钻和交互范式；支持桌面与窄屏、浅深主题、中英文、键盘操作和长名单滚动，不把设置草稿当成当前运行成员。图是可选的详情呈现，最终方案仍按第 2.7 节持久化。

验收从真实 `/team` → 原生多 Agent 编排 → ZCode UI 执行：设置保存与取消；至少三个独立提案及对齐、审查、修订／复核、综合的实际关系与过程；运行中动画和终态收敛；Agent 失败、取消、同模型多槽位、跨会话隔离；刷新／冷恢复不新增模型请求。使用隔离本地模型可验证事件与 UI，不冒充真实模型方案质量。本节保持未验收，直至对应自动化与真实界面证据齐备。

#### Scenario: Team 动态运行视图与交互关系的可观察行为

- **WHEN** GUI 查看或重开 Team run
- **THEN** 聊天运行卡片与详情显示真实阶段、调用、关系与终态；历史读取不启动 Agent
