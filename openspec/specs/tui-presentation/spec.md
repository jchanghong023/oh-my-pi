# tui-presentation

## Purpose

本规格规定 fork TUI 的 clean、compact、detailed 三档显示；compact 在 clean 基础上保留以文件为操作目标的 write／edit 上游原组件显示和固定两行活动区，并隐藏独立的模型处理忙碌提示。文件型 write／edit 只按目标与既有路由识别，不以是否真实修改文件或是否生成 diff 为显示门槛。显示模式只影响界面投影，原始消息、工具执行和模型上下文不随之改写。

## Requirements

### Requirement: 终端退出恢复

OMP MUST 在终端停止完成后清除待恢复状态，避免后续进程退出清理重复发送盲复位序列，使旧终端将不支持的键盘协议序列打印到 shell 提示符前。

#### Scenario: 正常停止后执行退出清理

- **WHEN** 终端已完成正常停止，且没有仍需退出的备用屏幕
- **THEN** 后续 emergency／postmortem 清理 MUST 不再输出终端复位序列；正常停止仍按本次实际启用的键盘模式发送匹配的关闭序列。
- **AND** 终端仍活动、停止未完成或备用屏幕仍活动时保留既有异常恢复路径；备用屏幕退出仍受实际活动状态约束。

### Requirement: 1. 三种显示模式

OMP MUST 按 `/display` 选择的 `clean`、`compact` 或 `detailed` 呈现同一份原始会话，默认使用 `compact`。compact MUST 以现有 clean 为基线，保留文件型 write／edit 与上游 detailed 相同的原组件显示、固定两行活动区，增加本规格规定的最近工具只读输出预览，并隐藏独立的模型处理忙碌提示；三档不得改变原始消息、执行和模型上下文。

#### Scenario: 1. 三种显示模式的详细边界

- **WHEN** 用户选择显示档位
- **THEN** clean 保持现有工具活动、工具结果图片和真实思考的隐藏行为；compact 保留文件型 write／edit 的上游原组件显示、固定两行活动区及最近工具只读输出预览，并隐藏独立的模型处理忙碌提示；detailed 保持原有完整组件及展开／折叠行为。
- **AND** `/display [clean|compact|detailed]`、无参数循环、默认值、保存与配置覆盖优先级不变，不新增显示档位、别名或旁路设置。
- **AND** `terminal.showImages` 和 `images.*` 仍独立生效，切换档位不改写图片设置；compact 中文件型 write／edit 历史原组件内的内容按 detailed 原规则及既有图片配置呈现，其他工具结果图片仍与 clean 一样隐藏；只读输出预览不显示图片或终端图形，不影响原有用户附件和模型识图。

#### Scenario: clean 与 compact 的显示差异

- **WHEN** 同一会话以相同尺寸、配置、草稿和执行状态分别按 clean 与 compact 显示
- **THEN** 除文件型 write／edit 的上游原组件显示、固定两行活动区、最近工具只读输出预览所需空间及独立的模型处理忙碌提示外，正文、用户消息、其他忙碌状态、独立通知、交互入口、滚动与历史选择 MUST 与 clean 一致。
- **AND** 文件型 write／edit 不采用最近次数筛选或额外成功／失败筛选；其他工具及非文件目标仅可按最近有输出的调用选择规则在临时区显示 Output，不恢复聊天历史中的普通工具预览、调用统计或错误卡片例外，不保留 compact 专属长用户消息折叠或压缩历史筛选。
- **AND** 文件型 write／edit 的进行中、成功、无变化、失败、取消及原有诊断反馈均沿用上游 detailed 的原组件和状态语义，不另做错误分类或重画；其他工具及非文件目标不因成功、失败、取消或子代理结果在聊天历史恢复隐藏卡片。

#### Scenario: compact 不显示独立的模型处理忙碌提示

- **WHEN** compact 下模型开始处理请求或输出真实思考，包括思考内容尚未到达、被隐藏、结束或取消，以及运行中切换显示档位
- **THEN** ANSI 与 native MUST 不显示独立的“模型思考中…”提示及其前置图标；同一普通模型处理提示的“处理中…”等文案也不显示，不以同类提示或空行替代。
- **AND** 固定两行活动区仍按既有规则显示真实思考、工具活动或保留活动内容；只读输出预览独立按其来源选择与关闭规则显示，不隐藏普通助手正文、其他状态通知、错误、审批与问答，不影响 Esc 中断或模型与工具执行。
- **AND** 两行活动区替代的是该独立运行提示的展示，不是底部状态栏图标；原提示的内部运行生命周期与中断控制保留，底部状态栏的品牌图标、旋转、计时和其他信息不因本替代改变。
- **AND** 切换到 clean 或 detailed 时恢复各自原有提示行为；只改变显示，不增删或改写思考内容及会话记录。

#### Scenario: clean 不显示实时思考占位或可展开思考

- **WHEN** clean 下模型开始、持续输出、完成、失败或取消真实思考
- **THEN** 聊天流中不显示思考正文、标题、完成提示、动画占位、可展开思考节点或空白块，输入区不增加活动区或只读输出预览。
- **AND** native 不发送可展开的隐藏思考正文，ANSI 不仅隐藏正文却保留标题；普通助手正文不因颜色或包含 Thinking 字样被隐藏。

#### Scenario: detailed 保留上游完整内容与原组件

- **WHEN** 切换 detailed 或在任何档位发生审批、问答、选择等实际交互
- **THEN** detailed 按原顺序展示完整工具与思考、用户全文及适用图片，展开、截断、复制和滚动保持原行为；完整可查看不等于强制展开。
- **AND** 隐藏工具记录不得隐藏或替代 clean 原有的实际交互界面；用户仍能通过原入口完成操作，活动区和只读输出预览均不替代审批或回答控件，输出预览本身不提供交互。

#### Scenario: 1. 三种显示模式 behavior

- **WHEN** 接收新消息、恢复历史、压缩后重建、切换代理视图或往返切换显示档位
- **THEN** 当前视口及后续内容使用相同的档位规则，没有旧 compact 预览、统计或隐藏思考残留；只读输出预览只恢复所属逻辑会话可确认的最近有输出来源及未到期终态，关闭计时不因重建或档位切换重启，不从已关闭历史重新打开。
- **AND** 保留原始内容、复制全文、草稿、附件和会话记录，不改变工具执行顺序、消息归属或模型输入。
- **AND** 粘贴标记、附件预览、提示词模板展开及 `/review` 原有输入行为不变；保存、模型接收和复制使用完整内容，不因显示切换生成摘要。

#### Scenario: 压缩期间的消息投递

- **WHEN** 手动或自动压缩进行期间收到子代理消息，之后压缩完成并继续当前会话
- **THEN** 该消息 MUST 保留在压缩完成后的模型上下文中，不得先在即将被替换的旧上下文消费后丢失；随后到达的子代理最终结果仍可按原有方式收取。
- **AND** 显示重建或档位切换不得复制、重新投递或重放这些消息，不改变发送者、接收者、正文、已提供时间或消息归属。

### Requirement: dark-terminal 可选主题局部柔化

OMP MUST 保留可选 `dark-terminal` 主题的既有结构，仅将其绿色与红色语义变量改用现有 `dark` 主题的 `#89d281` 与 `#fc3a4b`，强调色引用该绿色；不修改其他独立颜色、背景与语法高亮。默认深色主题按[运行默认值](../fork-runtime-defaults/spec.md)使用上游 `titanium` 原配色，此局部柔化仅在用户选择 `dark-terminal` 时生效。

#### Scenario: 可选 dark-terminal 主题的状态与强调颜色

- **WHEN** 使用 `dark-terminal` 主题显示强调、成功或错误
- **THEN** 使用柔化后的绿色或红色；其他主题、显式独立颜色、用户主题选择与配置优先级保持不变。

#### Scenario: 默认深色主题与上游一致

- **WHEN** 普通或 offline 进程未显式配置深色主题
- **THEN** 使用 `titanium` 及其上游内置原配色，不对 Titanium 应用 `dark-terminal` 的局部柔化；已有显式主题配置继续优先。

### Requirement: 紧凑历史的后台和进程回执

OMP MUST 保持 clean 与 detailed 既有后台任务、受监督进程和 wait 回执行为；compact 的聊天历史回执呈现 MUST 与 clean 一致，不按成功、失败或取消另设工具记录保留例外。两行活动区继续显示最近两次调用的意图／原始命令及保留内容；只读输出预览可以接收所选调用已有的后台 Output，但不构成另一套任务调度、统一后台跟踪或完成回执历史。

#### Scenario: 后台任务回执逐项筛选

- **WHEN** 后台任务回执包含成功、失败或取消的任务，或者 wait 消费其结果
- **THEN** 所有档位仍隐藏自动后台任务完成回执的状态行；compact 的聊天历史按 clean 处理相同回执与独立通知，不额外生成任务行、失败卡片、历史输出尾窗或工具统计。
- **AND** 只读输出区可以按最近有输出的调用规则显示真实进度及终态，随后按自身规则关闭；已有较新输出来源时，较早调用的回执不能抢占或重新打开预览。
- **AND** clean 和 detailed 原本可见的独立工件与结构化诊断保留；原任务结果、诊断、查询入口、投递、模型上下文及生命周期保持不变。

#### Scenario: 守护进程退出回执按退出结果裁剪

- **WHEN** 受监督进程完成、失败或取消并产生退出回执
- **THEN** compact 的聊天历史按 clean 处理回执，不按退出结果另设失败卡片或隐藏成功回执的专属例外；原进程退出码、诊断及生命周期保持不变。
- **AND** detailed 仍可按原有行为查看结果，两行活动区继续只呈现符合其选择规则的当前活动或静态保留内容；保留思考与工具行不添加“上次活动”前缀、分隔符或替代标题。
- **AND** 服务退出回执不自动重新打开已经关闭或被较新输出来源替换的预览，不为本区域新增服务日志订阅或轮询。

#### Scenario: 实时和历史重建采用同一回执边界

- **WHEN** 同一回执实时到达后被归档或重建，或者用户切换 clean、compact、detailed
- **THEN** clean 和 detailed 不改变原有筛选及详情能力，compact 与 clean 对相同聊天历史回执的选择一致。
- **AND** 所有档位原本隐藏的自动完成状态行不重新出现，原工具和独立诊断的已有语义不得被全局删除；clean 和 detailed 原本可见的独立工件与结构化诊断保留。
- **AND** 只读输出预览恢复不向转录追加或复制回执，也不重新消费后台结果。

#### Scenario: 调用返回不延长为后台活动

- **WHEN** 工具调用已经返回，但其启动的任务或受监督进程仍在后台运行，之后又到达后台更新或完成回执
- **THEN** 该调用仍可作为最近两次派发之一显示意图／原始命令，但 MUST 不因后台仍运行被标为调用尚未返回；后台更新或回执不改变派发顺序，也不使更早调用重新进入显示。
- **AND** 已返回调用的文字和活动区配色继续遵守固定两行活动区规则；不把保留内容或运行中配色当作调用持续运行或后台成功的证明。
- **AND** 若它仍是只读输出预览的所选调用，有限异步任务的已有后台帧 MUST 可以继续更新 Output 直到任务真实结束；调用耗时仍冻结，任务状态按既有事实呈现。新调用无 Output 不抢占该来源，不新增日志通道、查询轮询或执行生命周期。

### Requirement: `/jobs` 交互式任务面板

OMP MUST 在 `/jobs` 下为 ANSI 与 native 统一打开可浏览、可查看详情并按既有权限取消任务的交互式面板，任务树超出高度时仍保持选择与详情可达；`/jobs full` 保留完整命令折行报告。

#### Scenario: 不带参数打开交互式面板

- **WHEN** 用户在任一终端界面执行 `/jobs`
- **THEN** 打开可查看和取消任务的交互式面板，不因 ANSI 或任务数量多回退为非交互文本报告。
- **AND** 列出当前查看会话的运行中与最近任务，按任务和子代理父子关系组成树；不支持异步任务时给出警告且不打开面板。
- **AND** 复用现有可取消权限，聚焦子代理或其他只读视图不获得新的取消能力。

#### Scenario: 任务树超过面板高度仍可浏览到首尾

- **WHEN** ANSI 或 native 的任务树行数超过可用面板高度，例如在 `100×28` 或 `120×36` 下包含 40 个任务及相应代理树行
- **THEN** 用户可通过已有导航浏览全部任务，移动到首项、末项或中间项后当前选中项均保持可见，树形顺序和父子关系不变。
- **AND** 不只截取列表开头而让选中状态继续移到不可见行，不以增大终端或减少任务作为浏览前提；缩放后仍保持有效选择或沿用上游对已消失任务的选择规则。

#### Scenario: 选中任务的详情与取消目标可辨认

- **WHEN** 用户切换所选任务，或任务的状态与输出更新
- **THEN** 当前所选任务及其命令／标签、状态、已提供的目录、进程、退出码、工件和输出可通过面板交互查看，不因整个任务树先占满高度而永久位于被裁掉的末尾。
- **AND** 允许沿用上游预览和展开／滚动，不要求所有长输出同时铺满屏幕；现有完整输出入口继续可用。
- **AND** 取消动作只作用于用户可辨认的当前所选且有权限取消的运行中任务，不因不可见选择而误取消其他任务；关闭与取消键位语义不变。

#### Scenario: `/jobs full` 按整条命令折行

- **WHEN** 用户执行 `/jobs full`
- **THEN** 输出文本报告，先给出运行中任务数，再按树顺序列出运行中与最近任务，行首保留树形引导符。
- **AND** 命令或标签不截断，按报告区可用宽度折行且继续行保持缩进；超高报告仍可沿原入口滚动，没有任务时明确说明无异步任务。

### Requirement: 账户选择器的凭据身份

OMP MUST 按凭据实际归属的 canonical Provider 判定已登录与可注销状态；注销列表对同一份 canonical 凭据只生成一个 Provider 条目，不因登录别名重复或产生虚假账户，不改变原有凭据池及注销语义。

#### Scenario: 别名登录后的注销选择

- **WHEN** 用户通过 `openai-codex-device` 等登录别名登录，凭据实际写入 canonical Provider `openai-codex`
- **THEN** 注销选择器以唯一 canonical Provider 条目显示已登录和可选中，不额外产生独立的 device 别名已登录项。
- **AND** ANSI、native fallback 与 data-first picker 的可注销条目集合一致；凭据查询继续使用 auth storage 的真实 Provider 键，别名映射不改变池键或校验结果。

#### Scenario: 注销去重不合并不同凭据归属

- **WHEN** 多个登录入口映射到同一 canonical Provider，同时还存在其他 canonical Provider 的凭据
- **THEN** 每个有真实存储凭据的 canonical Provider 保留一个独立可选条目，不按相似显示名合并不同 Provider。
- **AND** 没有真实凭据时不因别名存在而显示已登录；已禁用但仍持有凭据的 Provider 继续沿用上游允许注销的行为。

#### Scenario: 登录方式列表仍保留各入口

- **WHEN** 用户打开登录而非注销选择器
- **THEN** 原有不同登录方式及别名入口继续可选，禁用过滤沿用既有规则；仅用于注销的凭据归属去重不改变登录流程、授权、凭据校验或实际移除范围。

### Requirement: 4. 显示投影边界

OMP MUST 将 compact 相对 clean 的差异限制为文件型 write／edit 的上游原组件显示、固定两行活动区、最近工具只读输出预览及隐藏独立的模型处理忙碌提示，复用既有展示、输入、布局、滚动和归档行为，不以新架构继续保留旧 compact 策略。

#### Scenario: 4. 显示投影边界 behavior

- **WHEN** 隐藏工具、显示 diff、更新活动或 Output、自动关闭预览或切换档位
- **THEN** 不增删、截断或改写模型消息、调用、结果、上下文或 Token，不改变权限、审批、取消、后台调度、任务身份、真实计时、会话持久化及公开执行协议。
- **AND** 不因 compact 延长工具调用的执行生命周期、创建另一套任务跟踪或重启计时，不新增模型请求、工具执行、轮询、遥测或无关配置；有限 Bash 名称遵循 fork-runtime 的独立任务元数据要求，不成为显示层改变路由的理由。

#### Scenario: 显示模式切换仍保留全文与原有行为

- **WHEN** 往返切换档位、使用原有展开入口、恢复会话或切换代理视图
- **THEN** clean 与 detailed 行为保持不变；compact 的文件型 write／edit 保留上游 detailed 原有完整查看能力，预览截断的 Output 及其他隐藏工具与思考全文仍可经 detailed 或已有全文入口查看，临时预览不新增详情交互。
- **AND** 草稿、附件、有效历史及原有交互保持，不重跑工具或重放模型输入，不为隐藏旧内容搬动、清空或改写已归档消息。

#### Scenario: 4. 显示投影边界的详细边界

- **WHEN** compact 显示文件型 write／edit 原组件、更新固定两行活动区或显示只读输出预览
- **THEN** 相对 clean 只增加本规格规定的原组件、两行活动区及只读预览，并隐藏独立的模型处理忙碌提示；沿用已有消息顺序、正文 Markdown 流式排版、稳定行发布、历史退休、缩放、滚动和布局调度。

### Requirement: 全部工具的显示投影覆盖

OMP MUST 对已注册的内置、隐藏、扩展、MCP 及设备派发工具统一应用当前档位；compact 中文件型 write／edit 沿用上游 detailed 的原历史展示，各工具的真实 Output 文本均可按最近有输出的调用规则进入只读预览，其余普通工具不恢复聊天历史卡片。固定两行活动区独立呈现摘要或所属逻辑会话最后实际显示的内容，不被 Output 取代；预览不复用完整有状态工具卡片。

#### Scenario: 原生与扩展工具均可识别

- **WHEN** 当前查看会话发生任一工具调用，包括无专用 renderer 的工具、扩展、MCP 或设备派发
- **THEN** 没有活跃可显示思考时，活动区 MUST 按实际派发顺序选择最近两次调用，包括已返回调用，每个调用仅占一行，在同一行呈现真实工具身份、已有短意图及原始命令预览；无命令时保留已有意图。
- **AND** 无意图且无命令时使用已有目标等可确定信息；各项均不足时保留真实身份，不伪造意图、目标或成功。wait 可复用已有结构化任务快照中的身份与命令，不以 stdout／stderr 或输出正文替代活动区意图／命令。

#### Scenario: 相同调用跨生命周期不改变归属

- **WHEN** 合法活动意图、原始命令或已有目标含换行、Tab、ANSI 样式、中文或其他宽字符
- **THEN** MUST 使用既有清理、排版与测宽行为，将每个工具摘要限定在其所属的一行；展示时将多行信息整理为单行并按扣除左边距后的实际宽度截断，不让较长调用占用另一工具的行。
- **AND** 保留可识别的工具身份及已有意图／命令，不整体取尾而丢掉身份；控制字符与宽字符不得造成溢出或新增工具历史行，原始参数与输出不被改写。
- **AND** 思考仍按当前宽度排版，过滤空白后显示最后两行非空行；摘要单行限制不约束历史原卡片内容，只读输出预览另按一行信息和五行 Output 处理，不改写意图或原始命令本身。clean 不增加活动区，detailed 保持原有组件。

### Requirement: 受限高度下补全选中项可见

OMP MUST 在终端高度受限时优先保留输入光标，并让可展示的补全菜单跟随当前选中候选；不得在显示其他候选的同时接受不可见的选中项，也不得为补全重新定位输入框或改变正常高度下的既有选择语义。

#### Scenario: 三行或四行终端导航到末尾候选

- **WHEN** ANSI 终端可用高度缩至 3 或 4 行，补全菜单包含至少三个候选，用户通过方向键选择末尾候选
- **THEN** 仍可见输入光标，菜单按真实剩余高度展示包含当前选中候选的窗口，而不是只截取候选列表开头。
- **AND** 接受补全时应用的是用户当前可见的选中候选；不能显示前两项而接受隐藏的第三项。

#### Scenario: 剩余高度不能显示任何候选

- **WHEN** 在保留输入光标后没有足够空间呈现候选
- **THEN** 不显示具有不可见选中项但仍可接受的假菜单；沿既有非菜单输入路径处理，直到有空间重新展示候选。
- **AND** 不丢失输入正文、光标、草稿或候选来源，不以新增配置或强制移动输入框换取展示空间。

#### Scenario: 高度恢复及选中项改变

- **WHEN** 终端恢复正常高度，或用户在有效候选间继续上下移动
- **THEN** 既有补全列表与键位可用，当前选中项保持可见，接受结果对应所见选择，不重放输入或误执行 slash 命令。
- **AND** native 沿用其既有受限弹出区域及选择行为，不因 ANSI 高度裁剪修正引入不可见选择。

### Requirement: 工具活动和结果图片显示由档位统一控制

工具活动及工具结果图片的显隐 MUST 由 `/display` 的 clean、compact、detailed 档位决定，不得存在独立旁路切换；已有终端和图片设置仍独立生效。

#### Scenario: 切换显示档位

- **WHEN** 用户切换显示档位或使用原工具可见性快捷键
- **THEN** 工具活动及结果图片的显示状态与当前档位一致，快捷键不得单独改变二者的可见性。

### Requirement: 多行输入的输入法安全布局

OMP MUST 在多行输入时保护输入法预编辑位置，避免非末行预编辑文本挤移右侧边框；安全布局不得依赖应用检测到实际预编辑文字。

#### Scenario: 光标在非末行末尾
- **WHEN** `tui.imeSafeCursor` 已启用、输入框获得焦点并使用硬件光标，光标位于带侧边框的非末行文本末尾，且该行不处于选区渲染
- **THEN** 即使尚未出现预编辑文字，该行 MUST 保留左边框和输入文本，不绘制右边框；不改变消息原文或其他行布局。

#### Scenario: 安全布局条件不满足
- **WHEN** 输入法安全布局关闭，或焦点、硬件光标、侧边框、行末位置、选区条件中任一条件不满足
- **THEN** 非末行 MUST 沿用正常边框布局；末行及其他输入区域的既有安全行为保持不变。

### Requirement: 紧凑模式按文件目标保留 write／edit 原展示

compact MUST 仅按 write／edit 的操作目标与既有路由识别文件操作；一旦已有参数足以确定其为文件写入或编辑，MUST 沿用上游 detailed 的原组件和完整历史显示行为，保持相同内容、消息顺序、状态反馈、交互、截断、展开／折叠、滚动及归档语义。是否真实修改文件、是否有 diff、是否成功及结果快照字段 MUST NOT 成为额外显示门槛；只读输出预览的来源选择、六行预算与自动关闭不得限制这些历史组件。

#### Scenario: 文件目标的所有生命周期状态均沿用原展示

- **WHEN** 已可确定文件目标的 write／edit 正在生成参数、执行、成功返回、未改变内容、失败、取消或仅部分操作完成
- **THEN** compact MUST 与同一状态下的上游 detailed 使用相同历史原组件和反馈，不等文件改动证明或最终结果到达后才允许显示，不因没有 diff、结果字段缺失或调用失败隐藏原组件。
- **AND** 原组件有 diff 时按原样展示；没有 diff 时保留上游原有状态或内容，不补造 diff、成功或取消事实；不强制展开、不重画为两行摘要、不另做错误分类或历史组件专属高度预算。

#### Scenario: 目标未明确到明确的参数流

- **WHEN** write／edit 的路径、补丁或设备内层参数尚不足以确定文件目标，之后已有参数明确为文件操作
- **THEN** 未明确前历史组件可保持隐藏，明确后 MUST 显示同一调用的上游原组件；不能因先前隐藏就将可能的文件调用提前退休、归档为空或永久漏显。
- **AND** 目标判断复用既有路径、协议与工具路由，不额外探测文件是否存在、读取前后内容、验证改动或建立文件系统监控；新建文件与已存在文件采用相同规则。

#### Scenario: 多次调用与跨轮历史

- **WHEN** 一轮或多轮出现四次及更多文件型 write／edit 操作，或当前轮结束、下一轮开始
- **THEN** compact 中历史原组件集合、顺序和保留 MUST 与上游 detailed 一致，不只保留最近两次或最后三次，也不因轮次切换清空或隐藏这些原组件。
- **AND** 固定两行活动区仍按自己的最近两次调用规则显示；摘要淘汰、静态保留、思考优先、只读 Output 来源切换及自动关闭均不得移除聊天流中的文件型 write／edit 原组件。

#### Scenario: 文件路由与设备包装

- **WHEN** write／edit 通过磁盘路径、文件型 URL、既有文件协议、远程文件或文件冲突解决路由操作文件，或由设备包装派发同一文件操作
- **THEN** compact MUST 依据既有路由声明与可确定的目标识别文件操作；设备包装按内层工具及目标识别，不只看外层 write 名称，也不要求结果携带文件改动证明。
- **AND** 已识别的文件操作沿用上游原组件与原路由，包括无变化及失败；clean 与 detailed 的路由、工具身份、权限、执行和原始结果不变。

#### Scenario: 非文件目标不恢复工具卡片

- **WHEN** write 用于消息、配置、进程控制、设备帮助或派发非文件工具，或非文件结果恰好包含 diff、文件路径或 `fileChanged` 等字段
- **THEN** compact MUST 继续隐藏其普通聊天历史卡片及错误卡片，不根据结果文本或字段将其伪装为文件操作；真实的工具 Output 仅可按只读预览规则显示。
- **AND** `out://` 等原有助手回复路由保持，正文不被搬入预览、不重复生成或因自动关闭而删除；只读预览不得从该调用的参数正文或已显示助手正文抽取内容补造 Output。
- **AND** bash、eval 等其他工具写盘不触发新的文件监控、前后快照或 diff 合成，不因此恢复历史卡片；不改变上游原工具能力或 detailed 的已有显示。

### Requirement: 固定两行活动区

compact MUST 在现有输入区上方提供固定两行内容的活动区，并在其与输入框／状态栏之间固定保留一行空白。活跃真实思考优先；显示工具时按实际派发顺序选择当前查看逻辑会话中已有事实可确定的最近两次调用，包括已返回调用，每个调用仅占一行，显示真实工具身份、已有短意图及原始命令预览；无命令时保留已有意图，不显示工具输出正文。无当前活动时沿用所属会话的保留内容规则，不添加历史活动标签。它不进入聊天历史，也不改变工具执行。

#### Scenario: 两行内容和固定位置

- **WHEN** compact 生效且终端空间可容纳正常输入区
- **THEN** 活动区 MUST 相对输入框固定，保留两行可用内容，并在其下方、输入框／状态栏上方保留一行完全空白，正常空间下合计占三行；不是旧版一行内容加一行固定空白，不足两行的内容仍以空行补足。
- **AND** 思考先按当前可用宽度排版，再过滤空行及仅含空白字符的行，按原顺序显示最后两行非空行；不足两行时在下方补空行，非空行自身的文字与缩进保持不变。工具每次调用独占一行，最多显示最近两次，较早的在上、较新的在下；只有一次时占第一行，第二行留空，不再拆成单个工具的身份行与反馈行。工具行无论运行中、已返回或静态保留，均直接以真实工具名起始，按“工具名 · 意图 · 原始命令预览 · 耗时”呈现已有信息，缺失字段省略，不添加“上次活动 ·”前缀、替代历史标识或独立标题行；下方留白不用于显示内容。
- **AND** 活跃及保留思考、工具意图／命令 MUST 与聊天正文使用相同的左内边距，普通布局为一列，并沿用共享紧凑布局的边距规则；排版、换行与截断先扣除该边距，不通过缩进造成溢出。ANSI 与 native 的起始列一致，快照不保存或叠加布局缩进，空内容和下方留白仍为空行；极窄宽度优先保证内容不超出可用列。
- **AND** 两行内容与下方一行留白在活跃思考、工具内容、历史保留与无内容之间切换时保持相同占用，不因活动状态使输入框上下跳动；极小终端仍遵循既有输入光标和交互可达性规则，空间不足时可压缩留白，不以留白挤掉有效输入。
- **AND** clean 与 detailed 不增加该区域，输入框、附件及扩展组件的相对布局沿用既有机制。

#### Scenario: 思考优先

- **WHEN** 当前查看会话存在按现有思考显隐设置可显示的活跃真实思考
- **THEN** 活动区 MUST 显示真实思考的最新内容，工具参数、输出或结果更新不抢占它；思考结束或不再有可显示思考时才按工具选择规则回退，无当前工具活动则保留最后实际显示且仍允许显示的内容。
- **AND** 思考不在聊天流留下标题、正文、动画占位或可展开隐藏节点，不调用模型生成摘要，也不把普通助手正文当作思考。

#### Scenario: 思考空白行不清空活动内容

- **WHEN** 思考内容含中间空白行、末尾连续换行或仅含空格／制表符的行，或者流式更新只追加这些空白字符
- **THEN** ANSI 与 native MUST 在按当前可用宽度排版后跳过所有空白行，显示最后两行非空行；长逻辑行折成多个非空显示行时，按显示行选择，而不是先取两条逻辑行再折行。
- **AND** 只有一行非空内容时显示在第一行，第二行留空；仅追加空白不得清空已有思考文字或以全空快照覆盖已有非空显示。
- **AND** 整段思考没有可显示内容时，仍按既有工具选择与保留内容规则回退；没有任何已显示内容时保持两行空白，不生成占位文字。过滤只影响活动区显示，不改写原始思考、会话记录或模型上下文。

#### Scenario: agent loop 内已显示活动不得自动变空

- **WHEN** 当前逻辑会话的 compact 活动区在 agent loop 中已经实际显示过思考或工具文字，且用户未主动隐藏相关内容、切换显示档位或查看其他会话
- **THEN** 后续等待、单次思考结束、空消息、新模型流开始、工具切换或工具返回 MUST NOT 让活动区重新变为空白；只能由按既有优先级选出的新非空活动内容替换，暂无新非空内容时继续显示最后实际显示的内容。
- **AND** 是否有新内容 MUST 在既有 ANSI／控制字符清理、排版与空白行过滤后判断；原始字符串非空但最终显示为空时，不得抢占已有思考或工具文字，也不得覆盖其非空快照。
- **AND** loop 未结束且状态栏运行标记仍运行时，保留文字继续保持运行配色与扫光；loop 结束且状态栏标记停止后，只将文字变为灰色静态，不删除文字或清空快照。后续新 loop 的首个非空活动前仍保留该会话已有内容。

#### Scenario: 无思考时显示最近调用而非日志

- **WHEN** 当前查看逻辑会话没有可显示的活跃思考，且已有实际派发的工具调用
- **THEN** 活动区 MUST 显示最近两次实际派发的调用，包括已返回调用，每个调用一行；不为较早仍未返回的调用淘汰较新的已返回调用，不等待执行结果才显示。
- **AND** 参数生成、参数补全、进度与输出更新不能改变派发顺序；尚未派发的调用不抢占已派发调用，调用返回也不使其重新排序或立刻消失。
- **AND** 新轮开始前可以保留已有调用行，跨轮不因返回状态另设筛选；不轮播并发调用，不展示累计工具清单或调用统计，不扩展统一后台任务跟踪，也不从未实际查看的已结束历史转录补造工具行。

#### Scenario: 派发顺序决定最近两次调用

- **WHEN** A、B 依次派发，之后 B 先返回而 A 仍未返回，随后又派发 C
- **THEN** 无活跃可显示思考时 MUST 先依次显示 A、B 两行；B 返回后仍保留 A、B，不把 B 的行改为输出或删除。
- **AND** C 派发后只显示 B、C，A 即使尚未返回也不继续占行；A 或 B 的迟到参数、进度、输出及终态更新不把它们重新选为最新调用。

#### Scenario: 单个工具的一行显示意图及原始命令预览

- **WHEN** 工具调用被选入两行活动区
- **THEN** 该调用 MUST 在同一行显示真实工具身份、已有的 `i`、`intent` 或 `title` 等非空意图及调用参数中的原始命令预览；长意图先截断以保留命令空间。可确定的平面 shell 命令列表只显示首条原始命令及其后连接符和省略号；引用中的分隔符及重定向不得误判为命令边界，复杂结构无法可靠分割时保留原顺序预览。shell 预览最多显示 40 个终端列，超出以省略号标示；不调用模型另写摘要。完整命令沿用 detailed 既有查看入口。
- **AND** 无意图且无命令时，回退已有路径、目标、查询等可确定信息；都没有时只显示身份及可确定状态，不伪造描述。
- **AND** 可确定状态只能附在该工具自身的一行，不另占标题或反馈行；只有一次调用时第二行留空，不展示 stdout／stderr、工具输出尾窗或执行结果正文，即使这些更新包含非空文本也不替代意图／命令。

#### Scenario: 工具专属参数与设备包装的活动摘要

- **WHEN** 工具缺少短意图，或经 `write xd://<tool>` 的既有设备路由调用
- **THEN** 活动区 MUST 从已知工具参数回退可确定的操作及目标：AST 模式与路径、OpenWiki 页面／章节／空间、LSP／Debug／IDA 的操作目标、raw edit／apply_patch 的文件、task 的单项／批量派发、todo／goal 的操作目标、GitHub／安全扫描／记忆修改／Skill 管理的操作标识、ask 的问题、context_notes 的读取／写入／清空、实验名及简短实验描述，以及 yield 的合法提交条目标识；批量参数使用已有代表项和数量，不展开完整正文。
- **AND** Eval 的已有 `code`（含独立百分号命令）作为原始代码预览，可与标题／意图同现；多行代码仍按单调用一行整理和截断，不执行、重写或以结果正文替代代码。
- **AND** 设备调用 MUST 保留真实外层工具名，并对既有路由支持的 hashline 包装、大小写及部分参数采用同样的摘要规则；可确定的内层意图、命令和目标优先于运输 URI，内层 Bash 沿用 shell 预览及后台“提交”规则，内层 wait 沿用已有结构化任务摘要及“等待”计时；文档请求不得冒充工具执行。
- **AND** 显式短意图继续优先，缺失或错误类型字段不导致渲染失败；不从 think 的私有思考、yield 的提交正文、文档／记忆正文或工具输出补造意图、目标及成功，不为显示保留完整工具参数副本或新增任务跟踪。

#### Scenario: wait 关联已有后台任务

- **WHEN** wait 的已有进度快照包含结构化任务信息，或从所属会话已有活动更新恢复正在等待的调用
- **THEN** MUST 在 wait 自身一行显示已有短意图及所等待任务的身份与命令／标签，等待耗时标为“等待”；没有任务信息时保留原有意图，不猜测所等待的命令。
- **AND** 复用现有等待任务摘要及活动更新，不新增后台跟踪、轮询、订阅或计时，不改变最近两次调用的选择，不展示任务输出正文。

#### Scenario: 工具行末显示实际执行耗时

- **WHEN** 某次工具调用在两行活动区中显示，且已有可信的工具执行起止时间或计时事实
- **THEN** MUST 在该调用自身一行的末尾追加执行耗时，沿用既有时长格式；运行中的调用按真实经过时间持续递增，不依赖工具输出或进度事件，也不因关闭颜色动画而停止更新。
- **AND** 每个调用独立计时，从已有工具执行开始事实起算，不把参数生成阶段计入执行耗时；调用返回后冻结为该次调用的实际耗时，不因它启动的后台任务仍运行而继续增长。bash 返回的既有回执确认任务仍在后台运行时，在自身行末附上任务 ID，并将冻结耗时标为“提交”，不冒充命令完成耗时；wait 仍显示自身等待耗时。
- **AND** 轮次取消本身不是工具结束的证据：确认仍在运行时继续计时，已有真实返回／终态时冻结；静态保留内容中的耗时不继续递增，切回可确认的运行调用时使用原有累计时间，不从零重新计时。
- **AND** 同一行同时保留工具身份、意图／原始命令与末尾耗时；长意图或命令先按剩余宽度截断，正常宽度下不挤掉身份和耗时，不新增内容行或占用下方留白，极窄终端沿用既有安全截断规则。
- **AND** 缺少可信起点或耗时信息时只显示可确定信息，不伪造耗时；复用既有工具计时与界面刷新机制，不为每个工具新增独立定时器，不改变最近两次调用的选择、执行生命周期或会话快照的持久化边界。

#### Scenario: 最近两次调用各占一行

- **WHEN** 没有可显示的活跃思考，且存在两次或更多实际派发的调用
- **THEN** MUST 只显示最近两次调用，较早者在第一行、较新者在第二行，每行独立呈现该调用的身份及意图／原始命令，不受它是否已经返回影响。
- **AND** 两次同名工具调用仍是不同调用，各自显示意图／命令；不按工具名去重，不混入其他调用的意图，不将任何一行改为实时输出。

#### Scenario: 长意图或命令不占用另一工具行

- **WHEN** 被选中的工具意图、原始命令或目标包含长文本、多行、宽字符或样式
- **THEN** MUST 按既有安全清理、测宽及截断规则将其限制在该调用的一行内，保留工具身份；不得换行挤掉另一工具，不用整块最新两行截尾替代逐调用布局。
- **AND** 原始命令指现有调用参数中的命令，不是 stdout 或模型重写；显示层的单行整理和截断不得改写原始参数、工具结果或完整查看入口，也不得伪造运行、成功、失败或取消。

#### Scenario: 无内容、结束、取消与切换

- **WHEN** 当前没有可显示的活跃思考、尚在生成参数的调用或仍未返回的已派发调用，包括当前轮结束或被取消后确实无当前活动
- **THEN** 已有实际显示内容时 MUST 直接保留所属会话最后实际显示的思考或工具活动；工具快照最多保留两次调用的单行意图／命令，耗时保持冻结。思考与工具行均不得额外添加“上次活动”及其分隔符、其他历史标识或替代标题；思考继续占原有两行，不因增加标签截掉原文，不删除原始思考正文中用户或模型实际写出的同名文字。文字配色与扫光直接沿用状态栏运行标记的活动窗口，不因单次思考或工具活动结束而提前切换；状态栏运行标记停止后，思考与工具文字统一使用灰色静态显示。
- **AND** 已返回调用仍可在最近两次调用中保留，但不得冒充当前运行活动；保留文字不追加到聊天历史，不从终态输出、历史转录或未实际显示的更新补造摘要，不推断成功或取消。
- **AND** 没有任何实际显示内容时保持两行空内容，不生成虚构活动；保留思考仍受现有思考显隐设置约束，隐藏后不通过快照回显。

#### Scenario: 取消本轮不等于工具已取消

- **WHEN** 用户取消当前轮、会话进入取消过程或收到轮次取消事件，但尚无某工具已取消或已返回的实际信息
- **THEN** MUST 不仅凭轮次取消把该工具标为已取消、成功或失败，也不改变真实执行或取消权限。
- **AND** 已有事实仍确认调用处于已派发未返回状态时继续按调用选择规则处理；无法确认当前活动时可转为保留内容，思考与工具行均不添加“上次活动”前缀或替代历史标识，配色遵守状态栏运行标记的活动窗口，不得以冻结的运行文字暗示该调用仍在实时运行。
- **AND** 之后已有调用返回或终态事实到达时只更新其所属会话的选择或可确定状态，不将本轮取消当作后台任务已停止。

#### Scenario: 新轮首个活动前保留上轮内容

- **WHEN** 同一逻辑会话开始新轮，但尚未出现新的可显示思考、实际派发调用或参数生成预览
- **THEN** MUST 允许继续显示该会话原有保留内容，包括最多两条已显示工具意图／命令，思考与工具行均不添加历史活动标签；新用户消息、普通助手正文或单纯轮次开始不将其误当成新活动，新派发调用到达后按该会话最近两次派发顺序更新工具行。保留文字的配色仍直接沿用当前查看会话状态栏运行标记的活动窗口，标记恢复运行时一并恢复“思考中”配色，不等待新的思考或工具内容。
- **AND** 新的可显示活动出现后覆盖保留内容；不为保留或覆盖发送请求、重跑调用、重新消费消息或重启任务时钟。

#### Scenario: 按逻辑会话保留一份内存快照

- **WHEN** 用户离开当前查看会话、查看其他会话，之后切回先前实际查看过的逻辑会话
- **THEN** OMP MUST 对每个实际查看过且有已显示内容的逻辑会话最多保留一份内存快照，可包含两条工具单行记录；切回且没有可确认的当前活动时，可以显示该会话自身最后实际显示的保留内容，不添加历史活动标签，也不得显示其他会话的内容。
- **AND** 同一逻辑会话的对象或界面组件重建不得生成多份快照或改变归属；从未实际显示过内容的会话不得从已结束轮次转录中回放内容以填充快照。
- **AND** 新查看会话确有可确认的当前活动时，优先按本规格显示其自身当前活动；原会话的迟到事件不得污染新会话的显示或快照。
- **AND** 不为保留快照新增未查看会话的持续跟踪，不增加持久化、跨进程共享或重启恢复；进程重启后不得以旧快照恢复活动区，已有真实当前活动仍按原事实显示。

#### Scenario: 两行活动区运行态与状态栏运行标记一致

- **WHEN** compact 的固定两行活动区显示工具文字、真实思考或保留内容
- **THEN** 状态栏运行标记处于运行态时，上述工具文字与思考文字 MUST 统一保持当前“思考中”的灰色基底＋绿色流动高亮扫光配色；灰色采用现有 `dim`／`muted` 层级，高亮采用主题绿色 `success`，不使用逐字彩虹渐变或整段固定绿色。复用现有 shimmer 动画、刷新机制及动画开关，关闭动画时停止动态效果，不新增独立动画设置或定时器。
- **AND** 文字运行态 MUST 直接复用当前查看会话状态栏品牌旋转标记与轮次计时使用的活动窗口：`statusLine.getTurnElapsedMs() !== null` 时运行，返回 `0` 也属于运行态；返回 `null` 时，思考文字、工具身份与意图／命令及耗时统一变为灰色静态配色，采用既有 `dim`／`muted` 灰色层级，不恢复普通正文色，不继续扫光。标记是否因布局或配置可见不改变其底层活动窗口这一状态来源。
- **AND** 不再以 `loadingAnimation` 对象是否存在、是否显示或是否播放动画作为本配色的状态来源，也不另以 `isStreaming`、单次模型响应、思考显隐、工具返回、agent loop 事件或异步任务数量维护第二套运行态。原运行提示对象被移除但状态栏仍运行时，文字继续保持运行态；原对象仍存在但状态栏已停止时，文字统一变灰。不得为同步配色改变状态栏或原独立运行提示自身的生命周期，也不得恢复被 compact 隐藏的独立运行提示。
- **AND** 思考结束、工具返回、两者交替、暂时没有新活动或显示已返回调用及保留内容时，只要状态栏运行标记仍运行，均不得提前变色；同屏两条工具行不因各自调用是否已返回而使用不同的运行态配色。配色不证明所显示的每次调用仍在执行；调用状态和耗时继续按自身真实执行事实更新，已返回调用的耗时保持冻结，不因统一配色、新轮开始或切回会话重启计时。运行态切换不清空最后实际显示的两行非空思考内容。
- **AND** ANSI 与 native MUST 使用同一状态栏活动窗口及相同配色语义；切换会话或显示档位后复用状态栏既有的会话归属与活动窗口清理／恢复，不沿用其他会话的运行态。clean、detailed、聊天流中的文件型 write／edit 原组件、其他忙碌提示及内容选择、左对齐、两行内容和下方一行留白规则保持不变，不生成请求、不重跑调用。

#### Scenario: 异步等待及回执不另设配色生命周期

- **WHEN** 当前查看会话派发异步任务、等待其结果、接收进度或完成回执，或切换到异步子代理会话
- **THEN** 活动区配色 MUST 始终沿用当前查看会话状态栏运行标记的活动窗口；既有执行链在非终态暂停、等待异步结果或自动续轮间隙仍保持该窗口时，工具文字与思考文字继续保持“思考中”配色，不因当前模型流或单次 agent loop 已结束而提前变色。
- **AND** 状态栏运行标记已停止但异步任务仍在后台运行时，思考与工具文字 MUST 使用灰色静态配色；后台任务、子代理或受监督进程仍在运行本身不改变文字配色，已返回的派发调用耗时保持冻结。
- **AND** 异步进度或完成回执仅更新任务信息、未恢复状态栏活动窗口时，MUST 不恢复运行态配色；若既有投递或唤醒链恢复该窗口，文字同时恢复“思考中”配色，窗口再次关闭时同步变灰。不为配色主动启动 loop，也不根据回执到达、入队或结果待处理状态独立推断运行态。
- **AND** 切换主会话与子代理会话时，MUST 沿用状态栏既有的会话归属与活动窗口清理／恢复；迟到回执不改变其他会话的活动区配色。本场景不改变派发、投递、唤醒、取消、后台回执显隐、原独立运行提示生命周期、底部状态栏或活动内容选择，不新增后台跟踪、订阅或轮询。

### Requirement: 紧凑变更最小化与旧行为彻底清退

本变更 MUST 清除旧 compact 专属代码、补丁、测试和现行文档，只保留本规格显示差异所必需的最小上游改动；不得用新框架、兼容层或保留旧分支代替清退。

#### Scenario: 移除旧紧凑专属实现

- **WHEN** 旧分段、数量筛选、统计、错误例外、专属日志、后台卡片跟踪、用户消息折叠或紧凑历史规则不再被本次需求使用
- **THEN** 对应实现、状态、定时刷新、设置、兼容路径和仅为其增加的跨包补丁 MUST 删除或恢复已集成上游行为，不只是关闭入口或保留不可达代码。
- **AND** 共享原组件、任务订阅和上游能力按原归属保留；不得为减少文件冲突另建平行转录、布局、任务状态、归档或渲染框架。

#### Scenario: 清理测试和现行文档

- **WHEN** 原测试、fixture、截图契约、测试清单或现行文档只约束旧 compact 行为
- **THEN** MUST 移除其过时内容，不将旧预期重新固定为新契约；专属测试通道依 fork-verification-gates 的本次 delta 清退。
- **AND** 混合文件中仍保护 clean、detailed、共享上游或其他 fork 行为的部分保留；不得按文件名含 compact 就整块删除有效内容。
- **AND** 现行说明只描述 clean 基线与本规格显示差异，不再承诺工具段、错误例外、stdout 回退或结束清空 diff；已发布 changelog 和历史归档不重写，也不作为现行要求。

#### Scenario: 上游对照与无关内容保护

- **WHEN** 判断旧 compact 补丁的移除范围
- **THEN** 以仓库记录的当前已集成上游为对照，只保留其他已批准需求独立需要的共享差异；不得仅因补丁曾修复旧 compact 问题就继续保留它。
- **AND** 不整文件／整仓回滚、不改变上游基线、不执行上游同步，不损失用户其他改动和无关 fork 功能。

### Requirement: 三档共享转录导航与输入布局

三档 MUST 保留既有共享转录视口、滚动、历史提交、输入锚定和交互优先级；删除旧 compact 工具段规则不得删除仍被 clean、detailed 或原 diff 使用的共享能力。

#### Scenario: 正文与表格沿用上游滚动与归档

- **WHEN** 正文或表格超过聊天区可见高度，或 Todo 等自动底部组件占用空间
- **THEN** 复用上游共享布局、稳定行发布、压力归档与终端原生历史；按[运行默认值](../fork-runtime-defaults/spec.md)默认启用现有 `Complete Scrollback`，使可归档正文及时进入终端历史，不为 Todo 或其他自动组件增加归档例外。
- **AND** 尚未稳定的 Markdown 不提前提交为不可改写历史，正文结束后按原顺序只归档一次；不新建聊天正文翻页或滚轮浏览状态。
- **AND** PageUp／PageDown 保持上游输入编辑区、补全和选择列表语义；空输入框不接管这些键用于聊天正文，Esc 不增加“退出聊天浏览”行为，聊天滚轮不由 fork 视口截获。
- **AND** 终端原生历史滚动和 native 原有交互保持；`Complete Scrollback` 的开启与显式关闭均沿用上游语义，作用于 HUD、草稿与对话框。组件收起后，已归档行沿用上游空间补偿，不重放、复制历史或新增填充框架。

#### Scenario: 缩放与内容收缩

- **WHEN** 终端缩放、草稿收缩、面板关闭或 diff 展开／折叠
- **THEN** 输入框和原 diff 遵循共享上游布局及历史机制；两行活动区计入真实可用空间，不通过移动输入框、重复历史或裁掉有效内容掩盖布局问题。
- **AND** ANSI 和 native 对内容选择保持一致，不要求它们使用相同字符串或重新绘制原组件。
- **AND** 底部区域增高时，有效内容按扣除实际底部组件后的可见高度分配；超出视口的内容继续可见或可由历史查看，不得同时从视口与历史丢失。欢迎区空间不足时按既有规则先进入历史，消息顺序不重复、不丢失。

#### Scenario: 无可见变更的重绘与状态提示

- **WHEN** 重绘或隐藏内容相关事件不带来可见状态变化，或相邻的子代理查看／返回等独立状态提示同时可见
- **THEN** 已有可见正文、输入框及光标的几何位置保持既有稳定性；相邻提示沿用其原有顺序和间距，归档、焦点重建与高度变化不无故改变同一对可见提示的间距。
- **AND** 正常滚动、已有合法布局和 `Complete Scrollback` 的归档补偿仍按原规则处理；不为掩盖显示问题移动输入框、重复历史或留下额外空白。

### Requirement: 紧凑模式的最近工具只读输出预览

compact MUST 在原两行活动摘要上方提供只读 Output 预览，正常空间下总高固定 6 行：1 行真实工具信息及单行命令／目标，5 行最新输出。按实际派发顺序选最近已有可显示 Output 的调用，新调用无输出不抢占，旧调用不抢占较新已有输出。收到来源调用整体真实终态即开始 3 秒关闭计时，不等待绘制；到期占 0 行，允许正常历史补偿空白。预览不复用完整卡片、不显示 Shell 结构或图片、不提供交互。

#### Scenario: 六行仅含一行信息和五行 Output

- **WHEN** compact 有符合选择规则的输出来源且终端空间足够
- **THEN** 预览 MUST 正好占 6 行，第一行在可用宽度内显示真实工具身份、可确定的命令／目标及状态；有限 Bash 的自动名称与原 job ID 保持可辨，多行命令仅为显示整理成一行并截断，不改写原始参数。
- **AND** 后五行只显示当前来源的最新 Output；按当前可用宽度排版后取最后五个输出显示行，不足时补空行，不额外增加 Output 标题、边框行、参数区、Shell 结构、图片、按钮或展开提示。
- **AND** 预览位于原两行活动摘要上方，不插入摘要与输入框之间；原摘要及其一行留白独立保留，不计入这六行，关闭预览不清空它们或 TODO。

#### Scenario: 无 Output 的新调用不抢占

- **WHEN** A 已产生 Output，之后 B 实际派发但尚无可显示 Output，或 B 只有参数、图片、空字符串及空白文本
- **THEN** MUST 继续显示 A 的 Output 和 A 的真实信息，不将 A 的内容标为 B，不因 B 的派发清空或切换来源；若尚无任何可显示 Output，临时区保持 0 行，不仅为命令或参数占位。
- **AND** 若 A 已处于终态三秒计时，B 无输出不延长或取消该计时；A 到期后区域可归零，B 之后首次产生 Output 时再打开。

#### Scenario: 最近有输出按派发顺序而非到达顺序选择

- **WHEN** A、B 依次派发且 B 首次产生可显示 Output，之后 A 又产生进度、输出或终态
- **THEN** 来源 MUST 切到 B 并保持 B，A 的迟到事件不能抢占；同名工具的不同调用不合并，也不按最近收到输出事件轮播。
- **AND** wait／read 没有自己的 Output 时不替换原 Bash，产生真实 Output 后与其他工具采用相同规则；不假定 wait 的结构化任务快照就是原 Bash stdout，也不自动固定跟踪一个旧后台命令。

#### Scenario: 流式快照与输出清理

- **WHEN** 工具发出累计预览、滚动尾窗、重置后的当前快照或含换行、Tab、控制字符及宽字符的 Output
- **THEN** MUST 按原更新契约替换当前输出文本，不能把每个累计快照重复追加；显示沿用既有安全清理、测宽和排版，先按宽度排版再选最新五行，不溢出区域。
- **AND** 清理后没有可显示文本的帧不构成新来源，不以空白快照清除已有非空预览，不从参数、任意元数据、思考或工具名称伪造进度。
- **AND** 五行截断只影响预览，不改变原始结果、工件或模型上下文，不为获得 Output 新增日志轮询、重复执行或模型请求。

#### Scenario: 聚合读取和助手回复不搬动原展示

- **WHEN** read 与其他 read 共用历史聚合组件，或 write 通过 `out://` 等回复路由输出助手正文
- **THEN** 预览 MUST 只取对应调用实际已有的 Output 文本，不复制或搬动整个 read 聚合组件，也不混入其他 read 的内容和状态。
- **AND** 助手正文继续经原路由保留，不能从回复参数或已显示正文补造预览；该工具若另有真实 Output 文本，仍可按统一规则显示，但不生成第二份助手回复。
- **AND** 文件型 write／edit 的原历史展示同样独立保留；临时区不双挂载原卡片、不复用其交互或图形生命周期，不因预览关闭 dispose 历史组件。

#### Scenario: 显示期间高度稳定和小终端适配

- **WHEN** 预览显示期间更换输出来源、增加 Output、开始／结束思考，或后台启动调用返回
- **THEN** 在终端尺寸和其他界面状态不变时 MUST 保持六行占用，不在来源切换之间先归零再展开，不因输出长度改变输入位置或焦点。
- **AND** 终端过小时可按既有空间分配缩减输出行，优先保留输入光标、审批及问答；不通过新的清屏、历史回填或滚动锚点系统隐藏布局问题。尺寸变化只重排当前文本，不改变来源及关闭期限。

#### Scenario: 有限异步 Bash 持续二十五秒输出

- **WHEN** 有限异步 Bash 每秒输出、持续 25 秒，其启动调用已返回或已自动转后台，且尚无较新调用产生 Output 抢占它
- **THEN** 预览 MUST 在这 25 秒运行期间持续反映已到达的 Output；loop 结束不关闭仍运行的所选任务，不依赖模型读取 `proc://`、调用 wait 或反复查询才能刷新。
- **AND** 调用耗时保持真实返回后的冻结值，后台任务状态独立按既有事实显示；只读预览更新资格不能依赖聊天历史卡片是否仍保留，ANSI 与 native 均须满足实时输出契约。

#### Scenario: 收到终态即计时且不等待可见绘制

- **WHEN** 已选来源真实成功、失败或取消的整体终态到达
- **THEN** MUST 从收到该权威终态起计时 3 秒，到期自动关闭并将预览自身占用归零，不等待终态被实际绘制，不因普通输出更新、resize 或界面重建重启计时。
- **AND** 离开当前视图、切换档位、全屏覆盖或终端反压不暂停计时；允许终态尚未被用户看到即到期，切回后不重新显示已过期终态，完整结果及原有诊断仍保留。
- **AND** 新来源可以提前替换旧终态预览，不保证每个调用都展示完整三秒；旧来源关闭动作不得关闭已经选中的新来源或其他会话。新调用仅派发而未产生 Output 时不算替换。

#### Scenario: 调用返回、早到终态及多 job 聚合

- **WHEN** 有限异步启动调用返回 running、后台终态早于启动回执到达，或一个 task 调用包含多个异步及阻塞子任务
- **THEN** MUST 以调用整体的真实结束事实决定关闭，不能因启动返回、loop 结束或 primary job 单独结束而提前计时；晚到 running 回执不得覆盖真实终态或重置关闭期限。
- **AND** 多 job 调用须等待已有权威聚合结算及仍在执行的阻塞部分结束；最后排队项取消而没有后续输出时，仍可用已有结算事实确认终态，不因缺帧永久占位，也不轮询或推定成功。
- **AND** 终态早到后立即重建或切换代理，也须保留可确定的终态和原接收期限，不退回 running，不从恢复时间重新给三秒。

#### Scenario: 关闭后不回退到旧来源

- **WHEN** 当前来源 B 的终态三秒到期，A 是较早派发且仍输出的调用，或者 B 又收到迟到帧
- **THEN** 预览 MUST 保持关闭，不回退到 A、不被 A 的迟到输出或 B 的重复终态重新打开。
- **AND** 只有实际派发顺序更晚的调用首次产生有效 Output，才可成为新的来源并重新打开；原输出来源被替换或关闭，不取消其真实任务、不改变结果投递。

#### Scenario: 合法历史空白和预览关闭范围

- **WHEN** 预览展开挤出正文到终端历史，随后自动收起
- **THEN** MUST 只释放预览自身六行占用，不保留其专属错误占位；允许 Complete Scrollback 的正常归档空间补偿空白，不为消除这些空白重放、复制或回填历史。
- **AND** 不删除原工具结果、文件历史、助手正文、工件、独立诊断或完整查看入口；不改变权限、审批、问答、取消及既有滚动行为。

#### Scenario: 无交互文本预览与现有能力边界

- **WHEN** 用户查看该区域，或所选工具无中间文本、只产生非文本结果、启动受监督服务或使用交互 PTY
- **THEN** 区域 MUST 仅显示真实已有 Output 与单行工具信息，不提供点击、展开、滚动、Shell 回放或图形控件，不参与焦点和按键路由；完整内容继续经 detailed 或已有全文入口查看。
- **AND** 不显示图片、Mermaid、SVG 或终端图形，不复制整张原卡片；无文本调用不产生预览。服务及 PTY 保持既有输出能力，不新增日志轮询、PTY 复制或后台监控。
- **AND** 服务启动调用的完成只代表启动调用结束，其真实 Output 可按该调用终态进入关闭计时，不把它冒充服务进程终态，也不等待长期服务退出。

#### Scenario: 会话恢复及两条渲染路径一致

- **WHEN** 用户切换逻辑会话、代理视图或档位后回到 compact，或相同事件分别经过 ANSI 与 native
- **THEN** MUST 使用所属逻辑会话已有派发事实和 Output 资格恢复来源，不能按最近更新缓存的迭代顺序选源，不展示其他会话内容或重新打开已到期来源；没有原会话事实时不从任意已结束历史补造当前进度。
- **AND** 同名工具和相同 call ID 的不同逻辑会话保持隔离，旧输出及旧关闭动作不能污染新视图；恢复不暂停或重置已收到终态的关闭期限，不新增未查看会话的持续跟踪或持久化系统。
- **AND** ANSI 与 native 具有相同的单行信息、五行文本、来源选择、终态接收计时及空闲零行语义，不要求在此区域提供原卡片或 Shell 图形能力；展示不重复执行、投递或触发原卡片副作用。
