# tui-presentation

## Purpose

本规格规定 fork TUI 的 clean、compact、detailed 三档显示、紧凑工具摘要与 Bash 日志呈现。显示模式只影响界面投影，原始消息、工具执行和模型上下文不随之改写。

## Requirements

### Requirement: 1. 三种显示模式

OMP MUST 用户选择 clean、compact 或 detailed 时按选定模式呈现。

#### Scenario: 1. 三种显示模式的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- **经典模式**：隐藏全部工具和思考。
- **全量模式**：通过 `detailed` 选择完整工具与思考展示，不应用 clean 隐藏或 compact 摘要裁剪。
- **紧凑模式**：默认启用，采用以下规则。

模式切换 通过 /display。

#### Scenario: 1. 三种显示模式 behavior

- **WHEN** the documented capability is used in the section's applicable context
- **THEN** 用户选择 clean、compact 或 detailed 时按选定模式呈现

### Requirement: 2. 紧凑模式规则

OMP MUST 紧凑模式按本节显示工具与模型摘要。

#### Scenario: 2. 紧凑模式规则的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

| 内容         | 显示规则                                                                                                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 活动区边界   | 从首次输入到正常完成、用户终止或不可恢复错误结束本轮，始终算同一轮；**中途插话不拆轮，中间的普通文本不视为任务结束**。本轮结束后的下一次新输入才创建新活动区，并将上一轮转为历史。 |
| 历史消息     | 隐藏已结束的工具、diff 和思考，保留正常对话；仍在运行的后台任务按下述规则保留状态。                                                                                                                                       |
| 消息顺序     | 沿用上游消息的先后顺序；保留的写入 diff 位于对应工具调用处，聚合工具预览与统计位于最近相关调用处。调用之后的回复必须显示在工具反馈之后，不得把工具区固定追加到最终回复下方。ANSI 与 native 路径遵循相同顺序；折叠、数量限制与历史隐藏规则不变。 |
| 普通工具     | 默认最多 **2 次调用，每次 1 行**。正在执行的调用优先，其余位置补最近调用（例外：如果正在运行中的工具超过2个，按实际的运行命令为准）；内容按**意图优先、实际执行的 Bash 命令其次**展示。超长内容折叠，完整命令保留供查看。 |
| 摘要行       | 仅当本活动区的**累计工具调用次数大于当前普通工具预览实际显示的调用行数**时，另占 **1 行**显示累计调用次数与累计失败次数；文字和颜色均使用低强调样式，不加粗。普通工具预览与摘要通常合计最多 **3 行**；运行中工具超过 2 个时按上行例外显示，diff 和长任务日志另计。 |
| 统计归属     | 调用及失败次数归调用发起时的活动区；旧后台结果不计入新轮，也不展开旧历史；同轮压缩不清零。 |
| 当前思考     | 持续显示真实思考输出的最近 **2 行**，用于观察输出是否持续。活跃思考的最新行使用 `thinkingText`、上一行使用 `dim`，与普通对话正文区分；思考阶段结束进入工具执行后，保留尾窗并整体使用 `dim`，直至本轮结束。只有一行内容时保留第二行空白。 |
| 写文件类工具 | 仅实际写入或修改文件的 **write/edit** 调用计入，合计保留最近 **3 次**；读取、预览及未写入的失败调用不计入此类。**保留的 3 次调用全部展开，均不得折叠**，显示各自对应的写入内容及 diff，不改成标题行、折叠摘要或文件汇总。 |
| 后台任务状态 | 尚未结束的后台任务保留状态入口，不因进入历史或超出普通工具的数量限制而消失；日志遵循下一节规则，结束后按所属轮次处理。                                                                                                    |

- 写文件区高度受限时，最近 3 次写入仍全部保持展开，通过滚动查看超出视口的内容；ANSI 主输入框聚焦且没有弹窗时，`PageUp`／`PageDown` 翻页查看完整写入区，输入草稿保持不变；已启用 `tui.mouse` 时可用滚轮滚动，native 使用自身滚动视口。不得因调用较旧、最新 diff 过长或屏幕高度不足而折叠任一次调用，也不得仅保留标题行、裁掉正文或在截断处追加 `/display detailed` 提示。最近 3 次的数量限制、消息顺序及本轮结束后的历史隐藏规则不变，ANSI 与 native 遵循相同规则。
- 工具预览、累计统计、Bash 日志与思考预览统一左右各留 **1 个字符**，正文左边界与普通助手回复对齐，不额外嵌套缩进。折行、截断先扣除两侧留白；极窄终端不得溢出。
- 用户消息、普通回复、工具活动区与思考预览之间使用 **1 行**空白区分；已有相邻空白不叠加。工具区内调用、统计与日志紧排，不因只有一个调用而在区内插空行；思考内部不额外插空行，不新增标题、竖线、边框或背景卡片。
- 区域分隔计入实际高度预算，不计入工具、统计、日志或思考的内容行数上限。屏幕高度不足时优先工具反馈与可编辑输入，分隔可让位，不能因新增留白挤掉必要内容；ANSI 与 native 使用一致的留白、配色和内容边界。

#### Scenario: 最近三次写入均保持展开

- **WHEN** 当前活动区存在最近 3 次实际写入或修改文件的调用
- **THEN** 3 次调用均展示各自的写入内容及 diff，不折叠前两次，也不提供将其中任一次收成标题或摘要的折叠状态。
- **AND** 新写入到达后，只移出超过最近 3 次范围的旧调用；保留的调用仍全部展开。视口高度不足或 diff 较长时通过滚动查看，不改变真实写入、原始记录与模型上下文。

#### Scenario: 紧凑活动区对齐与分隔

- **WHEN** 用户消息之后出现一个或多个工具调用、累计统计、长任务日志及真实思考预览
- **THEN** 这些内容与助手正文采用相同的一字符水平留白；工具区内紧排，区域边界仅一行空白，单工具和多工具不产生不同的额外空白层。
- **AND** 命令、中文与宽字符按扣除留白后的宽度折行或截断；窄屏仍保留工具与输入的优先级，不改变消息顺序、真实执行和模型上下文。

#### Scenario: 并行工具超出视口与缩放

- **WHEN** 紧凑模式中运行工具的行数超过可用视口，或用户缩放终端且当前没有写入 diff
- **THEN** 输出行数不超过分配高度；超出的运行调用沿用已有滚动视口，通过 `PageUp`／`PageDown` 和已启用的滚轮查看，不丢弃调用或改写原始内容，输入草稿保持不变。
- **AND** 正常绘制与缩放绘制复用同一紧凑投影，保留普通工具预览、统计及适用的日志；缩放仍可呈现上游原有的历史尾部，不因缺少写入 diff 而隐藏活动区。

#### Scenario: 2. 紧凑模式规则 behavior

- **WHEN** the documented capability is used in the section's applicable context
- **THEN** 紧凑模式按本节显示工具与模型摘要

### Requirement: 3. 紧凑模式下的 Bash 日志

OMP MUST Bash 输出按本节时间与日志规则呈现。

#### Scenario: 3. 紧凑模式下的 Bash 日志的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 同一命令累计运行**超过 30 秒**，才自动显示最近几行日志并持续更新；短时间成功结束的命令不展示输出。前台同步、异步后台采用相同规则。
- **失败或需要用户输入时立即提示，不等待 30 秒**；短命令失败至少显示一行错误原因。
- 显示命令已运行时长；没有新日志时，显示距上次输出的时长，尚无输出时明确标注。
- **前台转后台不重置计时，日志显示不中断、不清空**，继续跟随同一任务的输出。
- 日志区最多 **6 行：1 行状态＋5 行日志**；多任务共用这一上限，日志标注任务标识，并按输出时间保留最新内容。
- 日志由 **OMP 自动维护，仅刷新界面**；不依赖大模型轮询，不为刷新日志新增模型请求、工具调用或 Token 消耗。

#### Scenario: 3. 紧凑模式下的 Bash 日志 behavior

- **WHEN** the documented capability is used in the section's applicable context
- **THEN** Bash 输出按本节时间与日志规则呈现

### Requirement: 紧凑工具反馈可读性

OMP MUST 在紧凑模式下以短任务标识、有效失败摘要及中文工具状态呈现执行反馈；ANSI 与 native 使用一致的显示规则，不改变原始 ID、工具结果和模型上下文。

#### Scenario: 多任务日志使用稳定短标识

- **WHEN** 一个或多个 Bash 调用显示运行日志、输入等待或失败提示
- **THEN** 日志使用形如 `[任务1]` 的短编号代替完整 call ID；不同调用可区分，同一调用在刷新、预览换位及同轮压缩重建后保持编号。内部调用关联、失败归属和原始记录仍使用完整 ID，不新增展开或复制交互。

#### Scenario: 结构化错误不只显示结束符

- **WHEN** 短 Bash 调用失败，错误输出包含实际原因，但末尾是独立的 JSON 花括号、方括号或逗号
- **THEN** 立即显示实际原因，而不是仅显示这些结构符号；若只有空白或结构符号，则显示明确的命令失败提示。摘要沿用错误色、宽度截断和共享日志行数上限，不等待 30 秒，不删除或改写全量模式的原始输出。

#### Scenario: 中文状态对应真实执行状态

- **WHEN** 紧凑工具行显示等待执行、执行中、成功、失败或取消状态
- **THEN** 分别使用“待执行”“执行中”“完成”“失败”“已取消”的显示标签，保留已有“等待用户输入”“待确认”“已应用”专用标签。协议枚举、工具标识、命令、实际输出和模型内容保持原样，普通工具最多两条、统计行低强调及现有布局配色不变。

### Requirement: 发送后的长用户消息

OMP MUST 在紧凑模式下统一折叠发送后的长用户消息，覆盖长粘贴、提示词模板展开和 `/review` 提示词；折叠只影响 TUI 显示。

#### Scenario: 超过六个屏幕行

- **WHEN** 发送后的用户消息按当前显示宽度排版后超过 6 个屏幕行
- **THEN** 只显示前 5 行及一行“已折叠 N 行，切换全量模式查看”，N 为未显示的内容行数；当前轮和历史轮使用相同规则。不超过 6 行时完整显示，切换全量模式后显示全文。

#### Scenario: 内容与输入行为保持完整

- **WHEN** 用户粘贴长文本、使用提示词模板或执行 `/review`
- **THEN** 输入框沿用现有粘贴标记和附件预览，模板展开及 review 行为不变；保存、模型接收和复制的内容均为全文，不调用模型生成摘要。经典和全量模式保持现有规则。

#### Scenario: review diff 不占写入展示名额

- **WHEN** `/review` 展开的用户提示词包含长 diff，且活动区存在真实 write/edit 调用
- **THEN** 提示词中的 diff 按长用户消息折叠，不占实际 write/edit 最近 3 次的展示名额。实现集中在用户消息的 TUI 显示，不改动粘贴选项、模板展开或 review 业务链路。

### Requirement: 4. 显示投影边界

OMP MUST 显示模式切换只改变投影，不改模型上下文。

#### Scenario: 4. 显示投影边界的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 本文全部改动（包括 Bash 实时输出、摘要、历史投影和模式切换）**只调整或优化界面显示**：不得增删、截断或改写发送给大模型的消息、工具调用与结果、上下文或 Token；不得改变工具执行、审批、后台任务、会话持久化及其他实际功能。界面用的日志尾窗、折叠和计时不得回写模型上下文。

#### Scenario: 4. 显示投影边界 behavior

- **WHEN** the documented capability is used in the section's applicable context
- **THEN** 显示模式切换只改变投影，不改模型上下文

### Requirement: 简体中文用户界面

OMP MUST 导航和说明使用简体中文，命令、模型标识及机器字段保持原样。

#### Scenario: 简体中文用户界面的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 本节限定的主要 TUI 操作界面中，有实际使用价值的导航、操作、状态与说明文字使用简体中文；汉化不是逐词强制中文化。专有名词、不应翻译的技术词及中文用户通常能直接理解的英文保留原样，不为追求全中文生造译名。不新增语言配置、多语言框架或运行时翻译流程。汉化只改变展示文字，不改变功能、业务执行流程、默认值、权限、选择结果、持久化格式或协议。
- 本次只覆盖主要 TUI 操作界面：欢迎与输入区、完整设置页（分类、分组、名称、说明、风险提示、选项及二级编辑）、常用模型／账户／会话选择、问答与授权弹窗、计划审阅，以及基础状态栏与输入区的必要操作提示。保留原有欢迎提示和中文文案；ANSI 与 native 路径保持一致。不扩展到文档正文、CLI 命令帮助、安装器、统计／协作网页、工具展示卡片、独立终端应用、索引管理面板或后台宿主通知。
- 只翻译显示层：命令及子命令名称、参数名、配置键、环境变量、枚举存储值、模型／Provider／工具标识、路径、代码、快捷键及占位符、URL、结构化输出字段保持原样；品牌与技术专有名词按需保留。现有显示标签与实际值分离时只改标签；既有界面直接返回标签、且仅在本地按同一标签选择动作时，可同步替换配对的标签字面量，但不得改变判断结构、动作语义或对外机器值。
- 品牌、产品、模型、工具、协议、编程语言及开发生态常用术语保留英文，例如 Agent、Subagent、Provider、Skill、Hook、Prompt、Token、API、CLI、TUI、RPC、SDK、MCP、LSP、OAuth、Git、Diff、Markdown、JSON、YAML、Bash、Shell、Eval、Vim、Unicode、ASCII、Nerd Font、Snapcompact、Prewalk、Fireworks、Mnemopi、Hindsight、Sharpshooter；不翻译用户或第三方自定义的名称。普通导航、按钮、操作指引与解释性句子翻译为自然中文，句中的这些术语保持英文。
- 不翻译模型系统提示词、工具 schema／协议说明、Skill 正文、第三方内容、用户输入、文件正文和实际命令输出。原始错误、错误码与诊断日志保持可检索；可翻译 OMP 外层的面向用户说明，不改机器消费的错误契约与状态标记。
- 保留既有布局、显示宽度计算、换行、截断、搜索、排序、快捷键与取消行为；不为汉化重构界面或调整业务。中文文案应简明、术语统一，避免用英文替换另一处已正常工作的中文。

#### Scenario: 简体中文用户界面的可观察行为

- **WHEN** 打开主要 TUI 设置、选择或授权界面
- **THEN** 导航和说明使用简体中文，命令、模型标识及机器字段保持原样

### Requirement: 快捷键与状态栏

OMP MUST 状态栏和帮助按既定顺序及窄屏规则显示，不让帮助整段消失。

#### Scenario: 快捷键与状态栏的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- `Shift+Tab`：计划模式。
- `Ctrl+T`：临时模型。
- `Alt+P`：thinking blocks 显示/隐藏。
- `Shift+F1`：循环切换 thinking level。
- ANSI 终端的空输入框固定显示 `Ctrl+T 临时模型 Ctrl+Q 排队发送 Esc Esc 回退对话 /tree 会话历史 /goal-autopilot 目标 双击左方向键<- 子代理 /wiki 文档检索 /repo 代码索引 有使用问题反馈j00808874`，使用空格分隔，不加圆点分隔符，反馈联系方式固定放在最后；只作为帮助文字，不随状态、使用次数或自定义按键变化；帮助文字靠左显示，与光标保留两个字符间距，剩余留白放在提示之后。宽度不足时按实际显示宽度自动换行，不能因整段放不下而全部隐藏；仍受现有屏幕高度上限约束。输入文字后隐藏帮助，清空后恢复；复用既有占位提示布局，不新增配置或轮播；“回退对话”不表示撤销文件修改。
- ANSI 终端主输入区至少占两行内容；输入正文或帮助文字下方保留一整行完全没有文字的留白。多行正文、自动折行与帮助换行按实际内容行数加这一行留白展开，仍受现有屏幕高度上限约束；高度不足时优先保留光标所在输入行。留白只在框内，不增加框外间距。
- 状态栏 `default` preset 从左组移除 `vim`、`pr`、`cost`，增加 `subagents`、`token_rate`、`cache_hit`、`time_spent`；前三项位于 `git` 之后、`context_pct` 之前，`time_spent` 位于 `context_pct` 之后。右组移除 `session_name` 后为空，零配置启动即生效。
- Git 段统一显示纯文本 `git main · 改动5`，不显示 Git／分支图标及 `*`、`+`、`?` 分类符号；改动数为已暂存、未暂存、未跟踪文件的并集，同一文件同时有暂存与未暂存改动只计一次，未跟踪目录内按文件逐个统计，忽略文件不计入。零改动时省略数量；无分支或用户关闭分支显示时只显示 `git 改动5`，分支与数量都不可见时隐藏该段。ANSI 与 native 界面采用同一文字与计数规则；既有三类显示选项仍控制是否计入对应类别。
- 配置中的 `subagents` 段按所属组与顺序显示，运行中的子代理徽章不得强制移到右组或重复显示。
- 输入框顶边的 `statusLine.contextLine=embedded` 模式把上下文使用率与窗口容量合并为靠右的 `ctx 3% · 500K` 信息组，容量与说明文字弱化，组后留两个字符间距；使用率变化不让标签沿横线移动。保留用量横线，不显示预压缩与自动压缩的两根刻度，不改变压缩功能（显式选择 `annotated` 模式仍显示刻度）；未知用量只显示容量，超过 100% 的真实比例仍以错误色显示。路径先按配置的缩写上限显示，仅在状态段与上下文信息确实放不下时从左侧截断、保留末尾目录；状态段移入溢出行后，释放的宽度必须重新分配给路径（不超过配置上限），用量横线只填剩余空间；顶边放不下时沿用状态栏溢出显示。
- 盒式输入区中的 fork 状态栏支持窄终端自动换行。
- 设置向导的主题选项「Match terminal」保留已配置的深色主题，只把浅色主题映射为 `light`；选择该项不会把现有深色主题覆盖为 `titanium`。

- **THEN** 状态栏和帮助按既定顺序及窄屏规则显示，不让帮助整段消失
