# tui-presentation

## Purpose

本规格规定 fork TUI 的 clean、compact、detailed 三档显示、紧凑工具摘要与 Bash 日志呈现。显示模式只影响界面投影，原始消息、工具执行和模型上下文不随之改写。

## Requirements

### Requirement: 1. 三种显示模式

OMP MUST 按 `/display` 选择的 `clean`、`compact` 或 `detailed` 呈现同一份原始会话，默认使用 `compact`；三种模式只改变显示投影，不改变消息、工具、思考原文及其归属。

#### Scenario: 1. 三种显示模式的详细边界

- **WHEN** 用户选择任一显示模式
- **THEN** `clean` 隐藏全部工具活动、工具结果图片及全部真实思考；`compact` 使用本规格的局部工具段、写入段和固定思考区域；`detailed` 沿用上游完整工具与思考展示，不应用 clean 隐藏或 compact 摘要与数量裁剪。
- **AND** 模式切换继续通过 `/display [clean|compact|detailed]`，无参数切换和模式保存沿用既有行为；不新增模式、别名或显示开关。
- **AND** 既有配置覆盖来源与优先级、`terminal.showImages` 和 `images.*` 的独立含义不变；模式切换不隐式改写这些图片设置。

#### Scenario: 1. 三种显示模式 behavior

- **WHEN** 用户选择 clean、compact 或 detailed
- **THEN** 当前视口、之后的新消息、历史重建与代理视图按当前有效模式呈现，不出现旧模式残留的工具或思考块。
- **AND** 模式切换不修改模型上下文、原始消息、复制全文、会话持久化、工具结果或执行顺序。

#### Scenario: clean 不显示实时思考占位或可展开思考

- **WHEN** clean 下模型开始或持续输出真实思考，之后思考完成、失败或取消
- **THEN** 聊天消息中均不显示思考正文、`Thinking` 等思考标题、完成提示、动画占位、可展开的思考节点或空白消息块，输入区也不保留 compact 的固定思考区域。
- **AND** native 不发送可由用户展开查看的隐藏思考正文节点，ANSI 不退回仅隐藏正文但保留实时标题的展示。
- **AND** 普通助手正文不按颜色、包含的 `Thinking` 单词或类似措辞识别为思考；原有用户输入、审批及其他必要交互入口仍可达。

#### Scenario: detailed 保留上游完整内容与原组件

- **WHEN** 用户从 clean 或 compact 切换为 detailed，或直接以 detailed 恢复包含工具、写入、思考和长用户消息的会话
- **THEN** 按上游原顺序与位置显示全部工具调用及结果、思考和用户全文，不保留 compact 统计摘要、最后两条／三个筛选或专用单行思考区域。
- **AND** 展开、折叠、图片、截断、复制与滚动遵循上游原组件和既有独立设置；完整可查看不等于强制展开全部内容。

### Requirement: dark-terminal 可选主题局部柔化

OMP MUST 保留可选 `dark-terminal` 主题的既有结构，仅将其绿色与红色语义变量改用现有 `dark` 主题的 `#89d281` 与 `#fc3a4b`，强调色引用该绿色；不修改其他独立颜色、背景与语法高亮。默认深色主题按[运行默认值](../fork-runtime-defaults/spec.md)使用上游 `titanium` 原配色，此局部柔化仅在用户选择 `dark-terminal` 时生效。

#### Scenario: 可选 dark-terminal 主题的状态与强调颜色

- **WHEN** 使用 `dark-terminal` 主题显示强调、成功或错误
- **THEN** 使用柔化后的绿色或红色；其他主题、显式独立颜色、用户主题选择与配置优先级保持不变。

#### Scenario: 默认深色主题与上游一致

- **WHEN** 普通或 offline 进程未显式配置深色主题
- **THEN** 使用 `titanium` 及其上游内置原配色，不对 Titanium 应用 `dark-terminal` 的局部柔化；已有显式主题配置继续优先。

### Requirement: 紧凑模式连续工具段

OMP MUST 在 compact 中仅对原位置的连续工具段局部折叠，隐藏消息流中的全部思考块，并在输入区上方的单一固定区域展示活跃真实思考；工具消息顺序、原组件、输入区锚定、布局、滚动及历史归档继续沿用上游机制，不维护整轮工具活动区，不通过移动输入框消除工具空白。

#### Scenario: 连续普通工具段在原位置分组

- **WHEN** 上游消息顺序中出现连续普通工具调用
- **THEN** 仅将该连续段作为一个局部折叠单元，不跨可见助手正文、用户消息或文件写入调用合并；隐藏思考、工具自身结果与附属执行反馈不单独打断所属调用段，不跨已归档边界重新合并。
- **AND** 遇到边界后，后续普通工具开始新段；不同段保留原位置，回复位于对应反馈之后，不收集到整轮末尾或最终回复下方。
- **AND** 分段只作用于显示，不改变上游模型轮次、消息归属或工具执行顺序。
- **AND** `write agent://<id>` 与 `write agent://all` 的 Message 属于普通调用，待执行和成功发送均参与同段计数与最后两条筛选；调用错误按下述静默规则处理，待用户处理继续保留原始反馈，不占文件写入名额。
- **AND** `write proc://<id>`、`write proc://<id>/mode` 与 `write proc://<id>/kill` 的 Process 同样属于普通调用；待执行和成功结果不建立文件写入边界，调用错误静默，待确认与输入等待保留原反馈，不改变进程输入、模式切换或取消行为。
- **AND** `write cfg://...` 的 Config、`write xd://<tool>` 的非文件操作和设备帮助不因最外层名称为 write 而分段；实际文件 write／edit／apply_patch 仍保留写入边界与原组件，调用错误同样静默，不改变配置审批、保存或设备执行。
- **AND** 子代理查看／返回等 UI 状态提示保留原位置与既有显示，但不作为普通工具段或连续写入段边界，不参与调用或失败计数，不占普通预览或实际写入名额；提示前后仍按同段规则筛选。

#### Scenario: 普通工具段只保留最后两条默认预览

- **WHEN** 一个普通工具段包含一个或多个调用
- **THEN** 默认折叠态按上游调用顺序选择最后至多两次，各显示一行，不补空白调用行；没有实际调用时不生成空工具段、摘要或占位。
- **AND** 预览保持意图优先，Bash 无意图时使用实际命令；超长内容沿用既有宽度截断，全文保留供查看。
- **AND** 不按运行状态、完成先后或结果到达时间重排、补位，运行中调用超过两个也不扩大普通预览条数。
- **AND** 会话和同一轮可以有多个局部工具段，不将整轮或整个会话统一限制为三行；关键反馈遵循本需求的数量例外。

#### Scenario: 摘要仅统计所属普通工具段

- **WHEN** 一个普通工具段包含 N 次实际调用
- **THEN** N 不超过二时不显示统计摘要；N 大于二时在普通预览之前增加一行本段调用总次数，文字和颜色低强调且不加粗，不展示工具调用失败计数。
- **AND** 摘要到普通预览、普通预览彼此之间连续显示，不插额外空行；没有摘要时普通预览也连续显示。段内 UI 状态提示仍保留原位置及原有间距。
- **AND** 只取消普通工具行之间的额外分隔，保留段外间距、write/edit 原组件以及错误与待处理交互原有边距；实时、历史归档、重建与缩放采用同一规则，不移动输入框补偿空白。
- **AND** 统计只包含所属普通工具段的实际调用，包含被静默隐藏的调用错误，不包含相邻写入段、其他段或其他轮次；一个聚合调用包含多个子任务，不据此增加工具调用次数。
- **AND** 同次调用的参数流式更新、ID 修正、结果到达、重绘、重建和上下文压缩不新增调用计数；旧后台结果更新所属段，不记入新段。
- **AND** 同一集合分批进入历史时，已经发布的所属段摘要只保留一次，不为剩余调用反复生成计数递减的摘要；真正新段仍独立统计，不改写已归档摘要。

#### Scenario: 连续写入段保留最后三个原组件

- **WHEN** 连续 write/edit/apply_patch 调用实际写入或修改文件
- **THEN** 在所属连续写入段只保留最后至多三次实际写入的原组件，保持上游顺序与位置；一轮可有多个独立写入段，不在整轮或全会话全局只保留三个。
- **AND** 普通工具或可见非工具内容结束该写入段，UI 状态提示除外；读取、预览、未实际写入的失败调用不占实际写入额度，失败与待确认仍遵循关键反馈例外。
- **AND** 保留组件的展开、折叠、截断、文件内容、diff 与滚动沿用上游，不强制全部展开，不改成文件汇总，不建立写入专用分页或额外高度预算。
- **AND** `conflict://` 成功修改文件属于实际写入，保留组件显示各成功文件基于修改前后内容生成的 diff；批量部分失败同时保留原始错误，不将失败文件显示为成功。
- **AND** 后续写入只更新正在形成的所属段，不因新段出现删除或改写已归档的旧写入段。

#### Scenario: 文件型 URL 与等价磁盘路径使用同一写入规则

- **WHEN** write 通过 `local://` 或当前已支持的其他文件型 URL 成功执行真实文件写入
- **THEN** 按实际文件操作归入写入段，不仅因参数包含 URL 前缀而降为普通摘要或排除出实际写入额度。
- **AND** 同段四次成功 `local://` 写入与四次等价磁盘文件写入均只保留后三次原 Write 组件；保留内容、diff 和正常原组件间距，不留下被筛掉调用的空白单行。
- **AND** 失败、待确认和混合成功／失败仍按各调用真实事实处理，不因 URL 类型豁免关键反馈。

#### Scenario: 设备运输不改变内层文件与非文件操作归类

- **WHEN** 已有设备派发事实表明 `write xd://write` 的内层目标为 `agent://...`、`proc://...` 或 `cfg://...`
- **THEN** 使用与直接调用相同的 Message／Process／Config 普通工具段规则，既不切出文件写入段，也不占最后三个实际写入名额。
- **AND** `read → xd://write(agent://peer) → bash` 在没有其他边界或关键反馈时是同一个三调用普通段，显示一条统计及最后两次普通预览，普通摘要行间无额外空白。
- **AND** 设备内层确实执行文件 write／edit／apply_patch 时按相应实际写入事实处理；帮助、未执行、失败和待确认不仅凭派发工具名就算成功写入。
- **AND** 参数仍在生成、实际目标尚不可确定时继续使用已有待执行显示；完整目标和结果到达后按真实分类更新，不伪造执行或写入事实。

#### Scenario: Agent 工具调用错误默认静默

- **WHEN** compact 默认折叠态下工具返回 `isError`，但没有实际命令的非零退出／超时、部分已应用文件修改、原工具识别的后台／子代理失败或独立诊断，也不需要用户确认或输入
- **THEN** 不显示该调用的错误卡片、错误明细或失败状态行，不生成替代提示或空白占位；独立调用、分组读取和设备包装采用相同规则。
- **AND** 不改写原始结果、模型上下文或会话记录，Agent 仍收到完整错误并自行处理；用户显式展开或切换 detailed 仍可查看原始错误。
- **AND** 调用仍计入所属段总次数与原有最后两条选择，不因隐藏错误新增补位、排序或历史机制。

#### Scenario: 实际执行失败与用户交互不受普通预览数量限制

- **WHEN** 调用含实际命令的非零退出／超时、部分已应用文件修改、原工具识别的后台／子代理失败、取消、独立诊断，或需要审批、确认、用户输入，即使不在最后两条普通预览或最后三个实际写入内
- **THEN** 在原位置保留错误状态、反馈和已有交互入口，不等待其他调用结束才显示；Bash 折叠错误正文按「Bash 错误预览限定正文行数」显示，其他关键反馈保持原机制；工具报告的内嵌终态依「紧凑反馈沿用上游执行事实」判断，单独的调用层 `isError` 不触发此例外。
- **AND** 该段允许超过普通摘要加两条预览的三行上限；不为重新压到三行而隐藏或搬动关键反馈，不新增排序规则。
- **AND** 设备包装调用同样适用，不因使用不同组件而失去真实待处理标记；分组读取的调用错误按上述静默规则隐藏。
- **AND** 已由 wait 消费的对等消息依「紧凑等待行摘要」保留，不因通用成功状态而落入可丢弃普通预览。
- **AND** 反馈随上游真实状态更新，审批、输入、取消和工具实际执行行为不随显示折叠改变。

#### Scenario: 单一固定区域展示活跃思考

- **WHEN** compact 按当前显隐设置展示真实思考输出
- **THEN** 消息流中的当前及历史思考均不显示正文、标题、完成提示或空白占位；普通助手正文不按颜色或措辞当作思考隐藏。
- **AND** 仅在输入框最上方、附件预览及上方扩展组件之后保留一个固定单行思考区域，其与输入框之间固定保留一空行；位置相对输入框固定，不随聊天滚动、不硬编码终端行号，复用上游底部布局和瞬态组件，不创建独立视口或滚动区，不移动现有工具行。
- **AND** 优先展示当前会话活跃真实思考按当前宽度排版后的最新非空一行，使用与 ultrathink 一致的静态渐变，不新增动画定时器；从后向前跳过去除 ANSI 后全为空白的行，不回显结束的旧思考，不生成、补写、汇总或改为多行。
- **AND** compact 始终保留思考行及下方空行；无可显示思考时可按下述规则显示实时工具输出，无可用输出或取消时只清空文字，不收起区域，不因内容显隐或长度改变聊天和输入框的垂直布局，不把旧思考或工具输出留给下一次。
- **AND** 固定两行计入正常布局，不进入聊天历史、不延长消息或工具生命周期，不建立不同于上游的归档策略；原文和归属完整保存，detailed 在原位置展示完整思考，clean 不保留该区域。

#### Scenario: 无思考内容时显示实时工具输出末行

- **WHEN** compact 固定思考区域没有可显示的活跃真实思考，当前查看会话的工具产生实时 stdout
- **THEN** 复用既有工具实时输出快照，显示最近更新工具输出的最后一条非空文本行，不加工具名、调用说明、状态前缀或完成标记；沿用现有字体、静态渐变、位置、单行宽度裁剪及下方空行，现有工具行和完整输出入口保持不变。
- **AND** 按工具实际输出事件更新，不轮播、不调用模型生成摘要、不新增轮询或输出通道；Bash 沿用既有 stdout/stderr 合并通道，Eval 取执行中单元的 stdout，其他无可辨认实时 stdout 的工具不强制生成或补齐，也不把工具状态或通知当作 stdout。
- **AND** 新的可见思考立即恢复既有思考显示；工具完成、后台任务终态、取消或切换会话后，不回放已结束、历史或其他会话的输出；没有可用输出时保留固定空行，clean 与 detailed 不启用该回退。


#### Scenario: 多次工具与思考交替不累计思考历史

- **WHEN** 普通工具与真实思考连续交替一百次
- **THEN** compact 始终只有一个固定思考区域，不产生一百个历史思考块，隐藏思考不构成可见分段边界；工具继续按局部段预览、摘要和上游归档规则显示，不承诺整轮工具历史恒定行数。
- **AND** 中途出现正文、写入、失败或待处理交互时，其原有展示和分段规则保持；切换 detailed 后全部原始工具与思考仍可查看。

#### Scenario: 已显示工具段正常进入历史

- **WHEN** 工具段按上游生命周期进入历史，或用户开始下一轮输入
- **THEN** 按上游机制正常归档，不因下一轮开始统一清除旧工具与 diff，不为移动最近调用、更新摘要或筛选新写入回头改写已归档历史；思考原文保留但不进入 compact 的显示历史。
- **AND** 后台任务状态入口、输出更新与取消沿用上游；完成回执按紧凑历史筛选，不为跨轮常驻设独立活动区或改变任务生命周期。

#### Scenario: 缩放与窄屏继续使用上游布局

- **WHEN** 终端宽高变化，或保留的工具、写入、思考超过可用视口
- **THEN** 局部分段与筛选不变，普通摘要和预览连续且无额外空行，段内 UI 提示保持原间距；其余换行、宽字符处理、截断、分隔、滚动和输入区分配继续沿用上游，不在最终绘制后重新拼版或用独立高度预算凑工具行数。
- **AND** ANSI 与 native 使用相同分段、预览选择、段内统计、连续显示和关键反馈例外，其余原组件边距、展开及滚动不变，不强制两端使用背景卡片或统一字符串重画。
- **AND** 历史与当前视口使用上游一致的底部布局和归档机制，固定思考两行计入正常占用；底部区域增高时，超出视口的内容按上游策略保持可见或可由历史查看，不得同时丢出视口和回滚历史。
- **AND** `Complete Scrollback` 的开启与关闭在三种模式中各自保留上游语义，不因 compact 隐式等同于开启；收缩和缩放后消息顺序不变，不重复、不丢失。

#### Scenario: 流式表格前部仍可查看

- **WHEN** 流式正文或表格尚未稳定，前部行超过 ANSI 聊天区的实际可见高度、不能进入终端回滚历史
- **THEN** 三档共享同一转录视口的未归档行导航；空输入框下使用既有 PageUp／PageDown 绑定翻页，已启用鼠标报告时可在聊天区使用滚轮，溢出提示保持在实际可见区域内。
- **AND** 浏览前部时新内容继续接收，追加内容、列宽变化及终端缩放不强制跳回末尾；Esc 只退出浏览、不取消生成，返回末尾或开始输入后恢复原有跟随和压力归档，结束后的正文按原顺序仅归档一次。
- **AND** 不提前将可变表格写入终端历史，不改变 `Complete Scrollback`，不新建 compact 专属视口；草稿、弹窗、其他焦点组件、链接提示模式和 native 原有滚动继续拥有各自输入。

#### Scenario: 内容收缩后输入区跟随

- **WHEN** compact 中已有终端历史，工具折叠、HUD 消失、面板关闭或草稿收缩使可见内容变短
- **THEN** 输入框继续遵循相同终端尺寸、输入状态及相关配置下的上游锚定行为；上游会保持输入框位置的情形，compact 不得额外将输入框及固定思考区域上移。
- **AND** 不通过禁用上游位置补偿、改变临时区域归档语义、移走输入框或重建独立底部布局消除工具空白。
- **AND** 同一普通工具段内部的额外空行仍须消除；上游正常布局保留的输入区补偿、段外间距、输入框内留白及固定思考两行不作为移动输入框的理由。
- **AND** 在 `100×28`、`120×36` 及两者互相缩放时均遵守该规则；不将输入框锁死到绝对终端行号，也不取消上游在缩放、多行输入、附件等条件下本来允许的正常布局变化。

### Requirement: 紧凑模式 Bash 上游反馈

OMP MUST 在紧凑模式下复用上游的 Bash 输出、展开、计时、前台及后台反馈机制；普通调用可按连续工具段折叠，已结束的错误调用按下述规则精简折叠正文，但不得建立 fork 专有的延迟日志窗口、独立日志尾窗或刷新生命周期。

#### Scenario: Bash 不再使用专有定时日志窗口

- **WHEN** Bash 在前台运行、转入后台或持续输出
- **THEN** 输出的到达、预览、展开与运行时长按上游行为呈现；不再附加超过三十秒才显示的触发条件、共享六行日志配额、距上次输出计时或 fork 专有日志滚动区。
- **AND** 后台任务的计时、状态、输出和完成反馈直接跟随上游事实；紧凑显示不重新启动计时、不修改前后台转换，也不另行保存一套跨转换日志状态。
- **AND** 紧凑工具行在前台转后台后继续显示从原任务开始累计的时长，不从零重新计时，也不把前台调用返回误标为任务完成；会话内重建使用现有后台任务的真实开始时间，完成后使用真实执行耗时。复用既有组件、任务事实与计时刷新，不改变进程、截止时间或归档生命周期。

#### Scenario: Bash 错误预览限定正文行数

- **WHEN** compact 模式下 Bash 已返回错误结果，且用户未显式展开
- **THEN** 保持既有卡片布局、标题、Output 标签与真实错误状态；ANSI Bash 输出卡片底部不显示 `Exit: N`，compact 普通失败使用中性边框和背景，仅小面积强调失败状态，不整框染红。折叠底部省略重复计时、普通超时配置和服务 PID，保留工件入口与独立诊断；展开仍可查看完整技术信息。
- **AND** 空白行和仅含 ANSI 样式的空行不占输出名额；长行按可用宽度截断，不因自动换行增加正文行数，不增加单独的隐藏行计数提示。
- **AND** 命令正文只显示第一行，Output 正文显示最后至多两行非空内容，保持原顺序；若尾部是 Bun 的脚本退出包装提示且前面还有输出，则优先预览前面的诊断，只有包装提示时保留该提示，不编造未提供的原因。ANSI/native 遵循相同额度，卡片仍按关键反馈例外保留原位置，不受普通工具最后两条名额限制。
- **AND** 只改变显示预览，原始结果、模型上下文与会话记录保持完整；显式展开或切换 detailed 可查看原始命令及完整诊断。正常调用、持续输出、审批、确认和用户输入继续使用既有机制。

#### Scenario: 显示不增加执行或模型活动

- **WHEN** Bash 输出刷新，或用户展开、折叠和滚动已有反馈
- **THEN** 仅使用上游已有显示行为，不为刷新新增模型请求、工具调用、轮询提示、Token 消耗或工具执行，不改写原始结果及持久化内容。

### Requirement: 紧凑历史的后台和进程回执

OMP MUST 隐藏自动后台任务完成回执的状态行，保留独立诊断及原工具结果；受监督进程回执遵循下述筛选，clean 按工具活动隐藏规则处理。

#### Scenario: 后台任务回执逐项筛选

- **WHEN** 已有后台任务回执包含成功、失败或取消的任务
- **THEN** 所有显示模式均隐藏自动后台任务完成回执的状态行，不将其作为新的工具调用或折叠 Bash 行；独立工件或结构化诊断仍可见。
- **AND** 实时和历史重建使用同一筛选，不改变原工具结果、投递、查询、模型上下文或任务生命周期。
- **AND** `wait` 中未被原卡片承载的失败 Bash 结果折叠时标明并显示输出末尾最多两条非空行，不把截断片段首行当成失败原因；保留可用工件入口，工件仅为样本时明确说明。其他任务错误保留原摘要；ANSI 与 native 显示一致，不改变原始输出。

#### Scenario: 守护进程退出回执按退出结果裁剪

- **WHEN** 受监督进程退出并产生回执
- **THEN** compact 保留状态失败或退出码非零的回执，包含进程名、已提供的退出码和真实耗时；成功且退出码为零的普通回执 MUST NOT 显示。
- **AND** 混合多个进程时逐项处理，成功项的裁剪不吞掉同批失败项；不改变进程生命周期、退出码记录、失败通知或 detailed 的原有显示。

#### Scenario: 实时和历史重建采用同一回执边界

- **WHEN** 相同进程回执实时到达，随后归档、恢复会话或切换显示模式
- **THEN** compact 保留的关键回执集合保持一致，隐藏项无空白占位；切换 detailed 可查看未重复回执及完整工具详情，不改写已保存结果。

### Requirement: `/jobs` 交互式任务面板

OMP MUST 在 `/jobs` 下为 ANSI 与 native 统一打开可浏览、可查看详情并按既有权限取消任务的交互式面板，任务树超出高度时仍保持选择与详情可达；`/jobs full` 保留完整命令折行报告。

#### Scenario: 不带参数打开交互式面板

- **WHEN** 用户在任一终端界面执行 `/jobs`
- **THEN** 打开可查看和取消任务的交互式面板，不因 ANSI 或任务数量多回退为非交互文本报告。
- **AND** 列出当前查看会话的运行中与最近任务，按任务和子代理父子关系组成树；不支持异步任务时给出警告且不打开面板。
- **AND** 复用现有可取消权限，聚焦子代理或其他只读视图不获得新的取消能力。

#### Scenario: 任务树超过面板高度仍可浏览到首尾

- **WHEN** ANSI 或 native 的任务树行数超过可用面板高度，例如在 `100×28` 或 `120×36` 下包含 40 个任务及相应代理树行
- **THEN** 用户可通过已有导航浏览全部任务，移动到首项、末项或中间项后当前选中项均保持可见，树形顺序和父子关系不变。
- **AND** 不只截取列表开头而让选中状态继续移到不可见行，不以增大终端或减少任务作为浏览前提；缩放后仍保持有效选择或沿用上游对已消失任务的选择规则。

#### Scenario: 选中任务的详情与取消目标可辨认

- **WHEN** 用户切换所选任务，或任务的状态与输出更新
- **THEN** 当前所选任务及其命令／标签、状态、已提供的目录、进程、退出码、工件和输出可通过面板交互查看，不因整个任务树先占满高度而永久位于被裁掉的末尾。
- **AND** 允许沿用上游预览和展开／滚动，不要求所有长输出同时铺满屏幕；现有完整输出入口继续可用。
- **AND** 取消动作只作用于用户可辨认的当前所选且有权限取消的运行中任务，不因不可见选择而误取消其他任务；关闭与取消键位语义不变。

#### Scenario: `/jobs full` 按整条命令折行

- **WHEN** 用户执行 `/jobs full`
- **THEN** 输出文本报告，先给出运行中任务数，再按树顺序列出运行中与最近任务，行首保留树形引导符。
- **AND** 命令或标签不截断，按报告区可用宽度折行且继续行保持缩进；超高报告仍可沿原入口滚动，没有任务时明确说明无异步任务。

### Requirement: 紧凑反馈沿用上游执行事实

OMP MUST 让紧凑预览、状态和错误对应上游真实调用与结果；中文标签只表达既有事实，不把调用正常返回等同于其报告的工作成功，不建立新的执行状态机或任务编号。

#### Scenario: 标识与状态沿用上游事实

- **WHEN** compact 显示调用标识或待执行、执行中、成功、失败、取消状态
- **THEN** 来源为上游调用及结果，既有中文标签可表达“待执行”“执行中”“完成”“失败”“已取消”“等待用户输入”“待确认”“已应用”；协议枚举、原始 ID、命令和结果不变。
- **AND** 不另设跨段或跨轮的任务短编号；只有原始诊断而无独立状态时保留诊断，不为中文标签推断新的取消、失败或后台状态。

#### Scenario: 当前代理的紧凑工作状态

- **WHEN** compact 显示工作状态行
- **THEN** ANSI 与 native 仅依据当前查看代理的既有事实显示模型响应等待、活跃思考、正文回复、工具参数生成、工具执行、用户回答／授权等待、后台等待及停止中；单个执行工具可显示原名，多个执行工具只显示当前代理的实际调用数，不汇总其他代理及内部活动。
- **AND** 思考结束后不依历史思考继续显示思考中，参数生成不当作执行，切换代理直接读取新代理事实；无法确定时保持“处理中…”，不猜测服务端排队、网络阶段、百分比或剩余时间。
- **AND** 只改变既有单行标签，保留宽度裁剪、布局、整轮计时、重试／压缩专用提示及取消入口；不新增事件、状态机、轮询、模型请求、配置或持久状态，不改变执行、调度、审批和会话生命周期，clean 与 detailed 保持既有非 compact 状态呈现。

#### Scenario: 结构化错误保留完整诊断查看能力

- **WHEN** 实际执行失败的输出同时包含有效原因与 JSON 花括号、方括号、逗号等结构符号
- **THEN** Bash 的 compact 折叠预览同样选取最后两行非空内容，即使末尾为结构符号也不猜测或重写原因；完整诊断通过显式展开或 detailed 查看，其他工具保留原反馈；仅有调用层错误时仍按静默规则处理。
- **AND** ANSI/native 采用同一边界，原错误码、完整诊断、模型上下文与显式展开行为保持。

#### Scenario: wait 返回失败或取消任务结果

- **WHEN** wait 正常返回的任务快照包含失败、取消、非零退出或独立诊断
- **THEN** compact 保留该 wait 中未被原 Bash 卡片承载的关键反馈，不因普通工具预览额度将其隐藏或替换为摘要；同一 jobId 与同一终态已由有输出且可见的 Bash 卡片承载时，折叠 wait 不重复该任务行，仅含重复任务时不留占位。未关联任务、对等消息、取消操作结果及独立工件／结构化诊断仍保留，显式展开 wait 可查看原结果，ANSI/native、实时与历史恢复一致。

#### Scenario: task 正常返回包含失败或取消子代理

- **WHEN** task 本身返回结果，但子代理已有非零退出、aborted、error 或其他被原 renderer 识别的关键终态
- **THEN** 保留上游原反馈、失败／取消的子代理身份和已有诊断，不以普通“完成 · task”代替，也不因新增普通调用而被预览额度筛掉。
- **AND** 同一调用中的成功结果仍保持原有语义，不把所有子任务统一改成同一个终态，不修改顶层结果、原始状态或实际调用次数；紧凑摘要不展示工具调用失败计数。

### Requirement: 紧凑读取行的修正与冲突标注

OMP MUST 在 compact 读取行中保留实际读取目标、路径修正与冲突标注，在出现修正或冲突时呈现警告；意图优先不能覆盖修正后的真实路径，ANSI 与两种 native 展示保持语义一致。

#### Scenario: 路径被自动修正

- **WHEN** 结果带有后缀修正信息，说明原路径缺少或写错扩展名
- **THEN** 展示修正后的实际路径，在目标后追加 ` · corrected from <原路径>`。
- **AND** 该行为在有意图 `i`、无意图、分组读取或独立读取时均成立；意图可以保留，但不能成为看不到实际目标的替代物。
- **AND** 行呈警告而非普通成功；读取调用失败时默认静默，用户显式展开或切换 detailed 可查看完整原反馈。

#### Scenario: 目标文件存在冲突

- **WHEN** 结果的 `conflictCount` 大于零
- **THEN** 追加 ` · N conflicts`，数量为 1 时使用 ` · 1 conflict`，并明确呈警告。
- **AND** 修正与冲突并存时同时保留，顺序先修正后冲突；真实读取失败不伪装为成功或警告，按调用错误静默规则处理。

#### Scenario: 警告在 ANSI 和 native 中一致

- **WHEN** 同一读取警告分别在 ANSI、native fallback 或 data-first native 显示
- **THEN** 均以已有警告样式表达，不能一端使用 warning，另一端仅用普通 dim“完成”行；不为此改变协议状态枚举或引入新状态。
- **AND** 路径、意图和标注仍用现有测宽与截断；可用宽度容纳完整摘要时能看到真实路径及标注，窄屏时完整内容仍可通过上游既有全文入口查看。

### Requirement: 紧凑等待行摘要

OMP MUST 对只含普通任务信息的 wait 结果使用一行任务身份摘要，无任务时提供通用说明；已消费的对等消息及任务关键反馈保留原展示，不被摘要回退或普通预览数量限制吞掉。任务列表复用上游显示，仅在折叠态省略已由原 Bash 卡片承载的同一任务终态，显式展开恢复全部任务详情。

#### Scenario: 等待返回一个或多个后台任务

- **WHEN** wait 返回一个或多个任务快照，且不含已消费对等消息或关键反馈
- **THEN** 摘要标签为 `Wait`，明细取第一个 running 任务，没有 running 时取第一个，格式为 `[<type>] <jobId> <label>`；标签等于 jobId 时不重复。
- **AND** 多任务追加 ` · +N jobs`，N 为其余任务数；标签只取首行并去首尾空白，超宽使用既有截断。

#### Scenario: 等待只返回对等消息或已无任务

- **WHEN** wait 的结果不含任务快照
- **THEN** 若没有已消费消息或独立报告诊断，使用 `Wait · Background work or peer message` 通用摘要，不生成空白工具行。
- **AND** 若已有对等消息，则该通用文字不替代消息反馈，必须保留原发送者、正文、已提供的接收／到达时间和上游既有查看入口。

#### Scenario: 被 wait 消费的消息仍在原位置可见

- **WHEN** 主代理的 wait 已消费 `details.waited` 中的消息，结果未设置顶层 `isError`，随后又出现两次或更多普通工具调用
- **THEN** 消息仍按原 renderer 显示在所属结果的位置，不因 wait 正常返回或超出最后两条普通预览而消失。
- **AND** 不依赖另一张主会话消息卡补发，不复制、重新投递或重放消息，不改变发件人、收件人、正文或时间。
- **AND** ANSI 与 native 均保留相同的消息语义，正文换行、截断和展开使用原组件，不新增专用消息面板。

### Requirement: 发送后的长用户消息

OMP MUST 在紧凑模式下统一折叠发送后的长用户消息，覆盖长粘贴、提示词模板展开和 `/review` 提示词；折叠只影响 TUI 显示。

#### Scenario: 超过六个屏幕行

- **WHEN** 发送后的用户消息按当前显示宽度排版后超过 6 个屏幕行
- **THEN** 只显示前 5 行及一行“已折叠 N 行，切换详细模式查看”，N 为未显示的内容行数；当前轮和历史轮使用相同规则。不超过 6 行时完整显示，通过 `/display detailed` 切换到详细模式后显示全文。

#### Scenario: 内容与输入行为保持完整

- **WHEN** 用户粘贴长文本、使用提示词模板或执行 `/review`
- **THEN** 输入框沿用现有粘贴标记和附件预览，模板展开及 review 行为不变；保存、模型接收和复制的内容均为全文，不调用模型生成摘要。`clean` 和 `detailed` 模式分别沿用本规格既有显示规则。

#### Scenario: review diff 不占写入展示名额

- **WHEN** `/review` 展开的用户提示词包含长 diff，且显示序列中存在真实 write/edit 调用段
- **THEN** 提示词中的 diff 按长用户消息折叠，不占所属连续写入段最近 3 次实际 write/edit 的展示名额。实现集中在用户消息的 TUI 显示，不改动粘贴选项、模板展开或 review 业务链路。

### Requirement: 账户选择器的凭据身份

- **THEN** 使用现有清理、测宽和截断机制得到合法单行预览，不溢出可用宽度、不新增空白调用行，原始字段和完整输出不被改写。

### Requirement: 受限高度下补全选中项可见

OMP MUST 在终端高度受限时优先保留输入光标，并让可展示的补全菜单跟随当前选中候选；不得在显示其他候选的同时接受不可见的选中项，也不得为补全重新定位输入框或改变正常高度下的既有选择语义。

#### Scenario: 三行或四行终端导航到末尾候选

- **WHEN** ANSI 终端可用高度缩至 3 或 4 行，补全菜单包含至少三个候选，用户通过方向键选择末尾候选
- **THEN** 仍可见输入光标，菜单按真实剩余高度展示包含当前选中候选的窗口，而不是只截取候选列表开头。
- **AND** 接受补全时应用的是用户当前可见的选中候选；不能显示前两项而接受隐藏的第三项。

#### Scenario: 剩余高度不能显示任何候选

- **WHEN** 在保留输入光标后没有足够空间呈现候选
- **THEN** 不显示具有不可见选中项但仍可接受的假菜单；沿既有非菜单输入路径处理，直到有空间重新展示候选。
- **AND** 不丢失输入正文、光标、草稿或候选来源，不以新增配置或强制移动输入框换取展示空间。

#### Scenario: 高度恢复及选中项改变

- **WHEN** 终端恢复正常高度，或用户在有效候选间继续上下移动
- **THEN** 既有补全列表与键位可用，当前选中项保持可见，接受结果对应所见选择，不重放输入或误执行 slash 命令。
- **AND** native 沿用其既有受限弹出区域及选择行为，不因 ANSI 高度裁剪修正引入不可见选择。

### Requirement: 紧凑工具段摘要紧邻普通预览

在 compact 默认折叠态，OMP MUST 将连续普通工具段的统计摘要放在该段末尾普通工具预览之前，而不是放在较早调用的独立关键反馈之前；摘要与普通预览的布局 MUST 遵守既有关键反馈和 UI 状态提示规则。

#### Scenario: 较早失败输出不隔开摘要和预览

- **WHEN** 同一连续普通工具段超过两次调用，较早的 Bash 调用存在必须显示的非零退出或超时反馈，最后两次调用均显示为普通单行预览
- **THEN** 较早失败输出保留在其原位置，之后显示一条统计整个工具段的摘要，摘要正下方连续显示最后两条普通预览；失败输出不得位于摘要和这两条预览之间。
- **AND** 摘要和两条普通预览之间不插入额外空行，失败输出自身的内容和既有边距不变。

#### Scenario: 运行中的预览与已完成预览一起显示

- **WHEN** 有统计摘要的普通工具段的最后两次调用分别为已完成和执行中，且均显示为普通单行预览
- **THEN** 摘要紧邻两条预览上方，两条预览仍按调用顺序显示真实状态；不因运行状态或完成先后改变选择或排序。

#### Scenario: 被选调用的关键反馈和段内状态提示

- **WHEN** 最后两次调用之一包含必须保留的关键反馈，或该段含有子代理查看／返回等 UI 状态提示
- **THEN** 保留反馈和提示的原位置、内容及既有间距，不为强制形成三条相邻单行而隐藏、移动或裁剪这些内容；统计和普通预览的选择仍遵循现行规则。

#### Scenario: 状态更新和历史重建

- **WHEN** 普通工具段实时更新、进入历史、重建、缩放或在受支持的 ANSI 与 native 终端呈现
- **THEN** 摘要与所属预览采用相同的相对位置规则；不因结果到达、分批归档或重建重复生成该段摘要，也不改写已归档历史。
- **AND** 调用计数、分段边界、原始消息及工具执行不变；clean 和 detailed 模式不受影响。

### Requirement: compact 普通调用错误静默

compact 默认折叠态 MUST 静默普通工具调用错误；仅调用层 `isError` 不得视为关键反馈。实际执行失败、部分已应用修改、独立诊断和用户交互仍按既有关键反馈合同展示。

#### Scenario: 仅工具调用错误

- **WHEN** 工具返回 `isError`，但不存在实际执行失败、部分修改、独立诊断或待处理交互
- **THEN** 不显示错误卡片、失败状态行或占位；不改变模型上下文和会话记录，展开或切换 detailed 后仍可查看。

### Requirement: 工具活动和结果图片显示由档位统一控制

工具活动及工具结果图片的显隐 MUST 由 `/display` 的 clean、compact、detailed 档位决定，不得存在独立旁路切换；已有终端和图片设置仍独立生效。

#### Scenario: 切换显示档位

- **WHEN** 用户切换显示档位或使用原工具可见性快捷键
- **THEN** 工具活动及结果图片的显示状态与当前档位一致，快捷键不得单独改变二者的可见性。
