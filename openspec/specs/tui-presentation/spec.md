# tui-presentation

## Purpose

本规格规定 fork TUI 的 clean、compact、detailed 三档显示、紧凑工具摘要与 Bash 日志呈现。显示模式只影响界面投影，原始消息、工具执行和模型上下文不随之改写。

## Requirements

### Requirement: 1. 三种显示模式

OMP MUST 用户选择 clean、compact 或 detailed 时按选定模式呈现。

#### Scenario: 1. 三种显示模式的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- **经典模式**：隐藏全部工具和思考。
- **全量模式**：通过 `detailed` 选择完整工具与思考展示，不应用 clean 隐藏或 compact 摘要裁剪。
- **紧凑模式**：默认启用，采用以下规则。

模式切换 通过 /display。

#### Scenario: 1. 三种显示模式 behavior

- **WHEN** the documented capability is used in the section's applicable context
- **THEN** 用户选择 clean、compact 或 detailed 时按选定模式呈现

### Requirement: 紧凑模式连续工具段

OMP MUST 在紧凑模式下仅对原位置的连续工具段做局部折叠，隐藏消息流中的全部思考块，并在输入区上方的单一固定区域展示活跃真实思考；工具消息顺序、原组件行为、布局、滚动和历史归档继续沿用上游机制，不维护整轮工具活动区。

#### Scenario: 连续普通工具段在原位置分组

- **WHEN** 上游消息顺序中出现连续普通工具调用
- **THEN** OMP 仅将该连续段作为一个局部折叠单元，不跨可见的助手正文、用户消息或 write/edit 调用合并；隐藏的思考、工具自身的结果与附属执行反馈不单独打断所属调用段，不跨已归档边界重新合并工具。
- **AND** 遇到上述边界后，后续普通工具开始新段；不同段分别保留在原位置，回复仍位于对应工具反馈之后，不将各段收集到整轮末尾或最终回复下方。
- **AND** 分段只作用于显示，不改变上游模型轮次、消息归属或工具执行顺序。

#### Scenario: 普通工具段只保留最后两条默认预览

- **WHEN** 一个普通工具段包含一个或多个调用
- **THEN** 默认折叠态按上游调用顺序选取最后至多两次调用，各显示一行预览，不补空白调用行；预览内容保持意图优先，Bash 在没有意图时使用实际命令，超长内容沿用既有宽度截断，完整内容保留供查看。
- **AND** 不按运行状态、完成先后或结果到达时间重排、补位；运行中调用超过两个也不自动扩大普通预览条数。
- **AND** 一个会话可以显示多个局部工具段，不将整个会话或整轮工具反馈限制为三行；关键反馈遵循本需求的例外规则。

#### Scenario: 摘要仅统计所属普通工具段

- **WHEN** 一个普通工具段包含 N 次实际调用
- **THEN** N 不超过二时不显示统计摘要；N 大于二时，在该段两条普通预览之前增加一行本段调用次数与失败次数摘要，摘要的文字和颜色均为低强调样式，不加粗。
- **AND** 统计只包含该普通工具段的调用，失败次数依据上游提供的实际结果；不包含相邻写入段、其他工具段或其他轮次，不维护整轮累计与跨轮归属。
- **AND** 同一次调用的参数流式更新、ID 修正、结果到达、重绘、会话重建或上下文压缩不新增调用次数；更新只作用于该调用所属段，不把旧后台结果记入新段。

#### Scenario: 连续写入段保留最后三个原组件

- **WHEN** 连续的 write/edit 调用实际写入或修改文件
- **THEN** 只在该连续写入段内保留最后至多三次实际写入调用的原组件，并保持它们各自的上游顺序和位置；一轮可以包含多个独立写入段，不在整轮或整个会话中全局只保留三个。
- **AND** 普通工具或可见的非工具内容结束该写入段；读取、预览及未实际写入的失败调用不占实际写入名额，失败与待确认反馈仍遵循关键反馈例外。
- **AND** 保留组件的展开、折叠、截断、文件内容、diff 和滚动行为沿用上游，不强制全部展开，不改成 fork 专用文件汇总，也不建立专用写入分页或额外高度预算。
- **AND** 后续写入只更新尚在形成的所属写入段，不因新段出现而回头删除或改写已经归档的旧写入段。

#### Scenario: 失败与用户交互不受普通预览数量限制

- **WHEN** 任一调用失败，或正在审批、待确认、等待用户输入，即使该调用不在所属段最后两条普通预览或最后三个实际写入之内
- **THEN** OMP 在其原位置保留上游原始反馈及已有交互入口，不以调用计数代替错误或待处理内容，不等待其他调用结束才呈现。
- **AND** 该段允许超过普通摘要加两条预览的三行上限；不为重新压回三行而隐藏、搬动或再次裁掉关键反馈，也不新增排序规则。
- **AND** 反馈随上游真实状态更新；审批、输入、取消和工具实际执行的行为不随折叠改变。

#### Scenario: 单一固定区域展示活跃思考

- **WHEN** 紧凑模式按当前显隐设置展示真实思考输出
- **THEN** 消息流中的当前及历史思考块均不显示正文、标题、完成提示或空白占位；普通助手正文不属于思考，不按颜色或措辞识别和隐藏。
- **AND** 仅在输入区上方显示一个固定思考区域，位置相对输入区固定，不随聊天记录滚动、不硬编码终端行号；复用上游现有底部布局及瞬态组件机制，不创建独立视口或滚动区，也不将工具搬入其中。
- **AND** 区域只展示当前会话活跃真实思考按当前宽度排版后的最近两行；最新行使用 thinkingText、上一行使用 dim，只有一行内容时保留第二行空白；不生成、补写或汇总思考。
- **AND** 思考结束、被隐藏、取消或切换会话时清空内容，不将旧思考留给下一次使用；空闲占位沿用上游瞬态布局处理。固定区域不进入聊天历史，不延长消息或工具生命周期，不改变归档时机。
- **AND** 原始思考及其归属完整保存，detailed 仍在原位置展示完整思考，clean 继续隐藏思考。

#### Scenario: 多次工具与思考交替不累计思考历史

- **WHEN** 普通工具与真实思考连续交替一百次
- **THEN** compact 始终只有一个固定思考区域，不产生一百个思考历史块，隐藏思考不形成可见工具分段边界；工具仍遵循原有段内预览、摘要和归档规则，不承诺整轮工具历史恒定行数。
- **AND** 中途出现正文、写入、失败或待处理交互时，原有展示与分段规则保持不变；切换 detailed 后全部原始思考与工具内容可查看。

#### Scenario: 已显示工具段正常进入历史

- **WHEN** 工具段按上游生命周期进入历史，或用户开始下一轮输入
- **THEN** 工具内容按上游机制正常归档；不因下一轮开始而统一清除上一轮工具和 diff，也不为移动最近调用、更新摘要或筛选新写入段回头改写已归档历史；思考原文仍完整保存，但不进入 compact 显示历史。
- **AND** 后台任务的状态入口、输出更新、完成回执和取消处理继续沿用上游，不为跨轮常驻另设 fork 活动区或改变任务生命周期。

#### Scenario: 缩放与窄屏继续使用上游布局

- **WHEN** 终端宽度或高度变化，或保留的写入组件、工具反馈、思考超过可用视口
- **THEN** 局部分段和筛选规则不变；换行、宽字符处理、截断、分隔、滚动和输入区分配继续使用上游机制，不在绘制后重新拼版，也不为固定三行工具区新增平行视口、手动去空行或独立高度预算。
- **AND** ANSI 与 native 使用相同的分段边界、预览选择、段内统计和关键反馈例外；各自上游的原组件边距、展开及滚动行为保持不变，不要求以额外嵌套、背景卡片或统一字符串重绘实现两端一致。

### Requirement: 紧凑模式 Bash 上游反馈

OMP MUST 在紧凑模式下沿用上游的 Bash 输出、展开、计时、前台及后台反馈机制；普通调用可按连续工具段折叠，但不得建立 fork 专有的延迟日志窗口、独立日志尾窗或刷新生命周期。

#### Scenario: Bash 不再使用专有定时日志窗口

- **WHEN** Bash 在前台运行、转入后台或持续输出
- **THEN** 输出的到达、预览、展开与运行时长按上游行为呈现；不再附加超过三十秒才显示的触发条件、共享六行日志配额、距上次输出计时或 fork 专有日志滚动区。
- **AND** 后台任务的计时、状态、输出和完成反馈直接跟随上游事实；紧凑显示不重新启动计时、不修改前后台转换，也不另行保存一套跨转换日志状态。

#### Scenario: Bash 错误与输入等待保留原始反馈

- **WHEN** Bash 失败，或需要审批、确认、用户输入
- **THEN** 原位置保留上游原始错误与交互反馈，不因普通工具段只保留最后两条预览而消失，不等待三十秒或其他运行中的调用完成。
- **AND** 直接遵循关键反馈例外；不以单独的失败尾行提取或统计数字替代原始诊断，原有展开和查看完整输出的入口保持可用。

#### Scenario: 显示不增加执行或模型活动

- **WHEN** Bash 输出刷新，或用户展开、折叠和滚动已有反馈
- **THEN** 仅使用上游已有显示行为，不为刷新新增模型请求、工具调用、轮询提示、Token 消耗或工具执行，不改写原始结果及持久化内容。

### Requirement: 紧凑反馈沿用上游执行事实

OMP MUST 让紧凑工具预览、状态和错误反馈对应上游实际调用事实，复用上游原始诊断与交互；既有中文状态标签仅表达已有状态，不建立全局任务短编号或独立的执行状态推断机制。

#### Scenario: 标识与状态沿用上游事实

- **WHEN** 紧凑工具预览显示调用标识或已有的等待执行、执行中、成功、失败、取消状态
- **THEN** 标识与状态来自上游调用及结果，既有中文标签可继续表达“待执行”“执行中”“完成”“失败”“已取消”以及“等待用户输入”“待确认”“已应用”；协议枚举、原始 ID、命令和结果保持原样。
- **AND** 不为日志另设跨段或跨轮的任务短编号；上游只有原始诊断而未提供独立执行状态时保留原反馈，不为生成中文标签新增取消、失败或后台状态机。

#### Scenario: 结构化错误不被局部折叠替换

- **WHEN** 失败输出包含有效错误原因以及 JSON 花括号、方括号、逗号等结构符号
- **THEN** 失败调用继续保留上游原始反馈和完整输出查看能力，不把整条错误折叠为仅有次数的摘要或 fork 单独提取的结尾符号行。
- **AND** ANSI 与 native 采用相同的关键反馈例外；原始诊断、错误码、模型上下文和上游已有配色与展开行为不变。

### Requirement: 发送后的长用户消息

OMP MUST 在紧凑模式下统一折叠发送后的长用户消息，覆盖长粘贴、提示词模板展开和 `/review` 提示词；折叠只影响 TUI 显示。

#### Scenario: 超过六个屏幕行

- **WHEN** 发送后的用户消息按当前显示宽度排版后超过 6 个屏幕行
- **THEN** 只显示前 5 行及一行“已折叠 N 行，切换全量模式查看”，N 为未显示的内容行数；当前轮和历史轮使用相同规则。不超过 6 行时完整显示，切换全量模式后显示全文。

#### Scenario: 内容与输入行为保持完整

- **WHEN** 用户粘贴长文本、使用提示词模板或执行 `/review`
- **THEN** 输入框沿用现有粘贴标记和附件预览，模板展开及 review 行为不变；保存、模型接收和复制的内容均为全文，不调用模型生成摘要。经典和全量模式保持现有规则。

#### Scenario: review diff 不占写入展示名额

- **WHEN** `/review` 展开的用户提示词包含长 diff，且显示序列中存在真实 write/edit 调用段
- **THEN** 提示词中的 diff 按长用户消息折叠，不占所属连续写入段最近 3 次实际 write/edit 的展示名额。实现集中在用户消息的 TUI 显示，不改动粘贴选项、模板展开或 review 业务链路。

### Requirement: 4. 显示投影边界

OMP MUST 将紧凑模式的差异限制在内容筛选、局部摘要、裁剪及基于上游既有底部布局的单一瞬态思考区域，复用上游消息、组件、布局及归档机制；显示切换不得改写模型上下文或改变工具与会话的实际功能。

#### Scenario: 4. 显示投影边界的详细边界

- **WHEN** 使用紧凑模式显示连续工具段、写入段、思考或长用户消息
- **THEN** 只改变应显示的内容及局部折叠，不为满足行数或最近调用数量改动上游的消息顺序、执行生命周期、正文 Markdown 流式排版、稳定行发布、历史退休、缩放、滚动或布局调度规则。
- **AND** 不建立平行的轮次归属、视口、归档或 Bash 日志机制；不为隐藏旧内容而清空、搬动或重写已归档消息。

#### Scenario: 显示模式切换仍保留全文与原有行为

- **WHEN** 用户通过 `/display` 在 clean、compact、detailed 之间切换，或按上游已有入口展开内容、恢复会话或切换视图
- **THEN** 沿用既有上游显隐、展开和重建路径；compact 应用本规格的局部折叠及固定思考区域，detailed 不显示固定思考区域，不应用 compact 的数量筛选、摘要或两行思考裁剪，clean 继续隐藏工具与思考。
- **AND** 默认 compact 及模式保存行为不变；上游完整消息仍可由 detailed 或既有全文入口查看，模式说明应与新的段内数量、历史保留和展开规则一致，不改变无关设置、快捷键或状态栏需求。

#### Scenario: 4. 显示投影边界 behavior

- **WHEN** 内容被局部折叠、隐藏、裁剪、展开、归档或在模式间切换
- **THEN** 不增删、截断或改写发送给模型的消息、工具调用与结果、上下文或 Token；不改变工具执行、审批、取消、后台调度、会话持久化及公开协议。
- **AND** 原始内容与上游已有的复制、查看、恢复能力保持完整，界面用的筛选与摘要不得回写原始记录或模型上下文；不新增配置项、模型请求、工具调用或无关功能。

### Requirement: 简体中文用户界面

OMP MUST 导航和说明使用简体中文，命令、模型标识及机器字段保持原样。

#### Scenario: 简体中文用户界面的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 本节限定的主要 TUI 操作界面中，有实际使用价值的导航、操作、状态与说明文字使用简体中文；汉化不是逐词强制中文化。专有名词、不应翻译的技术词及中文用户通常能直接理解的英文保留原样，不为追求全中文生造译名。不新增语言配置、多语言框架或运行时翻译流程。汉化只改变展示文字，不改变功能、业务执行流程、默认值、权限、选择结果、持久化格式或协议。
- 本次只覆盖主要 TUI 操作界面：欢迎与输入区、完整设置页（分类、分组、名称、说明、风险提示、选项及二级编辑）、常用模型／账户／会话选择、问答与授权弹窗、计划审阅，以及基础状态栏与输入区的必要操作提示。保留原有欢迎提示和中文文案；ANSI 与 native 路径保持一致。不扩展到文档正文、CLI 命令帮助、安装器、统计／协作网页、工具展示卡片、独立终端应用、索引管理面板或后台宿主通知。
- 只翻译显示层：命令及子命令名称、参数名、配置键、环境变量、枚举存储值、模型／Provider／工具标识、路径、代码、快捷键及占位符、URL、结构化输出字段保持原样；品牌与技术专有名词按需保留。现有显示标签与实际值分离时只改标签；既有界面直接返回标签、且仅在本地按同一标签选择动作时，可同步替换配对的标签字面量，但不得改变判断结构、动作语义或对外机器值。
- 品牌、产品、模型、工具、协议、编程语言及开发生态常用术语保留英文，例如 Agent、Subagent、Provider、Skill、Hook、Prompt、Token、API、CLI、TUI、RPC、SDK、MCP、LSP、OAuth、Git、Diff、Markdown、JSON、YAML、Bash、Shell、Eval、Vim、Unicode、ASCII、Nerd Font、Snapcompact、Prewalk、Fireworks、Mnemopi、Hindsight、Sharpshooter；不翻译用户或第三方自定义的名称。普通导航、按钮、操作指引与解释性句子翻译为自然中文，句中的这些术语保持英文。
- 不翻译模型系统提示词、工具 schema／协议说明、Skill 正文、第三方内容、用户输入、文件正文和实际命令输出。原始错误、错误码与诊断日志保持可检索；可翻译 OMP 外层的面向用户说明，不改机器消费的错误契约与状态标记。
- 保留既有布局、显示宽度计算、换行、截断、搜索、排序、快捷键与取消行为；不为汉化重构界面或调整业务。中文文案应简明、术语统一，避免用英文替换另一处已正常工作的中文。

#### Scenario: 简体中文用户界面的可观察行为

### Requirement: 快捷键与状态栏

OMP MUST 状态栏和帮助按既定顺序及窄屏规则显示，不让帮助整段消失。

#### Scenario: 快捷键与状态栏的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- `Shift+Tab`：计划模式。
- `Ctrl+T`：临时模型。
- `Alt+P`：thinking blocks 显示/隐藏。
- `Shift+F1`：循环切换 thinking level。
- ANSI 终端的空输入框固定显示 `Ctrl+T 临时模型 Ctrl+Q 排队发送 Esc Esc 回退对话 /tree 会话历史 /goal-autopilot 目标 双击左方向键<- 子代理 /wiki 文档检索 /repo 代码索引 有使用问题反馈j00808874`，使用空格分隔，不加圆点分隔符，反馈联系方式固定放在最后；只作为帮助文字，不随状态、使用次数或自定义按键变化；帮助文字靠左显示，与光标保留两个字符间距，剩余留白放在提示之后。宽度不足时按实际显示宽度自动换行，不能因整段放不下而全部隐藏；仍受现有屏幕高度上限约束。输入文字后隐藏帮助，清空后恢复；复用既有占位提示布局，不新增配置或轮播；“回退对话”不表示撤销文件修改。
- ANSI 终端主输入区至少占两行内容；输入正文或帮助文字下方保留一整行完全没有文字的留白。多行正文、自动折行与帮助换行按实际内容行数加这一行留白展开，仍受现有屏幕高度上限约束；高度不足时优先保留光标所在输入行。留白只在框内，不增加框外间距。
- 状态栏 `default` preset 从左组移除 `vim`、`pr`、`cost`，增加 `subagents`、`token_rate`、`cache_hit`、`time_spent`；前三项位于 `git` 之后、`context_pct` 之前，`time_spent` 位于 `context_pct` 之后。右组移除 `session_name` 后为空，零配置启动即生效。
- Git 段统一显示纯文本 `git main · 改动5`，不显示 Git／分支图标及 `*`、`+`、`?` 分类符号；改动数为已暂存、未暂存、未跟踪文件的并集，同一文件同时有暂存与未暂存改动只计一次，未跟踪目录内按文件逐个统计，忽略文件不计入。零改动时省略数量；无分支或用户关闭分支显示时只显示 `git 改动5`，分支与数量都不可见时隐藏该段。ANSI 与 native 界面采用同一文字与计数规则；既有三类显示选项仍控制是否计入对应类别。
- 配置中的 `subagents` 段按所属组与顺序显示，运行中的子代理徽章不得强制移到右组或重复显示。
- 输入框顶边的 `statusLine.contextLine=embedded` 模式把上下文使用率与窗口容量合并为靠右的 `ctx 3% · 500K` 信息组，容量与说明文字弱化，组后留两个字符间距；使用率变化不让标签沿横线移动。保留用量横线，不显示预压缩与自动压缩的两根刻度，不改变压缩功能（显式选择 `annotated` 模式仍显示刻度）；未知用量只显示容量，超过 100% 的真实比例仍以错误色显示。路径先按配置的缩写上限显示，仅在状态段与上下文信息确实放不下时从左侧截断、保留末尾目录；状态段移入溢出行后，释放的宽度必须重新分配给路径（不超过配置上限），用量横线只填剩余空间；顶边放不下时沿用状态栏溢出显示。
- 盒式输入区中的 fork 状态栏支持窄终端自动换行。
- 设置向导的主题选项「Match terminal」保留已配置的深色主题，只把浅色主题映射为 `light`；选择该项不会把现有深色主题覆盖为 `titanium`。
