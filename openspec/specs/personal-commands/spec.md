# personal-commands

## Purpose

规定个人 fork 新增或扩展的终端命令、关键词和会话操作语义，涵盖参数、状态迁移、取消与失败边界。复用原有命令链路，不建立平行调度器。

## Requirements

### Requirement: 工具参数自纠正提示

OMP MUST 反馈本次工具未执行并要求模型修正重调，不重复已成功的调用。

#### Scenario: 工具参数自纠正提示的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 工具参数 JSON 解析失败时，保留原始错误，并明确告知模型本次工具未执行，要求修正参数后重新调用，不只解释错误，也不重复已成功的调用。复用既有工具错误反馈与后续模型回合，不新增重试机制、次数配置或模型特判，不放宽校验或隐藏失败状态。
- 工具参数未通过 schema 校验时，保留校验错误与收到的参数，提示工具未执行、修正后重调且不重复成功调用；`xd://` 设备内容不是有效 JSON 时，保留解析错误并说明通过 `write` 向该设备写入 `?` 查看文档，再以 JSON 对象重调。
- 普通 `write` 目标缺少必需内容时，保持失败且不修改目标；反馈明确指出调用未执行，指导模型将路径与正文作为独立参数重调，不从意图字段推断或恢复正文。允许省略内容的内部目标仍沿用各自策略。
- `bash` 参数校验失败时保留原始校验错误，说明本次未执行，指导以 JSON 的 `command` 字符串及正确参数重调并给出示例；不从错误字段恢复命令、不重复已成功的调用，也不改变命令执行失败的反馈。
- 未找到工具时，保留原错误及现有相近名称建议，明确本次调用未执行，列出本次请求中的工具（最多 20 个，超出时标明截断），指导模型使用合适的可用工具而不重复调用；不改变工具解析或权限。
- `task` 调用的注入意图 `i` 含明显串入的 `tasks` 数组及 `agent` 字段时，在派发前拒绝并提示本次未执行、`i` 只写简短意图、`agent` 放在真实 `tasks[]` 项中，同时提供可用调用示例；不从字符串推断或自动恢复代理名称，正常省略 `agent` 仍使用默认代理，不改变其他工具或拥有自身 `i` 参数的工具。

#### Scenario: 工具参数自纠正提示的可观察行为

- **WHEN** 工具参数 JSON 解析失败
- **THEN** 反馈本次工具未执行并要求模型修正重调，不重复已成功的调用

### Requirement: 非 TUI 宿主的命令参数门禁

OMP MUST 在 ACP 与 RPC 宿主按各自规则判定内置命令是否可执行及是否接受参数，不允许时不得隐式执行命令。

#### Scenario: 非 TUI 宿主的命令参数门禁的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- ACP 宿主收到带参数的内置命令时，MUST 按 `acpAllowArgs`（未声明时回退 `allowArgs`）判定是否接受；不允许时 MUST NOT 执行该命令，原始输入 MUST 作为普通提示词转发。
- ACP MAY 为在 TUI 中打开选择器的命令声明独立的 ACP 参数许可；`/model` 在 ACP 中 MUST 接受模型参数，并按该参数切换模型或报告解析失败。
- RPC 宿主 MUST 对全部注册名独立派发：仅实现 TUI 处理器的命令 MUST 抛错 `/name is only available in the interactive TUI.`；不接受参数的命令在带参调用时 MUST 抛错 `/name does not accept arguments.`。两者 MUST NOT 静默回退为普通提示词。
- 没有命中内置命令的输入 MUST 交由宿主按普通提示词处理，命令层不解释其内容或改写参数。

#### Scenario: 非 TUI 宿主的命令参数门禁的可观察行为

- **WHEN** ACP 或 RPC 宿主收到带参数的内置命令或仅 TUI 可用的命令
- **THEN** 按 ACP 参数许可接受或回退为提示词，RPC 则按独立派发接受或抛出明确错误，均不隐式执行

### Requirement: `/loop` 轮次间隔

OMP MUST 首轮立即执行并按指定轮次或总时长限制等待和继续，暂停或切换后旧定时器不提交。

#### Scenario: `/loop` 轮次间隔的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 支持 `/loop [次数或总时长] [间隔] [任务内容]`，间隔无需参数名，仅在有效限制参数后紧接的位置识别完整时长标记，支持秒、分钟、小时及组合时长；正文中的时长不再解析。条件参数仍可放在间隔后、正文前。
- `/loop 10 30s xxx` 首轮立即执行，总计最多 10 轮，每轮结束后等待 30 秒再启动下一轮；`/loop 10m 30s xxx` 最多运行 10 分钟，等待计入总时长，到期不再启动下一轮。
- 指定间隔时数字限制包含首轮。
- TUI 与 ZCode 命令宿主共用解析和语义，等待期间可以暂停、关闭或切换会话，旧定时器不得继续提交；首轮、条件检查及 compact/reset 沿用现有执行链，不允许重叠提交。

#### Scenario: `/loop` 轮次间隔的可观察行为

- **WHEN** 用户输入带间隔的 loop 命令
- **THEN** 首轮立即执行并按指定轮次或总时长限制等待和继续，暂停或切换后旧定时器不提交

### Requirement: `/loop` 间隔上限与时长 tokens 的退化

OMP MUST 对 `/loop` 间隔实施上限校验，并只在可识别为单位时长时消费该 token。

#### Scenario: `/loop` 间隔上限与时长 tokens 的退化的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 间隔上限 MUST 为 2147483647 毫秒；推算结果超出该值 MUST 报 `Loop interval must not exceed 2147483647 milliseconds.`，且 MUST NOT 启动任何轮次。
- 间隔位上的形如时长的 token 使用未知单位时，MUST 不被当作间隔，MUST 作为任务正文保留；已知单位的非正数或非安全整数金额 MUST 报错而非当作正文。
- 限制位与条件标志的解析失败（负号或小数形式的限制、未知标志、缺失条件命令、重复条件）MUST 只报用法错误，MUST NOT 启动模型回合。
- 既非限制形态也非标志形态的 token MUST 原样作为正文，保持无界 loop 语义。

#### Scenario: `/loop` 间隔上限与时长 tokens 的退化的可观察行为

- **WHEN** 用户给出的间隔超过上限，或在间隔位给出未知单位的时长 token
- **THEN** 超限时明确报错且不运行，未知单位时该 token 退回正文

### Requirement: 魔法关键词的内置命令

OMP MUST 提供魔法关键词对应的内置命令，并允许命令后直接携带任务文本。

#### Scenario: 魔法关键词的内置命令的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- fork 为三个关键词新增对应的内置命令 `/ultrathink`、`/orchestrate`、`/workflowz`，方便输入，并允许命令后直接携带任务文本。
- collab guest 的本地命令白名单额外放行 fork 新增的 `ultrathink`、`orchestrate`、`workflowz` 与 `display`；白名单只决定 guest 可本地执行哪些命令，不扩大主机端权限，也不替代主机对参数的校验。
- guest 只镜像宿主的运行事实：进入、结束与逐条消息/工具事件按 state-only 应用，`isStreaming` 等状态取自宿主快照；离开或恢复本地会话时以一次 state-only `agent_end` 结束镜像，不重放模型回合、不改写历史条目、不新增消息系统。`message_end` 之后重置本地流式去重标记，避免同一条助手消息计两次。

#### Scenario: 魔法关键词的内置命令的可观察行为

- **WHEN** 用户调用 `/ultrathink`、`/orchestrate` 或 `/workflowz` 并携带任务文本
- **THEN** 对应命令接受任务文本并触发相应关键词行为

### Requirement: collab 只读链接的命令拒绝

OMP MUST 在只读 collab 会话中拒绝会产生提示词的命令，并且不得提交或转发内容。

#### Scenario: collab 只读链接的命令拒绝的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 只读链接上调用远端任务类命令（`remoteTask`）时 MUST 显示 `This collab link is read-only — prompting is disabled`，MUST NOT 提交提示词、MUST NOT 转发给宿主。
- 命令自身返回待发送提示词时同样 MUST 只显示该提示且 MUST NOT 提交，不得因命令已进入本地执行路径而放行。
- 拒绝时 MUST 保留用户草稿内容（含图片与图片链接），不静默丢弃或提交。
- 只读之外的可写 guest 会话中，已放行的远端命令 MUST 连同图片一起转发给宿主执行。

#### Scenario: collab 只读链接的命令拒绝的可观察行为

- **WHEN** 只读 collab 链接上执行远端任务命令或返回提示词的命令
- **THEN** 显示只读提示且不提交、不转发，草稿保留

### Requirement: collab 命令目录与共享进程会话迁移

OMP MUST 让 guest 命令目录与派发能力一致，并在共享进程宿主中以会话级方式切换目录。

#### Scenario: collab 命令目录与共享进程会话迁移的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 命令目录 MUST 支持 `includeTuiOnlyBuiltins` 与 `includeRpcBuiltins`：省略时 MUST NOT 广告仅 TUI 命令，声明时 MUST 同时广告可用处理器对应的命令。
- 声明仅 TUI 命令的宿主 MUST 将其派发回落到宿主端 TUI 处理器执行，作为 guest 可运行能力的唯一依据，不扩大主机权限。
- 共享进程宿主的会话迁移 MUST 通过 `rebindCwd` 建立会话级目录绑定；MUST NOT 修改进程级项目目录，以免影响同进程中的兄弟会话。
- `/wt` 解析出的目标路径与当前会话目录相同时 MUST 跳过重定位，并且 MUST NOT 清理源工作树或其中的未提交内容。

#### Scenario: collab 命令目录与共享进程会话迁移的可观察行为

- **WHEN** 宿主广告命令，或在共享进程中执行 `/move`、`/wt`
- **THEN** 目录与派发能力一致，目录切换只作用于当前会话，同路径目标不触发清理

### Requirement: JCH 命令

OMP MUST 各命令按其指定权限、参数、失败与取消边界执行，不让无效输入产生隐式副作用。

#### Scenario: JCH 命令的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

保留以下个人命令及其核心语义：

- `/jchime [故障现象]`：内置提示词恢复命令，面向内网较小模型提供完整可执行步骤及有边界的自主恢复空间；不是无模型的本地动作。默认环境为 CentOS 7、GNOME Terminal、SSH X11/Exceed、IBus 1.5.17 与 `libpinyin`；运行时重新核实，不使用快照中的历史地址或 PID。
  - 首选恢复块使用 Bash + 系统 Python 3.6+（本次调用显式 UTF-8 标准流编码），核对当前 UID、DISPLAY、唯一 daemon、地址文件归属和 PID、引擎可用性后，请求一次 `ibus restart`，重新发现实时总线并切回、核验 `libpinyin`。覆盖仅切引擎不能解决的 daemon/XIM 状态异常；同 daemon 的客户端会短暂中断，未提交的预编辑文字可能丢失。
  - 首选路径失败或实际症状未恢复时，模型必须根据真实结果继续诊断，自主选择引擎重切、恢复调用的总线/X11 环境对齐或当前显示会话 IBus 重建，不因脚本退出直接结束，不无依据重复失败步骤。正常重启无响应时，可在保存原始启动参数和必要环境、核对 UID/DISPLAY/PID/启动时间及信号前重验身份后，仅向该 daemon 的正数 PID 发送 SIGTERM；确认原进程退出且无其他 daemon 接管后按原启动方式重建，不自动升级 SIGKILL。daemon 已退出时，仅在当前用户、DISPLAY、X11 与现有 D-Bus 会话归属明确且无重复实例时启动，不创建替代 D-Bus 会话。
  - 只操作当前用户、当前 DISPLAY；目标或权限未确认时不执行变更。禁止 sudo、全局/进程组杀进程、安装、联网、持久配置修改及自动关闭终端/重启客户端；必要信息只读调查可继续，环境调整只作用于恢复调用及其子进程。安全手段耗尽或需客户端手动操作时报告具体阻塞，不将子进程环境修改当作运行中终端已修复。
  - 各路径均重新核验总线和实际引擎；原脚本成功标记不是自主方案的必要条件。服务正常与实际中文输入恢复分开报告，最后由用户在故障窗口切换并输入中文确认；Windows 本机、ZCode/Electron 或客户端故障不承诺由服务端恢复。复用现有 TUI/ACP/RPC 提示词展开机制；验收包含提示词真实送达、目标隔离、首选失败后的自主权限和停止边界，不把模拟模型或本机 Windows 验证当作公司实机输入验收。
- `/jch-workflowzbatch <任务块软目标> <并发上限> <任务正文>`：内置提示词快捷命令，两个数量必须为正的安全整数，正文非空；非法输入只报用法，不启动模型回合。展开为以独立 `workflowz` 关键词开头的普通用户消息，保留正文首行缩进、内部换行、尾部空白与字面量，不新增关键词、调度器或配置写入。
  - 用于全仓审查、补日志、格式优化等互不依赖的批处理。任务块数量参数表示软上限，可按实际工作量调整，无需接近或凑足该数量，不扩大范围；任务块数与并发槽数独立，可以多于并发槽数，不以并发上限决定拆分数量。并发数量是向 OMP 下达的同时运行子代理总数上限指令（含嵌套），不是命令新增的程序级限制，现有配置上限更低时仍遵守，由工作池自动截断为较低值；提示词明确要求不向用户询问是否覆盖或修改并发上限，也不修改任何全局配置。
  - 按任务正文确认实际范围和统一规则，向子代理提供已核实的适用规则/需求路径，修改型任务分配不重叠文件集合并保留无关已有修改；复用现有工作池排队、完成即补位，不等待整批屏障。
  - 子代理按任务正文自主完成所属范围：只读任务只报告，修改任务完成证据充分且已授权的最小修改及允许的文件级检查；证据不足只列候选，不推测性修改或扩大范围。跨界发现交主代理协调，不越过文件归属直接修改；跨文件修改由主代理调整归属并指定单一修复责任人。
  - 主代理负责调度、及时补位、跨界协调和结果汇总，不默认重复读取已分配文件的完整 diff 或重审全部改动，仅对争议发现、跨文件修改和结果冲突作必要的定点核对，不集中补跑检查；子代理对所属修改的自查与允许检查不受此限制。
  - 主代理和所有子代理禁止任何测试（含单文件、冒烟、E2E）、全仓格式化、全仓静态检查及 fastcheck/fulltest/slowtest 等门禁。仅允许对自己负责修改的文件执行文件级非测试检查或任务要求的格式化，不能限定这些文件的工具不得运行，也不得扩大到目录、包或工作区。
  - 提示词的「执行」与「本次验证限制」两节须原样传给每个子代理（含嵌套委派），另附该子代理的具体任务与范围；两节约束适用于主代理及所有层级的子代理，并约束主代理收尾。与仓库及子目录 AGENTS.md 的验证要求冲突时，以本次明确限制为准，其他规则继续有效，系统及开发者级约束不受覆盖。不修改长期规则，不在汇总阶段补跑禁止操作。
  - 子代理精简返回完成状态、处理结果、覆盖及修改文件、实际文件级检查和受阻/未验证项；有发现或修复时保留触发条件、根因、修改位置及最短证据链，无发现时不展开调用链或正确性评级。主代理按任务项去重汇总完成项、失败或受阻项、修改文件及实际文件级检查，注明测试未运行与跨文件、运行时行为未验证，不声称功能验收通过。该例外仅适用于本命令发起的批处理，不适用于命令本身的实现维护。
  - 命令展开与参数边界需自动化验证；真实公开入口需确认展开内容以用户消息送至 Provider 并沿用原有关键词通知。命令机制验证不等于模型实际遵循约束或大规模批处理验收。

#### Scenario: JCH 命令的可观察行为

- **WHEN** 用户调用 JCH 命令且输入有效或无效
- **THEN** 各命令按其指定权限、参数、失败与取消边界执行，不让无效输入产生隐式副作用

### Requirement: `/clear` 在非 TUI 宿主的上下文重置

OMP MUST 在非 TUI 宿主原地重置上下文并保留会话身份，重置竞态时明确报告且不清空数据。

#### Scenario: `/clear` 在非 TUI 宿主的上下文重置的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 重置 MUST 原地清空对话上下文，会话 MUST 继续存在，会话 ID、标题、目录、模型与设置 MUST NOT 改变。
- 压缩进行中时 MUST 先中止压缩并等待其真正结束，再执行重置。
- 成功回执 MUST 为 `Context reset — N messages dropped; session continues.`，`N` 为实际丢弃的消息数；`N` 为 1 时 MUST 使用单数 `message`。
- 流式响应进行中 MUST NOT 重置，回执 MUST 提示先结束或中断当前响应。
- 等待压缩结束时若会话被切换或销毁，MUST 输出 `Session changed while resetting the context; nothing was cleared.`，MUST NOT 以异常使整个请求失败，也 MUST NOT 清空新会话的上下文。

#### Scenario: `/clear` 在非 TUI 宿主的上下文重置的可观察行为

- **WHEN** 在 ACP/RPC 会话中执行 `/clear`，且当时正在压缩、正在流式或发生会话切换
- **THEN** 按压缩等待、流式拒绝或竞态回执处理，成功时给出丢弃消息数的回执

### Requirement: `/logout` 在非 TUI 宿主的凭据移除

OMP MUST 按 provider 与账号移除存储凭据并刷新 provider 状态，其他凭据来源仍生效时明确警告。

#### Scenario: `/logout` 在非 TUI 宿主的凭据移除的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 未指定 provider 时 MUST 只列出存在存储凭据的 provider；仅一个时 MUST 直接使用，多个时 MUST 经选择界面选择；选择被取消 MUST 不删除任何凭据且不输出结果。
- 指定的 provider 未知 MUST 以警告跳过；没有存储凭据时 MUST 说明当前认证来自环境或配置文件并提示在其来源处移除。
- 同一 provider 有多个账号时 MUST 经账号选择；只有一个账号时 MUST 直接使用。
- 移除 MUST 只删除所选账号的存储凭据，并 MUST 刷新该 provider 的模型/认证状态。
- 移除后仍存在其他凭据来源时，回执 MUST 以警告级输出并包含 `still authenticated via …` 与实际来源；否则 MUST 为信息级。
- 选择期间会话 ID、generation、模型注册表或生命周期状态发生变化时 MUST 取消移除并报 `Logout cancelled: the session changed during account selection.`。

#### Scenario: `/logout` 在非 TUI 宿主的凭据移除的可观察行为

- **WHEN** 在 ACP/RPC 会话中执行 `/logout`，且存在多个账号、其他凭据来源或期间切换了会话
- **THEN** 按选择结果删除单个凭据并刷新 provider，必要时给出仍已认证的警告，竞态时取消

### Requirement: `/skills` 在非 TUI 宿主的注册表操作

OMP MUST 使用配置的注册表源并仅经确认授权安装带脚本的技能，结果以会话通知输出。

#### Scenario: `/skills` 在非 TUI 宿主的注册表操作的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 注册表源 MUST 为已配置的技能注册表地址，未配置时 MUST 使用默认注册表地址。
- `search`、`install`、`installed`、`update` 与帮助子命令 MUST 与非 TUI 结果输出一致；缺少查询或目标时必须报用法错误，未知子命令 MUST 报错并给出用法。
- 安装或更新包含脚本的技能时 MUST 经 `ui.confirm` 获取授权；宿主没有确认界面时 MUST 失败并说明需要确认能力，MUST NOT 默认同意。
- 输出 MUST 经会话通知机制发送（信息/警告/错误分级），变更完成后 MUST 刷新技能列表与命令列表；已是最新时 MUST 明确说明无需更新。
- 注册表或安装错误 MUST 以 `Skills: <原因>` 形式输出为错误通知，MUST NOT 使整个请求失败。

#### Scenario: `/skills` 在非 TUI 宿主的注册表操作的可观察行为

- **WHEN** 在 ACP/RPC 会话中执行 `/skills` 子命令，包括带脚本技能的安装
- **THEN** 使用配置或默认注册表，未获确认时不安装，结果经会话通知输出并刷新技能状态

### Requirement: `/wiki` 与 `/repo` 的 RPC 面板

OMP MUST 在 RPC 宿主以对话框面板提供索引维护，破坏性操作需二次确认，取消与会话切换安全中止。

#### Scenario: `/wiki` 与 `/repo` 的 RPC 面板的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- `/wiki` 面板 MUST 提供索引列表、新建索引（目录与名称输入）、删除索引、搜索与 grep，并 MUST 支持分页浏览命中章节。
- `/repo` 面板 MUST 提供索引状态、构建、更新、重建与删除；删除 MUST 保留项目文件。
- 删除等破坏性操作 MUST 先经确认对话框；用户取消 MUST 本次操作不产生任何变更。
- 索引进度 MUST 节流上报（同一阶段未完成时至少间隔 200 毫秒），完成时 MUST 输出最终结果行。
- 任一阶段 MUST 记录包含操作标识与阶段名的操作日志；输出失败 MUST 只记录警告，不中断索引。
- 会话切换、销毁或取消信号触发时 MUST 中止当前索引操作并输出取消结果，MUST NOT 写入已切换会话。
- TUI MUST 继续打开既有面板，语义与外观不变。

#### Scenario: `/wiki` 与 `/repo` 的 RPC 面板的可观察行为

- **WHEN** 在 RPC 宿主执行 `/wiki` 或 `/repo` 并选择操作，或中途取消
- **THEN** 经确认后执行对应索引操作并按节流输出进度，取消与会话切换时安全中止

### Requirement: `/wt` 会话工作树

OMP MUST 按目标提交与工作树状态切换会话目录，保留两端未提交内容。

#### Scenario: `/wt` 会话工作树的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 以下工作树策略仅适用于 `/wt`。
- 指定的本地分支已存在时直接使用，不因同名报错、不重建或重置分支：已有对应工作树时把会话切到该目录；尚无对应工作树时为该分支创建工作树，检出该分支自身的提交，而不是当前分支的 `HEAD`。目标就是当前工作树的分支时保持当前位置，不重复创建。
- 指定的分支不存在时，从当前 `HEAD` 创建新分支与工作树。
- 新建工作树的根目录放在当前会话工作目录的父目录下，与当前目录平级，不放入 `~/.omp/wt`，也不由全局 `worktree.base` 或 `OMP_WORKTREE_DIR` 改变这一位置规则；已有工作树直接复用其原位置，不为满足平级要求搬迁它。目录冲突沿用现有可用路径选择机制，不覆盖已有目录。
- 新建工作树的代码以目标分支的已提交内容为准，不携带源目录的已暂存、未暂存、未跟踪改动或删除状态；当前分支及原目录的这些内容、暂存状态保持不变，不自动 stash、提交、reset 或 clean。`worktree.cleanSource` 不得让 `/wt` 清理原目录。
- 切换到已有工作树时保留该工作树自身的未提交改动，不用源目录覆盖它，也不为切换而清理它。

#### Scenario: `/wt` 会话工作树的可观察行为

- **WHEN** 用户用 wt 切换到已有分支、已有工作树或当前分支
- **THEN** 按目标提交与工作树状态切换会话目录，保留两端未提交内容

### Requirement: 设备文档查询入口

OMP MUST 仅将向 `xd://` 设备写入的 `?` 识别为本次指定的设备文档请求。

#### Scenario: 请求设备文档
- **WHEN** 用户或 Agent 向设备写入 `?`，允许其周围空白
- **THEN** MUST 返回该设备文档，而不执行设备动作。

#### Scenario: 空内容和 help 不是文档入口
- **WHEN** 向设备写入空内容或 `help`，包括不同大小写
- **THEN** MUST NOT 仅因该内容返回设备文档；MUST 按该设备既有输入、校验及错误规则处理，不能据此猜测执行成功。

### Requirement: LSP code action 应用结果状态

OMP MUST 使 LSP code action 的结构化成功状态与实际应用结果一致。

#### Scenario: 未指定动作
- **WHEN** `code_actions` 指定 `apply=true` 但 `query` 缺失或仅含空白
- **THEN** MUST 不应用任何动作，并以失败状态和明确提示返回；`details.success` MUST 为 `false`，工具结果 MUST 标记失败，不能以成功状态报告该次应用。

#### Scenario: 指定并应用动作
- **WHEN** `apply=true` 且有效选择器匹配可应用动作并实际成功应用
- **THEN** MUST 保留已应用动作与结果的真实成功反馈；取消、选择失败或应用失败不得伪报成功。
