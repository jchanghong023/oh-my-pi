# personal-commands

## Purpose

规定个人 fork 新增或扩展的终端命令、关键词和会话操作语义，涵盖参数、状态迁移、取消与失败边界。复用原有命令链路，不建立平行调度器。

## Requirements

> 状态：用户已确认的最新 Dev 需求基线。本次仅更新文档；现有代码和原型尚未按本规则完成实现或验收。


### Requirement: 原生 `/sketch` 离线画布

OMP MUST 在原生交互 TUI 提供无需安装扩展或额外配置的 `/sketch`，通过本地浏览器绘图后将真实 PNG 附件加入当前草稿，由用户手动发送。

#### Scenario: 本地绘图与手动提交

- **WHEN** 用户在原生 TUI 调用 `/sketch`
- **THEN** 打开自包含浏览器画布，支持手绘、剪贴板图片粘贴与标注、颜色、笔刷大小、撤销、清空和画布尺寸调整；图片粘贴取决于实际桌面剪贴板能力
- **AND** 画布页面的按钮、操作说明、悬浮提示、无障碍标签及内置状态／错误提示 MUST 使用中文，保留快捷键名称和 PNG 等必要技术标识
- **AND** 浏览器按 `Enter` MUST 将 PNG 作为真实图片附件加入原输入草稿，保留已有文字与附件，MUST NOT 自动发送或启动模型回合；用户可补充描述后自行发送
- **AND** 画布 HTML、脚本、样式等离线资源 MUST 随源码和发行二进制静态内嵌；绘图本身 MUST NOT 请求公网、CDN 或外部模型服务
- **AND** 浏览器脚本、样式及 API MUST 以 Firefox 128 默认原生能力为基线，不再兼容 Firefox 52；本机浏览器验证 MUST 使用 Selenium＋geckodriver 和隔离临时 profile，MUST NOT 将本机验证表述为公司 CentOS 或实际桌面环境的兼容认证
- **AND** 本功能仅属于原生 TUI，MUST NOT 宣称 GUI、ACP 或 RPC 绘图集成，也不提供远程自动转发；OMP 与浏览器应在同一主机，异地主机须由用户自行将显示端口通过 SSH 转发至 OMP 的回环地址
- **AND** offline 不自动启动浏览器，显示完整画布地址供用户手动打开；Linux offline 打开原生 `/sketch` 时按[内网网页入口自动复制本机地址](../fork-runtime/spec.md#requirement-内网网页入口自动复制本机地址)请求复制完整画布地址，保留手动复制地址与原有草稿、取消和图片提交行为；其他环境不自动覆盖剪贴板

#### Scenario: 全窗口画布与视野操作

- **WHEN** 用户打开 `/sketch` 页面
- **THEN** 工具栏和状态区之外的浏览器窗口 MUST 全部用于绘图工作区，新画布初始尺寸匹配该区域；不强制浏览器进入系统全屏模式
- **AND** 支持滚轮围绕光标缩放、缩放按钮、100% 和适应窗口；支持空格加拖动、中键拖动和显式平移模式，平移不得产生笔迹，缩放和平移后绘图及画布尺寸调整的坐标 MUST 正确
- **AND** 缩放、平移及浏览器窗口尺寸变化 MUST NOT 改写已有图像像素或导出尺寸；提交 MUST 导出完整画布 PNG，而非当前可见区域，保留现有撤销、粘贴、清空和手动附件提交语义


#### Scenario: 取消、隔离与本地服务清理

- **WHEN** 用户在终端或浏览器按 `Escape`，或当前会话、视图归属或生命周期已变化
- **THEN** 取消 MUST 保留原输入草稿；会话切换、销毁或焦点移动后，旧结果 MUST NOT 插入其他会话或输入视图，包括 PNG 读取、归一化和附件插入期间的迟到结果
- **AND** 本地服务 MUST 仅绑定 `127.0.0.1`，以端口 `0` 请求系统分配端口，每次启动使用随机能力 URL，拒绝跨来源请求并限制提交载荷大小
- **AND** 提交完成、取消、失败或宿主销毁时 MUST 关闭本次本地服务并使旧能力 URL 失效

OMP MUST 内置 Developer Test Agent 的专属子代理、五个技能及 `/dt`、`/generate-dt-files`、`/generate-dt-dir`、`/incremental-dt`、`/cloud-dt-fix` 命令，复用现有发现、命令展开、task、todo、ask 和 `skill://` 链路，不建立旧宿主 API 兼容层。

#### Scenario: 使用内置单元测试流程

- **WHEN** 用户调用上述命令或委托 `developer-test-agent`
- **THEN** 保留原插件的 Python、Java、C/C++ 和 Go 语言路由，按原有意图执行生成、修复、覆盖率、断言审查和报告流程，保持原有覆盖率门禁及批量任务串行规则
- **AND** 无需额外安装插件或配置资源目录；源码与发行产物均包含技能引用文档、脚本、示例和二进制资源，资源路径不依赖当前项目目录
- **AND** 专属子代理与五个技能默认不向 LLM 展示，不因普通测试请求自动选择、路由或注入提示；仅在用户显式指定代理、技能或上述命令时使用，保留手动发现与调用入口
- **AND** 子代理需澄清时将问题交回主代理询问，不在 headless 子代理内调用交互工具
- **AND** 保留 `.codecovcli/cache` 的本地覆盖率报告契约；原宿主的 `@baize/dtagent-plugin` 自动遥测上报是外部依赖，不因内置而宣称已提供，也不自动修改旧宿主的配置或历史记忆

### Requirement: 工具参数自纠正提示

OMP MUST 反馈本次工具未执行并要求模型修正重调，不重复已成功的调用。

#### Scenario: 工具参数自纠正提示的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 工具参数 JSON 解析失败时，保留原始错误，并明确告知模型本次工具未执行，要求修正参数后重新调用，不只解释错误，也不重复已成功的调用。复用既有工具错误反馈与后续模型回合，不新增重试机制、次数配置或模型特判，不放宽校验或隐藏失败状态。
- 工具参数未通过 schema 校验时，保留校验错误与收到的参数，提示工具未执行、修正后重调且不重复成功调用；`xd://` 设备内容不是有效 JSON 时，保留解析错误并说明通过 `write` 向该设备写入 `?` 查看文档，再以 JSON 对象重调。
- 普通 `write` 目标缺少必需内容时，保持失败且不修改目标；反馈明确指出调用未执行，指导模型将路径与正文作为独立参数重调，不从意图字段推断或恢复正文。允许省略内容的内部目标仍沿用各自策略。
- `bash` 参数校验失败时保留原始校验错误，说明本次未执行，指导以 JSON 的 `command` 字符串及正确参数重调并给出示例；不从错误字段恢复命令、不重复已成功的调用，也不改变命令执行失败的反馈。
- 未找到工具时，保留原错误及现有相近名称建议，明确本次调用未执行，列出本次请求中的工具（最多 20 个，超出时标明截断），指导模型使用合适的可用工具而不重复调用；不改变工具解析或权限。
- `task` 调用的注入意图 `i` 含明显串入的 `tasks` 数组及 `agent` 字段时，在派发前拒绝并提示本次未执行、`i` 只写简短意图、`agent` 放在真实 `tasks[]` 项中，同时提供可用调用示例；不从字符串推断或自动恢复代理名称，正常省略 `agent` 仍使用默认代理，不改变其他工具或拥有自身 `i` 参数的工具。

#### Scenario: 工具参数自纠正提示的可观察行为

- **WHEN** 工具参数 JSON 解析失败
- **THEN** 反馈本次工具未执行并要求模型修正重调，不重复已成功的调用

### Requirement: 非 TUI 宿主的命令参数门禁

OMP MUST 在 ACP 与 RPC 宿主按各自规则判定内置命令是否可执行及是否接受参数，不允许时不得隐式执行命令。

#### Scenario: 非 TUI 宿主的命令参数门禁的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- ACP 宿主收到带参数的内置命令时，MUST 按 `acpAllowArgs`（未声明时回退 `allowArgs`）判定是否接受；不允许时 MUST NOT 执行该命令，原始输入 MUST 作为普通提示词转发。
- ACP MAY 为在 TUI 中打开选择器的命令声明独立的 ACP 参数许可；`/model` 在 ACP 中 MUST 接受模型参数，并按该参数切换模型或报告解析失败。
- RPC 宿主 MUST 对全部注册名独立派发：仅实现 TUI 处理器的命令 MUST 抛错 `/name is only available in the interactive TUI.`；不接受参数的命令在带参调用时 MUST 抛错 `/name does not accept arguments.`。两者 MUST NOT 静默回退为普通提示词。
- 没有命中内置命令的输入 MUST 交由宿主按普通提示词处理，命令层不解释其内容或改写参数。

#### Scenario: 非 TUI 宿主的命令参数门禁的可观察行为

- **WHEN** ACP 或 RPC 宿主收到带参数的内置命令或仅 TUI 可用的命令
- **THEN** 按 ACP 参数许可接受或回退为提示词，RPC 则按独立派发接受或抛出明确错误，均不隐式执行

### Requirement: `/loop` 轮次间隔

OMP MUST 首轮立即执行并按指定轮次或总时长限制等待和继续，暂停或切换后旧定时器不提交。

#### Scenario: `/loop` 轮次间隔的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 支持 `/loop [次数或总时长] [间隔] [任务内容]`，间隔无需参数名，仅在有效限制参数后紧接的位置识别完整时长标记，支持秒、分钟、小时及组合时长；正文中的时长不再解析。条件参数仍可放在间隔后、正文前。
- `/loop 10 30s xxx` 首轮立即执行，总计最多 10 轮，每轮结束后等待 30 秒再启动下一轮；`/loop 10m 30s xxx` 最多运行 10 分钟，等待计入总时长，到期不再启动下一轮。
- 指定间隔时数字限制包含首轮。
- TUI 命令宿主沿用既有解析和语义，等待期间可以暂停、关闭或切换会话，旧定时器不得继续提交；首轮、条件检查及 compact/reset 沿用现有执行链，不允许重叠提交。

#### Scenario: `/loop` 轮次间隔的可观察行为

- **WHEN** 用户输入带间隔的 loop 命令
- **THEN** 首轮立即执行并按指定轮次或总时长限制等待和继续，暂停或切换后旧定时器不提交

### Requirement: `/loop` 间隔上限与时长 tokens 的退化

OMP MUST 对 `/loop` 间隔实施上限校验，并只在可识别为单位时长时消费该 token。

#### Scenario: `/loop` 间隔上限与时长 tokens 的退化的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 间隔上限 MUST 为 2147483647 毫秒；推算结果超出该值 MUST 报 `Loop interval must not exceed 2147483647 milliseconds.`，且 MUST NOT 启动任何轮次。
- 间隔位上的形如时长的 token 使用未知单位时，MUST 不被当作间隔，MUST 作为任务正文保留；已知单位的非正数或非安全整数金额 MUST 报错而非当作正文。
- 限制位与条件标志的解析失败（负号或小数形式的限制、未知标志、缺失条件命令、重复条件）MUST 只报用法错误，MUST NOT 启动模型回合。
- 既非限制形态也非标志形态的 token MUST 原样作为正文，保持无界 loop 语义。

#### Scenario: `/loop` 间隔上限与时长 tokens 的退化的可观察行为

- **WHEN** 用户给出的间隔超过上限，或在间隔位给出未知单位的时长 token
- **THEN** 超限时明确报错且不运行，未知单位时该 token 退回正文

### Requirement: `/loopgoal` 固定目标循环

OMP MUST 新增 `/loopgoal`，与 `/loop` 仅有两处差异：将输入目标包装为固定提示词，以及最终回复精确为 `无` 时停止。其余行为 MUST 复用现有 `/loop`，MUST NOT 改变 `/loop` 的原有行为或接入 Goal 管理系统。

#### Scenario: 启动与重复完整回合

- **WHEN** 用户输入 `/loopgoal [次数或总时长] [间隔] [--while|--until '<命令>'] [目标]`
- **THEN** 参数语义 MUST 与 `/loop` 一致：无间隔时次数表示首轮之外的重复次数，指定间隔时次数包含首轮；未附目标时下一条普通输入作为目标，暂停后下一条输入恢复并成为新目标
- **AND** 每轮 MUST 将目标原文带入固定提示词，让 Agent 根据当前上下文与实际结果直接执行下一步，较大目标本轮推进合适的小任务、不重复已完成工作、不扩大范围；完成时只回复 `无`
- **AND** 循环程序 MUST 独立保留含目标原文的固定提示词，每轮原样重发，不依赖压缩摘要；轮内正常调用工具，MUST NOT 在每次工具调用后追加提示词

#### Scenario: 沿用 Loop 上下文策略与停止机制

- **WHEN** `/loopgoal` 运行
- **THEN** 首轮提交、轮次调度、空闲等待、上下文处理及错误行为 MUST 与 `/loop` 一致；上下文策略沿用 `loop.mode` 的直接发送／压缩／重置配置，MUST NOT 增加专属的 50% 压缩阈值、首轮等待或准备流程
- **AND** 仅当完整终止回合的最终助手文本去除首尾空白后精确等于 `无` 时结束循环，不将工具输出、思考内容或包含 `无` 的其他文本作为完成信号
- **AND** 参数、次数／时长、间隔、条件、用户暂停／关闭与恢复、状态展示和自动补全 MUST 沿用现有 Loop；暂停清空重复提示词，下一条输入成为新目标并恢复，不增加保留旧目标的专属恢复语义
- **AND** MUST NOT 增加任务树、验收流程、专用收尾工具、独立状态机或专属调度／取消机制；模型负责判断与执行

#### Scenario: 忙时提交与目标原文保留

- **WHEN** 用户在流式执行或上下文压缩期间提交带目标的 `/loopgoal`
- **THEN** MUST 沿用 `/loop` 对已转发或已入队目标的捕获机制，空闲后继续原定轮次，不得只执行一次或重复提交被拒绝的输入
- **AND** 固定提示词包装 MUST 原样保留传入目标中的代码空白、空行、Markdown 和字面模板语法，不在替换后对目标进行格式化；原有输入解析规则保持不变

#### Scenario: 等待目标时忽略无关完成回复

- **WHEN** `/loopgoal` 尚未捕获实际提交的目标，已有其他回合的最终回复为 `无`
- **THEN** MUST 保持等待目标，不得把无关回复作为目标完成；目标实际进入会话后，仍沿用精确匹配 `无` 的停止规则

OMP MUST 提供魔法关键词对应的内置命令，并允许命令后直接携带任务文本。

#### Scenario: 魔法关键词的内置命令的详细边界

#### Scenario: 魔法关键词的内置命令的可观察行为

### Requirement: 共享命令目录与会话迁移

OMP MUST 让命令目录与相应宿主的派发能力一致，并在共享进程宿主中以会话级方式切换目录。

#### Scenario: 共享命令目录与会话迁移的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 命令目录 MUST 支持 `includeTuiOnlyBuiltins` 与 `includeRpcBuiltins`：省略时 MUST NOT 广告仅 TUI 命令，声明时 MUST 同时广告可用处理器对应的命令。
- 共享进程宿主 MUST 声明 `sessionScopedCwd`，会话迁移后由 sessionManager 提供当前目录；MUST NOT 修改进程级项目目录，以免影响同进程中的兄弟会话。
- `/wt` 解析出的目标路径与当前会话目录相同时 MUST 跳过重定位，并且 MUST NOT 清理源工作树或其中的未提交内容。

#### Scenario: 共享命令目录与会话迁移的可观察行为

- **WHEN** 宿主广告命令，或在共享进程中执行 `/move`、`/wt`
- **THEN** 目录与派发能力一致，目录切换只作用于当前会话，同路径目标不触发清理

### Requirement: JCH 命令

OMP MUST 各命令按其指定权限、参数、失败与取消边界执行，不让无效输入产生隐式副作用。

#### Scenario: JCH 命令的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

保留以下个人命令及其核心语义：

- `/minimal [任务]`：内置提示词命令，展开用户指定的最小充分变更与验证要求；可单独发送，也可携带任务文本，复用既有命令派发和普通用户消息链路。该提示词约束模型行为，不是程序级测试或修改拦截。

- `/jchime [故障现象]`：内置提示词恢复命令，面向内网较小模型提供完整可执行步骤及有边界的自主恢复空间；不是无模型的本地动作。默认环境为 CentOS 7、GNOME Terminal、SSH X11/Exceed、IBus 1.5.17 与 `libpinyin`；运行时重新核实，不使用快照中的历史地址或 PID。
  - 首选恢复块使用 Bash + 系统 Python 3.6+（本次调用显式 UTF-8 标准流编码），核对当前 UID、DISPLAY、唯一 daemon、地址文件归属和 PID、引擎可用性后，请求一次 `ibus restart`，重新发现实时总线并切回、核验 `libpinyin`。覆盖仅切引擎不能解决的 daemon/XIM 状态异常；同 daemon 的客户端会短暂中断，未提交的预编辑文字可能丢失。

### Requirement: `/clear` 在非 TUI 宿主的上下文重置

OMP MUST 在非 TUI 宿主原地重置上下文并保留会话身份，重置竞态时明确报告且不清空数据。

#### Scenario: `/clear` 在非 TUI 宿主的上下文重置的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 重置 MUST 原地清空对话上下文，会话 MUST 继续存在，会话 ID、标题、目录、模型与设置 MUST NOT 改变。
- 压缩进行中时 MUST 先中止压缩并等待其真正结束，再执行重置。
- 成功回执 MUST 为 `Context reset — N messages dropped; session continues.`，`N` 为实际丢弃的消息数；`N` 为 1 时 MUST 使用单数 `message`。
- 流式响应进行中 MUST NOT 重置，回执 MUST 提示先结束或中断当前响应。
- 等待压缩结束时若会话被切换或销毁，MUST 输出 `Session changed while resetting the context; nothing was cleared.`，MUST NOT 以异常使整个请求失败，也 MUST NOT 清空新会话的上下文。

- **THEN** 按压缩等待、流式拒绝或竞态回执处理，成功时给出丢弃消息数的回执

- **AND** `OMP_OFFLINE` 进程继续遵循现有浏览器禁用策略

### Requirement: 仅递归发现同源导航页面

递归抓取 MUST 只跟踪最终入口页面同协议、同主机和同端口的导航链接；MUST 对 URL 去重，忽略普通页内锚点但保留查询参数。`#/...` 属于页面路由而非页内锚点，导航、去重与来源记录 MUST 保留完整路由及其查询参数。导航重定向和全文读取 MAY 跨源，不因原始 URL 与最终页面不同源而阻断正常浏览器跳转；页面渲染所需的站外资源 MAY 正常加载，但其他站点的导航链接 MUST NOT 因此扩展递归范围。

#### Scenario: 站内外链接与 URL 去重

- **WHEN** 页面包含相同 URL 的多个片段链接、带不同查询参数的同源链接和站外链接
- **THEN** 片段不同但其余部分相同的 URL 只抓取一次，不同查询参数的 URL 分别处理
- **AND** 站外链接不加入递归抓取目标，页面正常渲染所需的站外 CSS、脚本和图片请求不因递归范围限制而被额外拦截

#### Scenario: Hash 路由与路由查询参数

- **WHEN** 入口或同源递归链接使用 `#/xxx/xxx?id=123&lang=zh` 形式的路由
- **THEN** OMP 使用包含完整 Hash 路由和查询参数的地址导航与记录来源，不退化为站点根页面
- **AND** 不同路由或路由查询参数分别抓取，相同路由与参数的重复链接只抓取一次

#### Scenario: 浏览器原生重定向与深度边界

- **WHEN** 入口或子页面发生 HTTP／JavaScript 重定向，或用户设置 `--max-depth 1`
- **THEN** OMP 像在已登录浏览器中打开 URL 一样使用原生导航、Cookie 和会话处理跳转，允许跨源重定向，等待最终页面并记录最终来源 URL，不另建匿名会话或伪造登录状态
- **AND** 递归范围以入口在重定向和全文读取后的最终来源确定；子页重定向到其他站点时可保存其最终内容，但不将该站点的其他导航链接加入递归目标
- **AND** 深度以入口页为第 0 层；深度为 1 时只处理入口页和其直接链接的同源页面

### Requirement: 保存独立且不覆盖的 Markdown 文件

OMP MUST 将每个成功提取的页面保存为独立 Markdown 文件，并在文件中记录来源 URL。默认输出到当前工作目录的 `tmp/`，`--output` 可指定其他目录；已有文件 MUST NOT 被覆盖。内容使用现有 HTML→Markdown 转换，保留已渲染主文档中的业务列表、表格及其他区块，不以文章筛选算法只保留一个正文片段；链接保留指向原网站的目标，不下载图片、PDF 或其他附件。

#### Scenario: 默认输出和重复保存

- **WHEN** 用户未指定输出目录并保存页面，或者目标文件名已存在
- **THEN** OMP 在当前工作目录的 `tmp/` 创建 Markdown 文件，内容包含页面提取结果及来源 URL
- **AND** 目标文件已存在时保留原文件，为新结果使用其他文件名

#### Scenario: 保存延迟渲染的企业页面

- **WHEN** 企业网站通过 JavaScript 延迟渲染业务内容，或从其他源的 API 加载数据
- **THEN** OMP 等待主文档加载完成、页面文字及各来源的文档／Fetch／XHR 请求稳定后再提取，不将跨域 API 排除在加载等待之外，持续事件流不作为必须结束的请求
- **AND** 默认在 DOM 就绪后至少等待 5 秒；`--wait <秒数>` 可指定 0–240 秒的最短等待时间并支持小数，用于延迟启动的应用；等待期间继续跟踪页面与网络状态，超时明确报错而不是保存尚未稳定的页面
- **AND** 提取保留文章之外已渲染的业务表格和列表，默认继续滚动和读取全文；不自动点击无关业务按钮或翻页

#### Scenario: 递归页面和附件

- **WHEN** 页面正文包含其他网页的相对链接、图片或 PDF 链接，且用户执行递归抓取
- **THEN** 每个成功抓取的网页分别生成 Markdown，正文链接保留可指向原网站的目标
- **AND** 不将图片、PDF 或其他附件下载为本地归档文件；正文提取可能省略导航等杂项，不承诺无损页面备份

### Requirement: 默认滚动加载页面内容

`/crawl` MUST 默认在自有后台标签中逐屏向下滚动主文档及视口内的嵌套滚动面板，在每次滚动后等待渲染文字和数据请求稳定；此行为 MUST 同样应用于入口页和递归子页面，不要求 `--scroll` 等启用参数。`--no-scroll` 显式关闭逐屏滚动，但不关闭全文读取；既有浏览器会话、授权、导航和取消边界继续生效，MUST NOT 点击“加载更多”等无关控件、翻页或操作用户原有标签。

#### Scenario: 滚动追加内容及子页面链接

- **WHEN** 页面或嵌套面板滚动后追加业务内容，或出现新的同源导航链接，且用户未显式指定 `--no-scroll`
- **THEN** OMP 继续滚动并等待，直至没有可继续向下滚动的可见区域，且末尾的滚动尺寸、页面文字和数据请求稳定后才保存 Markdown
- **AND** 保存结果包含仍保留在主文档中的追加内容，递归链接在滚动加载结束后发现，并继续遵循同源、去重和深度／页数边界
- **AND** `--wait` 为每页初始载入及打开全文后的最短等待时间，不在每次滚动后重复完整等待

#### Scenario: 无限增长、取消及虚拟列表

- **WHEN** 页面持续追加内容、用户取消，或列表离屏后移除已显示的数据
- **THEN** 滚动与加载共用有界的页面执行预算；无法到达稳定末尾时明确失败，不将未完成的结果作为完整页面保存
- **AND** 取消停止滚动并释放自有标签，保留此前已经保存的其他页面；不抢占用户原有标签或焦点
- **AND** 文档明确不承诺完整归档会移除旧行的虚拟列表，不通过业务 API、翻页或改变业务状态的操作补齐

#### Scenario: 滚动请求无法前进

- **WHEN** 滚动尺寸仍显示可继续向下，但实际滚动并等待稳定后，滚动位置和尺寸、页面地址及文字均未改变
- **THEN** OMP 明确报告滚动无进展并结束该页，不重复空转直至耗尽页面预算，也不将未完成页面保存为完整结果
- **AND** 释放该页的自有标签，继续遵循其他页面失败处理与取消边界

### Requirement: 默认读取明确的全文内容

`/crawl` MUST 默认识别可见且语义明确的全文阅读控件，包括“查看全文”“阅读全文”“展开全文”“显示全文”“继续阅读”及对应的明确英文阅读文字，不要求用户附加启用参数。MUST 优先展开页内内容；全文为 HTTP／HTTPS 链接时在自有标签中导航并处理重定向，不按链接的 `target` 新开窗口。读取成功后 MUST NOT 再沿推荐区的阅读链接自动串行跳转；显式同源递归仍按正常规则执行。

#### Scenario: 入口及子页的截断博客

- **WHEN** 入口或递归子页面默认仅显示摘要，并有明确的全文阅读控件
- **THEN** OMP 自动展开或导航到全文，等待渲染和数据请求稳定，再继续滚动及提取，保存全文与最终来源 URL
- **AND** 控件支持包裹文字的子元素、常见空白及末尾箭头，不将普通“加载更多”、点赞、评论或提交按钮视为全文操作

#### Scenario: 全文无法打开或操作会提交业务表单

- **WHEN** 全文控件不可用、点击后既无内容变化也无导航、指向下载／非网页协议，或会提交表单
- **THEN** 命令明确报告失败，不执行表单提交、不下载附件，也不将未变化的摘要伪报为全文
- **AND** 既有取消、失败继续处理其他页面及已保存文件保留规则继续生效

### Requirement: 进度、失败和取消

OMP MUST 在终端 TUI 和 GUI 中展示抓取进度与最终结果，并提供 `/crawl stop` 取消当前会话的抓取。页面访问或提取失败 MUST NOT 阻止处理其他可访问页面，最终结果 MUST 报告失败 URL 和原因；取消或中断后 MUST 保留已保存文件，不自动断点续爬。

#### Scenario: 一个页面失败但可发现其他链接

- **WHEN** 已打开的页面无法提取 Markdown，但仍能获取其导航链接
- **THEN** OMP 记录该页面 URL 和失败原因，继续尝试其符合范围的链接及队列中其他页面
- **AND** 最终向用户报告成功和失败结果，不伪报全部成功

#### Scenario: 用户取消任务并重新执行

- **WHEN** 用户在任务运行时输入 `/crawl stop`
- **THEN** 当前会话的抓取停止，已保存文件保留，自有后台标签得到释放
- **AND** 重新执行时从入口重新抓取，不自动恢复队列，也不覆盖已有文件

### Requirement: 终端命令及参数补全

OMP MUST 在终端提供 `/crawl` 命令名、参数名和 `--output` 本地目录补全；补全 MUST NOT 为生成 URL 候选而读取或提示浏览器历史。GUI MUST 支持执行该命令及其参数，但不要求提供参数补全。

#### Scenario: 终端输入命令参数

- **WHEN** 用户在终端输入 `/crawl`、参数名前缀或 `--output` 后的目录前缀
- **THEN** 终端分别提供匹配的命令、参数或本地目录候选，不读取浏览器历史填充 URL

#### Scenario: GUI 执行内置命令

- **WHEN** 用户在 OMP GUI 输入合法的 `/crawl` 或 `/crawl stop`
- **THEN** GUI 通过 OMP 内置命令执行并显示实际进度、结果或取消状态，不要求 GUI 提供参数补全

### Requirement: Dev 浏览器工作台启动入口

OMP MUST 提供会话内 `/dev` 和命令行 `omp dev` 两个工作台启动入口，输出完整可复制地址；非 offline 自动打开浏览器，offline 由用户手动打开。两者 MUST 指向目标目录的同一新 Dev 业务能力；会话内 `/dev` 进入独占 Dev，当前 TUI 此后仅接受再次 `/dev` 结清退出，不恢复旧 Dev 阶段输入或子操作，不因打开网页自动创建需求或调用模型。

#### Scenario: 从 OMP 会话打开
- **WHEN** 用户启动 OMP 后输入 `/dev`
- **THEN** 普通模型、工具或任务未结清时拒绝进入并提示先停止或等待，普通 Loop 未退出时提示先退出；不自动终止普通任务或退出 Loop。准入成功才启动或复用目标目录的工作台服务，显示实际完整地址，仅非 offline 自动打开浏览器
- **AND** 进入后当前 TUI 拒绝所有普通命令和输入，仅接受再次 `/dev` 退出；网页与普通 TUI 不同时操作，普通原会话保留但不继续操作。不显示旧 Dev 三行固定状态区，也不自动启动需求、Team 或 Goal
- **AND** 普通 Collab 正在共享或处于 `join` 会话时拒绝进入，提示先自行停止共享或离开该会话，不自动停止共享或离开 Collab；成功进入后仍支持 Dev 网页按既有 Collab 机制共享及 `join`

#### Scenario: 直接从命令行打开
- **WHEN** 用户在自己的目录运行 `omp dev`，包括先手动 `git pull` 获取新流程记录后运行
- **THEN** 使用当前 OMP 的有效目录、profile、模型和运行环境启动工作台，输出完整地址，仅非 offline 自动打开浏览器，不要求先手动进入 TUI 或另外启动前端开发服务器
- **AND** 读取已有新需求记录不自动拉取仓库、执行 Git 写入、迁移聊天、接管远端会话或启动 Agent

#### Scenario: 再次 dev 结清退出
- **WHEN** 用户已进入 Dev，在当前 TUI 再次执行 `/dev`
- **THEN** 通过既有 native stop／settlement 停止并结清 Dev 自有工作，成功后恢复普通原会话；失败保留 Dev 锁定及真实原因，不提前恢复普通命令和输入
- **AND** 退出不取消需求、不撤销 Git、不删除材料；不为普通 `/new`／move／dispose 与 Dev 并存保留会话快照、克隆或额外架构

#### Scenario: 单纯重开网页
- **WHEN** 用户重开同一工作台网页，而非在 TUI 再次执行 `/dev`
- **THEN** 返回已有实际入口和状态，不重复创建需求、不重放任务或确认；不将重开网页解释为退出 Dev
- **AND** 多人访问唯一共享 Dev Web 读取同一业务数据，不启动各自的 Dev Web，不建立仓库单 IR 或 SR 执行名额；TUI 模式独占与普通 WebGUI 原生项目准入保持各自边界

#### Scenario: 浏览器无法自动打开
- **WHEN** 服务已就绪但宿主没有可用桌面浏览器，或自动打开失败
- **THEN** 仍输出完整实际地址，并明确报告浏览器未自动打开；不能把服务启动失败冒充仅浏览器打开失败，也不能只输出不可用地址

#### Scenario: 页面关闭不停止宿主任务
- **WHEN** 用户从任一入口打开的浏览器页面关闭、刷新或断开
- **THEN** 按 dev-browser-workbench 的生命周期保留宿主任务和 Dev 锁定，不恢复普通 TUI 输入；再次 `/dev` 退出、显式停止或退出 OMP 才按原生规则处理自有资源，页面不是执行 owner

#### Scenario: 新界面与新流程
- **WHEN** 用户进入新 Dev
- **THEN** 使用 Dev 自有 WebGUI 风格界面，提案采用需求→四 Agent 评审→方案→入库三栏流程，正式需求采用大表格与同页代码证据报告；开发在平台外完成，不提供计划／执行／IR 验收 Agent、开发名额、冻结锁或最终归档流水线；原 WebGUI 保持不变

### Requirement: 旧 Dev 终端交互退役但能力保留

OMP MUST 移除旧 Dev 阶段输入模式及其终端配置、详情、推进、丢弃和仅业务结束交互，`/dev` 只负责独占网页 Dev 的进入与结清退出。旧终端子命令产品路径 MUST 不再执行或作为兼容别名保留；网页只复用需求管理、文档、配置与进度分析能力，不恢复旧编码流水线。普通 OMP TUI、原生命令和独立技能保持不变，但须先成功退出 Dev 才使用普通 TUI 操作。

#### Scenario: 旧子操作不绕过网页流程
- **WHEN** 用户尝试 `/dev new`、`business`、`finish-business`、`next`、`back`、`drop` 或 `config` 等旧终端子操作
- **THEN** 按当前真实命令目录明确拒绝，不启动旧模式、不执行部分控制、不交给模型或自动转换成旧流程
- **AND** 新建提案、业务讨论、人工文档确认及材料查看在网页按新合同完成；Team 和原生子代理保持既有配置方式，不新增 Dev Team 配置；Dev Agent 设置采用业务需求、需求评审 A／B／C、综合评审、方案、需求进度分析及独立 Skill 设计角色，不保留计划、执行或 IR 验收角色

#### Scenario: 命令目录与帮助一致
- **WHEN** 用户查看补全、帮助或调用 Dev 入口
- **THEN** 目录准确展示 `/dev` 进入／再次 `/dev` 结清退出、Dev 中当前 TUI 只接受该退出动作，以及 `omp dev` 的网页启动语义；不宣传旧阶段终端操作、直接跳过业务检查或 drop 保留文件的行为
- **AND** 不新增旧状态兼容、恢复或迁移入口，不改变非 Dev 命令在普通模式的参数、权限及执行方式；协议宿主仍按既有目录与准入规则处理命令

### Requirement: WebGUI 浏览器正式入口

OMP MUST 提供 `/webgui` 和 `omp webgui`，复用已迁入并精简后的 ZCode Web／手机界面、前端服务契约及协议，不能改成交付替代性的简化聊天页。网页 MUST 支持项目选择／打开／创建、显式创建原生会话并实际开发、全部可访问历史与独立续聊、实时消息／流式回复／执行状态、当前会话临时选模、指定会话停止、补充问答、文件／图片上传、`@` 文件上下文、忙时队列、运行中 guide、编辑提问重发、失败回复重试、当前有效 profile 用户级 AGENTS 编辑、文件／Git 自动刷新及所有 TUI 内置命令与有效 Skill；支持多原生会话并行及失败安全退出。全部执行复用 OMP 原生能力与真实状态，不迁移 ZCode 后端或桌面端，不另建模拟执行器、独立 SDK 进程、消息数据库或任意图工作流引擎，不扩展本次未指定的审批、配置修改或 Git 写操作。

#### Scenario: 会话内进入与退出
- **WHEN** 用户在普通 TUI 输入 `/webgui`
- **THEN** 复用 Dev 的 TUI 独占准入和输入门禁，并取得项目级占用权；成功后登记当前会话到本 OMP 进程的 Web 服务，输出本实例的本机和局域网地址，仅非 offline 尝试打开浏览器，同进程内不按项目重复启动前端或监听器
- **AND** 当前终端只接受再次 `/webgui` 退出，普通会话与草稿保留；关闭或刷新网页不退出，手机直接访问本实例服务，不进行远控配对
- **AND** 再次 `/webgui` 或宿主关闭时结清本实例自有 Web 工作并关闭本实例服务；结清成功才恢复普通终端，失败保持锁定并允许重试，不关闭或影响其他 OMP 进程的服务

#### Scenario: 独立命令与资源边界

- **THEN** 各页显示、文件／Git、上下文引用、订阅及发送均绑定各自选定项目和会话；切换后建立正确的新绑定，旧请求、迟到事件及旧连接不能读写 B 或把 A 的数据当作 B 的结果
- **AND** A 的运行不因页面切换被取消或迁移，B 不继承 A 的草稿、问答、队列、附件或临时模型，项目离线或绑定失败明确报错，不静默选择其他项目

### Requirement: WebGUI 显式创建同进程原生会话

用户 MUST 能在选定项目新建真实原生 AgentSession。新增会话 MUST 由当前 OMP 进程原生能力持有并独立驻留，不得借用正在运行的另一会话作为执行器，不得运行 ZCode 执行器、模拟回复或独立 SDK 进程。

#### Scenario: 显式新建与首条消息
- **WHEN** 用户在已选项目点击新建会话，或在尚未绑定会话的项目显式发送首条消息
- **THEN** 完成目标项目准入后创建属于本实例的原生会话，显示真实会话身份与目录；新建本身不调用模型，发送消息才按原生规则开始回合，模型和工具能够实际完成该目录的开发任务
- **AND** 创建失败不显示伪会话或已发送成功，不将消息发给其他会话，保留草稿和附件；无需先进入 TUI 或启动另一进程，不能要求 lazy 启动阶段预建 Agent

### Requirement: WebGUI 原生聊天与会话临时选模

WebGUI MUST 将用户消息交给所属原生会话执行，展示真实流式回复、工具调用／结果、错误与运行状态；临时选模仅影响指定会话，不改变全局默认或兄弟会话。

#### Scenario: 聊天框选择当前会话临时模型
- **WHEN** 用户在已绑定 OMP 会话的 WebGUI 聊天框打开模型选择器
- **THEN** 使用该原生会话的真实可用模型列表，显示当前实际模型，不暴露密钥或凭据配置，不根据前端缓存冒充宿主当前选择
- **AND** 用户选择后直接调用该会话已有的临时选模接口，成功后显示原生实际选择；不修改全局默认模型、不影响其他会话、不发送聊天或调用模型推理
- **AND** 请求携带当前原生会话 ID；会话已变更、项目占用已结束或模型不可用时拒绝，不写入其他会话，不在失败时显示已切换成功
- **AND** 刷新、其他页面或原生会话模型变化时从同一原生所有者更新选中状态；尚未绑定会话时不伪造当前模型或因打开选择器自动创建 Agent，明确引导先创建会话；显式创建后立即按该真实会话开放选择

#### Scenario: 消息执行而非回显
- **WHEN** 用户向已绑定原生会话发送开发请求
- **THEN** 由该会话真实调用模型及原生工具，网页实时显示已接纳、运行、流式内容、工具结果及最终成功／失败状态；工具写入发生在所属项目，不能以 echo 用户文字、静态回复或仅显示消息列表冒充执行
- **AND** 同一会话各已授权页面观察同一真实状态，保留原生旁观、输入权限和并发输入限制；断线重连读取当前实际状态，不重复提交消息，不新增绕过原生权限的接管机制

### Requirement: WebGUI 全部历史与跨目录独立续聊

WebGUI MUST 保留当前 OMP 可访问的全部历史列表与只读消息，不得按新选项目或全局 current 静默删减历史。只读浏览 MUST NOT 创建 Agent、取得执行占用或切换现有会话；执行历史必须由用户显式继续。

#### Scenario: 浏览其他项目历史
- **WHEN** 页面选定 A 项目，用户查看可访问的 B 项目历史
- **THEN** 仍可读取已授权历史及真实消息，不改变 A 的目录、模型、运行、占用或输入归属，不把历史只读可见解释为 B 已取得执行准入

#### Scenario: 显式继续跨 cwd 历史
- **WHEN** 用户点击「继续此会话」
- **THEN** 以历史目标的真实 cwd 取得项目准入，恢复目标项目的原生配置、工具、上下文与模型到本实例独立驻留的原生会话；已驻留时复用该目标会话，不新建重复执行者，不把另一正在执行的会话切换目录或加载走
- **AND** 历史快照可读且具备原生恢复条件时即可发起继续，不以目标 runtime 尚未存在为由禁止；页面确认真实目标会话及模型后才允许向其发送／选模，恢复失败保留草稿和真实错误，不在旧 cwd 执行或绕过其他 owner

### Requirement: WebGUI 指定会话独立停止与取消

WebGUI MUST 提供作用于指定原生会话的停止／取消，沿用原生 abort 及其自有子工作的结清语义，不得终止兄弟会话或将取消当作删除历史、文件或 Git 回滚。

#### Scenario: 并行会话中停止一个
- **WHEN** A、B 两个原生会话并行运行，用户停止 A
- **THEN** 只向 A 的原生执行及按原生规则归属 A 的子工作发起取消，显示真实取消中／完成／失败状态；B 继续运行，A 的历史、已有文件及 Git 修改保留
- **AND** 对不存在、失效或越权会话的请求明确拒绝，不回落到当前会话；未结清时不能假报空闲或停止成功

### Requirement: WebGUI 原生补充问答

WebGUI MUST 展示所属原生会话实际等待的问题、选项及自由输入，并将回答送回同一等待点，不得用普通聊天代替问答协议。

#### Scenario: 回答与过期隔离
- **WHEN** 会话 A 等待补充回答，用户选择选项或提交输入
- **THEN** 显示真实问题与可用输入，回答仅恢复 A 对应的原生等待点，并展示已接纳或拒绝结果；B 的问答与运行不变
- **AND** 过期、重复、已取消、跨会话或旧页面回答明确拒绝，不回答后来新问题；失败保留用户输入，退出时按结清规则处理仍在途的问答

### Requirement: WebGUI 文件与图片上传

WebGUI MUST 接收真实文件字节，保留文件名、MIME、大小及会话归属；图片 MUST 使用原生图片输入能力，不得仅发送文件名、前端预览 URL 或描述文字。

#### Scenario: 上传并提交真实附件
- **WHEN** 用户在指定会话上传文件或图片并发送消息
- **THEN** 显示上传中、成功或真实失败状态；原生消息接收到对应真实附件与元数据，图片按当前模型实际图片能力接纳或明确拒绝，不假定所有模型都支持图片，也不伪造识图成功
- **AND** 上传失败或消息被拒绝时保留可恢复的草稿及错误，不把附件送往其他会话；取消上传、移除未提交附件或页面断线的清理不能删除仍被已接纳消息使用的附件，也不能泄露其他会话附件

### Requirement: WebGUI 授权的文件上下文引用

WebGUI MUST 支持 `@` 文件选择与上下文提交，按所属项目及会话权限解析实际文件，让原生模型获得文件上下文，而非仅收到未经解析的 `@` 文本。

#### Scenario: 引用文件及拒绝越权路径
- **WHEN** 用户在 A 会话选择或输入 `@` 文件并发送
- **THEN** 在授权的 A 项目作用域读取实际内容并作为原生上下文提交，网页显示所引用文件和读取失败；不存在、不可读、路径穿越、符号链接逃逸或未经授权的其他目录明确拒绝，不读取 B 的文件
- **AND** 页面切换或引用解析失败不静默遗漏上下文后发送，不沿用旧目录解析同名文件；失败保留用户草稿及引用信息

### Requirement: WebGUI 忙时原生消息队列

会话忙时 WebGUI MUST 默认使用原生 follow-up 排队语义，显示真实队列状态；不得将排队伪装为已执行、静默中断当前回合或在其他会话出队。

#### Scenario: 忙时追加与明确立即发送
- **WHEN** A 运行中，用户发送后续消息或显式选择立即发送
- **THEN** 默认消息进入 A 的原生 follow-up 队列，显示实际已接纳／等待／执行／拒绝状态及原生顺序；队列拒绝时显示原因并保留草稿，用户消息 echo 不算入队或开始执行证据
- **AND** 显式立即发送才按原生中断和队列规则处理，并向用户呈现其结果，不能暗中中断；切换页面不将 A 的消息转交 B，停止与退出按原生规则处理未执行项且不伪报已完成

### Requirement: WebGUI 运行中 guide

WebGUI MUST 允许用户向运行中的指定会话发送 guide，使用原生 steer 语义，与默认 follow-up 队列明确区分。

#### Scenario: 引导运行中的会话
- **WHEN** 用户向正在运行的 A 提交 guide
- **THEN** guide 送入 A 的原生 steer 路径，显示实际接纳、等待应用、应用或拒绝状态，不靠用户消息回显冒充已经影响执行；执行中可观察后续原生状态及结果
- **AND** A 不再运行或原生语义不允许时明确拒绝并保留输入，不静默改为新回合、follow-up 或 B 的消息，不改变兄弟会话

### Requirement: WebGUI 编辑已有提问并重发

WebGUI MUST 支持编辑已有用户提问后按原生 branch 语义重发，保留历史和正确会话归属，默认不得回滚工作区或 Git。

#### Scenario: 从既有提问创建原生分支
- **WHEN** 用户选择已存在的用户消息、修改内容并确认重发
- **THEN** 以该原生消息作为分支位置执行，显示真实分支及运行身份，不把编辑伪装为篡改原历史或普通末尾追加；原历史仍可读，已有工作区文件不自动撤销
- **AND** 消息不属于目标会话、不可分支或运行状态不允许时明确拒绝；失败保留编辑内容和草稿，不覆盖另一会话、原消息或其正在运行的分支

### Requirement: WebGUI 失败回复原生重试

WebGUI MUST 支持对真实失败回复发起原生 retry，保留对应请求、会话、上下文及附件归属，不另造聊天执行器或重复创建无关会话。

#### Scenario: 重试失败回合
- **WHEN** 用户在失败回复上点击重试
- **THEN** 按该会话原生 retry 语义重新执行，显示真实接纳、运行、流式结果或再次失败；不可重试、已失效或归属不匹配时明确拒绝，不重试其他消息
- **AND** 失败保留编辑内容和未发送草稿，不将其他会话当前选模或上下文覆盖到目标请求，不把配置失败、队列接纳或静态回复当作模型执行成功

### Requirement: WebGUI 当前 profile 用户级 AGENTS 编辑

WebGUI MUST 显示、编辑和保存当前 OMP 进程有效 profile 的用户级 AGENTS 真实文件，展示实际目标路径。此能力不是项目 AGENTS 编辑器，也不是 `~/.zcode` 配置或任意路径写入入口。

#### Scenario: 读取编辑与保存
- **WHEN** 用户打开用户级 AGENTS 设置并修改保存
- **THEN** 显示当前有效 profile 的实际目标路径与真实内容，按该目标保存到真实文件并显示实际结果；文件尚不存在时展示实际缺失状态，用户显式保存才创建对应文件，不伪造已持久化内容
- **AND** 未保存或保存失败保留编辑内容；项目、页面或 profile 上下文变化时不能将旧编辑写到另一 profile／项目路径，须明确保留未保存状态并要求对正确目标提交，不泄露无关配置

### Requirement: WebGUI 文件与 Git 自动刷新

WebGUI MUST 自动更新所属项目的文件树、已打开预览及 Git 状态，覆盖原生工具和外部进程修改；此要求不新增 Git 写接口，不限制用户开发请求经原生工具或命令按已有权限修改代码及执行 Git 操作。

#### Scenario: 开发结果和外部修改可见
- **WHEN** 原生工具或外部编辑器创建、修改、删除文件，或改变已有 Git 状态
- **THEN** 对应页面无需用户手动刷新即更新文件树、预览内容／缺失状态及 Git 状态和 Diff，不持续显示旧内容，不将 B 的变化显示到 A
- **AND** 项目切换、页面退订、断连及服务退出清理所属订阅和 watcher，迟到刷新不覆盖新项目或新预览；读取失败显示真实错误，不以空树、空 Diff 冒充成功

#### Scenario: 只读浏览边界
- **WHEN** 网页读取项目文件、Git 或有效 Skill
- **THEN** 文件浏览提供列表、属性、搜索、文本及范围读取；Git 提供概览、变更、Diff、提交图、本地分支与自动刷新；每次读取以页面所属原生项目和会话的目录、权限为准，不固定旧 cwd
- **AND** 这些浏览读取不创建 Agent、不调用模型、不修改全局设置，不新增 Git 写接口、Checkpoint 或任意目录写入口，不泄露凭据；显式项目创建、附件提交、用户级 AGENTS 保存及原生工具／命令开发按各自合同与既有权限执行，不受只读面板边界错误禁止

### Requirement: WebGUI 全部原生命令与有效 Skill

WebGUI MUST 支持 TUI 全部内置命令及当前项目有效 Skill，与原生命令目录、参数、权限和执行语义一致；不得缩减为仅显示目录、大部分可用或对已要求能力统一返回不可用。

#### Scenario: 原生命令与 Skill 真实执行
- **WHEN** 用户在网页调用任一 TUI 内置命令或当前有效 Skill
- **THEN** 使用所属原生会话的真实命令／Skill 目录、参数解析及执行能力；Skill 按该会话真实 cwd 发现并执行，显示真实结果及错误，不通过 ZCode 插件库存决定可用性，也不把命令名或 Skill 名当作普通模型聊天冒充命令执行
- **AND** 交互式命令提供网页对应交互；模式与退出类命令先按原生独占、结清和权限规则完成当前模式结清，成功后才允许转换，失败保留原模式锁定，不允许同一原生会话或项目的 WebGUI 与 Dev 并发。未知命令或非法参数明确报错，不交给模型猜测执行

#### Scenario: 命令支持不恢复退役产品页
- **WHEN** 原生命令涉及模型、配置、统计、工具、Skill、MCP、Dev 或模式生命周期
- **THEN** 保留其原生执行与授权语义及必要命令结果／交互，不因删除 ZCode 页面删除底层能力；不恢复本规范明确删除的集成终端、部署、内嵌浏览器、商业推广、MCP 专属管理页或用量／成本统计面板，不为这些退役页面重建专属 Web 管理适配
- **AND** 用户调用原生统计或 MCP 等内置命令时仍提供其必要结果、输入和授权交互，不因专属面板退役将该命令降级为不可用；Git 面板只读不禁止原生开发工具／命令按原有权限执行写操作

#### Scenario: 浏览器承载原生交互而非伪造终端
- **WHEN** 内置命令需要编辑器、剪贴板、窗口、画面或音频等交互面
- **THEN** 在网页使用对应的真实浏览器交互，保持命令的原生操作、参数、授权和会话归属，不构造假 TUI／终端或用文字转录冒充实际画面；终端专属诊断在网页报告真实浏览器与传输能力，不声称存在终端协议或设备
- **AND** 网页 `/record` 通过用户明确授权录制真实浏览器共享画面并导出 WebM，开始、停止、失败和资源释放均对应真实录制状态；不得将视频称为 `.ompcast` 或宣称可由 `omp play` 回放，原 TUI `/record` 的 `.ompcast` 格式和 `omp play` 保持不变
- **AND** 网页 `/live` 复用原生实时语音服务及认证，浏览器持有实际麦克风与音频连接；不向网页暴露服务密钥，不改个人浏览器配置或绕过录屏／麦克风权限，拒绝、取消或缺少能力显示真实原因且释放自有媒体资源

### Requirement: WebGUI 不干扰正常 OMP 与 TUI

WebGUI MUST 是显式启用的独立宿主能力。网页功能及其实现改动 MUST NOT 改变普通 OMP／TUI 的既有默认行为、输入权限、会话生命周期或资源归属；未启用网页模式时不得产生网页运行副作用。

#### Scenario: 未启用时保持原生路径
- **WHEN** 用户正常启动、聊天、执行工具或使用 TUI、RPC、ACP，且未显式启用 WebGUI
- **THEN** 不启动网页服务、额外 SDK 会话、worker、watcher 或媒体，不安装网页问答／命令绑定，不读取网页项目目录或改写网页状态；原命令参数、模型选择、cwd、配置、审批、暂停、录制和错误行为保持原样
- **AND** 为网页复用原生代码时，新增选项、回调和宿主分支必须显式启用且默认走原路径，不把网页依赖循环、初始化或全局 current 状态引入普通入口；不得以支持网页为由顺带修订普通模式行为

#### Scenario: 借用原会话后完整恢复
- **WHEN** 从原 TUI 会话进入 WebGUI，再成功结清退出
- **THEN** 恢复该会话及草稿、真实工具／扩展 UI、审批与输入绑定，不 dispose 原会话，不遗留网页订阅、占用或媒体；原 TUI 能继续正常执行命令、问答、模型和工具，失败仍遵循独占门禁而非半恢复
- **AND** 网页显式新建会话的临时模型、队列、上下文与取消不污染原会话；用户明确保存用户级 AGENTS 等共享配置时仅按原生既有加载规则生效，不暗改其他配置，也不另存一份伪用户级文件来冒充保存

### Requirement: WebGUI 原生运行视图与退役页面边界

WebGUI MUST 保留原生子代理及任务运行视图，保持真实归属；产品精简仅移除明确指定的专属页面和适配，不删除原生 Agent／TUI／Dev 的能力或用户数据。

#### Scenario: 子代理与原生任务运行视图
- **WHEN** 网页查看父会话的子代理或原生 task／workpool 的实际运行

#### Scenario: 原 WebGUI 保持原样
- **WHEN** 用户通过 `/webgui` 或 `omp webgui` 使用原 WebGUI
- **THEN** 沿用既有前端、后端、项目及多会话行为，不出现新增 Dev 流程，不修改其入口、协议、构建配置或正式资源；不因 Dev 长期运行而绕过既有项目互斥和网络安全边界。


#### Scenario: Dev 不提供自由会话
- **WHEN** 查看 Dev 导航或通过旧链接选择正式 IR／SR
- **THEN** 不显示自由会话、会话列表、新建普通会话或正在开发区域；正式需求不挂载聊天和阶段动作，普通开发使用平台外的原生入口

#### Scenario: 提案临时目录与托管推送
- **WHEN** 长期 Dev 整理 OpenSpec 提案并准备入库
- **THEN** 业务需求及方案在固定临时工作区生成同一 Change，评审只读，项目代码只供参考；当前 IR、全部 SR 及方案经人工逐文件确认后，平台从最新默认分支创建提案分支并提交推送，不要求个人目录
- **AND** 人工在 Git 网页创建、评审、合并 PR；后台仅按合入且文档完整两个条件自动转正并创建各 SR 分支，不依赖人工通知，不启动编码、验收或归档 Agent。本轮仅演示，不新增真实 CLI、Git 或数据库实现
