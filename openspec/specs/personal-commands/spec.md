# personal-commands

## Purpose

规定个人 fork 新增或扩展的终端命令、关键词和会话操作语义，涵盖参数、状态迁移、取消与失败边界。复用原有命令链路，不建立平行调度器。

## Requirements

### Requirement: 原生 `/sketch` 离线画布

OMP MUST 在原生交互 TUI 提供无需安装扩展或额外配置的 `/sketch`，通过本地浏览器绘图后将真实 PNG 附件加入当前草稿，由用户手动发送。

#### Scenario: 本地绘图与手动提交

- **WHEN** 用户在原生 TUI 调用 `/sketch`
- **THEN** 打开自包含浏览器画布，支持手绘、剪贴板图片粘贴与标注、颜色、笔刷大小、撤销、清空和画布尺寸调整；图片粘贴取决于实际桌面剪贴板能力
- **AND** 浏览器按 `Enter` MUST 将 PNG 作为真实图片附件加入原输入草稿，保留已有文字与附件，MUST NOT 自动发送或启动模型回合；用户可补充描述后自行发送
- **AND** 画布 HTML、脚本、样式等离线资源 MUST 随源码和发行二进制静态内嵌；绘图本身 MUST NOT 请求公网、CDN 或外部模型服务
- **AND** 浏览器脚本 MUST 以 Firefox 52 ESR 的保守语法和基础 API 为基线（ES5 风格函数、`XMLHttpRequest`，不使用可选链、`async`/`await` 或 `NodeList.forEach`）；该设计基线 MUST NOT 被表述为公司旧 Firefox、CentOS 或桌面环境的实机兼容认证
- **AND** 本功能仅属于原生 TUI，MUST NOT 宣称 GUI、ACP 或 RPC 绘图集成，也不提供远程自动转发；OMP 与浏览器应在同一主机，异地主机须由用户自行将显示端口通过 SSH 转发至 OMP 的回环地址

#### Scenario: 取消、隔离与本地服务清理

- **WHEN** 用户在终端或浏览器按 `Escape`，或当前会话、视图归属或生命周期已变化
- **THEN** 取消 MUST 保留原输入草稿；会话切换、销毁或焦点移动后，旧结果 MUST NOT 插入其他会话或输入视图，包括 PNG 读取、归一化和附件插入期间的迟到结果
- **AND** 本地服务 MUST 仅绑定 `127.0.0.1`，以端口 `0` 请求系统分配端口，每次启动使用随机能力 URL，拒绝跨来源请求并限制提交载荷大小
- **AND** 提交完成、取消、失败或宿主销毁时 MUST 关闭本次本地服务并使旧能力 URL 失效

### Requirement: 内置 Developer Test Agent

OMP MUST 内置 Developer Test Agent 的专属子代理、五个技能及 `/dt`、`/generate-dt-files`、`/generate-dt-dir`、`/incremental-dt`、`/cloud-dt-fix` 命令，复用现有发现、命令展开、task、todo、ask 和 `skill://` 链路，不建立旧宿主 API 兼容层。

#### Scenario: 使用内置单元测试流程

- **WHEN** 用户调用上述命令或委托 `developer-test-agent`
- **THEN** 保留原插件的 Python、Java、C/C++ 和 Go 语言路由，按原有意图执行生成、修复、覆盖率、断言审查和报告流程，保持原有覆盖率门禁及批量任务串行规则
- **AND** 无需额外安装插件或配置资源目录；源码与发行产物均包含技能引用文档、脚本、示例和二进制资源，资源路径不依赖当前项目目录
- **AND** 专属子代理与五个技能默认不向 LLM 展示，不因普通测试请求自动选择、路由或注入提示；仅在用户显式指定代理、技能或上述命令时使用，保留手动发现与调用入口
- **AND** 子代理需澄清时将问题交回主代理询问，不在 headless 子代理内调用交互工具
- **AND** 保留 `.codecovcli/cache` 的本地覆盖率报告契约；原宿主的 `@baize/dtagent-plugin` 自动遥测上报是外部依赖，不因内置而宣称已提供，也不自动修改旧宿主的配置或历史记忆

### Requirement: 工具参数自纠正提示

OMP MUST 反馈本次工具未执行并要求模型修正重调，不重复已成功的调用。

#### Scenario: 工具参数自纠正提示的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 工具参数 JSON 解析失败时，保留原始错误，并明确告知模型本次工具未执行，要求修正参数后重新调用，不只解释错误，也不重复已成功的调用。复用既有工具错误反馈与后续模型回合，不新增重试机制、次数配置或模型特判，不放宽校验或隐藏失败状态。
- 工具参数未通过 schema 校验时，保留校验错误与收到的参数，提示工具未执行、修正后重调且不重复成功调用；`xd://` 设备内容不是有效 JSON 时，保留解析错误并说明通过 `write` 向该设备写入 `?` 查看文档，再以 JSON 对象重调。
- 普通 `write` 目标缺少必需内容时，保持失败且不修改目标；反馈明确指出调用未执行，指导模型将路径与正文作为独立参数重调，不从意图字段推断或恢复正文。允许省略内容的内部目标仍沿用各自策略。
- `bash` 参数校验失败时保留原始校验错误，说明本次未执行，指导以 JSON 的 `command` 字符串及正确参数重调并给出示例；不从错误字段恢复命令、不重复已成功的调用，也不改变命令执行失败的反馈。
- 未找到工具时，保留原错误及现有相近名称建议，明确本次调用未执行，列出本次请求中的工具（最多 20 个，超出时标明截断），指导模型使用合适的可用工具而不重复调用；不改变工具解析或权限。
- `task` 调用的注入意图 `i` 含明显串入的 `tasks` 数组及 `agent` 字段时，在派发前拒绝并提示本次未执行、`i` 只写简短意图、`agent` 放在真实 `tasks[]` 项中，同时提供可用调用示例；不从字符串推断或自动恢复代理名称，正常省略 `agent` 仍使用默认代理，不改变其他工具或拥有自身 `i` 参数的工具。

#### Scenario: 工具参数自纠正提示的可观察行为

- **WHEN** 工具参数 JSON 解析失败
- **THEN** 反馈本次工具未执行并要求模型修正重调，不重复已成功的调用

### Requirement: 非 TUI 宿主的命令参数门禁

OMP MUST 在 ACP 与 RPC 宿主按各自规则判定内置命令是否可执行及是否接受参数，不允许时不得隐式执行命令。

#### Scenario: 非 TUI 宿主的命令参数门禁的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- ACP 宿主收到带参数的内置命令时，MUST 按 `acpAllowArgs`（未声明时回退 `allowArgs`）判定是否接受；不允许时 MUST NOT 执行该命令，原始输入 MUST 作为普通提示词转发。
- ACP MAY 为在 TUI 中打开选择器的命令声明独立的 ACP 参数许可；`/model` 在 ACP 中 MUST 接受模型参数，并按该参数切换模型或报告解析失败。
- RPC 宿主 MUST 对全部注册名独立派发：仅实现 TUI 处理器的命令 MUST 抛错 `/name is only available in the interactive TUI.`；不接受参数的命令在带参调用时 MUST 抛错 `/name does not accept arguments.`。两者 MUST NOT 静默回退为普通提示词。
- 没有命中内置命令的输入 MUST 交由宿主按普通提示词处理，命令层不解释其内容或改写参数。

#### Scenario: 非 TUI 宿主的命令参数门禁的可观察行为

- **WHEN** ACP 或 RPC 宿主收到带参数的内置命令或仅 TUI 可用的命令
- **THEN** 按 ACP 参数许可接受或回退为提示词，RPC 则按独立派发接受或抛出明确错误，均不隐式执行

### Requirement: `/loop` 轮次间隔

OMP MUST 首轮立即执行并按指定轮次或总时长限制等待和继续，暂停或切换后旧定时器不提交。

#### Scenario: `/loop` 轮次间隔的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 支持 `/loop [次数或总时长] [间隔] [任务内容]`，间隔无需参数名，仅在有效限制参数后紧接的位置识别完整时长标记，支持秒、分钟、小时及组合时长；正文中的时长不再解析。条件参数仍可放在间隔后、正文前。
- `/loop 10 30s xxx` 首轮立即执行，总计最多 10 轮，每轮结束后等待 30 秒再启动下一轮；`/loop 10m 30s xxx` 最多运行 10 分钟，等待计入总时长，到期不再启动下一轮。
- 指定间隔时数字限制包含首轮。
- TUI 命令宿主沿用既有解析和语义，等待期间可以暂停、关闭或切换会话，旧定时器不得继续提交；首轮、条件检查及 compact/reset 沿用现有执行链，不允许重叠提交。

#### Scenario: `/loop` 轮次间隔的可观察行为

- **WHEN** 用户输入带间隔的 loop 命令
- **THEN** 首轮立即执行并按指定轮次或总时长限制等待和继续，暂停或切换后旧定时器不提交

### Requirement: `/loop` 间隔上限与时长 tokens 的退化

OMP MUST 对 `/loop` 间隔实施上限校验，并只在可识别为单位时长时消费该 token。

#### Scenario: `/loop` 间隔上限与时长 tokens 的退化的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 间隔上限 MUST 为 2147483647 毫秒；推算结果超出该值 MUST 报 `Loop interval must not exceed 2147483647 milliseconds.`，且 MUST NOT 启动任何轮次。
- 间隔位上的形如时长的 token 使用未知单位时，MUST 不被当作间隔，MUST 作为任务正文保留；已知单位的非正数或非安全整数金额 MUST 报错而非当作正文。
- 限制位与条件标志的解析失败（负号或小数形式的限制、未知标志、缺失条件命令、重复条件）MUST 只报用法错误，MUST NOT 启动模型回合。
- 既非限制形态也非标志形态的 token MUST 原样作为正文，保持无界 loop 语义。

#### Scenario: `/loop` 间隔上限与时长 tokens 的退化的可观察行为

- **WHEN** 用户给出的间隔超过上限，或在间隔位给出未知单位的时长 token
- **THEN** 超限时明确报错且不运行，未知单位时该 token 退回正文

### Requirement: 魔法关键词的内置命令

OMP MUST 提供魔法关键词对应的内置命令，并允许命令后直接携带任务文本。

#### Scenario: 魔法关键词的内置命令的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- fork 为三个关键词新增对应的内置命令 `/ultrathink`、`/orchestrate`、`/workflowz`，方便输入，并允许命令后直接携带任务文本。

#### Scenario: 魔法关键词的内置命令的可观察行为

- **WHEN** 用户调用 `/ultrathink`、`/orchestrate` 或 `/workflowz` 并携带任务文本
- **THEN** 对应命令接受任务文本并触发相应关键词行为

### Requirement: 共享命令目录与会话迁移

OMP MUST 让命令目录与相应宿主的派发能力一致，并在共享进程宿主中以会话级方式切换目录。

#### Scenario: 共享命令目录与会话迁移的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 命令目录 MUST 支持 `includeTuiOnlyBuiltins` 与 `includeRpcBuiltins`：省略时 MUST NOT 广告仅 TUI 命令，声明时 MUST 同时广告可用处理器对应的命令。
- 共享进程宿主 MUST 声明 `sessionScopedCwd`，会话迁移后由 sessionManager 提供当前目录；MUST NOT 修改进程级项目目录，以免影响同进程中的兄弟会话。
- `/wt` 解析出的目标路径与当前会话目录相同时 MUST 跳过重定位，并且 MUST NOT 清理源工作树或其中的未提交内容。

#### Scenario: 共享命令目录与会话迁移的可观察行为

- **WHEN** 宿主广告命令，或在共享进程中执行 `/move`、`/wt`
- **THEN** 目录与派发能力一致，目录切换只作用于当前会话，同路径目标不触发清理

### Requirement: JCH 命令

OMP MUST 各命令按其指定权限、参数、失败与取消边界执行，不让无效输入产生隐式副作用。

#### Scenario: JCH 命令的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

保留以下个人命令及其核心语义：

- `/minimal [任务]`：内置提示词命令，展开用户指定的最小充分变更与验证要求；可单独发送，也可携带任务文本，复用既有命令派发和普通用户消息链路。该提示词约束模型行为，不是程序级测试或修改拦截。

- `/jchime [故障现象]`：内置提示词恢复命令，面向内网较小模型提供完整可执行步骤及有边界的自主恢复空间；不是无模型的本地动作。默认环境为 CentOS 7、GNOME Terminal、SSH X11/Exceed、IBus 1.5.17 与 `libpinyin`；运行时重新核实，不使用快照中的历史地址或 PID。
  - 首选恢复块使用 Bash + 系统 Python 3.6+（本次调用显式 UTF-8 标准流编码），核对当前 UID、DISPLAY、唯一 daemon、地址文件归属和 PID、引擎可用性后，请求一次 `ibus restart`，重新发现实时总线并切回、核验 `libpinyin`。覆盖仅切引擎不能解决的 daemon/XIM 状态异常；同 daemon 的客户端会短暂中断，未提交的预编辑文字可能丢失。
  - 首选路径失败或实际症状未恢复时，模型必须根据真实结果继续诊断，自主选择引擎重切、恢复调用的总线/X11 环境对齐或当前显示会话 IBus 重建，不因脚本退出直接结束，不无依据重复失败步骤。正常重启无响应时，可在保存原始启动参数和必要环境、核对 UID/DISPLAY/PID/启动时间及信号前重验身份后，仅向该 daemon 的正数 PID 发送 SIGTERM；确认原进程退出且无其他 daemon 接管后按原启动方式重建，不自动升级 SIGKILL。daemon 已退出时，仅在当前用户、DISPLAY、X11 与现有 D-Bus 会话归属明确且无重复实例时启动，不创建替代 D-Bus 会话。
  - 只操作当前用户、当前 DISPLAY；目标或权限未确认时不执行变更。禁止 sudo、全局/进程组杀进程、安装、联网、持久配置修改及自动关闭终端/重启客户端；必要信息只读调查可继续，环境调整只作用于恢复调用及其子进程。安全手段耗尽或需客户端手动操作时报告具体阻塞，不将子进程环境修改当作运行中终端已修复。
  - 各路径均重新核验总线和实际引擎；原脚本成功标记不是自主方案的必要条件。服务正常与实际中文输入恢复分开报告，最后由用户在故障窗口切换并输入中文确认；Windows 本机、Electron 或客户端故障不承诺由服务端恢复。复用现有 TUI/ACP/RPC 提示词展开机制；验收包含提示词真实送达、目标隔离、首选失败后的自主权限和停止边界，不把模拟模型或本机 Windows 验证当作公司实机输入验收。
- `/jch-workflowzbatch <任务块软目标> <并发上限> <任务正文>`：内置提示词快捷命令，两个数量必须为正的安全整数，正文非空；非法输入只报用法，不启动模型回合。展开为以独立 `workflowz` 关键词开头的普通用户消息，保留正文首行缩进、内部换行、尾部空白与字面量，不新增关键词、调度器或配置写入。
  - 用于全仓审查、补日志、格式优化等互不依赖的批处理。任务块数量参数表示软上限，可按实际工作量调整，无需接近或凑足该数量，不扩大范围；任务块数与并发槽数独立，可以多于并发槽数，不以并发上限决定拆分数量。并发数量是向 OMP 下达的同时运行子代理总数上限指令（含嵌套），不是命令新增的程序级限制，现有配置上限更低时仍遵守，由工作池自动截断为较低值；提示词明确要求不向用户询问是否覆盖或修改并发上限，也不修改任何全局配置。
  - 按任务正文确认实际范围和统一规则，向子代理提供已核实的适用规则/需求路径，修改型任务分配不重叠文件集合并保留无关已有修改；复用现有工作池排队、完成即补位，不等待整批屏障。
  - 子代理按任务正文自主完成所属范围：只读任务只报告，修改任务完成证据充分且已授权的最小修改及允许的文件级检查；证据不足只列候选，不推测性修改或扩大范围。跨界发现交主代理协调，不越过文件归属直接修改；跨文件修改由主代理调整归属并指定单一修复责任人。
  - 主代理负责调度、及时补位、跨界协调和结果汇总，不默认重复读取已分配文件的完整 diff 或重审全部改动，仅对争议发现、跨文件修改和结果冲突作必要的定点核对，不集中补跑检查；子代理对所属修改的自查与允许检查不受此限制。
  - 主代理和所有子代理禁止任何测试（含单文件、冒烟、E2E）、全仓格式化、全仓静态检查及 fastcheck/fulltest/slowtest 等门禁。仅允许对自己负责修改的文件执行文件级非测试检查或任务要求的格式化，不能限定这些文件的工具不得运行，也不得扩大到目录、包或工作区。
  - 提示词的「执行」与「本次验证限制」两节须原样传给每个子代理（含嵌套委派），另附该子代理的具体任务与范围；两节约束适用于主代理及所有层级的子代理，并约束主代理收尾。与仓库及子目录 AGENTS.md 的验证要求冲突时，以本次明确限制为准，其他规则继续有效，系统及开发者级约束不受覆盖。不修改长期规则，不在汇总阶段补跑禁止操作。
  - 子代理精简返回完成状态、处理结果、覆盖及修改文件、实际文件级检查和受阻/未验证项；有发现或修复时保留触发条件、根因、修改位置及最短证据链，无发现时不展开调用链或正确性评级。主代理按任务项去重汇总完成项、失败或受阻项、修改文件及实际文件级检查，注明测试未运行与跨文件、运行时行为未验证，不声称功能验收通过。该例外仅适用于本命令发起的批处理，不适用于命令本身的实现维护。
  - 命令展开与参数边界需自动化验证；真实公开入口需确认展开内容以用户消息送至 Provider 并沿用原有关键词通知。命令机制验证不等于模型实际遵循约束或大规模批处理验收。

#### Scenario: JCH 命令的可观察行为

- **WHEN** 用户调用 JCH 命令且输入有效或无效
- **THEN** 各命令按其指定权限、参数、失败与取消边界执行，不让无效输入产生隐式副作用

### Requirement: `/clear` 在非 TUI 宿主的上下文重置

OMP MUST 在非 TUI 宿主原地重置上下文并保留会话身份，重置竞态时明确报告且不清空数据。

#### Scenario: `/clear` 在非 TUI 宿主的上下文重置的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 重置 MUST 原地清空对话上下文，会话 MUST 继续存在，会话 ID、标题、目录、模型与设置 MUST NOT 改变。
- 压缩进行中时 MUST 先中止压缩并等待其真正结束，再执行重置。
- 成功回执 MUST 为 `Context reset — N messages dropped; session continues.`，`N` 为实际丢弃的消息数；`N` 为 1 时 MUST 使用单数 `message`。
- 流式响应进行中 MUST NOT 重置，回执 MUST 提示先结束或中断当前响应。
- 等待压缩结束时若会话被切换或销毁，MUST 输出 `Session changed while resetting the context; nothing was cleared.`，MUST NOT 以异常使整个请求失败，也 MUST NOT 清空新会话的上下文。

#### Scenario: `/clear` 在非 TUI 宿主的上下文重置的可观察行为

- **WHEN** 在 ACP/RPC 会话中执行 `/clear`，且当时正在压缩、正在流式或发生会话切换
- **THEN** 按压缩等待、流式拒绝或竞态回执处理，成功时给出丢弃消息数的回执

### Requirement: `/logout` 在非 TUI 宿主的凭据移除

OMP MUST 按 provider 与账号移除存储凭据并刷新 provider 状态，其他凭据来源仍生效时明确警告。

#### Scenario: `/logout` 在非 TUI 宿主的凭据移除的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 未指定 provider 时 MUST 只列出存在存储凭据的 provider；仅一个时 MUST 直接使用，多个时 MUST 经选择界面选择；选择被取消 MUST 不删除任何凭据且不输出结果。
- 指定的 provider 未知 MUST 以警告跳过；没有存储凭据时 MUST 说明当前认证来自环境或配置文件并提示在其来源处移除。
- 同一 provider 有多个账号时 MUST 经账号选择；只有一个账号时 MUST 直接使用。
- 移除 MUST 只删除所选账号的存储凭据，并 MUST 刷新该 provider 的模型/认证状态。
- 移除后仍存在其他凭据来源时，回执 MUST 以警告级输出并包含 `still authenticated via …` 与实际来源；否则 MUST 为信息级。
- 选择期间会话 ID、generation、模型注册表或生命周期状态发生变化时 MUST 取消移除并报 `Logout cancelled: the session changed during account selection.`。

#### Scenario: `/logout` 在非 TUI 宿主的凭据移除的可观察行为

- **WHEN** 在 ACP/RPC 会话中执行 `/logout`，且存在多个账号、其他凭据来源或期间切换了会话
- **THEN** 按选择结果删除单个凭据并刷新 provider，必要时给出仍已认证的警告，竞态时取消

### Requirement: `/skills` 在非 TUI 宿主的注册表操作

OMP MUST 使用配置的注册表源并仅经确认授权安装带脚本的技能，结果以会话通知输出。

#### Scenario: `/skills` 在非 TUI 宿主的注册表操作的详细边界

- **THEN** 以下具体约束适用：

- 注册表源 MUST 为已配置的技能注册表地址，未配置时 MUST 使用默认注册表地址。
- `search`、`install`、`installed`、`update` 与帮助子命令 MUST 与非 TUI 结果输出一致；缺少查询或目标时必须报用法错误，未知子命令 MUST 报错并给出用法。
- 安装或更新包含脚本的技能时 MUST 经 `ui.confirm` 获取授权；宿主没有确认界面时 MUST 失败并说明需要确认能力，MUST NOT 默认同意。
- 输出 MUST 经会话通知机制发送（信息/警告/错误分级），变更完成后 MUST 刷新技能列表与命令列表；已是最新时 MUST 明确说明无需更新。
- 注册表或安装错误 MUST 以 `Skills: <原因>` 形式输出为错误通知，MUST NOT 使整个请求失败。

#### Scenario: `/skills` 在非 TUI 宿主的注册表操作的可观察行为

- **WHEN** 在 ACP/RPC 会话中执行 `/skills` 子命令，包括带脚本技能的安装
- **THEN** 使用配置或默认注册表，未获确认时不安装，结果经会话通知输出并刷新技能状态

### Requirement: `/knowledge` 的 RPC 面板

OMP MUST 在 RPC 宿主以对话框面板提供索引维护，破坏性操作需二次确认，取消与会话切换安全中止。

#### Scenario: `/knowledge` 的 RPC 面板的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- `/knowledge` 面板 MUST 提供索引列表、新建索引（目录与名称输入）、删除索引、搜索与 grep，并 MUST 支持分页浏览命中章节。
- 删除等破坏性操作 MUST 先经确认对话框；用户取消 MUST 本次操作不产生任何变更。
- 索引进度 MUST 节流上报（同一阶段未完成时至少间隔 200 毫秒），完成时 MUST 输出最终结果行。
- 任一阶段 MUST 记录包含操作标识与阶段名的操作日志；输出失败 MUST 只记录警告，不中断索引。
- 会话切换、销毁或取消信号触发时 MUST 中止当前索引操作并输出取消结果，MUST NOT 写入已切换会话。
- TUI MUST 继续打开既有面板，语义与外观不变。

#### Scenario: `/knowledge` 的 RPC 面板的可观察行为

- **WHEN** 在 RPC 宿主执行 `/knowledge` 并选择操作，或中途取消
- **THEN** 经确认后执行对应索引操作并按节流输出进度，取消与会话切换时安全中止

### Requirement: `/wt` 会话工作树

OMP MUST 按目标提交与工作树状态切换会话目录，保留两端未提交内容。

#### Scenario: `/wt` 会话工作树的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 以下工作树策略仅适用于 `/wt`。
- 指定的本地分支已存在时直接使用，不因同名报错、不重建或重置分支：已有对应工作树时把会话切到该目录；尚无对应工作树时为该分支创建工作树，检出该分支自身的提交，而不是当前分支的 `HEAD`。目标就是当前工作树的分支时保持当前位置，不重复创建。
- 指定的分支不存在时，从当前 `HEAD` 创建新分支与工作树。
- 新建工作树的根目录放在当前会话工作目录的父目录下，与当前目录平级，不放入 `~/.omp/wt`，也不由全局 `worktree.base` 或 `OMP_WORKTREE_DIR` 改变这一位置规则；已有工作树直接复用其原位置，不为满足平级要求搬迁它。目录冲突沿用现有可用路径选择机制，不覆盖已有目录。
- 新建工作树的代码以目标分支的已提交内容为准，不携带源目录的已暂存、未暂存、未跟踪改动或删除状态；当前分支及原目录的这些内容、暂存状态保持不变，不自动 stash、提交、reset 或 clean。`worktree.cleanSource` 不得让 `/wt` 清理原目录。
- 切换到已有工作树时保留该工作树自身的未提交改动，不用源目录覆盖它，也不为切换而清理它。

#### Scenario: `/wt` 会话工作树的可观察行为

- **WHEN** 用户用 wt 切换到已有分支、已有工作树或当前分支
- **THEN** 按目标提交与工作树状态切换会话目录，保留两端未提交内容

- **THEN** MUST 返回该设备文档，而不执行设备动作。

#### Scenario: 空内容和 help 不是文档入口
- **WHEN** 向设备写入空内容或 `help`，包括不同大小写

### Requirement: LSP code action 应用结果状态

OMP MUST 使 LSP code action 的结构化成功状态与实际应用结果一致。

### Requirement: 显式调用无模型网页保存命令

OMP MUST 提供用户显式调用的内置 `/crawl` 命令，在终端 TUI 与 OMP GUI 中直接执行网页保存，不通过 Skill 或 LLM 完成命令解析、抓取、转换和保存。命令默认只保存入口页，默认自动滚动和读取全文，不要求启用参数；支持递归、关闭逐屏滚动 `--no-scroll`、输出目录、并发数、最大页数、最大深度和最短渲染等待时间 `--wait <秒数>` 参数。

#### Scenario: 保存单个页面

- **WHEN** 用户输入 `/crawl https://example.com/page`，且浏览器与文件权限允许执行
- **THEN** OMP 仅抓取该入口页面并保存 Markdown，不递归访问页面中的链接
- **AND** 命令直接处理并显示结果，不启动模型回合

#### Scenario: 使用递归及限制参数

- **WHEN** 用户输入 `/crawl <URL> --recursive --output <目录> --concurrency <数量> --max-pages <数量> --max-depth <深度>`
- **THEN** OMP 依照指定目录、并发数、页数与深度上限递归处理，不将命令或参数交给模型解释
- **AND** 不提供上限参数时不默认限制页数和深度；不提供并发参数时递归抓取最多同时使用 2 个后台标签页

#### Scenario: 参数错误

- **WHEN** `/crawl` 缺少入口 URL、参数无法识别或参数值无效
- **THEN** OMP 显示用法或错误，不启动抓取，也不将该命令回退为模型提示

### Requirement: 复用用户浏览器并保留权限边界

`/crawl` MUST 使用 Browser Relay 在用户现有浏览器中创建自有后台标签，使用其可用登录态；MUST NOT 导航或关闭用户原有标签、抢占当前标签或窗口焦点。仅允许自动处理本规格定义的明确全文阅读控件；MUST NOT 点击无关业务按钮、提交表单或执行修改业务数据的交互操作。浏览器启用状态与现有授权和受限目录规则 MUST 继续生效。

#### Scenario: 使用已登录浏览器

- **WHEN** 用户的浏览器已连接 Relay，且用户显式启动抓取
- **THEN** OMP 使用自有后台标签访问页面，复用对应浏览器会话可用的登录态
- **AND** 结束或取消时释放自有标签，不关闭用户浏览器或用户原有标签

#### Scenario: 浏览器或授权不可用

- **WHEN** 浏览器被禁用、Relay 未连接、所需授权被拒绝或输出目录不符合既有权限规则
- **THEN** 命令明确报告原因，不绕过限制，也不静默改用其他浏览器或抓取途径
- **AND** `OMP_OFFLINE` 进程继续遵循现有浏览器禁用策略

### Requirement: 仅递归发现同源导航页面

递归抓取 MUST 只跟踪最终入口页面同协议、同主机和同端口的导航链接；MUST 对 URL 去重，忽略普通页内锚点但保留查询参数。`#/...` 属于页面路由而非页内锚点，导航、去重与来源记录 MUST 保留完整路由及其查询参数。导航重定向和全文读取 MAY 跨源，不因原始 URL 与最终页面不同源而阻断正常浏览器跳转；页面渲染所需的站外资源 MAY 正常加载，但其他站点的导航链接 MUST NOT 因此扩展递归范围。

#### Scenario: 站内外链接与 URL 去重

- **WHEN** 页面包含相同 URL 的多个片段链接、带不同查询参数的同源链接和站外链接
- **THEN** 片段不同但其余部分相同的 URL 只抓取一次，不同查询参数的 URL 分别处理
- **AND** 站外链接不加入递归抓取目标，页面正常渲染所需的站外 CSS、脚本和图片请求不因递归范围限制而被额外拦截

#### Scenario: Hash 路由与路由查询参数

- **WHEN** 入口或同源递归链接使用 `#/xxx/xxx?id=123&lang=zh` 形式的路由
- **THEN** OMP 使用包含完整 Hash 路由和查询参数的地址导航与记录来源，不退化为站点根页面
- **AND** 不同路由或路由查询参数分别抓取，相同路由与参数的重复链接只抓取一次

#### Scenario: 浏览器原生重定向与深度边界

- **WHEN** 入口或子页面发生 HTTP／JavaScript 重定向，或用户设置 `--max-depth 1`
- **THEN** OMP 像在已登录浏览器中打开 URL 一样使用原生导航、Cookie 和会话处理跳转，允许跨源重定向，等待最终页面并记录最终来源 URL，不另建匿名会话或伪造登录状态
- **AND** 递归范围以入口在重定向和全文读取后的最终来源确定；子页重定向到其他站点时可保存其最终内容，但不将该站点的其他导航链接加入递归目标
- **AND** 深度以入口页为第 0 层；深度为 1 时只处理入口页和其直接链接的同源页面

### Requirement: 保存独立且不覆盖的 Markdown 文件

OMP MUST 将每个成功提取的页面保存为独立 Markdown 文件，并在文件中记录来源 URL。默认输出到当前工作目录的 `tmp/`，`--output` 可指定其他目录；已有文件 MUST NOT 被覆盖。内容使用现有 HTML→Markdown 转换，保留已渲染主文档中的业务列表、表格及其他区块，不以文章筛选算法只保留一个正文片段；链接保留指向原网站的目标，不下载图片、PDF 或其他附件。

#### Scenario: 默认输出和重复保存

- **WHEN** 用户未指定输出目录并保存页面，或者目标文件名已存在
- **THEN** OMP 在当前工作目录的 `tmp/` 创建 Markdown 文件，内容包含页面提取结果及来源 URL
- **AND** 目标文件已存在时保留原文件，为新结果使用其他文件名

#### Scenario: 保存延迟渲染的企业页面

- **WHEN** 企业网站通过 JavaScript 延迟渲染业务内容，或从其他源的 API 加载数据
- **THEN** OMP 等待主文档加载完成、页面文字及各来源的文档／Fetch／XHR 请求稳定后再提取，不将跨域 API 排除在加载等待之外，持续事件流不作为必须结束的请求
- **AND** 默认在 DOM 就绪后至少等待 5 秒；`--wait <秒数>` 可指定 0–240 秒的最短等待时间并支持小数，用于延迟启动的应用；等待期间继续跟踪页面与网络状态，超时明确报错而不是保存尚未稳定的页面
- **AND** 提取保留文章之外已渲染的业务表格和列表，默认继续滚动和读取全文；不自动点击无关业务按钮或翻页

#### Scenario: 递归页面和附件

- **WHEN** 页面正文包含其他网页的相对链接、图片或 PDF 链接，且用户执行递归抓取
- **THEN** 每个成功抓取的网页分别生成 Markdown，正文链接保留可指向原网站的目标
- **AND** 不将图片、PDF 或其他附件下载为本地归档文件；正文提取可能省略导航等杂项，不承诺无损页面备份

### Requirement: 默认滚动加载页面内容

`/crawl` MUST 默认在自有后台标签中逐屏向下滚动主文档及视口内的嵌套滚动面板，在每次滚动后等待渲染文字和数据请求稳定；此行为 MUST 同样应用于入口页和递归子页面，不要求 `--scroll` 等启用参数。`--no-scroll` 显式关闭逐屏滚动，但不关闭全文读取；既有浏览器会话、授权、导航和取消边界继续生效，MUST NOT 点击“加载更多”等无关控件、翻页或操作用户原有标签。

#### Scenario: 滚动追加内容及子页面链接

- **WHEN** 页面或嵌套面板滚动后追加业务内容，或出现新的同源导航链接，且用户未显式指定 `--no-scroll`
- **THEN** OMP 继续滚动并等待，直至没有可继续向下滚动的可见区域，且末尾的滚动尺寸、页面文字和数据请求稳定后才保存 Markdown
- **AND** 保存结果包含仍保留在主文档中的追加内容，递归链接在滚动加载结束后发现，并继续遵循同源、去重和深度／页数边界
- **AND** `--wait` 为每页初始载入及打开全文后的最短等待时间，不在每次滚动后重复完整等待

#### Scenario: 无限增长、取消及虚拟列表

- **WHEN** 页面持续追加内容、用户取消，或列表离屏后移除已显示的数据
- **THEN** 滚动与加载共用有界的页面执行预算；无法到达稳定末尾时明确失败，不将未完成的结果作为完整页面保存
- **AND** 取消停止滚动并释放自有标签，保留此前已经保存的其他页面；不抢占用户原有标签或焦点
- **AND** 文档明确不承诺完整归档会移除旧行的虚拟列表，不通过业务 API、翻页或改变业务状态的操作补齐

#### Scenario: 滚动请求无法前进

- **WHEN** 滚动尺寸仍显示可继续向下，但实际滚动并等待稳定后，滚动位置和尺寸、页面地址及文字均未改变
- **THEN** OMP 明确报告滚动无进展并结束该页，不重复空转直至耗尽页面预算，也不将未完成页面保存为完整结果
- **AND** 释放该页的自有标签，继续遵循其他页面失败处理与取消边界

### Requirement: 默认读取明确的全文内容

`/crawl` MUST 默认识别可见且语义明确的全文阅读控件，包括“查看全文”“阅读全文”“展开全文”“显示全文”“继续阅读”及对应的明确英文阅读文字，不要求用户附加启用参数。MUST 优先展开页内内容；全文为 HTTP／HTTPS 链接时在自有标签中导航并处理重定向，不按链接的 `target` 新开窗口。读取成功后 MUST NOT 再沿推荐区的阅读链接自动串行跳转；显式同源递归仍按正常规则执行。

#### Scenario: 入口及子页的截断博客

- **WHEN** 入口或递归子页面默认仅显示摘要，并有明确的全文阅读控件
- **THEN** OMP 自动展开或导航到全文，等待渲染和数据请求稳定，再继续滚动及提取，保存全文与最终来源 URL
- **AND** 控件支持包裹文字的子元素、常见空白及末尾箭头，不将普通“加载更多”、点赞、评论或提交按钮视为全文操作

#### Scenario: 全文无法打开或操作会提交业务表单

- **WHEN** 全文控件不可用、点击后既无内容变化也无导航、指向下载／非网页协议，或会提交表单
- **THEN** 命令明确报告失败，不执行表单提交、不下载附件，也不将未变化的摘要伪报为全文
- **AND** 既有取消、失败继续处理其他页面及已保存文件保留规则继续生效

### Requirement: 进度、失败和取消

OMP MUST 在终端 TUI 和 GUI 中展示抓取进度与最终结果，并提供 `/crawl stop` 取消当前会话的抓取。页面访问或提取失败 MUST NOT 阻止处理其他可访问页面，最终结果 MUST 报告失败 URL 和原因；取消或中断后 MUST 保留已保存文件，不自动断点续爬。

#### Scenario: 一个页面失败但可发现其他链接

- **WHEN** 已打开的页面无法提取 Markdown，但仍能获取其导航链接
- **THEN** OMP 记录该页面 URL 和失败原因，继续尝试其符合范围的链接及队列中其他页面
- **AND** 最终向用户报告成功和失败结果，不伪报全部成功

#### Scenario: 用户取消任务并重新执行

- **WHEN** 用户在任务运行时输入 `/crawl stop`
- **THEN** 当前会话的抓取停止，已保存文件保留，自有后台标签得到释放
- **AND** 重新执行时从入口重新抓取，不自动恢复队列，也不覆盖已有文件

### Requirement: 终端命令及参数补全

OMP MUST 在终端提供 `/crawl` 命令名、参数名和 `--output` 本地目录补全；补全 MUST NOT 为生成 URL 候选而读取或提示浏览器历史。GUI MUST 支持执行该命令及其参数，但不要求提供参数补全。

#### Scenario: 终端输入命令参数

- **WHEN** 用户在终端输入 `/crawl`、参数名前缀或 `--output` 后的目录前缀
- **THEN** 终端分别提供匹配的命令、参数或本地目录候选，不读取浏览器历史填充 URL

#### Scenario: GUI 执行内置命令

- **WHEN** 用户在 OMP GUI 输入合法的 `/crawl` 或 `/crawl stop`
- **THEN** GUI 通过 OMP 内置命令执行并显示实际进度、结果或取消状态，不要求 GUI 提供参数补全

### Requirement: Dev 浏览器工作台启动入口

OMP MUST 提供会话内 `/dev` 和命令行 `omp dev` 两个工作台启动入口，自动打开浏览器并输出完整可复制地址。两者 MUST 指向目标目录的同一新 Dev 业务能力；会话内 `/dev` 进入独占 Dev，当前 TUI 此后仅接受再次 `/dev` 结清退出，不恢复旧 Dev 阶段输入或子操作，不因打开网页自动创建需求或调用模型。

#### Scenario: 从 OMP 会话打开
- **WHEN** 用户启动 OMP 后输入 `/dev`
- **THEN** 普通模型、工具或任务未结清时拒绝进入并提示先停止或等待，普通 Loop 未退出时提示先退出；不自动终止普通任务或退出 Loop。准入成功才启动或复用目标目录的工作台服务，自动打开浏览器并显示实际完整地址
- **AND** 进入后当前 TUI 拒绝所有普通命令和输入，仅接受再次 `/dev` 退出；网页与普通 TUI 不同时操作，普通原会话保留但不继续操作。不显示旧 Dev 三行固定状态区，也不自动启动需求、Team 或 Goal
- **AND** 普通 Collab 正在共享或处于 `join` 会话时拒绝进入，提示先自行停止共享或离开该会话，不自动停止共享或离开 Collab；成功进入后仍支持 Dev 网页按既有 Collab 机制共享及 `join`

#### Scenario: 直接从命令行打开
- **WHEN** 用户在自己的目录运行 `omp dev`，包括先手动 `git pull` 获取新流程记录后运行
- **THEN** 使用当前 OMP 的有效目录、profile、模型和运行环境启动工作台并打开浏览器，输出完整地址，不要求先手动进入 TUI 或另外启动前端开发服务器
- **AND** 读取已有新需求记录不自动拉取仓库、执行 Git 写入、迁移聊天、接管远端会话或启动 Agent

#### Scenario: 再次 dev 结清退出
- **WHEN** 用户已进入 Dev，在当前 TUI 再次执行 `/dev`
- **THEN** 通过既有 native stop／settlement 停止并结清 Dev 自有工作，成功后恢复普通原会话；失败保留 Dev 锁定及真实原因，不提前恢复普通命令和输入
- **AND** 退出不取消需求、不撤销 Git、不删除材料；不为普通 `/new`／move／dispose 与 Dev 并存保留会话快照、克隆或额外架构

#### Scenario: 单纯重开网页
- **WHEN** 用户重开同一工作台网页，而非在 TUI 再次执行 `/dev`
- **THEN** 返回已有实际入口和状态，不重复创建需求、不重放任务或确认；不将重开网页解释为退出 Dev
- **AND** 独立实例的开发冲突仍由同一工作区准入处理，不允许通过另一入口启动并行需求

#### Scenario: 浏览器无法自动打开
- **WHEN** 服务已就绪但宿主没有可用桌面浏览器，或自动打开失败
- **THEN** 仍输出完整实际地址，并明确报告浏览器未自动打开；不能把服务启动失败冒充仅浏览器打开失败，也不能只输出不可用地址

#### Scenario: 页面关闭不停止宿主任务
- **WHEN** 用户从任一入口打开的浏览器页面关闭、刷新或断开
- **THEN** 按 dev-browser-workbench 的生命周期保留宿主任务和 Dev 锁定，不恢复普通 TUI 输入；再次 `/dev` 退出、显式停止或退出 OMP 才按原生规则处理自有资源，页面不是执行 owner

### Requirement: 旧 Dev 终端交互退役但能力保留

OMP MUST 移除旧 Dev 阶段输入模式及其终端配置、详情、推进、丢弃和仅业务结束交互，`/dev` 只负责独占网页 Dev 的进入与结清退出。旧终端子命令产品路径 MUST 不再执行或作为兼容别名保留；其所需 Agent、材料、配置和控制能力转由网页复用，不删除普通 OMP TUI、其他原生命令或独立技能，但这些普通 TUI 操作须先成功退出 Dev。

#### Scenario: 旧子操作不绕过网页流程
- **WHEN** 用户尝试 `/dev new`、`business`、`finish-business`、`next`、`back`、`drop` 或 `config` 等旧终端子操作
- **THEN** 按当前真实命令目录明确拒绝，不启动旧模式、不执行部分控制、不交给模型或自动转换成旧流程
- **AND** 新建、业务文档输入、阶段确认、材料查看和需求删除仍可在网页按新合同完成，不能因移除终端 UI 一并删除功能；Team／模型角色配置继续使用既有配置方式，不新增网页配置入口

#### Scenario: 命令目录与帮助一致
- **WHEN** 用户查看补全、帮助或调用 Dev 入口
- **THEN** 目录准确展示 `/dev` 进入／再次 `/dev` 结清退出、Dev 中当前 TUI 只接受该退出动作，以及 `omp dev` 的网页启动语义；不宣传旧阶段终端操作、直接跳过业务检查或 drop 保留文件的行为
- **AND** 不新增旧状态兼容、恢复或迁移入口，不改变非 Dev 命令在普通模式的参数、权限及执行方式；协议宿主仍按既有目录与准入规则处理命令

### Requirement: WebGUI 浏览器正式入口

OMP MUST 提供 `/webgui` 和 `omp webgui`，复用已迁入的 ZCode Web／手机原有界面、前端服务契约及协议。本轮完成浏览器协议接入层，不实现聊天、历史管理、工具、审批、文件、Git、终端及 OMP 配置修改等业务能力；不迁移 ZCode 后端或桌面端。

#### Scenario: 会话内进入与退出
- **WHEN** 用户在普通 TUI 输入 `/webgui`
- **THEN** 复用 Dev 的 TUI 独占准入和输入门禁，并取得项目级占用权；成功后登记当前会话到本 OMP 进程的 Web 服务，输出本实例的本机和局域网地址并尝试打开浏览器，同进程内不按项目重复启动前端或监听器
- **AND** 当前终端只接受再次 `/webgui` 退出，普通会话与草稿保留；关闭或刷新网页不退出，手机直接访问本实例服务，不进行远控配对
- **AND** 再次 `/webgui` 或宿主关闭时结清本实例自有 Web 工作并关闭本实例服务；结清成功才恢复普通终端，失败保持锁定并允许重试，不关闭或影响其他 OMP 进程的服务

#### Scenario: 独立命令与资源边界
- **WHEN** 用户运行 `omp webgui`
- **THEN** 在当前 CLI 进程启动独立持有的 Web 服务，不发现或复用其他进程服务，不创建 Agent 会话、不占用项目、不调用模型、不自动安装依赖；浏览器使用本进程真实有效工作目录作为显示上下文，不生成项目或会话记录，命令退出关闭本实例服务
- **AND** 当前入口直接提供预先构建的迁入前端静态资源；Vite 仅用于资源构建，不作为常驻运行服务。资源缺失明确报告路径与准备方式，不以当前用户项目冒充 OMP 自有资源，不宣称已随发行二进制打包
- **AND** 每个 OMP 实例由系统分配独立空闲端口，同实例后续项目复用该端口；浏览器打开失败仍保留真实可访问地址，服务启动失败不得报告就绪；未调用入口时不启动服务或改写状态

#### Scenario: 浏览器协议与界面边界
- **WHEN** 电脑或手机通过浏览器打开 WebGUI
- **THEN** 两者直接连接 OMP 自有共享 Web 后端，使用同一份前端服务接口、协议编解码、数据 Schema 和错误语义；不引入独立中转服务、Relay、远控配对或桌面 Host，手机不依赖电脑浏览器在线
- **AND** 保留原有 Root、页面、布局、导航、聊天组件和各功能入口；移除额外预览说明、顶部调试／项目／会话信息栏、临时项目选择器和手机预览外框，不用新面板替代原有界面
- **AND** 全部浏览器依赖的服务方法与事件须有明确的协议响应，完成连接初始化、调用分发、订阅、退订和断连清理；启动只读取本轮真实拥有的连接状态、能力和界面设置，不伪造原生项目、会话、消息或操作结果
- **AND** 未接入业务方法用 TODO 注释注明待对接能力，并通过既有协议错误或能力状态明确表示尚未接入；前端在装配及原有提示机制中处理，不出现接口缺失、协议错误或未捕获异常，不以假成功或吞掉真实错误满足验收
- **AND** 手机只适配窄屏、布局、触控和输入，呈现不依赖远控功能开关；关闭浏览器不释放原生项目占用，不创建 Agent、不调用模型、不执行业务写入

#### Scenario: 本轮界面验收
- **WHEN** 在真实浏览器打开、刷新桌面界面并访问保留的导航及页面
- **THEN** 显示原有界面，无额外调试信息，无接口或未捕获错误；未接入操作明确提示且不产生业务副作用
- **AND** 不新增测试用例，手机实机界面及触控由用户验收，不以桌面浏览器证据宣称手机实机通过

### Requirement: 同进程 Web 后端与 Dev／WebGUI 项目互斥

每个 OMP 进程 MUST 独立持有同进程 Web 服务，同实例内多个项目会话共用本实例端口，不跨进程共享服务。Web 后端直接调用本进程原生接口，不经过内部 HTTP、不另起 SDK／Agent 或独立 Web worker。同一项目仍只能由一个原生 owner 持有 Dev 或 WebGUI 模式。

#### Scenario: 跨目录入口与 profile 统一准入
- **WHEN** 用户从 `/dev`、`omp dev` 或会话内 `/webgui` 进入项目模式
- **THEN** 按真实 Git 项目根或非 Git 真实目录确定项目身份，子目录、路径别名、会话 ID、配置根和 profile 不得绕过同一项目的 OS 级占用锁；先取得占用再建立业务宿主或发布入口
- **AND** 启动、运行、退出结清中均持有占用；模式冲突必须拒绝，不能只靠前端按钮或同一 TUI 的标志判断，不靠超时强制释放仍存活的 owner
- **AND** 保留 Dev 同目录同分支的既有开发名额、Git 与结清规则；退出失败不得释放项目占用或恢复普通终端

#### Scenario: 多项目单入口与选择隔离
- **WHEN** A、B 项目登记到同一 OMP 实例，电脑和手机选择项目
- **THEN** 使用本实例相同 HTTP 服务及端口，按项目 ID 直接路由到内存中的原生对象；每页独立选择，不修改后端全局“当前项目”，已离线项目不静默回落到其他项目，不发现其他 OMP 实例的项目
- **AND** WebGUI 只能读取 WebGUI 模式项目的会话信息；Dev 模式只显示占用并提示使用原生终端输出的完整工作台地址，不在公开项目列表分发其随机能力凭据，不允许改 URL 绕过模式门禁
- **AND** 同进程监听器直接挂载现有 Dev HTTP／WS 和能力路径，不经内部 HTTP 代理、不重写 Dev 业务；保留原生随机能力路径、Host／Origin／Cookie 语义及非 offline 仅本机访问边界，不把 WebGUI 局域网监听变成 Dev 的额外网络授权

#### Scenario: Web 服务归属与退出隔离
- **WHEN** 用户退出当前 Web 模式、关闭当前 OMP/TUI，或关闭浏览器
- **THEN** 退出 Web 模式须先结清本实例自有工作、关闭本实例 Web 服务和连接并释放自有项目占用；其他 OMP 进程及端口继续运行。关闭浏览器不退出模式，进程死亡由 OS 释放占用
- **AND** 服务与项目原生对象的关联只存本进程内存，不维护全局服务发现、后台常驻 Web worker、跨进程项目登记或代理控制端点；关闭 TUI 不得留下本实例可访问的 Web 服务
