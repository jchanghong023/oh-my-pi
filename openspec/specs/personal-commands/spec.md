# personal-commands

## Purpose

规定个人 fork 新增或扩展的终端命令、关键词和会话操作语义，涵盖参数、状态迁移、取消与失败边界。复用原有命令链路，不建立平行调度器。

## Requirements

### Requirement: 原生 `/workspace` 工作区写入提醒

OMP MUST 在原生 TUI 提供 `/workspace`，以隐藏提示词提醒模型遵守写入范围；它不是沙箱、可靠写保护或新增 `approvalMode`，MUST NOT 改变工具、模型、审批策略或 Plan 原有执行限制，也不新增 CLI 参数或 ACP 入口。

#### Scenario: 命令与独立会话状态

- **WHEN** 用户调用 `/workspace` 或 `/workspace <消息>`
- **THEN** 无参数 MUST 仅切换开关，不启动模型任务；带参数 MUST 确保开启，并经原生输入链路提交消息恰好一次，已开启时不关闭或忽略消息，保留草稿与附件处理
- **AND** 新会话默认关闭，状态独立持久化并随该会话恢复，不修改全局配置；可与 Plan 同时开启，原生补全与状态显示 MUST 反映开关，两者同时开启时均可辨识

#### Scenario: 明确允许路径与外部授权

- **WHEN** 开启后的主会话生成提醒
- **THEN** 提醒 MUST 携带归一化后的实际允许路径：当前 cwd 所在 Git 项目的真实根及子目录、`os.tmpdir()` 系统临时目录、当前会话 `local://` 实际目录；无 Git 项目时明确说明，直接修改范围仅为上述临时区域，不以 cwd 或主目录兜底
- **AND** 其他仓库与 `additionalDirectories` 不自动获准；符号链接及平台路径归一化只提高提醒准确性，不构成系统写保护
- **AND** 外部读取允许；对范围外的修改、创建、删除、移动或重命名，模型 MUST 先说明具体目标与操作并询问；用户已明确授权该路径及操作时不重复询问，不扩展授权，也不建立新的程序级授权缓存
- **AND** 提醒适用于文件工具、Bash、Eval、导入模块、脚本及子进程，不新增工具审批、命令分析、拦截器或执行限制

#### Scenario: 真实用户输入交付

- **WHEN** 开启时实际交付普通用户输入、忙时排队、steer 或 follow-up
- **THEN** 每个交付批次 MUST 附带一份当前隐藏提醒，不改写用户原文、草稿或历史编辑文本；同批多条用户消息不重复提醒
- **AND** 程序 synthetic follow-up、工具结果及子代理通知 MUST NOT 冒充新的用户提交；无新用户输入的重试或压缩不新增用户提交记录，开启时上下文重建仍保留当前提醒能力

#### Scenario: 子代理固定快照与恢复

- **WHEN** task 或 eval 创建子代理
- **THEN** 子代理 MUST 固定继承创建时的开关与明确允许范围，递归派生沿用快照，不因自己的 cwd 或其他仓库扩大范围；OMP 实际分配的隔离工作树额外获准，子代理使用自己的会话临时目录
- **AND** 父会话之后切换不打断或实时重配已有子代理，只影响父会话后续输入与之后创建的子代理；warm／cold 续跑 MUST 恢复子会话已记录的快照，而非套用父会话后来的状态
- **AND** 原有隔离创建、合并、清理、权限及子代理执行能力保持不变

#### Scenario: 关闭与历史上下文

- **WHEN** 用户关闭提醒或恢复已关闭的会话
- **THEN** MUST 停止生成活动提醒，并在上下文重建或续聊时依据持久化开关过滤旧活动提醒，不将旧开启文字视作当前状态；保留用户原始历史
- **AND** MUST NOT 承诺抹除模型已经看到的文字或摘要记忆，或保证模型绝不越界写入

### Requirement: 原生 `/sketch` 离线画布

OMP MUST 在原生交互 TUI 提供无需安装扩展或额外配置的 `/sketch`，通过本地浏览器绘图后将真实 PNG 附件加入当前草稿，由用户手动发送。

#### Scenario: 本地绘图与手动提交

- **WHEN** 用户在原生 TUI 调用 `/sketch`
- **THEN** 打开自包含浏览器画布，支持手绘、剪贴板图片粘贴与标注、颜色、笔刷大小、撤销、清空和画布尺寸调整；图片粘贴取决于实际桌面剪贴板能力
- **AND** 画布页面的按钮、操作说明、悬浮提示、无障碍标签及内置状态／错误提示 MUST 使用中文，保留快捷键名称和 PNG 等必要技术标识
- **AND** 浏览器按 `Enter` MUST 将 PNG 作为真实图片附件加入原输入草稿，保留已有文字与附件，MUST NOT 自动发送或启动模型回合；用户可补充描述后自行发送
- **AND** 画布 HTML、脚本、样式等离线资源 MUST 随源码和发行二进制静态内嵌；绘图本身 MUST NOT 请求公网、CDN 或外部模型服务
- **AND** 浏览器脚本、样式及 API MUST 以 Firefox 128 默认原生能力为基线，不再兼容 Firefox 52；本机浏览器验证 MUST 使用 Selenium＋geckodriver 和隔离临时 profile，MUST NOT 将本机验证表述为公司 CentOS 或实际桌面环境的兼容认证
- **AND** 本功能仅属于原生 TUI，MUST NOT 宣称 GUI、ACP 或 RPC 绘图集成，也不提供远程自动转发；OMP 与浏览器应在同一主机，异地主机须由用户自行将显示端口通过 SSH 转发至 OMP 的回环地址
- **AND** offline 不自动启动浏览器，显示完整画布地址供用户手动打开；Linux offline 打开原生 `/sketch` 时按[内网网页入口自动复制本机地址](../fork-runtime/spec.md#requirement-内网网页入口自动复制本机地址)请求复制完整画布地址，保留手动复制地址与原有草稿、取消和图片提交行为；其他环境不自动覆盖剪贴板

#### Scenario: 全窗口画布与视野操作

- **WHEN** 用户打开 `/sketch` 页面
- **THEN** 工具栏和状态区之外的浏览器窗口 MUST 全部用于绘图工作区，新画布初始尺寸匹配该区域；不强制浏览器进入系统全屏模式
- **AND** 支持滚轮围绕光标缩放、缩放按钮、100% 和适应窗口；支持空格加拖动、中键拖动和显式平移模式，平移不得产生笔迹，缩放和平移后绘图及画布尺寸调整的坐标 MUST 正确
- **AND** 缩放、平移及浏览器窗口尺寸变化 MUST NOT 改写已有图像像素或导出尺寸；提交 MUST 导出完整画布 PNG，而非当前可见区域，保留现有撤销、粘贴、清空和手动附件提交语义

#### Scenario: 取消、隔离与本地服务清理

- **WHEN** 用户在终端或浏览器按 `Escape`，或当前会话、视图归属或生命周期已变化
- **THEN** 取消 MUST 保留原输入草稿；会话切换、销毁或焦点移动后，旧结果 MUST NOT 插入其他会话或输入视图，包括 PNG 读取、归一化和附件插入期间的迟到结果
- **AND** 本地服务 MUST 仅绑定 `127.0.0.1`，以端口 `0` 请求系统分配端口，每次启动使用随机能力 URL，拒绝跨来源请求并限制提交载荷大小
- **AND** 提交完成、取消、失败或宿主销毁时 MUST 关闭本次本地服务并使旧能力 URL 失效

### Requirement: 内置 Developer Test Agent

OMP MUST 内置 Developer Test Agent 的专属子代理、五个技能及 `/dt`、`/generate-dt-files`、`/generate-dt-dir`、`/incremental-dt`、`/cloud-dt-fix` 命令，复用现有发现、命令展开、task、todo、ask 和 `skill://` 链路，不建立旧宿主 API 兼容层。

#### Scenario: 使用内置单元测试流程

- **WHEN** 用户调用上述命令或委托 `developer-test-agent`
- **THEN** 保留原插件的 Python、Java、C/C++ 和 Go 语言路由，按原有意图执行生成、修复、覆盖率、断言审查和报告流程，保持原有覆盖率门禁及批量任务串行规则
- **AND** 无需额外安装插件或配置资源目录；源码与发行产物均包含技能引用文档、脚本、示例和二进制资源，资源路径不依赖当前项目目录
- **AND** 专属子代理与五个技能默认不向 LLM 展示，不因普通测试请求自动选择、路由或注入提示；仅在用户显式指定代理、技能或上述命令时使用，保留手动发现与调用入口
- **AND** 子代理需澄清时将问题交回主代理询问，不在 headless 子代理内调用交互工具
- **AND** 保留 `.codecovcli/cache` 的本地覆盖率报告契约；原宿主的 `@baize/dtagent-plugin` 自动遥测上报是外部依赖，不因内置而宣称已提供，也不自动修改旧宿主的配置或历史记忆

### Requirement: 文件写入缺少正文时的反馈

普通 `write` 缺少必需正文时 MUST 拒绝写入，不从意图字段推断或恢复正文。允许省略正文的内部目标仍按各自规则处理。

#### Scenario: 普通文件写入缺少正文

- **WHEN** 普通 `write` 调用提供文件路径但缺少必需的 `content`
- **THEN** 目标不变，反馈指出未执行并指导模型提供独立的 `path` 和 `content` 参数。

### Requirement: `/loopn` 顺序循环提示词

OMP MUST 提供原生 TUI 命令 `/loopn "x1" "x2" "x3"`，只接收一个或多个非空提示词，不增加次数、间隔、条件等参数、编辑器或暂停恢复流程，不改变原 `/loop` 行为。

#### Scenario: 按序发送与回绕

- **WHEN** 用户启动 `/loopn` 并提供提示词列表
- **THEN** 首条立即进入原生提交链路，前一轮及其后台工作结清后才发送下一条，末条结束后回到首条；单条提示词也可循环
- **AND** 复用 Loop 调度及当前 `loop.mode` 上下文策略，状态栏显示 `LoopN · 当前序号/总数`；含空白的提示词使用引号，未闭合引号或空提示词报错且不启动
- **AND** 与 `/loop` 互斥，冲突时明确提示先停止已有循环，不替换其配置

#### Scenario: 停止后不自动恢复

- **WHEN** 用户按 `Esc`、再次输入 `/loopn` 或当前轮发生错误
- **THEN** 关闭循环并清除列表及待发送调度；`Esc` 沿用原生本轮中断，后续普通输入不恢复列表；重新启动必须重新提供提示词

### Requirement: 魔法关键词的内置命令

OMP MUST 提供魔法关键词对应的内置命令，并允许命令后直接携带任务文本。

#### Scenario: 魔法关键词的内置命令的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- fork 在原生 TUI 新增 `/ultrathink`、`/orchestrate`、`/workflowz`，并允许命令后直接携带任务文本；ACP 不注册这些内置命令。

#### Scenario: 魔法关键词的内置命令的可观察行为

- **WHEN** 用户调用 `/ultrathink`、`/orchestrate` 或 `/workflowz` 并携带任务文本
- **THEN** 对应命令接受任务文本并触发相应关键词行为

### Requirement: 同目录工作树切换

OMP MUST 保留 `/wt` 的同目录保护。

#### Scenario: 共享命令目录与会话迁移的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- `/wt` 解析出的目标路径与当前会话目录相同时 MUST 跳过重定位，并且 MUST NOT 清理源工作树或其中的未提交内容。

#### Scenario: 共享命令目录与会话迁移的可观察行为

- **WHEN** `/wt` 解析到当前会话目录
- **THEN** 不触发重定位或清理

### Requirement: JCH 命令

OMP MUST 各命令按其指定权限、参数、失败与取消边界执行，不让无效输入产生隐式副作用。

#### Scenario: JCH 命令的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

保留以下个人命令及其核心语义：

- `/minimal [任务]`：内置提示词命令，展开用户指定的最小充分变更与验证要求；可单独发送，也可携带任务文本，复用既有命令派发和普通用户消息链路。该提示词约束模型行为，不是程序级测试或修改拦截。

- `/jchime [故障现象]`：内置提示词恢复命令，面向内网较小模型提供完整可执行步骤及有边界的自主恢复空间；不是无模型的本地动作。默认环境为 CentOS 7、GNOME Terminal、SSH X11/Exceed、IBus 1.5.17 与 `libpinyin`；运行时重新核实，不使用快照中的历史地址或 PID。
  - 首选恢复块使用 Bash + 系统 Python 3.6+（本次调用显式 UTF-8 标准流编码），核对当前 UID、DISPLAY、唯一 daemon、地址文件归属和 PID、引擎可用性后，请求一次 `ibus restart`，重新发现实时总线并切回、核验 `libpinyin`。覆盖仅切引擎不能解决的 daemon/XIM 状态异常；同 daemon 的客户端会短暂中断，未提交的预编辑文字可能丢失。
  - 首选路径失败或实际症状未恢复时，模型必须根据真实结果继续诊断，自主选择引擎重切、恢复调用的总线/X11 环境对齐或当前显示会话 IBus 重建，不因脚本退出直接结束，不无依据重复失败步骤。正常重启无响应时，可在保存原始启动参数和必要环境、核对 UID/DISPLAY/PID/启动时间及信号前重验身份后，仅向该 daemon 的正数 PID 发送 SIGTERM；确认原进程退出且无其他 daemon 接管后按原启动方式重建，不自动升级 SIGKILL。daemon 已退出时，仅在当前用户、DISPLAY、X11 与现有 D-Bus 会话归属明确且无重复实例时启动，不创建替代 D-Bus 会话。
  - 只操作当前用户、当前 DISPLAY；目标或权限未确认时不执行变更。禁止 sudo、全局/进程组杀进程、安装、联网、持久配置修改及自动关闭终端/重启客户端；必要信息只读调查可继续，环境调整只作用于恢复调用及其子进程。安全手段耗尽或需客户端手动操作时报告具体阻塞，不将子进程环境修改当作运行中终端已修复。
  - 各路径均重新核验总线和实际引擎；原脚本成功标记不是自主方案的必要条件。服务正常与实际中文输入恢复分开报告，最后由用户在故障窗口切换并输入中文确认；Windows 本机、Electron 或客户端故障不承诺由服务端恢复。复用现有共享提示词展开机制；验收包含提示词真实送达、目标隔离、首选失败后的自主权限和停止边界，不把模拟模型或本机 Windows 验证当作公司实机输入验收。

#### Scenario: JCH 命令的可观察行为

- **WHEN** 用户调用 JCH 命令且输入有效或无效
- **THEN** 各命令按其指定权限、参数、失败与取消边界执行，不让无效输入产生隐式副作用

### Requirement: Grill Todo Markdown 任务清单

OMP MUST 内置仅显式调用的 `/skill:jch-grill-todo`，访谈正文保留 `jch-grill-me` 原文，仅将结束语改为访谈阶段结束、用户确认一致后询问是否生成 Todo，并在其后追加 Markdown 生成规则，原技能不变。用户确认达成一致后 MUST 另询是否在当前工作目录生成固定文件 `.todo.md`；达成一致不等于允许生成，允许生成不等于允许执行或覆盖旧文件。技能只负责符合格式的自包含 Markdown，不依赖执行器知识或提供运行器启动、解析及校验命令。

#### Scenario: 独立确认生成与覆盖

- **WHEN** 就绪问题全部解决且用户已确认双方理解一致
- **THEN** 单独询问是否生成文件；拒绝时不写文件，接受后重查文件是否存在，存在则另获覆盖许可，拒绝覆盖时保留原文件，不合并旧任务或另选文件名；生成许可前只读，不修改其他项目文件
- **AND** 用户停止访谈不代表达成一致或同意生成；重要决策变化使受影响分支重新澄清，并重新确认一致与生成许可

#### Scenario: 完整 Markdown 清单与文件交付

- **WHEN** 用户已允许生成及必要的覆盖
- **THEN** 写入真实、自包含的 Markdown，记录目标、范围、禁区、权限、已确认决策、经核实材料路径、前置条件、依赖顺序、具体变更及最小充分验证与完成标准，不依赖原会话记录，不留关键待定设计或占位任务
- **AND** 采用同级 `##` 任务分组，首个真实 checkbox 紧随所属分组标题，共享背景不含 checkbox；任务使用普通 `- [ ]`，细节为延续正文，不嵌套或以代码块包裹任务；跨组依赖明确
- **AND** 分组按文件顺序逐组闭环：每组所有任务均完成必要验证并可如实勾选后才进入下一组；前置依赖只能来自共享前置条件或已完成的前组，生成文件的共享背景必须明确该约束
- **AND** 每个 checkbox 必须有自己的产出、最小充分验证和可观察完成条件，完成依赖仅来自共享前置条件、已完成前项及本项工作，不等待后项；单项完成不等于完整产品验收，后续集成验收不得承担前项声称已经完成的首次必要验证
- **AND** 共用命令或同一批验收不自动要求合并；只有无法形成可独立验证的中间结果时，才把不可分的实现、测试、文档和验收合为一个 checkbox 的正文步骤，不提前勾选、弱化验证、重复检查或仅因工作相关就生成巨大 checkbox；保持约定的验证范围与频率
- **AND** 确认文件写入并检查 Markdown 结构，按文件顺序逐 checkbox 核对能否仅凭共享前置条件、已完成前项与本项工作及验证完成，再检查组级闭环；有前向完成依赖时先重排或调整任务边界再生成，不依赖跳过未完成项或回填前项，交付实际路径及实际检查结果，不将生成文件视为任务已实施或验收通过
- **AND** 不自动实施任务或创建执行会话；本技能为模型提示词约束，不新增运行时权限机制

#### Scenario: 统一验收不能阻塞前组勾选

- **WHEN** 实现任务必须等测试编写、文档同步及统一公开入口验收成功后才可勾选
- **THEN** 检查是否存在有自身完成证据的中间交付；只有无法独立验证时，才把这些不可分工作合为一个 checkbox 的正文步骤并置于可闭环的组，不生成“组 1 实现但等组 3 验收才勾选、组 3 又等组 1 完成”的清单
- **AND** 只有前组已有充分独立验收证据、不依赖后组才能完成时，才允许另设后续集成或最终验收组；不依赖执行器跳过未完成组或事后回填前组 checkbox

#### Scenario: 分阶段完成不等于整体验收

- **WHEN** 采用 TDD 或后续集成验收
- **THEN** 可将回归测试、修复及最终验收分别列项：测试项以观察到预期失败为完成条件，修复项以相关回归转绿为完成条件，最终验收检查更大范围的约定合同；前项不得等待后项才能勾选
- **AND** 在生成文件中明确单项完成与产品验收的区别，预期失败不宣称产品通过，也不要求每项重复完整产品验收

### Requirement: `/wt` 会话工作树

OMP MUST 按目标提交与工作树状态切换会话目录，保留两端未提交内容。

#### Scenario: `/wt` 会话工作树的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- 以下工作树策略仅适用于 `/wt`。
- 指定的本地分支已存在时直接使用，不因同名报错、不重建或重置分支：已有对应工作树时把会话切到该目录；尚无对应工作树时为该分支创建工作树，检出该分支自身的提交，而不是当前分支的 `HEAD`。目标就是当前工作树的分支时保持当前位置，不重复创建。
- 指定的分支不存在时，从当前 `HEAD` 创建新分支与工作树。
- 新建工作树的根目录放在当前会话工作目录的父目录下，与当前目录平级，不放入 `~/.omp/wt`，也不由全局 `worktree.base` 或 `OMP_WORKTREE_DIR` 改变这一位置规则；已有工作树直接复用其原位置，不为满足平级要求搬迁它。目录冲突沿用现有可用路径选择机制，不覆盖已有目录。
- 新建工作树的代码以目标分支的已提交内容为准，不携带源目录的已暂存、未暂存、未跟踪改动或删除状态；当前分支及原目录的这些内容、暂存状态保持不变，不自动 stash、提交、reset 或 clean。`worktree.cleanSource` 不得让 `/wt` 清理原目录。
- 切换到已有工作树时保留该工作树自身的未提交改动，不用源目录覆盖它，也不为切换而清理它。

#### Scenario: `/wt` 会话工作树的可观察行为

- **WHEN** 用户用 wt 切换到已有分支、已有工作树或当前分支
- **THEN** 按目标提交与工作树状态切换会话目录，保留两端未提交内容

### Requirement: LSP code action 应用结果状态

OMP MUST 使 LSP code action 的结构化成功状态与实际应用结果一致。

- **AND** 没有候选或无法唯一选定时不应用任何动作，返回明确提示，`details.success` 为 `false` 且工具结果标记失败。

### Requirement: 显式调用无模型网页保存命令

OMP MUST 提供用户显式调用的内置 `/crawl` 命令，在终端 TUI 与 OMP GUI 中直接执行网页保存，不通过 Skill 或 LLM 完成命令解析、抓取、转换和保存。命令默认只保存入口页，默认自动滚动和读取全文，不要求启用参数；支持递归、关闭逐屏滚动 `--no-scroll`、输出目录、并发数、最大页数、最大深度和最短渲染等待时间 `--wait <秒数>` 参数。

#### Scenario: 保存单个页面

- **WHEN** 用户输入 `/crawl https://example.com/page`，且浏览器与文件权限允许执行
- **THEN** OMP 仅抓取该入口页面并保存 Markdown，不递归访问页面中的链接
- **AND** 命令直接处理并显示结果，不启动模型回合

#### Scenario: 使用递归及限制参数

- **WHEN** 用户输入 `/crawl <URL> --recursive --output <目录> --concurrency <数量> --max-pages <数量> --max-depth <深度>`
- **THEN** OMP 依照指定目录、并发数、页数与深度上限递归处理，不将命令或参数交给模型解释
- **AND** 不提供上限参数时不默认限制页数和深度；不提供并发参数时递归抓取最多同时使用 2 个后台标签页

#### Scenario: 参数错误

- **WHEN** `/crawl` 缺少入口 URL、参数无法识别或参数值无效
- **THEN** OMP 显示用法或错误，不启动抓取，也不将该命令回退为模型提示

### Requirement: 复用用户浏览器并保留权限边界

`/crawl` MUST 使用 Browser Relay 在用户现有浏览器中创建自有后台标签，使用其可用登录态；MUST NOT 导航或关闭用户原有标签、抢占当前标签或窗口焦点。仅允许自动处理本规格定义的明确全文阅读控件；MUST NOT 点击无关业务按钮、提交表单或执行修改业务数据的交互操作。浏览器启用状态与现有授权和受限目录规则 MUST 继续生效。

#### Scenario: 使用已登录浏览器

- **WHEN** 用户的浏览器已连接 Relay，且用户显式启动抓取
- **THEN** OMP 使用自有后台标签访问页面，复用对应浏览器会话可用的登录态
- **AND** 结束或取消时释放自有标签，不关闭用户浏览器或用户原有标签

#### Scenario: 浏览器或授权不可用

- **WHEN** 浏览器被禁用、Relay 未连接、所需授权被拒绝或输出目录不符合既有权限规则
- **THEN** 命令明确报告原因，不绕过限制，也不静默改用其他浏览器或抓取途径
- **AND** `OMP_OFFLINE` 进程继续遵循现有浏览器禁用策略

### Requirement: 仅递归发现同源导航页面

递归抓取 MUST 只跟踪最终入口页面同协议、同主机和同端口的导航链接；MUST 对 URL 去重，忽略普通页内锚点但保留查询参数。`#/...` 属于页面路由而非页内锚点，导航、去重与来源记录 MUST 保留完整路由及其查询参数。导航重定向和全文读取 MAY 跨源，不因原始 URL 与最终页面不同源而阻断正常浏览器跳转；页面渲染所需的站外资源 MAY 正常加载，但其他站点的导航链接 MUST NOT 因此扩展递归范围。

#### Scenario: 站内外链接与 URL 去重

- **WHEN** 页面包含相同 URL 的多个片段链接、带不同查询参数的同源链接和站外链接
- **THEN** 片段不同但其余部分相同的 URL 只抓取一次，不同查询参数的 URL 分别处理
- **AND** 站外链接不加入递归抓取目标，页面正常渲染所需的站外 CSS、脚本和图片请求不因递归范围限制而被额外拦截

#### Scenario: Hash 路由与路由查询参数

- **WHEN** 入口或同源递归链接使用 `#/xxx/xxx?id=123&lang=zh` 形式的路由
- **THEN** OMP 使用包含完整 Hash 路由和查询参数的地址导航与记录来源，不退化为站点根页面
- **AND** 不同路由或路由查询参数分别抓取，相同路由与参数的重复链接只抓取一次

#### Scenario: 浏览器原生重定向与深度边界

- **WHEN** 入口或子页面发生 HTTP／JavaScript 重定向，或用户设置 `--max-depth 1`
- **THEN** OMP 像在已登录浏览器中打开 URL 一样使用原生导航、Cookie 和会话处理跳转，允许跨源重定向，等待最终页面并记录最终来源 URL，不另建匿名会话或伪造登录状态
- **AND** 递归范围以入口在重定向和全文读取后的最终来源确定；子页重定向到其他站点时可保存其最终内容，但不将该站点的其他导航链接加入递归目标
- **AND** 深度以入口页为第 0 层；深度为 1 时只处理入口页和其直接链接的同源页面

### Requirement: 保存独立且不覆盖的 Markdown 文件

OMP MUST 将每个成功提取的页面保存为独立 Markdown 文件，并在文件中记录来源 URL。默认输出到当前工作目录的 `tmp/`，`--output` 可指定其他目录；已有文件 MUST NOT 被覆盖。内容使用现有 HTML→Markdown 转换，保留已渲染主文档中的业务列表、表格及其他区块，不以文章筛选算法只保留一个正文片段；链接保留指向原网站的目标，不下载图片、PDF 或其他附件。

#### Scenario: 默认输出和重复保存

- **WHEN** 用户未指定输出目录并保存页面，或者目标文件名已存在
- **THEN** OMP 在当前工作目录的 `tmp/` 创建 Markdown 文件，内容包含页面提取结果及来源 URL
- **AND** 目标文件已存在时保留原文件，为新结果使用其他文件名

#### Scenario: 保存延迟渲染的企业页面

- **WHEN** 企业网站通过 JavaScript 延迟渲染业务内容，或从其他源的 API 加载数据
- **THEN** OMP 等待主文档加载完成、页面文字及各来源的文档／Fetch／XHR 请求稳定后再提取，不将跨域 API 排除在加载等待之外，持续事件流不作为必须结束的请求
- **AND** 默认在 DOM 就绪后至少等待 5 秒；`--wait <秒数>` 可指定 0–240 秒的最短等待时间并支持小数，用于延迟启动的应用；等待期间继续跟踪页面与网络状态，超时明确报错而不是保存尚未稳定的页面
- **AND** 提取保留文章之外已渲染的业务表格和列表，默认继续滚动和读取全文；不自动点击无关业务按钮或翻页

#### Scenario: 递归页面和附件

- **WHEN** 页面正文包含其他网页的相对链接、图片或 PDF 链接，且用户执行递归抓取
- **THEN** 每个成功抓取的网页分别生成 Markdown，正文链接保留可指向原网站的目标
- **AND** 不将图片、PDF 或其他附件下载为本地归档文件；正文提取可能省略导航等杂项，不承诺无损页面备份

### Requirement: 默认滚动加载页面内容

`/crawl` MUST 默认在自有后台标签中逐屏向下滚动主文档及视口内的嵌套滚动面板，在每次滚动后等待渲染文字和数据请求稳定；此行为 MUST 同样应用于入口页和递归子页面，不要求 `--scroll` 等启用参数。`--no-scroll` 显式关闭逐屏滚动，但不关闭全文读取；既有浏览器会话、授权、导航和取消边界继续生效，MUST NOT 点击“加载更多”等无关控件、翻页或操作用户原有标签。

#### Scenario: 滚动追加内容及子页面链接

- **WHEN** 页面或嵌套面板滚动后追加业务内容，或出现新的同源导航链接，且用户未显式指定 `--no-scroll`
- **THEN** OMP 继续滚动并等待，直至没有可继续向下滚动的可见区域，且末尾的滚动尺寸、页面文字和数据请求稳定后才保存 Markdown
- **AND** 保存结果包含仍保留在主文档中的追加内容，递归链接在滚动加载结束后发现，并继续遵循同源、去重和深度／页数边界
- **AND** `--wait` 为每页初始载入及打开全文后的最短等待时间，不在每次滚动后重复完整等待

#### Scenario: 无限增长、取消及虚拟列表

- **WHEN** 页面持续追加内容、用户取消，或列表离屏后移除已显示的数据
- **THEN** 滚动与加载共用有界的页面执行预算；无法到达稳定末尾时明确失败，不将未完成的结果作为完整页面保存
- **AND** 取消停止滚动并释放自有标签，保留此前已经保存的其他页面；不抢占用户原有标签或焦点
- **AND** 文档明确不承诺完整归档会移除旧行的虚拟列表，不通过业务 API、翻页或改变业务状态的操作补齐

#### Scenario: 滚动请求无法前进

- **WHEN** 滚动尺寸仍显示可继续向下，但实际滚动并等待稳定后，滚动位置和尺寸、页面地址及文字均未改变
- **THEN** OMP 明确报告滚动无进展并结束该页，不重复空转直至耗尽页面预算，也不将未完成页面保存为完整结果
- **AND** 释放该页的自有标签，继续遵循其他页面失败处理与取消边界

### Requirement: 默认读取明确的全文内容

`/crawl` MUST 默认识别可见且语义明确的全文阅读控件，包括“查看全文”“阅读全文”“展开全文”“显示全文”“继续阅读”及对应的明确英文阅读文字，不要求用户附加启用参数。MUST 优先展开页内内容；全文为 HTTP／HTTPS 链接时在自有标签中导航并处理重定向，不按链接的 `target` 新开窗口。读取成功后 MUST NOT 再沿推荐区的阅读链接自动串行跳转；显式同源递归仍按正常规则执行。

#### Scenario: 入口及子页的截断博客

- **WHEN** 入口或递归子页面默认仅显示摘要，并有明确的全文阅读控件
- **THEN** OMP 自动展开或导航到全文，等待渲染和数据请求稳定，再继续滚动及提取，保存全文与最终来源 URL
- **AND** 控件支持包裹文字的子元素、常见空白及末尾箭头，不将普通“加载更多”、点赞、评论或提交按钮视为全文操作

#### Scenario: 全文无法打开或操作会提交业务表单

- **WHEN** 全文控件不可用、点击后既无内容变化也无导航、指向下载／非网页协议，或会提交表单
- **THEN** 命令明确报告失败，不执行表单提交、不下载附件，也不将未变化的摘要伪报为全文
- **AND** 既有取消、失败继续处理其他页面及已保存文件保留规则继续生效

### Requirement: 进度、失败和取消

OMP MUST 在终端 TUI 和 GUI 中展示抓取进度与最终结果，并提供 `/crawl stop` 取消当前会话的抓取。页面访问或提取失败 MUST NOT 阻止处理其他可访问页面，最终结果 MUST 报告失败 URL 和原因；取消或中断后 MUST 保留已保存文件，不自动断点续爬。

#### Scenario: 一个页面失败但可发现其他链接

- **WHEN** 已打开的页面无法提取 Markdown，但仍能获取其导航链接
- **THEN** OMP 记录该页面 URL 和失败原因，继续尝试其符合范围的链接及队列中其他页面
- **AND** 最终向用户报告成功和失败结果，不伪报全部成功

#### Scenario: 用户取消任务并重新执行

- **WHEN** 用户在任务运行时输入 `/crawl stop`
- **THEN** 当前会话的抓取停止，已保存文件保留，自有后台标签得到释放
- **AND** 重新执行时从入口重新抓取，不自动恢复队列，也不覆盖已有文件

### Requirement: 终端命令及参数补全

OMP MUST 在终端提供 `/crawl` 命令名、参数名和 `--output` 本地目录补全；补全 MUST NOT 为生成 URL 候选而读取或提示浏览器历史。GUI MUST 支持执行该命令及其参数，但不要求提供参数补全。

#### Scenario: 终端输入命令参数

- **WHEN** 用户在终端输入 `/crawl`、参数名前缀或 `--output` 后的目录前缀
- **THEN** 终端分别提供匹配的命令、参数或本地目录候选，不读取浏览器历史填充 URL

#### Scenario: GUI 执行内置命令

- **WHEN** 用户在 OMP GUI 输入合法的 `/crawl` 或 `/crawl stop`
- **THEN** GUI 通过 OMP 内置命令执行并显示实际进度、结果或取消状态，不要求 GUI 提供参数补全

### Requirement: `/todoloop` 普通 Markdown 文件入口

原生 TUI MUST 提供 `/todoloop <路径>` 和 `/todoloop <路径> --check`。命令接受普通 Markdown，不要求固定文件名或 OpenSpec 项目，且不改变会话的工作目录或权限。

#### Scenario: 普通清单与 OpenSpec 任务使用同一入口

- **WHEN** 用户传入普通 Markdown 或 `openspec/changes/<change>/tasks.md`
- **THEN** 使用同一清单规则；相对路径以当前会话工作目录解析，支持按既有命令语法引用含空格的路径。执行代理沿用会话工作目录，不切换至文件父目录，也不自动执行 OpenSpec 工作流。

#### Scenario: 参数错误与宿主边界

- **WHEN** 缺少路径、存在多余参数或未知选项，或者在非原生 TUI 宿主调用
- **THEN** 无效参数报告用法且不搜索默认文件；非原生 TUI 沿用宿主的命令准入，不新增 CLI、ACP 或 RPC 执行入口。不因调用无效或不受支持而启动模型、代理或修改文件。

### Requirement: `/todoloop --check` 只读预检

`--check` MUST 使用与默认执行相同的文件解析和分组校验，在不启动模型或代理、不修改文件的前提下展示预检结果。

#### Scenario: 预检结果与执行前校验一致

- **WHEN** 用户预检一份清单
- **THEN** 对合法清单按文件顺序展示分组、任务身份、正文和完成标记，包含任务与组的完成数／总数及首个未完成组和组内首个未完成项；全部完成时如实展示。
- **AND** 文件不存在、无法读取、没有任务或格式非法时报告具体错误；默认执行也在派发任何代理之前拒绝同类错误，不自动修复 Markdown。

### Requirement: `/todoloop` 支持无编号 Markdown 任务

OMP MUST 支持无编号的 `[ ]`、`[x]`、`[X]` checkbox，与已有数字／点分数字编号及 Superpowers Step 任务混用，保持标题分组及文件顺序。无编号任务 MUST 有非空正文，按包含已完成项的全文件 checkbox 顺序生成独立 `auto:N` 内部身份并显示顺序号，不改写原文件或要求用户补编号；数字编号仍全文件唯一，Step 编号仍组内唯一，无效 Step 格式仍报错。

#### Scenario: 组内任务不带编号

- **WHEN** 组内包含 `- [ ] 待办任务`、`- [x] 已完成任务`，并与数字或 Step 任务混用
- **THEN** 预检及执行均接受无编号任务，自动身份不与数字或 Step 身份冲突，勾选及合法追加说明不改变身份
- **AND** 执行期间保留任务数量、身份、正文、顺序与分组校验，增删、重排或改写既有正文行仍报错（当前组任务末尾追加执行记录除外）

#### Scenario: 任务身份或格式不合法

- **WHEN** 同一文件存在重复数字编号、同组存在重复 Step 编号，或真实任务的 Step 格式、checkbox 状态或正文不合法
- **THEN** 报告格式错误，不跳过异常项继续派发，也不自动补编号或修复状态；不同组可使用相同 Step 编号，任务顺序不按编号重排。

#### Scenario: 执行记录与原任务正文分段

- **WHEN** 执行代理在当前组任务下追加执行或验证记录
- **THEN** 组提示建议记录追加在原任务全部延续正文及已有记录之后、下一任务或标题之前，与前文隔空行，并提供合法 Markdown 示例；程序同时接受不带空行的新行追加记录，不因追加导致段落变长就误判正文被改写
- **AND** 不在原正文内部插入空行、不重写旧记录、不增加标题或 checkbox；必须保留每条原始正文及已有说明行，非当前组不得追加记录；文件末尾追加不要求额外的末尾换行

#### Scenario: 常见 Markdown 清单格式与隐藏示例

- **WHEN** 文件使用无编号、数字或 Superpowers Step 任务、不同列表标记、缩进与 Tab、LF／CRLF／CR 换行，或以 UTF-8 BOM 开头
- **THEN** 保留原文件文本与任务顺序、按原文定位 checkbox，勾选及合法追加记录后可重读并继续执行；代码围栏、缩进代码与 HTML 注释内的标题和 checkbox 不进入清单
- **AND** 最近标题支持 ATX 及 Setext 的一级 `===`／二级 `---` 下划线标题，可混用；Setext 多行标题与下划线属于不可改写的原文，分组层级及身份仍由第一个真实 checkbox 确定
- **AND** 无法确定任务边界的未闭合代码围栏报告格式错误，不把后续真实任务静默吞掉；TodoLoop 的格式校验不改变 OpenSpec 自身的任务解析与计数。

#### Scenario: 原始输入只在内存保留

- **WHEN** TodoLoop 首次成功读取并解析本次输入
- **THEN** 在启动代理前保留原始文本快照，后续进度重读和格式破坏不得覆盖它；运行状态及结果提供 `originalContent`，供诊断和调用者显式决定恢复
- **AND** 不生成磁盘备份、不自动回滚工作文件，不以备份代替当前 checkbox 推进；快照不跨进程持久化，恢复不能伪装为此前任务已验收

### Requirement: `/todoloop` 确定性任务分组

TodoLoop MUST 以第一个真实 checkbox 前最近标题的层级划分同级组，保持文件及组内顺序。不得以编号前缀、首个未完成项或模型判断推断分组，且不派发无任务的组。

#### Scenario: 前置标题确定全文件组级

- **WHEN** 第一个真实 checkbox 前的最近标题为 ATX 或 Setext 标题
- **THEN** 同层级标题切分组，其他层级标题只作为上下文；同名标题对应不同章节，不合并。首项已完成或续做时仍沿用该层级，围栏、缩进代码和注释内的标题或 checkbox 不改变判断。

#### Scenario: 首个 checkbox 前无标题

- **WHEN** 首个真实 checkbox 前没有可识别的标题
- **THEN** 整份清单作为一个默认组，后续标题不改组，Step 重复检查以默认组为范围。

### Requirement: `/todoloop` 组级串行派发与接续

TodoLoop MUST 由程序控制任务选择、接续和终止。跳过已完成组，为首个未完成组启动新的原生 `task`，由同一代理连续处理本组剩余项。前次执行及其归属工作实际结清、清单重读并通过校验后，才能再次派发。

#### Scenario: 逐项勾选与整组推进

- **WHEN** 一次组执行包含多个剩余项，或代理实际结清
- **THEN** 代理只处理当前组，在每项满足其完成条件并完成必要验证后立即勾选，不必等整组结束，也不强制组内执行次序。程序只在合法清单中当前组已全部勾选时进入下一组。
- **AND** 若代理报告错误但合法清单显示本组已完成，保留错误记录并按清单继续；用户取消、文件异常或无法确认结清时不得继续。不增加模型裁决或独立验收，勾选不代表独立代码验收通过。

#### Scenario: 同组尝试耗尽

- **WHEN** 代理实际结清后本组仍有未勾选项
- **THEN** 未满三次时启动新 `task`，仅传入本组剩余项及前次简短结果、错误或进度事实。不重做已完成项，不因阶段性进展重置本组尝试次数，也不先启动后续组。
- **AND** 第三次结清后仍有剩余项即停止，报告组、未勾选项、实际次数和可确认的错误；没有具体错误则仅报告未完成事实。

#### Scenario: 重启时按清单续做

- **WHEN** 用户重新运行同一份清单，或清单启动时已全部勾选
- **THEN** 前者按当前文件从首个未完成组续做，重新计算本次运行的组尝试次数并保留工作区已有改动；后者直接显示完成，不启动模型或代理。checkbox 是唯一持久化任务状态，不另建进度或重试账本。

### Requirement: `/todoloop` 运行期间的清单不变量

程序 MUST 在派发前、原生进度刷新时及代理实际结清后重读清单，保护组边界、任务归属、身份、正文及顺序。仅当前组可把未完成项勾选为完成或在任务末尾追加独立执行记录，不得撤销已完成项。

#### Scenario: 校验发现清单遭改写或不可读取

- **WHEN** 重读失败、格式变得无效、组或任务被增删／移动／重排，或发生不允许的正文、标题和完成状态修改
- **THEN** 停止新增派发，必要时取消当前代理并等待实际结清，然后报告具体异常；不从旧快照推断进度、不把文件错误作为普通未完成项重试，也不自动回滚工作区。

### Requirement: `/todoloop` 组执行的取消与真实结清

组执行 MUST 沿用原生取消、超时及结清机制，不新增 TodoLoop 专属超时。取消请求、等待超时或中止标记不等于执行及其归属工作已经结清。

#### Scenario: 用户停止、切换会话或宿主退出

- **WHEN** 用户取消，或会话切换、销毁或宿主退出导致任务失去原有归属
- **THEN** 立即阻止新增派发，取消并结清自有执行；实际结清前不宣告已停止。即使清单期间已被勾选，也不自动接续或进入下一组，不回滚文件，不影响其他会话。

#### Scenario: 原生等待超时

- **WHEN** 等待或执行超时但当前代理尚未实际停止
- **THEN** 请求取消并等待真实结清，再按清单和剩余尝试次数决定是否推进；不能确认结清则报告结清失败，不启动新代理。

### Requirement: `/todoloop` 一次公共背景准备的启动边界

OMP MUST 在有效默认执行确认存在未完成组后、首个组执行代理启动前，由 TodoLoop 程序调用已有 scout 做公共背景调研。同一个 todo 文件、同一次任务，程序全程最多直接发起一次该调研，不因换组、部分完成、重试、内部恢复或调研失败再次派发。该上限不作用于执行 task 或其派生工作，不改变它们调用 scout 的原生行为。调研不计入组执行次数，命令参数及原生 TUI 宿主边界保持不变。

#### Scenario: 有剩余组的首次执行

- **WHEN** `/todoloop <路径>` 校验成功且存在至少一个未完成组
- **THEN** 先调用一次已有 scout，再在调研实际结清且精简结果可用后创建首个组执行代理；即使只有一个未完成组，也采用同一契约
- **AND** 程序决定时序及任务选择，主 AI 和调研代理不参与组拆分、排序、推进或重试决策

#### Scenario: 换组及组内接续

- **WHEN** 当前组完成后进入下一组、创建当前组的第二或第三个执行代理，或同一次任务内部恢复
- **THEN** 程序原样复用本次任务已取得的公共背景，不再直接发起公共背景调研、不重置该次数；执行 task 仍只处理本组剩余项，其原生工具及派生选择不受限制

#### Scenario: 执行 task 可以按原生规则派生 scout

- **WHEN** 某组执行 task 或其派生工作按需调用 scout
- **THEN** 沿用原生准入、工具、模型、权限和并发规则，不因 TodoLoop 的一次背景调研而拦截、过滤或收缩这些调用，不添加专属准入钩子或继承限制
- **AND** 一次上限只统计 TodoLoop 程序直接发起的公共背景调研，不统计执行代理自主调用的 scout，也不按模型请求计数

#### Scenario: 预检、非法输入或已全部完成

- **WHEN** 用户执行 `--check`、输入或文件非法，或启动时文件已全部勾选
- **THEN** 沿用原预检、错误或完成反馈，不创建调研或执行代理、不调用模型、不修改文件

### Requirement: `/todoloop` 背景调研只读且范围受限

调研 MUST 使用已有 scout 的只读职责、工具及原生准入，只读取任务文件、必要明确引用和相关源码，识别 Change 时沿用同 Change 提案、已有设计及相关增量材料边界。调研 MUST 保持用户工作区和 checkbox 不变，不实现、提交、生成材料或独立验收；不新增 TodoLoop 专属权限层、递归工具守卫或调研审查代理，不更改 scout 的通用定义。原生会话记录及缓存元数据保留原语义。

#### Scenario: 普通清单与 Change 材料

- **WHEN** 调研处理普通 Markdown、Superpowers 计划或可识别的 OpenSpec Change
- **THEN** 阅读完整任务文件后，仅调查剩余组实际需要的共同背景及明确引用；Change 的可选设计不存在时不生成，不自动执行 apply、规格同步或归档
- **AND** 只在必要范围调查相关源码、接口和约束，不因文件中可见其他目录或链接而取得额外访问权限

### Requirement: `/todoloop` 精简且有来源的冻结背景

调研 MUST 复用 scout 既有交接格式，提炼必要事实、材料来源、范围及未确认项，形成本次任务固定的精简简报。本文背景包仅指该简报，不另定义背景 schema、序列化协议或持久化格式。共享内容 MUST NOT 复制完整调研聊天、原始工具流水、主对话或执行组聊天；空结果不作为可用背景，不新增背景数据库或自动仓库文档。

#### Scenario: 形成可追溯的共同事实

- **WHEN** 调研读取共同需求、项目约束或相关接口
- **THEN** 背景包保留执行所需事实及其来源关系，明确哪些内容已确认、哪些尚需任务内核实；不得以压缩为由删除必要验收、权限或风险边界
- **AND** 原始材料和调研记录仍按原生只读记录可追溯，但不整段注入每个执行代理

#### Scenario: 无额外共同背景或输出无效

- **WHEN** 调研确认无需补充公共材料，或未能形成可用结果
- **THEN** 前者明确说明该事实及其调查范围，不制造占位资料或扩大扫描；后者作为准备失败报告，不以空包静默进入组执行

#### Scenario: 当前组数据变化不改写背景

- **WHEN** 组身份、剩余 checkbox、尝试次数或上次结果发生变化
- **THEN** 这些动态数据进入当次 `assignment`，不回写共享 `context`；当前状态仍以程序最新读取的真实文件为准

### Requirement: `/todoloop` 共享背景的稳定请求前缀

OMP MUST 复用原生 task 的共享 `context`，将同一精简背景传给本次任务全部执行及接续代理；当前组、剩余项、尝试次数和变化事实放入独立 `assignment`。在模型、工具及安全上下文相同的条件下，共同背景前缀保持一致，身份及协作内容沿用原生排列；不得另造提示词体系、覆盖原生规则或为缓存冒用身份。

#### Scenario: 两组及同组接续复用前缀

- **WHEN** 在相同有效模型、工具及权限下派发多个组或同组接续代理
- **THEN** 实际发往模型服务的共同背景前缀保持一致，差异仅出现在后续的当前任务及必要增量内容
- **AND** 验收以真实派发请求内容和原生缓存策略为依据，不以背景包对象相同、字符串引用相同或逻辑 fork 自述代替

#### Scenario: 必须变化的运行身份和任务数据

- **WHEN** 新代理具有不同原生执行身份、组编号、尝试次数或最近错误
- **THEN** 身份及当前任务事实保持真实，不借用另一运行实例的身份；必要的动态提示内容不破坏前面已冻结的公共背景

### Requirement: `/todoloop` 复用原生缓存策略而不依赖命中执行

OMP MUST 沿用已有原生缓存键、显式配置优先级及请求接线，由现有链路决定适用参数；MUST NOT 新增 TodoLoop 缓存开关、模型能力表、Provider 特判、缓存协议、预热或缓存专属重试。未命中、过期或不支持缓存不改变组执行语义，不为命中另行切换模型／账号或提高权限。

#### Scenario: 保持已有缓存与模型行为

- **WHEN** TodoLoop 通过原生链路发送带共享 context 的执行请求
- **THEN** 使用既有缓存配置和原生模型策略，不由 TodoLoop 重新判断或配置模型缓存能力，不覆盖显式设置、不增加为获取命中而发起的请求

#### Scenario: 缓存关闭、服务不支持或返回零命中

- **WHEN** 缓存被显式关闭、当前服务不支持共享缓存，或一个正常响应没有观测到缓存读取
- **THEN** 执行代理仍获得同一背景并正常处理本组，缓存参数继续由原生链路处理；不把未命中当任务失败，也不额外调用模型争取命中
- **AND** 保留既有模型选择和原生请求策略，不声称节省了未被服务证明的 token 或费用

#### Scenario: 真正的配置或 API 错误

- **WHEN** 请求因配置、认证、权限或模型服务错误失败
- **THEN** 按原生真实错误和所属阶段处理，不将错误吞掉或伪装为普通缓存未命中；不增加缓存专属重试次数

#### Scenario: 背景就绪不等于缓存已预热

- **WHEN** 调研完成、背景被冻结，或首个执行组首次发送该背景
- **THEN** 只报告背景可用，不据此宣称缓存已命中或已预热；是否产生缓存写入或读取以服务实际返回信息为准

### Requirement: `/todoloop` 共享背景不得覆盖最新文件事实

执行代理 MUST 在背景包覆盖且材料未变化时复用共同事实，不被强制逐组完整重读同一材料；仍 MUST 读取当前任务文件并核实当前任务所依赖的真实工作区、修改目标和变化材料。冻结背景不是动态源码、权限或 checkbox 的权威，不得以缓存命中跳过必要的最新事实核验。

#### Scenario: 后续组使用未变化的公共材料

- **WHEN** 相关公共材料已被背景包充分覆盖且未变化
- **THEN** 后续组及接续代理直接复用这些事实和来源，不为满足重复读取提示再完整调查；仅按当前项需要补读未覆盖内容
- **AND** 任务文件的原有派发前、运行中及实际结清后的重读和不变量校验保持不变

#### Scenario: 前序组改变共享接口或引用材料

- **WHEN** 工作区当前接口、相关材料或前提与冻结背景不同
- **THEN** 受影响的执行代理按原生能力读取并使用最新事实，将必要更新作为当次任务增量，不修改冻结前缀、不恢复旧工作区、不复制前序组聊天；编排程序不重新发起公共背景调研，不限制执行 task 为当前工作自主调用 scout
- **AND** 无法核实执行必需的最新事实时明确报告实际问题，不将过期背景作为已确认结论继续执行

### Requirement: `/todoloop` 共享事实但隔离执行聊天及作用域

每个组首次执行和每次接续 MUST 继续创建独立的新 `task`，仅复用本次调用的冻结事实底座及当次任务信息；不得继承主对话或其他执行代理完整聊天。背景和缓存复用 MUST 保持原生项目、cwd、profile、认证及权限隔离，不能把可读背景扩大为新的执行或访问授权。

#### Scenario: 不从前一执行组派生聊天历史

- **WHEN** 第一组完成后开始第二组，或当前组未完成而启动接续代理
- **THEN** 新代理获得同一背景、当前组剩余项及允许的简短结果／错误，不获得前一执行代理聊天和工具流水；先前工作区修改保持可见
- **AND** 共享仅限同一精简 context，不将交接结果当作聊天历史继承，也不把逻辑 fork 当作缓存命中证明

#### Scenario: 当前组任务与材料定位

- **WHEN** 程序首次派发某组或派发其接续代理
- **THEN** 明确提供组身份、剩余任务原文、清单绝对路径、会话工作目录及逐项验证后勾选的边界。执行代理读取当前清单，按需使用明确引用或同一 Change 的提案、已有设计和相关 delta specs，已由共享背景充分覆盖且未变化的材料不必重复读取。
- **AND** 缺少可选设计不自动生成，也不自动启动 apply、规格同步或归档；不限制 `task` 的原生派生，不新增审查、专属模型或工作树。

#### Scenario: 不同项目、权限或拥有者

- **WHEN** 请求来自另一项目、profile、凭据安全上下文，或会话所有权和权限已变化
- **THEN** 不将本次背景当作另一运行的私有上下文注入，也不借缓存键绕过原生准入；失去当前所有权时按停止及结清规则处理

#### Scenario: 新调用只按文件续做

- **WHEN** 用户结束本次任务后重新输入命令执行同一清单
- **THEN** 视为新的独立 TodoLoop 任务，从最新文件首个未完成组恢复；有剩余组时本次新任务的编排程序最多直接调研一次，全部完成时不调研；同一次任务内部恢复不重置该次数
- **AND** 不依赖旧背景、调研会话或模型缓存恢复任务游标，不做文件终身去重；原生会话记录和缓存元数据保持既有持久化语义，不新增跨任务背景／进度账本

### Requirement: `/todoloop` 准备阶段的失败、取消和真实结清

程序的公共背景调研 MUST 归属本次 TodoLoop 的原生所有权及取消链路，复用已有等待、取消和真实结清机制。成功、失败、超时、用户停止、会话切换和宿主退出均须结清相关执行及归属子工作；准备失败、空结果、无法确认结清或用户取消后 MUST NOT 派发执行组，程序不得再次发起公共背景调研，不新增准备专属状态体系、期限或重试预算。执行 task 自主派生的 scout 沿用原生生命周期。

#### Scenario: 调研有结果但仍有子工作在运行

- **WHEN** 调研返回文本或结构化结果，但自有执行或子工作尚未结清
- **THEN** 沿用原生运行或停止中反馈，不宣布已停止、不启动首个执行组；结果存在和取消标记都不替代实际结清证明

#### Scenario: 调研失败或必要材料不可读取

- **WHEN** 调研失败、必要材料不可访问或结果不可用
- **THEN** 结清自有工作后报告准备失败及真实原因，所有组保持未启动，checkbox 和工作区不被准备阶段改变
- **AND** 该失败不消耗任何组的执行代理次数，不伪造可用背景，程序不再次派发公共背景 scout；原生模型及错误策略保持不变，用户可另行处理后启动新的独立任务

#### Scenario: 用户取消或宿主所有权结束

- **WHEN** 用户按现有停止操作，或会话切换、销毁、宿主退出
- **THEN** 立即禁止新增调研和组派发，取消并结清自有工作；真实结清后才显示已停止，无法确认时报告结清失败，不影响无关会话或回滚工作区

#### Scenario: 准备期间清单被改变

- **WHEN** 调研期间任务文件出现不符合原不变量的修改或无法重新读取
- **THEN** 停止并结清准备，报告文件异常，不从旧快照或背景推断当前任务状态，也不让调研代理修复任务文件

### Requirement: `/todoloop` 共享背景不改变组推进和既有命令

OMP MUST 保留前置 TodoLoop 的标题推断、数字／Step 身份、文件顺序、组间串行、组内连续逐项勾选、每组最多三个执行代理及实际结清后整组检查。程序的背景 scout 不是 checkbox，不替代执行或独立验收。执行组使用原始 task，完整保留原生工具、模型、权限及派生能力，包括调用 scout；不改变无关命令、普通 task 或全局缓存默认行为。

#### Scenario: 部分完成和三次上限

- **WHEN** 某组部分完成后继续派发剩余项，或第三个执行代理结清后仍有未勾选项
- **THEN** 接续只处理本组剩余项且不重置次数；第三次仍未完成时停止，不进入后续组，背景调研不计入本组三次
- **AND** 缓存命中与否、背景是否可复用都不决定 checkbox 推进，不把任务勾选表述为独立代码验收通过

#### Scenario: 普通入口及配置保持原样

- **WHEN** 用户未运行 TodoLoop，或使用不属于本次 TodoLoop 的普通聊天、task、其他斜杠命令及非 TUI 宿主
- **THEN** 不启动背景任务、不注入共享包、不改写其缓存配置或会话身份；原有命令目录、准入、模型、工具、派生、超时及输出行为不变

### Requirement: `/todoloop` 沿用原生记录与展示

OMP MUST 复用原生 TUI、代理记录和错误反馈识别本次 scout 及各次组执行，不新增 TodoLoop 专属状态体系、用量账本、派生费用归集、缓存统计或费用面板。已有原生用量信息保持原语义，不将公共背景可用表述为已命中缓存、独立代码验收或必然节费。

#### Scenario: 调研记录不冒充任务完成

- **WHEN** TodoLoop 程序直接派发的公共背景 scout 启动、结束或失败
- **THEN** 保留其真实原生记录，不增加任务／组完成数，不计入某组的三个执行代理，不伪造当前执行组或尝试次数；执行 task 自主派生的 scout 继续按原生方式记录，不被当作程序超出一次上限
- **AND** 不另建日志／进度界面，不把完整背景、派发包或敏感缓存键刷入主聊天，不调用主 AI 解释或总结

#### Scenario: 不因共享背景新增效果统计

- **WHEN** 原生记录已有缓存或用量信息，或这些信息不可得
- **THEN** 沿用已有渠道及语义，不为本优化补建计量系统，不由相同文本、缓存键或本地模拟推断真实命中、节省量、零费用或不占上下文窗口

#### Scenario: 同组逐项进度及终态

- **WHEN** 当前代理完成组内一项、启动新的组执行尝试，或本次 TodoLoop 结束
- **THEN** 同一 TUI 状态区展示文件、任务与组的完成数／总数、当前组、组内首个未完成项和本组尝试次数。原生 `task` 记录按组的每次执行保留，不按 checkbox 新增卡片。
- **AND** 终态显示完成、失败或实际停止；失败保留能确认的原因与剩余项，不为输入错误伪造组或任务，不让主 AI 解释或总结编排，也不把完整派发提示或程序文本作为聊天正文输出。
