# zcode-visual-baseline

## Purpose

以官方 ZCode 3.18.0 为 WebGUI 与 AIReq 的视觉基础，在保留 OMP 已确认功能布局、权限、服务及共享前端架构的前提下，对齐设计规范、主题、面板、字阶、表格、控件用法、工作流头像和内容样式。该视觉基线不表示合并官方完整 3.18 实现或升级应用依赖。

## Requirements

### Requirement: 固定官方设计依据与 OMP 适配入口

仓库 MUST 保存官方 `DESIGN.md`、`CONTEXT.md` 原文及来源记录，版本固定为 ZCode `3.18.0`、提交 `b95ebaffeab641907b38652f45c1502bd762972d`。WebGUI 与 AIReq 根目录 MUST 提供设计规范阅读入口，先说明 OMP 适配规则，再引用固定官方原文。官方产品上下文 MUST NOT 覆盖 OMP 的已确认业务、平台或部署边界。

#### Scenario: 修改两个前端的界面
- **WHEN** 开发人员调整 WebGUI 或 AIReq 的视觉表现
- **THEN** 能从对应目录的 DESIGN／CONTEXT 入口追溯同一官方原文、精确版本、许可与哈希，并遵循 OMP 视觉适配需求
- **AND** 不因复制设计文档恢复原产品的插件市场、收费、桌面控制或其他已裁剪能力

### Requirement: 同一 AIReq 共享前端保持冻结契约

视觉对齐 MUST 在现有 WebGUI 副本与 AIReq 自有共享前端内按同一设计基线实施。AIReq 的 preview 和 runtime MUST 继续使用同一个 bootstrap、网络客户端、浏览器代码及冻结的请求／响应／错误／实时事件契约；mock MUST 仅归独立原型后端。视觉同步 MUST NOT 新增按 prototype/runtime 区分的界面、样式逻辑或浏览器业务 mock。

#### Scenario: 切换 AIReq 后端地址
- **WHEN** 同一共享前端从原型后端切换至符合契约的 OMP 后端
- **THEN** 仅切换地址，视觉规则、功能布局、人工操作、权限与事件消费路径不变
- **AND** 不替换客户端、转换接口格式或改变后端业务权威，视觉检查不代表真实服务已接通

### Requirement: 对齐深浅主题与面板层级

两套前端 MUST 对齐官方 Zai Light／Zai Dark 中适用的前景、弱文字、背景、surface、panel、border、popover、输入、hover、selected 及阴影规则。面板 MUST 按适用浏览器场景采用官方圆角、弱边框与装饰性 inset，不以统一固定零值抹去原生层级。颜色具体数值 MUST 由主题源码提供，文档不维护另一套颜色表。

#### Scenario: 深浅主题显示同一业务页面
- **WHEN** 使用者在深浅主题中查看表格、提案、材料、设置或弹层
- **THEN** 表面层级与文字角色保持清楚，现有主题存储与宿主适配仍有效
- **AND** 不整包引入终端、Highspeed 或桌面专用依赖，不改变栏宽、面板位置、展开状态、拖拽与最小宽度

### Requirement: 应用字体字阶和状态用法

业务界面 MUST 使用官方应用的 `font-sans`、`text-ui-*`、`--ui-font-size`、字重、行高和适用字体平滑规则；MUST NOT 用官网营销页字体或 HTML 根字号缩放替代应用规范。已与官方一致的基础控件 MUST 保留，在调用侧对齐尺寸、边框、圆角、hover、focus、selected、disabled 与弹层表面用法。

#### Scenario: 正文、元数据与控件并存
- **WHEN** 页面同时显示正文、辅助元数据、按钮和状态信息
- **THEN** 各内容按角色呈现可读层级，不将全部文字降为最弱字阶或颜色；选中、焦点、悬停和禁用可区分
- **AND** 事件、权限、数据作用域、接口与存储行为不因样式对齐改变，不重复替换已一致组件

#### Scenario: 左侧提案列表的可读层级
- **WHEN** 使用者在深浅主题中浏览或选中需求提案
- **THEN** 标题使用主文字色与基础字号，选中标题加中等字重并保留原生选中背景；提交人工号和阶段使用次级文字色与 `text-ui-sm`（默认 12px），工号使用普通界面字体
- **AND** 筛选菜单的“入库检查：需要处理”单项使用相同辅助字号，长标题和阶段保留截断及完整提示；不把可操作标题弱化为辅助文字，不改变字段、布局或选择行为

#### Scenario: 表格操作、依赖、评审信息和材料路径可读
- **WHEN** 使用者查看正式需求开发安排、依赖说明、评审会话或展开材料路径
- **THEN** 开发安排按钮使用原生小按钮字阶，依赖名称与原因使用 `text-ui-sm` 的主次文字色，评审信息使用辅助字号并通过悬停或键盘聚焦显示完整 Tooltip
- **AND** 路径复用原生折叠控件与按钮，路径正文使用等宽辅助字号并可换行、选择复制；不更换主题、不改变表格列宽、权限或业务行为

### Requirement: 表格恢复完整原生视觉并保留业务结构

AIReq 正式需求表格 MUST 采用原生表格容器、圆角、边框、表头、行和单元格层级及悬停／选中表现。九列、列宽、固定列、IR／SR 展开、滚动、筛选、复制、分支和人工进度操作 MUST 保持。中性色阶 MUST 作为基础，语义色仅表达已定义实际状态，不为装饰发明新的状态颜色或业务含义。

#### Scenario: 正式需求表格选择与滚动
- **WHEN** 使用者展开 IR、查看 SR、横向滚动、复制分支或选择进度报告
- **THEN** 保留原有字段、列宽、交互、选择和同页报告关系，只改变容器及内容的视觉层级
- **AND** 行和表头保持既定滚动／固定职责，不改变状态名、进度算法、编辑权限或人工决定

#### Scenario: 正式需求状态复用原生语义控件
- **WHEN** 使用者查看正式需求表格或同页进度报告
- **THEN** 同一状态复用原生 Badge、Progress 和语义图标；待开发为中性，开发中为进行色，待合入与待验收为等待色并以不同图标和文字区分，已完成为成功色
- **AND** 表格与报告保持同一映射，文字及百分比保留；表头和 IR／SR 主次明确，固定名称列与整行的选中／悬停背景一致，不新增失败含义或改变业务状态
- **AND** 本次状态样式迭代仅核对深色主题、电脑端本机原型，不宣称浅色、WebGUI 或真实后端已验证

### Requirement: 原生工作流与四 Agent 头像视觉

需求提案 MUST 继续复用 ZCode 原生轨道、头像、表情、完成标记、连线及动效／减少动态效果规则，并保留四 Agent、默认综合意见、人工判断、定向会话与当前／历史节点区别。视觉同步 MUST NOT 恢复另一套工作流执行引擎或改变阶段推进规则。

#### Scenario: 查看综合意见及独立报告
- **WHEN** 使用者切换评审头像或展开评审流程
- **THEN** Agent 身份颜色及状态表现一致，原会话归属、同版报告和人工通过门槛不变
- **AND** 外观或动画不自动批准、回退、重试、发送消息或启动模型，历史仍只读

### Requirement: 消息与只读材料沿用原生内容层级

聊天与材料 MUST 对齐官方 Markdown、列表、引用、代码及 Diff 的字体、边框、圆角和内容层级，同时保留现有安全渲染、会话归属、材料范围、完整路径及折叠规则、只读权限和底部操作位置。长文本与代码 MUST 继续在既定容器中换行或滚动。

#### Scenario: 阅读长材料并执行现有人工操作
- **WHEN** 使用者阅读长正文、路径、表格、引用或代码后执行底部人工操作
- **THEN** 内容与动作仍在原面板内可达，不增加编辑能力、不移动入口、不增加常驻信息行或替换模型上下文

#### Scenario: 只读材料复用 Markdown 阅读能力
- **WHEN** 用户在 AIReq 右侧阅读 IR、SR 或技术方案文件
- **THEN** 正文继续由原生 MessageResponse 渲染，采用适合材料栏的行宽、行高、字距和标题间距；文件正文不经前端重写，保留路径、原有滚动容器和底部业务动作
- **AND** 代码主题、字号、行号及换行跟随现有外观设置；用显式组件参数关闭复制和下载，保留代码换行、图表预览与表格查看等只读阅读能力，不用全局隐藏按钮替代权限控制
- **AND** 不恢复带入讨论、编辑或额外 SR 导航；普通聊天组件默认操作不变，样例声明的精简仅修改原型后端材料

### Requirement: 截图核对保持功能布局与证据边界

本轮 MUST 对 WebGUI 与 AIReq 按同一固定视觉基线核对，保留既有业务布局；允许边框、圆角及少量控件内部留白调整，不改变导航、面板位置、分栏比例、表格列数／列宽或业务动作。截图证据 MUST 记录实际入口、浏览器、窗口、主题及后端来源；未实际检查的入口不得标为通过。

#### Scenario: 深浅主题和窄桌面核对
- **WHEN** 交付本轮视觉对齐
- **THEN** 实际检查 Zai Light／Zai Dark、普通及较窄桌面窗口，并核对表格、面板、消息、材料、头像、弹层及关键交互状态
- **AND** 本轮遵照用户要求不运行测试套件；构建及 Chromium 截图不代称 Firefox 128、真实模型／Git、真实 OMP 后端或发行产物验证，不新增 AIReq 手机／平板验收范围

本轮截图范围按用户后续指令限定为 AIReq 共享前端：启动独立原型后端与该前端，检查深浅主题及正常／窄桌面。WebGUI 同步同一视觉源码基线并做静态核对，本次不启动、不构建或截图，不将其截图验收标为通过；其运行视觉验证另行安排。未运行测试套件。

### Requirement: 浏览器侧栏保留原生导航能力

AIReq 与 WebGUI MUST 保留 ZCode 侧栏切换、后退和前进的可见入口，复用原生图标、ghost／icon-md 按钮、Tooltip、主题及禁用态。展开时位于侧栏顶部，收起时位于内容区占位工具栏，不遮住标题；AIReq 正式需求复用其原有标题栏入口，不重复显示。WebGUI 使用既有任务导航，AIReq 使用现有浏览器历史恢复主页与 IR／SR 浏览位置；导航不得触发发送、业务回退或后台任务重建。浏览器不伪造桌面窗口按钮。

#### Scenario: 侧栏与浏览历史
- **WHEN** 用户展开或收起侧栏并浏览不同任务、AIReq 主页或 IR／SR
- **THEN** 始终能找到对应导航按钮，切换使用实际显隐状态；有历史才启用对应方向，返回后重新选择位置会截断前进分支
- **AND** 导航仅改变浏览位置，保留业务数据与会话；模型、权限和后台执行不因视觉恢复改变
- **AND** 主导航密度、底部头像和主名称遵循官方样式；已批准的业务入口、上下文及功能裁剪保持，不新增账号登录或套餐入口

#### Scenario: 侧栏展开三个、收起四个入口
- **WHEN** 在 AIReq 或 WebGUI 展开／收起侧栏
- **THEN** 展开显示侧栏收起、后退和前进；收起显示官方 ZCode 标志、后退、前进和新建，点击 Z 展开侧栏，悬停／键盘焦点反馈复用官方标志切换效果
- **AND** AIReq 正式需求不得遗漏新建按钮；新建使用原有新建提案能力，WebGUI 使用原有新建会话能力；权限不足显示禁用，不隐式发送或持久化空草稿

### Requirement: 开发加载保留原生热更新

AIReq 与 WebGUI 的开发 Vite 配置 MUST 合并稳定的 Lucide 图标预构建分组，避免逐图标静态请求；不预打包本地业务源码或关闭 HMR，不为性能更换已有图标组件或改写生产分包。

#### Scenario: 非首屏页面按需加载
- **WHEN** 用户首次进入设置、自动化，或 AIReq 的 Skill 设计、需求分析
- **THEN** 才加载对应页面模块，使用局部 Suspense 与现有错误边界，等待和失败均保留工作台导航及原有会话；设置的多条入口共用同一懒加载边界
- **AND** 提示锚点等轻量常量不从重页面静态导入；Office、PDF、PPTX 的现有懒加载保留
- **AND** 保存普通前端组件仍可局部热更新；不以业务发送、自动重建会话或清空草稿换取刷新速度

### Requirement: AIReq 自有页面在剩余面板中居中并保留内容间距

AIReq 自有页面 MUST 在左右侧栏之间的剩余内容面板内自动适应宽度；有最大宽度的内容列 MUST 在该面板内水平居中，并始终保留最小左右内边距与正文顶部留白。侧栏展开、收起和拖拽不通过固定屏幕偏移量计算内容位置，不改变业务状态。此轮范围明确排除 Skill 设计及 WebGUI。

#### Scenario: 内容随左右侧栏变化
- **WHEN** 用户展开、收起或调整侧栏，或在较窄、普通与宽屏桌面查看 AIReq 页面
- **THEN** 内容在新的剩余面板内自然重新居中，达到最大宽度后两侧留白等量；窄面板仍有最小水平间距，正文不紧贴顶栏或侧栏边缘
- **AND** 设置、自动化、需求分析、正式需求、提案正文与材料、入口／恢复及空态按内容角色使用合适最大宽度，表格和依赖图保留既定内部滚动／平移，不强制套用同一种窄阅读列
- **AND** 同页标题、筛选、说明、正文和相应操作遵循统一内容起点，不在外壳和子页重复居中或叠加水平 padding；原生聊天、帮助等已满足的区域保持现有布局
- **AND** 设置分区覆盖项目与 Release、模型、个性化、技能与外观；技能设置不等同于 Skill 设计，Skill 设计的源码、挂载和专属布局均不在本轮修改范围内
- **AND** 保持侧栏行为、拖拽比例、字段、模型配置、权限、调度和后台接口；本轮只整改 AIReq 共享前端与文档，不检查 WebGUI 或修改真实后台

#### Scenario: Skill 设计后续纳入居中与顶部留白
- **WHEN** 用户在自动化与 Skill 设计之间切换，或展开／收起导航和技能说明栏
- **THEN** Skill 设计复用自动化／插件市场的48px顶部框架，并在其下保留16／24px正文顶部间距；不恢复已删除的重复标题与说明
- **AND** 两栏工作区在剩余面板内以max-w-7xl居中，左右保留16／24px最小内边距；初始2:3、拖拽、说明折叠、对话、预览与保存规则保持不变
- **AND** 此后续授权仅解除上一轮对Skill设计的排除，不扩大到WebGUI、真实后端或业务流程

#### Scenario: AIReq 与 WebGUI 恢复官方 Web 外壳背景层次
- **WHEN** 在桌面浏览器打开AIReq或WebGUI的主页或设置页
- **THEN** 复用官方3.18.0提交b95ebaffeab641907b38652f45c1502bd762972d的DesktopWindowFrame，使用官方Web分支bg-background-win-alt；导航透明呈现该外壳背景，内部内容面板继续使用bg-background
- **AND** 深色外壳由原有主题变量取#2b2b2b、内容取#161616，不新增色值、纹理或桌面磨砂模拟；不以bg-sidebar覆盖外壳，不改变现有页面布局、导航或业务权限

#### Scenario: 主题与基础控件以固定官方源码为准
- **WHEN** 审查或修改两套前端的主题、基础控件和自有业务页面
- **THEN** 主题变量块与固定官方版本对齐，业务界面使用原生语义token与基础组件；不自行定义替代色板，不通过删除外壳或覆盖侧栏背景抹去官方层次
- **AND** 官方加载图标、字体字阶、候选及取消等基础交互样式复用原有控件；保留必要HTTP剪贴板、Worker打包、权限和存储适配，不为视觉对齐恢复已裁剪产品功能
- **AND** 审计说明区分逐字节一致、非视觉适配与未验证范围；WebGUI本轮只做源码和构建检查，不启动或截图

#### Scenario: WebGUI 与 AIReq 的复用边界
- **WHEN** 新增或维护任一前端页面
- **THEN** WebGUI的已有界面最大程度保持固定官方实现，仅作必要OMP适配；AIReq已有页面沿用官方，自有页面仅定义业务内容和流程，布局组织、外壳、面板、居中留白及视觉基础遵循ZCode
- **AND** 禁止独立设计替代颜色、基础控件或主题；不得因为业务不同而重造Button、Select、Tabs、Markdown、侧栏或基础反馈样式

### Requirement: AIReq 自有主页保持正式产品呈现

Skill设计、需求分析、正式需求、新建Issue、Issue分析和Issue进度 MUST 使用固定ZCode的页面框架、原生字阶、语义token与基础控件。界面面向使用者表达业务任务，不展示原型后端、mock、内存保存、预置回复、内部运行标识或模拟调度等实现说明；后端原型边界仍在开发和验证文档说明，不因此伪装已接入真实OMP或改变权限、数据归属与业务流程。

#### Scenario: 顶部留白与内容居中
- **WHEN** 进入六个入口，切换项目，展开或收起侧栏，调整电脑窗口或拖动分栏
- **THEN** 顶部沿用原生48px框架区，正文再保留16／24px顶部留白；标题使用官方字阶，内容按角色选择现有最大宽度，在剩余面板内居中并保留左右16／24px间距
- **AND** Skill设计保留已有72px顶部起点与两栏工作区；正式需求保留九列、固定名称列及内部横向滚动，不将长依赖原因直接撑入每个SR行

#### Scenario: 正常业务内容与可操作反馈
- **WHEN** 阅读列表、报告、聊天、文件，填写表单或查看加载／错误状态
- **THEN** 正常呈现名称、项目Release、业务进度、问题及下一步，不添加演示服务免责声明或展示调试控制；mock fixture提供同样字段的业务文案，不在前端过滤或改写任意服务正文
