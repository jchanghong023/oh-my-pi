# dev-browser-workbench

## Purpose

维护最新 Dev 业务流程、职责和边界。

> 状态：用户已确认的最新 Dev 需求基线。共享 UI 与原型／OMP 数据源分离已接入；完整业务仍未按本规则完成实现或验收。

## Requirements


### Requirement: Dev 网页原生浏览器边界

Dev 工作台 MUST 仅以桌面浏览器为界面设计、实现和验收目标，不要求手机布局、触屏交互或手机实机验证；WebGUI 的手机适配要求不转移到 Dev，原 WebGUI 本轮不修改。桌面浏览器 MUST 以 Firefox 128 默认启用的原生能力作为最低运行环境及浏览器技术上限；现代浏览器使用同一实现及同一生产资源集，不再以 Firefox 68 为兼容或验收目标。MUST NOT 引入 polyfill、API shim、浏览器专属回退、双构建或现代浏览器专属增强分支。允许开发期编译，但交付的全部脚本、样式、依赖及 Worker MUST 遵守此边界，并保持现有布局、三阶段开发 SR 流程与交互，不扩大 Agent 工具权限或绕过人员确认；Dev 服务的多人访问按最新部署需求，保留适用的能力路径与网络请求校验。

#### Scenario: OpenSpec 材料映射与来源
- **WHEN** 在需求提案中选择 IR、SR 或方案阶段
- **THEN** 分别默认显示同一 change 的 proposal.md、对应 specs/<capability>/spec.md 或有效 design.md；未生成方案时继续显示已有需求材料，不伪称方案完成
- **AND** 展示固定临时工作区内的完整来源路径与仓库相对路径；提案 Agent 生成上下文使用临时工作区，PR 前不在项目目录生成；转正后展示仓库相对路径并保留临时来源

#### Scenario: 同一原生实现完成需求流程
- **WHEN** 用户在 Firefox 128 或现代浏览器中打开同一 Dev 工作台地址
- **THEN** 均能查看需求列表、三阶段开发及真实只读材料，切换查看阶段而不推进流程，使用共享会话的消息、命令、工具过程和适用问答，并完成 Markdown 上传／下载、当前阶段明确推进／返回、当前方案确认及人工标记／确认
- **AND** 缺失材料、不可用操作与实际执行错误须如实呈现；不得以静态演示、只读替代页或要求升级浏览器代替完整功能

#### Scenario: 连接恢复与安全边界不因浏览器改变
- **WHEN** 任一目标浏览器参与 offline 同会话协作、刷新或断线重连，或在非 offline 环境访问 Dev
- **THEN** 按现有 offline 普通 HTTP／WS 或非 offline 安全策略处理；重连只读取实际状态，不重放消息、工具调用或确认
- **AND** 不以兼容旧浏览器为由降低非 offline 的传输或权限要求，不新增绕过身份、确认或宿主限制的通道；浏览器缺少安全能力且现有策略无法满足时须明确拒绝，不伪称功能成功

#### Scenario: 兼容性检查与证据边界
- **WHEN** 评估 Dev 网页的 Firefox 128 原生能力边界
- **THEN** 检查实际交付的完整脚本、CSS、依赖、资源 URL 及适用 Worker，并通过生产 HTTP(S) 入口使用 Selenium＋geckodriver 驱动本机已安装的真实 Firefox 128（当前版本 128.14.0）、隔离临时配置及默认能力／安全设置，观察布局并操作加载、材料、会话、文件、阶段控制与人工确认；其他浏览器、构建成功或静态检查不能代替本机 Firefox 128 验证
- **AND** 记录实际可执行路径、精确版本、发布通道、操作系统、生产入口及流程结果；无法观察的中文输入法、真实桌面输入或其他交互须标记未验证，不自动安装浏览器、不改写个人浏览器配置、不把未观察到的结果报告为通过

#### Scenario: 工作台图标随生产资源交付
- **WHEN** 浏览器加载 Dev 工作台
- **THEN** 页面显式引用同一能力路径下的内嵌图标资源，真实图标请求成功；不依赖不存在的根目录 favicon，也不为图标放宽原有能力路径或访问限制

#### Scenario: 初始展开与用户折叠偏好
- **WHEN** 首次打开 Dev 且没有保存的折叠偏好
- **THEN** 自由会话、正式需求、需求提案三个分区默认展开；自由会话展示最近 5 条聊天，需求分区内 IR 默认收起，仅自动展开正在查看的 IR 及所属分区以露出选中的 SR，不批量展开其他 IR
- **AND** 用户手动收起后不得因重渲染、会话组件重挂、阶段切换或刷新而反复强制打开；导航到不同 IR／SR 时展开对应目标，仍可再次手动收起

#### Scenario: 本浏览器记住展开选择
- **WHEN** 用户展开或收起分区／IR，随后刷新或切回原范围
- **THEN** 恢复已保存的选择，优先于首次默认值；自由会话沿用原生按项目保存的本浏览器偏好，需求分区与 IR 偏好按工号、项目、Release 隔离，不写共享业务数据库或项目配置，不同步为其他同事的选择
- **AND** 偏好不包含执行授权或业务状态；浏览器存储不可用时本页仍可操作，数据损坏回退默认值，原 WebGUI 不变

#### Scenario: 当前项目的自由会话入口
- **WHEN** 用户在 Dev 左侧使用自由会话
- **THEN** 复用 WebGUI 的单项目行、行内更多／文件／新建会话操作、会话操作及展开动画，行名显示“自由会话”，展开直接列出当前项目的会话，不增加外层“项目”分区或重复项目名
- **AND** 当前项目由既有工作区菜单决定；自由会话不依赖 Release、IR、SR，不自动创建提案、进入需求 Agent 或推进需求流程，复用原生会话与服务能力

#### Scenario: 最近五条的查询与历史保留
- **WHEN** 加载或刷新当前项目的自由会话列表
- **THEN** 服务仅查询该项目按更新时间降序排列的最近 5 条可见会话元数据，等时使用稳定次序；选中后才读取消息，不先加载全部历史再在前端截取
- **AND** 新建、更新、归档后重新计算最近 5 条，较早记录仍保留，不因列表上限而删除；切换项目只加载目标项目，不混入其他项目或 IR／SR 会话

#### Scenario: 自由会话默认审查且目录身份不变
- **WHEN** 用户进入自由会话，或在自由会话与需求流程间切换
- **THEN** 自由会话右侧默认为原“审查”页面，正式需求与需求提案默认“只读材料”，查看上下文分别管理；自由会话不显示需求阶段和提案流程控件
- **AND** 按原生规则保留会话创建时的工作目录及身份，查看项目不等于进入开发或重新绑定执行目录，不绕过个人开发目录、宿主权限或确认边界

### Requirement: 浏览器连接不拥有后台任务生命周期

工作台 MUST 将页面连接与原生 OMP 任务生命周期分开。关闭、刷新页面或临时断线 MUST NOT 停止已确认工作；重连 MUST 展示真实持久事实及仍存活的运行事实，不重放操作。OMP 宿主进程必须存活，本要求不承诺脱离宿主继续执行。

#### Scenario: 关闭页面后继续工作
- **WHEN** 原生 Agent 或获授权任务仍在运行，用户关闭或刷新浏览器
- **THEN** 宿主继续已有工作；再次打开同一工作台后显示所属需求的实际进度、结果和错误，不创建第二任务或自动再次提交输入

#### Scenario: 刷新恢复查看位置而非执行授权
- **WHEN** 同一工作台页签选择一个真实需求及某个查看阶段后刷新
- **THEN** 在读取宿主真实需求列表后恢复该需求和查看阶段；查看阶段可不同于实际进行阶段，恢复只读取和订阅现有状态，不启动会话、不加入共享房间、不重发消息、操作或人员确认
- **AND** 保存位置按工作台入口隔离；不存在的需求、无效阶段或不可用的浏览器存储不得导致误选其他需求或崩溃，未保存选择的新入口仍显示空状态


#### Scenario: 宿主退出或执行事实不可用
- **WHEN** 宿主退出、原生任务失败，或重连时无法确认原运行状态
- **THEN** 如实显示中断、失败或不可用，不因旧画面、旧 running 标记或文件存在推断任务仍在运行或成功
- **AND** 需要停止时复用原生显式停止及结清能力，关闭页面本身不是停止命令

#### Scenario: 当前 TUI 与网页互斥及退出
- **WHEN** 用户从普通 OMP 的 `/dev` 进入工作台，或再次 `/dev` 请求退出
- **THEN** 普通任务未结清时拒绝进入，提示先停止或等待，不暗中取消普通工作；成功进入后当前 TUI 只接受再次 `/dev`，拒绝所有普通命令及输入，不同时操作网页 Dev 与普通 TUI
- **AND** 再次 `/dev` 通过既有 native stop／settlement 结清 Dev 后恢复普通原会话；失败不提前解锁。退出不取消需求、不撤销 Git、不删除材料，关闭网页不退出 Dev 或停止任务
- **AND** 不为普通 `/new`／move／dispose 与 Dev 并存保留会话快照、克隆或额外生命周期；不要求私有 Provider／MCP 克隆，实际借用资源必须避免污染 root，原生生命周期及安全 Git 边界保持

#### Scenario: Dev 终端地址与当前反馈
- **WHEN** Dev 独占当前 TUI，用户查看工作台地址、提交普通输入或按 Esc／Ctrl+C
- **THEN** 地址独立完整显示，窄终端换行不丢失字符，保留终端原生鼠标选择复制及 Ctrl 点击链接能力，不启用该界面的鼠标捕获
- **AND** 被拒绝输入、退出提示、切换状态及浏览器打开失败直接显示在当前 Dev 界面，不藏在退出后才显示的普通会话中；输入仍不交给模型，只有再次 `/dev` 结清后恢复原会话及输入焦点


### Requirement: 完整复制 WebGUI 后改造 Dev 三栏与紧凑导航

新 Dev 实现的第一步 MUST 将现有 WebGUI 前端代码完整复制到 Dev 自有前端并替换旧 Dev 前端，再仅修改复制后的 Dev 代码实现本组需求。MUST NOT 仅参考布局、挑选组件、直接挂载原 WebGUI 或在原 WebGUI 中增加 Dev 分支；原 WebGUI 前后端、入口、协议、构建配置及正式资源 MUST 保持不变。Dev 副本使用自己的前端状态、构建和资源入口，复用 OMP 原生能力而不另建执行器。新 Dev 使用左侧需求导航、中间 AI 会话、右侧只读材料；左侧沿用 WebGUI 同类控件及列表节奏，顶部统一“新建需求提案”入口，不再区分两种需求来源或要求导入交接，并恢复“自动化”入口；中部为当前开发 SR 快捷入口、当前 Release 的“需求提案”和“正式需求”两栏，两栏共用同一 IR／SR 列表组件，底部固定 工作区菜单／设置入口，项目与其 Release 同组收进 工作区菜单，先选项目再选其 Release，按钮常驻显示当前选择摘要；子菜单样式、打开方式与动效沿用界面主题。协作入口属于当前会话顶部。

#### Scenario: 先完整替换再实现
- **WHEN** 开始重构 Dev 前端
- **THEN** 先完整复制 `vendor/zcode-frontend/preview/` 的 WebGUI 前端代码替换现有 Dev 前端，后续需求改动仅落在 Dev 副本及其 Dev 集成，不保留旧 Dev 前端或双轨入口。

#### Scenario: 第一阶段仅评审前端原型
- **WHEN** 用户尚未确认本轮 Dev 前端的 UI/UX
- **THEN** 仅调整复制后的同一套 Dev 界面，独立运行并使用仓库内按模块维护的假数据，不接 OMP、真实模型、Git、业务 HTTP/WS 或真实协作；预览不要求安装 Rust、OMP 原生模块或配置模型凭据
- **AND** 每个展示中的 Dev 模块均有连贯的示例内容，覆盖项目、Release、正式 IR/SR、需求提案 IR/SR、工号入口、聊天、三阶段开发、材料、文件与审查、协作、设置及操作记录；必要交互只更新前端演示状态，源码、假数据、资源、锁文件和启动说明一并纳入仓库，另一台机器可按说明预览
- **AND** 不将模拟对话、材料、阶段状态、审批或日志冒充真实执行，不写入正式后端状态；此阶段只是临时评审，不满足本规格的真实业务交付要求

#### Scenario: 前端确认后恢复真实对接
- **WHEN** 用户明确确认当前 Dev 前端可进入后端对接阶段
- **THEN** 在同一套界面接入真实 OMP 原生能力，完成本组完整最终需求，不保留假数据兜底；独立预览可继续作为显式样例入口保留，不是旧 Dev 业务模式或另一套 UI，不得据此永久不接 OMP
- **AND** 默认 fastcheck/fulltest 和 `F:\testgithub\test` 中 OpenCode Go `beam-free` 的完整真实流程验收仅暂缓，须在用户允许恢复后完成；原型观察不抵充真实功能、日志或模型输出的验收证据

#### Scenario: 共享 UI 的原型与真实数据入口
- **WHEN** 用户要求先分离现有原型与真实数据，保留独立预览并嵌入 OMP 启动
- **THEN** 页面、组件、样式和显示派生 MUST 共用一套实现，通过明确的类型合同注入不同数据源；现有独立预览命令与样例交互保留，正式内嵌资源的模块依赖图 MUST NOT 加载样例或预览适配器
- **AND** OMP 入口 MUST 使用现有同进程宿主的真实项目、Release、需求、材料、工作区及原生会话接口；读取、连接或操作失败如实显示，不回退样例，不重放操作，不创建第二执行器，也不修改原 WebGUI
- **AND** 本轮仅实施数据边界与启动接入，不新增原型业务或补做完整 Dev 后端；宿主未实现的新版能力不得通过模拟结果或旧业务兼容界面冒充完成，独立样例验证不代替完整真实业务验收


#### Scenario: 第一阶段保持 WebGUI 同类控件风格
- **WHEN** 在 Dev 副本调整已有组件或增加同类型组件、控件
- **THEN** 沿用原 WebGUI 的组件、CSS、间距、字体、颜色、圆角和交互状态，不建立另一套视觉体系；中间聊天输入框保持原组件及原有文字，不添加额外说明
- **AND** 只读材料作为原右侧面板中文件、审查、辅助对话的同级标签页，默认打开并选中，关闭、切换、收起和重新打开沿用原面板，不增加永久固定的额外材料栏


#### Scenario: 复用自动化页面与原生任务查看
- **WHEN** 用户在 Dev 左栏点击“自动化”
- **THEN** 打开已复制的原自动化页面，沿用定时任务列表、筛选、新建编辑、调度、启停、删除及运行历史组件；项目选项来自 Dev 登记清单，运行历史会话独立只读查看，不覆盖 IR/SR；切回需求时恢复聊天，不因查看自动化推进或启动需求
- **AND** “工作流”标签复用 OMP 原生 task / workpool 的只读运行、父子代理、消息及产物查看，不新增 Dev 执行器；第一阶段仅使用注明来源的内存样例，“立即运行”不启动模型或真实调度，不把演示记录报告为真实成功

#### Scenario: 原 WebGUI 不受改造影响
- **WHEN** Dev 副本增加需求导航、多项目设置、材料查看及三阶段开发控制
- **THEN** `/webgui`／`omp webgui` 仍使用原来的前端与宿主，不新增 Dev 工作流，不修改原 WebGUI 源码、构建配置或正式资源；Dev 新状态不污染原 WebGUI 的项目、会话或浏览器状态。

#### Scenario: 紧凑需求列表
- **WHEN** 用户查看项目需求
- **THEN** 项目和 Release 不进入展开树，不使用占据大量空间的需求卡片；IR 使用原 WebGUI 项目分组样式，点击展开／收起下属 SR；SR 使用原聊天记录行；“需求提案”和“正式需求”使用相同列表组件、标题控件和行高，IR、SR 标题前分别显示紧凑的中性描边类型标记，保留 SR 缩进和 IR 展开箭头；类型标记不显示内部编号。标题由 AI 生成。列表头部搜索沿用 WebGUI 命令中心弹窗及键盘选择、打开／关闭动效，状态筛选沿用原下拉菜单及动效，展开／收起复用原 Collapsible 高度和淡入淡出动效；搜索限当前栏目及 Release 的 IR、SR；两栏筛选互不影响。只有列表滚动，含项目／Release 的 工作区菜单、设置及新建入口保持稳定；搜索、筛选和展开不改变执行状态。

#### Scenario: 统一提案入口及同构列表
- **WHEN** 用户新建或浏览尚未成为正式需求的提案
- **THEN** 点击“新建需求提案”直接打开提案讨论，不增加名称或背景前置表单；左侧取消“草稿”折叠入口，改为“需求提案”和“正式需求”两栏。正式需求位于提案上方，两栏标题复用原 WebGUI“项目”的 WorkspacePurposeSection 控件，点击标题展开／收起整栏，右侧全部展开／收起仅作用于本栏 IR，保留另一栏展开状态；固定顺序，不允许拖拽交换。两栏复用同一 IR／SR 组件、类型标签、缩进、展开／收起动画、讨论按钮与搜索筛选控件。点击 IR 展开 SR，IR“需求讨论”按钮及提案内任意 SR 均进入该提案当前讨论阶段的同一会话（业务需求 Agent／方案 Agent），复用消息历史、未发送输入和上下文，不因 SR 新建／切换 Agent；选中 SR 只定位该 SR 材料和导航，不展示三阶段开发按钮；未拆分时说明可先讨论需求。

#### Scenario: 提案状态、两阶段和打回
- **WHEN** 用户查看需求提案
- **THEN** 分开展示草稿／方案完成／PR 待合并状态和业务需求／方案讨论阶段，不提供“待评审”状态或筛选。提交给开发人员不要求已有方案，但须先通过业务需求评审 Agent 检查；开发人员明确接手后切换到方案阶段，使用方案 Agent 完成方案、SR 实施顺序及依赖。IR 与全部 SR 在每阶段共用一个会话，查看另一阶段历史只读，不推进实际阶段。
- **AND** 开发人员遇业务卡点可填写原因打回业务补充，返回草稿的业务需求阶段，保留历史并使旧方案失效；新一轮方案完成前禁止 PR 提交。方案完成后才启用 PR 入口；PR 提交仍在提案列表，合并且默认分支包含 IR、全部 SR 与本轮方案后才移入正式需求。原型仅以静态方案、PR 记录和明确标注的文件核对演示这些转换，不执行模型、Git、真实角色验证或数据库操作。

#### Scenario: 工号进入及切换
- **WHEN** 用户首次打开 Dev Web，或从工作区菜单切换工号
- **THEN** 使用沿用原 WebGUI 字体、输入框和按钮的居中单列表单，入口固定深色，不覆盖工作台主题偏好，仅输入工号，不索要密码或个人 Token。检查格式后进入共享工作台；工号仅为操作标识，不代表员工身份认证。当前工号在工作区菜单可见，切换工号返回入口并重新读取对应个人开发项目，不能沿用上一工号绑定。
- **AND** 工号使用小写 `j` 加 8 位数字格式，例如 `j00808874`，允许回车进入，错误在字段下方说明；同标签页刷新可恢复工号，存储不可用时仍可在当前页面进入。保留前导零，纯数字、错误前缀或位数错误必须拒绝。所有身份变化仅为浏览器原型，不提供真实登录、共享数据库或多人同步。

#### Scenario: 提案目录只读展示与复制
- **WHEN** 用户查看提案 IR 并打开“更多”
- **THEN** 显示只读目录 `/tmpdata/DFT_LAB/omp/{project_name}/{工号}/{提案id}/`、项目目录标识和提交人工号，提供复制按钮与成功／失败反馈，说明其为临时工作区，内含 openspec/changes/<change-id>/；SR 不重复显示。路径绑定提案创建时的项目及提交人，切换查看人工号、项目显示名称、Release 或个人开发路径不修改原提案目录；无个人开发项目也可查看与新建提案。
- **AND** 原型提供不同项目与不同提交人的提案样例，新建提案记录当前工号；只展示内存路径，不创建目录或连接数据库。共享元数据统一存储目标为 `/tmpdata/DFT_LAB/omp/omp_dev_sqlite.db`，不是每项目一个数据库。

#### Scenario: 跨 Release 定位当前开发
- **WHEN** 当前项目有开发中的 SR，而人员正在查看其他需求或 Release
- **THEN** 独立“正在开发”入口显示本仓库当前 IR 的全部开发 SR、开发人及各自实际阶段；跨 Release 时注明来源，点击只返回既有会话及其 Release，不启动第二任务或推进阶段。选中背景表示查看位置，工作标记表示实际开发，两者不混为一体。

#### Scenario: 项目与需求的空状态
- **WHEN** 当前配置无项目、所选项目无 Release 或当前 Release 无正式需求
- **THEN** 分别引导添加已有 Git 项目、添加 Release 或从新建入口创建需求提案，不默认创建对象、回落到别的项目或启动 Agent；项目与 Release 清单归共享数据库 `/tmpdata/DFT_LAB/omp/omp_dev_sqlite.db`，共享项目路径只读；每个工号在各项目下另配自己的开发项目目录，无绑定可以浏览但不能进入开发，页面选择只影响当前浏览器。切换项目必须替换为该项目的 Release 首项，无 Release 时清空旧值，不沿用其他项目选择。

#### Scenario: 查看 IR 和 SR
- **WHEN** 用户选择 IR 或其 SR 标题
- **THEN** IR 标题点击只展开／收起下属 SR，保留当前会话；需求讨论及相关 AI 工作沿用按钮操作，不新增导航入口。选择 SR 进入其聊天布局并查看完整需求；提案 SR 与 IR 讨论共用同一业务需求 Agent 会话，不拆分会话；不同提案仍隔离。正式 SR 未开始显示待开始和明确开始按钮，已完成展示历史只读；选择本身不启动 Agent、不开始开发。

#### Scenario: 提案与正式导航分离
- **WHEN** 新建后仅产生工作目录或未通过审核的材料
- **THEN** 不以此在正式 IR 列表添加占位需求；提案恢复仍由真实记录和 OMP 会话引用支持。

#### Scenario: 没有会话时不回落样例
- **WHEN** 没有项目、Release 或需求，或已选 IR／SR 已失效
- **THEN** 展示对应空态和明确下一步；无项目可进入原项目设置组件，登记后由用户明确选择，无 Release 可添加版本或开始自由会话，空需求可新建提案
- **AND** 不使用固定样例任务作为后备，不挂载可发送到错误上下文的聊天框，不自动创建业务对象或启动 Agent；读取工作区期间显示状态，失效目标不替换成其他需求

#### Scenario: 固定目录失败后的恢复入口
- **WHEN** 已选工作区不存在、不可访问、仓库不符或绑定缺失
- **THEN** 阻止进入，保留原目标并显示原因、原路径和重试／选择项目／原项目设置入口，不回落共享项目或其他人的目录
- **AND** 重试仅重新读取，不重建 worktree、不转移占用、不重发消息或动作；恢复原目录后沿原工作区身份读回已保存的草稿。原型恢复按钮必须标明样例，不代表修复了真实目录

### Requirement: 实际阶段与历史材料分离

SR 开始开发后，中央会话顶部 MUST 显示 SR 标题、实际阶段和三阶段开发导航。点击阶段选择对应阶段／轮次的历史会话与材料只读查看，实际执行阶段和后台任务不因浏览改变；不把历史查看绑定成可写的当前会话。顶部保留当前必要动作，Git 范围、分支与操作记录收入可关闭的“更多”弹层，不常驻挤占聊天。

#### Scenario: 当前阶段条
- **WHEN** SR 正在开发计划
- **THEN** 展示开发计划、开发与验证、交付 PR；区分已完成、当前、未开始，不再展示旧八阶段。

#### Scenario: 查看过去阶段
- **WHEN** 用户在开发与验证时点击开发计划
- **THEN** 右侧显示历史计划并同时标明查看阶段与实际阶段；中间只读展示对应阶段的原历史会话，标明轮次并提供返回当前阶段；不停止 Agent、不回退或推进。

#### Scenario: IR 不显示开发阶段
- **WHEN** 用户处于浏览器需求讨论或 IR 总览
- **THEN** 只显示整理、待确认、检查中、可下载或待需求合入等适用状态；不把 IR 放入 SR 开发流水；全部 SR 合并后单独展示 IR 验收、最终 PR 待合并和完成状态。

### Requirement: 正式材料只读与统一材料菜单

IR、SR、方案、计划、完成报告、验证及交付材料 MUST 全部只读。右侧默认打开并选中当前阶段材料，可通过原面板按钮收起和重开。Markdown 复用现有正文渲染器，复制、下载仍使用原文；支持切换、收起、重新打开和带入讨论，不另建阶段管理页面。

#### Scenario: 材料未生成或失效
- **WHEN** 所选资料缺失、尚未生成或依赖已变化
- **THEN** 分别显示尚未生成、真实错误或已失效需重新生成；不展示假产物，不把已失效测试报告作为当前结论。

#### Scenario: 统一材料入口
- **WHEN** 用户展开材料菜单
- **THEN** 能查看 IR、当前 SR、方案、计划、完成报告、UT/ST 记录及交付说明等已有材料；方案只维护一个当前版本，正文说明推荐理由和取舍，不提供候选 ID 选择流程。

#### Scenario: 修改正式内容
- **WHEN** 用户希望改标题或资料正文
- **THEN** 通过 AI 对话，在获准阶段内更新；不提供正文编辑器、重命名表单或拖拽拆分。设置中的项目名称和目录不属于 IR/SR 标题。

#### Scenario: 材料失败与等待生成分开
- **WHEN** 选中材料缺失、读取失败或尚未生成
- **THEN** 读取失败显示原因并保留所选路径，禁用复制／下载／带入讨论及依赖该材料的阶段批准；元数据或摘要存在不能绕过正文不可用
- **AND** 重新读取只重试当前材料；暂时读失败可恢复，缺失文件需恢复原文件或由当前开发人明确重新生成，不替换其他材料。尚未生成使用中性等待状态，历史失效版本仍只读

#### Scenario: 失败保留输入且不自动重放
- **WHEN** 发送消息被拒绝，或用户提交的原型动作失败
- **THEN** 未接纳的消息不追加到对话，保留文字草稿；未完成动作不修改阶段，弹窗保留路径、名称或打回说明，成功后才关闭；用户明确重试才重新提交
- **AND** 查询／重试读取不隐式重放失败命令，重复查询已接纳结果不重复追加消息；草稿遵守原工号／工作区／会话作用域及浏览器存储边界，不能以演示宣称真实断线恢复能力

### Requirement: 单仓库单 IR、受限 SR 并行与独立 worktree

同一真实仓库跨全部项目登记、Release、clone、worktree 与工号 MUST 同时只有一个开发中的 IR；该 IR 内满足依赖条件的独立 SR 可以并行，默认最多 2 个。每个 SR MUST 仅有一个开发人、一组固定分支和独立 worktree，并从该开发人服务端可访问的开发仓库启动；不同仓库及提案讨论可并行。

#### Scenario: 原子准入与依赖检查
- **WHEN** 用户明确开始一个正式 SR
- **THEN** 核对提案已真实合入、业务及方案确认有效、个人目录有效且属于本仓库、SR 未被占用、同仓库无其他开发 IR、并行额度充足，以及 design.md 中全部前置 SR 已合入并在默认分支核验；共享数据库中原子预留仓库与 SR 名额，准备中也占用额度
- **AND** 首个 SR 开始时冻结 IR／SR 正文及确认方案；依赖未满足时显示阻塞原因，不启动工作树或会话，不以相同工号限一个 SR 代替仓库级并发控制

#### Scenario: 独立工作树与固定起点
- **WHEN** 全部准入检查成功
- **THEN** 获取最新默认分支，从记录的确切提交创建该 SR 的独立分支／worktree，记录项目、仓库、IR、SR、开发工号、开发根、分支、worktree、基点及创建时间；获取失败阻塞，不静默使用过期引用
- **AND** 聊天、文件、审查、暂存绑定此记录；切换工号、项目、Release 或修改个人目录均不重绑；浏览 SR 不创建工作树，缺失／失效绑定明确报错，不回落共享目录或他人目录

#### Scenario: 多个开发 SR 的定位与只读查看
- **WHEN** 仓库内两个独立 SR 同时开发
- **THEN** 正在开发入口列出本 IR 的多个 SR、阶段和开发人，可定位自己的任一开发会话，不覆盖另一 SR；查看他人 SR 只读，不转移占用或发送、批准、停止、发布、登记其 PR
- **AND** 工号仅为操作标识，不构成员工身份认证；动作层仍核对记录归属和实际阶段，不能只依赖按钮禁用

#### Scenario: 等待与释放
- **WHEN** SR 准备中、开发中、等待审查或等待合并
- **THEN** 继续占用 SR 名额；暂停、关闭浏览器、重启、切换项目均不释放；真实合并且结清自有任务后释放该 SR 名额，依赖 SR 才可启动
- **AND** 仓库 IR 占用持续到最终验收与归档 PR 已真实合入；未完成 SR 不因释放显示记录而失去占用，不自动删除分支或 worktree

### Requirement: 三阶段开发明确批准与真实验证

SR MUST 从开发计划开始，经开发与验证、交付 PR 三阶段开发推进；方案及 SR 顺序／依赖已在提案阶段完成并合入，不在执行侧启动方案 Agent；进入下一阶段需要人员明确动作。开发与 UT、ST MUST 合并为开发与验证，分别记录真实 UT/ST 结果。

#### Scenario: 开发计划推进
- **WHEN** 人员查看当前开发计划
- **THEN** 使用确认计划进入开发与验证、确认开发与验证进入交付 PR 等明确动作；聊天、文件存在或 Agent 回复不形成批准。

#### Scenario: 批准绑定当前阶段与材料版本
- **WHEN** 当前开发人批准阶段推进
- **THEN** 在任何状态变更前核对实际阶段、轮次、提交的材料摘要、所需材料集合及文件版本；计划需要 plan，开发与验证需要 completion／UT／ST，缺失、失效或版本不符时拒绝；重复或过期请求不得跳过阶段
- **AND** 保存阶段、轮次、摘要、完整文件快照和确认时间；下一阶段不自动生成后续产物，须等待本阶段材料完整。原型只显式生成静态样例，不将样例报告视为实际测试通过

#### Scenario: 历史轮次只读且不改变执行
- **WHEN** 用户选择已访问阶段或旧轮次
- **THEN** 读取原阶段／轮次的会话与材料并标明历史只读，不能发送消息、生成材料、批准、返回、停止或登记交付；可返回实际阶段，不重启任务、不重绑 worktree
- **AND** 已完成 SR 仍可只读查看原阶段／轮次会话，不显示可写当前阶段返回入口。尚未进入的阶段禁用；动作层独立检查查看范围，不能只依赖按钮禁用。工作区仍为当前固定目录，历史材料不等同历史代码快照

#### Scenario: 开发验证报告
- **WHEN** Agent 完成获授权的实现和验证
- **THEN** 交付完成报告、验证记录、限制和未完成项，等待人员确认；未执行、失败和环境限制如实保留，不冒充全部通过。

#### Scenario: 不重复需求阶段
- **WHEN** SR 准备开发计划
- **THEN** 使用默认分支已合入的 IR、SR、提案方案和确认记录，不重复业务整理、SR 撰写或方案 Agent 阶段；发现合入方案不适用须披露阻塞，不自行改写冻结基线或恢复方案阶段。

### Requirement: 人工 PR、IR 验收与最终归档

提案、SR 和最终验收归档 PR MUST 均由 AI 提交／推送分支并提供标题及正文，由人工创建、评审、合并和告知结果。平台 MUST 核对默认分支中的真实文件版本及合并事实，不依赖 PR API，不以通知、链接或勾选代替核验；支持 squash／rebase 后提交身份变化。

#### Scenario: 提案合入
- **WHEN** 人工告知提案 PR 已合并
- **THEN** 核验 proposal.md、全部 SR 增量规格和确认 design.md 已进入默认分支，成为正式提案，显示在正式需求导航；不提前把未实现的增量规格同步到 openspec/specs

#### Scenario: SR 交付范围与合并前验证
- **WHEN** SR 准备交付 PR
- **THEN** 同一 PR 包含代码、测试及该 SR 对 openspec/specs/<capability>/spec.md 的同步，记录源 Change／SR／版本；合并前对齐最新默认分支并重跑受影响验证，需求冲突和 Git 合并冲突暂停交人工，普通实现问题由 Agent 修复
- **AND** 不向默认分支直接推送，不把提交、推送、人工 PR 创建与合并当成同一状态，不为普通状态变更制造额外状态 PR

#### Scenario: IR 验收与最终 PR
- **WHEN** 全部 SR 的代码、测试与规格已合入
- **THEN** IR 验收 Agent 基于最新默认分支执行整体验收，修复实现问题后重跑受影响验证及整体验收；业务或方案变更重新提案；最终候选提交包含全部修复，默认分支合并前变化时重新核对影响与必要验证
- **AND** 修复与归档放在最后一个 PR，无修复时为归档 PR；归档前核对各 SR 的实现、测试、规格完整且一致，归档只移动 Change 目录，不再次同步规格

#### Scenario: IR 完成
- **WHEN** 人工合并最终 PR 并告知平台
- **THEN** 核验默认分支中的最终候选成果、验收版本和归档结果后才标记 IR 完成、释放仓库 IR 占用；SR PR 合并只完成该 SR，不代表整个 IR 已完成

### Requirement: 返工保留代码并使后续材料失效

返回开发计划或开发与验证前 MUST 停止并结清当前 SR 的 Agent 及递归子任务。返回 MUST 保留已有代码，不执行自动代码回退；修改前序材料后，需要重新确认并重新生成或验证相关后续成果。

#### Scenario: 只查看历史不失效
- **WHEN** 用户仅查看过去的方案或计划
- **THEN** 保留当前阶段、批准和报告资格；不把查看历史变成 Back。

#### Scenario: 实际修改计划或实现
- **WHEN** 人员明确返回开发计划或开发与验证，Agent 更新计划或实现
- **THEN** 增加执行轮次，该步骤批准及后续依赖产物失效，原材料、会话、确认与旧 PR 记录保留历史但不可作为本轮交付；新轮次重新生成并确认材料；Agent 依据现有代码调整实现，后续验证必须检查旧实现残留，以及实现与已合入方案的兼容性；不改写冻结方案。

#### Scenario: 停止失败
- **WHEN** 后代任务、工具或外部进程未确认结清
- **THEN** 保持原阶段并显示可重试失败，不在仍有写入时完成返回。

#### Scenario: 已交付后请求返回
- **WHEN** 代码 PR 已合入
- **THEN** 不通过普通 Back 撤销默认分支代码或重开已结束执行；实现问题进入 IR 整体验收修复，业务变化重新提案；不使用普通 Back 撤销已合并结果。

### Requirement: 正式资料 Git 与共享业务数据库分离

正式需求、方案、计划及交付时已有报告 MUST 使用可读 Markdown 和必要 JSON 纳入 Git。项目、Release、提案状态与阶段、开发占用、PR 标记、反馈、方案版本、操作记录及 OMP 会话引用 MUST 统一保存于非 Git 的共享数据库 `/tmpdata/DFT_LAB/omp/omp_dev_sqlite.db`，通过项目 ID 隔离，不另建每项目数据库或共享 JSON 状态权威；原生聊天正文及历史仍由 OMP 管理，Dev 关联必要会话引用。

#### Scenario: 运行状态不随资料提交
- **WHEN** 资料被提交到需求或开发分支
- **THEN** 不夹带进程、端口、队列、锁、绝对路径或聊天副本；Git 拉取只保证材料可读，不保证重建完整运行进度。

#### Scenario: NFS 上工作流数据共享
- **WHEN** 同项目存在多个 worktree 或用户顺序换机器
- **THEN** 访问同一份必要工作流状态，不能各 checkout 独立形成相互矛盾的开发占用；结构带格式版本和稳定引用，按钮状态从真实事实计算。

#### Scenario: 未生成的后置资料
- **WHEN** 代码交付时尚没有公司后续测试结论
- **THEN** 不预造未来报告，不强制通过 Dev 为未来每次测试状态创建 PR。
