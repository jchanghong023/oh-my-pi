# dev-browser-workbench

> **首要交付与维护约束：前端和接口是正式代码，原型 mock 的只是后端服务。**
>
> 前端、接口客户端及请求／响应／错误／实时事件契约 MUST 按正式代码标准交付；原型后端以纯内存 mock 实现同一契约，真实 OMP 后端以真实业务实现同一契约。接入真实 OMP 时 MUST 只实现后端并切换配置地址，MUST NOT 修改前端、替换客户端或转换接口格式。后续每次功能、架构或接口更新 MUST 继续遵守此边界，同步维护共享正式前端、共享契约与后端实现；MUST NOT 把前端或接口的正式化留待以后。

## Purpose

Dev 是 AI 驱动的需求澄清、需求管理与开发进度跟踪平台：将自然语言整理为 IR／SR，分析方案和依赖，安排人员与排期，管理需求分支，根据代码证据报告实现进度及遗留问题。Dev 不参与实际编码。

本规格整合此前分步确认的最新规则，删除旧开发计划、执行 Agent、开发准入名额、固定通过验收及归档流水线要求，不以历史原型或其他旧流程说明恢复这些能力。普通 OMP／TUI／WebGUI 的原生开发能力不变。

当前已统一 Dev 共享前端入口与网络客户端：`preview/main.tsx` 和 `runtime/main.tsx` 均加载同一 `app/bootstrap.tsx`，使用同一 `client/remote-data-source.ts`，旧 `runtime/omp-data-source.ts` 宿主适配已移除。原型后端可独立启动，业务数据、模拟回复、任务和事件由服务端纯内存持有。真实 OMP 业务后端尚未实现，真实接入剩余工作仅为后端实现下述既有冻结契约并配置后端地址，不再迁移前端、替换客户端或转换接口格式；真实服务未改造，发行内嵌资源未重新生成。原型 API 检查、浏览器演示及既有启动命令、截图和历史验证均保留其原有证据范围，不替代真实模型、Git、共享数据库、正式宿主业务或发行产物验收，也不证明真实 OMP 已接通。

## Requirements

### Requirement: 需求管理而非编码执行

Dev MUST 只负责需求澄清、评审、方案、人员排期、需求分支管理和代码证据进度跟踪。MUST NOT 提供 SR 开始开发、计划／执行 Agent、自动改代码、运行测试、修复代码、固定通过验收或编码交付流水线。开发者在平台外使用自己的工具实现需求；依赖和计划时间不构成开发执行锁或任务调度。

#### Scenario: 正式需求不进入开发聊天
- **WHEN** 选择正式 IR 或 SR，包括旧链接与恢复的选择
- **THEN** 展示大表格及同页进度报告／需求材料，不挂载开发聊天、输入框或阶段推进按钮
- **AND** 不启动原有开发、验收或归档 Agent，不因切换浏览对象执行代码或 Git 操作

### Requirement: 复用 Dev 自有界面与数据源边界

Dev MUST 沿用已完整复制的 WebGUI 控件与布局能力，在 Dev 自有共享前端修改。WebGUI 与 Dev 的视觉基础按 [zcode-visual-baseline](../zcode-visual-baseline/spec.md) 对齐官方 ZCode 3.18，允许该规格明确授权的主题、字体、控件视觉和面板层级适配；WebGUI 的业务、后端、协议及构建配置不因此改变，不以视觉同步恢复已裁剪功能。Dev 原型和正式版 MUST 共用同一份前端代码、同一接口客户端及完全相同的浏览器代码，不保留另一套旧 Dev 界面，不按 prototype／runtime 模式分支业务界面或注入两套前端业务数据源；选择后端的唯一差异 MUST 是配置的后端地址。

原型后端与 OMP 后端 MUST 可各自独立启动，并实现同一请求、响应、错误及实时事件契约；同一客户端对两者使用相同的调用、错误处理和事件消费路径。原型后端 MUST 在服务端纯内存持有业务数据、状态、模拟回复、任务和事件，不依赖数据库、Git、模型或 OMP；服务重启恢复初始样例，页面刷新、关闭或断开连接 MUST NOT 重置业务或作为服务任务停止条件。主题、尚未发送的输入草稿等浏览器偏好保留既有作用域，不成为业务状态权威。

共享网络契约 MUST 固定遵循 `backend/contract.ts` 的版本 1（`DEV_CONTRACT_VERSION = 1`），包括各 operation 的参数与结果、响应 envelope、错误码及实时事件，并保持既有二进制 services RPC；真实 OMP 后端 MUST 实现该合同，而非按后端提供者替换客户端或调整请求／响应格式。bootstrap 的 `provenance`（`sample`／`live` 及可选提示）仅表达数据来源，`capabilities.requirementManagement` 表达实际业务支持，`scenarioOperations` 仅表达原型演示操作可用性；这些字段 MUST NOT 构成 prototype／runtime 业务 mode 或另一套业务界面，主业务 `readPrHandoff(group)` MUST 独立于原型演示接口。

OMP 后端 MUST 负责真实业务、持久化及模型、Git 等外部能力，复用 OMP 原生宿主的会话、工具、任务和生命周期，不新增第二执行器。前端 MUST 能持续连接原型后端进行开发和演示，接入 OMP 时只切换配置的后端地址，不复制、重写或替换前端或客户端。模拟身份 MUST 由后端响应与事件数据表达，共享 UI 依同一契约展示，不用前端模式业务分支制造模拟回复或样例。

#### Scenario: 同一浏览器代码只切后端地址
- **WHEN** 前端持续连接原型后端完成项目、Release、提案讨论、评审、方案、人员排期、入库和正式进度报告演示后，改为连接 OMP 后端
- **THEN** 只修改后端地址配置，浏览器代码、接口客户端、业务界面及请求／事件消费路径不变，不复制、重写或替换客户端，不注入另一业务数据源
- **AND** 两类后端在相同业务动作中遵守同一请求、响应、错误及实时事件契约；既有界面、人工确认、版本门禁和权限规则保持不变

#### Scenario: 原型后端可独立演示
- **WHEN** 不启动 OMP 后端、不提供 Rust 宿主、模型凭据、Git 或数据库，仅启动原型后端及共享前端
- **THEN** 可在桌面浏览器完成上述演示，样例数据与资源随源码交付，输入校验、取消、状态变化、错误反馈及实时事件由相同客户端呈现
- **AND** 模拟回复、证据、任务和 Git 结果由原型后端数据明确标为样例，不调用真实模型、Git 或数据库，不冒充真实执行

#### Scenario: 原型业务不归页面所有
- **WHEN** 已在原型后端保存业务变更或接纳模拟任务后，刷新、关闭页面或断开浏览器连接，再次连接同一仍运行的原型后端
- **THEN** 读取后端当前业务状态与任务结果，不恢复初始样例，不因页面离线停止已接纳的服务任务，也不自动重发动作
- **AND** 重启原型后端才恢复初始样例，不从浏览器业务副本、数据库或 Git 恢复此前业务；此行为不表示正式持久化已实现

#### Scenario: OMP 后端独立承担真实能力
- **WHEN** 不启动原型后端，共享前端连接独立运行的 OMP 后端处理真实业务
- **THEN** 真实业务状态、持久化和外部能力由 OMP 后端负责，原生宿主管理实际会话、工具和任务，不依赖原型服务或另建执行器
- **AND** 原型后端的纯内存生命周期不替代正式部署的共享数据库、权限和持久化要求

#### Scenario: 两类后端错误均不回退样例
- **WHEN** 原型后端或 OMP 后端读取、连接或动作失败
- **THEN** 同一客户端显示该后端返回的错误或连接错误并保留目标和输入，不自动切换后端、加载样例兜底或重放动作
- **AND** 原型后端提供的模拟失败也走相同错误处理路径；构建、预览或原型模拟成功不能作为真实模型、Git、共享数据库或发行产物验收

### Requirement: 桌面导航与浏览器边界

Dev MUST 仅面向电脑端浏览器，设计、原型和验收只考虑电脑布局，不提供手机、平板或触屏专用布局。电脑端窄窗口和拖窄分栏仍在验收范围，不能因“只考虑电脑”而允许内容或操作溢出容器。Firefox 128 默认启用的原生能力是最低运行环境与技术上限；现代浏览器使用同一实现和生产资源集，不引入 polyfill、API shim、浏览器专属回退或双构建。

#### Scenario: 电脑端窄分栏与外观可访问性
- **WHEN** 电脑窗口约 1122px，用户拖窄右侧材料栏
- **THEN** 文档底部返回、评审通过等操作在材料栏内换行，按钮完整可见，不依赖页面横向滚动；人工确认与版本门禁不变
- **AND** 外观页界面主题、浅色／深色代码主题及行号／换行开关关联可见标签和说明，在无障碍树中有可识别名称；保留键盘打开、关闭与切换能力，不增加移动端布局


#### Scenario: 导航只服务需求平台
- **WHEN** 打开独立原型
- **THEN** 左侧保留新建需求提案、自动化、正式需求、需求提案列表及底部项目／Release／设置入口，不显示自由会话、会话列表、新建普通会话或正在开发区域，不留空白占位
- **AND** 需求提案只列 IR，不显示 SR 树或展开全部；整行进入 IR，保留提出人、阶段、搜索、组合筛选及最近更新／创建时间排序
- **AND** 项目与 Release 在工作区菜单同组展示，先选项目再选所属 Release；选择、搜索、排序和查看历史不推进业务状态

#### Scenario: 自动化保留独立演示边界
- **WHEN** 进入已有自动化页面
- **THEN** 复用现有列表、筛选及查看控件，运行记录与需求讨论隔离；原型操作不启动真实调度或模型，不把 Team／提示词命令冒充任意图工作流引擎
- **AND** 明确这是通用定时任务与工作流，提供进入“主页 → 需求分析”的入口；通用任务不自动推进 IR／SR。Dev 不展示桌面端“保持电脑运行”开关，普通非 Dev 自动化保持原行为
- **AND** 通用定时任务区分“已启用 · 等待执行”“执行中”“已暂停”；启用不等于执行，只有当前运行记录明确执行中才归入执行中筛选，暂停任务单独筛选，列表与详情一致

#### Scenario: 浏览器验收证据匹配环境
- **WHEN** 声称 Firefox 128 验证通过
- **THEN** MUST 使用 Selenium＋已存在的 geckodriver 驱动本机真实 Firefox 128，隔离临时 profile，记录精确版本、入口和实际交互范围，不自动安装浏览器／驱动或修改个人配置
- **AND** Chromium、本机 Firefox、发行资源与真实多人服务分别记录，不互相代称通过；未观察的中文输入法或桌面交互明确未验证

### Requirement: 项目与 Release 只配置远程仓库

项目 MUST 配置名称、Git 远程仓库地址及默认分支；Release 配置所属项目和版本名称，继承项目仓库。MUST NOT 要求共享项目路径、个人开发目录、目录浏览或目录校验。平台按需自行拉取并管理内部工作副本。

#### Scenario: 保存配置不执行 Git
- **WHEN** 保存项目或 Release 设置
- **THEN** 仅保存配置并保留稳定 ID 及关联，不拉取、创建分支、推送、移动文件或重绑历史
- **AND** 项目与 Release 设置仅允许启动共享 OMP Web 的人修改，其他人只读；原型后端只校验格式和保存服务端内存，不把格式通过当仓库可访问或分支存在
- **AND** 项目卡片、编辑表单与保存反馈区分“配置已记录”和“仓库连接／默认分支已检查”；原型明确显示两项均未检查，不提供假成功。真实接入后的连接和分支检查须单独显示结果，不能把保存或格式校验成功当检查通过
- **AND** 远程 URL 必须包含主机；`https://`、`https:///` 等缺主机地址不能保存，合法 HTTPS／SSH URL 与 SCP 风格地址仍可记录；格式校验不执行连接

### Requirement: 自然语言澄清生成 IR 与 SR

一个 IR MUST 对应一个 OpenSpec Change；每个 SR 对应一个 `specs/<capability>/spec.md`，整份 IR 共用 `proposal.md`、`design.md` 及与 design.md 同目录的 `sr-dependencies.json`。业务需求 Agent 只生成／修改需求文件，不写代码或开发执行材料；方案 Agent 同轮维护 design.md 与 sr-dependencies.json，不编制编码任务计划。SR spec.md 不维护依赖，design.md 保留实现思路和技术取舍并引用 JSON，不重复依赖清单。

#### Scenario: 新提案首发
- **WHEN** 点击新建需求提案但尚未发送
- **THEN** 进入按 Web、工号、项目、Release 隔离的同一未发送草稿，保留文字与附件，不创建可见 IR／SR、材料或模型回复
- **AND** 首次发送实际接纳后才加入列表；重复点击及失败重试沿用待接纳身份，不生成空提案，失败保留输入
- **AND** 首发失败仍显示尚未生成材料，不生成占位 proposal.md，也不把未接纳草稿误报为材料读取失败；明确重试成功后才生成材料
- **AND** A（`j00808874`）的 Web 上允许业务人员首发，不要求本人拥有该 Web 或配置个人开发目录
- **AND** 输入及空材料区以业务目标、使用人员／场景和完成标准引导，说明可先描述已知信息、AI 再追问；输入提示不改变明确发送才创建提案的边界

#### Scenario: 三栏讨论与只读材料
- **WHEN** 进入提案 IR
- **THEN** 左侧提案列表、中间 AI 讨论、右侧只读材料保持原三栏尺寸与拖拽能力；顶部依次为标题、居中工作流时间线、当前 Agent／状态及处理人
- **AND** 时间线为业务需求→需求评审→技术方案→需求入库，点击已进入节点仅查看历史，不推进阶段或启动新 Agent；历史只读并可返回当前阶段
- **AND** 三栏下四阶段名称同时完整可见，复用原生时间线紧凑模式，不依赖横向滚动；减少重复 Agent 信息，完整名称与模型仍可查看
- **AND** 提案 SR 只阅读自身规格；直接选择 SR 时中间提示返回所属 IR，不挂载独立会话、时间线或阶段动作

#### Scenario: 移除未入库草稿
- **WHEN** 团队参与人从现有提案菜单移除允许删除的草稿
- **THEN** 显示目标与确认／取消；取消保留，确认仅移除原型后端内存条目；已入库、修订及开发历史继续受既有保护，不以停用的编码能力阻断草稿操作

#### Scenario: 文件归属及来源
- **WHEN** 阅读 IR 材料
- **THEN** 提供 proposal.md、全部 SR spec.md、design.md 和 sr-dependencies.json；SR 只显示自身规格，不混入其他 SR 或旧开发阶段材料
- **AND** 材料优先显示“业务需求”“技术方案”“SR 依赖”及 SR 标题；正文前“文件路径与技术信息”默认收起，展开后完整换行显示路径且不截断，正文复用现有 Markdown 阅读器。右侧选中 sr-dependencies.json 时复用现有图画布及控件展示只读 SR 依赖图，不展示 JSON 正文；节点包含稳定 ID 与标题，箭头从前置 SR 指向依赖方，支持缩放、平移及点击连线查看原因，独立 SR 保留节点；缺失、无效或过期材料明确报错，不绘制旧图
- **AND** 不提供复制、下载、带入讨论、正文编辑或表格／代码块操作按钮；流程操作固定在正文外底栏
- **AND** 提案显示 `/tmpdata/DFT_LAB/omp/{project_name}/{原提交人工号}/{提案id}/` 临时来源，转正后显示仓库相对来源并保留临时来源记录

### Requirement: 四 Agent 需求评审与人工判断

需求评审 MUST 为单个业务阶段：A／B／C 三个不同模型独立并行只读评审同版 IR／全部 SR，第四个综合评审 Agent 汇总来源、依据与分歧。最终是否通过 MUST 由人判断，不按投票、评分或模型问题标签自动放行／阻断。

#### Scenario: 综合意见与定向追问
- **WHEN** 打开当前评审
- **THEN** 默认展示综合意见，可通过原生工作流 Agent 头像切换 A／B／C 原始会话并定向追问；只读限制文件写入，不禁用当前报告的对话
- **AND** 可展开原生三路并行汇入综合评审再到人工判断的图，头像保留名称、模型、焦点与方向键切换；不将人画成 Agent
- **AND** 方向键连续切换及 Home／End 后焦点保留在对应头像，不被会话输入框自动抢走；用户主动进入输入框后不再强制转移焦点

#### Scenario: 版本完整后人工决定
- **WHEN** 同轮同版三个原始报告及综合意见均完整可读
- **THEN** 人工可通过进入方案或直接返回业务补充，记录工号、时间与版本；不增加争议裁决表单、逐项问题勾选或滚动已读门禁
- **AND** 报告缺失、失败、未完成或过期时不能作本轮批准；需求更新使旧报告和决定失效但保留历史，追问不自动修改需求或批准
- **AND** “返回业务补充”是实际退回阶段，不是查看业务历史；确认后列表、当前阶段及重新进入均为业务需求，保留旧评审历史但使其失效，取消不改变阶段
- **AND** 单个原始评审按同轮快照重试后，综合意见须重新生成，不能沿用旧人工决定；原型固定报告不证明真实并行调用或重试完成

### Requirement: 方案补充循环与工期预估

方案 MUST 逐 SR 展示实现思路及待确认事项；前置稳定 SR ID 和依赖原因 MUST 只读取 sr-dependencies.json，可并行关系只由依赖图推导。JSON 结构为 `{ "srs": [ { "srId": "...", "estimate": { "workingDays": 3, "assumptions": "估算依据与不确定项" }, "prerequisites": [ { "srId": "...", "reason": "..." } ] } ] }`，每个稳定 SR ID 唯一覆盖 IR 全部 SR，无依赖用空数组，不存储并行关系，不允许自依赖、未知 ID 或循环。提案只展示逐 SR 工期预估及假设，保存在 JSON 每个 SR 的 estimate 字段；workingDays 为正数工作日，可用小数，assumptions 说明依据、范围和不确定项。提案不分配负责人、开发人员或计划起止时间，不维护排期数据库副本。预估不代表实际用时或承诺日期；依赖和并行关系下不直接相加为 IR 总工期。

方案材料顶部 MUST 提供“技术方案／SR 依赖／工期预估”直接切换入口。工期预估只读呈现 JSON；人通过方案对话要求 AI 修改，同轮更新方案产物、使旧确认失效并随同一 PR 评审；不提供人工文件或预估编辑表单。

#### Scenario: 五秒服务端内存检查演示

- **THEN** 只修改原型后端内存中的远端结果夹具，由原型后端下一轮每五秒模拟检查更新业务状态并通过同一契约返回状态与事件；不操作真实 Git、PR、模型或数据库

### Requirement: 内网 HTTP 与子路径共享前端兼容

Dev 原型及正式共享前端 MUST 支持通过普通内网 IP 的 HTTP／WS 入口使用，不依赖 localhost 安全上下文例外，不要求 HTTPS 或浏览器安全策略豁免。默认浏览器后端地址 MUST 跟随当前页面 origin 与构建挂载前缀，原型预览服务器代理同前缀的 HTTP／WS 至独立后端并移除挂载前缀，不修改冻结请求、响应或实时契约。资源、页面刷新及连接 MUST 支持配置的 `/xxx/xxx/` 子路径；独立后端仍可仅监听服务器 loopback。

#### Scenario: 另一台电脑通过内网 IP 打开原型
- **WHEN** 使用者打开 `http://服务器IP:4173/xxx/xxx/`，浏览器报告非安全上下文
- **THEN** 前端资源、工号入口、业务 HTTP 及 WS 会话在同源挂载路径下工作，不向访问者本机 localhost 发业务请求
- **AND** 页面及 Skill 会话 ID 使用共享兼容工具，附件仍使用同一 SHA-256 算法与协议格式；缺少 WebCrypto 时采用可靠纯 JavaScript 实现，不能跳过校验或伪造摘要
- **AND** 复制分支、消息、代码和路径复用同一兼容工具，保留用户触发、焦点和选区；失败显示或记录失败而非成功，浏览器麦克风不可用时给出明确替代输入提示

#### Scenario: 正式宿主挂载相同前端
- **WHEN** 正式宿主提供同一构建前缀的静态资源并接入冻结 HTTP／WS 路由
- **THEN** 无需替换客户端或编写模式分支；地址覆盖仍可显式指定可达后端，原型内存及真实后端权威不变
- **AND** 原生 runtime 保留宿主随机能力目录下的相对资源与接口地址，不为支持 HTTP 去掉能力前缀；原型浏览器验证不能代称真实 OMP 后端、Firefox 或正式宿主已验收

工期预估缺失或字段不完整时，只要当前材料的 SR 依赖结构、版本及拓扑有效，仍展示只读依赖图，对应节点显示“待预估”。依赖本身缺失、无效、循环或材料过期仍报错，不绘制旧图。图可阅读不等于方案完整：确认、提交与自动转正仍须补齐每个 SR 的正数工作日和非空估算假设；人通过方案对话让 AI 更新同一 JSON，不手工改文件。
