# dev-browser-workbench

## Purpose

Dev 是 AI 驱动的需求澄清、需求管理与开发进度跟踪平台：将自然语言整理为 IR／SR，分析方案和依赖，安排人员与排期，管理需求分支，根据代码证据报告实现进度及遗留问题。Dev 不参与实际编码。

本规格整合此前分步确认的最新规则，删除旧开发计划、执行 Agent、开发准入名额、固定通过验收及归档流水线要求，不以历史原型或其他旧流程说明恢复这些能力。普通 OMP／TUI／WebGUI 的原生开发能力不变。

本轮交付仅为文档及独立演示原型；不修改正式宿主、适配层或后端。已有真实入口与原型数据源分离不代表本规格完整业务已经实现或验收。

## Requirements

### Requirement: 需求管理而非编码执行

Dev MUST 只负责需求澄清、评审、方案、人员排期、需求分支管理和代码证据进度跟踪。MUST NOT 提供 SR 开始开发、计划／执行 Agent、自动改代码、运行测试、修复代码、固定通过验收或编码交付流水线。开发者在平台外使用自己的工具实现需求；依赖和计划时间不构成开发执行锁或任务调度。

#### Scenario: 正式需求不进入开发聊天
- **WHEN** 选择正式 IR 或 SR，包括旧链接与恢复的选择
- **THEN** 展示大表格及同页进度报告／需求材料，不挂载开发聊天、输入框或阶段推进按钮
- **AND** 不启动原有开发、验收或归档 Agent，不因切换浏览对象执行代码或 Git 操作

### Requirement: 复用 Dev 自有界面与数据源边界

Dev MUST 沿用已完整复制的 WebGUI 控件、主题、字体、间距、动效与布局能力，在 Dev 自有前端修改；原 WebGUI 前后端、协议、构建配置及正式资源 MUST 保持不变。原型和正式入口共用同一套 UI，通过明确类型合同注入不同数据源，不保留另一套旧 Dev 界面。

#### Scenario: 独立演示 app
- **WHEN** 按 `packages/dev-frontend/README.md` 启动原型
- **THEN** 无需 OMP、Rust、模型凭据或正式业务服务，即可在桌面浏览器演示项目、Release、提案讨论、评审、方案、人员排期、入库和正式进度报告
- **AND** 样例数据与资源随源码交付，操作有连贯的状态变化、输入校验、取消与错误反馈；模拟回复、证据与 Git 结果明确标为样例，不冒充真实执行
- **AND** 业务变更仅保存当前页内存，刷新恢复样例；主题、草稿等浏览器偏好按原作用域保留，不把原型记录写入正式数据库

#### Scenario: 正式入口不回退样例
- **WHEN** 正式 OMP 入口读取或连接失败
- **THEN** 显示真实错误并保留目标，不加载预览适配器、固定回复或样例数据兜底，不重放动作
- **AND** 本轮不补做正式后端；构建或预览成功不能作为真实模型、Git、共享数据库或发行产物验收

### Requirement: 桌面导航与浏览器边界

Dev MUST 仅面向电脑端浏览器，设计、原型和验收只考虑电脑布局，不提供手机、平板或触屏专用布局。电脑端窄窗口和拖窄分栏仍在验收范围，不能因“只考虑电脑”而允许内容或操作溢出容器。Firefox 128 默认启用的原生能力是最低运行环境与技术上限；现代浏览器使用同一实现和生产资源集，不引入 polyfill、API shim、浏览器专属回退或双构建。

#### Scenario: 电脑端窄分栏与外观可访问性
- **WHEN** 电脑窗口约 1122px，用户拖窄右侧材料栏
- **THEN** 文档底部返回、评审通过等操作在材料栏内换行，按钮完整可见，不依赖页面横向滚动；人工确认与版本门禁不变
- **AND** 外观页界面主题、浅色／深色代码主题及行号／换行开关关联可见标签和说明，在无障碍树中有可识别名称；保留键盘打开、关闭与切换能力，不增加移动端布局


#### Scenario: 导航只服务需求平台
- **WHEN** 打开独立原型
- **THEN** 左侧保留新建需求提案、自动化、正式需求、需求提案列表及底部项目／Release／设置入口，不显示自由会话、会话列表、新建普通会话或正在开发区域，不留空白占位
- **AND** 需求提案只列 IR，不显示 SR 树或展开全部；整行进入 IR，保留提出人、阶段、搜索、组合筛选及最近更新／创建时间排序
- **AND** 项目与 Release 在工作区菜单同组展示，先选项目再选所属 Release；选择、搜索、排序和查看历史不推进业务状态

#### Scenario: 自动化保留独立演示边界
- **WHEN** 进入已有自动化页面
- **THEN** 复用现有列表、筛选及查看控件，运行记录与需求讨论隔离；原型操作不启动真实调度或模型，不把 Team／提示词命令冒充任意图工作流引擎
- **AND** 明确这是通用定时任务与工作流，提供进入“平台配置 → 需求进度分析”的入口；通用任务不自动推进 IR／SR。Dev 不展示桌面端“保持电脑运行”开关，普通非 Dev 自动化保持原行为
- **AND** 通用定时任务区分“已启用 · 等待执行”“执行中”“已暂停”；启用不等于执行，只有当前运行记录明确执行中才归入执行中筛选，暂停任务单独筛选，列表与详情一致

#### Scenario: 浏览器验收证据匹配环境
- **WHEN** 声称 Firefox 128 验证通过
- **THEN** MUST 使用 Selenium＋已存在的 geckodriver 驱动本机真实 Firefox 128，隔离临时 profile，记录精确版本、入口和实际交互范围，不自动安装浏览器／驱动或修改个人配置
- **AND** Chromium、本机 Firefox、发行资源与真实多人服务分别记录，不互相代称通过；未观察的中文输入法或桌面交互明确未验证

### Requirement: 项目与 Release 只配置远程仓库

项目 MUST 配置名称、Git 远程仓库地址及默认分支；Release 配置所属项目和版本名称，继承项目仓库。MUST NOT 要求共享项目路径、个人开发目录、目录浏览或目录校验。平台按需自行拉取并管理内部工作副本。

#### Scenario: 保存配置不执行 Git
- **WHEN** 保存项目或 Release 设置
- **THEN** 仅保存配置并保留稳定 ID 及关联，不拉取、创建分支、推送、移动文件或重绑历史
- **AND** 项目与 Release 设置仅允许启动共享 OMP Web 的人修改，其他人只读；原型只校验格式和保存内存，不把格式通过当仓库可访问或分支存在
- **AND** 项目卡片、编辑表单与保存反馈区分“配置已记录”和“仓库连接／默认分支已检查”；原型明确显示两项均未检查，不提供假成功。真实接入后的连接和分支检查须单独显示结果，不能把保存或格式校验成功当检查通过
- **AND** 远程 URL 必须包含主机；`https://`、`https:///` 等缺主机地址不能保存，合法 HTTPS／SSH URL 与 SCP 风格地址仍可记录；格式校验不执行连接

### Requirement: 自然语言澄清生成 IR 与 SR

一个 IR MUST 对应一个 OpenSpec Change；每个 SR 对应一个 `specs/<capability>/spec.md`，整份 IR 共用 `proposal.md`、`design.md` 及与 design.md 同目录的 `sr-dependencies.json`。业务需求 Agent 只生成／修改需求文件，不写代码或开发执行材料；方案 Agent 同轮维护 design.md 与 sr-dependencies.json，不编制编码任务计划。SR spec.md 不维护依赖，design.md 保留实现思路和技术取舍并引用 JSON，不重复依赖清单。

#### Scenario: 新提案首发
- **WHEN** 点击新建需求提案但尚未发送
- **THEN** 进入按 Web、工号、项目、Release 隔离的同一未发送草稿，保留文字与附件，不创建可见 IR／SR、材料或模型回复
- **AND** 首次发送实际接纳后才加入列表；重复点击及失败重试沿用待接纳身份，不生成空提案，失败保留输入
- **AND** 首发失败仍显示尚未生成材料，不生成占位 proposal.md，也不把未接纳草稿误报为材料读取失败；明确重试成功后才生成材料
- **AND** A（`j00808874`）的 Web 上允许业务人员首发，不要求本人拥有该 Web 或配置个人开发目录
- **AND** 输入及空材料区以业务目标、使用人员／场景和完成标准引导，说明可先描述已知信息、AI 再追问；输入提示不改变明确发送才创建提案的边界

#### Scenario: 三栏讨论与只读材料
- **WHEN** 进入提案 IR
- **THEN** 左侧提案列表、中间 AI 讨论、右侧只读材料保持原三栏尺寸与拖拽能力；顶部依次为标题、居中工作流时间线、当前 Agent／状态及处理人
- **AND** 时间线为业务需求→需求评审→技术方案→需求入库，点击已进入节点仅查看历史，不推进阶段或启动新 Agent；历史只读并可返回当前阶段
- **AND** 三栏下四阶段名称同时完整可见，复用原生时间线紧凑模式，不依赖横向滚动；减少重复 Agent 信息，完整名称与模型仍可查看
- **AND** 提案 SR 只阅读自身规格；直接选择 SR 时中间提示返回所属 IR，不挂载独立会话、时间线或阶段动作

#### Scenario: 移除未入库草稿
- **WHEN** 团队参与人从现有提案菜单移除允许删除的草稿
- **THEN** 显示目标与确认／取消；取消保留，确认仅移除原型内存条目；已入库、修订及开发历史继续受既有保护，不以停用的编码能力阻断草稿操作

#### Scenario: 文件归属及来源
- **WHEN** 阅读 IR 材料
- **THEN** 提供 proposal.md、全部 SR spec.md、design.md 和 sr-dependencies.json；SR 只显示自身规格，不混入其他 SR 或旧开发阶段材料
- **AND** 材料优先显示“业务需求”“技术方案”“SR 依赖”及 SR 标题；正文前“文件路径与技术信息”默认收起，展开后完整换行显示路径且不截断，正文复用现有 Markdown 阅读器。右侧选中 sr-dependencies.json 时复用现有图画布及控件展示只读 SR 依赖图，不展示 JSON 正文；节点包含稳定 ID 与标题，箭头从前置 SR 指向依赖方，支持缩放、平移及点击连线查看原因，独立 SR 保留节点；缺失、无效或过期材料明确报错，不绘制旧图
- **AND** 不提供复制、下载、带入讨论、正文编辑或表格／代码块操作按钮；流程操作固定在正文外底栏
- **AND** 提案显示 `/tmpdata/DFT_LAB/omp/{project_name}/{原提交人工号}/{提案id}/` 临时来源，转正后显示仓库相对来源并保留临时来源记录

### Requirement: 四 Agent 需求评审与人工判断

需求评审 MUST 为单个业务阶段：A／B／C 三个不同模型独立并行只读评审同版 IR／全部 SR，第四个综合评审 Agent 汇总来源、依据与分歧。最终是否通过 MUST 由人判断，不按投票、评分或模型问题标签自动放行／阻断。

#### Scenario: 综合意见与定向追问
- **WHEN** 打开当前评审
- **THEN** 默认展示综合意见，可通过原生工作流 Agent 头像切换 A／B／C 原始会话并定向追问；只读限制文件写入，不禁用当前报告的对话
- **AND** 可展开原生三路并行汇入综合评审再到人工判断的图，头像保留名称、模型、焦点与方向键切换；不将人画成 Agent
- **AND** 方向键连续切换及 Home／End 后焦点保留在对应头像，不被会话输入框自动抢走；用户主动进入输入框后不再强制转移焦点

#### Scenario: 版本完整后人工决定
- **WHEN** 同轮同版三个原始报告及综合意见均完整可读
- **THEN** 人工可通过进入方案或直接返回业务补充，记录工号、时间与版本；不增加争议裁决表单、逐项问题勾选或滚动已读门禁
- **AND** 报告缺失、失败、未完成或过期时不能作本轮批准；需求更新使旧报告和决定失效但保留历史，追问不自动修改需求或批准
- **AND** “返回业务补充”是实际退回阶段，不是查看业务历史；确认后列表、当前阶段及重新进入均为业务需求，保留旧评审历史但使其失效，取消不改变阶段
- **AND** 单个原始评审按同轮快照重试后，综合意见须重新生成，不能沿用旧人工决定；原型固定报告不证明真实并行调用或重试完成

### Requirement: 方案补充循环与开发安排

方案 MUST 逐 SR 展示实现思路及待确认事项；前置稳定 SR ID 和依赖原因 MUST 只读取 sr-dependencies.json，可并行关系只由依赖图推导。JSON 结构为 `{ "srs": [ { "srId": "...", "prerequisites": [ { "srId": "...", "reason": "..." } ] } ] }`，每个稳定 SR ID 唯一覆盖 IR 全部 SR，无依赖用空数组，不存储并行关系，不允许自依赖、未知 ID 或循环。AI 建议计划开始／结束须说明计划起点、时区、人员日历和代码依据等假设；不单列工时，不把计划跨度当实际用时。

方案材料顶部 MUST 提供“技术方案／SR 依赖／人员与排期”直接切换入口，人员、依赖及建议排期不再藏在长方案正文末尾；切换只阅读现有材料与元数据，不改变版本、当前阶段或人工逐文件确认条件。

#### Scenario: 两个方案产物共享版本与确认
- **WHEN** 方案 Agent 生成／更新方案或需求版本变化
- **THEN** design.md 与 sr-dependencies.json 共用现有需求版本／方案轮次，同轮生成、更新和失效，任一产物变化均使旧方案确认失效；两者均可查看并须人工逐文件确认
- **AND** JSON 是依赖唯一权威；缺失、无效或过期须明确展示原因，不回退 SR spec.md、design.md 或旧依赖，不沿用旧确认，不允许提交或自动转正

#### Scenario: 方案退回业务
- **WHEN** 方案参与人无法回答问题并选择退出方案、退回业务补充
- **THEN** 在大输入框自行粘贴完整意见，取消不改变阶段；确认后直接回业务 Agent，不先进入评审，不自动拆题或分派
- **AND** 当前意见完整显示于业务讨论上方，可内部滚动及全屏只读阅读；保留原文、提出人、提交人及历史，新需求版本需重评、再生成当前方案
- **AND** 待处理退回意见未通过业务需求讨论补充并更新 IR／SR 前，不允许再次发起评审；文件更新后记录已补充，再评审及重新生成方案，不以重跑评审跳过意见，也不新增逐项裁决表单
- **AND** 方案参与人工号用于记录来源，不形成独占讨论、生成方案或退回权限；团队 Web 的其他业务参与人可继续当前方案，其他 Web 仍只读
- **AND** 旧方案与旧确认不能用于新版本入库；方案完成不自动推进，人工检查当前 IR、全部 SR、design.md 和有效 sr-dependencies.json 后逐文件确认

#### Scenario: 同页人员与时间调整
- **WHEN** 当前方案有效完成
- **THEN** 右侧材料旁展示独立开发安排元数据卡片；管理员分配唯一 IR 负责人，管理员或该负责人复用正式需求弹窗调整 SR 开发者及计划开始／结束，其他人只读
- **AND** 负责人分配与正式需求筛选复用人员检索，可按工号、姓名和部门辨别候选并保留直接输入工号；原型目录明确标注虚构姓名／部门及非身份核验，未收录但格式合法的工号仍可保存。无目录时如实提示，不伪造人员信息
- **AND** 保留 AI 原建议、人工调整标记和假设；工号合法，起止同时填写或清空且结束晚于开始；依赖时间冲突及同一人时间重叠须提醒，不自动移动其他 SR
- **AND** 工号输入旁直接说明“一个小写英文字母后接 8 位数字，例如 j00808874，可留空”；格式错误展示具体原因，修改合法后清除错误，不只依赖浏览器默认提示
- **AND** IR 时间从全部 SR 最早开始／最晚结束汇总，部分未排期明确提示，不维护独立 IR 排期副本
- **AND** 人员和排期只改数据库元数据，不改文档版本、依赖、推送资格或新增审批／PR；依赖修改通过方案讨论更新仓库文档，方案失效不开放旧安排为当前建议

### Requirement: 提案分支与后台自动入库

方案完成且人工逐文件确认当前 IR、全部 SR、design.md 和有效 sr-dependencies.json 后，平台 MUST 才从配置仓库的最新默认分支创建独立提案分支，将上述完整材料一同 Git 提交并推送，提供 PR 标题及正文。人工在 Git 网页创建、评审和合并包含 JSON 的 PR；平台 MUST NOT 自动创建／合并 PR，不依赖 PR API，不要求个人目录。

#### Scenario: 两条件自动转正
- **WHEN** 后台确认提案分支已合入默认分支，且默认分支上的 IR、全部 SR、design.md 和有效 sr-dependencies.json 完整
- **THEN** 自动转为正式需求，无需登记 PR 地址、人工通知或再次确认合入；可选 PR 地址仅供参考，支持 merge／squash／rebase 事实核验
- **AND** 从包含提案的最新默认分支创建并推送各 SR 分支，记录映射与基点，固定需求和验收标准并开始跟踪；重复检查不重复转正或创建分支
- **AND** 沿用同一项目、IR／SR、人员、人工排期、AI 原建议及依赖，不重置元数据；未分配人员或排期冲突不增加转正门槛
- **AND** 新 SR 进度为 0%，不代表代码完成，不归档 Change 或提前将未实现增量同步为已实现规格

#### Scenario: 未满足条件保留提案
