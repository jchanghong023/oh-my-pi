# Spec Delta

## MODIFIED Requirements

### Requirement: Dev 网页原生浏览器边界

Dev MUST 仅面向桌面浏览器，以 Firefox 128 默认启用的原生能力为最低环境及技术上限；现代浏览器使用同一实现和资源集，不引入 polyfill、API shim、专属回退或双构建，不转移 WebGUI 手机适配要求。

#### Scenario: 浏览器证据匹配目标
- **WHEN** 声称 Firefox 128 通过
- **THEN** 使用 Selenium 和已存在的 geckodriver 驱动本机真实 Firefox 128，隔离临时 profile，记录精确版本、入口及实际操作范围，不安装浏览器／驱动或修改个人配置
- **AND** Chromium、Firefox、生产资源及真实服务证据分别记录，不互代；未观察的输入法或桌面交互明确未验证，原型预览不证明正式业务或发行验收

### Requirement: 浏览器连接不拥有后台任务生命周期

真实部署 MUST 将页面连接与原生后台工作分开。关闭、刷新或断线不停止已确认工作；重连只读取实际事实，不重放消息、确认或 Git 操作，不承诺脱离宿主继续执行。

#### Scenario: 退出与内存原型区别
- **WHEN** 用户再次 `/dev` 请求退出
- **THEN** 先结清本实例自有工作，成功才恢复普通原会话，失败保持 TUI 独占并可重试；不取消需求、回滚 Git 或停止其他实例，关闭网页不等于退出
- **AND** 独立原型关闭或刷新会停止并重置内存定时演示，不能作为真实后台证据

## ADDED Requirements

### Requirement: Dev 自有界面与紧凑导航

Dev MUST 沿用已完整复制的 WebGUI 控件、主题、字体、间距、动效与布局，仅在 Dev 自有前端修改；原 WebGUI 前后端、入口、协议、构建及正式资源不变。原型和正式入口共用 UI 并通过明确类型合同注入不同数据源，不保留旧 Dev 界面或样例兜底。

#### Scenario: 需求导航与空态
- **WHEN** 打开工作台
- **THEN** 左侧只保留新建提案、自动化、正式需求、提案列表及底部项目／Release／设置；不提供自由会话、会话列表、新建普通会话或正在开发区域，不留占位
- **AND** 提案只列 IR，整行进入，保留提出人、阶段、搜索、组合筛选及时间排序，不显示 SR 树或展开全部；项目和 Release 在工作区菜单同组联动，无项目／版本／需求分别显示空态，不擅自回落其他对象
- **AND** 自动化复用已有列表、筛选和只读记录，演示不启动真实调度或模型，不把提示词或 Team 命令冒充任意图引擎

### Requirement: 独立原型与真实数据源分离

本轮 MUST 仅修改文档和 packages/dev-frontend 独立原型，不修改正式宿主、后端或运行时。原型无需 OMP、Rust、模型凭据和真实服务，业务变更只存本页内存，刷新恢复样例；源码与样例资源随仓库交付。

#### Scenario: 演示与正式失败
- **WHEN** 演示聊天、评审、排期、入库或代码进度
- **THEN** 样例回复、证据与 Git 结果明确标注，操作有连贯状态、校验、取消和错误反馈，不冒充真实执行
- **AND** 正式入口读取失败显示真实错误并保留目标，不加载预览适配器、固定回复或样例；构建／预览成功不证明模型、Git、数据库或多人业务已实现

### Requirement: 三栏提案与四 Agent 评审

提案 MUST 保持左侧列表、中间讨论、右侧只读材料三栏及拖拽能力；顶部时间线为业务需求→需求评审→技术方案→需求入库，历史节点仅只读查看，不推进阶段。首次发送实际接纳前只保留按 Web、工号、项目及 Release 隔离的未发送草稿，不创建可见 IR／SR、材料或回复。

#### Scenario: IR 与评审范围
- **WHEN** 查看当前需求评审
- **THEN** A／B／C 三个不同模型独立并行只读检查同轮同版 IR／全部 SR，第四个 Agent 综合来源、依据和分歧；默认综合意见，可切换原始会话追问，头像支持焦点和方向键，原生图展示三路汇入综合再到人工判断，不把人画成 Agent
- **AND** 四份报告完整可读后由人判断，不按投票、评分或标签自动放行／阻断；需求更新使旧报告、决定及方案失效，原始报告重试后重新综合，历史保留
- **AND** 提案 SR 仅显示自身规格及返回 IR 入口，不挂载聊天、时间线或阶段动作；失败保留输入，不生成空提案或重复接纳身份

### Requirement: 方案与人员排期元数据

方案 Agent MUST 逐 SR 说明实现思路、稳定 SR 依赖、原因、可并行关系及待确认项，不编制编码任务计划。AI 建议起止须说明计划起点、时区、人员日历及代码依据等假设，不单列工时或伪造可用性。

#### Scenario: 补充与开发安排
- **WHEN** 方案参与人无法回答业务问题
- **THEN** 人工在大输入框粘贴意见，取消不改阶段，确认直接回业务 Agent；正文保留原文、人员和历史，支持内部滚动及全屏阅读，更新后重评并重新确认方案
- **AND** 当前方案有效完成后，右侧提供文档外安排卡片；管理员分配唯一 IR 负责人，管理员或负责人调整 SR 人员和时间，其他人只读；起止同时填写／清空、结束晚于开始，依赖和人员冲突持续提醒但不自动移动其他 SR
- **AND** 人员、AI 原建议、人工排期及调整记录只入数据库，不改文档版本或建 PR，不增加推送或转正审批；依赖通过方案文档修改并入 Git，IR 汇总 SR 时间，部分未排期明确提示

### Requirement: 正式材料只读与来源

IR MUST 提供 proposal.md、全部 SR spec.md 和 design.md，SR 仅提供自身规格，不混入旧开发阶段材料。提案显示固定临时来源 /tmpdata/DFT_LAB/omp/{project_name}/{原提交人工号}/{提案id}/，转正显示仓库相对来源并保留临时记录。

#### Scenario: 选择与失败反馈
- **WHEN** 阅读材料
- **THEN** 使用业务名称选择，多份 SR 按标题区分，完整路径在正文前独立换行，正文复用 Markdown 阅读器；不提供复制、下载、带入讨论、正文编辑或表格／代码块操作按钮，流程操作在正文外底栏
- **AND** 未生成、读取错误及旧版失效分别提示并保留目标，不用摘要或其他样例代替；依赖不可读正文的确认不得继续，重试仅重读，不重放业务动作

### Requirement: 提案分支与后台自动转正

当前 IR、全部 SR 和方案完整且人工逐文件确认后，平台 MUST 才从最新默认分支创建独立提案分支并提交推送文档，提供 PR 内容。人工在 Git 网页创建、评审、合并 PR；平台不自动创建／合并 PR、不依赖 PR API、不要求个人目录。

#### Scenario: 两条件自动转正
- **WHEN** 后台确认提案分支合入默认分支且所有需求与方案文档完整有效
- **THEN** 自动转正并从包含提案的最新默认分支创建推送各 SR 分支，保存映射和基点；不重复转正或建分支，不要求 PR 地址、人工通知或再次批准，未分配人员或排期冲突不增加门槛
- **AND** 保留项目、IR／SR ID、人员、人工排期、AI 原建议及依赖；新 SR 为 0%，不表示代码完成，不归档 Change 或同步未实现规格
- **AND** 未合入、材料缺失或拉取失败保留提案和原因，显示最近／下次检查；原型仅每五秒读取内存场景，场景按钮不直接转正，不操作真实 Git 或后台

### Requirement: 正式需求表格与代码证据进度

Dev MUST 不编码，不提供开始开发、计划／执行／IR 验收 Agent、测试、修复或最终归档流水线。正式需求入口在自动化下方，无左侧 IR／SR 树；进入默认收起导航，主区域为可展开 IR／SR 表格，选择后同页右侧显示进度报告／需求材料，不进入聊天或独立详情页。

#### Scenario: 表格与报告可操作
- **WHEN** 查看正式需求
- **THEN** 提供需求、状态与进度、人员、只读依赖、计划开始／结束、问题及最近分析列，搜索／筛选／我负责的，固定表头和名称列、单层横向滚动；选择对象保留筛选、展开及滚动，报告默认约 380px、可拖至 320～480px 并收起
- **AND** 后台只读分析需求、验收和代码证据，报告百分比、遗漏、问题、不确定项、活动、时间、版本、分支和合入依据；未合入最高 99%，已合入且全部条件满足才可自动 100%，AI 不确定可由管理员／IR 负责人依据证据调整，记录工号、时间及依据并保留原问题
- **AND** IR 为全部 SR 算术平均，无 SR 为 0%，全部 SR 完成才完成，不把未达 100% 舍入为完成；依赖与计划只作提醒，不建立冻结锁、单 IR 限制、开发名额或个人目录准入，实际开发在平台外完成

### Requirement: 仓库、共享数据库与个人配置分离

项目 MUST 只配置名称、Git 远程仓库及默认分支，Release 继承项目仓库，不要求本地／个人目录。平台按需托管副本，保存设置不执行 Git。工号为小写 a–z 加八位数字，仅作操作标识，切换不改变 Web 所有者、Token 或 profile。

#### Scenario: 数据和权限归属
- **WHEN** 保存配置或业务资料
- **THEN** 正文、验收标准、方案及稳定 SR 依赖入 Git；项目、Release、提案状态、人员、建议／人工排期、进度及必要会话引用入共享库，各 Web 经固定 18321 的 dev_db 服务访问同一 NFS SQLite，不各自打开文件；Token、个人配置及聊天正文不入业务库
- **AND** 仅所有者为 j00808874 的 Web 可讨论提案，其他 Web 只读材料；已有项目仅管理员可改，模型／个性化／技能全员可看但只有 Web 所有者可改，全部写入口与快捷键同样受限；Skill 设计只明确发送／保存到个人或有效项目目标，不充当需求编码器
- **AND** 原型只存内存，不实现真实权限、CLI、模型、Git、网络服务或数据库，真实部署与验证不得由演示结果代称
