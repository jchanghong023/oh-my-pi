# Spec Delta: tui-presentation

## MODIFIED Requirements

### Requirement: 1. 三种显示模式

OMP MUST 按 `/display` 选择的 `clean`、`compact` 或 `detailed` 呈现同一份原始会话，默认使用 `compact`。compact MUST 以现有 clean 为基线，保留文件型 write／edit 与上游 detailed 相同的原组件显示、固定两行活动区，增加本规格规定的最近工具只读输出预览，并隐藏独立的模型处理忙碌提示；三档不得改变原始消息、执行和模型上下文。

#### Scenario: 1. 三种显示模式的详细边界

- **WHEN** 用户选择显示档位
- **THEN** clean 保持现有工具活动、工具结果图片和真实思考的隐藏行为；compact 保留文件型 write／edit 的上游原组件显示、固定两行活动区及最近工具只读输出预览，并隐藏独立的模型处理忙碌提示；detailed 保持原有完整组件及展开／折叠行为。
- **AND** `/display [clean|compact|detailed]`、无参数循环、默认值、保存与配置覆盖优先级不变，不新增显示档位、别名或旁路设置。
- **AND** `terminal.showImages` 和 `images.*` 仍独立生效，切换档位不改写图片设置；compact 中文件型 write／edit 历史原组件内的内容按 detailed 原规则及既有图片配置呈现，其他工具结果图片仍与 clean 一样隐藏；只读输出预览不显示图片或终端图形，不影响原有用户附件和模型识图。

#### Scenario: clean 与 compact 的显示差异

- **WHEN** 同一会话以相同尺寸、配置、草稿和执行状态分别按 clean 与 compact 显示
- **THEN** 除文件型 write／edit 的上游原组件显示、固定两行活动区、最近工具只读输出预览所需空间及独立的模型处理忙碌提示外，正文、用户消息、其他忙碌状态、独立通知、交互入口、滚动与历史选择 MUST 与 clean 一致。
- **AND** 文件型 write／edit 不采用最近次数筛选或额外成功／失败筛选；其他工具及非文件目标仅可按最近有输出的调用选择规则在临时区显示 Output，不恢复聊天历史中的普通工具预览、调用统计或错误卡片例外，不保留 compact 专属长用户消息折叠或压缩历史筛选。
- **AND** 文件型 write／edit 的进行中、成功、无变化、失败、取消及原有诊断反馈均沿用上游 detailed 的原组件和状态语义，不另做错误分类或重画；两行活动区中这些调用的动作行按统一动作状态规则显示，不改变原组件；其他工具及非文件目标不因成功、失败、取消或子代理结果在聊天历史恢复隐藏卡片。

#### Scenario: compact 不显示独立的模型处理忙碌提示

- **WHEN** compact 下模型开始处理请求或输出真实思考，包括思考内容尚未到达、被隐藏、结束或取消，以及运行中切换显示档位
- **THEN** ANSI 与 native MUST 不显示独立的“模型思考中…”提示及其前置图标；同一普通模型处理提示的“处理中…”等文案也不显示，不以同类提示或空行替代。
- **AND** 固定两行活动区按动作记录规则显示真实思考动作（进行中显示“正在思考”及最新思考片段，结束显示对应终态），或显示工具动作与保留内容；只读输出预览独立按其来源选择与关闭规则显示，不隐藏普通助手正文、其他状态通知、错误、审批与问答，不影响 Esc 中断或模型与工具执行。
- **AND** 两行活动区替代的是该独立运行提示的展示，不是底部状态栏图标；原提示的内部运行生命周期与中断控制保留，底部状态栏的品牌图标、旋转、计时和其他信息不因本替代改变。
- **AND** 切换到 clean 或 detailed 时恢复各自原有提示行为；只改变显示，不增删或改写思考内容及会话记录。

#### Scenario: clean 不显示实时思考占位或可展开思考

- **WHEN** clean 下模型开始、持续输出、完成、失败或取消真实思考
- **THEN** 聊天流中不显示思考正文、标题、完成提示、动画占位、可展开思考节点或空白块，输入区不增加活动区或只读输出预览。
- **AND** native 不发送可展开的隐藏思考正文，ANSI 不仅隐藏正文却保留标题；普通助手正文不因颜色或包含 Thinking 字样被隐藏。

#### Scenario: detailed 保留上游完整内容与原组件

- **WHEN** 切换 detailed 或在任何档位发生审批、问答、选择等实际交互
- **THEN** detailed 按原顺序展示完整工具与思考、用户全文及适用图片，展开、截断、复制和滚动保持原行为；完整可查看不等于强制展开。
- **AND** 隐藏工具记录不得隐藏或替代 clean 原有的实际交互界面；用户仍能通过原入口完成操作，活动区和只读输出预览均不替代审批或回答控件，输出预览本身不提供交互。

#### Scenario: 1. 三种显示模式 behavior

- **WHEN** 接收新消息、恢复历史、压缩后重建、切换代理视图或往返切换显示档位
- **THEN** 当前视口及后续内容使用相同的档位规则，没有旧 compact 预览、统计或隐藏思考残留；只读输出预览只恢复所属逻辑会话可确认的最近有输出来源及未到期终态，关闭计时不因重建或档位切换重启，不从已关闭历史重新打开。
- **AND** 保留原始内容、复制全文、草稿、附件和会话记录，不改变工具执行顺序、消息归属或模型输入。
- **AND** 粘贴标记、附件预览、提示词模板展开及 `/review` 原有输入行为不变；保存、模型接收和复制使用完整内容，不因显示切换生成摘要。

#### Scenario: 压缩期间的消息投递

- **WHEN** 手动或自动压缩进行期间收到子代理消息，之后压缩完成并继续当前会话
- **THEN** 该消息 MUST 保留在压缩完成后的模型上下文中，不得先在即将被替换的旧上下文消费后丢失；随后到达的子代理最终结果仍可按原有方式收取。
- **AND** 显示重建或档位切换不得复制、重新投递或重放这些消息，不改变发送者、接收者、正文、已提供内容或消息归属。

### Requirement: 紧凑历史的后台和进程回执

OMP MUST 保持 clean 与 detailed 既有后台任务、受监督进程和 wait 回执行为；compact 的聊天历史回执呈现 MUST 与 clean 一致，不按成功、失败或取消另设工具记录保留例外。两行活动区按动作记录规则呈现最近调用的动作状态与真实对象摘要；只读输出预览可以接收所选调用已有的后台 Output，但不构成另一套任务调度、统一后台跟踪或完成回执历史。

#### Scenario: 后台任务回执逐项筛选

- **WHEN** 后台任务回执包含成功、失败或取消的任务，或者 wait 消费其结果
- **THEN** 所有档位仍隐藏自动后台任务完成回执的状态行；compact 的聊天历史按 clean 处理相同回执与独立通知，不额外生成任务行、失败卡片、历史输出尾窗或工具统计。
- **AND** 只读输出区可以按最近有输出的调用规则显示真实进度及终态，随后按自身规则关闭；已有较新输出来源时，较早调用的回执不能抢占或重新打开预览。
- **AND** clean 和 detailed 原本可见的独立工件与结构化诊断保留；原任务结果、诊断、查询入口、投递、模型上下文及生命周期保持不变。

#### Scenario: 守护进程退出回执按退出结果裁剪

- **WHEN** 受监督进程完成、失败或取消并产生退出回执
- **THEN** compact 的聊天历史按 clean 处理回执，不按退出结果另设失败卡片或隐藏成功回执的专属例外；原进程退出码、诊断及生命周期保持不变。
- **AND** detailed 仍可按原有行为查看结果，两行活动区继续只呈现符合其动作选择规则的当前活动或静态保留内容；保留动作行不添加“上次活动”前缀、分隔符或替代标题。
- **AND** 服务退出回执不自动重新打开已经关闭或被较新输出来源替换的预览，不为本区域新增服务日志订阅或轮询。

#### Scenario: 实时和历史重建采用同一回执边界

- **WHEN** 同一回执实时到达后被归档或重建，或者用户切换 clean、compact、detailed
- **THEN** clean 与 detailed 不改变原有筛选及详情能力，compact 与 clean 对相同聊天历史回执的选择一致。
- **AND** 所有档位原本隐藏的自动完成状态行不重新出现，原工具和独立诊断的已有语义不得被全局删除；clean 和 detailed 原本可见的独立工件与结构化诊断保留。
- **AND** 只读输出预览恢复不向转录追加或复制回执，也不重新消费后台结果。

#### Scenario: 调用返回不延长为后台活动

- **WHEN** 工具调用已经返回，但其启动的任务或受监督进程仍在后台运行，之后又到达后台更新或完成回执
- **THEN** 该调用仍可按动作选择规则作为最近结束项显示其动作状态与对象摘要，但 MUST 不因后台仍运行被标为调用尚未返回或重新显示进行中动画；后台更新或回执不改变动作记录身份，也不使更早调用重新进入显示。
- **AND** 已返回调用的动作词按真实结果态静态显示；不把保留内容或运行中配色当作调用持续运行或后台成功的证明。
- **AND** 若它仍是只读输出预览的所选调用，有限异步任务的已有后台帧 MUST 可以继续更新 Output 直到任务真实结束；该调用自身不显示耗时。新调用无 Output 不抢占该来源，不新增日志通道、查询轮询或执行生命周期。

### Requirement: 全部工具的显示投影覆盖

OMP MUST 对已注册的内置、隐藏、扩展、MCP 及设备派发工具统一应用当前档位；compact 中文件型 write／edit 沿用上游 detailed 的原历史展示，除 todo 外各工具的真实 Output 文本均可按最近有输出的调用规则进入只读预览，todo 保留独立面板、不重复进入预览，其余普通工具不恢复聊天历史卡片。固定两行活动区独立呈现动作记录或所属逻辑会话最后实际显示的内容，不被 Output 取代；预览不复用完整有状态工具卡片。

#### Scenario: 原生与扩展工具均可识别

- **WHEN** 当前查看会话发生任一工具调用，包括无专用 renderer 的工具、扩展、MCP 或设备派发
- **THEN** 活动区 MUST 按动作选择规则选择最多两条动作记录，每个动作仅占一行，呈现该动作类别的中文状态词及真实对象详情；未单独映射的工具统一使用“正在调用／调用完成”等通用词，详情保留真实工具名称及已有简短参数摘要，不得误标为文件读取或命令执行。
- **AND** 无意图且无命令时使用已有目标等可确定信息；各项均不足时保留真实工具名称于详情，不伪造意图、目标或成功。wait 可复用已有结构化任务快照中的身份与命令，不以 stdout／stderr 或输出正文替代活动区详情。
- **AND** 只读输出预览按实际派发顺序选择最近一个已有可显示 Output 的调用，不依赖原组件是否专用、通用或聚合。没有 Output 的新调用不抢占已有来源；预览仅提取该调用自身的文本，不把整个 read 组或助手正文作为其输出。
- **AND** write／edit 的历史展示仍仅按操作目标与既有文件路由识别，不检查文件是否实际变化；非文件结果即使包含 diff 也不被伪装成文件操作。

#### Scenario: 相同调用跨生命周期不改变归属

- **WHEN** 参数流、执行进度、前后台转换、终态或迟到结果到达
- **THEN** 原调用身份、执行事实与任务计时 MUST 保持不变；不把参数生成当作已执行，也不把调用返回当作后台工作成功。
- **AND** 增量内容更新同一条动作记录，不因新文本或新输出重复插入、重置计时或重启动画周期；两次相同命令或同一路径的独立调用仍是两条动作记录，不按显示文字合并。输出预览按派发顺序在已有 Output 的调用中选择最近来源，而非按参数、返回或输出事件到达顺序排序。新调用首次产生 Output 才可替换较旧来源，较旧调用迟到更新不能抢占已有较新输出。
- **AND** 重建与代理切换只读取所属会话已有事实及其自身显示状态，不扩展权限、调度或后台跟踪范围；输出缓存的迭代顺序不视为派发顺序，迟到事件与关闭动作不得改写其他会话的活动、Output 或快照。

#### Scenario: 无可用意图或目标时保留身份而非空白

- **WHEN** 被选中的调用没有非空意图、原始命令和可用目标，或只提供通用工具名称
- **THEN** compact MUST 在该动作所属的一行保留通用动作状态词及真实工具名称，不伪造意图、目标、输出、进度或成功；另一条动作记录仍可使用其自身的一行。
- **AND** 已选只读预览的信息行同样保留真实工具身份和可确定状态，不伪造 Output；没有 Output 的调用不产生临时预览，仍可按原规则显示活动摘要。clean 不增加活动区或预览，detailed 保留原组件和既有完整查看能力。

#### Scenario: 搜索结果的原有完整性

- **WHEN** 显示 Web Search 结果或通过其 CLI 使用既有的显式答案行数限制
- **THEN** detailed 的 TUI 原组件在折叠和展开状态均保留完整答案，TUI 不传入 CLI 的答案限行参数；独立 CLI 的显式限行能力保持原有行为。
- **AND** clean 保持普通搜索工具及其非文件设备包装的隐藏规则；compact 的聊天历史继续按 clean 处理，搜索产生真实 Output 后可进入只读预览。五行输出预算只限制临时预览空间，不改写完整搜索结果、完整查看能力或模型接收的答案。

### Requirement: 流式工具摘要的显示稳定性

OMP MUST 在两行活动区安全呈现尚未完整的工具调用信息；缺失或错误类型字段不得导致渲染失败，不替代原工具的参数校验。每条动作记录独占一行，最多显示两条记录的动作状态与真实详情，不因长文本丢失另一条记录，也不因参数流或输出更新改变动作记录身份与派发事实。只读输出预览独立遵守最近有输出来源和六行预算规则，不改变此摘要边界。

#### Scenario: Eval 标题为非字符串

- **WHEN** 流式 Eval 参数包含有效代码，但 `title` 为数字、对象或其他非字符串
- **THEN** compact 的 ANSI 与 native MUST 继续在固定两行活动区显示按选择规则确定的动作状态及可确定字段，不因字符串操作失败中断显示；clean 不增加活动区，detailed 保持原有显示。
- **AND** 原工具仍按既有 schema 接受或拒绝实际参数，显示层不修正业务输入或推断成功。

#### Scenario: 部分参数逐步变为完整参数

- **WHEN** 同次调用从空参数、部分 JSON 或缺少意图／标题逐步更新到完整参数
- **THEN** compact MUST 使用当时可用的合法字段更新同一条动作记录的详情，并保持调用身份与实际派发事实；合法字段到达后不留下异常占位或空白动作行。
- **AND** 尚在生成参数的调用不作为进行中动作显示动画，不占用动作记录槽位；参数更新不得抢占已派发调用的动作记录，不得显示为已执行或当作 Output；无已派发调用时沿用保留内容规则。
- **AND** clean 保持原有隐藏，detailed 保留原组件，显示层不改变原始参数或工具校验。

#### Scenario: 设备包装摘要与直接调用保持同样稳定

- **WHEN** 同一未完成或错误类型的显示字段通过 `write xd://eval` 等已有设备运输到达
- **THEN** compact 的固定两行活动区 MUST 与直接调用遵守相同安全显示、动作记录身份及每动作一行的边界，不因外层包装绕过显示字段类型约束，不吞掉原派发或工具校验错误。
- **AND** clean 与 detailed 保持原有行为；compact 仅在内层可确定为文件型 write／edit 时保留其历史原组件，其他设备调用只可按最近有输出的调用规则进入只读预览，不恢复普通聊天历史卡片。

#### Scenario: 样式与宽字符不破坏单行边界

- **WHEN** 合法活动意图、原始命令或已有目标含换行、Tab、ANSI 样式、中文或其他宽字符
- **THEN** MUST 使用既有清理、排版与测宽行为，将每条动作详情限定在其所属的一行；展示时将多行信息整理为单行并按扣除左边距后的实际宽度截断，不让较长动作占用另一条记录的行。
- **AND** 保留可识别的动作状态词及已有详情，不整体取尾而丢掉动作区；控制字符与宽字符不得造成溢出或新增动作行，原始参数与输出不被改写。
- **AND** 思考详情按单行动作记录处理，不再按宽度折成两行原文；摘要单行限制不约束历史原卡片内容，只读输出预览另按一行信息和五行 Output 处理，不改写意图或原始命令本身。clean 不增加活动区，detailed 保持原有组件。

### Requirement: 固定两行活动区

compact MUST 在输入区上方提供固定两行内容的活动区，其下固定保留一行空白。每行 MUST 按“动作状态 + 两个半角空格 + 灰色详情”布局：动作区固定四个中文字符的显示宽度，用既有终端列宽工具计算，不用字符串长度；详情起点固定，状态切换不使其左右移动；每项动作只占一行，详情中的换行与制表符折叠为空格，超长安全裁剪，不挤出第三行。动作记录按“运行中优先、其次最近结束”选择，串行首项放下行；思考作为单条动作记录并单独计时。无当前活动时沿用所属会话保留内容规则，不添加历史活动标签。它不进入聊天历史，也不改变工具执行。

#### Scenario: 两行内容和固定位置

- **WHEN** compact 生效且终端空间可容纳正常输入区
- **THEN** 活动区 MUST 相对输入框固定，保留两行可用内容，并在其下方、输入框／状态栏上方保留一行完全空白，正常空间下合计占三行；不足两项时留空补足，串行场景只有一项时放在下行、上行留空。
- **AND** 每行 MUST 以固定 8 显示列的动作区起始，其后两个半角空格，再为灰色详情；动作由进行中变为完成或失败时详情起点 MUST 保持不变。动作区宽度用既有列宽工具按显示宽度计算，中文宽字符与样式控制序列不得造成错位。
- **AND** 活动区 MUST 与聊天正文使用相同的左内边距，普通布局为一列，并沿用共享紧凑布局的边距规则；排版与截断先扣除该边距，不通过缩进造成溢出。ANSI 与 native 的起始列一致，快照不保存或叠加布局缩进，空内容和下方留白仍为空行。
- **AND** 两行内容与下方一行留白在活动、保留与无内容之间切换时保持相同占用，不因活动状态使输入框上下跳动；极小终端仍遵循既有输入光标和交互可达性规则，空间不足时可压缩留白，不以留白挤掉有效输入。
- **AND** clean 与 detailed 不增加该区域，输入框、附件及扩展组件的相对布局沿用既有机制。

#### Scenario: 动作类别与状态文案

- **WHEN** 思考、读取文件、Bash／Shell 命令、write／edit／补丁等文件修改工具或其他工具的动作被选入活动区
- **THEN** 动作词 MUST 按类别映射：思考为“正在思考／思考完成”，读取为“正在读取／读取完成”，执行为“正在执行／执行完成”，文件修改为“正在写入／写入完成”，其余工具统一回退“正在调用／调用完成”；每词均为四个中文字符宽度。
- **AND** 失败时动作词 MUST 使用对应“思考失败／读取失败／执行失败／写入失败／调用失败”；结果状态沿用现有生命周期事实，`tool_execution_end` 的 `isError` 为真即失败，MUST NOT 仅因调用结束显示成功，也不得通过输出文字或新增退出码规则重新判定结果。
- **AND** 现有事件不携带取消标志时，取消 MUST NOT 被单独判定：按已有结果态显示对应完成或失败词；底层无法区分的状态使用通用文案，不伪造取消事实。
- **AND** 失败或取消时详情优先包含操作对象与已有简短原因；空间不足时压缩对象、保留可读原因；没有原因就只显示对象，不生成猜测性解释；完整工具输出和错误信息仍按现有方式展示。
- **AND** 未单独映射的工具详情 MUST 显示真实工具名称及已有简短参数摘要，不得为空，也不得误标成文件读取或命令执行；设备包装调用沿用既有内层身份与目标投影。

#### Scenario: 等待确认沿用进行中显示

- **WHEN** 现有流程中某调用已派发并进入等待用户确认阶段，而事件层面无法区分审批等待与真实执行
- **THEN** 活动区 MUST 保持该动作的进行中显示，不新增“等待确认”状态判定，不新增确认流程；已有确认交互与审批控件原样保留。
- **AND** 不为区分审批等待修改底层事件、扩展包装或审批链；确认通过后的真实执行继续按进行中显示，结果到达后按真实结果态更新。

#### Scenario: 思考记录与阶段耗时

- **WHEN** 当前查看会话存在按现有思考显隐设置可显示的真实思考阶段
- **THEN** 思考 MUST 作为单条动作记录显示：进行中为“正在思考”，详情为当前思考片段最新的非空一行，超长在尾部省略，尚无内容时详情为空；MUST 使用已有真实可显示思考内容，不额外调用模型生成摘要，不编造思考内容。
- **AND** 思考成功结束时 MUST 原位切换为“思考完成”，详情替换为“用时 xx 秒”，不继续保留旧思考文字；统一保留一位小数，例如“用时 5.0 秒”“用时 12.3 秒”，不足 0.1 秒显示“用时 <0.1 秒”，超过一分钟仍保持秒为单位。
- **AND** 每个独立思考阶段 MUST 单独计时，基于现有 `thinking_start`／`thinking_end` 等阶段起止事件或已有耗时数据；不计入工具执行、等待确认或整轮累计时间，不按动画帧数估算，不用整次模型请求耗时冒充思考阶段耗时。现有事件无法可靠划定阶段时不伪造精确时长。
- **AND** 思考阶段以错误结束时显示“思考失败”；中断且无独立失败事实时按通用“思考完成”兜底，不推断失败原因。本次只给思考完成态显示耗时，不额外增加工具耗时或实时计时器。

#### Scenario: 思考优先

- **WHEN** 当前查看会话存在按现有思考显隐设置可显示的活跃真实思考
- **THEN** 思考 MUST 作为一条进行中动作记录占据一个槽位，显示“正在思考”及最新思考片段详情；工具参数、输出或结果更新 MUST 不重复插入或重置该记录，思考结束或不再有可显示思考时按动作选择规则原位切换或回退。
- **AND** 思考不再独占两行原文；思考不在聊天流留下标题、正文、动画占位或可展开隐藏节点，不调用模型生成摘要，也不把普通助手正文当作思考。

#### Scenario: 思考空白行不清空活动内容

- **WHEN** 思考内容含中间空白行、末尾连续换行或仅含空格／制表符的行，或者流式更新只追加这些空白字符
- **THEN** 思考详情 MUST 取当前思考片段最新的非空一行；仅追加空白不得清空已显示的思考详情或以空内容覆盖已有非空详情。
- **AND** 整段思考没有可显示内容时详情为空，动作词仍按真实状态显示；过滤只影响活动区显示，不改写原始思考、会话记录或模型上下文。

#### Scenario: agent loop 内已显示活动不得自动变空

- **WHEN** 当前逻辑会话的 compact 活动区在 agent loop 中已经实际显示过动作内容，且用户未主动隐藏相关内容、切换显示档位或查看其他会话
- **THEN** 后续等待、单次思考结束、空消息、新模型流开始、工具切换或工具返回 MUST NOT 让活动区重新变为空白；只能由按选择规则选出的新非空动作内容替换，暂无新内容时继续显示最后实际显示的内容。
- **AND** 是否有新内容 MUST 在既有 ANSI／控制字符清理与空白过滤后判断；原始字符串非空但最终显示为空时，不得抢占已有动作记录或覆盖其非空快照。
- **AND** 动作结束时其动作词立即切换为真实结果态并停止动画；loop 未结束不使已结束动作恢复扫光，loop 结束且无可见进行中动作时全部文字为静态，不删除文字或清空快照。后续新 loop 的首个非空活动前仍保留该会话已有内容。

#### Scenario: 无思考时显示最近调用而非日志

- **WHEN** 当前查看逻辑会话没有可显示的活跃思考，且已有实际派发的工具调用
- **THEN** 活动区 MUST 按“运行中优先、其次最近结束”显示最多两条动作记录，包括已返回调用，每个动作一行；MUST NOT 为较新的已返回调用淘汰仍在运行的调用，不等待执行结果才显示。
- **AND** 参数生成、参数补全、进度与输出更新不能改变动作记录身份与派发事实；尚未派发的调用不抢占已派发调用的槽位，调用返回不使其重新排序或立刻消失。
- **AND** 新轮开始前可以保留已有动作行，跨轮不因返回状态另设筛选；不轮播并发调用，不展示累计工具清单或调用统计，不扩展统一后台任务跟踪，也不从未实际查看的已结束历史转录补造动作行。

#### Scenario: 派发顺序决定最近两次调用

- **WHEN** A、B 依次派发，之后 B 先返回而 A 仍未返回，随后又派发 C
- **THEN** A、B 均在运行时 MUST 保持各自槽位显示 A、B；B 返回后其原位变为结束态，A 的运行显示不受影响。
- **AND** C 派发且 A、C 均在运行时，两个运行项 MUST 占据两行，B 作为更早结束项退出；运行项优先级高于完成项原位保留，不为显示完成提示隐藏运行项。A 之后结束时在原位变为静态，C 保持运行。
- **AND** 派发事实决定记录身份与最近结束项的排序；迟到参数、进度、输出及终态更新不把已退出的调用重新选入，也不改变仍在运行项的位置。

#### Scenario: 并行动作的稳定槽位

- **WHEN** 现有系统支持并行且两个或更多动作同时运行
- **THEN** MUST 最多显示两个进行中的动作，已显示的运行项保持位置；空位优先补入最早开始、尚未展示且仍在运行的动作。
- **AND** 超过两个动作同时运行时不轮播；可见动作结束后立即用等待展示的运行项补位；没有待展示的运行项时，结束项在原位变为静态，并用剩余位置保留最近结束项。
- **AND** 只有一个运行项且已有位置时，不为了重新排序而移动它。只适配已有并行能力，不新增并行、不把现有并行改为串行。

#### Scenario: 串行连续动作的位置切换

- **WHEN** 动作 A 结束后动作 B 开始，或思考结束后读取开始
- **THEN** 第一个动作出现时 MUST 显示在下行、上行留空；当前动作结束时 MUST 在原位置切换为结束态；下一个动作开始时，最近结束的动作 MUST 放在上行，新动作放在下行。
- **AND** 更早的结束动作退出这两行区域，不改变原有历史记录；完成态不额外新增第三行。例如思考结束、读取开始时上行为“思考完成  用时 5.0 秒”，下行为“正在读取  <路径>”；读取结束后下行原位变为“读取完成  <路径>”；执行开始时上行为“读取完成  <路径>”，下行为“正在执行  <命令>”。

#### Scenario: 单个工具的一行显示意图及原始命令预览

- **WHEN** 工具调用被选入两行活动区
- **THEN** 该调用 MUST 在同一行的详情中显示实际命令及参数，保留原有参数顺序；多行命令折叠为单行，超长时尾部省略；无命令时回退已有意图、路径、目标、查询等可确定信息，不伪造描述。
- **AND** 成功结束后保留同一份命令／对象摘要，不把 stdout／stderr 塞进这两行，也不把参数 JSON 原样铺满状态区；可确定状态只附在该动作自身的一行，不另占标题或反馈行，不展示工具输出尾窗或执行结果正文。
- **AND** 读取与写入详情 MUST 显示实际目标文件路径，优先使用已有仓库相对路径；长路径从中间省略，尽量保留文件名与必要目录；多个文件时复用现有真实工具摘要，不为展示另造复杂解析器。

#### Scenario: 工具专属参数与设备包装的活动摘要

- **WHEN** 工具缺少短意图，或经 `write xd://<tool>` 的既有设备路由调用
- **THEN** 活动区详情 MUST 从已知工具参数回退可确定的操作及目标：AST 模式与路径、OpenWiki 页面／章节／空间、LSP／Debug／IDA 的操作目标、raw edit／apply_patch 的文件、task 的单项／批量派发、todo／goal 的操作目标、GitHub／安全扫描／记忆修改／Skill 管理的操作标识、ask 的问题、context_notes 的读取／写入／清空、实验名及简短实验描述，以及 yield 的合法提交条目标识；批量参数使用已有代表项和数量，不展开完整正文。
- **AND** Eval 的已有 `code`（含独立百分号命令）作为原始代码预览；多行代码仍按单动作一行整理和截断，不执行、重写或以结果正文替代代码。
- **AND** 设备调用 MUST 保留真实外层工具身份于详情，并对既有路由支持的 hashline 包装、大小写及部分参数采用同样的摘要规则；可确定的内层意图、命令和目标优先于运输 URI，内层 Bash 沿用命令详情规则，内层 wait 沿用已有结构化任务摘要；活动区不显示“提交”“等待”计时；文档请求不得冒充工具执行。
- **AND** 显式短意图继续可用作详情回退，缺失或错误类型字段不导致渲染失败；不从 think 的私有思考、yield 的提交正文、文档／记忆正文或工具输出补造意图、目标及成功，不为显示保留完整工具参数副本或新增任务跟踪。

#### Scenario: wait 关联已有后台任务

- **WHEN** wait 的已有进度快照包含结构化任务信息，或从所属会话已有活动更新恢复正在等待的调用
- **THEN** MUST 在 wait 自身一行的详情中显示所等待任务的身份与命令／标签；没有任务信息时保留原有意图，不猜测所等待的命令。
- **AND** 复用现有等待任务摘要及活动更新，不新增后台跟踪、轮询、订阅或计时，不显示等待耗时，不改变动作选择规则，不展示任务输出正文。

#### Scenario: 工具行末显示实际执行耗时

- **WHEN** 某次工具调用在两行活动区中显示
- **THEN** 活动区 MUST NOT 显示工具执行耗时、实时计时器、“提交”或“等待”计时前缀；本场景取代旧的工具行耗时契约，耗时仅保留思考完成态的“用时 xx 秒”。
- **AND** 工具的真实执行计时事实仍按原有机制存在于会话与完整结果展示中，显示层不删除、不改写；后台任务 ID 等既有结构化信息仍可在只读输出预览的信息行按原规则呈现，不进入动作行。
- **AND** 不为移除耗时改变工具执行生命周期、会话快照持久化边界或动作选择规则。

#### Scenario: 最近两次调用各占一行

- **WHEN** 存在两次或更多动作记录且无更多运行项需要占位
- **THEN** MUST 最多显示两条动作记录，每条独立呈现该动作的状态词与详情，不受它是否已经返回影响；串行场景按“最近结束在上、当前进行在下”排列，只有一条记录时放下行。
- **AND** 两次同名工具调用仍是不同动作，各自显示详情；不按工具名或显示文字去重，不混入其他动作的意图，不将任何一行改为实时输出。

#### Scenario: 长意图或命令不占用另一工具行

- **WHEN** 被选中的动作详情包含长文本、多行、宽字符或样式
- **THEN** MUST 按既有安全清理、测宽及截断规则将其限制在该动作的一行内，保留动作状态词；不得换行挤掉另一条记录，不用整块最新两行截尾替代逐动作布局。
- **AND** 详情指现有调用参数中的命令与目标，不是 stdout 或模型重写；显示层的单行整理和截断不得改写原始参数、工具结果或完整查看入口，也不得伪造运行、成功、失败或取消。

#### Scenario: 终端缩窄的安全裁剪

- **WHEN** 终端缩窄使两行内容超出可用列宽
- **THEN** MUST 优先压缩详情，极窄时连动作区也按可用列宽安全裁剪；裁剪 MUST 正确处理中文宽字符和样式控制序列，不泄漏颜色，不破坏两行布局。
- **AND** 详情起点在可容纳动作区时保持固定；长中文路径、长命令与多行内容均不得挤出第三行。

#### Scenario: 无内容、结束、取消与切换

- **WHEN** 当前没有可显示的进行中动作，包括当前轮结束或被取消后确实无当前活动
- **THEN** 已有实际显示内容时 MUST 保留所属会话最后实际显示的动作记录，动作词按真实结果态静态显示；MUST NOT 添加“上次活动”及其分隔符、其他历史标识或替代标题。
- **AND** 已返回调用仍可在最近结束位置保留，但不得冒充当前运行活动或重启动画；保留文字不追加到聊天历史，不从终态输出、历史转录或未实际显示的更新补造记录。
- **AND** 没有任何实际显示内容时保持两行空内容，不生成虚构活动；保留思考仍受现有思考显隐设置约束，隐藏后不通过快照回显。

#### Scenario: 取消本轮不等于工具已取消

- **WHEN** 用户取消当前轮、会话进入取消过程或收到轮次取消事件，但尚无某工具已取消或已返回的实际信息
- **THEN** MUST 不仅凭轮次取消把该工具标为已取消、成功或失败，也不改变真实执行或取消权限。
- **AND** 已有事实仍确认调用处于已派发未返回状态时继续按动作选择规则处理；无法确认当前活动时可转为保留内容，不添加历史标识，不得以冻结的进行中文字暗示该调用仍在实时运行。
- **AND** 之后已有调用返回或终态事实到达时只更新其所属会话的记录状态，不将本轮取消当作后台任务已停止。

#### Scenario: 新轮首个活动前保留上轮内容

- **WHEN** 同一逻辑会话开始新轮，但尚未出现新的可显示动作
- **THEN** MUST 允许继续显示该会话原有保留内容，不添加历史活动标签；新用户消息、普通助手正文或单纯轮次开始不将其误当成新活动，新动作到达后按选择规则更新。
- **AND** 保留内容的动画 MUST 已停止，动作词按真实结果态静态显示；新轮运行标记恢复本身不重启动画，只有新的可见进行中动作才触发动画。
- **AND** 新的可显示活动出现后覆盖保留内容；不为保留或覆盖发送请求、重跑调用、重新消费消息或重启任务时钟。

#### Scenario: 按逻辑会话保留一份内存快照

- **WHEN** 用户离开当前查看会话、查看其他会话，之后切回先前实际查看过的逻辑会话
- **THEN** OMP MUST 对每个实际查看过且有已显示内容的逻辑会话最多保留一份内存快照，可包含两条动作记录；切回且没有可确认的当前活动时，可以显示该会话自身最后实际显示的保留内容，不添加历史活动标签，也不得显示其他会话的内容。
- **AND** 同一逻辑会话的对象或界面组件重建不得生成多份快照或改变归属；从未实际显示过内容的会话不得从已结束轮次转录中回放内容以填充快照。
- **AND** 新查看会话确有可确认的当前活动时，优先按本规格显示其自身当前活动；原会话的迟到事件不得污染新会话的显示或快照。
- **AND** 不为保留快照新增未查看会话的持续跟踪，不增加持久化、跨进程共享或重启恢复；进程重启后不得以旧快照恢复活动区，已有真实当前活动仍按原事实显示。

#### Scenario: 两行活动区运行态与状态栏运行标记一致

- **WHEN** compact 的固定两行活动区显示进行中动作词、结束态动作词或保留内容
- **THEN** 底部状态栏运行标记自身的品牌旋转、计时与活动窗口 MUST 保持不变；活动区动画不再由整轮运行标记驱动，而仅由可见进行中动作驱动：有可见进行中动作词时播放扫光，全部可见动作结束、状态区关闭或退出 compact 时停止刷新并清理资源，即使整轮标记仍在运行也不保留已结束动作的动画。
- **AND** 只有进行中动作词 MUST 播放轻微扫光：亮色缓慢从左向右经过动作词，文字始终完整可读，位置和宽度不变；所有进行中动作采用同一种动画与节奏，复用现有 shimmer 样式、调色板与共享刷新机制；不修改中心扫光助手，周期沿用现有恒速。MUST NOT 新增独立旋转符、进度条、跳动字符或增减省略号。
- **AND** 灰色详情始终无动画，可随真实内容更新，但不参与扫光、闪烁或打字动画；进行中动作词使用主题前景色／强调色的轻微亮度变化；成功使用正常静态文字；失败只突出前面的动作词，优先用现有错误色；详情统一使用可读的主题灰色，不写死过暗颜色。
- **AND** 动作一结束 MUST 立即停止该动作的动画并更新状态词；快速动作不得为展示动画延迟真实结束状态。MUST 遵守现有禁用颜色、禁用动画和非交互输出规则；禁用动效后仍能仅凭状态文字识别状态，不新增配置体系。
- **AND** 动画只触发状态区必要的重绘，复用现有 TUI 机制，不把每帧追加成新日志，不改变输入框或滚动位置。ANSI 与 native MUST 使用相同动作词与配色语义；native 扫光由终端自身计时，周期不受本规格控制，MUST 在验证中单独标注。clean、detailed、聊天流中的文件型 write／edit 原组件及其他忙碌提示保持不变。

#### Scenario: 异步等待及回执不另设配色生命周期

- **WHEN** 当前查看会话派发异步任务、等待其结果、接收进度或完成回执，或切换到异步子代理会话
- **THEN** 已返回调用的动作词 MUST 保持静态结果态，后台任务仍在运行、进度或回执到达均不重启动画、不新建动作记录、不把已返回调用重新标为进行中。
- **AND** 异步回执仅更新任务信息时不产生新的可见进行中动作；新的真实派发或思考阶段才按选择规则进入活动区并触发动画。不为动画主动启动 loop，也不根据回执到达、入队或结果待处理状态独立推断运行态。
- **AND** 切换主会话与子代理会话时沿用既有会话归属与清理／恢复；迟到回执不改变其他会话的活动区显示。本场景不改变派发、投递、唤醒、取消、后台回执显隐、底部状态栏或动作内容选择，不新增后台跟踪、订阅或轮询。

#### Scenario: 增量更新不产生重复记录

- **WHEN** 同一动作连续收到思考片段、参数流、进度或输出更新
- **THEN** MUST 更新同一条动作记录的详情，不产生重复记录，不重置思考计时，不重启动画周期。
- **AND** 两次相同命令或同一路径的独立调用仍是两条动作记录，不按显示文字合并；整轮结束、清空会话和新轮开始时沿用现有 compact 状态区的清理时机，不得留下失效的进行中动画。

### Requirement: 紧凑模式按文件目标保留 write／edit 原展示

compact MUST 仅按 write／edit 的操作目标与既有路由识别文件操作；一旦已有参数足以确定其为文件写入或编辑，MUST 沿用上游 detailed 的原组件和完整历史显示行为，保持相同内容、消息顺序、状态反馈、交互、截断、展开／折叠、滚动及归档语义。是否真实修改文件、是否有 diff、是否成功及结果快照字段 MUST NOT 成为额外显示门槛；只读输出预览的来源选择、六行预算与自动关闭不得限制这些历史组件。

#### Scenario: 文件目标的所有生命周期状态均沿用原展示

- **WHEN** 已可确定文件目标的 write／edit 正在生成参数、执行、成功返回、未改变内容、失败、取消或仅部分操作完成
- **THEN** compact MUST 与同一状态下的上游 detailed 使用相同历史原组件和反馈，不等文件改动证明或最终结果到达后才允许显示，不因没有 diff、结果字段缺失或调用失败隐藏原组件。
- **AND** 原组件有 diff 时按原样展示；没有 diff 时保留上游原有状态或内容，不补造 diff、成功或取消事实；不强制展开、不重画为两行摘要、不另做错误分类或历史组件专属高度预算。

#### Scenario: 目标未明确到明确的参数流

- **WHEN** write／edit 的路径、补丁或设备内层参数尚不足以确定文件目标，之后已有参数明确为文件操作
- **THEN** 未明确前历史组件可保持隐藏，明确后 MUST 显示同一调用的上游原组件；不能因先前隐藏就将可能的文件调用提前退休、归档为空或永久漏显。
- **AND** 目标判断复用既有路径、协议与工具路由，不额外探测文件是否存在、读取前后内容、验证改动或建立文件系统监控；新建文件与已存在文件采用相同规则。

#### Scenario: 多次调用与跨轮历史

- **WHEN** 一轮或多轮出现四次及更多文件型 write／edit 操作，或当前轮结束、下一轮开始
- **THEN** compact 中历史原组件集合、顺序和保留 MUST 与上游 detailed 一致，不只保留最近两次或最后三次，也不因轮次切换清空或隐藏这些原组件。
- **AND** 固定两行活动区仍按自己的动作选择规则显示；动作记录淘汰、静态保留、只读 Output 来源切换及自动关闭均不得移除聊天流中的文件型 write／edit 原组件。

#### Scenario: 文件路由与设备包装

- **WHEN** write／edit 通过磁盘路径、文件型 URL、既有文件协议、远程文件或文件冲突解决路由操作文件，或由设备包装派发同一文件操作
- **THEN** compact MUST 依据既有路由声明与可确定的目标识别文件操作；设备包装按内层工具及目标识别，不只看外层 write 名称，也不要求结果携带文件改动证明。
- **AND** 已识别的文件操作沿用上游原组件与原路由，包括无变化及失败；clean 与 detailed 的路由、工具身份、权限、执行和原始结果不变。

#### Scenario: 非文件目标不恢复工具卡片

- **WHEN** write 用于消息、配置、进程控制、设备帮助或派发非文件工具，或非文件结果恰好包含 diff、文件路径或 `fileChanged` 等字段
- **THEN** compact MUST 继续隐藏其普通聊天历史卡片及错误卡片，不根据结果文本或字段将其伪装为文件操作；真实的工具 Output 仅可按只读预览规则显示。
- **AND** `out://` 等原有助手回复路由保持，正文不被搬入预览、不重复生成或因自动关闭而删除；只读预览不得从该调用的参数正文或已显示助手正文抽取内容补造 Output。
- **AND** bash、eval 等其他工具写盘不触发新的文件监控、前后快照或 diff 合成，不因此恢复历史卡片；不改变上游原工具能力或 detailed 的已有显示。
