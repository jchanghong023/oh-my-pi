# Spec Delta

## ADDED Requirements

### Requirement: 新 Dev 模块与普通 OMP 的隔离

Dev MUST 复用 OMP 原生会话、工具和生命周期，保持普通 OMP、原 WebGUI 和独立 OpenSpec／Superpowers 既有行为，不建立第二执行器、第二聊天库或旧流程兼容路径。

#### Scenario: 进入退出和资源归属
- **WHEN** 显式进入或退出 Dev
- **THEN** 沿用原生 TUI 独占和自有任务结清，关闭网页不退出真实服务，退出不撤销需求或 Git，不关闭其他实例；本轮只改文档和独立原型，不实现正式宿主或后端

### Requirement: 需求 Agent 与代码证据分析职责

Dev MUST 只提供业务需求、需求评审 A／B／C、综合评审、方案及需求进度分析角色，独立 Skill 设计属于设置能力。MUST NOT 提供开发计划、执行、IR 验收或归档 Agent，不编码、运行测试或修复代码。

#### Scenario: 四 Agent 评审
- **WHEN** 提交当前 IR／全部 SR 评审
- **THEN** 三个不同模型同轮同版独立并行只读评审，第四个 Agent 综合来源、依据和分歧；四份报告完整后由人工判断，不按投票、评分或标签自动通过／阻断
- **AND** 可切换原始会话追问，需求更新使旧报告和决定失效；原始报告重试后重新综合，保留历史，不用固定原型回复证明真实调用

### Requirement: 完整输入和版本证据

Agent MUST 读取完整 IR、全部 SR、当前方案及必要代码上下文，评审、文档确认和人工判断绑定实际文件集合与版本，不用摘要或不同轮次材料替代。

#### Scenario: 当前材料变化
- **WHEN** 需求或方案版本变化
- **THEN** 旧报告及确认不能用于新版本；保留历史、来源和错误，材料缺失或不可读时不放行依赖该材料的批准，重复或过期请求不得推进

### Requirement: 正式需求与平台外开发边界

Dev MUST 仅展示正式需求大表格、同页代码证据报告与只读材料，不挂载开发聊天、阶段动作或执行入口。平台外开发使用开发者自己的工具，不要求个人 OMP Web 或个人 Git 目录。

#### Scenario: 不建立冻结和实施流水线
- **WHEN** 平台外开发者修改仓库需求、方案或代码
- **THEN** 以实际内容和版本为准，旧证据不能证明新版本；不因首个 SR 开始冻结 IR，不为代码／测试／规格 PR、IR 验收或归档建立 Dev 流水线；普通 OMP 和独立同步／归档能力保持原规则

### Requirement: 仓库身份与需求分支关联

项目 MUST 只配置名称、Git 远程仓库及默认分支，平台按需托管内部工作副本。同仓库 clone／worktree 关联同一项目身份，不建立单 IR 锁、SR 名额、开发 worktree 或固定开发会话。

#### Scenario: 提案推送及自动转正
- **WHEN** 当前 IR、全部 SR、方案完整且人工逐文件确认
- **THEN** 平台才从最新默认分支创建提案分支并提交推送文档，提供 PR 内容，人工在 Git 网页创建、评审、合并；不自动创建／合并 PR，不依赖 PR API
- **AND** 后台仅按已合入默认分支且全部文档完整两个条件自动转正并创建推送各 SR 分支，记录基点；不需人工通知或再次批准，失败保留实际步骤并重试，不重复转正或建分支，不归档或提前同步未实现规格

### Requirement: 真实工作结清与可恢复操作

操作 MUST 防重并核对权限、轮次、文件和版本。返回、停止或退出前结清目标自有原生工作，不影响其他提案或实例。

#### Scenario: 失败与连接恢复
- **WHEN** 状态保存、提交推送部分失败，或页面刷新／断线
- **THEN** 保留成功步骤、提交及输入，明确错误，重试不重复提交或推进；页面不拥有真实后台生命周期，重连只读实际状态，不重放消息或人工决定，不假定共享路径可以迁移会话
- **AND** 原型关页停止内存演示，不作为真实后台持久或恢复证据

### Requirement: 唯一共享数据库和业务边界

各 Web MUST 经固定 18321 的 `omp dev_db` 服务访问 /tmpdata/DFT_LAB/omp/omp_dev_sqlite.db，不各自打开 NFS SQLite。`omp dev_web --port <端口>` 可选端口，省略自动选择并输出实际地址。上述真实命令及服务不在本轮实现。

#### Scenario: 文档、依赖、元数据及个人配置分离
- **WHEN** 保存需求数据
- **THEN** 正文、验收标准、方案和稳定 SR 依赖入 Git；项目、Release、提案状态、人员、建议／人工排期、调整记录、进度分析和必要会话引用入共享数据库；不登记开发占用或个人目录
- **AND** Token、个人模型／提示词／技能及聊天正文归所属 OMP，不入业务库或 Git；人员排期不改文档版本，不创建 PR，冲突只提醒，不构成开发锁或转正门槛

### Requirement: 代码证据完成条件而非验收归档流水线

Dev MUST 基于需求、验收标准及代码证据分析实现百分比、遗漏、问题、不确定项、活动、分析时间、版本、分支和默认分支合入依据，不编码或修复代码，不把百分比当置信度。

#### Scenario: SR 和 IR 完成
- **WHEN** 后台分析或管理员／IR 负责人调整 SR 进度
- **THEN** 未合入默认分支最高 99%，AI 与人工均不能标记完成；已合入且 AI 确认全部条件满足可自动 100%，AI 不确定时允许人工凭证据调整并记录工号、时间、依据，保留原问题
- **AND** IR 为全部 SR 算术平均，无 SR 为 0%，未实际 100% 不舍入为完成；全部 SR 完成才完成 IR，不需最终验收／归档 PR，不占用或释放仓库名额
