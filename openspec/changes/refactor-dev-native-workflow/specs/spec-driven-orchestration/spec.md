# Spec Delta

## ADDED Requirements

### Requirement: 新 Dev 模块与普通 OMP 的隔离

本次 Dev MUST 一次性替换旧 Dev 流程并复用 OMP 原生能力。普通 OMP、TUI、独立 OpenSpec、Superpowers、JCH、原生工具及既有用户配置 MUST 不因新工作台改变默认行为；未启用功能时不启动额外工作。

#### Scenario: 独立能力照常使用
- **WHEN** 用户未启用 Dev 或使用独立需求命令
- **THEN** 保留包内固定版本、schema、技能发现和原生校验；不强制进入工作台，不添加阶段批准或后台证据任务。

#### Scenario: 旧流程退役
- **WHEN** 用户目录含旧 Dev 状态或使用旧子操作
- **THEN** 不保留旧八阶段兼容入口、双轨、自动迁移或旧状态恢复；保留原用户材料、代码和 Git 历史。

#### Scenario: TUI 进入退出
- **WHEN** 用户通过 /dev 显式进入或退出
- **THEN** 普通工作未结清则拒绝进入；进入后沿用独占输入门禁，再次 /dev 结清自有工作才恢复普通会话；退出不回滚 Git、不删除资料。

### Requirement: 原生需求与四阶段执行职责

需求整理 MUST 由现有需求相关 Agent 资源完成 IR 和全部 SR；SR 开发复用方案、计划和执行能力。所有对话正文 MUST 归 OMP 管理，Dev 只保留必要聊天 ID、阶段及执行轮次关联。

#### Scenario: 业务 review 可派发
- **WHEN** 整组格式检查通过
- **THEN** 主需求 Agent 能派独立 reviewer 读取固定快照并输出审查记录；不是给每个 SR 再启动独立需求撰写阶段。

#### Scenario: 技术材料职责
- **WHEN** 方案或计划 Agent 开始工作
- **THEN** 方案只提供一个当前推荐方案及理由取舍；计划明确步骤、修改范围和验证安排；二者不提前写业务代码或代替人批准。

#### Scenario: 原生能力继续可用
- **WHEN** 执行 Agent 及获授权实施后代工作
- **THEN** 保留必要原生工具、技能、任务、wait、LSP、MCP及扩展能力，继续适用项目规则和写入边界；不新增 Dev Team 配置或多候选方案管理产品。

#### Scenario: 不复制聊天
- **WHEN** 展示或恢复需求及阶段会话
- **THEN** 由 OMP 原生历史读取；Dev 不维护第二套聊天正文库，不把会话 ID 等同用户身份。

### Requirement: 完整输入和确认版本交接

每次阶段交接 MUST 使用已确认输入的完整文件、真实版本和人员决定，不以摘要替代 IR 或 SR。技术方案必须获得当前 SR、所属 IR、相关背景和当前项目已有需求、代码、接口、测试及约束。

#### Scenario: SR 输入完整
- **WHEN** 人员启动技术方案
- **THEN** 传入冻结的当前 SR 和完整 IR、确认及 review 记录、必要资料；相关 SR 只作为上下文，不启动依赖调度。

#### Scenario: 存在递归规格
- **WHEN** 项目使用嵌套 OpenSpec 或既有 Markdown 权威
- **THEN** 完整枚举全部相关规格和原文，不只读顶层，不复制竞争性需求权威；使用 OpenSpec 时保留包内 omp-spec 来源和原生校验。

#### Scenario: 上游实际修改
- **WHEN** 技术材料内容或文件集合发生变化
- **THEN** 原确认及下游输入资格按实际变化失效；审核或批准不能被应用到不同内容、不同阶段或不同轮次。

### Requirement: 冻结需求在工具与集合层强制执行

冻结 MUST 保护整组 IR/SR 的标题、正文和成员关系，覆盖主 Agent、子代理及可写工具；不能只在执行前检查一次哈希，或仅靠 UI 和提示词约束。开发材料仍按当前阶段权限更新。

#### Scenario: 开发工具试图修改需求
- **WHEN** 原生 write/edit、命令、扩展或子代理触及冻结需求
- **THEN** 阻止改变权威冻结内容，或将不符合冻结快照的结果拒绝进入正式状态与提交；披露具体变化，不更新批准依据。

#### Scenario: 新增或遗漏成员
- **WHEN** 冻结后发现新增 SR、删除文件或拆分清单不一致
- **THEN** 判定违反冻结集合，阻止相应开发转换和正式发布，不把单文件哈希仍匹配当成整组有效。

#### Scenario: 开发产物允许变化
- **WHEN** 实现、验证或返工调整方案计划和代码
- **THEN** 只影响对应技术材料及后续资格，不解冻业务需求，也不改变其他 SR 的冻结内容。

### Requirement: 项目、IR、SR、worktree 与会话绑定

宿主 MUST 为所有操作、事件和原生会话保存正确的项目、IR、SR、阶段及执行轮次关联；同一仓库的工作树由统一项目协调，不把每个 checkout 当成互不知情的项目。

#### Scenario: 同项目多个 worktree
- **WHEN** 需求整理或 SR 开发建立独立目录
- **THEN** 明确对应源仓库、分支和起始提交；阶段持续复用该 SR worktree，不能把其 Git index 当作其他 worktree 的 index。

#### Scenario: 切换与迟到事件
- **WHEN** 浏览器切换项目或原执行结果迟到
- **THEN** 事件只更新原所属对象，不串入当前会话，不因查看位置变化重绑运行任务或附件。

#### Scenario: 同 SR 不多人同时开发
- **WHEN** 多个页面对同一 SR 发出冲突操作
- **THEN** 串行校验状态与材料版本；第一版不支持多人同时开发同 SR，也不处理多人跨 clone 修改 IR/SR。

#### Scenario: 历史关联异常
- **WHEN** OMP 历史缺失、会话 ID 不匹配或 worktree 不存在
- **THEN** 保留有效材料和状态，明确不可用原因，不猜测另一会话、不自动重放输入或伪造历史。

### Requirement: 真实工作结清与可恢复操作

流程操作 MUST 具有防重和版本校验，并分别保存文件、Git、人员决定及原生任务的实际结果。停止和返回必须等待所属主 Agent、递归子任务、工具、队列和 Goal 真实结清。

#### Scenario: 重复点击和过期批准
- **WHEN** 同一操作被重复提交或批准范围已经改变
- **THEN** 不重复创建工作树、提交、消息或阶段批准；过期请求明确拒绝，不把同一次点击转成下一阶段确认。

#### Scenario: 保存提交推送部分失败
- **WHEN** 必要状态写入、Git commit 或 push 中途失败
- **THEN** 如实保留已完成步骤和失败位置，不伪报全部成功，不无条件重做已经完成操作，不强制覆盖代码。

#### Scenario: 浏览器关闭
- **WHEN** 页面关闭、刷新或断线
- **THEN** 不停止已接受工作，不释放开发名额；重连只读取和订阅实际事实，不自动发送消息或恢复旧执行。

#### Scenario: 完成报告产生
- **WHEN** Agent 交付当前完成与验证报告
- **THEN** 停止自主可写推进并等待人员明确动作；普通询问修复影响不构成继续实施授权。

### Requirement: NFS 共享数据和顺序换机

配置、仓库、worktree 和工作流 JSON 可位于 NFS。第一版 MUST 只支持顺序换机器，同一 OMP 配置/profile 不同时在多台机器运行；换机前必须停止并退出旧机器使用该 profile 的全部 OMP 进程。

#### Scenario: 正常换机
- **WHEN** 旧机器任务和配置写入已经结清并退出
- **THEN** 新机器可读取同一份材料、工作流状态和 OMP 历史；原机器的进程、端口和 Agent 执行不会因共享目录自动迁移。

#### Scenario: 原宿主状态未知
- **WHEN** 无法确认旧机器已经退出或存在未结清操作
- **THEN** 不自动抢占、不按过期时间假定安全，不把另一机器 PID 当本机 PID 杀进程；明确等待人工处理。

#### Scenario: 不能复用本机锁当跨机证明
- **WHEN** 不同 Linux 主机访问相同 NFS 路径
- **THEN** 不能以现有本机 abstract socket 锁证明全局互斥；按顺序交接和共享状态约束工作，不引入分布式调度或自动接管。

#### Scenario: 现有 SQLite 的范围
- **WHEN** 评估 NFS 存储可用性
- **THEN** Dev 不新建 SQLite/WAL；OMP 现有数据库不因提案顺带改造，NFS 实际兼容性需单独验证，不能把源码检查当实机通过。

### Requirement: 四阶段交付结束与收尾边界

代码 PR 合入默认分支并由人员明确确认后，SR MUST 结束 Dev 流程，保留正式资料与必要记录并提醒清理。第一版不在 Dev 管理合入后测试、复测、关联修复或自动撤销。

#### Scenario: 结束不等于清理
- **WHEN** 本 SR 达到交付终点
- **THEN** 提示可清理工作目录，由用户明确决定；不自动删除分支、脏文件、OMP 历史或其他工作树。

#### Scenario: 普通修复和技术返工
- **WHEN** 代码 PR 合入前人员明确授权范围内修正
- **THEN** 继续本 SR，保留代码并使旧报告失效；若改方案或计划先停止执行返回并重新确认，不能改冻结业务要求。

#### Scenario: 不强制旧收尾流水
- **WHEN** 完成开发验证或进入交付
- **THEN** 不再以第七阶段同步归档、撤销全部资料或新建关联需求作为固定前置；独立 OpenSpec 同步归档仍按原生显式操作和校验执行。
