# Spec Delta

## Purpose

让终端用户显式选择循环提交、无人值守目标或特定工作方式，在维持会话控制权、用量限制及权限隔离的前提下推进任务。

## ADDED Requirements

### Requirement: 循环提交指令

`/loopn` MUST 接受一条或多条指令；含空白的指令用引号括起。每轮和该轮后台工作全部结束后才提交下一条，最后一条完成后从第一条继续。

#### Scenario: 等待后台工作并停止循环
- **WHEN** 当前轮已有回复但仍有后台工作，或用户按 `Esc`、再次调用 `/loopn`，或本轮报错
- **THEN** 后台工作未结束不发下一条；运行中显示当前序号，收到停止条件后不再自动提交。

### Requirement: 无人值守目标的生命周期

`/goal-autopilot` MUST 在终端创建当前分支的无人值守目标并让 AI 规划、执行和核验交付。用户可查看、替换、暂停、恢复、删除目标，并可设置用量上限。

#### Scenario: 未完成或用量耗尽
- **WHEN** 交付仍有未解决阻塞，或用量达到上限
- **THEN** 报告阻塞并保留目标，或因耗尽暂停推进；不把未核验的交付标为完成。

#### Scenario: 补充输入和压缩
- **WHEN** 用户在工具批次执行期间提交补充消息，或对话被压缩
- **THEN** 补充消息在当前完整工具批次结束后送达；压缩后仍沿原目标继续。

### Requirement: 无人值守审批和表单接口

仅当本次无人值守授权适用时，系统 MUST 按该授权处理本地审批；明确拒绝和需独立审批的操作不继承授权。旧请求、目标或其他会话不得获得该授权。

#### Scenario: 命中本地审批或独立审批
- **WHEN** 当前已授权的请求派生一项适用的本地审批，或操作被明确拒绝、需要独立审批
- **THEN** 仅前者按本次授权处理；后者保留原拒绝或独立审批边界。

#### Scenario: 原授权失效
- **WHEN** 用户暂停无人值守目标、替换目标或切换会话
- **THEN** 原授权立即失效；之前的请求不能再凭原授权通过本地审批。

#### Scenario: 表单空闲超时
- **WHEN** 有效无人值守请求的表单连续 60 秒无输入
- **THEN** 若存在符合提交条件的显式推荐，则采用推荐，不将其当作用户提交；否则让 AI 自行判断，不反复等待同一表单。

### Requirement: 显式调用工作方式

终端 MUST 提供 `/ultrathink`、`/orchestrate` 和 `/workflowz`，分别随任务提交深度思考、多步统筹和预设工作流程要求。`/orchestrate` 可在子代理可用时分派工作。

#### Scenario: 设置或所需工具不可用
- **WHEN** 用户使用上述命令但所需设置或工具不可用
- **THEN** 说明原因且不提交任务，不把命令静默降级为普通消息。
