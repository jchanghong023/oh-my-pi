# Spec Delta

## REMOVED Requirements

### Requirement: 独立能力与开发模式的边界

**Reason**: 本轮已确认的新 Dev 流程取代本条旧规则；继续保留会产生阶段、权限、资料归属或交付边界冲突。

**Migration**: 仅记录旧标题退役，不重复删除或迁移状态；当前 Dev 仅管理需求、方案、人员排期及代码证据进度，不编码、不设执行名额或验收归档流水线，普通 OMP 不受影响。

### Requirement: 四个固定 Agent 与真实文件门禁

**Reason**: 本轮已确认的新 Dev 流程取代本条旧规则；继续保留会产生阶段、权限、资料归属或交付边界冲突。

**Migration**: 需求评审改为三个不同模型独立只读评审及第四个综合评审，由人工判断；不恢复旧固定实施角色或门禁，不删除用户文件。

### Requirement: Dev 子代理的宿主约束

**Reason**: 本轮已确认的新 Dev 流程取代本条旧规则；继续保留会产生阶段、权限、资料归属或交付边界冲突。

**Migration**: Dev 仅在需求文档和只读分析权限内复用原生子代理，不建立执行或验收角色；普通 OMP 原生子代理保持原规则。

### Requirement: 方案来源须可从原生阶段历史确证

**Reason**: 本轮已确认的新 Dev 流程取代本条旧规则；继续保留会产生阶段、权限、资料归属或交付边界冲突。

**Migration**: 当前方案绑定完整 IR／SR 文件及版本，由方案 Agent 维护；不据本历史条款恢复旧流程或迁移会话。

### Requirement: 完整文件与用户原始确认交接

**Reason**: 本轮已确认的新 Dev 流程取代本条旧规则；继续保留会产生阶段、权限、资料归属或交付边界冲突。

**Migration**: 评审及确认绑定完整文件集合和当前版本，变化使旧决定失效；不恢复开发批准或冻结锁，不删除历史。

### Requirement: 已批准需求集合新增产物即视为变化

**Reason**: 本轮已确认的新 Dev 流程取代本条旧规则；继续保留会产生阶段、权限、资料归属或交付边界冲突。

**Migration**: 提案文件变化需重新评审及确认，不把旧意见用于新版本；不建立代码开发冻结集合，不迁移旧状态。

**Migration**: 开发及验证在平台外进行，Dev 只报告代码证据和问题，不编制完成报告或执行验收收尾流水线。

**Reason**: 本轮已确认的新 Dev 流程取代本条旧规则；继续保留会产生阶段、权限、资料归属或交付边界冲突。
