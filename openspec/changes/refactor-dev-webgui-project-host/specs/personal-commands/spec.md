# Spec Delta

## MODIFIED Requirements

### Requirement: 同进程 Web 后端与 WebGUI 项目占用

每个 OMP 进程 MUST 独立持有同进程 WebGUI 服务，同实例内多个项目会话共用本实例端口，不跨进程共享服务。Web 后端直接调用本进程原生能力，不经过内部 HTTP、不启动独立 SDK／Agent 进程或独立 Web worker；用户显式新建或继续历史时由本进程原生 SDK 创建或恢复独立原生会话。同一项目只能由一个 WebGUI 项目 owner 持有；项目 owner 与其名下多个原生会话的执行 owner 不得混淆，不能以项目占用禁止同一 owner 下的多会话并行。

#### Scenario: 跨目录入口与 profile 统一准入
- **WHEN** 用户通过会话内 `/webgui` 进入，或在独立 WebGUI 显式打开／创建项目并请求创建／继续执行会话
- **THEN** 按真实 Git 项目根或非 Git 真实目录确定项目身份，子目录、路径别名、会话 ID、配置根和 profile 不得绕过同一项目的 OS 级占用锁；先取得占用再建立业务宿主或发布入口
- **AND** 启动、运行及退出结清期间均持有占用；占用冲突必须拒绝，不能只靠前端按钮或同一 TUI 的标志判断，不靠超时强制释放仍存活的 owner；同一 WebGUI owner 下新增会话复用其项目准入，各会话仍独立执行与结清，不绕过其他进程的项目占用
- **AND** 当前 TUI 退出结清失败时不提前恢复普通终端

#### Scenario: 多项目单入口与选择隔离
- **WHEN** A、B 项目登记到同一 OMP 实例，不同桌面浏览器窗口选择项目
- **THEN** 使用本实例相同 HTTP 服务及端口，按项目 ID 直接路由到内存中的原生对象；每页独立选择，不修改后端全局“当前项目”，已离线项目不静默回落到其他项目，不发现其他 OMP 实例的项目
- **AND** WebGUI 的活动执行与控制只能针对已准入项目内的所属原生会话；全部可访问历史仍按授权只读展示，不因页面当前项目或项目尚未准入而静默隐藏，继续历史须另行取得真实目标项目准入
