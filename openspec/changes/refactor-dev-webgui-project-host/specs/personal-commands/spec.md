# Spec Delta

## MODIFIED Requirements

### Requirement: AIReq 浏览器工作台启动入口

OMP MUST 提供会话内 `/aireq` 和命令行 `omp aireq` 两个工作台启动入口，输出完整可复制地址；非 offline 自动打开浏览器，offline 由用户手动打开。两者 MUST 指向目标目录的同一新 AIReq 业务能力；会话内 `/aireq` 进入独占 AIReq，当前 TUI 此后仅接受再次 `/aireq` 结清退出，不恢复旧 AIReq 阶段输入或子操作，不因打开网页自动创建需求或调用模型。

#### Scenario: 从 OMP 会话打开
- **WHEN** 用户启动 OMP 后输入 `/aireq`
- **THEN** 普通模型、工具或任务未结清时拒绝进入并提示先停止或等待，普通 Loop 未退出时提示先退出；不自动终止普通任务或退出 Loop。准入成功才启动或复用目标目录的工作台服务，显示实际完整地址，仅非 offline 自动打开浏览器
- **AND** 进入后当前 TUI 拒绝所有普通命令和输入，仅接受再次 `/aireq` 退出；网页与普通 TUI 不同时操作，普通原会话保留但不继续操作。不显示旧 AIReq 三行固定状态区，也不自动启动需求、Team 或 Goal
- **AND** 普通 Collab 正在共享或处于 `join` 会话时拒绝进入，提示先自行停止共享或离开该会话，不自动停止共享或离开 Collab；成功进入后仍支持 AIReq 网页按既有 Collab 机制共享及 `join`

#### Scenario: 直接从命令行打开
- **WHEN** 用户在自己的目录运行 `omp aireq`，包括先手动 `git pull` 获取新流程记录后运行
- **THEN** 使用当前 OMP 的有效目录、profile、模型和运行环境启动工作台，输出完整地址，仅非 offline 自动打开浏览器，不要求先手动进入 TUI 或另外启动前端开发服务器
- **AND** 读取已有新需求记录不自动拉取仓库、执行 Git 写入、迁移聊天、接管远端会话或启动 Agent

#### Scenario: 再次 dev 结清退出
- **WHEN** 用户已进入 AIReq，在当前 TUI 再次执行 `/aireq`
- **THEN** 通过既有 native stop／settlement 停止并结清 AIReq 自有工作，成功后恢复普通原会话；失败保留 AIReq 锁定及真实原因，不提前恢复普通命令和输入
- **AND** 退出不取消需求、不撤销 Git、不删除材料；不为普通 `/new`／move／dispose 与 AIReq 并存保留会话快照、克隆或额外架构

#### Scenario: 单纯重开网页
- **WHEN** 用户重开同一工作台网页，而非在 TUI 再次执行 `/aireq`
- **THEN** 返回已有实际入口和状态，不重复创建需求、不重放任务或确认；不将重开网页解释为退出 AIReq
- **AND** 多个 Web 共享需求元数据，不建立仓库单 IR、SR 名额或跨 Web 开发互斥；TUI 宿主模式独占与普通 WebGUI 项目准入保持各自边界

#### Scenario: 浏览器无法自动打开
- **WHEN** 服务已就绪但宿主没有可用桌面浏览器，或自动打开失败
- **THEN** 仍输出完整实际地址，并明确报告浏览器未自动打开；不能把服务启动失败冒充仅浏览器打开失败，也不能只输出不可用地址

#### Scenario: 页面关闭不停止宿主任务
- **WHEN** 用户从任一入口打开的浏览器页面关闭、刷新或断开
- **THEN** 按 aireq-browser-workbench 的生命周期保留宿主任务和 AIReq 锁定，不恢复普通 TUI 输入；再次 `/aireq` 退出、显式停止或退出 OMP 才按原生规则处理自有资源，页面不是执行 owner

#### Scenario: 新界面与新流程
- **WHEN** 用户进入新 AIReq
- **THEN** 使用 AIReq 自有 WebGUI 风格界面；提案为需求→四 Agent 评审→方案→入库三栏流程，正式需求为大表格与同页报告，不提供开发聊天、计划／执行／IR 验收 Agent、冻结锁或最终归档流水线；实际编码在平台外完成，原 WebGUI 不变

### Requirement: 旧 AIReq 终端交互退役但能力保留

OMP MUST 移除旧 AIReq 阶段输入模式及其终端配置、详情、推进、丢弃和仅业务结束交互，`/aireq` 只负责独占网页 AIReq 的进入与结清退出。旧子命令不再执行或保留兼容别名，网页只复用需求管理、文档、设置和只读进度分析，不恢复旧编码能力；普通 OMP TUI、原生命令和独立技能保持不变，普通 TUI 操作须先退出 AIReq。

#### Scenario: 旧子操作不绕过网页流程
- **WHEN** 用户尝试 `/aireq new`、`business`、`finish-business`、`next`、`back`、`drop` 或 `config` 等旧终端子操作
- **THEN** 按当前真实命令目录明确拒绝，不启动旧模式、不执行部分控制、不交给模型或自动转换成旧流程
- **AND** 新建提案、业务讨论、人工文档确认与材料查看在网页按新合同完成；Team 和原生子代理保持原有独立配置，AIReq 设置只保留业务需求、需求评审 A／B／C、综合评审、方案、需求进度分析及独立 Skill 设计角色

#### Scenario: 命令目录与帮助一致
- **WHEN** 用户查看补全、帮助或调用 AIReq 入口
- **THEN** 目录准确展示 `/aireq` 进入／再次 `/aireq` 结清退出、AIReq 中当前 TUI 只接受该退出动作，以及 `omp aireq` 的网页启动语义；不宣传旧阶段终端操作、直接跳过业务检查或 drop 保留文件的行为
- **AND** 不新增旧状态兼容、恢复或迁移入口，不改变非 AIReq 命令在普通模式的参数、权限及执行方式；协议宿主仍按既有目录与准入规则处理命令

### Requirement: 同进程 Web 后端与 AIReq／WebGUI 项目互斥

每个 OMP 进程 MUST 独立持有同进程 Web 服务，同实例内多个项目会话共用本实例端口，不跨进程共享服务。Web 后端直接调用本进程原生能力，不经过内部 HTTP、不启动独立 SDK／Agent 进程或独立 Web worker；用户显式新建或继续历史时允许且必须由本进程原生 SDK 创建或恢复独立原生会话。同一项目的 AIReq 或 WebGUI 模式仍只能由一个原生 owner 持有；项目级模式 owner 与其名下多个原生会话的执行 owner 不得混淆，不能以项目互斥禁止同一 WebGUI owner 下的多会话并行。

#### Scenario: 跨目录入口与 profile 统一准入
- **WHEN** 用户从 `/aireq`、`omp aireq`、会话内 `/webgui` 进入项目模式，或在独立 WebGUI 显式打开／创建项目并请求创建／继续执行会话
- **THEN** 按真实 Git 项目根或非 Git 真实目录确定项目身份，子目录、路径别名、会话 ID、配置根和 profile 不得绕过同一项目的 OS 级占用锁；先取得占用再建立业务宿主或发布入口
- **AND** 进入模式后在启动、运行、退出结清中均持有占用；模式冲突必须拒绝，不能只靠前端按钮或同一 TUI 的标志判断，不靠超时强制释放仍存活的 owner；同一 WebGUI owner 下新增会话复用其项目准入，各会话仍独立执行与结清，不绕过其他进程或 AIReq owner
- **AND** 原生宿主模式独占不构成 AIReq 开发准入，AIReq 不设单 IR 锁、SR 名额或开发 worktree；退出失败不提前恢复普通终端，普通 WebGUI 原生项目准入不变

#### Scenario: 多项目单入口与选择隔离
- **WHEN** A、B 项目登记到同一 OMP 实例，不同桌面浏览器窗口选择项目
- **THEN** 使用本实例相同 HTTP 服务及端口，按项目 ID 直接路由到内存中的原生对象；每页独立选择，不修改后端全局“当前项目”，已离线项目不静默回落到其他项目，不发现其他 OMP 实例的项目
- **AND** WebGUI 的活动执行与控制只能针对已准入 WebGUI 模式下的所属原生会话；全部可访问历史仍按授权只读展示，不因页面当前项目或项目尚未准入而静默隐藏，继续历史须另行取得真实目标项目准入。AIReq 模式只显示占用并提示使用原生终端输出的完整工作台地址，不在公开项目列表分发其随机能力凭据，不允许改 URL 或继续历史绕过模式门禁
- **AND** 同进程监听器直接挂载现有 AIReq HTTP／WS 和能力路径，不经内部 HTTP 代理、不重写 AIReq 业务；保留原生随机能力路径及适用 Host／Origin／Cookie 语义；AIReq 长期共享服务按最新多人部署需求提供访问，不再以非 offline 仅本机作为该部署约束；不借此改变 WebGUI 自有访问边界

## ADDED Requirements

### Requirement: 独立 Skill 设计与原生聊天复用

AIReq MUST 在设置中提供独立“Skill 设计”，与原技能页并列；设计字段及临时路径先回填原聊天输入框，用户编辑并明确发送，生成后预览并选择个人 profile 或有效项目目标，不自动发送／保存或覆盖同名技能，不引入 AIReq 个人开发目录或需求编码阶段。

#### Scenario: 表单与补充讨论协同
- **WHEN** 用户填写任务目标、适用场景、输入及期望输出／成功标准，并在底部继续补充
- **THEN** 4 项核心字段明确必填，边界、参考流程／资料、例子可选；复用主页面聊天组件和 OMP 原生会话能力，精简外围展示但保留附件、停止、错误和必要工具／审批交互。会话与目标项目和设计草稿绑定，独立于 IR/SR，聊天字段建议需确认后回填，不另建聊天服务或执行器。

#### Scenario: 预览确认和项目级技能归属
- **WHEN** 设计内容足够，用户生成并确认预览后保存
- **THEN** 展示名称、description、正文和目标路径；内容改变使旧预览失效。可保存到实际个人 profile 的 skills/<name>/ 或有效可写项目的 .omp/skills/<name>/，无项目目标不阻止个人保存；不写他人或共享只读目录，仅 Web 所有者可改自己的技能，其他访问者保留表单并说明不支持；保存不证明已加载或评测通过

#### Scenario: 第一阶段只演示技能创建
- **WHEN** 当前仍处于原型评审阶段
- **THEN** 使用静态字段、独立会话和生成模板的样例，演示建议确认、预览、待试用例及项目内存保存，原技能页的作用域与加载方式保持原状；不调用真实模型、不写入真实技能目录、不执行技能／脚本或 Git，不以展示检查宣称真实业务验收。

### Requirement: AIReq 个人级模型与追加系统提示词设置

AIReq MUST 配置业务需求、需求评审 A／B／C、综合评审、方案、需求进度分析及独立 Skill 设计角色的模型／思考强度及追加提示词，删除计划、执行和 IR 验收角色。配置属于当前 OMP 用户级 profile，跨项目共用，不入共享业务库，不改原 WebGUI。

#### Scenario: 配置所有者与会话快照
- **WHEN** 访问者在 X 的 Web 查看模型、个性化或技能
- **THEN** 全员可看同一页面，但仅 X 可改 X 的配置；快捷键、草稿及全部写入口同样受限，不隐藏整页代替权限控制，切换工号不切换 Token 或 profile
- **AND** 新建角色会话复制当时配置，评审 A／B／C 与综合评审分别取相应角色；后续保存只影响新建会话，既有会话保留模型、强度及提示词快照，不热切换或改写历史，个人追加不扩大角色权限
- **AND** 原型仅演示内存设置，不读写真实 Token、配置或文件，不实现模型调用或权限服务

### Requirement: AIReq 自有多项目设置与浏览器选择

项目 MUST 只登记名称、Git 远程地址和默认分支，Release 登记所属项目和版本名称并继承仓库，不要求共享目录、个人开发路径、目录浏览或目录校验。各 Web 经固定 18321 的 aireq_db 服务读取唯一共享业务数据库，平台按需托管内部仓库副本。

#### Scenario: 保存与联动查看
- **WHEN** 保存配置或切换项目／Release
- **THEN** 保存只改元数据，不执行 Git、不移动材料或重绑历史；已有项目仅管理员 j00808874 可改，其他人只读。项目／Release 在工作区菜单同组联动，正式需求顶部保留选择；只加载所属项目 Release，无项目或版本明确引导，不回落样例目录
- **AND** 页面选择不改变其他页面、任务或会话归属，旧请求不写入新项目，不迁移草稿或附件；原型仅格式校验及内存保存，不把格式通过当作仓库可访问或分支存在

### Requirement: AIReq 长期共享需求整理入口

AIReq MUST 共享项目、Release、提案资料、正式需求、人员排期及进度，仅所有者为 j00808874 的 Web 提供提案讨论，其他 Web 只读材料；聊天归 A 的原生 OMP，不写业务库或在其他 Web 接管重放，不提供需求包导出／导入交接，不改原 WebGUI。

#### Scenario: 提案临时目录与托管分支
- **WHEN** 业务人员讨论提案并准备入库
- **THEN** 在固定临时工作区由业务 Agent 维护 IR／SR，评审只读，方案 Agent 维护 design.md 和稳定 SR 依赖；无需个人 OMP、Token 或 Git 路径，项目代码只作参考
- **AND** 当前 IR、全部 SR 和方案经人工逐文件确认后平台才创建推送提案分支，人工在 Git 网页创建、评审、合并 PR；后台仅按已合入且文档完整自动转正并创建 SR 分支，不要人工通知或再次入库审批

#### Scenario: 平台外开发与正式需求查看
- **WHEN** 查看正式 IR／SR 或旧开发链接
- **THEN** 只展示大表格、同页代码证据报告与只读需求材料，不挂载开发聊天或阶段动作；AIReq 无自由会话、会话列表或正在开发区，不设个人目录、冻结锁、执行名额或验收归档流水线，实际开发用平台外工具完成
- **AND** 正文、验收、方案及依赖入 Git，人员排期和进度入共享数据库，个人配置与聊天正文不入业务库；本轮只改文档与独立原型，不实现真实 CLI、Git、数据库或后台服务
