# Spec Delta

## MODIFIED Requirements

### Requirement: Dev 浏览器工作台启动入口

OMP MUST 提供会话内 `/dev` 和命令行 `omp dev` 两个工作台启动入口，输出完整可复制地址；非 offline 自动打开浏览器，offline 由用户手动打开。两者 MUST 指向目标目录的同一新 Dev 业务能力；会话内 `/dev` 进入独占 Dev，当前 TUI 此后仅接受再次 `/dev` 结清退出，不恢复旧 Dev 阶段输入或子操作，不因打开网页自动创建需求或调用模型。

#### Scenario: 从 OMP 会话打开
- **WHEN** 用户启动 OMP 后输入 `/dev`
- **THEN** 普通模型、工具或任务未结清时拒绝进入并提示先停止或等待，普通 Loop 未退出时提示先退出；不自动终止普通任务或退出 Loop。准入成功才启动或复用目标目录的工作台服务，显示实际完整地址，仅非 offline 自动打开浏览器
- **AND** 进入后当前 TUI 拒绝所有普通命令和输入，仅接受再次 `/dev` 退出；网页与普通 TUI 不同时操作，普通原会话保留但不继续操作。不显示旧 Dev 三行固定状态区，也不自动启动需求、Team 或 Goal
- **AND** 普通 Collab 正在共享或处于 `join` 会话时拒绝进入，提示先自行停止共享或离开该会话，不自动停止共享或离开 Collab；成功进入后仍支持 Dev 网页按既有 Collab 机制共享及 `join`

#### Scenario: 直接从命令行打开
- **WHEN** 用户在自己的目录运行 `omp dev`，包括先手动 `git pull` 获取新流程记录后运行
- **THEN** 使用当前 OMP 的有效目录、profile、模型和运行环境启动工作台，输出完整地址，仅非 offline 自动打开浏览器，不要求先手动进入 TUI 或另外启动前端开发服务器
- **AND** 读取已有新需求记录不自动拉取仓库、执行 Git 写入、迁移聊天、接管远端会话或启动 Agent

#### Scenario: 再次 dev 结清退出
- **WHEN** 用户已进入 Dev，在当前 TUI 再次执行 `/dev`
- **THEN** 通过既有 native stop／settlement 停止并结清 Dev 自有工作，成功后恢复普通原会话；失败保留 Dev 锁定及真实原因，不提前恢复普通命令和输入
- **AND** 退出不取消需求、不撤销 Git、不删除材料；不为普通 `/new`／move／dispose 与 Dev 并存保留会话快照、克隆或额外架构

#### Scenario: 单纯重开网页
- **WHEN** 用户重开同一工作台网页，而非在 TUI 再次执行 `/dev`
- **THEN** 返回已有实际入口和状态，不重复创建需求、不重放任务或确认；不将重开网页解释为退出 Dev
- **AND** 独立实例的开发冲突仍由同一工作区准入处理，不允许通过另一入口启动并行需求

#### Scenario: 浏览器无法自动打开
- **WHEN** 服务已就绪但宿主没有可用桌面浏览器，或自动打开失败
- **THEN** 仍输出完整实际地址，并明确报告浏览器未自动打开；不能把服务启动失败冒充仅浏览器打开失败，也不能只输出不可用地址

#### Scenario: 页面关闭不停止宿主任务
- **WHEN** 用户从任一入口打开的浏览器页面关闭、刷新或断开
- **THEN** 按 dev-browser-workbench 的生命周期保留宿主任务和 Dev 锁定，不恢复普通 TUI 输入；再次 `/dev` 退出、显式停止或退出 OMP 才按原生规则处理自有资源，页面不是执行 owner

#### Scenario: 新界面与新流程
- **WHEN** 用户进入新 Dev
- **THEN** 使用先完整复制 WebGUI 前端替换旧 Dev、再仅修改 Dev 副本实现的三栏工作台和提案两阶段与三阶段 SR 开发流程，需求 PR 合入后才开发，代码 PR 合入即结束；原 WebGUI 保持不变，不恢复旧八阶段界面。

### Requirement: 旧 Dev 终端交互退役但能力保留

OMP MUST 移除旧 Dev 阶段输入模式及其终端配置、详情、推进、丢弃和仅业务结束交互，`/dev` 只负责独占网页 Dev 的进入与结清退出。旧终端子命令产品路径 MUST 不再执行或作为兼容别名保留；其所需 Agent、材料、配置和控制能力转由网页复用，不删除普通 OMP TUI、其他原生命令或独立技能，但这些普通 TUI 操作须先成功退出 Dev。

#### Scenario: 旧子操作不绕过网页流程
- **WHEN** 用户尝试 `/dev new`、`business`、`finish-business`、`next`、`back`、`drop` 或 `config` 等旧终端子操作
- **THEN** 按当前真实命令目录明确拒绝，不启动旧模式、不执行部分控制、不交给模型或自动转换成旧流程
- **AND** 新建、业务文档输入、阶段确认、材料查看和需求删除仍可在网页按新合同完成，不能因移除终端 UI 一并删除功能；Team 和原生子代理保持既有配置方式，不新增 Dev Team 配置；5 个核心 Dev Agent 的个人级模型与追加系统提示词使用下述 Dev 设置入口

#### Scenario: 命令目录与帮助一致
- **WHEN** 用户查看补全、帮助或调用 Dev 入口
- **THEN** 目录准确展示 `/dev` 进入／再次 `/dev` 结清退出、Dev 中当前 TUI 只接受该退出动作，以及 `omp dev` 的网页启动语义；不宣传旧阶段终端操作、直接跳过业务检查或 drop 保留文件的行为
- **AND** 不新增旧状态兼容、恢复或迁移入口，不改变非 Dev 命令在普通模式的参数、权限及执行方式；协议宿主仍按既有目录与准入规则处理命令

### Requirement: 同进程 Web 后端与 Dev／WebGUI 项目互斥

每个 OMP 进程 MUST 独立持有同进程 Web 服务，同实例内多个项目会话共用本实例端口，不跨进程共享服务。Web 后端直接调用本进程原生能力，不经过内部 HTTP、不启动独立 SDK／Agent 进程或独立 Web worker；用户显式新建或继续历史时允许且必须由本进程原生 SDK 创建或恢复独立原生会话。同一项目的 Dev 或 WebGUI 模式仍只能由一个原生 owner 持有；项目级模式 owner 与其名下多个原生会话的执行 owner 不得混淆，不能以项目互斥禁止同一 WebGUI owner 下的多会话并行。

#### Scenario: 跨目录入口与 profile 统一准入
- **WHEN** 用户从 `/dev`、`omp dev`、会话内 `/webgui` 进入项目模式，或在独立 WebGUI 显式打开／创建项目并请求创建／继续执行会话
- **THEN** 按真实 Git 项目根或非 Git 真实目录确定项目身份，子目录、路径别名、会话 ID、配置根和 profile 不得绕过同一项目的 OS 级占用锁；先取得占用再建立业务宿主或发布入口
- **AND** 进入模式后在启动、运行、退出结清中均持有占用；模式冲突必须拒绝，不能只靠前端按钮或同一 TUI 的标志判断，不靠超时强制释放仍存活的 owner；同一 WebGUI owner 下新增会话复用其项目准入，各会话仍独立执行与结清，不绕过其他进程或 Dev owner
- **AND** 保留新 Dev 单项目单 SR、独立 worktree、人工 PR 和结清规则；退出失败不得释放项目占用或恢复普通终端

#### Scenario: 多项目单入口与选择隔离
- **WHEN** A、B 项目登记到同一 OMP 实例，不同桌面浏览器窗口选择项目
- **THEN** 使用本实例相同 HTTP 服务及端口，按项目 ID 直接路由到内存中的原生对象；每页独立选择，不修改后端全局“当前项目”，已离线项目不静默回落到其他项目，不发现其他 OMP 实例的项目
- **AND** WebGUI 的活动执行与控制只能针对已准入 WebGUI 模式下的所属原生会话；全部可访问历史仍按授权只读展示，不因页面当前项目或项目尚未准入而静默隐藏，继续历史须另行取得真实目标项目准入。Dev 模式只显示占用并提示使用原生终端输出的完整工作台地址，不在公开项目列表分发其随机能力凭据，不允许改 URL 或继续历史绕过模式门禁
- **AND** 同进程监听器直接挂载现有 Dev HTTP／WS 和能力路径，不经内部 HTTP 代理、不重写 Dev 业务；保留原生随机能力路径、Host／Origin／Cookie 语义及非 offline 仅本机访问边界，不把 WebGUI 局域网监听变成 Dev 的额外网络授权

## ADDED Requirements

### Requirement: 独立 Skill 设计与原生聊天复用

Dev MUST 在设置中新增独立“Skill 设计”入口，与原“技能”页面并列，不改造原技能管理页。Skill 设计 MUST 以结构化字段和补充讨论收集任务要求，生成预览后保存到目标项目的 OMP 原生默认可发现技能目录；它不构成新增 Dev 阶段或固定角色。

#### Scenario: 表单与补充讨论协同
- **WHEN** 用户填写任务目标、适用场景、输入及期望输出／成功标准，并在底部继续补充
- **THEN** 4 项核心字段明确必填，边界、参考流程／资料、例子可选；复用主页面聊天组件和 OMP 原生会话能力，精简外围展示但保留附件、停止、错误和必要工具／审批交互。会话与目标项目和设计草稿绑定，独立于 IR/SR，聊天字段建议需确认后回填，不另建聊天服务或执行器。

#### Scenario: 预览确认和项目级技能归属
- **WHEN** 设计内容足够，用户生成并确认预览后保存
- **THEN** 明确展示名称、description、技能正文和目标路径；名称或内容改变后旧预览不得继续保存。使用目标项目默认发现目录（通常为 `.omp/skills/<name>/SKILL.md`），校验同名冲突、路径及适用原生格式，不越过目标项目或改写个人模型／追加提示词。保存不证明技能已加载或评测通过，刷新／加载复用原生机制。

#### Scenario: 第一阶段只演示技能创建
- **WHEN** 当前仍处于原型评审阶段
- **THEN** 使用静态字段、独立会话和生成模板的样例，演示建议确认、预览、待试用例及项目内存保存，原技能页的作用域与加载方式保持原状；不调用真实模型、不写入真实技能目录、不执行技能／脚本或 Git，不以展示检查宣称真实业务验收。

### Requirement: Dev 个人级模型与追加系统提示词设置

Dev MUST 提供模型设置及参照 WebGUI 风格的个性化页面，针对业务需求、需求评审、方案、计划、执行 5 个核心 Agent 配置模型／思考强度及追加系统提示词。配置 MUST 在当前 OMP 用户级配置／profile 下持久保存，复用已有配置目录解析，在同配置内跨项目共用；MUST NOT 按项目、Release、IR/SR 或 worktree 另存、提供项目级覆盖或修改原 WebGUI。方案 Agent 只用于提案阶段，由评审开发人员在提交需求 PR 前完成方案；正式 SR 从开发计划开始。测试和技术审核使用 OMP 原生子代理及其既有配置，交付材料由执行 Agent 整理。

#### Scenario: 个人配置跨项目共用
- **WHEN** 用户保存某个 Dev Agent 的模型或追加提示词，再从项目 A 切换到项目 B
- **THEN** 读取相同有效 OMP 个人配置／profile 的同一份设置，不因项目改变而重置或另存；自定义配置根、agent 目录、profile、XDG 沿用 OMP 现有路径规则，不硬编码 `~/.omp/agent` 或写入项目 `.omp`。

#### Scenario: 按角色追加个人指令
- **WHEN** 用户在个性化页面选择一个核心 Agent 并保存追加系统提示词
- **THEN** 仅更新该角色的个人追加内容，保留其他角色配置和模型；留空清除个人追加，内置职责、阶段权限、冻结规则及人员确认保持有效；下一次创建该角色采用新配置，不自动重建会话或改写历史。
- **AND** 编辑器沿用 WebGUI 同类控件、保存／取消和 Ctrl/Cmd+S，保留未保存草稿，超限明确阻止保存；保存不启动 Agent 或执行项目任务。

#### Scenario: 第一阶段配置仅为演示
- **WHEN** 当前仍处于前端原型评审阶段
- **THEN** 使用仓库内维护的角色模型、提示词样例及页面内存演示，标明个人级、跨项目范围和目录示例，不读写真实配置、用户 `AGENTS.md` 或仓库文件，不实现后台配置接口与提示词注入，不把演示保存解释为真实落盘。

### Requirement: Dev 自有多项目设置与浏览器选择

Dev MUST 在自有前端提供共享项目与 Release 设置，只登记服务端已有有效 Git 仓库。项目与 Release 清单统一存入 `/tmpdata/DFT_LAB/omp/omp_dev_sqlite.db`，全 Web 共享，所有人可同时查看；Release 始终归属项目，不随 OMP profile 或 Git clone 另建清单。共享项目路径只读，查看项目不要求配置个人开发目录。 每位同事进入开发前，必须在所选项目下添加自己的“开发项目”路径，按工号与共享项目 ID 关联保存到同一数据库；该路径指 OMP 服务端可访问的已有 Git 工作目录，必须校验 Git 有效性、与共享项目的仓库对应关系及可写性，不可直接使用共享只读目录。修改个人路径不覆盖共享项目、不改变其他工号的绑定，不重定向已有运行任务。 浏览器项目／Release 选择只是当前页面查看偏好，不等同后端全局 current；不修改原 WebGUI。

#### Scenario: 共享登记与同时查看
- **WHEN** 同事添加已有项目目录或在项目下添加 Release
- **THEN** 服务在添加时检查 Git 项目，错误在目录下说明，不要求独立校验按钮；项目与 Release 登记写入共享 SQLite，重启后可读取，其他页面重新读取或接收更新后看见同一清单。添加不自动 clone、创建目录、启动模型或提交 Git；共享路径展示为只读，Release 不写入项目 Git 或个人 OMP 配置。

#### Scenario: 按工号绑定开发项目
- **WHEN** 同事在共享项目下输入或浏览选择自己的开发目录并保存
- **THEN** 校验 Git、目标仓库对应关系与写权限后，按工号和项目 ID 保存绑定；共享只读目录或其他项目的仓库必须拒绝。所有服务器路径相对于 OMP 服务机器，不是浏览器电脑。无绑定可浏览需求及材料，进入开发必须先配置；开发工作树来自该同事的开发项目，不能写共享只读目录。切换工号或项目不复用其他人的绑定，修改绑定不迁移现有任务。

#### Scenario: 原型演示共享清单与个人开发目录
- **WHEN** 当前处于前端原型阶段
- **THEN** 项目／Release 及按工号关联的目录使用仓库内维护的内存样例；展示一个已配置及一个未配置项目，保存演示 Git 与仓库关系检查，未配置时拦截开始开发。明确不提供真实多浏览器同步、工号登录或文件权限校验，不连接 SQLite、不写真实配置／Git，不把样例保存解释为真实落盘。

#### Scenario: 工作区菜单内项目与 Release 相邻并联动
- **WHEN** 一个 Dev 页面从 A 切换到 B，其他页面仍查看 A
- **THEN** 项目与 Release 在左下角 工作区菜单内同组相邻展示，先项目、后 Release；子菜单交互和动效沿用界面主题，按钮持续显示当前选择摘要，顶部不再保留选择器。只加载 B 自己的 Release 并选择首个有效项，没有时清空并引导添加，不沿用 A 的 Release。只改变当前页面的查看、输入和材料目标；原项目任务、其他页面及其会话保持原归属，旧请求和迟到事件不能写入 B，不重绑任务，不迁移草稿、附件或问答。

#### Scenario: 无效项目与绑定失败
- **WHEN** 项目目录无效、不可访问或连接绑定失败
- **THEN** 显示真实错误，不静默回落到另一目录，不因选择项目启动模型。

### Requirement: Dev 长期共享需求整理入口

开发人员 MUST 能长期运行新 Dev，供所有人员通过同一浏览器工作台完成提案整理、提交评审及直接查看共享材料，不提供需求包下载／导出／导入交接。所有人使用同一 Dev 界面，全部登记项目、正式需求、草稿和需求会话共享可见，修改串行，资料和任务按项目、IR 关联；MUST NOT 将此流程加到原 WebGUI、另建业务专用接口或角色视图。

#### Scenario: 浏览器整理与开发交接
- **WHEN** 开发人员在其 clone 中长期运行 Dev，业务人员打开实际 Dev 地址
- **THEN** 业务人员无需安装 OMP、Git、clone 仓库或加入 Collab，可选择项目、讨论提案并提交评审；接手开发人员直接选择共享正式需求并配置自己的开发项目路径，不要求使用 `/webgui`／`omp webgui`。

#### Scenario: 多项目操作不重新交接模式
- **WHEN** 已进入 Dev 的浏览器在登记项目间切换、整理提案或查看共享材料
- **THEN** 使用 Dev 宿主内绑定正确项目的 OMP 原生会话，不重复触发全进程模式交接，不结清、取消或 dispose 其他项目工作；首次 `/dev` 进入及再次 `/dev` 退出仍遵守既有独占准入与全部 Dev 自有工作结清规则。

#### Scenario: 原 WebGUI 保持原样
- **WHEN** 用户通过 `/webgui` 或 `omp webgui` 使用原 WebGUI
- **THEN** 沿用既有前端、后端、项目及多会话行为，不出现新增 Dev 流程，不修改其入口、协议、构建配置或正式资源；不因 Dev 长期运行而绕过既有项目互斥和网络安全边界。


#### Scenario: 自由会话使用当前共享项目上下文
- **WHEN** 从 Dev 的“自由会话”单项目行新建或打开聊天
- **THEN** 使用当前已选项目，复用原生会话和文件／审查入口，不再显示另一套项目清单；自由会话不要求选择 Release 或创建 IR／SR
- **AND** 查看共享项目与执行目录归属保持既有边界；切换项目不迁移或重绑现有会话目录，原 WebGUI 不修改
