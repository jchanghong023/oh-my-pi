# Spec Delta

## MODIFIED Requirements

### Requirement: Dev 浏览器工作台启动入口

OMP MUST 提供会话内 `/dev` 和命令行 `omp dev` 两个工作台启动入口，输出完整可复制地址；非 offline 自动打开浏览器，offline 由用户手动打开。两者 MUST 指向目标目录的同一新 Dev 业务能力；会话内 `/dev` 进入独占 Dev，当前 TUI 此后仅接受再次 `/dev` 结清退出，不恢复旧 Dev 阶段输入或子操作，不因打开网页自动创建需求或调用模型。

#### Scenario: 从 OMP 会话打开
- **WHEN** 用户启动 OMP 后输入 `/dev`
- **THEN** 普通模型、工具或任务未结清时拒绝进入并提示先停止或等待，普通 Loop 未退出时提示先退出；不自动终止普通任务或退出 Loop。准入成功才启动或复用目标目录的工作台服务，显示实际完整地址，仅非 offline 自动打开浏览器
- **AND** 进入后当前 TUI 拒绝所有普通命令和输入，仅接受再次 `/dev` 退出；网页与普通 TUI 不同时操作，普通原会话保留但不继续操作。不显示旧 Dev 三行固定状态区，也不自动启动需求、Team 或 Goal
- **AND** 普通 Collab 正在共享或处于 `join` 会话时拒绝进入，提示先自行停止共享或离开该会话，不自动停止共享或离开 Collab；成功进入后仍支持 Dev 网页按既有 Collab 机制共享及 `join`

#### Scenario: 直接从命令行打开
- **WHEN** 用户在自己的目录运行 `omp dev`，包括先手动 `git pull` 获取新流程记录后运行
- **THEN** 使用当前 OMP 的有效目录、profile、模型和运行环境启动工作台，输出完整地址，仅非 offline 自动打开浏览器，不要求先手动进入 TUI 或另外启动前端开发服务器
- **AND** 读取已有新需求记录不自动拉取仓库、执行 Git 写入、迁移聊天、接管远端会话或启动 Agent

#### Scenario: 再次 dev 结清退出
- **WHEN** 用户已进入 Dev，在当前 TUI 再次执行 `/dev`
- **THEN** 通过既有 native stop／settlement 停止并结清 Dev 自有工作，成功后恢复普通原会话；失败保留 Dev 锁定及真实原因，不提前恢复普通命令和输入
- **AND** 退出不取消需求、不撤销 Git、不删除材料；不为普通 `/new`／move／dispose 与 Dev 并存保留会话快照、克隆或额外架构

#### Scenario: 单纯重开网页
- **WHEN** 用户重开同一工作台网页，而非在 TUI 再次执行 `/dev`
- **THEN** 返回已有实际入口和状态，不重复创建需求、不重放任务或确认；不将重开网页解释为退出 Dev
- **AND** 独立实例的开发冲突仍由同一工作区准入处理，不允许通过另一入口启动并行需求

#### Scenario: 浏览器无法自动打开
- **WHEN** 服务已就绪但宿主没有可用桌面浏览器，或自动打开失败
- **THEN** 仍输出完整实际地址，并明确报告浏览器未自动打开；不能把服务启动失败冒充仅浏览器打开失败，也不能只输出不可用地址

#### Scenario: 页面关闭不停止宿主任务
- **WHEN** 用户从任一入口打开的浏览器页面关闭、刷新或断开
- **THEN** 按 dev-browser-workbench 的生命周期保留宿主任务和 Dev 锁定，不恢复普通 TUI 输入；再次 `/dev` 退出、显式停止或退出 OMP 才按原生规则处理自有资源，页面不是执行 owner

#### Scenario: 新界面与新流程
- **WHEN** 用户进入新 Dev
- **THEN** 使用以 WebGUI 界面为基础重构的三栏工作台和四阶段 SR 流程，需求 PR 合入后才开发，代码 PR 合入即结束；不恢复旧八阶段界面。

### Requirement: 旧 Dev 终端交互退役但能力保留

OMP MUST 移除旧 Dev 阶段输入模式及其终端配置、详情、推进、丢弃和仅业务结束交互，`/dev` 只负责独占网页 Dev 的进入与结清退出。旧终端子命令产品路径 MUST 不再执行或作为兼容别名保留；其所需 Agent、材料、配置和控制能力转由网页复用，不删除普通 OMP TUI、其他原生命令或独立技能，但这些普通 TUI 操作须先成功退出 Dev。

#### Scenario: 旧子操作不绕过网页流程
- **WHEN** 用户尝试 `/dev new`、`business`、`finish-business`、`next`、`back`、`drop` 或 `config` 等旧终端子操作
- **THEN** 按当前真实命令目录明确拒绝，不启动旧模式、不执行部分控制、不交给模型或自动转换成旧流程
- **AND** 新建、业务文档输入、阶段确认、材料查看和需求删除仍可在网页按新合同完成，不能因移除终端 UI 一并删除功能；Team／模型角色配置继续使用既有配置方式，不新增网页配置入口

#### Scenario: 命令目录与帮助一致
- **WHEN** 用户查看补全、帮助或调用 Dev 入口
- **THEN** 目录准确展示 `/dev` 进入／再次 `/dev` 结清退出、Dev 中当前 TUI 只接受该退出动作，以及 `omp dev` 的网页启动语义；不宣传旧阶段终端操作、直接跳过业务检查或 drop 保留文件的行为
- **AND** 不新增旧状态兼容、恢复或迁移入口，不改变非 Dev 命令在普通模式的参数、权限及执行方式；协议宿主仍按既有目录与准入规则处理命令

### Requirement: WebGUI 浏览器正式入口

OMP MUST 提供 `/webgui` 和 `omp webgui`，复用已迁入并精简后的 ZCode Web／手机界面、前端服务契约及协议，不能改成交付替代性的简化聊天页。网页 MUST 支持项目选择／打开／创建、显式创建原生会话并实际开发、全部可访问历史与独立续聊、实时消息／流式回复／执行状态、当前会话临时选模、指定会话停止、补充问答、文件／图片上传、`@` 文件上下文、忙时队列、运行中 guide、编辑提问重发、失败回复重试、当前有效 profile 用户级 AGENTS 编辑、文件／Git 自动刷新及所有 TUI 内置命令与有效 Skill；支持多原生会话并行及失败安全退出。全部执行复用 OMP 原生能力与真实状态，不迁移 ZCode 后端或桌面端，不另建模拟执行器、独立 SDK 进程、消息数据库或任意图工作流引擎，不扩展本次未指定的审批、配置修改或 Git 写操作。

#### Scenario: 会话内进入与退出
- **WHEN** 用户在普通 TUI 输入 `/webgui`
- **THEN** 复用 Dev 的 TUI 独占准入和输入门禁，并取得项目级占用权；成功后登记当前会话到本 OMP 进程的 Web 服务，输出本实例的本机和局域网地址，仅非 offline 尝试打开浏览器，同进程内不按项目重复启动前端或监听器
- **AND** 当前终端只接受再次 `/webgui` 退出，普通会话与草稿保留；关闭或刷新网页不退出，手机直接访问本实例服务，不进行远控配对
- **AND** 再次 `/webgui` 或宿主关闭时结清本实例自有 Web 工作并关闭本实例服务；结清成功才恢复普通终端，失败保持锁定并允许重试，不关闭或影响其他 OMP 进程的服务

#### Scenario: 独立命令与资源边界
- **WHEN** 用户运行 `omp webgui`
- **THEN** 在当前 CLI 进程启动独立持有的 Web 服务，不发现或复用其他进程服务；仅启动、连接、刷新网页时保持 lazy，不创建 Agent、不占用项目、不调用模型、不自动安装依赖，不生成项目或会话记录；浏览器以本进程真实有效工作目录作为初始显示上下文，不能把该上下文当作已经打开的项目或会话
- **AND** 用户可在网页显式选择／打开／创建项目，再显式新建原生会话或发送首条消息；取得目标真实目录的项目准入后，必须在本进程实际创建原生 AgentSession 并可调用工具开发，不得以独立命令仅供浏览为由禁用此路径。选择项目本身不自动调用模型，命令退出按本实例全部自有工作的结清合同处理
- **AND** 源码入口使用正式前端构建；安装包及编译二进制必须携带同一份内容可校验的静态资源，不依赖源码目录、运行时 Vite、联网下载或自动安装依赖。资源缺失明确报错，不读取当前用户项目充当自有资源
- **AND** 正式资源中实际引用的 JavaScript、样式、图像、字体、WASM、PDF CMap 与通知 MP3 必须可从同一监听器读取，内容匹配构建字节且使用正确 MIME，不因静态扩展名白名单遗漏返回 404
- **AND** 每个 OMP 实例由系统分配独立空闲端口，同实例后续项目复用该端口；浏览器打开失败仍保留真实可访问地址，服务启动失败不得报告就绪；未调用入口时不启动服务或改写状态

#### Scenario: 浏览器协议与界面边界
- **WHEN** 电脑或手机通过浏览器打开 WebGUI
- **THEN** 两者直接连接 OMP 自有共享 Web 后端，使用同一份前端服务接口、协议编解码、数据 Schema 和错误语义；不引入独立中转服务、Relay、远控配对或桌面 Host，手机不依赖电脑浏览器在线
- **AND** 保留原有聊天、模型选择、项目选择／打开／创建、会话、工具结果、必要审批与错误提示、Skill、Team／Workflow 及手机响应式布局；不保留 ZCode 专属插件市场／源／安装卸载更新／插件设置与侧栏预览／Sites、SSH／WSL／Docker／远端工作区连接向导历史状态、远控配对设备与启动停止、内嵌浏览器／Browser Use／浏览器权限、ZCode 电脑控制设置授权、桌面窗口控制更新托盘及桌面宿主专用设置。移除额外预览说明、调试栏、临时项目选择器和手机预览外框；由保留的正式项目界面完成项目操作，不用新面板或简化聊天页替代保留界面。
- **AND** 全部浏览器依赖的服务方法与事件须有明确的协议响应，完成连接初始化、调用分发、订阅、退订和断连清理；从真实原生状态提供会话历史、消息、执行状态及当前模型，不伪造原生项目、会话、消息或操作结果
- **AND** 本规范要求交付的业务必须真实接入，不允许以 TODO、占位、固定返回、统一不可用提示或前端消息回显代替完成。范围外尚未接入的保留能力通过既有明确错误或能力状态表示未接入，不能假成功、吞掉真实错误或触发未捕获异常
- **AND** 未接入的 Provider 管理、Hooks、Memory、OutputStyle 与配置发现／首次使用状态读取必须返回明确不可用，不能用空目录、空配置、`null` 或固定状态冒充原生读取成功；连接级展示默认值和显式不支持的能力状态不作为原生配置快照
- **AND** 手机只适配窄屏、布局、触控和输入，直接使用与电脑相同的聊天后端；关闭浏览器不退出原终端模式，也不创建替代 Agent

#### Scenario: 完整业务验收
- **WHEN** 验收 WebGUI 原生开发能力
- **THEN** 按 `fork-verification-gates` 的 WebGUI 验收 Requirements／Scenarios，使用同一份生产构建和公开 HTTP／WS 入口，在真实 Chrome 与本机真实 Firefox 128（当前版本 128.14.0）分别完成本规范全部业务，证明真实原生会话调用工具并产生实际开发文件结果及正确归属，而非仅打开页面
- **AND** 使用真实 OpenCode Go（provider `opencode-go`）／Beam Free 模型，实际 model id 以权威 catalog／discovery 确认并记录；`bun run fastcheck` 与 `bun run fulltest` 必须按现有默认成功，不加 `--full`、不放宽预算或 skip 掩盖失败。证据、隔离、缺失前提和失败路径规则以该 gate 规格为准，不以 mock、Chrome 结果或截图替代另一浏览器的真实业务结果
- **AND** 保留手机响应式能力，但本次不新增手机实机、发行物或部署验收；不自动安装浏览器／工具或修改个人浏览器配置，缺认证、目标模型或浏览器时如实报告阻塞，不声明通过

#### Scenario: Firefox 128 与 Chrome 共用入口
- **WHEN** 用户通过 Firefox 128 或当前 Chrome 打开 WebGUI
- **THEN** 使用同一份生产资源与原有界面，以 Firefox 128 默认启用的能力为兼容基线，不修改个人浏览器配置；移除 fork 为 Firefox 68、Chrome 109 新增的 API shim、WASM 加载改写、CSS 降级及专用回退，不改既有功能和布局；ZCode 原版自身的通用兼容逻辑不在本次清理范围
- **AND** 缺少 WeakRef／FinalizationRegistry 时不启用可选的跨 store 弱引用行缓存，不用强引用延长历史会话寿命；Dev 工作台原有原生能力边界不变
- **AND** 代码／Diff 预览在目标浏览器使用原生 adoptedStyleSheets，按需加载真实高亮 WASM，不要求旧版浏览器专属 Shadow DOM 样式兼容路径，不伪造空预览或修改浏览器安全设置
- **AND** Firefox 128 的开关轨道、滑块及推荐区滚动条保持可见、可用；Chrome 原有外观、Workflow 动画规则、状态机及 reduced-motion 行为不变
- **AND** 两个浏览器均须完成上述完整业务验收，页面启动、刷新、导航和输入只是其中一部分，不能据此声明全部功能已通过；手机实机结论仍不得从响应式截图推导

#### Scenario: 浏览器直连不依赖 ZCode 专属界面
- **WHEN** 用户从电脑或手机浏览器访问局域网内 OMP WebGUI
- **THEN** 直接使用 OMP HTTP／WS 与原有本地项目、会话和消息界面；删除的远程连接／远控能力不影响此访问路径，不要求配对、SSH、WSL、容器或桌面 Host
- **AND** 插件页面裁剪保留 Skill 设置；不删除 OMP 自身 Skill、MCP、浏览器、计算机操作及真实授权流程，不改变 Dev 与普通 TUI 的能力

#### Scenario: 删除已核实的原产品专属入口
- **WHEN** 用户在 WebGUI 使用聊天、设置或帮助界面
- **THEN** 不再提供依赖 Electron webview／购买完成 IPC 的套餐购买升级弹窗及其入口，不显示执行 `.zcode/v2` 迁移的存储路径设置，也不提供桌面检查更新／重启更新入口
- **AND** 删除对应前端组件、专属状态与调用链，不用隐藏开关或空实现代替；不删除或迁移用户数据，不以此删除 OMP 原生终端／Shell、模型配置、用量显示或自动化等未指定功能

#### Scenario: 删除指定界面及专属空壳
- **WHEN** 维护 WebGUI 的面板入口与服务装配
- **THEN** 删除终端、部署、内嵌浏览器和 ZCode 应用插件的入口及对应界面，移除顶部终端按钮、`Ctrl+J` 和相应命令面板入口；清理仅服务这些界面的状态、调用链、协议及 TODO／未实现后端空函数，不以隐藏或空实现代替
- **AND** 不再支持 ZCode 应用插件的推荐、侧栏预览及专属 UI 桥接；保留 OMP 原生插件、Skill、GenUI 共享能力、文件浏览与预览、Git、开发工具、聊天和后台 Bash 输出，不改动 OMP 真实 Shell／浏览器／计算机工具及其授权流程
- **AND** 复制来的集成终端 Shell 选择设置、专属配置协议与 `listIntegratedTerminalShells` 占位接口一并删除；OMP 原生 Bash 继续使用自己的 `shellPath` 配置，不将复制前端中的 Bash 文案视为原生依赖

#### Scenario: 删除指定 WebGUI 后端占位接口
- **WHEN** 维护 WebGUI 的已注册 RPC 服务
- **THEN** 不注册套餐购买升级、插件市场与安装管理、远端工作区 `source-server-workspace`、终端和聊天／会话业务的空实现通道或只抛未实现错误的方法表；删除仅有 TODO 的数据目录迁移接入声明
- **AND** 不以空通道、伪成功结果或兼容别名替代删除；保留实际协议握手、订阅归属和清理、既有未知通道／方法错误，以及真实原生会话的模型列表与临时选模
- **AND** 此后端删除仅涉及上述占位，不因此删除聊天等保留前端组件、原生 OMP 实现或仍有其他消费者的共享服务契约，不扩大到列表外的 Skill、文件／Git、记忆及自动化接入

#### Scenario: 精简专属界面不得破坏共享能力
- **WHEN** 删除原产品专属前端与已明确废弃的调用链
- **THEN** 保留现有项目／任务／文件的真实连接、绑定、取消和恢复逻辑及作用域校验；侧栏继续接收必要回调、主题和平台信息，不恢复远端连接向导或远控配对界面
- **AND** 独立 Web 入口保留普通 WebSocket 连接和模型提供商认证所必需的回调，不再保留原 ZCode 账号或云分享入口；移除集成终端界面不改变 OMP 真实 Shell 工具的客户端平台与输入参数
- **AND** OMP 直连页面不调用已删除的订阅与 ZCode 插件库存接口；Workflow 导航可见性与实际业务可用性分离，未接入执行仍明确不可用；Skill／子代理以真实列表为准，不因缺少插件库存丢弃已返回资源
- **AND** 清理无消费者购买优惠、购买链接、支付 SDK／图标、远控开关及内嵌浏览器恢复注册器，不扩删通用计算机操作审批、工具呈现及权限契约

#### Scenario: 中文界面与按需代码预览
- **WHEN** 用户通过浏览器使用 WebGUI
- **THEN** 界面固定为简体中文，不提供英文语言包和语言切换入口，不受浏览器旧语言偏好影响；保留消息插值、主题和手机响应式布局
- **AND** 代码与差异预览首次挂载时才启动共享高亮 Worker，不在空白首页预先启动；保留查看文件修改、子代理会话和 Workflow 动态展示的前端入口与共享实现，范围外未接入的原生业务继续明确标识不可用，不因暂未完成适配删除；本规范要求的原生开发能力不能归为此类未接入业务
