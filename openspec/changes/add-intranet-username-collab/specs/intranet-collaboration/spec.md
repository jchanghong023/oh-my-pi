# Spec Delta

## Purpose

规定仅在 `OMP_OFFLINE` 生效的 CentOS 7 内网多用户、多机器共享 OMP 会话时，以系统登录用户名查找房间、限制每人一个活动共享并直接加入控制的行为。客户端使用既有配置连接普通内网 WS，并通过同一服务器的 HTTP 查找用户名，无需证书、认证或房主批准。该能力复用原有房主会话、访客复制与工具执行方式；非 offline 的既有功能与安全策略保持不变。

## ADDED Requirements

### Requirement: 内网用户名协作仅在 offline 生效

本能力全部要求 MUST 仅在相关 OMP 进程按既有规则启用 `OMP_OFFLINE` 时生效，Relay 与用户名协作客户端均受该门禁约束。非 offline MUST NOT 启用用户名登记、查找、跨机器用户名唯一限制或直接加入授权；即使配置内网 Relay 也 MUST 保持原有协作及其他功能，不新增模式开关。

#### Scenario: 通过既有环境变量启用

- **WHEN** CentOS 7 的 Relay 和参与用户名协作的 OMP 客户端按既有真值规则启用 `OMP_OFFLINE`
- **THEN** 本规格后续的用户名登记、唯一活动房间、直接加入与生命周期要求生效
- **AND** 不要求新增 offline 命令行参数，不更改现有 `OMP_OFFLINE` 解析规则

#### Scenario: 非 offline 不启用用户名能力

- **WHEN** OMP 进程未启用 `OMP_OFFLINE`，包括变量未设置、空值或取非启用值，即使设置了内网 `collab.relayUrl`
- **THEN** 不登记或查询用户名，不限制原有协作房间为每用户名一个，不按用户名开放直接控制权限
- **AND** 原有默认／自定义 Relay、邀请链接及权限规则和其他功能保持不变，不向 Relay 发送新增用户名协议请求

### Requirement: 使用进程所属登录用户名登记房间

OMP MUST 使用房主进程实际所属 Linux 账号的登录用户名作为房间查找名，不使用数字 UID、`collab.displayName`、项目名或手填别名。用户名 MUST 仅用于路由到活动房间，不作为身份认证。

#### Scenario: 使用工号形式的登录用户名

- **WHEN** 所属 Linux 账号名为 `j00808874` 的 OMP 进程开始内网共享
- **THEN** 房间以 `j00808874` 登记，同事可按该用户名查找，不需要知道数字 UID 或所在机器

#### Scenario: 无法确定所属账号

- **WHEN** OMP 无法取得进程实际所属账号的登录用户名
- **THEN** 明确报告不能登记，不以 `anonymous`、数字 UID 或显示名代替，不发布到其他人的用户名下

### Requirement: 跨机器保持每用户名一个活动房间

一个共享 Relay 范围内，同一用户名 MUST 至多登记一个活动房间，限制跨机器、进程和 profile 生效。同一宿主对同一活动会话重复共享 MUST 复用房间；其他宿主 MUST NOT 自动抢占、替换或迁移已有房间。跨机器登记 MUST NOT 依赖读取另一机器的本机 IPC 端点或共享 NFS registry。

#### Scenario: 同一宿主重复共享

- **WHEN** 房主已登记当前活动房间，又在该宿主当前会话执行 `/collab`
- **THEN** 复用并报告已有房间，不创建第二个活动房间、不踢出现有访客

#### Scenario: 同一用户名从不同机器同时共享

- **WHEN** 两台机器的 OMP 进程同时为同一用户名登记活动房间
- **THEN** 最多一个登记成功，失败方明确提示用户名已共享、所在主机及可用 `/join <username>` 加入
- **AND** 失败方不显示已成功共享，不中断或转移成功方会话

#### Scenario: 不同用户名在同一 Relay 共享

- **WHEN** 两个不同登录用户名分别共享各自会话
- **THEN** 两个房间可同时活动，按一个用户名加入不会收到另一个用户名的历史、流式事件、提示或控制请求

### Requirement: 通过普通内网 WS 和 HTTP 按用户名加入

offline 客户端 MUST 使用既有 `collab.relayUrl` 配置的 `ws://<内网IP或主机名>:<端口>` 连接 Relay，并通过同一服务器的 HTTP 查询用户名，无需人工复制邀请链接。客户端 MUST NOT 因地址不是 localhost 而拒绝普通 WS 或强制升级 WSS；流程 MUST 不要求证书、TLS、HTTPS 或反向代理。用户名无有效房间或连接失败时 MUST 明确失败，不回退公网或显示加入成功。

#### Scenario: 同事跨机器加入

- **WHEN** 同事在另一台机器配置普通远端 `ws://` Relay 后执行 `/join j00808874`，该用户名有有效的活动共享
- **THEN** 通过同一服务器的 HTTP 查找后加入该房间，取得既有访客快照与后续实时事件，无需证书、邀请链接或额外凭据
- **AND** 不要求访客拥有或挂载房主目录，不改变访客本机工作目录来模拟房主机器

#### Scenario: 用户不在线或服务不可达

- **WHEN** 查询没有活动房间，或内网 Relay 不能连接、不能完成当前房间加入
- **THEN** 显示对应的未共享／不在线／连接失败原因，保持原本地会话可用，不显示已经加入

### Requirement: 用户名加入无需认证或审批

offline 客户端 MUST 能按用户名直接加入房主已主动共享的房间，取得既有完整控制访客能力，不要求房主确认、SSO、token、共享凭据或其他认证步骤。获知用户名 MUST NOT 自动启动共享或开放未共享会话；用户名加入 MUST 保持既有访客命令能力与房主工具执行位置。

#### Scenario: 无额外确认加入并协作

- **WHEN** 一个可达 Relay 的客户端按用户名成功加入主动共享的房间
- **THEN** 无需房主逐次确认或输入凭据即可读取会话历史、观察实时输出、发送提示、打断及使用既有可写访客的子代理与交互答复能力
- **AND** 所有模型调用和工具执行仍由房主会话在房主机器、以房主账号执行，Relay 不执行工具或接管会话

#### Scenario: 不越过既有访客门禁

- **WHEN** 用户名访客尝试运行房主专用的 `/model`、`/resume` 或本机 Shell 执行命令
- **THEN** 继续按既有访客命令门禁拒绝，不因用户名加入而直接获得任意宿主命令接口
- **AND** 既有只读邀请链接仍只授予只读权限，不因为新增用户名流程而自动升级


### Requirement: 共享撤销与房间换代隔离

停止共享、房主退出或连接已终止的房间 MUST 不再作为有效用户名目标。会话切换、房间替换、Relay 重启及旧连接的迟到消息 MUST NOT 让旧访客或旧控制请求静默进入另一会话；新加入 MUST 解析到当时仍有效的房间，不能使用已经撤销的登记冒充成功。

#### Scenario: 停止后再次查询

- **WHEN** 房主停止共享或其宿主连接已终止，同事再按该用户名加入
- **THEN** 不能取得旧房间访问权限；尚无新共享时明确报告不在线或未共享
- **AND** 已连接访客收到共享结束或连接失效状态，不继续显示为可控制

#### Scenario: 旧会话被新会话替换

- **WHEN** 房主切换会话并按既有共享策略形成新的活动房间
- **THEN** 原访客不能自动获得新会话内容，原房间排队或迟到的控制请求不能提交到新会话
- **AND** 同事显式重新 `/join <username>` 后才可进入新登记的活动房间

#### Scenario: Relay 重启

- **WHEN** Relay 退出并重新启动
- **THEN** 不把重启前的残留登记当作在线房间；只有存活房主重新建立有效登记后才能按用户名加入
- **AND** 不要求恢复历史消息存储，不以重启静默切换到其他用户名或会话
