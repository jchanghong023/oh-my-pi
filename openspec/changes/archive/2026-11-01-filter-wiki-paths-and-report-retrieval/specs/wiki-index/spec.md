# Spec Delta

## MODIFIED Requirements

### Requirement: Markdown 文档索引

OMP MUST 从文档索引数据库的同一快照交付完整原文与来源，保持既有查询参数及默认行为并允许 Wiki 工具使用可选路径范围，按可用能力在内部融合全文与语义召回或回退全文，并按固定分页和游标规则处理变更与失败；数据库打开、空库创建、无索引错误及空状态展示保持 HEAD 基线。

#### Scenario: Markdown 文档索引的详细边界

- **WHEN** 本节所述功能在适用条件下运行
- **THEN** 以下具体约束适用：

- **Rust 文档索引内核**：独立的普通 Rust 库 `crates/pi-wiki` 负责 Markdown 文件发现、忠实移植既有共享解析器语义的词法解析／章节切分、文档哈希、数据库 schema／旧库迁移、索引生命周期与导入／发布／回滚，以及全文查询分析、技术名称边界与切分上下文恢复、SQLite FTS5／BM25、全量排名、完整排名缓存、快照版本、游标和正文／来源读取；内核不依赖 N-API、`pi-natives` 或 shell，通过已有 `pi-walker` 与 `pi-vfs` 复用匹配器和文件锁。`crates/pi-natives/src/wiki/` 保留 N-API 薄绑定、Owner／取消／回调适配，以及依赖 JS 值和对象身份的页预算、同页去重、证据渲染、UTF-16 展示过滤与可取消的成功时长下限等待；异步操作复用 `grep` 的 native/N-API blocking-task 机制，仍通过单一 `.node` 发布，原全文／grep 不保留 TypeScript 第二实现。TypeScript engine／service／tool 继续承接宿主路径、参数 schema、会话、IPC／服务子进程、UI、logger 与取消／释放边界；新增语义、融合与可选精排优先复用 OMP 已有 Embedding／rerank 客户端、向量包装与 RRF，向量数值计算复用既有 Rust 原生能力，不为全 Rust 而重写已有轻量逻辑。既有 TS 公开名称、原有参数、结果结构、对象身份、回调与取消、正文／引用及有效旧全文游标身份不得被破坏；Wiki 工具可增加可选路径参数并在结果文本中展示实际检索状态，现有全文索引无需重建；普通搜索的自适应策略与可选模型调用按本次新增要求执行，数据库打开与空状态等其余既有合同保持。
- **共享数据库页读取**：wiki 查询连接默认请求最多 500 MiB 的 SQLite 内存映射读取；多个进程访问同一实际数据库文件时，由操作系统复用文件页面、按需加载并回收。保留原有 SQLite 私有页缓存与进程内排名缓存规则，不为每个进程新增大额堆缓存，不改变导入／删除、读快照、完整结果或游标。映射范围受 SQLite／平台支持限制，不是单进程或整机内存硬上限；正常关闭服务须释放映射与数据库句柄。
- **数据库与构建身份**：打开连接前后须确认同一实际数据库文件；导入租约、隐藏构建回收与创建、提交、发布与回滚须绑定原数据库身份，不能仅凭可复用的行 ID 操作其他构建或已发布索引。取得租约后替换数据库必须在回收或创建前拒绝；回调期间替换数据库、取消或关闭服务不得修改替换库中的既有证据。向量派生数据与其公开代际也受同一实际语料身份约束。
- 索引管理只有两个命令：`omp docs init "<dir>" --name "<name>"` 新建（同名已存在直接报错）与 `omp docs remove <name> --force` 删除；没有 list/status/更新/重建等其他命令入口（`/wiki` 面板会列出已有索引供检索，并可直接发起这两个动作），索引也不记录状态或时间戳。删除只删数据库中的索引及其派生向量，不删源文件。必要的模型身份和向量代际元数据不构成新的用户索引状态或维护入口。
- 文档重新导出后，刷新方式固定为「先 remove 删除旧索引，再 init 新建」。本 fork 只维护这两个命令：新增其他索引维护入口属于超出当前契约的范围，NEVER 引入。可选向量准备纳入既有导入授权，不在查询时自动建库或补算。
- **普通搜索（默认 `mode="search"`）**：保持关键词或自然语言问题直接输入，无布尔、引号或通配符语法（`AND`/`OR`/`*` 等按普通字符处理），不根据输入自动启用正则。有有效 Embedding 配置及当前 Wiki 语料的可用向量索引时，在内部融合既有全文召回与语义召回；缺少任一条件或可选向量路径不可用时使用既有全文搜索，不因缺少向量能力报错。全文或 RRF 基础排名可在有独立配置且可用的 Reranker 时进一步有限精排；无重排能力或精排失败时保留基础排名。除 Wiki 工具的可选路径范围外，不新增语义／精排查询参数、公开模式或前端开关。
- **全文分支技术相关性**：继续使用 SQLite FTS5 全文检索。优先返回同时覆盖所问技术主题、连续词组与当前章节标题的实质正文，不能让泛化描述、功能词或仅因全部词元出现的章节压过技术证据；代码片段（包括围栏及缩进代码）中形似标题的文字不算当前章节标题，技术主题不能误当功能词。同级使用相关性及 BM25 排序。拉丁词与数字按整词匹配，中英粘连仍保留拉丁词；汉字串按原样相邻 bigram 分析，功能词整词丢弃，超过 32 个词元等距取样保留首尾。全文分支的排序覆盖整个匹配集，并用存储正文补足完整名称召回；NEVER 因语义候选预算、有界全文候选窗口、评分文本截断或单页预算遗漏后续全文证据。
- **完整名称**：识别用户输入的文件名、标识符、选项、路径等技术名称（如 `mbist_check.rpt`、`std::vector`、`--flag`、`foo_bar`、`E123`、`ERR-123`、`C++`）；独立输入的非汉字标识符／命令（如 `hisms`、`scan`）同样按完整名称处理，普通多词文本（如 `git status`）仍按词组／自然语言检索，不新增语法。名称保留内部标点，忽略大小写；自然语言句子的结束标点不属于名称（如 `Explain mbist_check.rpt.` 的末尾句点），独立输入的 `mbist_check.rpt.` 则仍保留字面句点。完整名称边界须结合数据库中保存的相邻切分语境判断，不能把人为分段边缘当作名称结束；更长标识符、扩展名、命名空间或版本中的局部字串不能冒充完整命中（如切分后的 `C++` 仍不能冒充 `C++17` 的完整名称）。`match=exact-name` 的完整名称证据排在所有 `match=related` 相关章节之前；散落词元、去掉内部标点、只匹配部分名称或只有向量相似度只能算相关命中。没有完整名称命中时明确输出 `未找到完整名称命中`，即使存在相关章节也不能改称完整命中。RRF 与可选精排均不得改变这些事实与类别优先级。
- **显式 grep 模式（`mode="grep"`）**：`query` 按正则表达式处理，复用现有 grep 的 Rust 正则／PCRE2 引擎；Rust 不支持的合法表达式交给 PCRE2，两个引擎均拒绝时明确报非法正则，不采用文件 grep 的转义修复或字面量回退。`case` 默认 `true`（区分大小写），`false` 忽略大小写，仅用于 grep 模式。扫描所选已导入语料的数据库原始 Markdown，不依赖 FTS 候选、归一化文本、原文件或文件 grep 的 4MiB 上限；只返回实际正则命中的章节，标注 `match=regex`，按索引／文档／章节的固定来源顺序分页，不混入相关章节或完整名称判定。grep 不进行模型解析、调用、语义召回或融合；无索引错误与正常零命中行为沿用 HEAD。
- **grep 匹配边界与范围**：逐原始行匹配，不提供跨行模式、布尔查询语言或精确出现次数；`AND`／`OR`／`NOT` 不是布尔运算符，正则分组、`|` 和边界按引擎语义解释。恢复同一文档存储切片之间的连续原始行并去除重叠，不能把人为切分点当作 `^`／`$`、漏掉跨切片的单行匹配或只靠 500 字符重叠保证召回；命中范围涉及的存储章节均可到达。grep 保留表达式首尾空格，不静默截断；超过 500 个 UTF-16 单元明确报错。合法零命中正常成功，数据库扫描与页后等待均可取消，不预先承诺性能提升。
  - Rust 内核的 grep 校验拒绝空字符串及纯空白 query；这与将有效正则原样传给 matcher 是不同边界。含非空白内容的合法正则仍保留首尾空格，GUI 不得通过 trim 改写其匹配语义；不需要修改 Rust 原生语义。
- **连续分页**：只读 `wiki` 工具仍接受必填 `query: string` 与可选 `mode: "search" | "grep"`、`case: boolean`、`cursor: string`、`path: string`，不增加 `semantic`／`hybrid` 模式或额外算法字段；多个索引时覆盖全部已导入索引，`/wiki` 面板只搜索所选索引，`/` 发起内部自适应的默认检索、`g` 发起 grep。页脚给出本次实际结果集合的章节总数及「还有结果 + 按任务调整查询范围的提示 + 下一次调用参数」或明确耗尽；全文回退和 grep 的集合仍为全部匹配，融合集合为全部全文匹配与本次语义候选的去重并集，精排不得删改集合，不宣称枚举全部可能语义相关章节。新查询可按任务调整范围且不带旧游标；继续遍历当前结果集必须保持原 query、模式、有效大小写选项和路径范围并原样传回游标。游标绑定有效查询、检索模式／大小写选项、索引范围、可选路径范围与数据库逻辑版本；融合查询还绑定实际排名所用的向量代际、模型身份与内部召回策略，精排查询还绑定本次实际精排状态、重排模型身份和候选策略。原全文检索的有效旧游标身份保持不变，关闭再打开服务仍可续页，不因新查询可使用融合或精排而改变旧续页。损坏、跨查询／模式／选项／索引／路径或过期游标报错，不伪装成零命中。每页的版本、命中、计数、完整正文与来源来自同一读快照，数据库变化不能拼接旧来源与新正文。
- 分页顺序固定且与单页预算无关；连续页按序推进，每个匹配章节及来源恰好到达一次，不跳过放不下的下一节。常规工具页目标约 4000 字符（正文、定位、页头与续页信息均计入），每次最多 10 节；每页第一节即使超限也完整返回并标注，其他节放不下就留至下一页，不截断正文。默认检索 `query` 超过 500 字符先截断并带省略号，再用于全文、Embedding、可选精排与回显，续页使用该有效 query；grep 不适用此截断规则。入库章节上限仍为 18000 字符。逐字重复的长正文（超过 200 字符）可指向**同页**已完整展示的正文，但每个来源定位仍须保留；跨页重新提供完整正文，重复来源、仅标题章节及旧库结构标签都必须可遍历，不能被折叠或预算永久隐藏。
- 结果尚未耗尽时，在相同快照及固定顺序下为部分未展开章节列出索引名、路径、行号和标题线索，最多 10 条，并报告剩余、已预览和未列数量。线索连同页脚计入约 4000 字符目标；定位过长可截断，预算不足时可不显示线索但仍报告数量及续页参数。线索不是完整正文，不能代替证据引用，也不推进游标；续页仍从首个未完整交付的章节开始。
- `/wiki` 命中详情须能遍历完整存储正文：长行按当前宽度折行，通过方向键、PgUp/PgDn、Home/End 滚动，缩放终端后仍可到达正文尾部；来源与列表标签可以限宽，不能用限宽丢弃正文。
- **非阻塞与取消**：查询、续页及索引列表／删除不能在交互线程执行数据库工作、向量计算、模型等待或阻塞输入和渲染；`/wiki` 显示加载、搜索、删除或导入的实际操作状态，任何操作进行期间均可用 `c` 或 `Esc` 直接取消，不等待关闭确认，关闭面板也取消未完成操作。工具与对话宿主传递调用方取消信号；取消须及时结束该调用，不重试、不回落到交互线程同步搜索，也不把用户取消解释为向量或精排不可用后交付基础结果，迟到结果不能覆盖新请求。排队请求的取消不影响正在执行的其他请求；会话结束、切换 profile／数据库或服务关闭须释放其自有执行资源，不能泄漏后台进程或继续交付结果。续页失败／取消保留原结果页及所选命中的存储正文，不清空已有证据。
- **完整排名复用**：服务在存续期间有界保留按有效查询、索引范围、可选路径范围和数据库快照绑定的**全部实际结果排名**；同一未变化查询的再次读取或续页不重复全库扫描／排序，只读取当前页所需的完整正文与来源。融合或精排续页复用同次检索已确定的候选和最终顺序，不逐页请求 Embedding／Reranker、扩大候选、重新融合或精排。容量限制只能淘汰整个查询，不能截掉证据尾部；不以时间 TTL 代替真实数据库变更判断。导入／删除、原始 SQL 或 FTS 修改、外部提交、数据库文件替换以及关闭再打开后，必须重新确认逻辑版本和读快照，不能复用陈旧／混合证据或把并发变化后的版本标给旧排名。原全文／grep 的缓存淘汰或服务重开不改变游标身份：版本未变仍可续页，版本变化则明确报过期。融合或精排续页仅能复用或重现原排名；所需上下文不可重现时按现有游标失效边界要求重新查询，不能中途静默回退并交付另一顺序。页间不持有读事务。
- **持久化查询投影**：新导入文档在原有文档事务内预计算并保存查询无关的 Markdown 评分字段、规范化名称轨道及压缩的原字节来源映射；查询不再重复解析全部 Markdown。旧库首次打开时仅从数据库内已保存的原文自动迁移至 schema 12，不要求源目录或重新导入；schema 11 升级不重建未变化的 FTS。后续为可选向量增加的兼容存储迁移仍不得更改既有正文、来源和全文结果，不能因旧库没有向量要求先重建全文。投影会增加数据库空间并产生一次性准备成本，必须与迁移后的查询耗时分开报告，不隐藏首次准备等待。
  - 预计算与即时算法须在完整召回、排名、完整名称边界、Unicode 规范化、跨切片／重叠／缺口、链接标签与目标及旧版坐标语义上等价；不截断候选或正文，不保存逐命中位置数组。数据库内容未变时，既有全文游标与完整证据摘要保持一致。
  - 原始 SQL 对章节的增删改、归属变更及 ID 替换必须使受影响文档的投影失效，包括关闭外键或递归触发器的写入；缺失投影按原有算法现算，不能使用陈旧投影。无效版本、损坏或非法来源映射明确报错，不静默伪造结果。FTS 修改继续使排名缓存失效；文档事务失败／取消和索引回滚不留下已发布的派生数据。与正文不再一致的向量同样不得参与召回。
- **成功查询时长下限**：对外每次成功搜索（工具与 TUI，含融合、全文回退、续页和正常零命中）的总时长必须 **≥500ms（不少于 500ms，并非不超过 500ms）**。实际查询与页预算完成后，仅在不足下限时以可取消的异步等待补足，并按单调时钟复核；不能阻塞交互线程、在等待时持有数据库事务、将等待伪装成数据库工作或将下限用作缓存 TTL。运行诊断日志须区分真实执行工作、下限等待与对外总时长，沿用现有日志，不新增永久审计记录。错误和取消立即返回，不补足 500ms。
- **零命中与错误**：已有可查询索引时，正常无匹配返回成功结果，明确说明「在本次检索的已导入语料中 0 matches」及结果已耗尽，不证明知识或规定不存在；技术名称无完整命中仍按上条标注。缺少／空白 query、非法正则、非法或过期 cursor、无索引、全文数据库损坏及其他基础检索的实际操作故障仍按既有合同报错；缺 query 的错误指出收到的参数名和示例，无关额外键按现有宽松参数处理忽略。数据库不存在时仍按 HEAD 打开规则创建空 WAL 库并报告无索引，不改成正常零命中，不新增缺库／空库的返回或展示区别。可选向量或精排故障不改变这些基础错误，也不得被误报为全文无匹配。
- 默认非受限会话在 `tools.xdev=true` 时将 `wiki` 作为低频只读设备挂载：通过 `read xd://wiki` 按需读取说明与 schema，通过 `write xd://wiki` 携带 JSON 参数执行查询，不在顶层工具 schema 中常驻；`tools.xdev=false` 时仍作为顶层工具提供。显式工具清单继续按原生顶层工具暴露，受限清单不被扩大；仅改变展示与派发入口，不改变权限、查询、分页、取消或生命周期语义。
  - 设备查询保留原生只读工具的独立审批和共享调度：`tools.approval.wiki` 的显式策略仍生效，未配置时不继承 `tools.approval.write` 的拒绝／询问策略；同轮独立查询可以并发，不因 `write` 传输变为独占。普通文件写入和其他设备仍沿用原有审批及调度规则。

- 被强杀的中断导入留下的隐藏半成品索引（面板不可见、无法按名称删除）会在下一次 `init` 枚举到非空语料后回收，避免它长期占用空间。
- 数据库保存完整 Markdown 文字、原始路径和行号；导入成功后，查询、续页与引用的正文和来源只读取当前 Wiki 数据库，不再依赖或访问源目录，不检查源文件新鲜度，不自动同步。全文导入、基础全文结果和 grep 不需要模型、凭据、向量、结构化提取或用户 schema；可选向量准备与默认搜索中的语义分支可以调用已配置 Embedding，普通搜索的可选精排可以调用独立配置的 Reranker，但不能用模型输出替换存储原文或命中事实。grep 不调用任何模型。图片、附件及链接目标不随文字入库；路径和行号对应导入时的版本。

- 只丢弃明确的转换器 `Cell` / `Row` 空标题，英文单词技术标题同样保留；标题本身即内容的需求／清单条目以「仅有标题」标注并保留完整存储文字。同一命中类别内优先独立正文，再返回重复来源；完整名称类别始终先于相关类别。
- 每个命中的定位信息包含索引名、相对路径、行号、原文档 SHA-256 和 `sectionId`；索引名区分同名路径，文档指纹区分导入版本，不能把会随 remove+init 复用的 `sectionId` 当作永久引用。回答直接依据数据库返回正文，引用索引名 + 路径 + 行号，并保留版本身份；有冲突时列出各自证据，不回读源文件补证。
- 验收须覆盖技术主题／词组／本节标题相关性、大小写与标点及名称边界、窗口之外的全文证据、全部连续页的完整正文和来源、超长首节／重复来源／仅标题／旧库标签、既有空库创建与无索引错误、正常零命中与参数／游标／全文数据库错误，并从真实 CLI 和 TUI 完成 DB-only 查询、续页与引用。还须覆盖大语料查询／续页时输入与渲染可响应、活动／排队取消与资源释放、失败续页保留证据、同快照完整排名复用及数据库变化／淘汰／重开后的游标一致性，以及成功对外时长 ≥500ms、等待可取消和工作／等待／总时长分离。新增 Embedding／Reranker 可用性组合、查询向量失效与部分代际不兼容的分级回退、RRF、有限精排不丢证据、模型身份与向量代际、跨语言相关性和真实模型质量验收按新增要求执行；模型 stub 不能代表真实语义或精排质量。
- grep 验收须覆盖显式模式与默认技术名称对照、原始标点／大小写、Rust 正则与 PCRE2、FTS 候选之外的命中、非法／过长正则与合法零命中、CRLF／Unicode／重叠及长行跨切片匹配、真实行首行尾与伪切分边界、全部稳定连续页及模式／大小写游标隔离、缓存复用与快照变更、取消及 DB-only 的真实工具／CLI／TUI 入口，并确认不调用 Embedding 或 Reranker；测量实际扫描与缓存续页成本，不把局部数据或正常时长下限当作性能提升证据。
- 上游文档树内的 `docs/tools/wiki.md` 是 fork 新增文件：上游测试 `docs-tool-coverage` 要求每个内置工具都有 `docs/tools/<name>.md`，`wiki` 是 fork 新增内置工具，同步时该文件 MUST 保留。
- 全文导入全量成功后才公开索引，全文失败或取消不留下可见半成品；旧版全文或结构化数据库自动迁移，保留原文章节和全文检索，移除结构化数据。可选向量准备失败不能使成功的全文导入不可用，也不能留下被当作完整向量索引使用的半成品。
- Markdown 围栏中的标题不拆分章节，包括普通／有序列表、嵌套列表及引用中列表的围栏；列表或引用容器结束后须恢复根章节识别，超长分片与重叠长行仍保留原代码语境。结束围栏须使用相同字符、长度不少于起始围栏且后面仅有空白；支持 ATX/Setext 标题，CRLF 原文保持原始换行；Linux 上仅大小写不同的文档保持独立，终端展示过滤控制字符。已有错误章节边界不自动重切或回读源文件；需要纠正时由用户显式 remove → init 重新导入。

#### Scenario: Markdown 文档索引的可观察行为

- **WHEN** 已导入索引后执行搜索、grep、续页或取消
- **THEN** 从文档索引数据库的同一快照交付完整原文与来源，普通搜索在可选向量能力可用时内部融合、不可用时全文回退，再按独立可选的精排能力处理基础排名；grep 保持原始行正则语义，按固定分页和游标规则处理变更与失败。

### Requirement: Wiki 语义召回的模型与语料身份

OMP MUST 将向量仅用于当前 Wiki 存储章节的语义召回，复用已有 Embedding 配置与请求能力，以实际模型、维度、编码约定和语料版本识别向量。查询向量无效时 MUST 整体回退全文；已存向量不兼容时 MUST 排除其所属索引代际，其余完整有效代际仍可融合，仅无剩余有效代际时整体回退；除 Wiki 工具可选路径范围外不得增加语义模型控制参数，亦不得发送凭据到其他地址。

#### Scenario: 使用已配置的本地文本模型

- **WHEN** OMP 已显式配置兼容的本地 Embedding 服务和模型，当前 Wiki 有与该配置匹配的已发布向量索引
- **THEN** 普通 `search` 在内部为有效 query 生成查询向量，以向量相似度召回当前范围的章节，并将候选交给融合；不要求用户更改 query、增加参数、切换工具或启用 Mnemopi 记忆系统。
- **AND** 本地配置不被公司默认模型覆盖，不继承应仅用于公司端点的 Token。

#### Scenario: 公司 Embedding 复用既有身份规则

- **WHEN** 在 company lane 中解析到适用的现有公司 Embedding 配置，且没有更高优先级的显式本地或通用 API 配置
- **THEN** 按既有端点、凭据缓存和显式配置优先级调用公司模型，不另建公司认证、发现或公网回退链路；该行为不启用或修改记忆系统配置。

#### Scenario: 查询向量无效时整体回退

- **WHEN** 本次查询向量包含非有限值、零范数、与当前模型不一致的维度，或其实际模型、端点身份、编码约定与当前配置不一致
- **THEN** 本次普通搜索整体使用全文基础结果，不将查询向量补零、截断或混入其他模型空间检索，不伪造相似度；既有正文、向量和用户配置不因只读查询而被覆盖，可选精排仍按独立合同处理。

#### Scenario: 已存向量不兼容时仅排除所属代际

- **WHEN** 查询向量有效，但所选索引中部分已存向量存在非有限值、零范数、维度错误，或其模型、端点身份、编码约定与当前配置不兼容
- **THEN** 仅排除这些向量所属的索引代际，不将其补零、截断或与其他模型空间混用；其余完整有效代际继续参与语义召回和融合，全文分支仍覆盖全部所选索引及可选路径范围内的全文匹配。
- **AND** 没有剩余完整有效代际时才整体使用全文基础结果；例如 A 索引使用当前模型、B 索引使用旧模型时，只排除 B 的向量，不丢失 A 本可召回的语义证据，B 的全文证据仍可到达。
- **AND** 1024 维的本地 Qwen3-Embedding 向量不能与 2048 维的公司 Qwen3-VL-Embedding 向量混用；即使未来两个模型输出同维度，也不能据维度相同认作同一模型空间。原文、已存向量与配置不因本次排除被覆盖。

#### Scenario: 向量来源不属于当前 Wiki 证据

- **WHEN** 候选向量来自另一 profile、另一个数据库身份、已删除索引、其他文档版本，或只是记忆系统中的相似内容
- **THEN** 不得作为当前 Wiki 命中返回，不因 sectionId 被复用而关联到新正文；没有其余有效向量候选时继续使用当前 Wiki 的全文结果。

#### Scenario: 向量召回不改写证据

- **WHEN** 语义候选进入最终结果
- **THEN** 返回对应存储章节的完整原文、索引名、路径、真实行号和文档哈希，不将模型输入裁剪片段、向量、生成摘要或假设答案作为原文证据，不回读源文件补证。

### Requirement: Wiki 普通搜索的内部自适应与 RRF 融合

OMP MUST 保持既有 `search` 参数及默认行为并允许 Wiki 工具使用可选路径范围，根据当前语料的有效向量与 Embedding 可用性内部选择融合或全文基础排名。融合 MUST 使用基于各路名次的 RRF，不直接相加 BM25 与余弦分数；缺少可选能力不报错，基础排名可继续接受独立可选精排，grep 不参与该流程。

#### Scenario: 模型和向量索引同时可用

- **WHEN** 调用方只提交既有合法普通搜索，当前范围存在匹配当前模型的有效向量索引，且查询 Embedding 成功
- **THEN** 同时使用原有全文召回和语义召回，将来源相同的章节按实际证据身份去重，使用各路名次的倒数秩贡献求和得到 RRF 基础排名；基础路径不要求额外聊天模型、查询扩展、HyDE 或专用 Reranker，有可用 Reranker 时再按可选精排合同处理。
- **AND** 内部候选预算与融合常量由 OMP 管理，不新增 `semantic`／`hybrid` 模式、typed query 语法、客户端算法开关或必填参数。

#### Scenario: 模型与向量可用性的不同组合

- **WHEN** 已有可查询的全文库，但缺少模型、缺少有效向量索引，或者两者都没有
- **THEN** 相同调用正常得到既有全文基础结果，其命中、基础排名、名称判定、总数和分页与原全文路径一致，不报“没有向量模型／数据库”，不先调用一个已知缺席的服务，也不返回伪造的语义命中；没有可用 Reranker 时直接使用该基础结果，有可用 Reranker 时允许独立精排。

#### Scenario: 可选模型请求在查询中失败

- **WHEN** 新查询原本具备融合条件，但 Embedding 服务无法连接、请求在既有有界调用中失败，或响应不能用于语义召回
- **THEN** 保留本次同快照的正常全文基础结果，不向用户抛出该可选向量故障，不清空已有全文命中，不追加新的无界重试策略；后续可选精排同样不能成为基础结果可用性的前提，不因此掩盖全文数据库本身的错误。
- **AND** 复用现有日志按适用的 offline 级别记录有界故障信息，不记录查询正文、文档或凭据，不建立平行审计或遥测系统。

#### Scenario: 有效语义分支没有候选

- **WHEN** 查询 Embedding 成功，但本次没有合格语义候选，而全文存在匹配
- **THEN** 保留原全文基础结果与原有顺序，不以空向量结果覆盖全文，不因只有一路而进行无意义的 RRF；是否执行专用精排只由独立的可选 Reranker 合同决定。

#### Scenario: 全文无命中但语义召回有效

- **WHEN** 当前全文分支无匹配，但有效向量索引召回了语义相关的存储章节
- **THEN** 返回这些章节的完整真实证据，标为相关命中而非全文词面或完整名称命中；例如中文问题可以召回没有相同中文字面的英文技术章节。

#### Scenario: 多索引中的向量覆盖不完整

- **WHEN** 当前查询范围包含多个 Wiki 索引，只有其中一部分有与当前模型匹配的完整向量代际
- **THEN** 全文分支仍覆盖全部所选索引及可选路径范围内的全文匹配；只对有有效向量的语料做语义补充，不静默排除没有向量的索引，也不混合不兼容模型空间。

#### Scenario: 用户取消不是全文回退条件

- **WHEN** 调用方在 Embedding、向量检索、融合、可选精排或等待阶段取消操作
- **THEN** 整个请求按既有取消合同结束，不将取消转为模型不可用并继续全文搜索，不交付取消后的迟到结果。

#### Scenario: 显式 grep 与模型完全隔离

- **WHEN** 调用方提交 `mode: "grep"`，无论是否存在模型、向量、模型故障或 company lane
- **THEN** 只执行既有正则校验与数据库原始 Markdown 扫描，不解析模型凭据、不发 Embedding 或 Reranker 请求、不做 RRF；其大小写、来源顺序和完整正则匹配合同保持。

### Requirement: Wiki 融合结果的完整证据与稳定续页

融合及可选精排 MUST 保留查询范围内全部原全文命中和真实来源，明确语义部分只覆盖本次内部候选集合，精排只调整有限候选顺序而不改变结果集合。整个分页会话 MUST 绑定一次实际召回与最终排名，不能因模型可用性变化、页预算或缓存变化在中途切换顺序；除 Wiki 工具在结果文本中报告实际检索与精排状态外，现有查询与结果结构不增加算法控制字段。

#### Scenario: 全文证据超过语义候选预算

- **WHEN** 全文匹配数超过内部语义 top-k 或单页预算
- **THEN** 所有全文匹配仍进入本次实际结果集合并可连续遍历，不只对全文前若干条做融合或精排后永久丢弃其余章节；语义预算只限制额外的语义召回，精排预算只限制处理窗口，均不限制原全文证据。

#### Scenario: 完整技术名称优先于相关语义

- **WHEN** 查询 `mbist_check.rpt`、`std::vector`、`scan`、`C++` 等技术名称，候选包括完整名称和 `.rpt.bak`、更长标识符或 `C++17` 等相关章节
- **THEN** 依照现有完整名称边界判定事实，全部完整名称证据先于仅相关证据，RRF 与可选精排均不能升级部分名称或仅语义相似的候选；没有完整命中时仍说明未找到完整名称命中。

#### Scenario: 去重不丢来源

- **WHEN** 同一存储章节同时被全文与向量召回，或单一路径重复返回该章节
- **THEN** 最终集合只保留该章节一次，每一路只贡献一次有效名次；不同索引或不同来源的相同正文仍保留各自定位，继续遵守已有同页正文去重规则。
- **AND** RRF 同分时按稳定来源身份决定顺序，相同召回输入不因容器枚举或页大小改变排序。

#### Scenario: 结果计数和耗尽表述

- **WHEN** 融合结果被交付给工具、SDK、TUI 或 RPC
- **THEN** 保持现有结果字段，`total` 表示范围内全部全文命中与本次有效语义候选去重后的章节数，`hasMore` 与 `cursor` 仅描述该固定集合；正文说明其范围，不宣称已穷尽所有可能语义相关的章节。
- **AND** 全文回退与正常无匹配按既有结果结构表达；无索引仍按 HEAD 的错误与展示合同处理，不改成正常空结果，不新增客户端算法或空状态字段。

#### Scenario: 续页时模型暂时不可用

- **WHEN** 首次搜索已确定基础或精排后的最终排名，后续 Embedding／Reranker 服务停止或配置可用性改变，但同一排名和证据快照仍可合法复用
- **THEN** 从既定集合继续分页，不逐页调用模型、扩大候选、重新融合、重新精排或转为另一顺序，页中正文和来源仍来自原快照。

#### Scenario: 续页上下文不能恢复

- **WHEN** 融合或精排后的最终排名已被淘汰或服务重开，且无法合法重现原召回与精排上下文，或者文档／向量代际、实际使用的 Embedding／Reranker 身份、精排状态或内部候选策略已与游标不一致
- **THEN** 按已有游标错误边界明确要求重新查询，保留当前已显示证据，不把另一条全文排名接到旧分页后面，也不伪装成正常零命中。
- **AND** 调用方不带旧 cursor 发起的新搜索重新按当前条件选择全文或融合，缺少模型本身不导致新查询失败。

#### Scenario: 原全文游标在新版本中续页

- **WHEN** 升级前签发的有效全文游标仍与相同语料和有效 query 匹配，即使当前环境新增了可用模型和向量
- **THEN** 继续原全文结果顺序与身份，不自动提升该分页会话为融合或精排，不因可选模型能力上线使原有未变化全文证据不可到达。

### Requirement: Wiki 语义能力复用与可观察验收

新增能力 MUST 优先复用 OMP 已有 Embedding／rerank 客户端、配置身份、Rust 向量计算和 RRF，继续经同一 Wiki 服务交付给所有消费者；不得安装 QMD、复制第二套全文或向量引擎，基础搜索不得强制依赖额外模型。验收 MUST 分离确定性合同与真实模型质量，不以推测代替大语料成本测量。

#### Scenario: 同一既有接口覆盖所有消费者

- **WHEN** Agent 顶层工具或 `xd://wiki`、DocsService、TUI、RPC 对同一 profile 与相同语料发起等效查询
- **THEN** 使用相同的内部选择、模型身份、RRF、可选精排、缺库与回退事实；前端不自行启动模型或实现搜索；Wiki 工具按本变更合同提供可选路径参数及结果文本中的实际状态，TUI、RPC 不需新增方法、参数、模式、开关、结果字段或必填配置。

#### Scenario: 在现有能力上集中复用

- **WHEN** 接入向量准备、向量打分、融合和可选精排
- **THEN** 保留现有 Rust 全文／grep 内核及单一原生发布方式，数值计算复用已有批量 Rust 向量能力，Embedding／rerank API 和 RRF 仅提取或扩展必要公共能力；不为 Wiki 复制记忆系统、全套模型运行器、请求重试、配置解析或向量数学实现。
- **AND** 不引入 QMD CLI／SDK／MCP、外部常驻向量数据库或自研 ANN 作为必需依赖，不为追求全 Rust 重写已经适用的轻量宿主逻辑。

#### Scenario: 确定性合同覆盖

- **WHEN** 后续对本变更进行实现验收
- **THEN** 复用现有测试约定覆盖 Embedding／向量存在性组合、查询向量失效时整体回退、部分已存代际失效但其余代际继续融合、全部代际失效时全文回退、Reranker 缺席／成功／故障／无效响应、全文与 RRF 基础结果的可选精排、可选分支失败回退、既有空库创建与无索引错误、非法调用仍失败、技术名称优先、RRF 跨路融合与单路去重、有限候选不丢全文尾部、版本与模型隔离、分页变化、取消和 grep 无模型调用等可观察行为，不测试静态源码文本或仅复制字段。

#### Scenario: 真实本地模型的语义质量

- **WHEN** 后续在已配置本地服务的环境评估语义检索
- **THEN** 使用实际 Embedding 响应和有明确相关章节及干扰项的代表性语料，分别检查同义表述、中文问题对英文技术证据、术语相似但含义不同的情况，并对照同语料纯全文基线报告 Recall@k／MRR 等适用结果；不将一个样例、固定余弦分数或模型 stub 作为整体质量结论。
- **AND** 本次对话中的本地地址、模型别名和 1024 维观察仅为可用验收环境，不硬编码为所有用户的默认值；缺少真实服务时如实记录未执行，不影响基础检索的确定性验证。当前开发机器无 Reranker 时不要求安装，真实精排质量留给具备已配置重排服务的环境验证，不用模拟响应冒充真实质量结论。

#### Scenario: 规模与资源测量

- **WHEN** 后续评估代表性大语料
- **THEN** 分别记录向量构建成本、存储与内存、基础召回、可选精排和续页成本；首次模型加载与预热后结果分开，真实工作与既有 500ms 等待分开，不由 Rust 实现或精确扫描推断 100GB 场景一定可用或更快。

### Requirement: Wiki 可选精排与基础排名回退

OMP MUST 将 Reranker 作为普通搜索基础排名之后的独立可选增强，优先复用现有 rerank 调用能力。未配置、不可用或响应无效时 MUST 保持本次基础结果和顺序；成功时仅调整有限候选顺序，不修改证据、命中类别和结果集合，不新增精排控制参数或开发机模型安装要求；Wiki 工具可选路径筛选及实际状态展示按对应合同处理。

#### Scenario: 当前开发机器没有重排模型

- **WHEN** 普通搜索已得到全文或 RRF 基础结果，但当前执行端未配置可用 Reranker
- **THEN** 正常返回基础结果和原有顺序，不报告缺少重排模型，不为了探测而请求猜测端点，不自动下载、安装或启动重排模型；无库或基础结果为空时同样不发重排请求。

#### Scenario: 公司环境配置了可用 Reranker

- **WHEN** 当前执行端已配置可用重排模型及其受信任调用地址，并且普通搜索有候选正文
- **THEN** 复用 OMP 现有 rerank 客户端、认证与取消机制，对有效 query 和当前快照的有限候选正文请求相关性评分；无论基础结果来自纯全文还是 RRF，都可以执行精排，不要求同时具有向量索引。
- **AND** 公司 `Qwen3-VL-Reranker-2B` 是已有可选模型来源，不因模型目录中有此名称就假定公司接口已经兼容或可达，不猜测其他路由、不回退厂商公网；显式其他地址不获得公司专用凭据。

#### Scenario: 可选精排请求失败或响应无效

- **WHEN** 重排服务不能连接、既有有界请求失败，或响应包含不能对应候选的索引、重复索引、非有限分数或缺少本次候选窗口所需的评分
- **THEN** 本次不采用精排结果，保持请求前的完整基础结果和顺序，不将故障暴露为基础搜索失败、正常零命中或部分证据丢失，不新增无界重试，也不让无效分数混入实际排名。
- **AND** 按既有日志与 offline 级别要求记录有界失败信息，不记录 query、候选正文、模型响应正文或凭据。

#### Scenario: 有限候选精排不改变证据集合

- **WHEN** 基础结果超过内部精排预算，且候选窗口的精排请求成功
- **THEN** 候选窗口与预算在分页前确定，不依赖页大小；仅在同一既有命中类别内调整该窗口的顺序，窗口外证据继续保持基础相对顺序并全部可达，完整名称仍整体先于仅相关命中。
- **AND** 模型分数同分时保持基础相对顺序，不修改原 `matchKind`、`exactNameMatches`、正文、路径、行号、文档哈希或 `total`，不把重排分数当成事实置信度。

#### Scenario: 成功或回退后的续页保持最终排名

- **WHEN** 首次搜索完成了精排，或因精排缺席／失败确定使用基础排名，并已签发续页游标
- **THEN** 后续页沿本次最终排名推进，不因重排服务后来上线、恢复、停止或模型改变而中途切换顺序，不在每一页重复请求精排；不能恢复同一上下文时遵循原有游标失效边界，而不是拼接另一排名。

#### Scenario: 用户取消可选精排

- **WHEN** 用户在重排请求、结果处理或页后等待中取消调用，或会话／profile／页面生命周期结束
- **THEN** 请求按现有取消合同收口，不将取消视为精排失败后继续交付基础结果，迟到响应不覆盖新结果，释放自有调用资源。

#### Scenario: grep、无索引与零命中不启用精排

- **WHEN** 调用方提交 grep、打开缺库／无索引的只读页面，或有效 query 没有任何基础候选
- **THEN** 不解析或请求 Reranker，不新增模型配置交互；保留 HEAD 的 grep、无索引错误、正常零命中、空状态展示和参数错误语义。

## ADDED Requirements

### Requirement: Wiki 查询的相对路径范围

Wiki 工具 MUST 支持可选 `path`，以已导入的索引内相对路径限定单个文件或目录后代；该范围 MUST 在全文、语义召回及 grep 计算候选前生效，并绑定结果、缓存和续页。省略 `path` MUST 保持既有查询行为。

#### Scenario: 指定单个文件或目录

- **WHEN** 调用方提供不以 `/` 结尾的文件相对路径，或以 `/` 结尾的目录相对路径
- **THEN** 前者只匹配完整相同的文件路径，后者递归匹配该目录下的文件；目录边界不能把相似前缀的兄弟目录纳入。
- **AND** 路径按数据库中保存的相对路径字面匹配，保持大小写和路径组成部分中的空格；通配符、正则以及 SQL 模式特殊字符不获得特殊含义。绝对路径和越过索引根的路径不是有效范围，不读取或探测源文件系统。

#### Scenario: 多索引和已限定索引

- **WHEN** 多个已导入索引包含相同的相对路径，或既有服务调用方已经选定一个索引
- **THEN** Wiki 工具覆盖所有匹配路径的已导入索引，各来源仍分别可达；已有索引选择与路径范围取交集，不新增 Wiki 工具的索引选择参数。

#### Scenario: 所有检索分支遵循范围

- **WHEN** 已指定路径且使用全文、混合检索或 grep
- **THEN** 全文候选、语义 top-k、grep 原始行匹配和精排候选均只来自该范围；范围外候选不能占用有限语义／精排预算或进入结果、总数和未展开提示，不能在分页后才丢弃范围外结果。
- **AND** 范围内全部全文或 grep 匹配按既有合同可续页到达，完整名称优先、原文及来源保持不变。

#### Scenario: 范围内零命中或源目录消失

- **WHEN** 已有可查询索引但指定范围没有文档或没有匹配，或者导入后的源目录已不存在
- **THEN** 只从数据库检索，正常报告范围内零命中及结果耗尽，不声称其他范围没有信息；无索引和基础数据库错误仍按原合同报错。

#### Scenario: 路径范围与分页身份

- **WHEN** 带路径的查询产生续页游标
- **THEN** 下一次调用参数保留相同路径，游标与排名缓存绑定有效路径及既有查询、模式、大小写、索引和快照；修改或移除范围不能复用该游标。
- **AND** 省略 `path` 的既有查询及有效旧游标保持原有身份、结果和续页行为，不能因新增筛选使未变化的旧全文游标失效。

### Requirement: Wiki 查询实际检索状态

Wiki 工具 MUST 在每个成功结果页如实区分实际交付的全文、混合或 grep 结果，并说明最终排名是否采用精排；状态 MUST 绑定该结果集而非当前模型配置或调用尝试。

#### Scenario: 全文、混合及模型故障回退

- **WHEN** 普通搜索只采用全文基础排名，包括未配置模型、没有有效向量、模型请求失败、查询向量无效或有效语义分支没有候选
- **THEN** 报告实际采用全文，不因配置、请求尝试或错误回退声称使用了混合检索；可选精排是否采用独立报告。
- **WHEN** 有有效语义候选参与最终结果或基础排名，即使全文没有命中
- **THEN** 报告混合检索；不将纯语义相关证据标为完整名称命中，也不宣称语义相关内容已全部枚举。

#### Scenario: 精排成功、未使用或失败

- **WHEN** 有效精排响应被应用到有限候选窗口
- **THEN** 报告精排已采用，即使分数相同或最终顺序未变化；未配置、未调用、请求失败、响应无效或没有可精排候选时报告未采用，不改变基础结果与证据。

#### Scenario: grep 和正常零命中

- **WHEN** 显式 grep 成功，或已有索引的有效查询正常零命中
- **THEN** grep 结果明确为 grep 且精排未采用；零命中如实报告实际检索状态且不虚构精排，不将零命中当作无索引错误。

#### Scenario: 缓存复用和连续页

- **WHEN** 同一快照的缓存查询或续页复用已确定的最终排名，且模型配置或服务可用性随后变化
- **THEN** 每页报告原结果集的实际检索和精排状态，不因展示状态重复调用模型或切换排名；无法合法恢复新结果集上下文时遵守既有失效合同。
- **AND** 对仍有效但无法可信恢复状态的旧游标，明确状态未知而非猜测，同时保持旧游标原有可续页行为。

#### Scenario: 状态安全与边界

- **WHEN** Wiki 工具交付状态，或者查询被取消、遇到非法参数或基础数据库错误
- **THEN** 状态不得暴露凭据、查询正文、模型请求或响应正文，也不得触发额外模型探测；取消和基础错误仍按原合同结束，不伪装成成功回退。
- **AND** 状态占用纳入既有页面预算，不截断完整证据或改变首节超限例外；本变更不要求新增 TUI 界面或 RPC 协议方法。
