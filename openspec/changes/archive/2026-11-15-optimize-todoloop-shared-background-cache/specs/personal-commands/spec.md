# Spec Delta

本增量属于已有 `personal-commands` 能力，依赖 [add-todoloop-command 的 TodoLoop 增量](../../../add-todoloop-command/specs/personal-commands/spec.md)，不将该待定变更视为已同步的主规格。本增量仅增加同一文件、同一次 TodoLoop 任务中编排程序直接进行一次公共背景调研及原生 context 复用；不强制重复全量读取未变化的公共材料，不继承执行聊天。执行 task 及其派生工作保持原生能力，可以自主调用 scout，不受程序的一次上限限制。其他前置语义保持不变，本轮不修改前置变更或主规格。

## ADDED Requirements

### Requirement: `/todoloop` 一次公共背景准备的启动边界

OMP MUST 在有效默认执行确认存在未完成组后、首个组执行代理启动前，由 TodoLoop 程序调用已有 scout 做公共背景调研。同一个 todo 文件、同一次任务，程序全程最多直接发起一次该调研，不因换组、部分完成、重试、内部恢复或调研失败再次派发。该上限不作用于执行 task 或其派生工作，不改变它们调用 scout 的原生行为。调研不计入组执行次数，命令参数及原生 TUI 宿主边界保持不变。

#### Scenario: 有剩余组的首次执行

- **WHEN** `/todoloop <路径>` 校验成功且存在至少一个未完成组
- **THEN** 先调用一次已有 scout，再在调研实际结清且精简结果可用后创建首个组执行代理；即使只有一个未完成组，也采用同一契约
- **AND** 程序决定时序及任务选择，主 AI 和调研代理不参与组拆分、排序、推进或重试决策

#### Scenario: 换组及组内接续

- **WHEN** 当前组完成后进入下一组、创建当前组的第二或第三个执行代理，或同一次任务内部恢复
- **THEN** 程序原样复用本次任务已取得的公共背景，不再直接发起公共背景调研、不重置该次数；执行 task 仍只处理本组剩余项，其原生工具及派生选择不受限制

#### Scenario: 执行 task 可以按原生规则派生 scout

- **WHEN** 某组执行 task 或其派生工作按需调用 scout
- **THEN** 沿用原生准入、工具、模型、权限和并发规则，不因 TodoLoop 的一次背景调研而拦截、过滤或收缩这些调用，不添加专属准入钩子或继承限制
- **AND** 一次上限只统计 TodoLoop 程序直接发起的公共背景调研，不统计执行代理自主调用的 scout，也不按模型请求计数

#### Scenario: 预检、非法输入或已全部完成

- **WHEN** 用户执行 `--check`、输入或文件非法，或启动时文件已全部勾选
- **THEN** 沿用原预检、错误或完成反馈，不创建调研或执行代理、不调用模型、不修改文件

### Requirement: `/todoloop` 背景调研只读且范围受限

调研 MUST 使用已有 scout 的只读职责、工具及原生准入，只读取任务文件、必要明确引用和相关源码，识别 Change 时沿用同 Change 提案、已有设计及相关增量材料边界。调研 MUST 保持用户工作区和 checkbox 不变，不实现、提交、生成材料或独立验收；不新增 TodoLoop 专属权限层、递归工具守卫或调研审查代理，不更改 scout 的通用定义。原生会话记录及缓存元数据保留原语义。

#### Scenario: 普通清单与 Change 材料

- **WHEN** 调研处理普通 Markdown、Superpowers 计划或可识别的 OpenSpec Change
- **THEN** 阅读完整任务文件后，仅调查剩余组实际需要的共同背景及明确引用；Change 的可选设计不存在时不生成，不自动执行 apply、规格同步或归档
- **AND** 只在必要范围调查相关源码、接口和约束，不因文件中可见其他目录或链接而取得额外访问权限

### Requirement: `/todoloop` 精简且有来源的冻结背景

调研 MUST 复用 scout 既有交接格式，提炼必要事实、材料来源、范围及未确认项，形成本次任务固定的精简简报。本文背景包仅指该简报，不另定义背景 schema、序列化协议或持久化格式。共享内容 MUST NOT 复制完整调研聊天、原始工具流水、主对话或执行组聊天；空结果不作为可用背景，不新增背景数据库或自动仓库文档。

#### Scenario: 形成可追溯的共同事实

- **WHEN** 调研读取共同需求、项目约束或相关接口
- **THEN** 背景包保留执行所需事实及其来源关系，明确哪些内容已确认、哪些尚需任务内核实；不得以压缩为由删除必要验收、权限或风险边界
- **AND** 原始材料和调研记录仍按原生只读记录可追溯，但不整段注入每个执行代理

#### Scenario: 无额外共同背景或输出无效

- **WHEN** 调研确认无需补充公共材料，或未能形成可用结果
- **THEN** 前者明确说明该事实及其调查范围，不制造占位资料或扩大扫描；后者作为准备失败报告，不以空包静默进入组执行

#### Scenario: 当前组数据变化不改写背景

- **WHEN** 组身份、剩余 checkbox、尝试次数或上次结果发生变化
- **THEN** 这些动态数据进入当次 `assignment`，不回写共享 `context`；当前状态仍以程序最新读取的真实文件为准

### Requirement: `/todoloop` 共享背景的稳定请求前缀

OMP MUST 复用原生 task 的共享 `context`，将同一精简背景传给本次任务全部执行及接续代理；当前组、剩余项、尝试次数和变化事实放入独立 `assignment`。在模型、工具及安全上下文相同的条件下，共同背景前缀保持一致，身份及协作内容沿用原生排列；不得另造提示词体系、覆盖原生规则或为缓存冒用身份。

#### Scenario: 两组及同组接续复用前缀

- **WHEN** 在相同有效模型、工具及权限下派发多个组或同组接续代理
- **THEN** 实际发往模型服务的共同背景前缀保持一致，差异仅出现在后续的当前任务及必要增量内容
- **AND** 验收以真实派发请求内容和原生缓存策略为依据，不以背景包对象相同、字符串引用相同或逻辑 fork 自述代替

#### Scenario: 必须变化的运行身份和任务数据

- **WHEN** 新代理具有不同原生执行身份、组编号、尝试次数或最近错误
- **THEN** 身份及当前任务事实保持真实，不借用另一运行实例的身份；必要的动态提示内容不破坏前面已冻结的公共背景

### Requirement: `/todoloop` 复用原生缓存策略而不依赖命中执行

OMP MUST 沿用已有原生缓存键、显式配置优先级及请求接线，由现有链路决定适用参数；MUST NOT 新增 TodoLoop 缓存开关、模型能力表、Provider 特判、缓存协议、预热或缓存专属重试。未命中、过期或不支持缓存不改变组执行语义，不为命中另行切换模型／账号或提高权限。

#### Scenario: 保持已有缓存与模型行为

- **WHEN** TodoLoop 通过原生链路发送带共享 context 的执行请求
- **THEN** 使用既有缓存配置和原生模型策略，不由 TodoLoop 重新判断或配置模型缓存能力，不覆盖显式设置、不增加为获取命中而发起的请求

#### Scenario: 缓存关闭、服务不支持或返回零命中

- **WHEN** 缓存被显式关闭、当前服务不支持共享缓存，或一个正常响应没有观测到缓存读取
- **THEN** 执行代理仍获得同一背景并正常处理本组，缓存参数继续由原生链路处理；不把未命中当任务失败，也不额外调用模型争取命中
- **AND** 保留既有模型选择和原生请求策略，不声称节省了未被服务证明的 token 或费用

#### Scenario: 真正的配置或 API 错误

- **WHEN** 请求因配置、认证、权限或模型服务错误失败
- **THEN** 按原生真实错误和所属阶段处理，不将错误吞掉或伪装为普通缓存未命中；不增加缓存专属重试次数

#### Scenario: 背景就绪不等于缓存已预热

- **WHEN** 调研完成、背景被冻结，或首个执行组首次发送该背景
- **THEN** 只报告背景可用，不据此宣称缓存已命中或已预热；是否产生缓存写入或读取以服务实际返回信息为准

### Requirement: `/todoloop` 共享背景不得覆盖最新文件事实

执行代理 MUST 在背景包覆盖且材料未变化时复用共同事实，不被强制逐组完整重读同一材料；仍 MUST 读取当前任务文件并核实当前任务所依赖的真实工作区、修改目标和变化材料。冻结背景不是动态源码、权限或 checkbox 的权威，不得以缓存命中跳过必要的最新事实核验。

#### Scenario: 后续组使用未变化的公共材料

- **WHEN** 相关公共材料已被背景包充分覆盖且未变化
- **THEN** 后续组及接续代理直接复用这些事实和来源，不为满足重复读取提示再完整调查；仅按当前项需要补读未覆盖内容
- **AND** 任务文件的原有派发前、运行中及实际结清后的重读和不变量校验保持不变

#### Scenario: 前序组改变共享接口或引用材料

- **WHEN** 工作区当前接口、相关材料或前提与冻结背景不同
- **THEN** 受影响的执行代理按原生能力读取并使用最新事实，将必要更新作为当次任务增量，不修改冻结前缀、不恢复旧工作区、不复制前序组聊天；编排程序不重新发起公共背景调研，不限制执行 task 为当前工作自主调用 scout
- **AND** 无法核实执行必需的最新事实时明确报告实际问题，不将过期背景作为已确认结论继续执行

### Requirement: `/todoloop` 共享事实但隔离执行聊天及作用域

每个组首次执行和每次接续 MUST 继续创建独立的新 `task`，仅复用本次调用的冻结事实底座及当次任务信息；不得继承主对话或其他执行代理完整聊天。背景和缓存复用 MUST 保持原生项目、cwd、profile、认证及权限隔离，不能把可读背景扩大为新的执行或访问授权。

#### Scenario: 不从前一执行组派生聊天历史

- **WHEN** 第一组完成后开始第二组，或当前组未完成而启动接续代理
- **THEN** 新代理获得同一背景、当前组剩余项及允许的简短结果／错误，不获得前一执行代理聊天和工具流水；先前工作区修改保持可见
- **AND** 共享仅限同一精简 context，不将交接结果当作聊天历史继承，也不把逻辑 fork 当作缓存命中证明

#### Scenario: 不同项目、权限或拥有者

- **WHEN** 请求来自另一项目、profile、凭据安全上下文，或会话所有权和权限已变化
- **THEN** 不将本次背景当作另一运行的私有上下文注入，也不借缓存键绕过原生准入；失去当前所有权时按停止及结清规则处理

#### Scenario: 新调用只按文件续做

- **WHEN** 用户结束本次任务后重新输入命令执行同一清单
- **THEN** 视为新的独立 TodoLoop 任务，从最新文件首个未完成组恢复；有剩余组时本次新任务的编排程序最多直接调研一次，全部完成时不调研；同一次任务内部恢复不重置该次数
- **AND** 不依赖旧背景、调研会话或模型缓存恢复任务游标，不做文件终身去重；原生会话记录和缓存元数据保持既有持久化语义，不新增跨任务背景／进度账本

### Requirement: `/todoloop` 准备阶段的失败、取消和真实结清

程序的公共背景调研 MUST 归属本次 TodoLoop 的原生所有权及取消链路，复用已有等待、取消和真实结清机制。成功、失败、超时、用户停止、会话切换和宿主退出均须结清相关执行及归属子工作；准备失败、空结果、无法确认结清或用户取消后 MUST NOT 派发执行组，程序不得再次发起公共背景调研，不新增准备专属状态体系、期限或重试预算。执行 task 自主派生的 scout 沿用原生生命周期。

#### Scenario: 调研有结果但仍有子工作在运行

- **WHEN** 调研返回文本或结构化结果，但自有执行或子工作尚未结清
- **THEN** 沿用原生运行或停止中反馈，不宣布已停止、不启动首个执行组；结果存在和取消标记都不替代实际结清证明

#### Scenario: 调研失败或必要材料不可读取

- **WHEN** 调研失败、必要材料不可访问或结果不可用
- **THEN** 结清自有工作后报告准备失败及真实原因，所有组保持未启动，checkbox 和工作区不被准备阶段改变
- **AND** 该失败不消耗任何组的执行代理次数，不伪造可用背景，程序不再次派发公共背景 scout；原生模型及错误策略保持不变，用户可另行处理后启动新的独立任务

#### Scenario: 用户取消或宿主所有权结束

- **WHEN** 用户按现有停止操作，或会话切换、销毁、宿主退出
- **THEN** 立即禁止新增调研和组派发，取消并结清自有工作；真实结清后才显示已停止，无法确认时报告结清失败，不影响无关会话或回滚工作区

#### Scenario: 准备期间清单被改变

- **WHEN** 调研期间任务文件出现不符合原不变量的修改或无法重新读取
- **THEN** 停止并结清准备，报告文件异常，不从旧快照或背景推断当前任务状态，也不让调研代理修复任务文件

### Requirement: `/todoloop` 共享背景不改变组推进和既有命令

OMP MUST 保留前置 TodoLoop 的标题推断、数字／Step 身份、文件顺序、组间串行、组内连续逐项勾选、每组最多三个执行代理及实际结清后整组检查。程序的背景 scout 不是 checkbox，不替代执行或独立验收。执行组使用原始 task，完整保留原生工具、模型、权限及派生能力，包括调用 scout；不改变无关命令、普通 task 或全局缓存默认行为。

#### Scenario: 部分完成和三次上限

- **WHEN** 某组部分完成后继续派发剩余项，或第三个执行代理结清后仍有未勾选项
- **THEN** 接续只处理本组剩余项且不重置次数；第三次仍未完成时停止，不进入后续组，背景调研不计入本组三次
- **AND** 缓存命中与否、背景是否可复用都不决定 checkbox 推进，不把任务勾选表述为独立代码验收通过

#### Scenario: 普通入口及配置保持原样

- **WHEN** 用户未运行 TodoLoop，或使用不属于本次 TodoLoop 的普通聊天、task、其他斜杠命令及非 TUI 宿主
- **THEN** 不启动背景任务、不注入共享包、不改写其缓存配置或会话身份；原有命令目录、准入、模型、工具、派生、超时及输出行为不变

### Requirement: `/todoloop` 沿用原生记录与展示

OMP MUST 复用原生 TUI、代理记录和错误反馈识别本次 scout 及各次组执行，不新增 TodoLoop 专属状态体系、用量账本、派生费用归集、缓存统计或费用面板。已有原生用量信息保持原语义，不将公共背景可用表述为已命中缓存、独立代码验收或必然节费。

#### Scenario: 调研记录不冒充任务完成

- **WHEN** TodoLoop 程序直接派发的公共背景 scout 启动、结束或失败
- **THEN** 保留其真实原生记录，不增加任务／组完成数，不计入某组的三个执行代理，不伪造当前执行组或尝试次数；执行 task 自主派生的 scout 继续按原生方式记录，不被当作程序超出一次上限
- **AND** 不另建日志／进度界面，不把完整背景、派发包或敏感缓存键刷入主聊天，不调用主 AI 解释或总结

#### Scenario: 不因共享背景新增效果统计

- **WHEN** 原生记录已有缓存或用量信息，或这些信息不可得
- **THEN** 沿用已有渠道及语义，不为本优化补建计量系统，不由相同文本、缓存键或本地模拟推断真实命中、节省量、零费用或不占上下文窗口
