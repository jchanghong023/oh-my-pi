# Proposal

## Why

TodoLoop 的各组及接续代理会重复调查同一批背景材料，增加工具调用和输入开销。上游已有只读 scout、共享 `context` 及缓存接线，本变更只补 TodoLoop 的一次调研与结果复用，不重建这些能力。

## What Changes

- 保留 `/todoloop <路径> [--check]`，不新增命令或参数。`--check`、非法输入和启动时全部完成仍不创建代理、不调用模型、不改文件。
- 同一个 todo 文件、同一次 TodoLoop 任务，编排程序全程最多直接调用一次已有 `scout` 做公共背景调研，覆盖全部组及接续；有未完成组时先调研，即使只剩一组也不例外。换组、部分完成、接续或内部恢复不使程序再次调研。该限制不作用于执行 task 或其派生工作，它们仍可按原生规则自主调用 scout。程序的准备调研失败、取消、无可用结果或无法结清时停止，不补派、不启动执行组。
- scout 只读完整任务文件、必要明确引用、同 Change 的提案／已有设计／相关增量及必要源码，交接必要事实、来源、范围和未确认项。直接复用 scout 既有工具、模型策略和结果格式，不新增背景 schema、专属权限层或调研验收代理；没有额外公共背景时明确说明，不生成背景文件或扫描无关项目。
- 调研实际结清后，将精简交接结果作为本次任务固定的原生共享 `context`。各组首次及接续复用同一内容；当前组、剩余项、次数、上次简短结果／错误及变化事实留在各自 `assignment`，不复制调研全文、工具流水、主对话或其他组聊天，不改写原生身份与协作规则。
- 已充分覆盖且未变化的材料不强制各组完整重读；完整任务文件、当前修改目标及受影响的变化事实仍按需读取最新内容。共享简报不替代清单不变量、原生权限或实际文件事实。
- 缓存键、模型适配及请求参数全部沿用原生链路，不新增缓存开关、模型能力表、策略、预热、缓存重试或切换模型／账号的逻辑。未命中或不支持缓存仍正常执行，真实请求错误不伪装成未命中；不把相同前缀或键当作命中证据，不承诺节费或零 token。
- 保留首个 checkbox 前置标题推断、Superpowers Step 身份、组间串行、组内连续逐项勾选、每组最多三个全新执行代理、实际结清后整组检查及文件续做。scout 不计入组三次，也不增加 checkbox 或组完成数。
- 沿用原生 TUI、代理记录、错误和已有用量展示，不新增准备专属状态体系、用量账本、派生费用归集、缓存统计或费用面板，不向主聊天倾倒完整背景或派发包，不调用主 AI 调度或总结。

### Scope and Dependency

- 本变更依赖 [add-todoloop-command](../add-todoloop-command/proposal.md) 的按组执行及 Step 语义；其目前仍在待定变更目录，未被视为已合入的主规格。本轮不修改该变更、主规格或其完成记录。
- 对前置增量的“干净上下文与文件材料”，本变更允许共享 scout 的精简事实，避免强制重复完整读取未变化的公共材料；仍不继承执行聊天、不跳过任务文件重读和最新事实核实。执行组使用原始 task，不增加任何 scout 调用、工具、模型、权限或派生限制，也不添加 TodoLoop 专属准入钩子。
- “一次”只计算同一文件、同一次 TodoLoop 任务中程序直接发起的公共背景调研，不计算执行 task 或其子代理自主调用的 scout。退出后重新输入命令是新的独立任务，仍按当前文件恢复，有剩余组时程序可重新调研一次；不做文件终身去重，不新增跨任务背景数据库、进度文件或自动仓库文档。
- 只作用于显式运行 TodoLoop 的原生 TUI，不扩展 WebGUI、ACP、RPC 或独立 CLI；不修改普通 task、scout、聊天、其他命令及全局缓存默认行为，不新增模型、权限、超时或并发配置。
- 本轮仅同步修订提案、增量规格、设计及任务清单，不修改代码、提示词、主规格、命令说明或 Changelog，不运行软件验证，不同步主规格、归档、提交、push 或发布。旧的派生 scout 拦截、专属权限、背景协议、计量方案及自动实施／归档安排不再适用，后续实施须另行明确授权。

## Capabilities

### New Capabilities

无；不建立平行缓存、研究或 Agent 调度能力。

### Modified Capabilities

- `personal-commands`：明确同一文件、同一次 TodoLoop 任务中程序最多直接调研一次、复用原生共享 context 及缓存，并保持执行 task 原生能力和既有组执行／失败边界；不新增其他能力。

## Impact

- 现有缺口：`packages/coding-agent/src/todoloop/runner.ts` 逐组派发，`context.ts` 与 `src/prompts/todoloop-group.md` 要求各组读取公共材料；`native.ts` 使用的 eval 桥接尚未转发已有共享 context。
- scout 复用证据：`packages/coding-agent/src/prompts/agents/scout.md:3-35` 已定义压缩交接职责、读取／搜索工具及 `summary/files/architecture` 结果，`:64-67` 明确只读；无需另造调研代理、输出协议或权限子系统。
- 共享背景证据：`packages/coding-agent/src/prompts/tools/task.md:35` 要求公共内容放在 context、不逐 task 重复；`src/prompts/system/subagent-system-prompt.md:1-32` 已将 context 放在角色之后、动态身份之前，结构化子代理执行链已有对应字段。
- 缓存复用证据：`packages/coding-agent/src/session/agent-session.ts` 的 `getPromptCacheKeyForModel()` 已处理显式键优先及适用的任务族缓存亲和；本变更不新增或修改模型能力与 Provider 策略。
- 最小实施范围是把程序的一次 scout 调研放在现有组循环外，补必要的 context 转发及背景读取提示；沿用原生 task、等待、取消、结清和记录，不新增准入钩子、派生限制或独立背景、权限、缓存、统计模块。
- 验证先复用现有覆盖，仅在缺少覆盖时补新增的一次调用／准备失败边界；背景传递只用一条源码 TUI 主链路证明，不在桥接、任务包及 TUI 重复验证，不重建未改动的分组、Step、续做或原生派生测试矩阵。
- 这是当前源码证据支持的最小充分路线，不是对绝对最少代码行数的证明。新增调研自身有开销，不能预设总成本下降；源码与请求前缀证据也不等于功能已实现、软件验收通过或真实服务已命中缓存。
