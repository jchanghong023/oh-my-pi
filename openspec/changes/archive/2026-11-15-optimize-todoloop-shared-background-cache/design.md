# Design

## Context

动机见 [proposal.md](proposal.md)，行为以 [personal-commands 增量](specs/personal-commands/spec.md) 为准。本轮只修订规划，不实施、运行软件验证或归档。

已有 scout 提供只读调研及原生交接结果，原生子代理已有 context、等待、取消和结清。TodoLoop 缺的是循环前的一次背景调研及共享 context 转发，不是新的权限、缓存或代理系统。

## Goals / Non-Goals

**Goals:** 程序调研一次，将精简结果通过已有 context 供各组及接续复用。

**Non-Goals:** 不修改执行 task 的原生工具、模型、权限和派生能力，包括调用 scout；不增加准入钩子、派生拦截、调用预算、背景 schema、缓存策略、状态体系、统计模块或持久化，不重写解析及组推进。

## Decisions

### 1. 程序的 scout 调用放在组循环外

文件校验、预检及全部完成分支之后，在组循环前调用一次已有 scout。沿用其工具、模型及交接格式；调研任务提供清单和必要材料，材料发现复用现有代码，必要静态指令放入 prompts Markdown。

把返回的精简 context 保留在本次函数局部，然后进入原有组循环。换组及接续不回到准备步骤，因此不需要 scout 专属计数器、已启动标记或准入限制。调研失败、空结果、取消、文件异常或无法实际结清时停止，不补派。

“一次”只指 TodoLoop 程序直接发起的公共背景调研。各执行 task 及其派生工作完全沿用原生行为，可自主调用 scout；不统计或拦截这些调用，不改原有钩子、spawns、代理定义或共享 settings。

### 2. 只补已有 context 的转发

`eval/agent-bridge.ts` 的宿主 options 增加可选 context，转发到已有原生请求；不增加模型可见参数，不改缓存键、模型策略或用量字段。`todoloop/native.ts` 只补程序选择 scout 及 context 接线，继续使用原有句柄、等待和结清。

复用原生交接结果的精简文本表示，在现有 context 构建代码中只渲染一次；不新增背景模块、协议或 schema。各组使用同一个 context 值，动态组任务及上次简短结果／错误留在 assignment，不复制聊天或工具流水，不重排原生身份及协作内容。

### 3. 只调整背景读取说明

runner 调研后继续原有组循环。现有任务包及 `todoloop-group.md` 不再强制完整重读已覆盖且未变化的公共材料；任务文件、修改目标及变化事实仍读最新内容。编排程序不重启公共调研，但不限制执行 task 使用原生工具或自行调用 scout。

沿用现有原生记录和展示，只做必要的 scout 记录接线；不新增布局、阶段枚举或统计。分组、Step、组三次、文件续做及原生派生策略不改。

### 4. 验证只覆盖本次差异

- 先复用现有相关消费者及仍有效的通过结果；只对缺少覆盖的程序直接调用一次、准备失败／取消不启动执行组等新增边界补回归。
- 共享背景的实际派发与位置只在一条源码 TUI 主链路中证明：本地模拟模型、隔离配置，两组及一次接续；不在桥接、任务包、TUI 三层重复断言相同背景传递。
- 不为未改动的分组、Step、组三次、文件续做或原生派生补建测试矩阵，不新增派生 scout 拒绝测试，不扩展全 Provider 矩阵或全仓测试。普通调用默认行为沿用已有覆盖；不写字段转发、提示词措辞或源码文本测试。输入未变的有效检查不重复运行。

## Risks / Trade-offs

- 背景可能因前序修改过期 → 执行 task 按需读取最新文件，并可使用其原生 scout；程序不重新准备公共背景。
- 缓存可能未命中、调研本身有开销 → 完全沿用原生缓存接线，不承诺节费，不增加预热或统计系统。

## Migration Plan

无用户数据或格式迁移。后续获准实施时仅改现有编排、桥接、必要提示和确有缺口的消费者；必要验证通过后更新既有使用说明及包 Changelog。本轮不执行这些任务，实施及归档等待后续明确授权。
