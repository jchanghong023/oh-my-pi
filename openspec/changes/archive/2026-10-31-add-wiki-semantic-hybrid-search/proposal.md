# Proposal

## Why

现有 Wiki 已有 Rust 全文检索、技术名称边界判断、原文 grep、完整正文与版本引用，但主要依赖词面命中，不能稳定覆盖同义表述和中文问题对英文资料的语义召回。整体替换为 QMD 会失去现有技术名称、证据与分页合同，也会引入另一套索引生命周期和模型依赖。

OMP 已有可复用基础：Mnemopi 的 Embedding API 调用与向量配置解析、`pi-natives` 的 Rust 批量向量计算、向量归一化包装和 RRF 融合，以及 AI 包的 rerank 请求客户端。应在现有 Wiki 内增加语义召回和可选精排，借鉴 QMD 的双路检索、排名融合与候选重排思想，而不是安装 QMD、复制其实现或重新建设向量引擎。

## What Changes

- **保持查询接口不变。** `wiki` 的 `query`、`mode: "search" | "grep"`、`case`、`cursor`，`DocsService` 的查询入口，以及 TUI、RPC、ZCode 既有方法、参数与结果结构均不增加语义搜索专用字段或模式。省略 `mode` 仍等价于 `search`。
- **普通搜索内部自适应。** 对新的 `search` 查询，查询向量有效且当前 Wiki 范围内存在与该模型匹配的完整有效向量代际时，同时执行既有全文召回和有效语料的语义召回，再按 RRF 融合。某索引的已存向量代际不兼容时仅排除该代际，其余有效索引仍可融合；查询向量无效、模型不可用或没有剩余有效向量代际时整体使用既有全文基础结果，不向用户报告“缺少向量能力”的失败。
- **空状态保持 HEAD 基线。** 不改变数据库打开、空库创建和无索引错误：按既有规则打开不存在的 docs.db 会创建空 WAL 库，但没有已发布索引的查询仍报无索引，不改成正常空结果，也不新增区分缺库与空库的展示或返回字段。
- **grep 保持原义。** 显式 grep 只扫描数据库原始 Markdown，不调用 Embedding 或 Reranker、不做语义召回或 RRF；无索引错误与正常零命中的区别沿用 HEAD。
- **全文证据不因融合或精排丢失。** 保留现有完整技术名称召回与优先级；全部全文匹配仍可连续到达，向量和精排候选预算不能截掉全文证据尾部。模型不能修改命中类别或原文引用，仍返回存储原文、行号、索引和文档版本。
- **向量是 Wiki 的可选派生能力。** 复用现有 `init`／`remove` 生命周期；导入在 Embedding 已配置且可用时准备对应向量，向量失败不使已成功准备的全文语料不可用。没有模型仍可正常导入全文。旧库不强制重建，不在查询中自动建向量库或补算；缺少向量时继续全文检索。
- **Reranker 为可选增强。** 普通搜索先得到全文或 RRF 基础排名，再在有已配置且可用的重排模型时对内部有限候选精排；该阶段独立于向量索引是否可用。未配置、请求失败或响应不可用时保持基础结果与顺序，不报可选模型错误，不自动安装或下载模型。用户取消立即结束，不作故障回退。
- **不增加强制模型依赖。** 没有重排模型仍能完成全文／融合搜索。本次不纳入查询扩展、HyDE、多模态资料入库、相似文档推荐或近重复管理。

### Confirmed Behavior and Acceptance Boundary

所有算法选择隐藏在 OMP 内部，现有调用方不改调用参数；缺少可选 Embedding、向量索引或 Reranker 不导致基础搜索失败。用户在需求审查后明确保留 HEAD 的数据库打开与无索引行为，本变更不再修改缺库／空索引返回和展示合同。

后续实现验收须覆盖：Embedding 与向量索引可用性组合、查询向量无效时整体回退、部分已存向量代际不兼容时仅排除该代际、没有剩余有效代际时全文回退，以及既有空库创建、无索引错误、正常零命中和 grep 隔离；Reranker 未配置、可用、请求失败或响应无效，全文与融合两种基础排名的可选精排，候选上限不丢证据、完整名称优先、取消与稳定续页；导入／删除及模型切换后的版本隔离、各消费端共享行为。真实模型质量评估与确定性合同检查分开，不能以模型 stub 证明语义或精排质量。

已在本次对话前半段观察到的本地服务是 `http://127.0.0.1:1234/v1`、模型 `text-embedding-qwen3-embedding-0.6b`，曾实际返回 1024 维向量并通过一个中问英文档的排序样例。它仅作为后续可复现验收环境，不成为所有安装的默认地址、模型或质量保证。当前开发机器没有重排模型，不要求为本变更安装；公司已有 `Qwen3-VL-Reranker-2B`，可在公司运行环境配置为可选精排模型。公司 Embedding 和 Reranker 均须遵守既有凭据与显式配置优先级，公司网关协议和真实请求行为未经本次提案验证。

本次仅产出需求材料，不执行软件验证，不把历史样例当作本变更已实现或已通过验收。没有需要用户继续决定的范围问题；内部候选预算、实现分层和存储细节留给后续设计，但不能改变本提案的接口、回退、证据与生命周期边界。

## Capabilities

### New Capabilities

无。语义召回与融合属于既有 Wiki 索引能力的扩展，不建立并行产品或新查询接口。

### Modified Capabilities

- `wiki-index`：将普通搜索改为内部自适应的全文／语义融合，并可选精排；明确可选向量准备、模型与语料身份、RRF 和精排的证据保护、分级回退、分页一致性以及 TUI／RPC／ZCode 同源消费行为；空状态沿用 HEAD。

## Impact

- 受影响的实现区域：`crates/pi-wiki/`、`crates/pi-natives/src/wiki/`、`crates/pi-natives/src/vectors.rs`、`packages/coding-agent/src/docs/`、`src/tools/wiki.ts` 及其 TUI／RPC／ZCode 消费端。原全文／grep 内核继续使用 Rust；数值计算优先复用已有原生向量内核，不要求为全 Rust 而重写已有轻量宿主逻辑。
- 现有复用依据：`packages/mnemopi/src/core/embeddings.ts`、`vector-index.ts`、`polyphonic-recall.ts`、`packages/coding-agent/src/mnemopi/company-embeddings.ts`，以及 `packages/ai/src/rerank/`。只复用必要公共能力，不要求开启记忆系统，不复制一套 API 请求、配置、向量数学、RRF 或 rerank 客户端；现有客户端不构成公司网关已经兼容的证明。
- 算法参考：[QMD 2.8.3](https://github.com/tobi/qmd/tree/v2.8.3) 的全文／向量双路召回、RRF 和有限候选精排思路。不是引入 QMD SDK、CLI、MCP、模型下载器或数据库格式；不新增外部常驻向量服务或自研 ANN 索引。
- 有意变更的既有合同：默认 `search` 不再固定纯全文；可选向量准备与查询可以调用已配置 Embedding，普通搜索还可调用独立配置的可选 Reranker。基础全文结果不依赖模型，grep 不调用任何模型；原始证据仍来自当前 profile 的 Wiki 数据库，不回读源目录。
- 不变的边界：查询协议与现有返回结构、数据库打开与空库创建、无索引错误及空状态展示、权限、显式 grep、现有 `init`／`remove` 管理入口、配置根与 profile 隔离、技术名称事实判定、原文引用、取消、成功查询不少于 500ms 的既有约定及非 Wiki 功能。
- 后续实现须同步 Wiki 工具说明、中文使用文档中相关段落和包级 changelog，并调整直接受行为变化影响的既有用例。本次不修改这些文件或主规格，不生成设计和任务清单。
- 性能边界：现有 Rust 向量内核为精确扫描，不能据 Rust 实现或一个小样例承诺 100GB 语料成本；后续只报告适用环境中实际测得的构建、空间、内存与查询成本。
