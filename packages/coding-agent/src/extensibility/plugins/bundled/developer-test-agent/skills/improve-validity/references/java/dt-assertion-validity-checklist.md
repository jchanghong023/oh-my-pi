# DT 断言有效性审查参考文档

本文档汇总了与 DT（测试）断言有效性相关的审查点，供本 Skill 或其他工具作为参考使用。  
**用途**：仅作参考使用；并非 Skill 主体。

---

## I. 缺少断言

**目标**：识别测试用例中是否包含有效断言。

| # | 审查点 | 描述 |
|---|--------------|-------------|
| 1 | 类名为 Assert | 检测是否使用了断言相关类（如 `Assert`） |
| 2 | 调用方法名为 Assert | 检测是否调用了名为 Assert 的断言方法 |
| 3 | 调用方法名为 expect | 检测是否调用了 `expect` 风格的方法（如 Spring MVC 测试） |
| 4 | 调用方法名为 andExpect | 检测是否调用了 `andExpect` 风格的方法 |
| 5 | Mockito/PowerMockito verify | 检测是否调用了 `Mockito.verifyXX`、`PowerMockito.verifyXX` 等 |
| 6 | Native assert | 检测是否使用了 JDK 原生 `assert` 语句 |
| 7 | 匿名内部类中的断言 | 匿名内部类中是否包含上述 1–6 中的任意一种 |
| 8 | expected 注解 | 测试注解中是否包含 `expected` 风格的注解（如 `@Test(expected = ...)`） |

**判定**：若上述任意一项成立，则该用例**含有断言**；若均不成立，则存在**缺少断言**风险。

---

## II. 虚假断言

**目标**：识别存在断言形式但并未执行有效校验的用例。

| # | 审查点 | 描述 |
|---|--------------|-------------|
| 1 | assertTrue 参数 | 当用例包含 `assertTrue` 时，检查参数是否为字面量 `true` 或常量；若是，可能为虚假断言（未校验实际结果） |
| 2 | assertFalse 参数 | 当用例包含 `assertFalse` 时，检查参数是否为字面量 `false` 或常量；若是，可能为虚假断言 |
| 3 | assertNotNull 后续断言 | 当用例包含 `assertNotNull` 时，检查是否通过 `assertEquals`、`assertTrue` 或 `assertFalse` 对该对象进行了**至少一次**内容断言；若仅有 assertNotNull 而无内容断言，可能为虚假/弱断言 |

**判定**：若上述任一“可能为虚假断言”的情况成立，则标记为**虚假断言**，以便人工确认或自动告警。

---

## III. 中途退出

**目标**：识别测试逻辑在分支/循环中提前返回，导致后续断言不会被执行的风险。

| # | 审查点 | 描述 |
|---|--------------|-------------|
| 1 | 循环/if 内部 return | 检查**循环体**或 **if 体**中是否包含 `return` 关键字；若是，该分支后续的断言可能不会执行（中途退出） |

**判定**：若在循环或 if 块中发现 `return`，则根据控制流判断**中途退出**是否会导致某些路径缺少断言覆盖。

---

## 使用说明

- 本参考可与具体实现（如静态分析、AST 检查、注解扫描）配合使用。
- Skill 或脚本可参考本文档中的审查点列表，以保持检查与规范一致。
- 实现时，应分别针对“缺少断言”、“虚假断言”和“中途退出”输出结果，以便于报告与追溯。
