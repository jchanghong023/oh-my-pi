# DT 断言步骤与断言目标 — 审查参考文档

**用途**：作为断言有效性审查的参考。审查前先阅读被测方法源文件及其调用方法定义，依据实现中存在的"值变化"维度判断断言是否充分；不可仅凭测试代码或名称推断。

---

## I. 断言目标

确保断言 **有意义且有效**；测试应覆盖被测方法的 **值变化** 维度。

| # | 审查点 | 描述 |
|---|--------|------|
| 1 | 是否验证"值变化"维度 | 覆盖：非局部变量、参数对象内部字段变化、返回值及其字段 |
| 2 | 是否验证可观察的状态迁移 | 聚焦状态迁移，而非表面结果 |
| 3 | 核心逻辑被破坏时断言是否失败 | 核心逻辑被错误修改后断言仍通过 → 不可接受，必须加强绑定到业务/状态变化 |

**判定**：用例未覆盖任何值变化维度（且该维度存在），或满足第 3 项 → 标记 **断言目标未达成**。

---

## II. 必须断言的内容（推荐断言）

### 2.1 非局部变量（方法执行时改变的外部状态）

| # | 审查点 | 描述 |
|---|--------|------|
| 1 | 是否断言了变化的字段 | 验证**哪些字段**变化，而非仅"调用发生过" |
| 2 | 前后值是否正确 | 验证正确的前后值（或预期最终状态） |
| 3 | 是否验证结构性变化 | 集合增删、计数器更新、持久化实体、写入记录等 |
| 4 | 是否验证依赖的可观察副作用 | DB 写入、消息发送、缓存写入等 |

**判定**：方法改变非局部变量但未断言 1–4 项 → 标记 **非局部变量断言不充分**。

### 2.2 参数对象（被方法修改的入参）

| # | 审查点 | 描述 |
|---|--------|------|
| 1 | 参数内部哪些字段被修改 | 验证参数对象内部变化，非仅返回值或"未抛异常" |
| 2 | 每个被修改字段的正确性 | 对每个被修改字段断言其正确性 |
| 3 | 验证参数的结构性变化 | 集合大小变化、Map 更新、嵌套对象变化 |

**判定**：方法修改参数但未断言参数字段/结构变化 → 标记 **参数变化断言不充分**。

### 2.3 返回值（计算输出）

| # | 审查点 | 描述 |
|---|--------|------|
| 1 | 禁止仅存在性断言 | 仅 `assertNotNull(result)` 作为唯一断言禁用；需字段/内容级断言 |
| 2 | 断言关键业务字段 | 关键业务字段和派生/计算值必须断言 |
| 3 | 验证嵌套属性和集合内容 | 嵌套对象属性和集合内容（必要时含顺序） |
| 4 | 验证状态码、错误码、元数据 | 返回值含状态标志/错误码/元数据时 |

**判定**：返回值仅存在性断言，无 2–4 项内容断言 → 标记 **返回值断言不充分**（弱断言）。

---

## III. 必须避免的内容（非推荐断言）

| # | 审查点 | 描述 |
|---|--------|------|
| 1 | 仅存在性断言 | `assertNull/assertNotNull` 后无内容/字段/状态断言 → 不充分 |
| 2 | 虚假断言 | `assertTrue(true)` 或等价"恒真"断言 → **必须禁止** |
| 3 | 与状态迁移/业务无关的断言 | 核心逻辑被破坏时仍通过 → 不可接受 |

**判定**：第 1 项无后续内容断言，或满足 2/3 项 → 标记 **必须避免的断言**。

---

## IV. Flux/Mono 响应式断言

响应式测试必须验证 **完整响应式契约**（发射元素、终止信号、错误行为、可观察副作用）。

### 4.1 响应式契约完整性

| # | 审查点 | 描述 |
|---|--------|------|
| 1 | 验证生命周期信号 | 发射内容、顺序、终止、是否出错 |
| 2 | 验证终止信号 | 仅验证发射值不验证终止（onComplete/onError/cancel）→ 不完整 |
| 3 | 按需验证时序/重试/背压 | 业务涉及时序/重试/背压时断言应体现 |

**判定**：Flux/Mono 测试未验证终止信号或关键行为 → 标记 **响应式断言不完整**。

### 4.2 响应式断言策略参考

- 发射正常完成：`expectNext(...)` → `verifyComplete()`；Mono 单值同此；空 publisher 用 `expectNextCount(0)` → `verifyComplete()`
- 多值：顺序重要用 `expectNext(a, b, c)`；仅关注数量用 `expectNextCount(n)` → `verifyComplete()`
- 复杂对象：`expectNextMatches(predicate)` 或 `assertNext(consumer)`
- 错误终止：`expectError(SomeException.class)` 或细节版 `expectErrorSatisfies(...)`；先发射后失败：`expectNext(...)` → `expectError(...)`
- 取消/背压/时间：`thenCancel()` → `verify()`；`StepVerifier.create(publisher, 0)` → `thenRequest(n)`；`withVirtualTime(...)` → `thenAwait(...)`；`verifyTimeout(Duration)`

**判定**：对照策略检查发射与终止是否均已覆盖。

## V. 经验与典型修复

| 场景 | 推荐修复 |
|------|----------|
| 仅 verify 无返回值断言 | 捕获返回值，加 `assertSame`/`assertEquals` 内容断言 |
| 分支返回新实例 | `assertNotNull` + `assertEquals(result.getClass(), Xxx.class)` + 可观察字段（`assertNull(result.getId())`）+ 与 mock 对象 `assertNotSame` |
| 多次调用不同 stub | `assertSame(stubA, result1)`、`assertNotSame(stubA, newResult)` + `assertEquals(result.getClass(), Xxx.class)` |
| 返回值第三方类型且不可获取 | 保留 `assertNotNull`，不加臆测断言，加注释说明约束 |
| 返回值契约明确但仅存在性 | `assertEquals(expected, result)` 及关键字段断言 |
| 虚假断言 `assertTrue(true)` | 有返回值断言返回值；void 用 `assertDoesNotThrow`；契约抛异常用 `assertThrows` |

---

## VI. 修改时的注意事项

- **正确性优先**：不为追求内容级断言而引入依赖未经验证实现细节的断言（如反射访问第三方私有字段）。
- **不可获取则不断言 / 仅断言可观察行为**：第三方/依赖内部结构或公共 API 无法通过源码/文档获知时，不为该部分写断言；仅断言项目内可读、可推断的返回值/外部状态，避免反射、未文档化字段；无法内容级断言时加注释说明约束。
