# C/C++ 测试质量评估与异常覆盖检测

## 测试质量评估维度

### 结构评估

- 测试套组织：`Test + 被测对象名`，大驼峰
- Fixture使用：`SetUp()` / `TearDown()` 使用是否合理
- 辅助函数：数据构造（`fill_default_param`）、计算辅助（`calculateExpectedCRC`）是否提取
- include组织：系统头文件 → 项目头文件 → 被测模块头文件
- extern "C"：C++测C时是否正确包裹

### 命名规范检查

| 检查项 | 要求 |
|--------|------|
| 测试套命名 | `Test + 被测对象名`，大驼峰风格 |
| 测试用例命名 | 大驼峰风格，包含关键输入输出 |
| 用例名称语言 | 不使用中文 |
| 文件命名 | 被测文件名 + `_test` 后缀，`.cpp` 扩展名 |
| Mock文件命名 | 被mock对象名 + `_mock` 后缀 |
| 用例注释 | 每个用例上方有场景+预期注释 |

### 断言质量检查

| 检查项 | 说明 |
|--------|------|
| 缺失断言 | 无EXPECT/ASSERT的用例 |
| 伪断言 | `EXPECT_TRUE(true)` / `SUCCEED()` |
| 仅存在性 | `EXPECT_NE(ptr, nullptr)` 无字段验证 |
| 仅NoThrow | void方法仅 `EXPECT_NO_THROW` 不验证状态 |
| 与if重复 | 断言与if条件重复，恒为真 |
| 仅非空容器 | `EXPECT_FALSE(x.empty())` 不验证内容 |
| 字段级校验 | struct/指针/容器/map是否逐字段/元素校验 |
| 提前退出 | return/goto导致后续断言未执行 |
| 用例行数 | 是否控制在3-50行 |

### 字段级校验检查

| 返回类型 | 校验要求 |
|----------|----------|
| struct/class | 逐字段校验 |
| 指针返回 | 非空 + 字段校验 |
| vector/list | size + 元素校验 |
| map | size + key-value校验 |
| string | 内容校验 |
| void | 状态变化校验 |

## 异常覆盖检测

### C++异常处理

| 检查维度 | 说明 |
|----------|------|
| try-catch块 | catch捕获的异常类型及处理逻辑是否被覆盖 |
| 嵌套try-catch | 内层和外层异常处理是否均被覆盖 |
| 异常重抛 | catch后rethrow的路径是否被覆盖 |

### C错误处理

| 检查维度 | 说明 |
|----------|------|
| 错误码返回 | `if (ret != OK) return ERROR;` — 是否Mock触发 |
| 资源清理 | `if (failed) { free(ptr); return; }` — 是否验证清理 |
| NULL检查 | `if (ptr == NULL) return;` — 是否显式设置NULL测试 |

### catch块处理逻辑覆盖

| 逻辑类型 | 覆盖要点 |
|----------|----------|
| 日志记录 | 验证日志输出 |
| 异常转换 | 验证新异常类型和消息 |
| 资源清理 | 验证free/delete/close被调用 |
| 状态重置 | 验证全局/成员变量重置 |
| 错误码转换 | 验证返回的错误码 |

### 检查清单

- [ ] 被测方法中每个catch块/错误处理分支均有对应测试用例
- [ ] 错误处理中的处理逻辑被验证执行
- [ ] 错误触发条件通过Mock或构造实现
- [ ] 测试用例正确断言处理结果
