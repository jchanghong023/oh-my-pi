# 阶段 4：测试场景设计

本阶段是 Phase 3（Mock 分析）完成后、Phase 5（断言质量）之前的**强制设计步骤**。

agent 必须在编写任何测试代码之前，先完成测试场景设计，输出**最小测试用例集**。

---

## 用例生成规则（严格遵守）

### 1. 严禁冗余与正交去重

- 同一等价类内部**仅保留 1 个典型正例**，切勿重复生成多个类似的正常流程用例
- 多个独立校验项（如多个必填项缺失、多个格式错误）**合并为"单变量反例"**，避免组合暴涨

### 2. 精准采用测试设计技术

- **边界值分析**：仅保留边界点（min、min-1、max、max+1），剔除大量无效的区间内重复值
- **等价类划分**：明确列出有效等价类与无效等价类，**每类仅对应一个用例**

### 3. 合并同类项

- **主流程（Happy Path）**：尽可能覆盖完整的正向端到端链路，减少重复拆分细小步骤
- **异常用例**：只聚焦"关键破坏性场景"与"核心业务逻辑校验"，剔除通用的框架级基础校验（如纯前端的通用输入过滤）

---

## 用例数量控制

| 方法复杂度 | 建议用例数 | 上限 |
|-----------|-----------|------|
| 简单（< 3 个分支） | 2-3 个 | 4 |
| 中等（3-6 个分支） | 3-5 个 | 6 |
| 复杂（> 6 个分支） | 5-7 个 | 8 |

超出上限时，裁剪低优先级场景。

### 最小覆盖集（不可再减）

1. **1 个核心路径用例**：端到端覆盖主要业务功能
2. **1 个异常/Guard 用例**：覆盖关键破坏性场景
