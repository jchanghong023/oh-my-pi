# 测试设计

## 函数分类（7类）

1. 简单计算函数：无外部依赖，纯逻辑计算。重点验证算法正确性、边界值。无Mock需求。期望值使用辅助程序批量计算
2. 单依赖函数：依赖1-2个外部函数。验证依赖成功和失败两种场景。Mock外部函数返回成功和失败。验证错误传播
3. 多依赖函数：依赖多个外部函数，需要序列化Mock。验证依赖组合、调用顺序、错误传播。每个依赖失败都要单独测试
4. 状态机函数：涉及状态转换。覆盖所有状态转换路径、异常状态处理。验证状态变量变化
5. 回调函数：验证回调参数、调用时机、调用次数。使用lambda捕获回调行为
6. 业务流程函数：实现完整业务流程，多分支多路径。覆盖业务成功路径、失败回退路径、特殊路径。验证业务规则条件组合
7. 数据转换函数：数据格式转换或封装。验证输入输出映射、边界数据、特殊数据。重点关注数据完整性

## 复杂度评估

| 维度 | 低复杂度 | 中复杂度 | 高复杂度 |
|------|---------|---------|---------|
| 圈复杂度 | 1-5 | 6-10 | >10 |
| 代码行数 | <30 | 30-100 | >100 |
| 参数数量 | 1-2 | 3-5 | >5 |
| 外部依赖 | 0-1 | 2-4 | >4 |

复杂度影响：低2-5个用例，中5-15个，高15+个必须使用决策表和遗漏检查清单。

## 系统性测试设计完整9项

1. 控制流分析：绘制控制流图、计算圈复杂度、列出所有独立路径、测试用例数 ≥ 圈复杂度
2. 数据流分析：识别关键变量、分析变量生命周期、覆盖定义-使用路径
3. 边界条件分析：对每个输入参数按边界矩阵系统化测试（int/uint/指针/数组/字符串/结构体/bool/枚举），包括状态边界、资源边界、数值计算边界、多参数组合
4. 异常场景分析：资源申请失败分析（第一次/中间/最后/循环内失败）、外部调用失败分析（序列化失败场景）、参数异常分析（NULL/空数组/无效枚举/越界/超长/不兼容组合）
5. 资源泄漏分析：建立资源清单、异常路径泄漏检查（每个goto err路径验证释放）、部分失败泄漏检查（批量操作前N-1个资源释放）
6. 决策表法：列出所有条件和动作，每条规则必须有测试用例
7. 业务场景深度分析：识别业务关键路径，枚举业务场景（正常流程/快捷路径/回退路径/特殊路径）
8. 遗漏场景检查清单：控制流检查（if/switch/循环/return/goto）、边界条件检查、资源申请失败检查、外部调用失败检查、资源泄漏检查、业务逻辑检查
9. 优先级排序：P0必须覆盖（业务核心/安全/错误处理/资源失败）、P1应该覆盖（边界/异常/分支）、P2可以覆盖（性能/稳定性/兼容性）

反模式禁令（Mock误用、断言误用、编码误用、代码修改禁令，共21条+5种禁止编码方式）详见 [anti-patterns.md](./anti-patterns.md)。
