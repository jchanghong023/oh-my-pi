# 单元测试报告生成

为测试生成专业且结构化的单元测试报告。基于标准覆盖率和测试质量评估，补充异常覆盖检测、断言有效性评审和命名规范检查，避免与已有报告内容重复。

## 核心原则

1. **数据驱动**：基于实际覆盖率数据和测试代码分析生成报告
2. **不重复**：如已有报告或先前分析包含相关内容，不重复完整描述，仅补充状态、差异或未解决问题
3. **聚焦关键路径**：关注业务关键执行路径的覆盖，而非追求行数
4. **区分有效覆盖**：区分有意义的覆盖和表面覆盖
5. **可操作建议**：提供优先级排序的改进建议

## 语言路由（强制执行）

检测测试代码语言后，**必须读取对应语言的专属reference**获取语言特定的覆盖率工具、质量评估标准和检查项：

本 skill 的 `references/` 路径相对于加载时返回的 baseDir；用 `read` 读取资源时可用 `skill://test-report/<路径>`。reference 中的相对链接以该 reference 所在目录为基准，不依赖项目工作目录。

| 语言 | 触发条件 | 必读reference |
|------|----------|---------------|
| **Java** | 测试文件以 `.java` 结尾 | 按下方流程执行 |
| **C/C++** | 测试文件以 `.c`/`.cpp`/`.cc`/`.h`/`.hpp` 结尾 | `references/cpp/report-rules.md` |
| **Go** | 测试文件以 `.go` 结尾 | `references/go/report-rules.md` |
| **Python** | 测试文件以 `.py` 结尾 | `references/python/report-rules.md` |
语言检测后，若入口文件中引用了子文件则按需读取；若入口文件为自包含（无子文件引用），则直接按入口文件内容执行，不报错。新增语言时只需创建入口文件即可完成基本流程，子文件可后续按需补充。

## 执行步骤

### Step 1: 分析覆盖率数据

1. 使用项目已有的覆盖率工具获取覆盖率数据。若语言专属reference中提供了专用工具或命令，优先使用。
2. 分析返回的覆盖率数据。

### Step 2: 评估测试质量

1. 使用 `read` 工具加载测试文件源代码。
2. 从以下维度评估测试代码：
    - **结构**：测试组织、Fixture使用、辅助函数
    - **命名规范**：测试类/方法命名是否符合语言专属规范
    - **断言质量**：是否存在缺失断言、伪断言、仅存在性断言
    - **覆盖场景**：正常路径、边界条件、异常场景的覆盖情况

若语言专属reference中提供了更详细的质量评估维度，优先按其执行。

### Step 3: 汇总附加检查结果

基于 Step 1 和 Step 2，补充汇总以下检查结果。若语言专属reference中提供了更详细的检查项，优先按其执行：

- **异常覆盖检测**：被测代码中的异常处理路径（特别是catch块/error处理）是否被触发和验证
- **断言有效性检查**：是否存在提前退出、伪断言、缺失断言等问题
- **命名规范检查**：测试方法命名、类/方法文档、Copyright等是否符合要求

本技能仅报告发现，不执行修复。

### Step 4: 生成测试报告

基于 Step 1-3 的分析和评估结果，产出结构化、可读的测试分析报告。

## 测试报告输出格式

### 1. 概览总结

- 整体覆盖率指标（行覆盖率、分支覆盖率、方法覆盖率、类覆盖率）
- 测试用例总数及通过/失败统计
- 关键发现和风险等级评估

### 2. 详细覆盖率分析

- 按模块/包的覆盖率分布
- 低覆盖率区域识别
- 未覆盖的关键代码路径

### 3. 测试质量评估

- 测试命名规范评审
- 断言有效性分析
- 边界条件和异常场景覆盖
- 测试隔离性和独立性评估

### 4. 附加检查汇总

以简洁的检查清单格式汇总（仅报告发现，不修复）：

| 检查项 | 状态 | 发现 | 建议处理技能 |
|------------|--------|----------|-------------|
| 异常覆盖检测 | ✅ 通过 / ❌ 发现问题 / ⚠️ 无数据 | catch块覆盖、异常处理断言等关键发现 | improve-coverage / fix-ut |
| 断言有效性检查 | ✅ 通过 / ❌ 发现问题 / ⚠️ 无数据 | 提前退出、伪断言、缺失断言等关键发现 | improve-validity |
| 命名规范检查 | ✅ 通过 / ❌ 发现问题 / ⚠️ 无数据 | 命名、文档、Copyright等关键发现 | fix-ut |

规则：
- 如同一问题已在覆盖率或质量评估章节描述，不在此重复详情
- 如本节包含详细发现，后续建议章节应引用而非重复

本技能仅报告发现，不执行修复；处理建议中所列的 `improve-coverage` / `fix-ut` / `improve-validity` 为后续可选处理路径。

### 5. 问题和建议

- 识别的测试缺陷或不足
- 优先级排序的改进建议
- 建议的额外测试用例
- 不重复已在附加检查汇总中完整描述的问题

### 6. 结论

- 整体测试健康评分（A/B/C/D/F）
- 建议的后续行动

## 错误处理

| 场景 | 处理 |
|----------|----------|
| 测试文件未找到 | 输出错误信息 |
| 检查结果不可用 | 将对应项标记为 `⚠️ 无数据`，继续生成报告 |
| 覆盖率数据不可用 | 仅报告质量评估，注明"覆盖率数据不可用" |
