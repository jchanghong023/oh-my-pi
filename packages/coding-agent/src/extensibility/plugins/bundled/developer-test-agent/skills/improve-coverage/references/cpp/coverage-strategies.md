# C/C++ 未覆盖场景测试策略与异常覆盖检测

## 未覆盖代码分析与策略匹配

### 覆盖率问题路由

根据未覆盖代码特征，**从上到下顺序匹配**覆盖策略。每个优先级都必须检查，同一未覆盖代码可能匹配多条规则需综合运用。

### 未覆盖场景测试策略

| 未覆盖类型 | 典型场景 | 推荐测试策略 |
|-----------|---------|-------------|
| 空指针检查 | `if (ptr == NULL)` | 显式设置nullptr，验证处理行为 |
| 错误返回分支 | `if (ret != SUCCESS) return ret;` | Mock依赖返回错误码 |
| 内存分配失败 | `if (malloc() == NULL)` | **禁止Mock malloc**，使用替代策略：Mock被测函数实际调用的分配函数，或手动设置状态 |
| 数组越界检查 | `if (index >= size)` | 传入越界索引值 |
| 边界值 | `if (count >= MAX)` | 测试 MAX-1、MAX、MAX+1 |
| switch未覆盖case | `case SPECIFIC_VALUE:` | 传入对应的枚举/常量值 |
| 循环未进入 | `for (int i = 0; i < n; i++)` | 传入n=0或空集合 |
| 循环提前退出 | `if (condition) break;` | 构造满足break条件的数据 |
| 异常路径 | `if (error) { cleanup(); return; }` | Mock依赖触发错误，验证清理逻辑 |
| 防御性代码 | `if (invariant_check)` | 评估是否为不可达代码 |
| 平台特定代码 | `#ifdef _WIN32` | 在当前平台评估可达性 |

### 不可达代码处理

将代码归类为不可达前，必须验证：
1. 该代码路径是否在所有可能的输入下都无法触达
2. 是否因互斥条件导致不可达
3. 是否因前置检查导致后续分支不可达

确认不可达后，在覆盖率报告中记录原因，从分母中排除。

## 异常覆盖检测

### C++异常处理

| 检查维度 | 说明 |
|----------|------|
| try-catch块 | 检查catch捕获的异常类型及处理逻辑是否被测试覆盖 |
| 嵌套try-catch | 检查内层和外层异常处理是否均被覆盖 |
| 异常重抛 | 检查catch后rethrow的路径是否被覆盖 |

### C错误处理（非异常）

| 检查维度 | 说明 |
|----------|------|
| 错误码返回 | `if (ret != OK) return ERROR;` — Mock依赖返回错误码 |
| 资源清理 | `if (failed) { free(ptr); return; }` — 触发失败路径验证清理 |
| NULL检查 | `if (ptr == NULL) return;` — 显式设置NULL |

### catch块处理逻辑覆盖

| 逻辑类型 | 覆盖要点 |
|----------|----------|
| 日志记录 | 验证日志输出或日志Mock被调用 |
| 异常转换 | 验证新异常类型和消息 |
| 资源清理 | 验证free/delete/close被调用 |
| 状态重置 | 验证全局/成员变量重置 |
| 错误码转换 | 验证返回的错误码 |

## 覆盖率问题路由详情（4类）

按从上到下顺序匹配规则，一旦匹配成功立即加载对应策略：

### 1. 无测试用例
- 触发条件：测试文件中没有任何 TEST 宏
- 覆盖策略：用户需要先生成测试用例

### 2. If分支未覆盖
- 触发关键词：`if`, `else`, `==`, `!=`, `>`, `<`, `>=`, `<=`
- 其他特征：未覆盖代码行位于if语句块内；if条件为true/false的分支未覆盖；多重if-else if-else链部分分支未覆盖；嵌套if部分分支未覆盖
- 覆盖策略：构造正向和反向输入数据；Mock不同返回值触发不同分支；设置对象不同状态；利用枚举不同值；利用容器空/非空状态

### 3. 静态方法Mock限制
- 触发关键词：静态工具类, `std::bind`, `std::function`
- 其他特征：未覆盖代码行涉及调用静态辅助类方法；静态方法行为难以验证
- 覆盖策略：使用verify验证调用而非stub；对于有返回值静态方法按需stub返回值；考虑让部分方法真实执行

### 4. 私有方法未覆盖
- 触发关键词：需要分析覆盖率报告中未覆盖方法的方法名
- 其他特征：未覆盖代码行位于private方法中；该private方法未被任何测试用例直接调用
- 覆盖策略：通过public方法间接触发私有方法执行
