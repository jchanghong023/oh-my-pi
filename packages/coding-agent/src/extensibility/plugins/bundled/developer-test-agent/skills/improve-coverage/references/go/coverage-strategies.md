# Go 覆盖率策略

## 覆盖率缺口归因（≤90%时）

### 归因流程

1. 生成行级覆盖率，列出目标体中未覆盖的行号
2. 仅过滤到目标体（忽略下游私有方法）
3. 使用F1-F13矩阵逐行归因
4. 按成本顺序修复：F8（缺少测试）+ L1/L2/L3 优先，仍≤90%再升级L4/L5
5. 在将分支分类为不可达之前，先验证gomonkey注入无法覆盖——先升级到L5
6. 每批后重新测量，重复直到>90%或所有行覆盖/归因为不可达

### 归因→动作映射

| 归因 | 动作 |
|------|------|
| F8（缺少测试） | 用当前层级写测试，不改变层级 |
| F1（状态/配置依赖） | L1：预构造状态/设置配置字段 |
| F2（错误返回分支） | L2：接口stub返回错误 |
| F3（函数字段分发） | L3：注入 `c.field = mockFn` |
| F4（目标体内路由谓词） | L4：fake server原始协议帧 |
| F5/F7（补丁能力缺口） | L5：gomonkey.ApplyMethod |
| F9（不可达） | 从分母中排除 |

## 不可达行模式

| ID | 模式 | 示例 |
|---|---|---|
| U1 | 互斥路径 | `if x > 0 { return } ... if x <= 0 {` |
| U2 | 空值重检后重检 | `if err != nil { return } ... if err != nil {` |
| U3 | 常量false条件 | `if false {` |
| U4 | 穷尽switch后的防御代码 | `default:` 所有case已处理 |
| U5 | panic/fatal后不可达 | `t.Fatal()` 后的代码 |

将不可达行从覆盖率分母中排除，并记录原因用于分析（不输出报告产物）。

## 不可达升级规则

在将任何行分类为不可达（U1-U5）之前，**必须先写最小探针测试验证该行确实不可达**。如果探针显示该行可达，写一个正式测试用例。

特别适用于：字符串前缀回退分支（不是默认不可达，用 `errors.New()` 测试）、错误处理路径中的条件回调块。

## 层级升级规则

当使用L1-L3后覆盖率≤90%时，在将分支分类为不可达之前，**必须先升级到L5（gomonkey）**。升级顺序：F8+L1/L2/L3 → L4 for F4 → L5 for F5/F7 → 归类为不可达（需探针验证）。

1. 是否运行了 `go test -coverprofile`？— YES / NO
2. 实际百分比是多少？→ ____%（必须 >90%）
3. 是否运行了 `go test -race`？— YES / NO
4. 是否完成逐行归因分析？— YES / NO
