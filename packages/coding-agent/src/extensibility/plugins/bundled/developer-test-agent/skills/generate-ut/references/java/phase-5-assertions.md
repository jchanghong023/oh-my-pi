# 阶段 5：断言质量强制执行

## 5.1 断言目标

为确保断言**有意义且有效**，测试必须验证被测方法中尽可能多的**值变更**方面，具体包括：

1. **非局部变量**（方法作用域之外、在执行期间发生变化的状态），

2. **参数值**（内部字段被修改的输入对象），

3. **返回值**（字段反映有意义计算结果的输出对象/结构）。

断言应当聚焦于验证**可观察的状态转换**，而非表面的结果。

## 5.2 推荐断言（必须断言的内容）

### 5.2.1 非局部变量（被修改的外部状态）

识别在执行期间值发生变化的任何**非局部变量**（例如：类字段、共享对象、依赖状态、缓存、仓储、静态/全局持有者）。

断言必须验证：

* 发生变化的**确切字段**。
* 正确的前后值。
* 结构性更新，例如：

    * 集合元素的新增或删除
    * 计数器的更新
    * 实体的持久化
    * 记录的写入
* 通过依赖项产生的可观察副作用。

**目标：** 检测方法是否产生了预期的外部状态变更。

---

### 5.2.2 参数值（被修改的输入）

如果方法修改了输入参数（按引用传递的对象），断言必须验证：

* **参数内部**哪些字段发生了变化。
* 每个变更字段的正确性。
* 结构性变更，例如：

    * 集合大小的变化
    * Map 的更新
    * 嵌套对象的修改

**目标：** 确保输入变更符合预期的行为契约。

---

### 5.2.3 返回值（计算输出）

断言必须在**字段级别**验证返回值，而不仅仅是验证存在性。

必要的检查包括：

* 关键业务字段
* 派生/计算值
* 嵌套对象属性
* 集合内容（以及相关性时的顺序）
* 状态标志、错误码和元数据

**目标：** 确认返回的对象完整反映了预期的计算结果。

---

## 5.3 非推荐断言（必须避免）

避免使用无法验证真实行为的断言，包括：

* 仅验证存在性的断言：

    * `assertNull(...)`
    * `assertNotNull(...)`
* 虚假断言：

    * `assertTrue(true)`
* 与状态转换、变更或业务正确性无关的断言。

如果某条断言在核心逻辑被破坏时仍然能够通过，则该断言是**不可接受的**。

## 5.4 Flux/Mono 场景

在为 **Flux** 和 **Mono** 编写单元测试时，断言必须验证完整的响应式契约——包括发射的元素、终止信号、错误行为以及可观察的副作用。测试应当聚焦于**行为正确性**而非实现细节。

### 5.4.1 断言目标

响应式流遵循严格的信号生命周期：
onSubscribe → onNext (0..N) → (onComplete | onError | cancel)

断言必须验证：

* 发射了什么
* 以何种顺序
* 流如何终止
* 是否发生了错误
* 时序、重试或背压行为是否正确

仅验证值而忽略终止信号的测试被视为不完整。

### 5.4.2 断言策略参考

| 断言目标                            | Recommended Assertion                                           | 关键规则                                                                                                        |
| ----------------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 发射期望值并完成                    | `expectNext(...)` → `verifyComplete()`                          | 始终同时断言发射的数据**和**终止信号，以确保响应式契约得到完整验证。                                            |
| Mono 成功（单个值）                | `expectNext(value)` → `verifyComplete()`                        | 将成功的 `Mono` 视为两段式契约：**一个值 + 完成**。                                                             |
| 空发布者                            | `verifyComplete()` 或 `expectNextCount(0)` → `verifyComplete()` | 显式验证**无发射**且**正常完成**。                                                                              |
| 多个值（顺序敏感）                  | `expectNext(a, b, c)`                                           | 当顺序正确性重要时使用严格顺序。                                                                                |
| 多个值（仅计数）                    | `expectNextCount(n)` → `verifyComplete()`                       | 仅在值正确性已在其他地方验证时使用；否则优先使用显式匹配。                                                      |
| 基于谓词的匹配                      | `expectNextMatches(predicate)` 或 `assertNext(consumer)`        | 对于复杂对象优先使用谓词检查，而非依赖 `equals()`。                                                              |
| 记录并检查发射                      | `recordWith(...)` → `consumeRecordedWith(...)`                  | 在验证复杂集合或聚合属性时先进行记录。                                                                          |
| 错误终止（类型）                    | `expectError(SomeException.class)`                              | 当预期失败时始终验证**错误类型**。                                                                              |
| 错误终止（细节）                    | `expectErrorSatisfies(...)`                                     | 验证消息、原因或领域字段，而不过度拟合到精确字符串。                                                            |
| 发射值后失败                        | `expectNext(...)` → `expectError(...)`                          | 同时断言错误前的发射和失败信号。                                                                                |
| 取消行为                            | `thenCancel()` → `verify()`                                     | 在测试 `take`、`timeout` 或手动释放等操作符时使用取消断言。                                                     |
| 背压 / 请求控制                     | `StepVerifier.create(publisher, 0)` → `thenRequest(n)`          | 以零需求开始，以精确验证生产者行为。                                                                            |
| 基于时间的操作符                    | `withVirtualTime(...)` → `thenAwait(...)`                       | 优先使用**虚拟时间**而非真实延迟，以保持测试的确定性和快速性。                                                  |
| 超时保护                            | `verifyTimeout(Duration)`                                       | 通过强制最大执行窗口防止测试挂起。                                                                              |
| 重试 / 重新订阅                     | 结合 StepVerifier 与计数器或 mock 验证                          | 通过可观察的副作用验证订阅或重试次数。                                                                          |
| 兜底 / 恢复路径                     | 注入错误源 → 断言兜底发射                                       | 显式测试恢复逻辑，例如 `onErrorResume`。                                                                       |
| Reactor Context 使用                | `contextWrite(...)` → `expectNext(...)`                         | 在测试中注入上下文，并验证其是否正确影响行为。                                                                  |
| 调度器 / 线程行为                   | 必要时在 `doOnNext` 中捕获线程                                  | 优先断言可观察行为；仅当调度属于契约一部分时才验证线程。                                                        |
