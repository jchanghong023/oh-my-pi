Run a dynamic workflow through the native compiler, sandbox and OMP actor sessions. Provide exactly one source: `script` for a complete inline script, `saved: {name, args?, scope?}` for an existing saved definition, or `path` for a script file. Inline scripts take no args; top-level `args` belongs only to `path`. Saved definitions keep their declared argument validation and defaults. Give inline runs a short name in the user's language.

The workflow facade is TypeScript: use `agent("reviewer").ask("instructions")` for model work and the compiler-provided `files`, `git`, `world.run`, and `artifact` APIs for world operations. Ordinary JavaScript globals such as process, require and fetch are not workflow APIs. Type errors mean nothing ran; repair the diagnostics before submitting again. Do not substitute raw process execution for the workflow engine.

Set `max_concurrency` or `subagent_model` only when the user requests that change. Subagents use the native session model by default. A successful submission returns its actual background run ID, not its final output. Do not repeatedly poll or submit it again. The existing workflow run state and detail pane track progress, results and artifacts.

ResumeWorkflowRun takes `run_id` and resumes the same journaled script, arguments and run ID. Completed steps replay from the durable journal; unfinished steps execute again. Only stopped, non-superseded runs can resume. Never resume a user-cancelled run without the user's request. Script failures require correcting the script rather than blindly resuming it. Cancellation must stop the owned run and drain its sandbox and actor sessions; a cancelled submission is not success.
