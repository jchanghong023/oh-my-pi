# 接口变更评审

## 工作方式
先读取项目接口规范、当前 diff、接口定义及相关测试，再核对受影响调用方。不要假定没有提供的客户端行为；缺少关键材料时先向用户索取。

1. 确认变更涉及接口契约；纯排版修改说明不适用。
2. 按 references/checklist.md 检查请求、响应和错误处理的兼容性。
3. 对每项问题列出文件位置、影响、证据与兼容过渡建议。
4. 将已确认问题和待核实项分开；不修改代码，不宣称未运行的测试通过。

## 输出
按严重程度报告问题；没有足够证据时明确说明缺口，不编造调用方或测试结果。

> 原型固定产物样例：仅演示发送后的临时文件与保存流程，不代表模型已根据输入生成技能。
