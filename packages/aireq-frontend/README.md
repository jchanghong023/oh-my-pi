# AIReq 共享前端与独立原型

> **首要交付与维护约束：前端和接口是正式代码，原型 mock 的只是后端服务。**
>
> 后续更新必须按正式代码标准维护同一份前端、接口客户端及请求／响应／错误／实时事件契约。原型后端使用纯内存 mock，真实 OMP 后端实现相同契约；接入时只实现后端并切换地址，不改前端、不换客户端、不转换接口格式，不把前端或接口的正式化留待以后。

AIReq 是 AI 驱动的需求澄清、需求管理和开发进度跟踪平台：自然语言生成 IR／SR，四 Agent 评审后由人决定，讨论方案、依赖与人员排期，确认提案入库，再根据代码证据跟踪实现情况。**AIReq 不编码，不执行开发计划、测试、代码交付或 IR 验收归档。** 实际开发在平台之外完成。

本目录维护 AIReq 共享前端与独立可交互原型。**原型使用独立纯内存后端；预览与正式源码入口已统一到同一 bootstrap 和网络客户端，不再在页面内运行业务样例。** 后续对接真实 OMP 只实现遵守现有冻结合同的后端并配置地址，前端、客户端和接口格式不改。真实 OMP 业务后端尚未实现，不能把源码统一等同于正式服务已接通。完整规则见[平台说明](../../docs-zh-CN/spec-driven-orchestration.md)。

**AIReq 只考虑电脑端浏览器。** 设计、原型和验收不覆盖手机、平板或触屏专用布局；电脑端窄窗口与分栏拖拽仍须正常显示和操作，不是移动端适配。

## 架构目标与实施边界

- 原型和正式版共用一份前端、一套接口客户端及完全相同的浏览器代码，不按 prototype／runtime 模式编写不同业务界面，不注入两套前端业务数据源。开发、演示持续连接原型后端，接入 OMP 时只切后端地址，不复制、重写界面或替换客户端。
- 原型后端与 OMP 后端须能互相独立启动，实现同一请求、响应、错误及实时事件契约；连接、版本、缺失接口及业务错误直接显示，不转旧协议、不自动回退样例。
- 原型业务数据、状态、模拟回复、任务和事件全部在原型后端纯内存运行，不依赖数据库、Git 或模型。服务重启恢复初始样例，页面刷新或关闭不重置业务，也不停止服务任务。
- OMP 后端负责真实业务、持久化及外部能力对接，复用原生宿主能力，不新增第二执行器。既有 UI、业务门禁、权限、桌面 Firefox 128 及普通 OMP／WebGUI 非干扰边界不变。

已实现共享前端入口、同一网络客户端，以及原型独立启动、后端地址选择、请求／错误／实时事件契约和服务端内存作用域；以下命令运行原型。真实 OMP 后端仍待实现，不代表正式业务、持久化或模型／Git 能力已完成。**真实接入验收标准：只实现后端并配置地址；无需修改前端、替换客户端、迁移 runtime 或转换接口格式，即可使用相同浏览器代码完成业务。**

## Issue 管理原型

“正式需求”下方依次提供 **新建 Issue、Issue 分析、Issue 进度**。Bug、重构及其他非功能工作统一登记；Issue 仅属于项目，与 Release 无关；无 Release 的项目也可使用，切换 Release 不改变列表、表单或分析设置。单人开发，可选关联同项目任一正式 IR／SR，分支由平台分配，独立跟踪进度。分析最高 99%，合入默认分支后由人工确认到 100%，支持填写原因重新打开。

本轮只改需求文档与原型。Issue 状态、分支映射、分析调度及报告均在原型后端内存中演示，复用共享前端与契约；不接真实 OMP 后端、Git、PR、数据库或模型。未取得代码证据时不虚增进度，不提供伪造真实合入的按钮。完整需求见 [Issue 工作台规则](../../openspec/specs/aireq-browser-workbench/spec.md)。

## 当前实现：独立启动

需要 **Bun >= 1.4.4** 和现代桌面浏览器。在仓库的 `packages/aireq-frontend` 目录执行；也可把整个本目录复制到普通可写目录后执行，不复制 `node_modules` 或 `build`：

先安装依赖：

```sh
bun ./standalone.ts install
```

然后在两个终端中分别启动，两个进程均需保持运行：

```sh
# 终端一：原型业务后端
bun ./standalone.ts backend
```

```sh
# 终端二：前端预览
bun ./standalone.ts start
```

打开 **http://127.0.0.1:4173/**，或从内网其他电脑打开 **http://服务器IP:4173/**。前端默认监听 `0.0.0.0:4173`，以同源 HTTP／WS 代理连接仅监听本机的后端 `http://127.0.0.1:4174/`；浏览器不再把访问者自己的 localhost 当作服务器。各终端按 `Ctrl+C` 停止对应进程；端口占用时明确报错，不自动换端口。安装需访问 npm 包源；安装后运行原型不需要 OMP 服务、数据库、Git、模型/API 密钥、Rust、根仓库依赖、原始 vendor 前端或个人机器配置。

**即使在完整仓库内，也使用上述安装命令，不要直接运行 `bun install`。** 启动器在系统临时目录使用本包清单和 `bun.lock` 冻结安装并禁用安装脚本，再把依赖复制回本包并清理临时目录，不执行祖先 workspace 的安装脚本。重新安装前停止预览，安装会替换本包 `node_modules`；清单或锁文件变化后须重新安装。

等价脚本为 `bun run install:standalone`、`bun run backend`、`bun run start`。可选静态构建命令为 `bun ./standalone.ts build`，输出 `build/aireq`；静态页面仍需连接独立后端，不要用 `file://` 打开源码或页面。

### 内网 HTTP、子路径与后端地址

原型和正式共享前端支持普通内网 HTTP／WS，不要求 HTTPS 或浏览器“将不安全来源视为安全”设置。ID 复用共享 UUID 工具，附件保留原 SHA-256 校验值，HTTP 缺少 WebCrypto 时使用固定版本的纯 JavaScript SHA-256；复制文字由同一个工具在用户点击时兼容执行，失败不显示复制成功。浏览器麦克风仍受浏览器安全上下文限制，HTTP 下明确提示使用文字或上传音频。

若入口固定挂载在 `http://10.242.201.214:4173/xxx/xxx/`，终端一仍按前文启动后端，终端二执行：

```sh
OMP_AIREQ_BASE_PATH=/xxx/xxx/ bun ./standalone.ts start
```

`OMP_AIREQ_BASE_PATH` 必须以 `/` 开始、以 `/` 结束。独立预览默认值为 `/`；原生 runtime 构建保留默认相对基址 `./`，用于宿主已有随机能力目录，不能改成绕过能力路径的根接口。配置的是资源与接口挂载前缀，不是项目或工作区目录。原型的 Vite 代理自动移除这个前缀，再将 `/api/aireq/*` HTTP 与两个 WebSocket 请求原样交给独立后端，保持冻结契约不变。静态构建时使用相同环境变量；正式静态宿主需将该前缀下的资源交给前端，并将同前缀的 `api/aireq/*` HTTP／WS 路由到真实后端，不在浏览器里加入转码或另一套接口。

- 前端读取 `OMP_AIREQ_FRONTEND_HOST`（默认 `0.0.0.0`）和 `OMP_AIREQ_FRONTEND_PORT`（默认 `4173`）。仅本机预览可显式设置 `OMP_AIREQ_FRONTEND_HOST=127.0.0.1`。
- 后端读取 `OMP_AIREQ_BACKEND_HOST`（默认 `127.0.0.1`）和 `OMP_AIREQ_BACKEND_PORT`（默认 `4174`，允许 `0` 由系统分配端口），启动后输出实际 URL。
- 前端开发／静态预览代理读取 `OMP_AIREQ_PROXY_TARGET`（默认 `http://127.0.0.1:4174`），只在预览服务器使用，不进入浏览器。例如后端改为 `4184` 时，分别执行 `OMP_AIREQ_BACKEND_PORT=4184 bun ./standalone.ts backend` 和 `OMP_AIREQ_PROXY_TARGET=http://127.0.0.1:4184 bun ./standalone.ts start`；动态端口按实际输出设置。
- 浏览器地址优先级为 **URL 查询参数 `backend` > `VITE_AIREQ_BACKEND_URL` > 当前页面 origin 加构建 BASE_URL**。前两项仅用于显式连接另一个可达后端；内网同源部署无需填写，不能把服务器的 `127.0.0.1` 发给另一台电脑的浏览器。
- 后端不可达时页面显示连接失败并提供重试，不自动回落浏览器样例。`backend` 选择服务地址，不选择个人 Web 或身份。原型工号仅作操作标识，不代表真实身份认证。

### HTTP 与实时接口契约

共享类型契约位于 [`backend/contract.ts`](./backend/contract.ts)，版本固定为 **`AIREQ_CONTRACT_VERSION = 1`**。`AIReqRemoteOperations` 显式定义每个 operation 的参数和返回类型，`AIReqRemoteCall` 为对应判别联合；请求、响应 envelope、错误码、实时事件及既有二进制 services RPC 均为真实后端必须实现的合同，不另设 OMP 格式转换层。浏览器统一通过 [`client/remote-data-source.ts`](./client/remote-data-source.ts) 访问：

| 接口 | 请求与结果 |
| --- | --- |
| `GET /api/aireq/bootstrap` | 获取初始视图、`contractVersion: 1`、能力、`provenance` 及可用的 `scenarioOperations` |
| `POST /api/aireq/call` | JSON 请求 `{path,args,selection?}`；参数及结果遵循 operation type map，未知路径拒绝 |
| HTTP 身份／样例 | 查询参数 `clientId`、`employeeId`、`demo`；每个请求独立绑定访问者，不依赖全局“当前工号” |
| HTTP 响应 | 成功 `{ok:true,value}`；失败 `{ok:false,error:{code,message}}`，客户端如实显示，不回退样例；畸形 JSON 返回 HTTP 400，无权写入返回 HTTP 403 |
| `WS /api/aireq/events` | 事件 `type` 为 `workflow`、`models`、`skills`、`scheduler`、`freeChats` 或 `error` |
| `WS /api/aireq/services` | 复用既有 zcode 二进制 RPC；选择绑定由查询参数 `workspace`、`selection`、`session` 传入 |

两个 WebSocket 连接同样通过查询参数独立绑定身份与 demo，不把一个浏览器的工号切换应用到其他连接。事件通知后由客户端读取对应状态；分析任务与历史由后端分页返回摘要，报告按需单独获取，不随状态刷新传输全部正文。

`provenance.kind` 的 `sample`／`live` 仅表示数据来源，`notice` 仅用于来源提示，不是业务 mode，也不能切换业务界面。合同不再提供 `mode` 或 `prototypeBusiness`；`capabilities.requirementManagement` 表示需求管理业务支持，`scenarioOperations` 仅标识辅助演示操作是否可用。主业务 `readPrHandoff(group)` 独立于演示操作。缺失合同接口或版本不匹配须报错，不能转旧协议或补样例结果。

## 当前实现：推荐演示路径

入口工号仅检查“小写字母加 8 位数字”，不是身份认证。可使用管理员样例 **`j00808874`** 查看配置、分配及排期操作。切换工号不切换当前 Web 所有者、Token、模型或 profile。

1. **查看正式需求**：点击左侧“自动化”下的“正式需求”，选择项目／Release，展开 IR 查看 SR。搜索、状态筛选及“我负责的”只改变浏览范围。
2. **阅读进度证据**：选中 IR／SR 行，右侧同页切换“进度报告／需求材料”，查看实现百分比、代码活动、合入依据、遗留问题、分析时间和代码版本。表格始终保留，不进入编码聊天。
3. **调整人员与排期**：正式需求中管理员给 IR 分配负责人，管理员或该负责人调整 SR 开发人员及起止时间；提案只读展示工期预估，不分配负责人、开发人员或起止时间。查看 AI 原建议、人工调整标记、依赖时间冲突及人员重叠提醒。提醒不会自动重排任务。
4. **演示方案与入库**：在需求提案中选择“共享资源预约”，从右侧材料选择器阅读 `design.md` 或选择 `sr-dependencies.json` 查看依赖图；复用现有 Canvas、Controls（React Flow），不展示 JSON 正文。节点展示 SR ID／标题，箭头从前置 SR 指向依赖方，支持缩放、平移与点击连线查看原因；独立 SR 保留节点，无效或过期材料报错而不显示旧图。工期预估卡片、依赖图与正式表格的依赖均读取 JSON，可并行关系由图推导。人工逐文件确认当前 IR、全部 SR 和两个方案文件后演示创建分支、提交推送并自动创建 MR，查看平台生成的编号、地址、标题／正文及状态；人工评审、合并后，后台定时核验并转正。
5. **演示后台自动转正**：入库阶段展开“原型后台结果演示”，预置“已合入且文档完整”。下一轮检查自动转为正式需求并演示创建、推送 SR 分支；负责人、开发人员和排期保留，新 SR 仍为 0%。也可选择未合入、文档不完整或获取失败，查看保留提案及检查原因。
6. **从自然语言开始**：点击“新建需求提案”，输入目标与异常场景。首次消息接纳后才出现提案记录；原型按固定模板生成 IR 及两个 SR，不是语义拆分。补充需求、发起四 Agent 评审、阅读综合意见并人工选择通过或返回补充，再讨论方案并确认入库。

可在预览地址后添加以下参数，选择对应的具名后端样例作用域：

| 地址参数 | 演示入口 |
| --- | --- |
| `?demo=empty-requirements` | 空需求列表，从新建提案开始 |
| `?demo=requirements-review` | “自动化工作流探索”提案，查看当前版本的四 Agent 评审 |
| `?demo=review-chat` | 已准备的评审会话，默认综合意见，可追问或切换 A／B／C |
| `?demo=proposal-intake` | 方案就绪的提案，演示人工确认、推送与后台检查 |
| `?demo=analysis-scale` | 需求分析规模样例：初始 300 个 SR 任务、1000 条执行历史，进入设置 → 主页 → 需求分析 |

正常入口及每个具名 demo 各有一份独立的后端 worker 纯内存作用域，不为每个浏览器新建；连接同一后端、同一 demo 的访问者共享业务修改，不同 demo 互不污染。worker 重入 `backend/main.ts`，通过进程内 IPC 传递调用，不再次转发 HTTP。**刷新或关页不重置业务，也不停止后端任务；重启原型后端才恢复初始样例。** 主题和部分草稿等浏览器偏好仍可能保留，清除站点数据不是业务重置手段。不再把旧 SR 开发、IR 验收或目录故障场景作为当前平台演示路径。

## 当前交互规则

### 提案、评审与方案

提案保持左侧 IR 列表、中间讨论、右侧只读材料的三栏；分组使用提案文档图标，列表不展开 SR，SR 规格从材料选择器阅读。提案只记录提交人，不设置负责人；筛选为阶段、提交人和单项“入库检查：需要处理”，不细分检查问题，正常等待合入不算异常。合入且材料完整后自动离开提案列表。提案按业务需求、需求评审、技术方案、需求入库推进，流程操作位于右侧材料底栏。查看历史不会推进流程。

新建只打开未发送草稿，重复点击复用；首次发送成功才入列表，失败保留文字与附件。需求修改保留稳定 SR ID，更新材料版本，并使旧评审、方案及确认失效，不自动推进。

输入框与空材料区按业务目标、使用场景、完成标准引导，明确发送后再由 AI 追问。四阶段名称使用原生时间线紧凑展示；方案右栏可直接切换技术方案、SR 依赖、人员与排期，文件完整路径放在可展开的技术信息中，确认与版本门禁不变。

正式需求继续默认收起导航；表头移除前后列按钮与隐藏列提示，使用原生滚动条；表格铺满剩余面板宽度，两侧仅留12／16px。通用自动化提供需求分析入口，AIReq 不显示桌面保持唤醒开关；普通非 AIReq 自动化不受影响。

所有业务参与人在同一个共享 Web 继续方案、退回或确认当前材料，不要求个人 Web 或开发目录。工作区菜单同时显示访问工号与固定启动者，切换工号不切换 Web、Token 或 profile。

评审 A／B／C 使用三个不同模型，并行独立只读审查同版 IR／全部 SR；第四个综合评审 Agent 汇总来源、依据和分歧。默认阅读综合意见，Agent 头像可切换四个独立会话，“评审流程”展示原生三路并行汇合图。只读不禁止追问，但不修改需求；材料与四份同版报告完整后，**由人决定**通过或返回补充，模型评分、票数或问题标签不决定通过。原型展示固定报告，不运行多模型任务。

方案、SR 依赖和工期预估由方案 Agent 通过对话生成及更新，不提供“生成技术方案／生成方案／重新生成方案”按钮。人负责讨论、核对和逐文件确认。原型在当前方案轮次的一次非空文本消息被接受后，以固定回复模拟 AI 完成本轮产出，同时更新两份内存材料的版本和讨论内容，使旧确认失效；工期数值与依赖仍为固定样例，不代表真实语义分析。历史轮次、失败或拒绝的发送不更新当前方案，重复命令沿用既有去重机制。无真实模型调用、文件写入或 Git 操作；本轮不运行测试。

方案 Agent 讨论技术思路、边界、SR 依赖与可并行关系，不编制编码执行计划。业务缺口由人填写退回意见，返回业务 Agent 对话补充、重评后重新进入方案；保留长意见及历轮会话，不自动拆题分派。方案未完成或失效时不沿用旧建议。

评审与方案的退回都是实际返回业务阶段，列表与重新进入保持一致；待处理意见须先经业务讨论更新 IR／SR，再重新评审，不能直接跳过。取消退回不修改阶段。

方案 Agent 同轮生成、更新 `openspec/changes/<change-id>/design.md` 与同目录 `sr-dependencies.json`；两者沿用同一需求版本／方案轮次，需求补充或退回时一同失效。`design.md` 保留实现思路与技术取舍，只引用 JSON，不重复依赖清单；SR `spec.md` 不维护依赖。JSON 缺失、不可读、无效或过期时不回退旧图，禁止沿用方案确认、提交推送与自动转正。原型材料仅保存在后端内存，无真实文件生成。

### 提案工期预估与正式需求安排

提案右侧提供“技术方案／SR 依赖／工期预估”。每个 SR 的预估与依赖存于同一个 `sr-dependencies.json`：`estimate: { workingDays: 3, assumptions: "估算依据与不确定项" }`。工作日为正数，可用小数；预估不等于实际用时或承诺日期，不直接求和为 IR 总工期。界面只读，人通过方案对话让 AI 修改文件，同轮更新及失效确认、随同一 PR 评审。无有效预估不得沿用旧确认。

提案不分配负责人、开发人员和计划起止时间。转正保留仓库预估和依赖，再由管理员给正式 IR 分配负责人，由管理员或负责人安排 SR 人员及起止时间；正式安排为数据库元数据，不自动从预估换算、不反写 JSON。正式需求保留原有校验、人工记录、冲突提醒及 IR 时间汇总规则。

### 确认推送与自动转正

方案完成并人工逐文件确认当前 IR、全部 SR、`design.md` 与 `sr-dependencies.json` 后，才从最新默认分支创建提案分支并提交推送；此前不创建分支。平台按需拉取并管理内部工作副本，无需个人开发目录。

平台自动创建 MR 并记录编号、地址与状态；人到企业 Git 平台评审及合并，后台定时查询 MR 并核验实际合入与完整材料后转正。无需手填链接，没有自动合并或人工“确认合入”按钮。需求或方案版本变化使旧确认与推送失效，历史记录保留。

后台转正检查**提案分支已合入默认分支且 IR／全部 SR／两个当前方案产物完整有效**，包括 JSON 可读、覆盖及依赖图合法性。满足即进入正式表格，再从包含提案的最新默认分支创建推送 SR 分支，记录基点及映射；重复检查不重复创建。转正保留业务身份、人员及排期，新 SR 为 0%，不代表代码完成，也不提前同步已实现规格或归档 Change。

原型后端每 5 秒只读取内存预置结果，展示分支、基点、检查结果、最近及下次检查时间，刷新或关页不停止检查。未合入、文件不完整或获取失败保留提案并继续检查。正式目标还需核实真实 Git 中 merge／squash／rebase 的合入事实；服务端模拟不能替代。

提案列表按当前项目／Release 提供入库检查数量与组合筛选：检查失败、文档不完整、等待合入、首次／下轮检查等。未推送及其他阶段不误算等待合入；列表巡查只读取现有检查结果，不发起检查或推进阶段。

### 正式表格与进度报告

正式需求默认收起左侧提案导航，顶部提供导航开关及项目／版本选择。九列表格为：需求、状态与进度、负责人／开发人员、开发分支、依赖关系、计划开始、计划结束、问题、最近分析；固定表头和名称列，单层横向滚动。展开 IR 后，直接点击各 SR 的开发分支名称复制完整值，长名可悬停或聚焦查看；复用分析列表的分支复制组件，成功／失败明确反馈，访客同样可用，不触发行选择或 Git。优先读取 SR 分支映射，其次读取当前分析关联分支，无关联时明确显示而不猜测分支名。右侧报告／材料默认占内容区 35%，最小 360px、最大 50%，可拖拽调整；不新增手机布局或底部报告。

“我负责的”包含本人负责的 IR 或本人参与开发的 SR 所属 IR，保留整组需求作为上下文。新增指定 IR 负责人工号精确筛选及未分配 IR 筛选；检索弹层不挤占表格高度，支持工号、样例姓名／部门，直接输入目录外工号也可保存。目录姓名与部门均为虚构样例，不核验身份。可一键清除搜索、状态和人员筛选。提案搜索可匹配 SR 标题／编号，但只返回所属 IR，不恢复 SR 独立讨论。

顶部区分“当前筛选 N 个 IR”和“项目总计（当前版本）M 个 IR · K 个 SR”，清除筛选后当前数量恢复，项目／版本总计不随筛选变化。报告先展示当前状态、百分比、问题、已实现内容及待补充证据，再显示人员与计划时间和详细来源；顶部保留原型预置报告标识。

“人工确认完成”不可用时，原因直接显示在按钮旁并作为可访问说明：未合入最高 99%、已经完成无需重复确认，或缺少分析报告无法确认。既有合入、完成和人工依据门禁不变。

- IR 百分比取所属全部 SR 的算术平均，没有 SR 时为 0%；全部 SR 完成才完成，不能把未完成值四舍五入成 100%。
- SR 的0%～99%只由AI分析；AI最高99%。正式SR必须有非空平台开发分支，缺失显示异常。
- AI 分析到99%、开发分支非空且已合入后，才允许人工确认到100%／已完成；合入不自动提升进度，其他百分比仅由AI分析。
- 管理员或 IR 负责人仅可在 SR 报告中将符合条件的99%确认到100%，须填写依据；人员与时间调整不影响代码进度。
- 人工百分比旁直接标明“人工确认”，首屏显示来源、时间和依据；旧 AI 报告明确为此前分析。新转正 SR 尚无报告时显示“尚未分析”，不预填历史分析时间、代码版本或实现结论。
- 正式需求没有开发聊天、计划／执行 Agent、SR 交付流程或 IR 验收归档流程。代码证据来自外部开发活动，AIReq 只分析和跟踪。

IR 材料包括 `proposal.md`、全部 SR 的 `spec.md` 和 `design.md`；选择 SR 后只展示自身规格。按材料业务类型选择，再显示完整路径及正文，不提供复制、下载或带入讨论按钮。缺失、未生成与读取失败明确区分，重试保留对象，不自动重放操作或回落样例。

### 需求分析

从主页侧栏“正式需求”上方进入，设置不再提供该业务页面入口；模型及个性化配置保留在设置中。项目范围与调度设置默认收起，任务与执行历史为主要工作区。页面分“项目分析范围”和“统一调度与执行历史”。项目表支持按名称搜索，开关直接保存，新项目默认关闭；首个样例项目预置开启。第二部分包含全局自动开关、统一间隔（默认 60 分钟、正整数分钟）及运行摘要，下方切换“SR 任务／执行历史”标签，不上下堆叠列表。

项目／IR 联动筛选与 SR 名称／编号搜索直接过滤两类列表；历史另支持状态和时间筛选。任务与历史独立分页，默认 25 条、可选 50 条，显示总数、页码并支持首尾／前后翻页，固定表头和限定滚动区域，只渲染当前标签当前页。筛选变化重置相应页码，切标签和翻页保留筛选、各自页码；数据变化自动夹至合法页。

每个 SR 的任务与历史行展示分支名，点击即可复制完整分支名；访客同样可用，复制成功或失败有反馈，不执行 Git 操作，历史使用当次运行的分支。

桌面首屏优先显示项目开关、调度摘要和任务数据，间隔编辑与原型说明／模拟按钮收起在“调度设置”。分支独立成列，长分支单行省略、悬停或聚焦可看完整名称；复制成功原位显示勾号并播报结果。表格名称／编号分层、时间简写，分页统一位于列表底部。

“分析当前筛选范围的 N 个 SR”处理所有匹配且可接纳的任务，不限当前页，不受历史状态／时间影响，排除停用项目、完成和运行中的 SR。摘要查询不返回报告正文；任务失败行可就近查看原因或仅重试该 SR，历史也按 ID 读取单份报告，在当前视口弹窗展示，关闭返回触发控件。切换筛选／页码／标签关闭旧报告。全员可查询与查看，仅 Web 启动者可配置、立即分析、重试或推进演示；项目关闭、已完成或运行中的 SR 不接受重试，并显示原因。

## 暂缓功能及连接错误边界

浏览器控制、电脑控制、快捷键自定义、子智能体管理、插件管理暂不实现。AIReq 与 WebGUI 保留原生静态设置页；开关和写操作禁用，插件只展示打包的目录及本地搜索。前端不加载这些功能服务、不查询权限、不读写配置、不订阅事件。聊天输入框的子智能体目录预加载、插件引用目录／图标订阅和插件市场排序配置加载也已停用；不能通过输入框绕过设置页的静态边界。原生聊天命令、Skill、界面基本快捷键及 OMP／TUI 工具不属于这一裁剪范围。

不为消除控制台错误补桌面服务或空成功接口。当前共享网络契约版本为 **3**：bootstrap 的 `serviceManifest` 列出实际已注册服务及可调用／订阅成员，客户端只暴露已声明能力；缺少必需服务明确报错，未声明的可选事件不订阅。原型从内存服务注册表生成清单，后续正式服务遵循同一协议；本轮未实现真实业务后端。

与暂缓功能无关的连接错误仍须修正：切换工作区时立即标记旧连接失效，避免旧服务重新挂载；正常释放连接先等待已发出的 RPC 完成。每个工作区注册使用独立服务投影，避免同一 Agent 被错误注册为多个端点；Git 读取等待原生会话归属确认，不绕过所有权检查。这些属于正式前端／连接协议修正，不是新增业务接口。
