# Dev 共享前端与独立原型

Dev 是 AI 驱动的需求澄清、需求管理和开发进度跟踪平台：自然语言生成 IR／SR，四 Agent 评审后由人决定，讨论方案、依赖与人员排期，确认提案入库，再根据代码证据跟踪实现情况。**Dev 不编码，不执行开发计划、测试、代码交付或 IR 验收归档。** 实际开发在平台之外完成。

本目录维护共享 UI 和独立可交互原型；独立预览注入内存样例，OMP 正式入口使用真实宿主适配层。两者共用 `app/DevApplication.tsx`，不复制界面。原型状态不是后端实现或运行验证结果。完整规则见[平台说明](../../docs-zh-CN/spec-driven-orchestration.md)。

**Dev 只考虑电脑端浏览器。** 设计、原型和验收不覆盖手机、平板或触屏专用布局；电脑端窄窗口与分栏拖拽仍须正常显示和操作，不是移动端适配。

## 独立启动

需要 **Bun >= 1.4.4** 和现代桌面浏览器。在仓库的 `packages/dev-frontend` 目录执行；也可把整个本目录复制到普通可写目录后执行，不复制 `node_modules` 或 `build`：

```sh
bun ./standalone.ts install
bun ./standalone.ts start
```

打开 **http://127.0.0.1:4173/**，按 `Ctrl+C` 停止。默认仅监听本机；端口占用时明确报错，不自动换端口。安装需访问 npm 包源；安装后运行原型不需要 OMP 服务、模型/API 密钥、Rust、根仓库依赖、原始 vendor 前端或个人机器配置。

**即使在完整仓库内，也使用上述安装命令，不要直接运行 `bun install`。** 启动器在系统临时目录使用本包清单和 `bun.lock` 冻结安装并禁用安装脚本，再把依赖复制回本包并清理临时目录，不执行祖先 workspace 的安装脚本。重新安装前停止预览，安装会替换本包 `node_modules`；清单或锁文件变化后须重新安装。

等价脚本为 `bun run install:standalone`、`bun run start`。可选静态构建命令为 `bun ./standalone.ts build`，输出 `build/dev`；不要用 `file://` 打开源码或页面。

## 推荐演示路径

入口工号仅检查“小写字母加 8 位数字”，不是身份认证。可使用管理员样例 **`j00808874`** 查看配置、分配及排期操作。切换工号不切换当前 Web 所有者、Token、模型或 profile。

1. **查看正式需求**：点击左侧“自动化”下的“正式需求”，选择项目／Release，展开 IR 查看 SR。搜索、状态筛选及“我负责的”只改变浏览范围。
2. **阅读进度证据**：选中 IR／SR 行，右侧同页切换“进度报告／需求材料”，查看实现百分比、代码活动、合入依据、遗留问题、分析时间和代码版本。表格始终保留，不进入编码聊天。
3. **调整人员与排期**：管理员给 IR 分配负责人；管理员或该负责人调整 SR 开发人员及起止时间。查看 AI 原建议、人工调整标记、依赖时间冲突及人员重叠提醒。提醒不会自动重排任务。
4. **演示方案与入库**：在需求提案中选择“共享资源预约”，从右侧材料选择器阅读 `design.md` 或选择 `sr-dependencies.json` 查看依赖图；复用现有 Canvas、Controls（React Flow），不展示 JSON 正文。节点展示 SR ID／标题，箭头从前置 SR 指向依赖方，支持缩放、平移与点击连线查看原因；独立 SR 保留节点，无效或过期材料报错而不显示旧图。开发安排卡片与正式表格的依赖、原因均读取 JSON，可并行关系由图推导。人工逐文件确认当前 IR、全部 SR 和两个方案文件后演示提交推送，查看 PR 标题／正文；PR 由人到 Git 网页创建、评审和合并，地址选填。
5. **演示后台自动转正**：入库阶段展开“原型后台结果演示”，预置“已合入且文档完整”。下一轮检查自动转为正式需求并演示创建、推送 SR 分支；负责人、开发人员和排期保留，新 SR 仍为 0%。也可选择未合入、文档不完整或获取失败，查看保留提案及检查原因。
6. **从自然语言开始**：点击“新建需求提案”，输入目标与异常场景。首次消息接纳后才出现提案记录；原型按固定模板生成 IR 及两个 SR，不是语义拆分。补充需求、发起四 Agent 评审、阅读综合意见并人工选择通过或返回补充，再讨论方案并确认入库。

可在预览地址后添加以下参数，刷新重新初始化对应样例：

| 地址参数 | 演示入口 |
| --- | --- |
| `?demo=empty-requirements` | 空需求列表，从新建提案开始 |
| `?demo=requirements-review` | “自动化工作流探索”提案，查看当前版本的四 Agent 评审 |
| `?demo=review-chat` | 已准备的评审会话，默认综合意见，可追问或切换 A／B／C |
| `?demo=proposal-intake` | 方案就绪的提案，演示人工确认、推送与后台检查 |
| `?demo=analysis-scale` | 需求进度分析规模样例：初始 300 个 SR 任务、1000 条执行历史，进入设置 → 平台配置 → 需求进度分析 |

这些参数及正常入口都是当前页面独立的内存样例，不共享浏览器或其他 Web 的修改。刷新恢复业务夹具，关页停止模拟检查；主题和部分草稿等浏览器偏好可能保留，清除站点数据可完全重置。不再把旧 SR 开发、IR 验收或目录故障场景作为当前平台演示路径。

## 当前交互规则

### 提案、评审与方案

提案保持左侧 IR 列表、中间讨论、右侧只读材料的三栏；列表不展开 SR，SR 规格从材料选择器阅读。提案按业务需求、需求评审、技术方案、需求入库推进，流程操作位于右侧材料底栏。查看历史不会推进流程。

新建只打开未发送草稿，重复点击复用；首次发送成功才入列表，失败保留文字与附件。需求修改保留稳定 SR ID，更新材料版本，并使旧评审、方案及确认失效，不自动推进。

输入框与空材料区按业务目标、使用场景、完成标准引导，明确发送后再由 AI 追问。四阶段名称使用原生时间线紧凑展示；方案右栏可直接切换技术方案、SR 依赖、人员与排期，文件完整路径放在可展开的技术信息中，确认与版本门禁不变。

正式需求继续默认收起导航；表头区提供前后列按钮、隐藏列提示及方向键／Home／End 导航。通用自动化提供需求进度分析入口，Dev 不显示桌面保持唤醒开关；普通非 Dev 自动化不受影响。

所有业务参与人在同一个共享 Web 继续方案、退回或确认当前材料，不要求个人 Web 或开发目录。工作区菜单同时显示访问工号与固定启动者，切换工号不切换 Web、Token 或 profile。

评审 A／B／C 使用三个不同模型，并行独立只读审查同版 IR／全部 SR；第四个综合评审 Agent 汇总来源、依据和分歧。默认阅读综合意见，Agent 头像可切换四个独立会话，“评审流程”展示原生三路并行汇合图。只读不禁止追问，但不修改需求；材料与四份同版报告完整后，**由人决定**通过或返回补充，模型评分、票数或问题标签不决定通过。原型展示固定报告，不运行多模型任务。

方案 Agent 讨论技术思路、边界、SR 依赖与可并行关系，不编制编码执行计划。业务缺口由人填写退回意见，返回业务 Agent 对话补充、重评后重新进入方案；保留长意见及历轮会话，不自动拆题分派。方案未完成或失效时不沿用旧建议。

评审与方案的退回都是实际返回业务阶段，列表与重新进入保持一致；待处理意见须先经业务讨论更新 IR／SR，再重新评审，不能直接跳过。取消退回不修改阶段。

方案 Agent 同轮生成、更新 `openspec/changes/<change-id>/design.md` 与同目录 `sr-dependencies.json`；两者沿用同一需求版本／方案轮次，需求补充或退回时一同失效。`design.md` 保留实现思路与技术取舍，只引用 JSON，不重复依赖清单；SR `spec.md` 不维护依赖。JSON 缺失、不可读、无效或过期时不回退旧图，禁止沿用方案确认、提交推送与自动转正。全部材料仅保存在页面内存，无真实文件生成。

### 人员、依赖与计划时间

方案材料旁的独立卡片展示 AI 建议起止、假设及安排；管理员可分配唯一 IR 负责人，管理员或负责人可修改 SR 开发者及时间，其他用户只读。起止同时填写或清空，结束晚于开始；不单列工时。IR 时间由 SR 最早开始、最晚结束汇总，部分未排期须提示。

开发人员工号为一个小写英文字母后接 8 位数字（如 `j00808874`），可留空；字段旁显示格式，非法输入给出具体错误，修正后清除。

保留 AI 原建议、人工标记及记录，冲突仅提醒，不自动移动其他 SR，不根据计划计算进度。人员及时间属于目标共享数据库元数据，不写进 JSON；需求、验收条件与方案属于仓库文档。`sr-dependencies.json` 是唯一依赖权威，结构为 `{"srs":[{"srId":"稳定 SR ID","prerequisites":[{"srId":"前置稳定 SR ID","reason":"原因"}]}]}`：覆盖 IR 全部 SR，每个恰好一次，无依赖用 `[]`，禁止未知 ID、自依赖及循环；不重复存储可并行关系。人员与时间编辑不改变文档或已有推送、不产生 PR、不增加入库条件；依赖修改仍走方案讨论与 PR 评审。

### 确认推送与自动转正

方案完成并人工逐文件确认当前 IR、全部 SR、`design.md` 与 `sr-dependencies.json` 后，才从最新默认分支创建提案分支并提交推送；此前不创建分支。平台按需拉取并管理内部工作副本，无需个人开发目录。

人到企业 Git 网页创建、评审及合并 PR，平台不自动创建 PR、不依赖 PR API。PR 链接选填，没有人工“确认合入”按钮。需求或方案版本变化使旧确认与推送失效，历史记录保留。

后台转正检查**提案分支已合入默认分支且 IR／全部 SR／两个当前方案产物完整有效**，包括 JSON 可读、覆盖及依赖图合法性。满足即进入正式表格，再从包含提案的最新默认分支创建推送 SR 分支，记录基点及映射；重复检查不重复创建。转正保留业务身份、人员及排期，新 SR 为 0%，不代表代码完成，也不提前同步已实现规格或归档 Change。

原型每 5 秒只读取内存预置结果，展示分支、基点、检查结果、最近及下次检查时间。未合入、文件不完整或获取失败保留提案并继续检查。真实目标需服务端独立运行，并核实 merge／squash／rebase 的合入事实；浏览器模拟不能替代。

提案列表按当前项目／Release 提供入库检查数量与组合筛选：检查失败、文档不完整、等待合入、首次／下轮检查等。未推送及其他阶段不误算等待合入；列表巡查只读取现有检查结果，不发起检查或推进阶段。

### 正式表格与进度报告

正式需求默认收起左侧提案导航，顶部提供导航开关及项目／版本选择。九列表格为：需求、状态与进度、负责人／开发人员、开发分支、依赖关系、计划开始、计划结束、问题、最近分析；固定表头和名称列，单层横向滚动。展开 IR 后，直接点击各 SR 的开发分支名称复制完整值，长名可悬停或聚焦查看；复用分析列表的分支复制组件，成功／失败明确反馈，访客同样可用，不触发行选择或 Git。优先读取 SR 分支映射，其次读取当前分析关联分支，无关联时明确显示而不猜测分支名。右侧报告／材料默认约 380px，可在 320～480px 拖拽；不新增手机布局或底部报告。

“我负责的”包含本人负责的 IR 或本人参与开发的 SR 所属 IR，保留整组需求作为上下文。新增指定 IR 负责人工号精确筛选及未分配 IR 筛选；检索弹层不挤占表格高度，支持工号、样例姓名／部门，直接输入目录外工号也可保存。目录姓名与部门均为虚构样例，不核验身份。可一键清除搜索、状态和人员筛选。提案搜索可匹配 SR 标题／编号，但只返回所属 IR，不恢复 SR 独立讨论。

顶部区分“当前筛选 N 个 IR”和“项目总计（当前版本）M 个 IR · K 个 SR”，清除筛选后当前数量恢复，项目／版本总计不随筛选变化。报告先展示当前状态、百分比、问题、已实现内容及待补充证据，再显示人员与计划时间和详细来源；顶部保留原型预置报告标识。

“人工确认完成”不可用时，原因直接显示在按钮旁并作为可访问说明：未合入最高 99%、已经完成无需重复确认，或缺少分析报告无法确认。既有合入、完成和人工依据门禁不变。

- IR 百分比取所属全部 SR 的算术平均，没有 SR 时为 0%；全部 SR 完成才完成，不能把未完成值四舍五入成 100%。
- SR 未合入默认分支时，AI 和人工均最高 99%，不能确认完成。
- 合入且 AI 确认全部实现或人工根据证据确认，才为 100%／已完成；合入不直接等于完成。AI 不确定时保留百分比、遗留问题和不确定项。
- 管理员或 IR 负责人可在 SR 报告中调整进度或确认完成，须填写依据；人员与时间调整不影响代码进度。
- 人工百分比旁直接标明“人工调整／人工确认”，首屏显示来源、时间和依据；旧 AI 报告明确为此前分析。新转正 SR 尚无报告时显示“尚未分析”，不预填历史分析时间、代码版本或实现结论。
- 正式需求没有开发聊天、计划／执行 Agent、SR 交付流程或 IR 验收归档流程。代码证据来自外部开发活动，Dev 只分析和跟踪。

IR 材料包括 `proposal.md`、全部 SR 的 `spec.md` 和 `design.md`；选择 SR 后只展示自身规格。按材料业务类型选择，再显示完整路径及正文，不提供复制、下载或带入讨论按钮。缺失、未生成与读取失败明确区分，重试保留对象，不自动重放操作或回落样例。

## 设置与多人边界

项目设置只有名称、Git 远程地址和默认分支，Release 沿用项目配置。保存只记录内存配置并检查格式，不执行 clone／fetch／push；卡片、编辑表单及保存反馈明确区分配置已记录与仓库连接／默认分支未检查。原型没有真实检查入口，不伪造通过状态；真实接入后须分别显示连接和分支检查结果。项目与 Release 设置仅启动该共享 Web 的人可修改，其他账号只读；不要求个人开发目录。

目标部署只启动一个共享 `omp dev_web`，所有人访问同一地址；`--port <端口>` 指定端口，省略则选择可用端口并输出 URL。`omp dev_db` 在固定端口 **18321** 管理 `/tmpdata/DFT_LAB/omp/omp_dev_sqlite.db`，Web 经服务访问业务数据，不直接多端打开 NFS SQLite。**这是目标约定，本次不实现这些服务或单实例门禁。**

所有访问者共享项目、Release、提案及正式需求，并在同一 Web 讨论；使用启动者的 Token／profile，切换工号不改变后端。原型固定启动者样例为 `j00808874`，不再用 `backend` 参数切换个人 Web。工号和权限只作展示，不构成认证、跨端同步或安全隔离。

所有人都能查看全部设置；**外观和 Skill 设计所有人可用，其余设置仅启动者可修改**。其他账号保留切换查看、搜索、筛选和复制，草稿编辑、保存及快捷键不得绕过只读；不隐藏页面。模型、个性化、Agent 和原技能管理仍属受限设置，不能借 Skill 设计修改。角色包括业务需求、评审 A／B／C、综合评审、方案、需求进度分析和 Skill 设计；配置只影响新会话／轮次，历史保留快照，未保存配置离开时可保存、丢弃或取消。

个性化和模型配置离开前均提示保存／丢弃／取消；保存使用最新草稿。追加提示词按每个 Agent 的 UTF-8 字节数限制为 100 KiB，超限保留内容并禁止普通保存、快捷键及保存并离开，缩短后恢复。Git URL 须含主机，SCP 地址仍支持；格式通过不等于连接通过。分析间隔及下次时间须在安全整数／可表示日期范围内，拒绝无效值不改变原配置。

设置导航分为两组，不再按“基础设置／Agent 能力／数据管理”分组：
- **个人工具**：外观、Skill 设计，所有人可用。
- **平台配置**：Dev 项目与 Release、模型设置、个性化、技能、需求进度分析，所有人可看，仅 Web 启动者可修改。

### 需求进度分析

页面分“项目分析范围”和“统一调度与执行历史”。项目表支持按名称搜索，开关直接保存，新项目默认关闭；首个样例项目预置开启。第二部分包含全局自动开关、统一间隔（默认 60 分钟、正整数分钟）及运行摘要，下方切换“SR 任务／执行历史”标签，不上下堆叠列表。

正式 SR 自动取得唯一任务记录，不手动创建定时任务，不为每 SR 建定时器。每条记录独立显示状态、下次分析、最近执行及失败原因；完成停止、重开复用原记录，同 SR 不重复并发。全局开关只暂停自动接纳，仍可对开启项目立即分析；项目关闭同时排除自动与手动接纳。开关不取消已在执行项或删除历史。需求和代码版本均未变则记录跳过，不重复模型分析。

项目／IR 联动筛选与 SR 名称／编号搜索直接过滤两类列表；历史另支持状态和时间筛选。任务与历史独立分页，默认 25 条、可选 50 条，显示总数、页码并支持首尾／前后翻页，固定表头和限定滚动区域，只渲染当前标签当前页。筛选变化重置相应页码，切标签和翻页保留筛选、各自页码；数据变化自动夹至合法页。

每个 SR 的任务与历史行展示分支名，点击即可复制完整分支名；访客同样可用，复制成功或失败有反馈，不执行 Git 操作，历史使用当次运行的分支。

桌面首屏优先显示项目开关、调度摘要和任务数据，间隔编辑与原型说明／模拟按钮收起在“调度设置”。分支独立成列，长分支单行省略、悬停或聚焦可看完整名称；复制成功原位显示勾号并播报结果。表格名称／编号分层、时间简写，分页统一位于列表底部。

“分析当前筛选范围的 N 个 SR”处理所有匹配且可接纳的任务，不限当前页，不受历史状态／时间影响，排除停用项目、完成和运行中的 SR。摘要查询不返回报告正文；任务失败行可就近查看原因或仅重试该 SR，历史也按 ID 读取单份报告，在当前视口弹窗展示，关闭返回触发控件。切换筛选／页码／标签关闭旧报告。全员可查询与查看，仅 Web 启动者可配置、立即分析、重试或推进演示；项目关闭、已完成或运行中的 SR 不接受重试，并显示原因。

规模入口 `?demo=analysis-scale` 初始为恰好 300 个 SR 与 1000 条历史，不注入普通正式需求列表，和普通样例共用分页查询及调度。新增演示执行后历史总数可以增长，刷新恢复初始规模；不把固定总数标签当作分页验证。真实后端尚未接入，未来须在服务端分页，不能一次传全部报告再由浏览器裁切。

原型的“模拟一次调度检查（原型）”显式推进虚拟时间与运行状态；可演示成功、失败、跳过及独立历史，不启动真实后台、模型、Git 或数据库，不改正式需求报告，刷新恢复样例。模型配置仍在既有需求进度分析 Agent 设置维护，不在本页重复配置。

普通入口预置文档读取、模型调用和仓库读取三类失败历史，均有明确的模拟标记、阶段、原因、下一步与重试说明。原型重试不代表真实后端故障恢复，也不更新正式需求的代码证据。
