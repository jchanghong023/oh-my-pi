**方案 Agent · 提案方案讨论（原型样例）**

以本提案的 IR、全部 SR 和业务讨论为输入，由评审需求的开发人员完成方案。重点检查可行性、模块接口、数据流、异常边界、验收与需求的对应关系。

遇到业务规则缺口时，开发人员填写原因并“打回业务补充”。提案返回草稿的业务需求阶段，原方案失效；补充后旧业务评审失效，必须重新评审当前需求版本，再交给开发并完成本轮方案，才可提交 PR。

“生成方案（演示）”只产生静态样例材料；没有模型调用、真实评审、Git 操作或 PR 创建。PR 合并并核对默认分支中的 IR、全部 SR 和方案后，才转为正式需求。正式 SR 从开发计划开始，不再启动方案 Agent。

对应文件为 proposal.md、`specs/<capability>/spec.md` 和 design.md。先在提案的共享临时工作区生成，PR 准备时再由开发人员把确认文件带入项目仓库的同名 change。需求 PR 合并转正不归档、不表示代码已经实现。
