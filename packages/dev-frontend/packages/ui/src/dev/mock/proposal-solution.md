> 原型静态方案样例。未调用模型、修改文件、提交 PR 或验证 Git。

## 需求与方案对应

以整份 IR 和全部 SR 为输入，由评审需求的开发人员使用方案 Agent 完成实现方案，再提交需求 PR。开发计划阶段直接引用合入后的方案，不重新启动方案 Agent。

## 设计与实现边界

- 明确业务规则、异常路径、输入输出和验收条件，逐项对应 SR。
- 说明模块职责、接口、数据结构、兼容约束与技术取舍。
- 区分已确认事实和待业务补充的问题；有业务卡点时填写原因并打回业务需求阶段。
- 打回后旧方案失效；补充完成、重新交给开发并生成本轮方案后，才可提交 PR。

## 交付与默认分支

需求 PR 应包含 IR、全部 SR 和本方案。PR 提交仍属于需求提案，合并后须核对默认分支中的相关文件，才转为正式需求。此处仅演示状态，不代表真实评审或 Git 验证。
