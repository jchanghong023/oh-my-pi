# Changelog

## [Unreleased]

### Added

- 独立原型聊天输入框在模型选择器左侧增加全屏 Sketch 画图入口，画布“发送”仅回填 PNG 附件并关闭画布，保留原草稿，不自动发送消息；未接正式宿主。
- 独立原型在聊天发送按钮左侧增加麦克风，可演示语音转文字、编辑示例并追加到原草稿，不自动发送、不采集音频；后续复用 OMP 现有能力。

### Fixed

- 原型材料只读时显示带入讨论的禁用原因，停止操作明确反馈不执行真实结清。
- 业务评审通过后开发点击下一步进入 A 的方案 Agent；失效交付候选及已归档 IR 的历史提示不再矛盾。
- 模型设置离开前提示处理未保存编辑，未绑定项目 Skill 提供恢复入口，Skill 设计补充讨论可用。
- 自动化在筛选结果中创建后提供成功说明和新任务入口，不再因任务被筛选隐藏而像创建失败。
- 自由会话置顶后保持可见，重命名同步页头，刷新有效样例与浏览器前进／后退保留选择，查看文件直接进入文件树。
- 文字及附件草稿按工号隔离，IR 验收重新对齐保留未发送草稿，引用无匹配分别显示文件和会话状态。
- 帮助、表格及技能详情关闭后恢复触发焦点，文件树支持方向键，短窗口长描述和更改面板不再遮挡操作或正文。
- 图片未保存标注关闭前提供保存／丢弃／取消，下载明确为原图且与实际浏览器下载反馈一致。

### Removed

- 删除需求顶部下载按钮及需求包导出／导入交接演示，统一共享提案新建；右侧单份材料复制与下载保留。

### Changed

- 提案以 AI 对话补充 IR／SR；方案退出可粘贴意见并循环重评，显示提出人与当前处理责任，长意见支持滚动及全屏阅读，个人 Web 和项目门槛仅用于最终入库。

- 明确自由会话仍为正式 Dev 必需功能，保留原型入口并列明真实原生会话接入要求；正式入口尚未恢复，本次仅更新文档，未运行测试。

- 原型预览与 OMP 正式启动共用同一套 UI、分别注入样例与真实数据；保留原型启动方式，正式入口不回退演示，不新增原型业务。

- 提案原型补齐版本绑定的人工确认、AI 提交推送演示、人工 PR 与逐文件合并核验，移除单独材料发布旁路；正式提案可在开发前修订并重走入库，人工争议意见单独留档且不改写 AI 评审。

- 新建提案可通过聊天或显式操作生成 IR／SR 样例；后续补充更新整组材料与版本，使旧评审失效，重评后可沿现有流程交给开发。仅为固定模板内存演示。

- IR 最终验收绑定默认分支、候选及全部 SR 合并版本，变化后旧报告／推送／PR 失效并明确重验；最终 PR 核对修复、完整且内容不变的 Change 归档移动及跳过规格同步，合并记录使用归档目标。详细交付收进弹窗，仍仅为内存原型。

- SR 交付统一代码／测试／正式规格清单与 PR 信息，补齐当前候选合并前验证、默认分支变化失效、冲突人工处理及三类文件合并核验；移除单独发布 SR 材料的旁路，新增 `?demo=sr-delivery`，仍仅为静态原型。

- 业务需求评审变为必经门槛，绑定 IR／全部 SR 的文件集合与版本；未评审、未通过或过期时阻止开发交接、方案和提案 PR，补充后须重评并保留历史。新增 `?demo=requirements-review`，结果仍为静态演示。

- 分开正式入库与开发冻结：提案合并后尚未冻结，首个 SR 开始才保存整组需求／方案、成员与依赖的版本快照，后续并行 SR 复用；统一只读说明、准入和旧版本阻断，新增 `?demo=proposal-freeze`，仍仅为内存原型。

- 统一仓库开发准入：同仓库单 IR、依赖就绪 SR 默认最多两个并行，同一工号可接手两个；导航展示团队 SR、额度与阻塞原因，SR 合并仅释放名额，最终 IR 合并核验才释放仓库。默认数据及 `?demo=parallel-admission` 对齐新规则，仅为内存原型。

- 左下角项目与 Release 下新增“帮助”，用八步业务流程说明提案、开发、人工评审合并与整体验收归档，沿用现有弹窗和主题样式。

- 主界面正式 IR 增加验收入口、独立聊天与“整体验收／最终 PR／完成”导航；演示问题修复复验、最终 PR 信息、人工合并结果核验及只读历史，全部 SR 合入不再直接标记 IR 完成。新增 `?demo=ir-acceptance` 样例，未执行真实模型、Git、测试或归档。

- 设置页新增 IR 验收 Agent 的模型、思考强度和追加系统提示词样例，统一六个核心角色的职责说明；保存、取消与恢复演示配置沿用原交互，未接入真实验收流程。

- 仅更新最新 Dev 权威需求及原型差异说明：单仓库单 IR、默认两个依赖就绪 SR 并行、首个 SR 启动冻结、SR 代码／测试／规格同 PR、IR 验收及最终修复／归档 PR。此条不代表原型、代码或样例已实现这些规则。

- 补齐无项目／Release／需求、失效目标与目录、材料读取和发送失败的恢复演示；取消固定样例会话回落，失败保留输入且只在明确操作后重试。

- Agent 会话按创建时配置展示模型与思考强度，设置保存用于新阶段、新轮次和下一次需求评审；历史配置保留，不增加追加提示词预览。

- 阶段推进校验开发人、阶段、轮次与完整材料版本；历史会话和旧轮次只读，返工保留 worktree 并使旧材料失效，后续材料不再提前生成。

- 正式 SR 的聊天、文件与审查统一绑定启动时固定的个人开发 worktree，展示目录详情；按工作区隔离审查样例，缺失绑定不回落共享项目。

- 分开提交评审与开发接手，按工号显示我的 SR 并只读查看他人开发；补齐版本化需求评审、PR 临时文件交接和异常预览，明确共享服务使用账号 A 的模型配置。

- 三个导航分区首次默认展开、内部 IR 默认收起；记住用户折叠选择，仅在导航到不同需求时展开对应 IR，避免刷新或阶段切换反复打开。

- 提案改用 OpenSpec proposal/spec/design，先在固定共享临时工作区生成，更新材料来源、Agent 职责、方案版本与需求 PR 核对演示；合并转正保留 change，不自动归档。

- 左侧恢复原 WebGUI 单项目行，命名“自由会话”，直接展开当前项目最近 5 条聊天并保留行内操作；自由聊天默认右侧审查，与需求流程隔离，样例和说明随原型交付。

- 提案改为草稿／方案完成／PR 待合并状态，分业务需求与方案两阶段；支持打回补充、方案失效和合并文件核对演示，正式 SR 从开发计划开始。



- 提案 IR 的“更多”增加只读目录和复制，按项目与原提交人工号展示；共享数据库说明统一为 `/tmpdata/DFT_LAB/omp/omp_dev_sqlite.db`。

- 正式需求置于需求提案上方，两栏复用 WebGUI 项目标题的收起／展开控件；登录页固定深色，工号改为 `j` 加 8 位数字。

- 左侧“草稿”替换为“需求提案”，与正式需求共用 IR／SR 列表、展开、讨论及搜索筛选控件；新增工号入口和切换工号演示。

- 项目与 Release 改为团队共享，项目路径标注只读；每个项目可按工号配置个人开发目录，未配置时引导后再开始开发。

- 正式需求列表为 IR、SR 添加紧凑的中性描边类型标记，保留缩进与展开交互。

- 项目和 Release 选择移入左下角 工作区菜单，沿用界面主题的子菜单交互，常驻显示当前项目和版本摘要。

- Skill 设计去掉模板下拉选择、字段建议及回填操作，保留次要的“填入示例”按钮；问题和建议直接通过补充聊天说明，表单由用户自行修改。

- Skill 设计改为桌面左右工作区，补充讨论与文件预览按标签切换；新增缺项定位、示例填充、旧预览变更对照，以及保存项目／路径／名称冲突提示。

- Dev 的界面设计与验收仅面向桌面浏览器，不再要求手机适配；WebGUI 的手机范围不变，本轮不修改 WebGUI。

- Dev 导航改为点击 IR 展开 SR、点击 SR 进入带阶段信息的聊天布局，需求讨论沿用按钮操作；搜索采用 WebGUI 弹窗，筛选与列表展开复用原动效，未开始及已完成 SR 保留只读聊天布局。

### Fixed

- 修复原型提案入库后讨论串到其他需求、PR 合并状态误报，以及开发热更新后聊天区域可能崩溃的问题。

- 修复独立前端的类型检查错误，对齐 React 19 类型依赖及 RPC、文件预览和原生会话的现有接口，不新增业务功能。

- 原型巡查补齐辅助对话演示响应，收起顶部次要流程信息，改善 Markdown 材料阅读、IR／草稿统计、Skill 预览定位与补充字段间距。

### Added

- Dev 左栏恢复原自动化入口与页面，提供定时任务管理、历史和原生子任务查看的内存样例，操作不触发真实调度、模型或 IR/SR 流转。

- 新增独立“Skill 设计”原型：结构化字段、复用原聊天窗格的补充讨论、文件与待试用例预览及项目内存保存，不改造原技能页或执行真实模型／文件操作。

- Dev 左侧原型在 工作区菜单内将项目与其 Release 相邻联动选择，提供统一新建菜单、当前开发入口及需求搜索／筛选；项目登记归个人配置，Release 归各项目 Git，协作入口位于会话顶部。

- Dev 设置原型支持 5 个核心 Agent 的个人模型配置及追加系统提示词编辑，演示跨项目共用、保存／取消及键盘保存；尚未连接真实 OMP 配置读写。

- 支持使用 Bun 和浏览器独立预览当前 Dev 前端原型，无需 OMP、Rust 或模型凭据。
- 各 Dev 模块提供随源码交付的样例数据和本地演示交互；此为临时 UI/UX 评审阶段，确认后继续真实后端对接与最终验收。
