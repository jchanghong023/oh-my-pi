# wiki

Search persistent indexes built from Markdown directories. `wiki` is an essential read-only built-in tool: unrestricted sessions receive it by default, and non-restricted explicit tool sets that include `read` also receive `wiki`. Restricted sessions retain their exact host-provided allowlist and can use `wiki` only when it is explicitly named. `/wiki` opens the index-management hub; there is no dedicated document subagent, `/doc` research shortcut, or prose routing trigger.

The tool takes one parameter, `query`, and behaves like a search box: it accepts keywords or a whole question, and there is no query syntax to learn. Identifiers and numbers are matched whole, Han runs are cut into overlapping bigrams so `扫描链` still finds `扫描链`, and common function words are dropped. Matching is a union, never a filter: sections covering more of the query rank higher, so a sentence returns the best available material instead of nothing. Ranking puts the query's own spelling in a heading first, then in the body (`std::vector` beats a scattered `vector std`), then sections carrying every term, and closes each tier with BM25 — the IDF- and length-normalized score. Results are the complete stored Markdown of each matching section, in relevance order, capped at about 20000 characters per call; stored sections never exceed 18000 characters, so any hit can be delivered whole. The header reports the total number of matching sections; a footer marks a page cut by the cap and counts the sections skipped as too long and the repeated hits collapsed to a pointer. Converter structural labels (`#### Cell`) are not stored at all, while a heading that reads as a real phrase — requirement and checklist documents state requirements in headings — is kept and shown as a heading-only hit. Material claims should cite the relative source path and line range shown in the headers. Imported text is self-contained: queries do not need the original Markdown files. Images, attachments, and linked resources are not imported. With several indexes, one query searches all of them.

Indexing uses SQLite FTS5; search reranks a bounded BM25 candidate window, prefers complete technical names and matching section titles, and loads the page's full text by section id. These preferences order the results, they never filter the union down. It needs no model, credentials, vectors, or extraction schema, and existing databases need no rebuild.

Manage indexes with two commands: `omp docs init "<dir>" --name "<name>"` imports a directory, and `omp docs remove "<name>" --force` deletes that index (source files stay). There is no list, status, update or rebuild operation, and indexes carry no state or timestamps; to refresh after re-exporting documents, remove the index and import it again. The tool itself cannot import or delete indexes.
