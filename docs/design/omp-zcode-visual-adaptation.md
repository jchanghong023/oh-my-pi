# OMP 与 ZCode 3.18 视觉适配规则

## 适用范围与优先级

WebGUI 以[官方 ZCode 3.18.0 设计规范原文](zcode-3.18.0/DESIGN.md)为视觉基线，精确提交为 `b95ebaffeab641907b38652f45c1502bd762972d`。来源、未修改原文、许可证和哈希见 [zcode-3.18.0 来源记录](zcode-3.18.0/SOURCE.md)。本规则将官方视觉要求映射到 OMP 已确认的功能，不合并官方完整运行时、功能、依赖或页面。

当前用户指令及 OMP 已批准 OpenSpec 优先于官方产品上下文。视觉需求以 [zcode-visual-baseline](../../openspec/specs/zcode-visual-baseline/spec.md)为准；WebGUI 功能和宿主边界见 [personal-commands](../../openspec/specs/personal-commands/spec.md)。

官方 `CONTEXT.md` 主要是插件市场领域词汇，保留其原文不表示恢复原产品市场、计费、插件管理或新的宿主能力。将视觉基线升级为 3.18 不等于将本地应用版本、依赖及执行引擎声明升级为官方 3.18。

## WebGUI 前端

WebGUI 前端位于 `vendor/zcode-frontend`，由 `preview/` 构建，保留 OMP 原生服务与会话适配。保留现有主题、浏览器草稿存储及会话作用域，不为复制官方文件删除这些适配。

WebGUI 以固定官方源码界面为准。外壳、布局、字体、颜色、图标及基础控件沿用 ZCode 既有规则和组件；可复用时不手工仿制，不另定义替代色板、控件或主题。`DesktopWindowFrame` 的 Web 分支以 `bg-background-win-alt` 为外壳背景，内容使用 `bg-background`，不以 `bg-sidebar` 覆盖外壳，也不模拟桌面磨砂。

## 视觉规则

| 项目 | 必须对齐的视觉基础 | 保持的项目边界 |
| --- | --- | --- |
| 设计规范 | 固定官方 DESIGN、CONTEXT 原文、版本和来源 | 官方产品说明不代替 OMP 已确认的功能与部署要求 |
| 深浅主题 | 采用 Zai Light／Zai Dark 的前景、弱文字、背景、surface、panel、border、popover、输入、hover、selected 和阴影规则；颜色值来自主题源码 | 按实际使用范围移植，不整包导入终端、Highspeed、收费功能或桌面专用依赖；保留主题存储和宿主适配 |
| 面板圆角 | 按官方适用浏览器规则恢复面板圆角、弱边框及装饰性 inset，避免固定为零覆盖 | 不改栏目位置、分栏比例、最小宽度、展开状态、拖拽或系统平台标记，不为浏览器加桌面窗口控制 |
| 字体字阶 | 遵循应用 `font-sans`、`text-ui-*`、`--ui-font-size`、字重、行高和字体平滑规则 | 不以官网营销页字体为客户端标准，不更改 HTML 根字号或放大页面来模拟设计 |
| 控件用法 | 在调用侧消除与原生不一致的尺寸、边框、圆角及 disabled、focus、hover、selected、浮层表面覆盖 | 已与官方一致的基础控件不重复替换，不改事件、权限、接口和存储行为 |
| 聊天内容 | 对齐 Markdown、列表、表格、引用、代码及 Diff 的字阶、边界、圆角和内容层级 | 保留会话归属、路径展示／折叠、操作位置和安全渲染适配 |

## 颜色、密度与交互

基础表格和容器以官方中性色阶建立层次，不能把“恢复官方风格”理解为每个状态加一种装饰色。成功、等待、警告、失败等颜色仅用于已定义的实际语义状态；未定义的新业务配色须先成为明确需求，不能用颜色暗示额外通过、失败或阻塞条件。灰阶文本也必须维持主次层级，不能把正文或全部元数据统一降为最弱字号与颜色。

功能布局保持不变：不增加常驻信息行，不移动动作入口，不删除字段或重排聊天栏。允许边框、圆角及少量控件内部留白随视觉基线调整；不得借此改变分栏比例、面板展开或滚动职责。

控件的可见选中、hover、disabled、键盘 focus 和名称提示需要彼此可区分。长文本、路径、代码和表格继续在既定容器内换行或滚动，底部操作保持可达。

## 排除项

视觉适配不修改接口、实时事件、模型选择、权限或服务生命周期。分栏持久化等行为修复须独立评估，不混入视觉同步。不要恢复已裁剪的终端、Highspeed、插件市场、桌面壳或其他原产品入口。

## 核对与证据

实际视觉验证覆盖 Zai Light／Zai Dark、正常与较窄窗口、主要面板及消息，以及 hover、focus、selected、disabled 和浮层状态。记录实际入口、浏览器、窗口和后端来源；Firefox 128、Chromium、手机实机、真实宿主和发行产物的证据不得相互替代。

## 侧栏导航恢复与源码对照

WebGUI 浏览器侧栏提供 ZCode 顶栏的侧栏切换、后退和前进，采用 PanelLeftClose／PanelLeftOpen、ArrowLeft／ArrowRight、原生 ghost／icon-md Button、Tooltip 与主题反馈。展开时在侧栏顶部原 48px 标题区域显示，收起时进入内容区独立占位，不覆盖标题或叠加重复按钮；没有历史的方向明确禁用。浏览器不伪造 macOS 窗口控制，不引入 Electron 依赖。

WebGUI 继续使用现有任务导航历史；导航不发送消息、不撤销文件，也不重建后台任务。

历史源码对照结论：

| 区域 | 对照结果及处理 |
| --- | --- |
| 顶部工具栏 | 原生 DesktopTopOverlay 被裁剪后留下空白占位，且浏览器替代入口仅在收起时显示；现补齐双状态工具栏，保留浏览器适配 |
| 基础按钮、列表分组标题 | Button 基础样式及 ProjectSidebarListHeader 的显式样式与固定官方源码一致，无需重写 |
| 任务列表 | 保留原字体、圆角、选中态、悬停和滚动；加载图标恢复官方 LoaderCircle。工作树、设备和套餐相关标记的功能裁剪不当作视觉缺陷复原 |
| 侧栏底部 | 使用 Avatar 及加粗主名称，保留 OMP 标识 |
| 功能边界 | 不恢复账号认证、付费计划、设备管理或其他已裁剪功能 |

该次对照仅包括源码、补丁空白与前端语法解析；未运行测试、未启动或截图验收 WebGUI，不以此宣称交互或视觉验收通过。

侧栏展开时工具栏提供收起、后退、前进；收起时提供原生 ZCode Z 标志（点击展开）、后退、前进和新建会话。两种状态由同一 Toolbar 组件渲染，保持现有权限与草稿行为。

浏览器保持原生细分隔、拖拽手柄和必要内部间距，不增加 macOS 窗口按钮占位、桌面外框或整页装饰留白。

## 开发加载性能

WebGUI 的 Vite `optimizeDeps` 将 `lucide-react` 合并为同一依赖分组，避免开发模式按图标发起请求。此配置仅影响开发依赖优化，不改变组件使用方式、源码 HMR 或正式构建的动态分包。

不通过关闭源码映射、禁用 HMR 或为源码添加不可变缓存来掩盖开发加载成本。首次依赖预构建与源码转换仍有成本，配置变更后重启开发服务；实际速度取决于机器与缓存。

## 历史主题与控件核对

历史主题与基础控件核对以固定官方源码为准。浏览器根背景沿用主题语义 token，不为视觉对齐恢复已裁剪产品能力；保留 HTTP、Worker、权限与布局持久化适配。历史整合生产构建和宿主类型检查通过，但未启动 WebGUI，不是浏览器、Firefox 或完整发行二进制验收。
