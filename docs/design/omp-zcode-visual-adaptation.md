# OMP 与 ZCode 3.18 视觉适配规则

## 适用范围与优先级

WebGUI 和 AIReq 以[官方 ZCode 3.18.0 的设计规范原文](zcode-3.18.0/DESIGN.md)为视觉基线，精确提交为 `b95ebaffeab641907b38652f45c1502bd762972d`。来源、未修改原文、许可证和哈希集中保存在 [zcode-3.18.0](zcode-3.18.0/SOURCE.md)。本规则将官方视觉要求映射到 OMP 已确认的功能，不合并官方完整运行时、功能、依赖或页面。

当前用户指令及 OMP 已批准 OpenSpec 优先于官方产品上下文。视觉需求以 [zcode-visual-baseline](../../openspec/specs/zcode-visual-baseline/spec.md)为准；AIReq 业务与接口边界继续遵循 [aireq-browser-workbench](../../openspec/specs/aireq-browser-workbench/spec.md)，不恢复已退休的编码执行流程。

官方 `CONTEXT.md` 主要是插件市场领域词汇，保留其原文不表示恢复原产品市场、计费、插件管理或新的宿主能力。将视觉基线升级为 3.18 不等于将本地应用版本、依赖及执行引擎声明升级为官方 3.18。

## 同一正式前端，两个独立入口

- WebGUI 前端仍位于 `vendor/zcode-frontend`，保留现有 OMP 原生服务和会话适配。
- AIReq 共享前端仍位于 `packages/aireq-frontend`。`preview/main.tsx` 与 `runtime/main.tsx` 使用同一个 `app/bootstrap.tsx`、`client/remote-data-source.ts` 和冻结的 `backend/contract.ts`。
- 原型仅在独立后端 mock 业务。外观对齐修改同一份共享 AIReq UI，不新增仅原型可见的样式、业务数据源或 prototype/runtime 界面分支。
- 主题与浏览器草稿继续使用现有安全存储、工号和工作区作用域；不为复制官方文件删除这些适配。

## 八项视觉规则

| 项目 | 必须对齐的视觉基础 | 保持的项目边界 |
| --- | --- | --- |
| 1. 设计规范 | 固定官方 DESIGN、CONTEXT 原文、版本和来源；两套前端根目录提供明确的本地阅读入口 | 官方产品说明不代替 OMP 已确认业务与部署需求 |
| 2. 深浅主题 | 采用 Zai Light／Zai Dark 的前景、弱文字、背景、surface、panel、border、popover、输入、hover、selected 和阴影规则；颜色值来自主题源码 | 按实际使用范围移植，不整包导入终端、Highspeed、收费功能或桌面专用依赖；保留主题存储和宿主适配 |
| 3. 面板圆角 | 按官方适用浏览器规则恢复面板圆角、弱边框及装饰性 inset，避免固定为零覆盖 | 不改栏目位置、分栏比例、最小宽度、展开状态、拖拽或系统平台标记，不为浏览器加桌面窗口控制 |
| 4. 字体字阶 | 遵循应用 `font-sans`、`text-ui-*`、`--ui-font-size`、字重、行高和字体平滑规则 | 不以官网营销页字体为客户端标准，不更改 HTML 根字号或放大页面来模拟设计 |
| 5. 表格视觉 | 原生表格容器的圆角、细边框、表头、行、单元格、hover、选中及文字层级 | 保留 AIReq 的九列、列宽、固定列、IR／SR 展开、滚动、筛选、复制、分支及人工进度操作 |
| 6. 控件用法 | 在业务调用侧消除与原生不一致的尺寸、边框、圆角及 disabled、focus、hover、selected、浮层表面覆盖 | 已与官方一致的基础控件不为“升级”重复替换，不改事件、权限、接口和存储行为 |
| 7. 工作流与头像 | 复用官方轨道、头像、表情、完成标记、连线、动效与减少动态效果规则 | 保留四 Agent、默认综合意见、人工判断、定向会话和当前／历史节点；不恢复 ZCode 工作流执行引擎 |
| 8. 消息与材料 | 对齐 Markdown、列表、引用、代码及 Diff 的字阶、边界、圆角和内容层级 | 保留当前会话归属、只读材料范围、路径展示／折叠规则、操作位置和安全渲染适配 |

## 颜色、密度与交互

基础表格和容器以官方中性色阶建立层次，不能把“恢复官方风格”理解为每个状态加一种装饰色。成功、等待、警告、失败等颜色仅用于已定义的实际语义状态；未定义的新业务配色须先成为明确需求，不能用颜色暗示额外通过、失败或阻塞条件。灰阶文本也必须维持主次层级，不能把正文或全部元数据统一降为最弱字号与颜色。

AIReq 左侧提案列表的标题使用 `text-ui-base` 与 `text-foreground`，选中标题使用 `font-medium`，继续复用原生选中背景。提交人工号、阶段及入库检查使用 `text-ui-sm`（默认 12px），元数据使用 `text-foreground-subtle`；不得以 `text-ui-xs` 与 `text-foreground-subtlest` 组合承载这些需要阅读的信息。工号随中文说明使用普通界面字体，等宽字体保留给 IR／SR 编号、代码和文件路径。原因是此前标题被当作辅助文字、元数据仅 10px 且过淡，使可点击提案看起来像禁用项。长标题和阶段继续截断并提供完整提示，不改变字段和导航行为。

正式需求表格的开发安排按钮沿用原生 `Button size="sm"` 的字阶与高度，不覆写为 10px 微标签；只读工号使用普通界面辅助字号。依赖名称使用 `text-ui-sm text-foreground`，原因与材料不可用说明使用同字号的次级文字色，不能把长句当作徽标。评审会话的 Agent／模型／完成数量／人工判断说明使用 `text-ui-sm`，保留单行截断，并以原生 Tooltip 在悬停或键盘聚焦时提供整段内容。材料路径入口使用原生 `Collapsible` 与 `Button`，路径正文使用可读的 `font-mono text-ui-sm`，保留原有默认收起、换行及选择复制能力。以上修正只调整信息角色与控件用法，不改变列宽、分栏、权限、阶段或业务操作。

功能布局保持不变：不增加常驻信息行，不移动动作入口，不删除字段，不改变列表／表格列数及列宽，不重排聊天／材料栏。允许边框、圆角及少量控件内部留白随视觉基线调整；不得借此改变分栏比例、面板展开或滚动职责。

控件的可见选中、hover、disabled、键盘 focus 和名称提示需要彼此可区分。四个评审头像继续按同一 Agent 身份显示稳定颜色，头像切换仍定位对应会话；不能因状态样式变化自动通过评审。长文本、路径、代码和表格继续在既定容器内换行或滚动，底部业务动作可达。

正式需求表格在业务调用侧集成原生 `Badge`、`Progress` 和 Lucide 图标，表格行／单元格继续复用现有组件，不修改聊天 Markdown 表格或全局主题。五种已定义状态采用固定映射：待开发为中性色和虚线圆，开发中为 `progress-surface`／配对前景与圆点，待合入为 `warning-surface`／配对前景与合并图标，待验收使用相同等待色和检查图标，已完成为 `success-surface`／配对前景与完成图标。进度条通过原生 `indicatorClassName` 使用对应语义色；右侧报告复用相同状态标签和进度规则。琥珀色表示等待人工处理，不新增失败或阻塞判断；状态始终保留文字，进度保留百分比与无障碍说明，不能仅靠颜色区分。

业务表头采用次级文字色与中等字重，IR 名称用中等字重和中性分组表面，SR 保留缩进及普通字重。选中与悬停沿用原生主题 token，固定名称列与整行的背景同步，横向滚动时保持不透明。状态配色不覆盖整行，不改变九列、列宽、分配、筛选、进度计算及展开操作。本次状态样式迭代按用户指令仅检查深色主题的电脑端原型，不将浅色主题标为已验证。

提案导航使用原生 FilePenLine 提案文档图标，默认仅显示分组标题、原生搜索／排序／筛选入口与提案列表，不常驻检查统计。提案只显示提交人，不提供 IR 负责人筛选或提案负责人分配入口；正式需求的负责人不变。筛选菜单只保留阶段、提交人和“入库检查：需要处理”单项勾选，不细分异常类别、不提供“已合入”分类。启用筛选后才显示“找到 N 项”和清除入口。检查问题在对应提案原有两行内统一使用等待处理的图标与“需要处理”文字，原因在详情保留；正常待检查／等待合入不算异常，合入且材料完整后自动转出提案列表。原因是需求导航应优先展示提案与待处理事项，不能引入不存在的提案负责人或重复后台分类。

AIReq 只读材料继续复用原生 `MessageResponse`（与 Markdown 文件预览相同的渲染器），不增加另一套 Markdown 解析、手写文件卡片或前端正文改写。阅读容器使用基础字阶、正常字距、清晰段落行高和有上限的行宽；按 h1／h2／h3／h4 调整间距，保留原生标题字阶、引用、列表、表格和代码样式。代码主题、字号、行号和换行从现有外观设置传入，变更后立即刷新原生代码块。

只读材料通过组件参数关闭复制／下载，不再以“隐藏全部 button”的 CSS 误伤阅读工具。代码换行、图表预览及表格全屏／横向查看沿用原生控件；不恢复复制、下载、带入讨论或文档编辑入口，不增加 SR 导航或材料元数据面板。参数默认保留原生组件既有操作，材料栏显式关闭导出，不能影响普通聊天。原型样例缩短重复演示声明，保留 OpenSpec 标题结构、明确样例标识；真实文件正文原样渲染，不通过界面删除声明、翻译标题或伪造内容。

## 排除项

本次不修改 bootstrap、网络客户端、接口格式、实时事件、模型选择策略、工号及权限、Git 业务、需求状态、进度算法、依赖／排期、服务生命周期或原型后端与真实后端边界。分栏持久化等上游行为修复需要独立评估，不混入视觉同步。也不恢复已裁剪的终端、Highspeed、插件市场、桌面壳、手机界面或其他原产品入口。

## 核对与证据

WebGUI 与 AIReq 均以本固定版本规范为基线。AIReq 只需修改一份共享前端，分别连接原型或真实后端时保持同样的浏览器代码与视觉规则；视觉检查不证明真实 OMP 后端、模型或 Git 已接通。

本轮按用户授权构建并实际截图检查，不运行测试套件。截图至少覆盖 Zai Light／Zai Dark、普通与较窄电脑窗口、主要面板和表格、评审头像／展开图、消息与只读材料，以及 hover、focus、selected、disabled 和浮层状态。记录实际入口、浏览器、窗口和后端来源，未实际打开的入口或浏览器不得称为已验证。Firefox 128 仍是既有目标；Chromium 截图不能代替 Firefox、发行产物或真实宿主验收。AIReq 不新增手机、平板或触屏验收范围，WebGUI 保持其原有平台边界。

本轮截图范围按用户后续指令限定为 AIReq 共享前端：启动独立原型后端与该前端，检查深浅主题及正常／窄桌面。WebGUI 同步同一视觉源码基线并做静态核对，本次不启动、不构建或截图，不将其截图验收标为通过；其运行视觉验证另行安排。未运行测试套件。

提案的安排入口仅为“工期预估”：逐 SR 展示工作日及假设，数据与依赖共同读取 `sr-dependencies.json`。提案不显示负责人、开发人员或起止时间控件；人通过方案对话修改预估，转正后才按正式需求规则安排人员和日期。这样将方案可行性估算与正式开发安排分开。

AIReq 左下角项目入口复用 ZCode 原生圆形 Avatar 及 `text-ui-base font-semibold text-foreground` 主名称样式，Release 为次要信息；头像点击仍打开项目／Release 菜单，右侧设置齿轮保留。不引入 ZCode 账号登录或替换实际项目名称。

Skill 设计是主页工作能力，侧栏位于“自动化”下方，采用原生 WandSparkles 图标和同级 Button 导航；设置不再承载设计表单。独立页采用轻量标题栏、较窄说明列及较宽对话／预览列；沿用 Tabs、Select、Collapsible、输入框和 Markdown／代码阅读器，各栏独立滚动、底栏操作固定。减少重复状态、收起临时路径、文件用 Select 切换，保留原有 AI 对话和显式保存流程。

需求分析从设置移至主页正式需求上方，采用 FileSearch 导航图标和同级原生按钮；标题统一“需求分析”。复用正式需求的 MarkdownTable 基础组件、状态徽标及 Progress；进行中用 progress 语义色、成功用 success、失败用 destructive，文字和图标同步说明状态。项目范围与调度设置收纳到原生“分析设置”弹窗，主页保留紧凑调度摘要、任务／历史与筛选，避免配置表单挤占任务空间。

“新建需求提案”入口沿用 ZCode 新建任务的 MessageCirclePlus（对话气泡加号）图标和原生 ghost／lg 导航按钮，左对齐、常规字重，悬停及键盘焦点使用原生主题反馈；名称、草稿创建及权限行为不变。

## 侧栏导航恢复与源码对照

AIReq 和 WebGUI 浏览器侧栏均提供 ZCode 顶栏的侧栏切换、后退和前进，采用 PanelLeftClose／PanelLeftOpen、ArrowLeft／ArrowRight、原生 ghost／icon-md Button、Tooltip 与主题反馈。展开时在侧栏顶部原 48px 标题区域显示，收起时进入内容区独立占位，不以绝对定位遮住标题或叠加重复按钮；没有历史的方向明确禁用。AIReq 正式需求在其原有标题栏复用同一按钮组，切换操作使用实际侧栏显隐状态。浏览器不伪造 macOS 窗口控制，不引入 Electron 依赖。

WebGUI 继续使用现有任务导航历史；AIReq 将主页（自动化、Skill 设计、需求分析）与 IR／SR 选择一同记录在现有浏览器历史中，按钮与前进／后退快捷键恢复浏览位置。跳转不发送消息、不回退业务阶段、不撤销文件，也不借导航重建后台任务。新跳转截断当前分支的前进历史，刷新保留当前历史入口。

## 正式需求与 Skill 设计的布局比例

浏览器保持原生细分隔、拖拽手柄和必要内部间距，不增加 macOS 窗口按钮占位、桌面外框或整页装饰留白。普通聊天的三栏比例不变。

正式需求优先保留表格，同时改善报告／Markdown 的阅读宽度：右栏初始占扣除导航后的内容区 35%，最小 360px、最大 50%，中间表格最小 400px；边界优先满足桌面可用空间的约束。采用原生分栏持久化，切换对象和重新打开沿用记录，不再通过动画 resize 强制恢复 380px。使用新的 v3 布局键建立比例默认值，原 v2 存储不删除。

Skill 设计维持 2:3 默认比例，改用原生可拖拽分栏：说明列默认 40%、最小 280px、最大 60%；对话／预览列默认 60%、最小 360px。复用原生键盘拖拽、主题及手柄，不另写拖拽逻辑，左右独立滚动；各页比例独立记忆，调整不触发发送、生成或保存技能。
