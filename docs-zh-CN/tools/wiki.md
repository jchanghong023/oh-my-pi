# wiki

搜索由 Markdown 目录构建的持久索引。`wiki` 是必备的只读内置工具：非受限会话默认获得它，包含 `read` 的非受限显式工具集也会获得它；受限会话保留宿主给定的精确白名单，只有显式列出 `wiki` 时才可用。`/wiki` 打开索引管理 Hub；本 fork 没有专门的文档子代理、`/doc` 研究快捷命令或散文触发路由。

该工具只有一个参数 `query`，用法等同搜索框：关键词或整句都可以，没有需要学习的查询语法。标识符与数字按整词匹配，汉字串按相邻重叠 bigram 切分（因此 `扫描链` 依然能命中 `扫描链`），常见功能词会被丢弃。匹配是并集、不是过滤：覆盖查询越多词元的章节排序越靠前，因此一句话会返回可用的最佳材料而不是空结果。排序先看查询原样拼写是否出现在标题，再看是否出现在正文（`std::vector` 优于散落的 `vector std`），然后是包含全部词元的章节，每档内部按 BM25（IDF 与长度归一化的分数）收尾。返回结果是每个命中章节**完整**的入库 Markdown，按相关度排序，单次调用上限约 20000 字符；入库章节不超过 18000 字符，因此任何命中都能整段返回。表头给出命中章节总数；页脚标记本次被上限截断的情况，并统计因过长而跳过的章节数以及被折叠为指针行的重复命中。转换器的结构标签（`#### Cell`）完全不入库，而读起来像真实短语的标题（需求与清单类文档常用标题陈述要求）会保留，以「仅有标题」的命中形式展示。实质性结论应引用表头中的相对源路径与行号区间。入库文本自成一体：查询不需要原始 Markdown 文件。图片、附件与链接目标不会入库。存在多个索引时，一次查询会搜索全部索引。

索引使用 SQLite FTS5；检索会在有界的 BM25 候选窗口内重排，优先完整技术名称与匹配的章节标题，并按 section id 载入整页文本。这些偏好只影响排序，从不把并集过滤掉。它不需要模型、凭据、向量或抽取 schema，已有数据库也不需要重建。

用两个命令管理索引：`omp docs init "<dir>" --name "<name>"` 导入目录，`omp docs remove "<name>" --force` 删除该索引（源文件保留）。没有 list、status、更新或重建操作，索引也不记录状态或时间戳；文档重新导出后要刷新，请删除索引再重新导入。工具本身不能导入或删除索引。
