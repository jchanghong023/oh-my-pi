# 公司内网 OMP 新手快速指南（Linux / tcsh）

## 1. 设置环境变量

在启动 OMP 的终端执行：

```tcsh
setenv OMP_OFFLINE 1
setenv OMP_CONFIG_ROOT "$HOME/omp-data"
```

- `OMP_OFFLINE`：启用公司内网模式。
- `OMP_CONFIG_ROOT`：数据目录，可换成有写权限的绝对路径；旧数据不会自动搬过来。

这两行可放进 `~/.tcshrc`，以后新开的 tcsh 终端自动生效。

## 2. 启动

**按公司环境要求，先启动 IDE 和模型代理：**

```tcsh
ma dmas_ide
ide agent
```

代理就绪后，进入自己的项目目录（替换示例路径）：

```tcsh
cd /path/to/project
omp
```

继续当前项目最近会话用 `omp -c`；没有可恢复会话时会新建。在上述内网模式下，OMP 复用 Claude Code 中已配置的公司 API 地址和凭据，无需另行登录。

## 3. 常用操作

以下在 **OMP 输入框**使用。直接输入任务，按 `Enter` 发送；输入 `/` 补全命令，输入 `@` 选择文件。

| 按键 / 命令                    | 用途                                                 |
| ------------------------------ | ---------------------------------------------------- |
| `Ctrl+T` 或 `/switch`          | 查看、临时切换当前会话模型                           |
| `/model`                       | 设置各角色模型                                       |
| `Shift+Tab` 或 `/plan`         | 切换计划模式，先出方案                               |
| `Ctrl+O`                       | 展开 / 收起工具调用详情                              |
| `Esc`                          | 在主会话中中断当前任务；循环模式下中断本轮并暂停循环 |
| `/tree`                        | 查看、切换会话分支                                   |
| `/copy`                        | 选择并复制对话内容                                   |
| `/copy code`                   | 复制助手回复中最近的代码块                           |
| `/new`                         | 新建会话                                             |
| `/resume`                      | 恢复历史会话                                         |
| `/context` / `/compact`        | 查看上下文占用 / 压缩上下文                          |
| `/wiki`                        | 查询已导入的公司资料                                 |
| `/repo`                        | 建立、更新代码定位索引                               |
| `/team 需求`                   | 多模型独立调查、交叉审查并汇总方案，只读             |
| `/advisor on` / `/advisor off` | 开启 / 关闭第二模型复审，默认逐轮，频率可配置        |
| `/skill:技能名 任务`           | 调用本地技能，从补全中选择技能名                     |
| `/todo` / `/hub`               | 查看待办进度 / 子代理活动                            |
| `/queue 后续任务`              | 当前轮结束后再执行；空闲时直接执行                   |
| `/quit`                        | 退出                                                 |

运行中想排队，也可输入消息后按 `Ctrl+Q`；普通 `Enter` 会引导当前任务。快捷键失效时用 `/hotkeys` 查看绑定。

这四个命令可以**直接带任务文本**：

| 命令           | 用途                                            | 可复制示例                                                   |
| -------------- | ----------------------------------------------- | ------------------------------------------------------------ |
| `/ultrathink`  | 深入分析再行动                                  | `/ultrathink 分析这个错误的根因，给出证据和修复方案`         |
| `/orchestrate` | 拆分任务、委派子代理、整合验证                  | `/orchestrate 按 @a.md 实现，拆分独立任务并行完成，统一验证` |
| `/workflowz`   | 按阶段组织批量多代理任务                        | `/workflowz 按模块检查当前仓库，汇总有证据的功能问题，只读`  |
| `/fullsend`    | 优先速度与验证质量，不以成本或 token 用量为约束 | `/fullsend 按 @a.md 完成实现和必要验证，修复问题后复测`      |

这些命令向模型追加任务要求；`/orchestrate` 依赖 `task` 工具，`/workflowz` 依赖 `task` 和 `eval` 工具，相关设置也需启用。

## 4. 企业核心功能（本 fork）

### 4.1 `/wiki`：把公司资料变成可查询的本地知识库

适合查内部规范、接口约定、历史方案和业务术语。**先导入资料，再查询**；不是联网搜索，也不会自动抓取公司知识库。

**首次导入：**

1. 准备已导出的 Markdown 目录。导入会递归读取 `.md` 文件，跳过符号链接；PDF、Word 等需先转成 Markdown，图片、附件和链接目标不会随正文入库。
2. 在 OMP 输入框输入 `/wiki`，按 `n` 新建，填写索引名和目录，确认后等待导入完成。面板会列出索引名、文档数、章节数和源目录。
3. 也可在**系统终端**执行以下命令，替换目录和索引名；终端与 OMP 会话须使用一致的 `OMP_CONFIG_ROOT`、profile 等配置环境：

```tcsh
omp docs init "/path/to/company-markdown" --name "company-docs"
```

索引名必须唯一，同名不会覆盖。导入和检索在本机完成，不调用模型、不需要向量服务；只有完整导入成功后索引才可见，失败或取消不会留下可查询的半成品。

**自己查资料：** 在 `/wiki` 面板用 `↑/↓` 选择索引，按 `/` 输入关键词或问题，按 `Enter` 搜索；再用 `↑/↓` 选中结果、`Enter` 查看正文。终端面板搜索当前选中的索引；`Esc` 返回或关闭。导入中按 `c` 取消，按 `Esc` 则先确认是否取消并关闭。

**让 AI 查资料并解释：** 退出面板，在普通对话中输入：

```text
用 wiki 查询 MBIST 仿真日志的检查项和判据，按索引名、文件路径和行号标注依据；区分资料明确规定与推断，缺少依据时说明。
```

AI 的 `wiki` 工具一次查询覆盖全部已导入索引，返回命中章节正文和来源；它只读，不代为新建或删除索引。关键词、整句都可以，中文不用分词；没有布尔、引号或通配符语法，`AND`、`OR`、`*` 都按普通字符处理。结果有长度上限，提示截断或问题太宽时，用更具体的技术词继续查。

**资料更新：** 索引保存导入时的 Markdown 快照，源目录移走后仍可查，但源文件修改不会自动刷新。重新导出后，先删除旧索引，再重新导入：

```tcsh
omp docs remove "company-docs" --force
omp docs init "/path/to/company-markdown" --name "company-docs"
```

删除只移除本地索引，不删除源资料；面板中也可按 `d`、再按 `y` 确认删除。刷新前先确认新导出目录可读：删除后若重新导入失败，旧索引不会自动恢复。没有 `omp docs update`、`list` 或 `status` 命令，查看已有索引用 `/wiki`。

引用的路径、行号对应导入时版本，不一定是源文件现状；查不到不等于公司没有相关规定，历史资料也不自动代表现行规范。详细约定见[文档索引需求](requirements/fork.md#markdown-文档索引)。

### 4.2 `/repo`：为当前项目建立代码定位索引

适合反复查实现、错误信息、配置键和 Python 定义。它与公司资料的 `wiki` 索引分开维护；建库、查询不调用模型，也不需要安装语言服务器。

**首次建立：** 进入目标项目启动 OMP，输入 `/repo`，核对面板的 `Root:`，按 `b`、再按 `y` 确认建立。Git 项目范围是当前 worktree 的根目录（从子目录启动也索引整个 worktree）；非 Git 项目范围是启动时的当前目录。数据库保存在用户数据目录，按 profile 和项目根目录隔离，不向源码目录写库。

面板可查看文件数、Python 符号数、索引代次（`Generation`）、覆盖状态（`Coverage`）、待处理路径（`Pending`）、失败（`Failures`）和最近完整核对时间（`Last full check`）。

| 面板按键  | 操作                                                                         |
| --------- | ---------------------------------------------------------------------------- |
| `u`       | 更新：完整枚举、读取并核对当前范围，同步新增、修改和删除；内容未变不重新解析 |
| `r` → `y` | 重建；数据库损坏或不兼容时可用此入口恢复                                     |
| `d` → `y` | 删除该项目索引，不删除源码                                                   |
| `c`       | 取消正在进行的建立、更新或重建                                               |
| `Esc`     | 关闭；操作中先确认是否取消并关闭                                             |

失败或取消不发布半成品，原有可用索引保留。首次建库须在面板确认，AI 查询不会自动建立；**没有 `omp repo ...` 系统终端命令组**。

**让 AI 定位代码：** 建库完成后，在普通对话中输入：

```text
用 repo 搜索当前项目中读取配置的代码候选，再读取当前源码确认并解释处理流程。
```

```text
用 repo symbol 定位 Python 类 ConfigLoader 及其 load 方法的定义，读取当前文件后解释输入、输出和错误处理。
```

这里的 `repo search`、`repo symbol` 是 AI 工具动作，不是让你在终端执行的命令。`search` 查源码、测试和配置等文本候选，可按相对路径缩小范围；`symbol` 仅定位 Python 模块、类、函数和方法的定义及可用签名，其他语言用文本搜索或已有语言工具。需要覆盖详情时可让 AI 调用 `repo status`，它不扫描源树。

**何时更新：**

- OMP 内建文件编辑、新建、删除和重命名记录已知变化，已有索引会在下一次文本或符号查询前局部处理。
- 切分支、外部编辑器改动、外部批量新增/删除，或修改 `.gitignore` 等范围规则后，在 `/repo` 按 `u` 完整核对；不保证查询自动发现这些变化。
- bash/eval 等执行后可能标记 `unchecked`（未核对）；Git 候选线索不等于完整核对。看到未核对、待处理或失败提示时，不把旧结果当成当前完整覆盖。

索引遵循忽略规则，符号链接、二进制、无效 UTF-8、超 2 MiB 等文件不纳入；具体排除或失败看状态。**命中只是定位线索**：编辑前必须读当前源码；找全部出现位置用 `grep`，按文件名找文件用 `glob`，调用方或影响范围需结合当前源码和可用 LSP 调查。索引不提供调用图、依赖分析或测试覆盖判断，无命中不能证明代码不存在。详细约定见[代码定位索引需求](requirements/repo-index.md)。

### 4.3 `/team 需求`：多模型调查、交叉审查，先把方案想清楚

适合需求还不清晰、实现方向存在取舍，或需要核对公司规范与现有代码的任务。**只做分析和规划，不自动实施。**

先用 `Ctrl+T` 选好负责对齐与最终汇总的当前会话模型，再在输入框描述目标、资料入口、约束和希望得到的结果。以下示例中的 `a.md` 须已存在且路径明确：

```text
/team @a.md 结合现有代码和内部 wiki 比较可行方案，保持已有接口兼容，给出关键证据、推荐理由、主要风险、执行前检查和验收条件。
```

只输入 `/team` 会提示补充问题，不猜测任务。在 `OMP_OFFLINE=1` 且未另设 `team.members` 时，默认使用当前可用且启用的公司聊天模型；当前会话模型也加入独立提案，重复模型只算一次。显式 `team.members` 优先，它与 `/model` 的角色设置不是同一项；指定成员不可用会报错，不静默略过。普通非内网启动没有这份公司默认名单。

流程由程序推进：各模型独立调查，随后对齐需求与验收标准、交叉审查、修订与必要复核，最后汇总；每个方案最多两轮修订。过程中无需手工分配代理、转发意见或回答中途问题。阶段与模型状态看启动后的提示，子代理明细可用 `/hub` 查看；取消按启动提示使用后台任务取消入口，不把主会话的普通 `Esc` 当作已取消整个讨论。

只读由子代理工具白名单限制：可以读文件、搜索代码和查 `wiki`，不能写项目文件、运行 bash/eval、安装依赖、构建测试、更新索引、提交或推送。“修订”只改方案内容，正常会话记录仍会保存。当前 `/team` 子代理**不开放 `repo` 工具**，代码调查使用只读文件和搜索工具；公司资料应提前通过 `/wiki` 导入。

结果回到当前会话，包括共同需求与验收标准、方案、证据、取舍、风险和待核实前提，不自动生成项目中的方案文件。有明确优势才推荐，不靠多数票；未解决阻断或必要复核未完成的方案标为“尚不可采用”。成员失败会如实显示，必要阶段失败会报告流程未完成，不能把失败当成同意或验证通过。

回复“选择方案 A”只确认方案，不授权改代码；实施需另发明确任务，例如后文的 `/goal` 示例。若补充约束实质改变方案，或结果提示需求理解存在重要差异，带上澄清后的要求重跑 `/team`。详细约定见[多模型方案讨论需求](requirements/team.md)。

## 5. 直接复制的例子

**开启复审（默认逐轮）：**

```text
/advisor on
```

`/advisor status` 查看状态，`/advisor off` 关闭。提示缺少模型时，用 `/model` 设置 advisor 角色。

**解释文件：**

```text
@a.md 解释这个文件的用途和主要流程，只读，不修改。
```

**首次执行后最多再重复 3 轮（共最多 4 轮）：**

```text
/loop 3 hello
```

**首次检查、修复后最多再重复 5 轮（共最多 6 轮）：**

```text
/loop 5 检查当前改动，发现明确功能问题就修复，然后重新检查；没有问题就不要做无关修改
```

按 `Esc` 中断正在执行的本轮并暂停循环；暂停后发送新任务会继续循环，输入 `/loop` 才会关闭。循环已开启时，再次输入 `/loop ...` 会关闭它，不会改成新的轮数；上述例子不会因“没有问题”而自动提前终止循环。

**按方案实现、测试并独立复审（先确认项目里有 `a.md`）：**

```text
/goal @a.md 按方案实现所有代码，补充必要的测试；必须覆盖所有主要接口，必须通过所有 UT，完成代码后必须分配独立子代理对你的代码进行检查。
```

先退出计划模式。用 `/goal show` 看状态，`/goal pause` 暂停，`/goal resume` 继续，`/goal drop` 删除目标（保留代码改动）。测试结果和子代理过程以实际输出为准。


## 6. 用不了时

- **模型不可用**：先确认 IDE 和代理已启动；在系统终端运行 `omp models`，检查是否有 `company` 模型及错误提示。
- **公司配置错误**：检查 `~/.claude/settings.json` 的 `env.ANTHROPIC_BASE_URL`、`env.ANTHROPIC_AUTH_TOKEN`，改完重启 OMP。配置在其他目录时设置 `CLAUDE_CONFIG_DIR`。
- **旧会话找不到**：确认项目目录、`OMP_CONFIG_ROOT` 和 `PI_CODING_AGENT_DIR` 与之前一致；`omp config path` 查看 agent 配置目录，不一定是实际会话目录。未设置 `OMP_CONFIG_ROOT` 时，已生效的 XDG 数据目录也可能影响会话存储位置。
- **复制失败**：直接选择终端文本复制。

内网使用本地技能和公司资料，不使用公网搜索、在线安装或更新。`OMP_OFFLINE=1` 会关闭公网工具及自动更新，但不会拦截显式安装、更新命令，内网不要运行这些联网命令。
