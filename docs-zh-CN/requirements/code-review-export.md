# `/code-review-export` 代码审查材料导出

> 本文是该功能唯一权威需求契约；实施与实际验证状态见[需求目录](README.md)。下文保留完整目标，并明确当前实现的拒绝边界和能力限制；限制说明不等于所有场景均已验收。

## 1. 目标与边界

内置 `/code-review-export` 是纯导出工具：把用户选定范围的完整改动、变更前后源码、版本信息和原生审查指令打成固定本地 ZIP，由用户自行发给其他 Agent 或审查者 review。它不创建 Agent、不调用模型、不需要模型凭据，也不分析代码。它随 OMP 分发，不是 Skill，不要求用户安装技能、编写配置或安装新的语言工具。

- 命令的参数、交互选择及取消语义与现有 `/review` 一致；改变的是最终动作：导出材料，不启动代码审查。
- 不调用当前会话模型或其他模型，不进行智能上下文调查；不自动上传、发送审查请求、生成审查结论或替用户提交材料。审查与补充上下文调查由接收 ZIP 的其他 Agent／审查者完成。显式选择 PR 时仍可读取该 PR 的 GitHub 数据，这不是模型调用或材料上传；本地 Git 范围导出不依赖模型服务或网络。
- 不修改业务源码、项目配置、Git index、工作树、分支或 refs，不 checkout、commit、push；除本次导出所需的仓库根 `.tmp/` 自有文件外不写项目文件。
- **不脱敏。** 导出的代码保持来源原始字节，包括硬编码密码、Token 或其他凭据；不得掩码、替换、删除敏感字符串，不得格式化、改编码、改换行或语义改写。用户须自行判断材料是否适合交给接收方。
- 不因此整仓收集隐私：未修改的源码、凭据、私钥、用户配置、会话和私人文件不因自动调查进入 ZIP；不扫描用户主目录，不跟随仓库外链接。不得以隐私排除为由修改应导出的源码正文。

## 2. 命令输入与交互

```text
/code-review-export [与 /review 相同的参数]
/code-review-export https://github.com/<owner>/<repo>/pull/<number> [补充指令]
/code-review-export pr://<owner>/<repo>/<number> [补充指令]
/code-review-export [补充指令]
```

参数解析复用 `/review`：识别首个有效 GitHub PR URL 或 `pr://` PR 引用（含 `/review` 已支持的 diff 路径形式与尾随标点），剩余参数作为补充指令。普通文字不是新增的模式 verb；不增加 `commit <ref>`、任意 A/B 端点、导出模式、输出路径或额外确认选择。

### 2.1 交互模式

没有直接 PR 引用时，使用 `/review` 的同一选择流程：

1. 最近会话中的 PR 候选，按现有规则去重，最多三个。
2. `1. Review against a base branch (PR Style)`：继续使用原有分支选择器。
3. `2. Review uncommitted changes`。
4. `3. Review a specific commit`：继续使用最近 20 个提交的选择器。
5. `4. Review a specific PR`：继续使用当前仓库的 open PR 列表与搜索。
6. 没有参数补充指令时，保留 `5. Custom review instructions`。

PR picker 保持现有行为：每次列表最多 100 项，支持服务端搜索，以及输入 `#123`／数字直接定位；取消搜索输入回原 picker，空查询恢复初始列表，搜索失败保留原列表，无匹配有提示而非悄悄换目标。直接 PR 参数跳过范围菜单，其余参数仍作为补充指令。

自定义指令继续打开标题为 `Enter custom review instructions` 的编辑器，初始内容 `Review the following:\n\n`，沿用 `promptStyle: true`。取消或空白内容不导出。以当前未提交范围准备材料，补充指令原样保存供接收者审查；不解释指令、不据此搜索其他源码。没有未提交 diff 时导出空 diff、审查指令及元数据，明确提示没有变更，不伪造改动、不新增范围问卷。

取消主菜单、分支／提交／PR 选择或导出中的操作均结束本次请求，不发表半成品，不改已有成功 ZIP。冻结捕获与打包展示实际运行状态并可取消，不出现等待模型选择上下文的阶段。`/review` 自身行为不得因本命令改变。

### 2.2 无交互模式

无 UI 时仍接受相同参数。直接 PR 引用按该 PR 导出；没有直接 PR 时以当前未提交改动为冻结范围，参数原样作为后续 review 的 focus，不新增交互步骤或新 CLI 语法，也不擅自退回某个历史提交／分支。没有 diff 时导出空 diff、审查指令及元数据，并明确记录无变更。自定义指令／headless 路径也必须真正完成版本冻结与打包；只返回提示词、改为默认审查或仅打印计划不算完成。

无法确定或读取有效范围时明确失败，不猜测历史版本、不悄悄改成另一个范围。范围确定方式、补充指令及限制写入包内元数据。

## 3. 比较范围与冻结版本

所有路径以实际 Git 仓库根为基准，而非命令加载时的旧 cwd；会话经 `/move` 或 `/wt` 改目录后使用当前会话目录。仓库子目录发起时仍导出正确的仓库范围。

| 选择 | 基线 | 目标 |
| --- | --- | --- |
| 未提交改动 | 固定的 `HEAD` | 捕获时最终工作树：同时包含 staged、unstaged 与未被 ignore 的 untracked 文件 |
| 指定提交 | 所选提交的第一父提交；根提交使用空树 | 所选提交的固定 SHA |
| 基线分支（PR Style） | 所选分支与当前分支的 merge-base | 当前分支固定 SHA；不包含当前工作树未提交内容 |
| PR | 该 PR 比较所用、已固定身份的基线 | 该 PR 固定的目标 SHA，不是本地同名分支或 checkout |
| 自定义／headless | 当前未提交范围 | 同一冻结工作树；无 diff 时明确记录为仅审查指令与元数据 |

- 在首次使用时解析并固定完整 SHA；后续 diff、文件读取和指令均绑定同一比较身份，不能因分支移动或 PR 更新拼接不同版本。
- 历史提交／PR 的文件只读对应对象或等价固定版本，不得用当前 checkout 补齐。无法取得 PR 的固定变更文件版本必须失败，不能把只有 patch 的材料冒充完整源码。
- 未提交范围表示 `HEAD` 到最终工作树的一次比较，不把 staged 与 unstaged 两段 patch 直接串接，也不导出已被后续工作树覆盖的 index 中间态作为最终代码。
- 工作树捕获要检查源文件在读取期间字节未变，并在发布 ZIP 前再次核对捕获范围及已读取变更源码。新增、删除、重命名、内容或状态变化造成不一致时中止；不能只靠 mtime／文件大小判断，也不能把变化后的内容混入旧 diff。
- **仓库根 `.tmp/` 在发现、diff、源码和再次核对各阶段均排除**，防止旧 ZIP、本次 staging 或其他临时材料递归进入导出；排除须记录，不能改变实际 Git 状态。
- 基线无共同祖先、ref 无效、Git／PR 读取失败须明确报错；不静默比较无关树。非 Git 或其他不支持的版本控制状态须明确说明，不隐式切换实现。

## 4. 确定性导出材料

### 4.1 变更材料

- 保存完整文本 diff，不能沿用 `/review` 的审查过滤器丢弃 lockfile、生成文件或其他已变更文本，也不能只保留统计、文件名或固定 diff 半径。
- 保存全部变更文本的目标版本及理解原变更所需的基线版本：新增只有 after，删除只有 before，修改保留 before／after，重命名记录原／新路径并保留对应版本；复制、纯模式变化和仅重命名也不能被当作无变更漏掉。
- 原文件字节、编码、BOM、CRLF／LF、尾部空白及末尾是否换行保持不变。面向模型的展示可带行号，但 ZIP 中源码不加入行号、标记、省略号或替代文本；生成的说明与元数据使用 UTF-8。
- **原字节保留不等于支持所有文本编码。** 当前快照的文本 diff 生成使用严格 UTF-8；含 NUL 或非 UTF-8 的变更在快照中标为二进制，不生成逐行文本 diff。打包层按字节保存实际纳入的源码，不转码；可识别带 BOM 的 UTF-16／UTF-32 源码并按其换行字节计算行数，但这不代表 diff 已理解这些编码。其他传统编码的变更可能仅有二进制身份／大小／哈希而无源码 payload，须记录限制。完整文本 diff／必要源码的原目标仍保留，此类材料不能被宣称已完成所有文本编码的完整审查准备。
- 二进制默认只记录路径、状态、版本、大小、哈希／Git 对象等可得身份和未附 payload 的原因，不把二进制乱码当文本，也不伪称已包含二进制内容。
- 必需变更文本读取失败、native／GitHub 返回截断或内容身份无法核对时失败，不发表宣称完整的 ZIP。没有变更时明确提示仅导出了审查指令与元数据。

### 4.2 不进行上下文调查

- 导出路径不得访问会话模型、凭据或模型 API，不创建独立 Agent，不要求任何 `select_context` 等结构化模型结果。
- 范围由用户已选 Git／PR 比较确定，只收录该范围的变更前后完整文本版本；不自动追踪 imports、调用方、类型、测试、配置或需求，不将未修改文件或整仓源码作为补充上下文装包。
- 用户补充指令只写入审查材料，不能让导出工具执行命令、测试、搜索、审查或上传。
- README 明确说明材料边界：包内是选定范围的变更材料，不是已调查完所有依赖的审查上下文。接收者自行审查，并按需要向用户索取额外源码。


### 4.3 容量与限制

不静默截断必要 diff／代码，也不因 ZIP 库限制悄悄丢文件。包无法在实际限制内完整形成时，清楚提示需拆分范围，本次失败并保留旧 ZIP；不新增用户任意 A/B 或模式选择来掩盖限制。

当前实现有分层的明确拒绝边界，单位均为 MiB（`1024 × 1024` 字节）；上限不是裁剪预算：

| 阶段 | 当前上限与可观察行为 |
| --- | --- |
| 快照单文件／Git blob 读取 | 32 MiB；超过读取边界或 native 返回截断则失败 |
| 快照完整 diff | 64 MiB；超限失败，不只保留前半段 |
| 冻结内容捕获 | 已读取并缓存／观察的变更文件版本累计 256 MiB，不是整个仓库大小；超限失败 |
| ZIP 单成员 | 16 MiB；适用于源码、`diff.patch`、指令和元数据等每个成员。因此快照可读取 32 MiB 文件、可构建 64 MiB diff，不表示它们都能进入 ZIP；实际待归档成员仍须各自满足 16 MiB |
| ZIP 全包 | 所有成员未压缩字节合计 64 MiB，包含 README、manifest、diff、源码、两份指令和元数据；压缩率高不能绕过该限制 |
| GitHub 响应 | 复用接口每次响应的 8 MiB 捕获上限；这是 JSON／base64 等响应字节，不是可保证读取的源码大小。输出被截断或 recursive tree 标记不完整均失败 |

必要变更文件及完整 `diff.patch` 不能为满足这些限制而自动裁剪；任一必要成员或全包超限时提示拆分比较范围，本次失败且保留旧包，不新增命令参数或选择菜单。大文件、完整 diff 和不静默漏失必要材料的原要求不因这些边界而删除；以上边界也不代表容量场景已验收。

## 5. ZIP 内容、指令与来源

最终路径固定为 **`<仓库根>/.tmp/review-bundle.zip`**，不支持另选路径。包至少包含：

```text
README.md
manifest.json
diff.patch
changed-files/before/<仓库相对路径>
changed-files/after/<仓库相对路径>
instructions/review.md
instructions/reviewer.md
metadata/<必要的版本、状态与限制资料>
```

不存在的 before／after 版本不造空文件冒充。所有入包源码按原始字节完整保存，不进行上下文选择、范围裁剪或非连续块拼接，也不生成 `context/` 成员。

### 5.1 审查指令

- `instructions/review.md` 保存原生 `/review` 针对**本次已选冻结范围**完整渲染的审查命令提示词，含生效的用户补充指令／自定义指令及相应分发规则；不能用一句“执行 /review”、未渲染模板或另一套简写规则替代。
- `instructions/reviewer.md` 保存当前分发版本 `src/prompts/agents/reviewer.md` 的完整 reviewer Agent 提示词，不能摘录、总结或省略。
- README 链接这两份指令并说明用途：供接收者后续审查使用，导出命令本身不执行其中的审查、任务派发或工具调用。指令中的历史目标必须可对应本包冻结身份，不能把当前 checkout 冒充目标版本。
- manifest 记录两份指令的来源、渲染范围／版本、成员路径、字节数及 SHA-256；不得给未实际收集的 Agent 提示或环境信息编造来源。
- 两份指令来自**运行中的 OMP 内置版本**，不伪称来自被审仓库的历史提交。原生 `/review` prompt 可能按其既有规则概述大 diff；这不允许裁剪 `diff.patch` 或变更源码，接收者必须以 manifest 指向的冻结成员及完整 diff 为准。外部审查者不能假定原提示词中的 OMP 工具／任务分发约定在其环境可用。

### 5.2 清单、计数与可追溯性

README 提供包用途、比较方向、冻结身份、材料导航、无脱敏风险、如何使用审查指令，以及所有影响完整性的限制。manifest 至少记录：

- 原命令参数、补充／自定义指令、实际模式、范围选择依据、仓库相对路径体系和比较方向。
- 完整 base／target 提交身份、工作树快照依据及 PR 仓库／编号／固定比较身份；根提交或无 diff 的特殊语义明确说明。
- 每个变更的状态、原／新路径、文件类型、Git mode、before／after 成员、可得对象身份。
- 导出源码／指令成员的 SHA-256、字节数，以及未附二进制、排除和缺失；哈希对应真实归档字节。
- 文件数、源码行数、未压缩字节数和压缩后 ZIP 字节数，注明统计口径，区分变更文件、源码版本及归档成员，不能将 before／after 两份误报为两个业务变更。无法取得的统计或身份应注明，不伪造精确值；不得以 manifest 自身哈希形成无法实现的递归要求。

纯工具包使用 `formatVersion: 2`。`fileCount` 是归档文件成员数（包括 manifest），`sourceFileCount` 是实际附 payload 的完整源码版本成员数，源码行数累计各实际导出版本，不含 diff 和指令；没有补充上下文数、裁剪范围或模型选择字段。manifest 清单覆盖自身以外的成员，不递归计算自身哈希；manifest 的 `compressedBytes` 为 `null` 并注明原因，实际压缩后 ZIP 字节数由编码完成后的命令通知报告。不得把这些计数解释为不同业务文件／变更的数量。

路径必须是安全的仓库相对路径：拒绝绝对路径、盘符／UNC、`..` 越界、成员重复冲突及会逃出 staging／归档根的形式；保留原有合法文件名，不靠改名导致路径身份丢失。当前还明确拒绝反斜杠、控制字符、冒号、空／`.`／`..` 路径段、`.git` 内部路径，以及打包层不支持的尾随点／空格和 Windows 保留设备名；这些是受限错误，不得静默改名或漏掉路径。

## 6. 特殊 Git／文件状态

- untracked 仅纳入非 ignored 且属于本次范围的文件；对生成物／私人文件的排除只适用于非 ignored 的 untracked 材料，不得据此过滤 tracked 源码或改动文本；仓库根 `.tmp/` 仍按全阶段排除。ignored 私有文件不进入 ZIP。
- 当前未提交范围遇到 unresolved conflict／unmerged index（含 `U`、`AA`、`DD` 状态）明确拒绝导出，不把冲突当普通 clean 修改；不宣称已支持完整表达冲突的多版本内容。
- 当前已知 before／after mode 为符号链接 `120000`、子模块 gitlink `160000` 或其他非 `100644`／`100755` 的变更明确拒绝整次导出；不跟随链接、不递归收集子仓库，也不静默省略变更后声称成功。工作树读取逐级检查路径，即使链接指向仓库内部也不解引用；符号链接、非普通文件（含目录／子模块）、不安全父路径和越界路径均报错。GitHub 已知特殊类型不能作为普通源码读取，目标枚举中的排除须记录。
- 二进制、纯 mode 变化、重命名／复制、删除、根提交、detached HEAD、无共同祖先及包含空格／Unicode 的路径须有明确处理或受限错误；不支持的状态不可悄悄忽略。
- Git 对象缺失、PR 权限／认证／传输错误、内容截断、无法访问的必需文件、非法归档路径均不能转成“无改动”或成功。
- 当前**本地范围**拒绝 reftable 仓库：中央 VCS 的 fallback 无法提供所需原字节 blob，不得走有损／截断降级路径。此限制不等同于禁止通过固定 GitHub 对象读取 PR。
- **native 历史 mode 缺失是显式能力限制。** 本地历史读取的 native 接口可能不给出完整 mode 元数据，不能因此认定对象都是普通源码。可读取的历史符号链接 blob 只保留其存储的链接目标原始字节、不解引用，并在包和最终通知中显著记录类型／mode 识别限制；已知特殊 mode 仍按上述规则拒绝，无法读取的必需对象仍失败。该限制不能作为符号链接／gitlink 语义已经完整支持或验收的证明。

## 7. 发布、取消与失败保全

1. 在仓库根 `.tmp/` 创建本次唯一、自有 staging，不使用共享中间文件，不预先删旧包。
2. 写完整材料并生成临时 ZIP；检查必需成员、无重复／越界路径和清单一致性，重新打开 ZIP，逐成员校验解包结果与预期原始字节／哈希一致。
3. 再次核对工作树来源未变及取消状态；全部检查完成后才原子替换固定路径。这里的“覆盖前检查”是程序完整性与一致性检查，不新增与 `/review` 不同的用户覆盖确认菜单。
4. 成功后展示固定绝对路径、模式、比较身份、文件数、源码行数、未压缩／压缩字节数及限制，并说明未调用模型、未审查、未上传；不能把成功通知重新当成一次审查 prompt。
5. 任意捕获、读取、压缩、校验、取消或替换失败均如实报告，最后一次成功的 `review-bundle.zip` 保持可用；未有旧包时不留下伪成功文件。
6. 只清理本次自有中间产物，不删除整个 `.tmp/`、他人文件、并发导出的 staging 或旧成功 ZIP；清理失败也不能掩盖原始失败。

## 8. 验收条件与当前证据

验收必须通过真实命令入口形成 ZIP，并解包核对结果，不能用静态注册、提示词文字测试或 mock 的成功路径替代。最小定向覆盖包括：

- `/review` 与本命令的 PR 参数、会话 PR、open PR picker／搜索、基线分支、提交、未提交、自定义编辑器、headless focus 和取消的行为对应；原 `/review` 无回归。
- staged + unstaged 的最终工作树语义、非 ignored untracked、删除／重命名／mode、根提交与 merge-base，仓库子目录及会话 cwd 切换；历史／PR 目标与故意不同的 checkout 不混读。
- 所有必要文本 diff／版本均存在，原编码、BOM、CRLF、末尾换行、Unicode 与硬编码凭据按原始字节保留；无脱敏、无无关私有文件、无根 `.tmp/` 自包含。
- 在没有模型凭据、模型服务不可用时仍能从真实命令入口完成本地导出，模型端点请求数为零；自定义指令只进入材料，不触发调查或审查，不收录未修改源码。
- 两份完整审查指令实际进入 ZIP，review prompt 对应选定冻结范围，reviewer prompt 与分发源一致；README 链接、manifest 来源／大小／哈希可核对，未自动执行审查。
- ZIP 全成员校验、计数口径与最终通知一致；在读取期间／发布前改变源文件、取消、截断、无权限、压缩／校验／替换失败时均不损坏先前成功包。
- 二进制、conflict、symlink、submodule 与不支持状态有真实元数据或明确错误，不越界、不静默漏报；无源码／Git 状态写入、无上传或自动审查。

实际实施与验证证据统一维护在[需求目录](README.md)，只对已执行场景作通过结论；静态检查、局部回归与本地 Git 导出不代表联网 PR、跨平台或全部特殊状态均已验收。
