# rpc-ui 协议:最小核心接入需求

> 目标:ZCode 桌面版经 OMP 的 rpc-ui 协议驱动 OMP 作为 Agent 后端。本文是本功能域唯一权威需求,采用行为级契约:接口字段、错误码、事件载荷以当前实现与测试为准,本文不维护字段级协议表。
>
> 2026-10-06 经需求访谈由完整架构设计收缩为最小核心;取消的能力见 §5,不从旧版文档恢复。

## 1. 范围与边界

- 宿主是 ZCode 桌面版:ZCode 负责进程管理、界面与调用适配;OMP 负责会话运行与权威状态。
- OMP 侧改动只发生在 rpc-ui 模式;上游原生单会话 rpc-ui(v1/v2)行为保持不变,fork 扩展经 v3 协商门控。
- 不做:远程多客户端、ZCode v4 线协议兼容、第二套协作产品、遥测、通用文件代理。

## 2. 保留能力与行为契约

### 2.1 普通消息链路(地基)

- 发送消息、流式回答、工具过程事件、停止(abort)和历史恢复读取;会话忙时可插话(steer/follow_up)。
- 请求接受不等于执行完成;`prompt_result` 是本轮终结信号,两者不得混淆。
- 审批与 ask 交互闭环:工具审批和选择/输入/确认/敏感输入经交互协议完成;会话关闭或取消必须结束其等待中的交互;A 会话等待不阻塞 B 会话。
- 停止或失败后已产生的内容仍可读取;界面刷新不重复发送用户消息。

### 2.2 项目模式与多会话

- `--mode rpc-ui --rpc-project` 启动:一个项目一个 OMP 主进程,承载多个会话。
- 会话生命周期:创建、恢复、关闭(保留历史)、改名、删除;同一身份并发恢复只加载一次;繁忙时关闭/删除默认拒绝,显式取消后有序执行。
- 多会话隔离:消息、执行、取消、审批、交互、队列按会话归属,互不串话;没有进程级"当前会话"。
- 进程重启后按持久会话身份恢复历史;不承诺执行中的工具自动续跑。
- 零会话可用;目录查询不创建会话、不调用模型。

### 2.3 命令与技能调用

- 命令目录自动来自实际命令注册表(上游+fork+技能),新增命令天然可发现;不维护人工覆盖清单,不强制移植业务命令。
- 动态补全处理别名、参数与光标位置,无执行副作用;过期补全结果由宿主丢弃。
- `execute_command` 严格分发:已知命令按注册表语义执行;未知命令或参数错误明确报错,绝不当作普通消息发送给模型。
- 命令完成通道区分:本地完成直接返回;触发模型执行的以 `prompt_result` 收尾;异步管理操作有独立终态。
- 依赖终端交互的命令如实报告不支持及原因,不伪装成功。

### 2.4 临时切模型

- `set_model` 只改变当前会话的模型,不写任何配置文件;其他会话与新建会话默认值不变。
- 会话执行中拒绝切换并提示稍后重试;失败保留原模型。
- 切换后可查询当前实际模型;该会话后续消息与技能执行使用它。

### 2.5 role 持久配置

- 界面可见全部可配置 role(含未配置项与自定义 role),不因无账号/无候选模型而隐藏。
- 选定 role 模型即自动保存到用户级 OMP 配置;实际落盘成功才报告已保存;失败保留待保存选择并如实显示当前配置。
- 同 role 陈旧写入报修订冲突;不同 role 并发修改互不丢失。
- 被项目配置或运行覆盖时如实显示实际来源;临时切换与 role 配置是两种独立操作,不得共用隐含写配置的行为。

## 3. 验收条件(行为级)

按仓库规则以自动化测试与真实公开入口 E2E 验证;模拟测试不替代真实进程边界验证。

- 项目模式 E2E:真实进程下多会话并发——A 等待审批/输入时 B 可执行、取消或关闭 A 不影响 B;重启后历史按身份恢复。
- 消息 E2E:经真实 RPC 入口完成发送→流式→工具过程→停止/完成→历史读取;接受与完成不混淆。
- 命令 E2E:目录可发现、补全无副作用、已知命令正确执行、未知命令不触发模型调用。
- 模型 E2E:临时切换后真实请求使用目标模型且配置文件内容不变;role 保存后配置文件落盘、重启读取一致、冲突如实报错。
- 稳定性:输出队列有界,慢消费者不导致无限内存增长;旧单会话 rpc-ui 行为回归不破坏。

## 4. 实现与验证现状(指针,非验收声明)

- OMP 侧项目模式、消息链路、命令目录/补全/执行、模型与 role 的实现入口为 `packages/coding-agent/src/modes/rpc/`(rpc-project-*.ts 等),自动化测试为 `test/rpc-project-*.test.ts`(fulltest 的 rpc-project 组)。
