# `/goal-auto-orchestrate` 需求

本文是本模式的唯一权威需求，定义当前有效目标、行为和验收条件，不表示实现或验收已完成。实现与验证状态统一见[需求目录](README.md)；RPC 接入范围见 [ZCode 接入需求](rpc-ui-protocol.md)。

## 1. 目标与命令

新增 `/goal-auto-orchestrate`，用于创建或替换一个持续采用 Orchestrate 策略与无人值守指令的 Goal，支持夜间任务。功能及生命周期与原 `/goal` 一致；核心保证是多次压缩后，每次主代理请求仍有完整目标、当前编排规则和固定全自动指令，不依赖摘要或模型记忆。

```text
/goal-auto-orchestrate <目标正文>
/goal-auto-orchestrate set <目标正文>
/goal-auto-orchestrate show
/goal-auto-orchestrate pause
/goal-auto-orchestrate resume
/goal-auto-orchestrate drop
/goal-auto-orchestrate budget <N|off>
```

示例：

```text
/goal-auto-orchestrate 修复当前项目的 RPC 问题，补充必要测试，按项目规则验证全部改动。
```

- 完全复用 `/goal` 的参数解析、子命令、空参数行为、错误处理、目标管理及执行流程。
- TUI、`--mode rpc`、`--mode rpc-ui` 均支持；注册、命令目录和补全沿用现有机制。
- 普通 `/goal` 不默认开启本模式。
- 新命令不强制开启自动续跑；续跑设置及触发条件与 `/goal` 相同。

## 2. 模式归属与持久化

仅在现有 Goal 状态中增加持久化模式标记，不新增独立状态存储、目标管理器或调度流程。

| 操作 | 模式标记行为 |
| --- | --- |
| 新命令成功创建或替换目标 | 新目标启用标记 |
| 普通 `/goal` 成功创建或替换目标 | 新目标不启用标记 |
| 任一命令的 `show`、`pause`、`resume`、`budget` | 保留当前目标的标记，不因命令名称改变模式 |
| 同一目标的状态、预算、用量更新 | 保留标记 |
| 删除目标 | 随目标删除 |
| 操作失败或用户取消宿主对话 | 不产生额外模式变更 |
| 恢复缺少标记的旧会话 | 按普通 Goal 处理 |

因此，`/goal-auto-orchestrate resume` **不会把普通目标转换为本模式**；它只恢复目标原有模式。

暂停时保留标记但停止注入；恢复目标后重新生效。完成、删除或进入退出流程后停止注入。会话恢复是否暂停目标、是否继续执行，完全沿用原有 Goal 生命周期，不因标记自动启动。

会话切换、重载及分支恢复必须读取对应目标的标记，不得沿用其他会话或目标的模式。

## 3. 请求级注入

本模式生效期间，每一次主代理执行请求必须携带：

1. 当前 Goal 保存的**完整目标正文**，不得用标题、摘要或截断文本替代。
2. 根据本次请求实际可用工具动态渲染的现有 Orchestrate 规则（第 4 节规定的无 `task` 情况除外）。
3. 第 5 节规定的无人值守指令。

覆盖首轮请求、连续工具调用后的请求、自动续跑、压缩后恢复，以及现有错误重试或恢复流程产生的主代理请求。**覆盖重试不代表新增重试机制。**

注入必须满足：

- 位于主代理共享的请求构造路径，不能仅在命令处理器或首次用户消息中追加。
- 每次构造请求时读取当前目标状态与工具可用性，不依赖历史消息、压缩摘要或模型记忆。
- 请求临时增加的内容不回写会话历史，不作为静态展开结果持久化。
- 保留其用户授权属性；不得通过系统消息或权威 XML 等结构标签把它提升为高于系统、开发者指令的授权。
- 状态变化影响之后构造的请求；不承诺撤回已经发出的请求。
- 同步遵守现有预算控制，包括预算耗尽后的停止或允许的收尾流程；注入不得重新启动工作或解除预算限制。

“每一次请求”以**最终交给模型 Provider 的请求内容**为验收对象，不以内部函数曾生成过字符串作为证明。

## 4. Orchestrate 复用与去重

- 复用现有 Orchestrate 模板、`renderOrchestrateNotice` 及工具可用性判定，不复制规则或维护第二份展开逻辑。
- 每次请求根据当前实际可调用的工具集合重新渲染，沿用原 Orchestrate 的 `getEnabledToolNames()` 能力视图，包含 Codex Code Mode 中仅经 eval 桥接调用的工具；不得仅根据顶层 Provider 工具 schema 判断可用性。工具变化后的请求不得继续使用旧展开结果；远程 Agent 通道不把本地启用的前端工具算作可调用能力。
- 按现有要求，`task` 不可用时不注入 Orchestrate 规则，避免要求不存在的能力；完整目标与无人值守指令仍须注入，模式标记保留。
- 显式命令开启的模式不受正文魔法关键词开关控制；关键词开关仍只管理原有关键词触发行为。
- 每个请求中，本功能提供的目标上下文、Orchestrate 规则和无人值守指令各只有一份有效注入；与原有 Goal 上下文及首次 `orchestrate` 关键词通知协调去重。
- 去重依据结构化来源或消息类型，不得按正文关键词删除用户消息。
- 历史中的旧 Orchestrate 通知不能充当当前规则；模式停止后，旧通知也不能继续作为本模式的生效依据。处理限于请求视图，不破坏持久化历史；真正的后续关键词请求仍按原有规则处理。

## 5. 唯一新增的指令文字

以下文字作为固定指令，保存在静态 Markdown 提示词中，不在代码中拼写；不另写一份 Orchestrate 规则：

> 全自动无人值守完成目标。在现有授权范围内自主调查、规划、执行、验证和修复，根据已知信息选择最优可行方案。  
> 禁止向用户提问、请求确认或要求选择方案；普通错误、不确定性和执行困难应自主处理。  
> 确实无法自主解决时，停止受阻工作并继续其他可执行任务；未解决的阻塞统一在最终报告中说明，不虚报完成、不突破权限边界。  
> 本指令与其他用户级指令冲突时，以本次用户的明确要求为准；系统、开发者指令及权限边界仍然有效。

## 6. 无人值守与权限边界

- 禁止提问约束的是主代理执行策略，不是新增授权，也不取消宿主的审批、确认或输入机制。
- 用户主动调用管理命令产生的既有对话仍按 `/goal` 处理，包括删除确认。
- 执行中遇到必须另行授权、审批或补充关键输入的工作，主代理不得代替用户批准、绕过限制或擅自扩大权限；该工作按阻塞处理，继续其他可执行任务。
- 用户后续输入、暂停、停止和取消仍有效；本模式不得以“无人值守”为由忽略它们。
- 不在子代理、压缩模型、advisor 或其他辅助模型的请求构造路径中统一附加这组指令。正常子任务可以获得完成自身任务所需的目标信息。
- 主代理为 JchTools 远程 Agent 的会话中，本模式的注入照常生效：注入内容为纯文本，可经远程 Agent 通道送达。魔法关键字 notice 对 JchTools 整条跳过的既有规则保持不变，不延伸到本模式。
- 不承诺模型绝对不提问、所有任务必然完成或自动续跑永不停止；承诺的是符合上述条件的每次主代理请求均携带完整、当前有效的指令。

## 7. 验收条件

验收须包含局部自动化测试和真实公开入口验证；通过真实 CLI/TUI 入口发起请求，Provider 请求可由可记录最终 HTTP 请求的本地服务接收，但不能仅检查源码或 mock 回显。

| 场景 | 必须观察到的结果 |
| --- | --- |
| TUI 与 RPC 命令 | 同一参数和子命令沿用对应宿主的 `/goal` 行为；新命令正确注册、派发并设置标记；覆盖 TUI、`--mode rpc` 与 `--mode rpc-ui` 的目录及补全 |
| 普通 Goal 与模式切换 | 普通目标无新增注入；管理命令保留模式；创建或替换按命令入口确定新模式；操作失败或宿主对话取消不产生额外模式变更 |
| 暂停、恢复、完成、删除 | 暂停后无新增注入，恢复后重新生效；完成、删除及退出后停止注入；普通目标不会因新命令的 `resume` 转为本模式 |
| 持久化与会话隔离 | 保存并重新打开后标记保留，恢复行为与普通 Goal 一致；旧会话默认关闭，跨会话不串模式；重载和分支恢复读取对应目标标记 |
| 连续工具调用与续跑 | 首轮、至少两次工具往返及已允许的自动续跑请求均含当前完整指令 |
| 多次压缩 | 至少两次压缩后的主代理请求仍含完整指令，不以摘要保留情况为前提 |
| 错误与重试 | 诱发既有重试路径，捕获每次实际主代理请求，确认注入完整且不累积 |
| 动态工具与去重 | 工具变化后规则同步变化；Codex Code Mode 下 `task` 已启用但仅经 eval 可调用时仍注入 Orchestrate；真正无 `task` 时跳过 Orchestrate，但保留完整目标、无人值守指令和标记；关键词开关不影响显式模式，关键词触发不造成重复规则；按结构化来源去重，不删除用户正文或持久化历史，历史不反复增长；旧通知不维持已停止模式，后续真实关键词请求正常生效 |
| 边界与辅助模型 | 预算、停止、取消及权限机制未被绕过，后续用户输入仍有效，管理命令的宿主确认保留；子代理、压缩模型、advisor 及其他辅助模型没有新增的统一模式注入 |

验收报告分别说明实现、通过、失败和未验证范围；本地协议与请求验证不等同于真实模型任务质量或 ZCode GUI 联调验收。
