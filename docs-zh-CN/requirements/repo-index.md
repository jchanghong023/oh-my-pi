# 代码定位索引

本文是代码定位索引的唯一权威需求。接口精简、设备执行失效通知、LSP 落盘更新、Windows 删除路径身份、Python 3.6 标识符兼容及长根路径确认已实现；Windows 定向回归和真实 CLI／TUI 验证通过，范围见「实现行为与验证边界」及[需求目录](README.md)。公司仓库、NFS 和 Linux 尚未验证，不能将本地模拟模型验收当成真实模型能力或完整门禁通过。它为当前项目提供文本候选和 Python 定义定位，仍需与 `read`、`grep` 和已有语言工具配合；原检索调研讨论的其他技术路线不因此成为本工具的能力。

## 环境、价值与范围

| 环境条件 | 当前处理 |
| --- | --- |
| Python 3.6 项目 | 内置语法解析 Python 定义，无须改造源码、补写类型或安装语言服务；不进行名称绑定 |
| 大量源码、配置和测试 | 索引保留文本、路径及源码/测试/配置/其他类别，按路径过滤并显示类别辅助定位 |
| 网络文件系统上的项目 | 索引放在用户 profile 的目录，不向源码目录写库；没有增加 NFS 专用存储方案，也未在公司网络文件系统上证明性能或并发特性 |
| 离线环境 | 建库与查询在本机使用内置能力，不调用模型或外部搜索服务 |

本地索引减少重复检索时的源树扫描，返回 Python 模块、类、函数和方法的位置、可用签名；索引还需建库、更新和核对。它不包含 `related`、`impact`、依赖或调用图、测试覆盖/配置消费推断、向量检索、自动摘要或多人共享索引，不能据此断言企业环境中的定位速度或任务成功率。

## 用户入口：`/repo` 内置命令

在 omp 中输入 `/repo` 打开当前范围的索引面板；RPC UI 通过同一命令及协议对话提供相同索引操作，接入契约见 [ZCode 接入](rpc-ui-protocol.md#必须接入的命令)。不提供 `omp repo ...` CLI 命令组。首次建立需由用户确认面板或 RPC 对话显示的根目录，AI 的只读查询不能代为建立。建立、重建和删除确认必须完整展示目标根目录；长路径按当前终端宽度折行，确认按键独立可见，缩放不得丢弃路径尾部。

| 面板状态或操作 | 当前行为 |
| --- | --- |
| 尚无索引 | 显示目标根目录，用户可确认建立；普通查询不自动建库 |
| 查看状态 | 显示文件/符号数、索引代次、失败、已知待处理路径、未核对原因和最近完整核对时间 |
| 更新 | 完整枚举并读取当前范围，通过内容指纹发现新增、修改和删除（含同大小、同修改时间的变更），内容未变不重新解析 |
| 重建及恢复 | 重建完整索引；数据库损坏或 schema 不兼容时可经面板重建恢复，不将查询故障冒充无命中 |
| 删除 | 清除该范围的索引，不删除或修改项目文件；在途建库先取消并等待，避免删除后重新发布 |
| 建立、更新、重建中 | 显示进度，可取消；失败或取消不公开半成品，原有可用代次保留并报告未核对 |

Git 项目以当前 worktree 根目录为范围，非 Git 项目以当前工作目录为范围；规范化路径后按根目录和用户 profile 隔离数据库，不混用不同 worktree 的内容。

## AI 入口：一个 `repo` 工具、三种查询

AI 侧提供一个只读 `repo` 工具，普通搜索只需 `{"query":"关键词"}`；可选 `action` 默认 `search`，需要 Python 定义或详细状态时显式选择 `symbol` 或 `status`。参数仅有 `query`、`action`、`path`、`cursor`，不提供类别、页大小、建库、更新、重建或删除参数。
默认非受限会话在 `tools.xdev=true` 时将 `repo` 作为低频只读设备挂载：通过 `read xd://repo` 按需读取说明与 schema，通过 `write xd://repo` 携带 JSON 参数执行查询，不在顶层工具 schema 中常驻；`tools.xdev=false` 时仍作为顶层工具提供。显式工具清单继续按原生顶层工具暴露，受限清单不被扩大；仅改变展示与派发入口，不改变只读权限、查询或生命周期语义。
设备查询保留原生只读工具的独立审批和共享调度：`tools.approval.repo` 的显式策略仍生效，未配置时不继承 `tools.approval.write` 的拒绝／询问策略；同轮独立查询可以并发，不因 `write` 传输变为独占。普通文件写入和其他设备仍沿用原有审批及调度规则。

| 动作 | 主要输入 | 返回内容 |
| --- | --- | --- |
| `status` | 无查询词 | 根目录、代次、覆盖状态、已知待更新路径、失败和未核对原因；不扫描源树 |
| `search`（默认） | 普通文本，可选相对路径/目录、分页 | 文件、类别、原始行号范围与有界文本片段 |
| `symbol` | Python 符号名，可选路径、分页 | 模块、类、函数及方法的定义位置、限定名与可用签名 |

每页固定最多 20 条；cursor 绑定动作、查询词、路径与索引代次，省略动作与显式 `search` 等价，代次变化时须从第一页重查。查询文字只显示命中、续页、截断及必要的覆盖提示；根目录、代次、数量、排除清单和最近完整核对时间通过 `status` 查看，不在每次搜索中重复。候选和字段输出受限，已知待更新项、未核对范围及失败仍须提示。无索引、正常无命中和查询错误分别呈现，不能把任何一种当作“仓库没有此代码”。

`path` 始终是索引根内的相对路径：接受 Windows 分隔符并归一化 `.`、重复分隔符及根内 `..`；POSIX 上若索引中存在含字面反斜杠的对应文件或目录，优先按该字面路径过滤，否则仍按 Windows 分隔符归一化。拒绝绝对路径、盘符相对路径及越过根目录的路径；过滤与游标身份共用同一读快照中选定的归一化结果，不用无声零命中掩盖非法范围。

## 索引内容与实现方式

数据流如下：

```text
仓库中的源码、测试、配置等文本文件
   ↓ 枚举与分类：记录路径、文件类别和内容指纹
   ↓ 文本入库：保存可搜索内容及原始行号
   ↓ Python 解析：提取模块、类、函数和方法的定义位置与签名
   ↓ SQLite 索引：供 repo 按需查询
```

**解析。** Python 的模块、类、函数、方法定义由内置 Tree-sitter 解析提取，支持 Python 3.6 风格的装饰器、嵌套定义、异步函数，以及同步上下文中合法的 `async`／`await` 定义名、类名、参数和标识符引用；原始名称、限定名、签名和源码坐标保持不变，不将异步函数作用域内非法的保留字标识符当成合法代码。同名定义靠路径、限定名和行号区分。这是按名称找定义的工具，不解析引用、类型或实际调用。Python 语法解析失败时保留该文件可用的文本内容，不返回过期定义，并在覆盖状态中记录失败；空或仅含注释的语句块同样属于解析失败，不能因语法树缺少错误节点而接受。其他语言、配置和测试仅提供文本定位。

已有索引中因旧版解析器记录的失败或缺失符号，须通过 `/repo` 的重建重新解析；仅按未变内容指纹复用旧记录的更新不修复这些定义。

**存储。** 独立的用户目录 SQLite 数据库保存路径、类别、指纹、原始文本和 Python 符号，文本候选使用 FTS5 trigram。代码索引与手动维护的 Markdown `wiki` 数据库和命令完全分离；建库后无已知待处理路径的查询不必重读或遍历源码。不提供网络文件系统专用缓存、服务或跨用户共享。

**检索范围。** 文件枚举遵循现有 Git 忽略及文件搜索规则，包含可纳入范围的隐藏文件；符号链接不跟随，二进制、无效 UTF-8、超 2 MiB 及不可读文件被排除或报告。类别仅是筛选标签，不表示测试覆盖或配置依赖，忽略规则也不是源码访问控制。

**文本匹配。** 按 JavaScript `toLowerCase()` 做不区分大小写的原样字面量查找；完整边界匹配优先，其次子串，拆分出的词元补充召回，例如 `timeout` 可找到 `ERR_TIMEOUT`。不足三个字符也有匹配路径，标点不是给用户的 SQL 语法；`symbol` 对名称和限定名称做大小写不敏感的子串定位。查询给出候选片段，不提供正则 grep 或找全所有出现位置的保证。

- 同一文件较早的子串不能掩盖较后的完整边界匹配；片段和排序使用最佳匹配位置。Unicode 组合附加符属于单词延续部分，不可被当作完整边界。
- 文本查询仅为当前页加载原始正文及生成片段；翻页可复用绑定数据库、查询条件与代次的有界定位缓存，不缓存完整源码。文本与符号查询在同一独立 SQLite 读快照中执行，扫描期间可取消，不发布或缓存部分查询结果。
- 并发维护持有独占锁时，查询不等待整次建库／重建完成；读取当前已发布代次，并保留已知 pending／unchecked 提示。锁释放后仍处理待更新路径，不读取或发布半成品，也不吞掉数据库错误或取消。

**内容一致性。** 完整核对先读取文件与指纹，再以同一数据库代次发布文件、文本、符号与覆盖状态。文件被替换或读取时变化，不把混合内容标成已核对；取消/失败保留旧代次和未核对提示。索引行号指向建立该代次时的原文，编辑前须读取当前文件确认。

- 发布前再次核对文件内容指纹与文件清单；扫描期间未通知的修改、新增或删除使本次核对失败，保留旧代次并记录未核对。已通知的较新变化保留待处理/未核对状态，不能被本次核对清除。
- 强杀建库/重建进程留下的未发布代次，在下一次取得独占维护锁后回收；回收不删除当前已发布代次或源文件。

## 索引如何更新

采用首次手动建立、已有索引的已知路径自动维护、面板完整核对的组合：

| 变化来源 | 当前处理 |
| --- | --- |
| 成功的 omp 文件编辑、新建、删除及重命名（含 LSP 实际落盘及回滚） | 记录变更路径（重命名包含旧/新路径），下次 `search`/`symbol` 前合并处理；部分失败保留已落盘路径的通知，预览、拒绝及未执行操作不视为成功 |
| 任意 bash/eval 命令（含通过 `write xd://eval` 等设备入口执行） | 实际执行后标记可能影响范围的未核对状态，执行后异常、超时或中断及后台任务最终结束同样通知；帮助、参数拒绝和未执行调用不误标。不从命令文本猜测修改了什么，Git 线索仅用来提议候选路径 |
| 内建 JCH Git 命令（`/jchgitpull`、`/jchgitdiscardall` 等含改树步骤者） | 与 bash/eval 同等对待：任一改树步骤启动后即通知索引未核对（部分失败同样通知）；纯只读命令（如 `/jchgs` 的 fetch+status）与 fetch 即失败未触达改树步骤时不通知 |
| 会话启动/切换、Git HEAD 或工作区线索 | 对已有索引记录未核对状态并尝试低成本候选发现；没有线索不等于当前树未变 |
| 外部编辑、新增/删除及修改忽略规则 | 不承诺查询即时发现；`.ignore`、`.gitignore` 等范围规则变化持续标记未核对，直至面板完整核对 |
| 面板“更新” | 枚举并读取纳入范围的文件，按内容指纹确认全部文件，删除消失的条目；同大小同时间戳的变化和未跟踪新文件也能在完整核对中发现 |
| 文件读取竞争、损坏库、取消或失败 | 不把半成品发布为新代次；旧结果带未核对/失败提示，损坏或不兼容库可在面板重建恢复 |

已知路径变化可局部重新索引，完整核对必须遍历并读取纳入范围的文件，但内容未变者不重复解析。文件删除清除其文本与符号；Windows 大小写等价的删除通知须对应原索引路径，不因文件或父目录已消失而残留旧记录，POSIX 上不同大小写的独立路径不得混同。已索引文件被目录替换时，增量维护移除旧文件记录并处理已发现的新增子文件，不把最终路径上的目录当成永久读取故障。查询前不会每次完整扫描。覆盖状态区分待处理路径、未核对原因与失败；最近核对成功只说明核对完成时的状态，不能证明此后没有外部修改。需要当前或穷尽结论时仍回到文件系统和现有工具。

## 日常使用与现有工具分工

用户首次进入项目后输入 `/repo`，确认目标目录并选择“建立索引”。建库成功后正常描述开发任务，无需逐次指定检索动作；AI 根据问题选择工具。外部批量修改或切换分支后，需要完整核对时，在 `/repo` 中选择“增量更新”。

| 任务 | 使用方式 |
| --- | --- |
| 找已有实现、错误信息或配置键 | `repo search` 定位候选，再用 `read` 阅读当前源码 |
| 找模块、类、函数或方法定义 | `repo symbol` 定位，再读取定义与必要上下文 |
| 找测试或配置文件中的内容 | `repo` 按路径筛选，结果类别辅助定位，不推断覆盖或消费关系 |
| 已知文件路径的小改动 | 直接 `read`，无需强制经过索引 |
| 按文件名或路径找文件 | 使用现有 `glob` |
| 找名称的全部文本出现位置 | 使用现有 `grep`，检查搜索范围、错误及截断 |
| 找某种语法写法 | 可用时使用只读 `ast_grep`；需要结构化修改则先阅读 `xd://ast_edit` 设备文档 |
| 调查调用方或修改影响 | AI 使用 `grep`、可用的 `lsp` 与当前源码继续调查；`repo` 不提供分析结论 |

`grep`、`glob`、`ast_grep`、`lsp` 和 `read` 均复用现有能力；语义检索 `find` 不是文件名 glob，`ast_edit` 不属于只读查询工具。LSP 沿用现有配置与可用性判断，不新增语言服务器安装要求，`repo` 不依赖 LSP。没有索引时退回现有工具并提示可通过 `/repo` 建立；不能因为缺少索引阻止普通开发任务。

## 实现行为与验证边界

本地自动化覆盖文本匹配、路径/类别筛选、分页与代次失效、Python 定义和解析失败、添加/编辑/删除/重命名、完整核对（包括同大小同时间戳）、取消/失败后保留旧代次、删除不动源码以及并发读取的代次一致性，使用真实 SQLite 与内置 Python 解析而非服务替身。已有 Windows 上 wiki/repo 相关 13 个文件的 131 个测试通过、10 个按平台条件跳过，以及 coding-agent 类型检查和改动格式检查通过的记录。已有交互端到端冒烟以真实 PTY 运行 `bun run dev` 和本机构建的 native 模块：从 `/repo` 建立/查看状态，经真实工具派发执行 `search`/`symbol`，实际编辑后再查询，随后外部改动完整核对、取消重建、面板删除，结果通过；**模型响应由 localhost stub 提供，并非真实模型对任务的成功率验证**。既有 AST 部分写入失败的局部回归、fastcheck 和 Windows native 只读文件故障冒烟仍限于其原记录工作树。本轮 Windows 六个定向文件 110 项通过、8 项按平台跳过；当前源码 native 构建、coding-agent 类型检查、改动文件格式及 lint、Rust LSP diagnostics 通过。真实 `bun run dev`＋`tui-test` 使用隔离配置和 localhost 模拟模型，验证设备 Eval 未核对提示、真实 basedpyright 重命名后的文本／符号更新、Python 3.6 参数／类名及后续定义、151 字符根路径在 48／80／120 列的完整确认；真实服务另验证大小写别名删除及 LSP 目录重命名／删除。OpenLane 建库为 309 文件、998 符号，排除 31 个二进制及 1 个超限文件，无解析失败；`import` 六页 106 个唯一路径与文件系统独立核对一致，完整更新、取消重建保留旧代次、删除及缺库提示通过，341 个文件指纹未变。证据为 `node_modules/.cache/repo-p2-fix-20261018/verification.json`；本轮未运行 fulltest／slowtest、Linux／WSL、公司 NFS 或真实模型验收。

另有确定性合成 Python 语料的本地对照基准，以生产环境使用的 native `grep`（同样纳入隐藏文件、遵循忽略规则、大小写不敏感的字面量查询）对照已建索引；两边均检查命中及未命中的路径集合，分别记录首次和重复查询，以及建库、单路径更新、完整核对与数据库大小。这不是公司代码，工作负载、存储和主机配置均不代表公司部署；不能据此声称公司项目提速或 AI 修改质量改善。在公司真实仓库应另行记录目标命中/遗漏、端到端任务结果、建库与维护成本、网络文件系统和权限下的行为。

索引只提供代码定位线索：不保证找全调用方，不判断影响范围、测试覆盖或配置消费，也不替代当前文件阅读、穷尽 `grep`、项目构建测试及人工审查。

## 验收与验证入口

以上行为是后续维护的验收依据。自动化验证须覆盖省略动作的默认搜索、显式 Python 定义和状态查询、路径过滤、固定分页与续页失效、精简输出保留覆盖提示、短查询、增量与完整核对、失败/取消不发布半成品、删除不改源码，以及真实 `/repo` 面板到工具结果的链路。存储层类别筛选仍由既有测试覆盖，不作为工具输入。

现有 UT/集成入口为 `packages/coding-agent/test/repo-index.test.ts`、`repo-lifecycle.test.ts`、`repo-tool.test.ts`、`repo-review-regressions.test.ts`、`lsp/edits.test.ts` 和 `packages/natives/test/python-symbols.test.ts`，涵盖最佳匹配、扫描中取消、外部变化复核、真实强杀后的代次回收、并发读快照、设备执行状态、LSP 部分提交／回滚、删除路径身份及长路径确认；真实 TUI E2E 为 `scripts/repo-ui-smoke.ts`，已由 `scripts/fulltest-ui-smoke.ts` 接入 `bun run fulltest`。`scripts/repo-index-perf.ts` 提供合成语料基准。这些入口的存在不代表本次运行通过，执行仍遵循 `AGENTS.md` 的授权限制。
