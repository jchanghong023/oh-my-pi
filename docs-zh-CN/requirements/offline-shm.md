# 离线 shm 运行与异步备份

本文维护当前行为契约与验收条件；实现与验证状态统一见[需求目录中的本功能状态](README.md)。文档描述不代表 Linux、公司 CentOS 7、实际 shm／NFS 或多进程边界已验收。

## 1. 目标与适用范围

- 公司环境仅允许使用 shm 和 NFS，不使用 `/local`，不要求 sudo，不修改系统挂载或 Swap 设置。
- 仅在 Linux 且 `OMP_OFFLINE` 启用时生效；复用现有 `1`、`true`、`yes`、`on` 判定，忽略大小写和首尾空白。其他值不启用。
- 非 offline 模式和非 Linux 平台不创建 shm 工作目录、不启动备份、不检查备份状态；数据根统一及取消独立 Wiki 目录入口属于[通用目录需求](fork.md#安装与运行)，不受本功能启用条件限制。
- 使用已存在且可写的 `/dev/shm`；运行目录从解析后的原始数据根派生，不硬编码 `.omp` 目录名，不改用其他磁盘目录。
- 采用“shm 运行目录＋NFS 异步持久备份”，不是启动预加载或缺失时回源的透明缓存。不实现任何自动恢复。

## 2. 数据范围与路径

### 2.1 运行数据

“所有磁盘 IO”指 OMP 原本在自身数据目录中的读写，不包括工具对项目源码、EDA 文件及外部输入的正常访问。在本模式下，这些自有数据的日常运行读写统一使用 `/dev/shm` 下的运行根；用户主动持久化配置的显式双写是第 2.3 节规定的例外，不改变数据库、会话等运行数据的路由：

- 配置、认证存储、模型目录缓存、用户级技能和扩展的本地管理数据。
- 会话、分支、Goal／计划／任务持久状态、会话附件及输出产物。
- Wiki、记忆等 OMP 自有数据库及 SQLite 的 WAL／SHM 辅助文件；Repo 数据库的 NFS 共置例外见[代码定位索引](repo-index.md#环境价值与范围)。
- 日志、缓存、native 展开文件、OMP 自有临时文件、锁与 IPC 运行状态。

程序安装位置、项目源码、项目级 `.omp/`、显式交付到项目中的输出、外部 EDA 产物不自动迁移。外部 Claude 配置、`OMP_SKILLS_DIR` 等外部输入仍从原位置读取；本需求不承诺消除既有外部输入的 NFS 访问。

在本模式下，显式自定义会话目录（如 `--session-dir`）是运行域内的会话命名空间，不是旧数据源：外部目录按其绝对路径映射到当前 profile 的 shm 会话目录下，不探测、读取或复制原目录；已位于运行根内的目录保持原路径。新建、继续、列举、分支及附件使用映射后的真实运行路径。显式 `--resume`／`--session` 等指定运行根外的会话文件时，直接报错并提示将会话及附件人工恢复到运行根后再使用该运行路径，不自动读取、导入或复制；也不能借助运行根内的符号链接或含 `symlink/..` 的原始路径回读外部会话。会话、附件（包括列举、ID 扫描、定位、读取及 seance 来源）及派生的进程锁 sidecar 均须在访问或修改前检查原始路径分量，不能先词法折叠再检查，也不能借链接读写外部位置。单个被拒绝的会话主文件不得中断其他孤儿备份的恢复或隐藏同目录正常会话。

非文件会话后端的目录仅作为不透明键使用：默认目录解析在创建、继续、工作目录切换及回退后新建会话时保持一致，不创建、验证或扫描对应磁盘目录；文件后端及实际附件写入仍须遵循运行域和符号链接边界检查。

### 2.2 运行根与备份目录

- 先用现有数据根解析规则得到原始持久根：优先读取有效的 `OMP_CONFIG_ROOT`；未设置、为空或按既有规则无效时，沿用上游默认目录解析，包括现有目录名规则，不拼接写死的 `.omp`。冗余末尾分隔符作词法归一化，保留文件系统根；等价的带／不带末尾分隔符路径不得派生不同域，不为此访问原始根或解析其符号链接。
- 原始持久根也是每轮异步备份的目标；不新增 Wiki 专用目录或备份目标环境变量。
- 运行根从原始持久根确定性地派生到 `/dev/shm/omp-<uid>-<domainId>/<原始根目录名>`；`domainId` 由主机、用户和原始根身份确定，不同域不得因同名目录混用。profile 在运行根内保留相对布局；身份区分不改变原始持久根。
- 示例：上游默认解析结果为 `~/.omp` 时，运行根以 `.omp` 为末级目录，位于上述私有数据域下，备份写入 `~/.omp/.offline-shm-backups/`，不是覆盖 `~/.omp` 中的旧活动数据。`.omp` 仅作示例；设置 `OMP_CONFIG_ROOT` 或默认目录名变化时，运行根和备份所在原始根随解析结果变化。
- `OMP_CONFIG_ROOT` 保留原始值及现有优先级，不能改写成 shm 路径后传给子进程，否则子进程会丢失真正备份目标；运行根与原始持久根在内部明确区分。
- Wiki、会话、日志、缓存及其他 OMP 自有运行数据均从运行根派生，保留 profile 内相对布局；XDG 或其他分域默认规则不得绕过运行根回写 NFS。Repo 数据库允许与 NFS 项目代码共置，不要求迁入 shm，具体存储边界见[代码定位索引](repo-index.md#环境价值与范围)。
- 启动只做必要的本机路径计算和运行根初始化，不访问或遍历原始持久根。
- 同一主机、用户及原始根的多个进程复用同一运行根和备份域，profile 数据在域内隔离；已有数据直接使用，退出不自动删除有效数据或缓存。
- 运行目录及含凭据的备份域须保持用户私有权限；共享备份容器与域内数据的权限边界见下文，不得接管或修改其他用户目录的权限。

### 2.3 用户配置的 shm／NFS 双写（权威要求，程序实现待验收）

本节是 Linux offline 下**用户主动持久化 OMP 配置**的唯一权威保存要求，适用于 TUI、RPC、配置命令和经用户授权的 Agent 代配；Team 配置服务必须遵循本节，不能以局部实现约定降低要求。Settings 共享保存、Team TUI／RPC 与 CLI 配置入口已接入双端保存机制，Windows 定向回归及真实入口已有证据；标题“程序实现待验收”保留，真实 Linux／公司 NFS 跨主机锁及 CentOS 实机仍未验收，Windows seam 不能代替。实施与验证状态、失败复验记录见[需求目录](README.md)。

当前 `ConfigFile`／`ModelsConfigFile` 只承担读取／迁移，没有主动 `models.yml` writer 或 provider 保存 API；这不豁免下述已授权 provider 变更的双端要求，也不表示 Team 接口提供 provider 配置。Agent 获授权新增 provider 时仍须双端最小安全写，不能把任意文本 `edit` 视为具有共享程序服务的锁、版本校验或事务保证。

* **两个必要目标：** 同一保存操作 MUST 将本次授权修改的配置字段同时保存到 shm 运行目录和原始持久目录的同一 profile。公司环境的原始持久目录为 NFS；路径 MUST 来自第 2.2 节解析后的 `persistentRoot`，不得另猜一个 NFS 路径。默认 profile 对应两根各自的 `agent/`，命名 profile 对应两根各自的 `profiles/<name>/agent/`；两端分别按实际 `.yml`／`.yaml` 优先级定位文件。不得把 shm 路径写回 `OMP_CONFIG_ROOT`。
* **保存范围：** 本要求针对用户明确保存的配置文件字段（如 `config.yml` 的设置及已授权的 `models.yml` provider 变更），不是每次业务写入都同步 NFS，不自动复制认证、数据库、会话、日志或整个目录。两份文件分别最小合并同一字段变更，保留各自其他内容、注释和私有权限；移除字段、空数组及重复成员的语义不得在两端改变。
* **成功标准：** “同时写入”指同一次保存完成确认前两个目标都必须完成，不要求两次文件写发生在同一瞬间。MUST 在锁内确认两端本次目标字段均已保存或原本同值，再读回形成成功回执；只写 shm、只写 NFS、等待周期备份、仅写入备份 generation 或安排稍后异步补写，均不能报告持久保存成功。非 Linux offline 不虚构 shm 目标。
* **跨主机保护：** NFS 持久配置 MUST 使用服务器端支持、对所有访问同一目标的主机有效的互斥。采用实际目标旁的稳定 sidecar 文件上的跨主机 POSIX 记录锁，在目标 NFS 部署验证其有效性；锁文件不因解锁而删除／替换，避免各进程锁住不同 inode。现有 Linux abstract Unix socket 锁只在本机有效，不能充当此锁。无法确认锁语义、取得锁或安全解析目标时，保存必须失败，不能退化为无锁覆盖或只写 shm 后报成功；不自动安装锁服务或修改挂载。
* **锁与版本方案：** 所有 OMP 自有的持久配置写入口对同一 NFS 文件使用同一稳定锁协议；并发保证以遵从协议的写入者为边界，不承诺拦住不合作的外部编辑。双端保存固定先取得 NFS 目标锁，再取得活动端现有本机文件锁，在两锁都持有时重读两端、比较联合版本、最小合并、先写 shm 再写 NFS 并分别读回，最终释放锁。目标身份指数据域、profile、逻辑文件及符号链接解析后的实际目标，不以每次原子替换变化的 inode／mtime／整文件摘要制造无关字段冲突；版本比较的是授权字段原始值及缺失／空值，保留无关外部修改。符号链接不能把配置写入备份 generation、其他 profile 或其他用户目录。不得只在锁外比较后无条件替换；NFS 锁等待与 I/O 不得同步阻塞 TUI／RPC 主线程和停止通道。
* **部分与未知：** 两个文件不构成跨文件原子事务。锁前或首次提交前发现问题不修改任一配置；先写 shm 后 NFS 出错时必须报告部分完成，提交／读回事实不能确认时报告未知并标出已知结果。不得通过回滚覆盖外部新改动；重新保存前必须重新读取双方现值及版本、由用户确认，不自动重放。回执的“已提交”是本请求在锁内确认的事实，不表示其他后续保存不能改变当前值。
* **与备份及启动的边界：** 原始配置双写是用户操作，不是第 4 节后台备份；备份仍只写隔离备份域。启动、普通运行和配置预览不因此自动同步／回填或扫描 NFS；明确打开配置可按需读取两端以展示原值。shm 丢失后的人工恢复规则不变，不把原始配置已更新解释成启动会自动恢复。

## 3. 启动与前台性能

- 启动直接打开或创建 shm 运行目录，不从原始目录读取旧 OMP 数据进行迁移、补齐、预热或回退。
- 启动关键路径不得等待备份目标检查、NFS 访问、目录遍历、数据复制、数据库快照或备份协调锁。
- TUI 在界面可交互后、RPC 在可接收请求后才启用后台备份；ACP 在 JSON-RPC 输入 reader 已建立、能够接收请求后启用，不等待 initialize、会话创建或首条 stdout 响应。文本／JSON print 模式在进入正常执行阶段时启用，不等待最终答案或首次 stdout；其他命令在进入正常执行阶段后启用，不延迟首个正常输出或请求处理。
- shm 为空时按全新环境运行：原 NFS 中的配置、会话及索引不会自动出现；用户如需旧数据，须自行恢复到 shm。
- 既有公司模型认证、外部技能加载等启动逻辑保持原契约；“不影响启动”指新增机制不引入 NFS 搬运、备份或恢复依赖，不宣称既有启动逻辑完全没有 NFS I/O。
- shm 不存在、不可写或空间不足时明确报告相关操作失败，不静默切回 NFS 或 `/local` 写活动业务数据。
- Linux offline 运行缓存中的 native addon 优先沿用普通 shm 文件映像加载；该路径能够执行时，不新增 memfd、Bun FFI、glibc 或内核版本前提。仅普通 shm 映像无法执行（如 `/dev/shm` 挂载为 `noexec`）时，才通过匿名 memfd 和 `/proc/self/fd` 加载；安装目录中的 addon 沿用既有加载路径。此可执行内存后备路径当前要求 Linux x64／arm64、Bun FFI、glibc `libc.so.6`、支持 memfd 与 sealing 的内核（Linux 3.17 起或兼容 backport）、procfs 及允许 executable memfd 的安全策略，不提供 musl libc 回退；这些不是所有 Linux offline 运行统一提高的内核／glibc 前提。需要后备路径但不支持时明确失败，不改挂载、不安装依赖、不回退到持久可执行副本。成功的 memfd／加载映像在同一进程中复用，反复创建 Worker 不得逐次累积描述符；失败及临时句柄须释放。公司 CentOS 7 的普通加载及实际 noexec 后备所需内核／backport 与策略支持情况须分别实测，不能由实现方式推定通过。

## 4. 后台异步备份

### 4.1 调度与生命周期

- 每 10 分钟触发一次异步备份，不新增必填配置文件或启动步骤。
- 首次备份在前台就绪满一个周期后触发，不在启动阶段抢先全量复制。
- 备份在独立后台执行上下文中进行；文件复制、快照和 NFS 等待不得同步阻塞交互、模型流、工具调用或 RPC 事件处理。
- 同一数据域最多执行一轮备份；多个主进程、Worker 或子 Agent 不得重复调度相同数据域。上一轮未完成时合并后续触发，不堆积任务。
- 未变化的普通文件可复用上一完整版本的内容，SQLite 仍逐库生成一致性快照；不为提速跳过本轮必须持久化的数据，也不关闭数据库的一致性保障。
- 退出不等待 NFS，不执行同步最终备份；退出前尚未成功备份的修改不承诺持久化。短命命令未到备份周期即退出时，同样不保证其新增数据已备份。
- 备份执行资源须有明确所有者，不能因重复启动或异常退出累积无主备份进程；不新增常驻系统服务。
- ACP 断连或处理退出时停止其备份调度；备份提示写 stderr，不向 JSON-RPC stdout 注入协议外文本。

### 4.2 内容与一致性

- 保存可供用户人工恢复的 OMP 数据，包括配置、认证、会话及其必要附件、持久任务状态、数据库、日志和可落盘缓存；不能只复制主数据库而遗漏必要关联文件。
- 不备份 socket、管道、进程锁、PID、正在生成的临时快照等仅对当前运行有效的对象。排除依据是运行时用途，而不是仅凭扩展名：`bun.lock`、`package-lock.json`、`yarn.lock` 等用于重建依赖的持久锁文件仍须纳入完整备份。
- 运行根内的符号链接按链接保存，不把目标内容展开为普通文件。相对内部链接保留原始 target 字符串，不对 `.` 或 `symlink/..` 作会改变逐段解析含义的词法化简；绝对内部链接转换为指向域内目标的相对链接，使完成版本和恢复后的链接不再指回活动运行树。指向运行根外的链接排除并记入 manifest，不回读外部目标；保留备份链接语义不改变各消费端既有的符号链接访问限制。
- SQLite 使用 Online Backup API 或等价的一致性快照机制，不能直接复制正在写入的 `.db`，也不能把普通文件同步当作数据库快照。
- 普通文件稳定复制后才发布；持续追加的 `.jsonl` 及运行日志 `.log`／`.log.N` 保存经校验的完整换行前缀，不发布半条记录。备份自身的延迟日志须在采集目录快照前落盘，不放宽对其他目录变更的检查。备份写入临时位置，校验该轮内容完整后再原子发布为完成版本。
- 保证单个数据库的事务一致性和该轮必要文件完整；不把逐库快照宣传为所有数据库、配置及文件在同一时刻的全局事务快照。
- 备份记录格式应足以识别目标、完整轮次及内容范围，用户无需解析活动 WAL 即可辨认可恢复版本。
- 保留上一轮完整可恢复版本；新备份失败或中断不得损坏它。不得无限积累历史版本或失败临时文件。
- 每个版本只表示对应运行根内的完整可备份内容，不与原始旧 NFS 树合并。同一运行目录实例（runtime incarnation）内相对上一轮消失的条目记录为删除；重建后的空运行根不证明原持久数据已删除。备份不删除、清空或用空内容覆盖原始旧 NFS 树。

### 4.3 原始目录与多进程

- 备份写入解析后的原始持久根内 `.offline-shm-backups/<domain hash>/`：设置有效 `OMP_CONFIG_ROOT` 时使用该根，否则使用上游默认根。只管理该隔离备份域，不覆盖原根中的旧活动数据或无关文件；不改写用户 shell 配置、不经由 `/local` 中转，不执行运行目录的自复制。
- `.offline-shm-backups/` 是供同一原始根下不同用户创建各自域的共享容器，新建时使用 sticky `01777`；管理员预先提供且当前用户可写、可遍历的 sticky 共享容器（如组共享 `01770`）也可使用。容器创建者可初始化权限或迁移其自己拥有的旧私有容器，不修改其他用户拥有的容器；其他用户遗留的 `0700` 容器须由所有者运行更新后的备份完成迁移，或预先提供共享访问权限，不能由第二个用户接管。容器本身不存放凭据；各域及其版本、`data/` 目录仍须由当前用户拥有且为 `0700`，普通文件仅所有者可读写，原有所有者执行位按需保留。
- 同一主机、用户和数据域的多个 OMP 进程共享备份协调；只协调后台备份，不在前台启动等待。
- 不同主机或用户指向同一个共享原始目录时，备份按主机和用户隔离，不能互相覆盖；不建设跨主机共写同一活动数据库的机制。
- 父进程、Worker、task 子 Agent、独立 CLI 及 Python／JavaScript Eval 启动的 OMP 子进程继承相同 offline 状态、原始数据根环境和内部运行根身份，不把 shm 路径重新当作原始持久根，不重复映射。

### 4.4 完整版本与人工恢复

备份布局如下；`<domain hash>` 为数据域标识的哈希，不与运行根路径中的 `domainId` 混用：

```text
<原始持久根>/.offline-shm-backups/<domain hash>/
  current.json
  generations/<id>/
    manifest.json
    data/
```

- `current.json` 的 `current` 指向最新完成版本，`previous` 在已有上一完整版本时指向该版本，值均为 `generations/` 下的 `<id>`。首次成功备份没有 `previous`；失败或中断的临时目录不是恢复来源。
- 每个完成版本的 `manifest.json` 标明 `status: "complete"`、`generation`、`domainId`、`persistentRoot`、`runtimeRoot`、完成时间、条目及排除范围。`data/` 是相对该运行根的可恢复内容，SQLite 已形成独立快照，无需读取活动 WAL；不是原始旧 NFS 树的全集，也不是跨文件全局事务快照。
- 人工恢复前，先停止使用对应运行域的所有 OMP 进程及其后台任务，避免恢复时仍有写入或备份。按 `current.json` 选择最新或上一完整版本，核对其 manifest 的完整状态、版本及目标域；不要选 `.staging-*` 等未发布内容，也不要修改备份版本。
- 将选中版本 **`data/` 的内容**（包括隐藏项，而非 `data/` 目录本身或 `manifest.json`）复制到该 `manifest.runtimeRoot` 指定的、未被进程使用且为空的运行根。不得覆盖合并到已有活动运行根、其他域或原始持久根；恢复其他主机／用户的数据不属于自动路径迁移。
- 恢复须由相应用户操作，保留私有所有者权限和所有者可执行位：目录保持 `0700`，普通文件保持仅所有者可读写，原有所有者可执行文件保留执行位；符号链接须作为链接复制，不解引用或改写相对 target。manifest 的条目记录原始 mode，可供核对；不能为图方便开放组／其他用户权限或统一去掉可执行位。不要接管其他用户目录，也不要从仍在运行的数据库复制 `.db`／WAL／SHM 来拼接恢复。
- 完成复制后，再以相同原始根及所需 profile 启动 OMP；恢复单个外部旧会话时也须连同必要附件放到运行域内，再指定恢复后的会话路径。没有恢复命令、向导或自动回填；没有成功完成版本时，不承诺存在可恢复的新增数据。


## 5. 故障与诊断

- 后台备份中 NFS 不可达、无权限或空间不足时，仅备份失败；前台继续使用 shm，不回滚或删除正在使用的数据，不把失败标记为成功。用户主动配置保存按第 2.3 节返回双端结果，不能套用“仅备份失败”而报告保存成功。
- 后续正常周期可以再次备份，不增加阻塞前台的即时重试循环。
- 复用现有 logger，不新增独立日志系统，不记录凭据或业务正文；级别过滤遵循 [Fork 运行诊断日志](fork.md#运行诊断日志) 的内网例外，不为备份开始、完成或最近成功时间绕过过滤，用户故障提示保持。
- 后台备份故障须有有界、非阻塞的用户提示，不能只静默失败，也不能每个文件重复刷屏。
- 不承诺备份失败后的数据持久性；可丢失范围从最近一次成功备份起算，而不是固定等于一个周期。
- shm 数据在系统重启、断电、卸载或外部清理后可能丢失；tmpfs 也可能使用 Swap，不宣称数据绝不落盘。

## 6. 明确不做

- 自动恢复、启动回填、缓存未命中回源、恢复命令或恢复向导。
- 启动时迁移已有数据、复制可执行文件或检查完整备份。
- `/local`、其他本地持久盘、自动安装依赖、sudo 或系统级部署。
- 运行数据的无损写穿、每次业务写入同步 NFS、同步退出备份；第 2.3 节用户主动保存配置所要求的 shm／NFS 双写不属于此排除范围。
- 自动搬迁项目源码、EDA 工作区或其他程序的数据。
- 除通用统一数据根变更外，不改变非 offline 行为；不将 Ubuntu／WSL 通过视为公司 CentOS 7 验收。

## 7. 验收条件

| 场景 | 必须观察到的结果 |
| --- | --- |
| 开关与平台 | 适用 Linux 下四种真值启用 shm；未设置、空值、`0`、`false` 不启用；非 Linux 不启用 shm；通用统一数据根行为不受该开关限制 |
| 启动路径 | 有大量旧备份或 NFS 卡顿时，新增机制仍不访问、复制或等待备份；界面／RPC／首个正常输出不依赖备份就绪 |
| 空 shm | 按新环境运行，不回读旧配置、会话或索引，不清空原始旧 NFS 树；空运行根不被当成旧持久文件已删除的证据；人工预先恢复后的 shm 数据可正常使用 |
| 数据路由 | 日常自有数据使用对应 shm 运行根；有效 `OMP_CONFIG_ROOT` 与上游默认目录派生规则保持，默认目录名不写死；真实 CLI／TUI／RPC 随根派生，工具仍可访问 NFS 项目；用户主动配置保存例外按第 2.3 节双写 |
| Native 加载前提 | shm 普通映像能够执行时沿用既有加载，不因 Linux offline 统一新增 memfd／glibc／内核版本前提；仅普通加载无法执行（如 `noexec`）时，在支持可执行内存后备所需 memfd、procfs、运行时与安全策略的 Linux 环境下仍可加载，不支持时明确失败，不复制到持久可执行目录、不改挂载；CentOS 7 普通加载与 noexec／backport 结果分别记录 |
| ACP 生命周期 | JSON-RPC 输入 reader 就绪后满 10 分钟才首次备份，不依赖首条响应；物理 EOF、输入错误或连接终止立即停止调度，不等待会话清理完成；故障提示仅写 stderr，不污染 stdout 协议 |
| 路径与进程 | 分别验证未设置、空值、无效值及有效绝对路径的 `OMP_CONFIG_ROOT`；原始根与 shm 运行根区分正确，profile／用户／同名原始目录不混用；Wiki 无独立覆盖；派生进程不改写备份目标或重复调度 |
| 自定义会话路径 | 显式自定义会话目录映射到当前 profile 的运行域且不读取原目录；列举、继续、分支及附件返回并使用真实运行路径；外部 `--resume`／`--session` 文件及外链在读取或修改前失败并提供人工恢复指导 |
| 正常备份与恢复 | 前台就绪后每 10 分钟异步触发，写入原始根的隔离备份域；不重叠、不阻塞前台；`current.json` 指向最新及可用的上一完整版本，manifest 可辨认目标与范围；依赖锁文件等持久内容保留，进程锁等运行时状态排除；停止对应进程后将完整 `data/` 内容恢复到空的 `manifest.runtimeRoot`，数据库可独立打开、会话及必要附件可读、内部链接语义与私有权限及执行位保留，无需活动 WAL |
| 并发与变更 | 后台备份不并发覆盖，普通文件无半份内容；同一 runtime incarnation 的删除与未恢复旧数据不混淆，备份不改变原始旧 NFS 活动树；不同主机／用户使用各自私有备份域。用户主动修改原始配置的唯一例外及跨主机保护见第 2.3 节 |
| 失败与中断 | NFS 无权限／不可达／空间不足及备份中断时，原完整备份和当前 shm 数据保留，前台可继续操作，诊断不泄露敏感内容 |
| 退出与资源 | 正常退出不等待慢 NFS；反复启动、退出及异常结束不遗留叠加的备份任务，不清空有效 shm 数据 |
| 用户配置双写 | Linux offline 的默认及命名 profile 同次保存分别更新 shm 与实际原始 NFS 配置，只改授权字段；展示两端具体原值、缺失／空值／失败及结果，备份 generation 不变；任一端未完成不返回完整成功，取消／未知结果不自动重放 |
| NFS 配置并发 | 在同一部署的两台主机、同一用户／持久目标上以相同旧版本竞争保存，跨主机锁内比较只允许一方提交该版本；另一方冲突且不覆盖先提交值，锁不支持／不可用时明确失败；只在本机或 Windows seam 验证不计为此项通过 |
| 性能 | 相同源码和环境下对照启动到可交互／可请求／首输出的时长，并验证备份期间输入、取消及 RPC 响应；不以新进程冒充冷盘、不预先宣称提速倍数 |

验收须按仓库授权规则复用 UT 并验证真实公开入口；公司 CentOS 7、实际 shm／NFS 和多进程边界须单独记录实测状态，未执行不得标为通过。所有实际验证结论及未验收项统一记录在[需求目录](README.md)，本文不另行维护通过记录。
